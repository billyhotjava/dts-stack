# Repository Guidelines

## Project Structure & Module Organization
- `source/` holds app code: Java services (`dts-admin`, `dts-platform`, `dts-common`) and web apps (`dts-admin-webapp`, `dts-platform-webapp`, `dts-analytics-webapp/modern`).
- `builds/` contains Dockerfiles and build scripts used by compose images.
- `services/` and `plugins/` contain supporting service definitions.
- `config/`, `.env` (generated by `./init.sh`), and `imgversion*.conf` hold environment and image configuration.
- `docs/` and `worklog/` capture docs and permissions notes.
- `docker-compose*.yml` define base services, app services, and dev mounts.

## Build, Test, and Development Commands
- Initialize env and certificates: `./init.sh single 'Strong@2025!' dts.local`.
- Dev mode (source mount + hot reload): `./dev-up.sh --mode local`; stop with `./dev-stop.sh --mode local`.
- Deploy mode (containers only): `docker compose -f docker-compose-app.yml up -d`.
- Build service image: `docker build -t dts-admin:TAG -f builds/dts-admin/Dockerfile .`.
- Webapp dev/build (run from webapp dir): `pnpm dev` (Vite), `pnpm build`.

## Coding Style & Naming Conventions
- Follow existing patterns in each module; avoid cross-module style changes.
- Java services use Maven + JHipster; formatting is enforced via `prettier` (Java + config files).
- Webapps use `biome` (TS/JS) and Vite; keep file naming consistent with current directories.
- Use lowercase, hyphenated image/service names (e.g., `dts-admin-webapp`).

## Module-Specific Workflows
- `source/dts-admin`: `npm run backend:unit:test`, `npm run java:jar:prod`, `npm run java:docker:prod`.
- `source/dts-platform`: `npm run backend:unit:test`, `npm run java:jar:prod`, `npm run java:docker:prod`.
- `source/dts-common`: `npm run backend:unit:test`, `npm run java:jar:prod`.
- `source/dts-admin-webapp` and `source/dts-platform-webapp`: `pnpm dev`, `pnpm build`, `pnpm preview`.
- `source/dts-analytics-webapp/modern`: `pnpm dev`, `pnpm typecheck`, `pnpm build`.

## Testing Guidelines
- Java services: run `npm run backend:unit:test` from the service directory.
- Webapps: run `pnpm run typecheck` (analytics modern) or `pnpm build` as sanity check.
- No repo-wide test aggregator is defined; run tests in the module you touch.

## Commit & Pull Request Guidelines
- Recent history uses Conventional Commit style (e.g., `fix: docker build`). Use `feat:`, `fix:`, `chore:` with brief scopes when relevant.
- No PR template or CI workflow config is present; include commands run in the PR description.
- PRs should include a clear summary, affected modules (e.g., `source/dts-platform`), and any required ops steps (compose flags, env updates).
- Include screenshots for UI changes and note any data migrations.

## Security & Configuration Tips
- Update domains and trusted proxies in `.env`; re-run `./init.sh` when `BASE_DOMAIN` changes.
- Compose files are self-contained by mode: x86 app in `docker-compose-app.yml`, dev in `docker-compose.dev.yml`, and legacy ARM/Kylin in `docker-compose.legacy.yml`.

## Common Errors & Fixes
- `The JAVA_HOME environment variable is not defined correctly` (during build):
  - Often caused by JVM thread creation failing in constrained containers. Use `MAVEN_UNRESTRICTED=1` (default) or build with host Maven (`LEGACY_USE_HOST_MAVEN=1`).
- `Failed to start thread "GC Thread#0" ... pthread_create failed (EPERM)`:
  - Container thread limit/SECcomp issue. Run `MAVEN_UNRESTRICTED=1 ./builds/dts-build.sh -all` or build jars on host.
- `bad class file: ... class file truncated` (dts-common snapshot):
  - Delete the corrupted snapshot under `/root/.m2/repository/com/yuzhi/dts/common/dts-common/0.0.1-SNAPSHOT` and rebuild.
- `dbt 项目目录或 target 目录不可写`:
  - Ensure `services/dts-dbt/` (and `services/dts-dbt/target`) are writable; avoid mounting the project directory as `:ro`.
- `dpkg`/`lzma` errors during `apt-get install` in `dts-dbt` build:
  - Default to `INSTALL_APT_DEPS=0` to skip apt; only enable when adapters need build deps.
  - If enabling apt, keep `INSTALL_BUILD_DEPS=0` and `INSTALL_GIT=0` unless needed; pass proxy/mirror via `HTTP_PROXY`/`APT_MIRROR`.
- `Unable to resolve Configuration with the provided Issuer` (OIDC issuer timeout):
  - Check container DNS/host mapping for the Keycloak/SSO domain; ensure it resolves to the host gateway inside containers.
