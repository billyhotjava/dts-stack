# DTS 数据质量交互原型

该目录是 DTS 数据治理产品的数据质量交互原型。页面结构以 2026-07-31 实际登录采集的阿里云 DataWorks DQC 为参考，业务对象、数据源、负责人、运行记录和报告内容均替换为 DTS 合成数据。

原型只用于产品评审，不连接 DTS API，不保存表单，不会执行质量任务，也不是新的数据质量控制面。后续产品化应继续复用现有质量规则、运行记录、失败样例和数据资产契约。

## 启动

端口 `4173` 当前由其他原型占用，建议使用独立端口：

```bash
python3 -m http.server 4187 \
  --bind 0.0.0.0 \
  --directory /opt/prod/s10/v2.2.3/worklog/prototype/dq
```

访问：<http://127.0.0.1:4187/>

原型无需安装依赖，也无需构建。直接打开 `index.html` 亦可，但使用静态服务更接近浏览器验收环境。

## 页面范围

主导航完整保留 DataWorks DQC 的 8 个页面：

1. 质量大盘
2. 规则列表
3. 规则模板库
4. 按表配置
5. 按模板配置
6. 质量监控
7. 运行记录
8. 质量报告

同时补齐产品闭环所需的二级页面：规则详情、新建规则、模板详情、表质量详情、批量配置向导、质量监控详情/编辑、运行详情、去噪管理、报告编辑和报告预览。

页面通过 URL hash 路由，可直接访问例如：

- `#/overview`
- `#/rule-editor`
- `#/table-detail`
- `#/batch-wizard`
- `#/run-detail`
- `#/report-preview`

## 文件结构

```text
worklog/prototype/dq/
├── index.html                 # 入口和脚本加载顺序
├── styles.css                # DTS/DataWorks 风格设计系统
├── app.js                    # 外壳、导航、hash 路由和通用弹层
├── prototype-data.js         # 合成数据，唯一 fixture 入口
├── views-overview.js         # 质量大盘
├── views-assets.js           # 规则、模板及其详情/编辑
├── views-config.js           # 按表、按模板及批量向导
├── views-operations.js       # 监控、运行、去噪及详情
├── views-reports.js          # 报告列表、编辑、预览
├── SCREEN-INVENTORY.md       # 实采页面与补齐范围清单
└── dataworks-*.png           # 经授权登录会话采集的参考截图
```

所有 JavaScript 均采用 IIFE 和 `window.DQPrototype` 命名空间；没有框架、打包器或远程资源依赖。单个源码文件控制在 800 行以内。

## 原型交互

- 左侧 8 个主页面和 11 个二级页面可以相互跳转。
- 大盘支持时间范围、规则/表视角和生产环境开关。
- 新建规则、批量配置、监控编辑和报告编辑提供完整表单/步骤展示。
- 规则试跑、订阅、问题处置、导出与保存使用弹层或 toast 模拟，不写入数据。
- `Esc` 关闭弹层，`Ctrl/Command + K` 打开原型全局搜索。

## 边界与后续接入

- 原型中的资产 ID、规则 ID 和运行 ID 仅为示例，不可作为真实主键。
- 产品实现应复用 DTS 现有资产标识和质量运行控制面，不新增平行规则表、运行表或报告事实源。
- 数据源连接必须跟随绑定的数据资产，凭据继续通过现有 secret 管理链路获取。
- “去噪管理”和报告定时订阅属于方向性原型；若后端尚无合同，产品页面必须明确显示能力状态。
- 密级标记与业务标签在视觉和语义上保持独立，本原型未使用业务标签承载密级。
