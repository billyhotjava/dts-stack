# T04: 连通测试

**优先级**: P0
**状态**: READY
**依赖**: T03

## 目标

实现数据源连通测试交互，mock 返回成功/失败两态并在 UI 区分。

## 技术设计

- 触发点：`DataSourcesPage` 行操作（T01）、`DataSourceDetailPage` 顶部（T02）、`DataSourceFormModal` 内「测试连接」（T03）三处共用一个测试动作。
- mock service：`dataSourcesService.testConnection(payload|id)` 返回 `Promise<Result<ConnectionTestResult>>`（对齐现网已存在的 `ConnectionTestResult` 类型）；mock 带可调延迟，按入参或 fixture 决定返回成功或失败（含失败原因文案）。
- UI 态：测试中（loading + 状态点「测试中」）、成功（绿点 + 耗时/版本信息）、失败（红点 + 错误原因，可展开详情）；成功后回写列表/详情的连通状态（不可变更新）。
- 状态语言统一用 Swiss 状态点 token，与阶段状态点/运行状态同源。
- 错误处理：网络/超时态与业务失败态区分呈现，不静默吞错。

## 影响范围

- 扩展 `app/src/mock/services/dataSourcesService.ts`（`testConnection`）
- 改动 T01/T02/T03 三处触发 UI
- 共享一个 `useConnectionTest` hook（`app/src/stages/connect/useConnectionTest.ts`）封装测试态机

## 验证

- [ ] 三处入口均可触发测试，loading→结果态过渡正确。
- [ ] mock 可稳定复现成功与失败两态，失败展示原因。
- [ ] 测试成功后对应数据源连通状态回写，列表状态列同步。
- [ ] 至少 2 个样例源（PLM 订单/ERP 客户）测试成功 → 阶段① `✓` 点亮。

## 完成标准

- [ ] 连通测试经 `dataSourcesService.testConnection` 返回 `Result<ConnectionTestResult>`。
- [ ] 成功/失败/测试中三态 UI 区分清晰，状态点 token 统一。
- [ ] 测试结果驱动阶段①完成状态派生（已连通 ≥ 1 源）。
