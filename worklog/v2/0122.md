数据中台详细设计说明书 (V2.落地版)
一、 工作台 (Workbench)
定位：效能聚合，不直接操作底层组件。
1.1 我的概览
业务指标：我创建的资产数、所辖任务的平均成功率、本日新增数据量。
底层映射：统计自 OpenMetadata (资产) 和 Airflow (任务历史)。
1.2 待办事项
功能点：权限审批申请、Schema 变更(Drift)审核、质量核查不通过工单。
重构逻辑：当入湖引擎发现源端字段变更且策略设为“人工审核”时，在此处生成记录。
1.3 我的收藏：快速跳转至常用的“逻辑模型”或“入湖任务”。
二、 数据资源中心 (Resource Center) —— [Addax 主要落点]
定位：打通数据孤岛，实现“资产化入湖”。
2.1 数据源管理 (DataSource)
功能设计：
新建数据源：下拉选择类型（MySQL, PG, Oracle...），界面渲染对应 Addax Reader/Writer 参数。
连接配置：只需填写主机、库名、账号；密码通过“三员管理端”托管。
连通性测试：调用 Addax check 接口。
2.2 元数据采集 (Discovery)
功能设计：配置采集频率，自动拉取表注释、字段类型。
黑盒映射：OpenMetadata Ingestion。采集结果进入“资产门户”。
2.3 数据入湖配置 (IngestJob)
功能设计：
任务定义：选择数据源 -> 选择目标 ODS 库。
表/流选择：多选源库中的表，自动映射到中台 ODS 表名。
同步策略：全量重写 (Full Refresh)、增量追加 (Incremental Append)、实时日志 (CDC)。
入湖对账 (新)：配置逻辑（如：每小时对比源表与目标表 count(*)）。
Schema 策略：设置源端变动时的行为（自动迁移/阻断任务/待办提醒）。
三、 数据开发中心 (Data Studio) —— [dbt & Airflow 核心]
定位：逻辑加工与全链路作业流。
3.1 项目空间管理：配置 dbt 环境变量、Git 仓库地址、成员权限。
3.2 逻辑建模 (Model)
SQL IDE：基于 dbt。
功能点：
语法补全：自动提示 ref (引用模型) 和 source (引用入湖表)。
采样预览：点击“试运行”，后台执行 dbt compile 并展示查询结果预览。
物化设置：UI 选择表、视图或增量模型。
3.3 任务编排 (JobFlow)
定位：基于 Airflow 的可视化画布。
节点设计：
同步节点：引用 2.3 定义的“入湖任务”。
模型节点：引用 3.2 定义的“逻辑模型”。
校验节点：引用 4.3 定义的“质量规则”。
依赖配置：连线定义先后顺序，支持按 Cron 表达式配置调度。
四、 数据治理中心 (Governance Center) —— [dbt tests & OpenMetadata]
定位：标准定义与质量闭环。
4.1 标准管理：定义业务术语（Glossary），关联到资产详情。
4.2 指标中心：定义原子指标，底层通过 dbt 自动生成指标汇总 SQL。
4.3 质量管控
规则配置：基于 dbt tests。
功能点：配置表行数波动、字段非空、主键唯一、枚举值范围。
质量报告：展示入湖阶段的“对账报告”和加工阶段的“模型校验报告”。
五、 数据资产门户 (Data Portal) —— [OpenMetadata]
定位：资产搜索与血缘消费。
5.1 资产搜索：通过表名、字段备注模糊搜索所有数据。
5.2 血缘视图
重构点：融合血缘。
展示：业务系统表 -> (Addax节点) -> ODS表 -> (dbt节点) -> 指标/报表。
黑盒化：点击节点展示“任务负责人”和“运行日志入口”，不暴露 Addax ID 或 dbt 路径。
六、 任务运维中心 (Ops Center) —— [Airflow 运行态展示]
定位：监控作业运行状况。
6.1 运行概览：大屏展示今日失败任务数、SLA 超时占比。
6.2 任务实例监控
统一列表：展示所有 JobFlow 的运行记录。
详情弹窗：点击后显示节点甘特图。
日志系统：
同步节点日志：调取 Addax API 抓取同步流日志。
计算节点日志：展示 dbt 执行过程输出。
6.3 补数管理：选择日期范围，生成补数实例，自动重跑整条 DAG。
七、 数据服务中心 (Service Center)
定位：数据消费出口。
7.1 数据 API 管理：将 dbt 模型产出的表，一键发布为 API。
7.2 数据推送 (Outbound)
技术映射：利用 Addax Writer (如导出到 Kafka, ClickHouse, Google Sheets)。
功能点：配置“反向 ETL”任务。
八、 关键对象交互流程图 (实现逻辑)
为了落地，你需要实现以下核心逻辑：
保存入湖配置 (UI) -> 后端生成 Addax 作业配置 -> 状态存入业务 DB。
保存编排画布 (UI) -> 后端根据节点关系解析 -> 生成 Airflow Python DAG -> 部署至 Airflow 服务器。
Airflow 运行时 -> 触发 Addax 同步任务 -> 轮询 Job 状态 -> 成功后触发 DbtRunOperator -> 状态同步至“运维中心”。
OpenMetadata 采集 -> 扫描 Addax 和 dbt 的产出物 -> 自动构建全链路血缘。
