# 项目任务进度最小生命周期 Demo Runbook

## 1. 目标

本目录用于在一套刚重置、无历史业务数据的 DTS 环境中，完全通过页面手工走通一次最小数据生命周期：

`CSV 文件接入 → ODS 落表 → 资产登记与治理属性 → 规划对象 → DWD 明细模型 → 质量规则 → DWS 汇总模型 → 指标 → BI 看板 → 血缘、权限、审计与运行证据`

业务场景固定为“项目任务进度快照”。整个 Demo 只使用：

- 1 份干净测试数据；
- 1 份可选脏数据，用于验证质量失败与恢复；
- 1 张 ODS 源表；
- 1 张 DWD 项目任务快照明细表；
- 1 张 DWS 项目进度汇总表；
- 1 条质量规则；
- 1 个原子指标；
- 1 个简单 BI 看板。

本 Runbook 的目标是验证 DTS 的真实操作链路和证据链，不是展示复杂业务模型。所有编码、表名和主键都使用稳定 ASCII 值；中文仅用于名称和说明。

## 4. 推荐执行顺序和停线规则

按下面顺序执行，不跳阶段：

1. 完成环境基线检查；
2. 检查并上传干净 CSV；
3. 立即执行文件接入计划，得到 ODS 表；
4. 补齐 ODS 资产治理属性并在建模计划中确认该源；
5. 配置或复用最少的数据标准、计量单位和状态码；
6. 手工建立并物化 DWD 模型；
7. 手工建立、发布并执行质量规则，确认失败记录数为 0；
8. 手工建立并物化 DWS 模型；
9. 建立原子指标和 BI 看板；
10. 检查血缘、权限、审计和运行证据；
11. 主链路验收通过后，再选择是否进行脏数据负向演练。

遇到以下任一情况应停止向下游推进，在 `evidence-register.md` 记录为 `BLOCKED`：

- 上游任务失败或实际数据行数不符合预期；
- ODS 资产未进入默认数据湖，导致质量规则不能选择；
- 源资产未在当前建模计划中确认；
- 模型校验、交付检查或物化运行失败；
- 质量执行是 SQL 执行错误，而不是正常的数据质量失败；
- 干净数据的质量失败记录数不为 0；
- 页面显示成功，但找不到对应运行 ID、版本或物理表结果。

## 5. 检查测试 CSV

- 文件格式：`.csv`。
- 文件编码：UTF-8 BOM；字段分隔符为半角逗号。
- 第一行必须是字段名，字段名保持小写下划线。
- 共有 12 列、8 行数据；不要增加合计行、空行、公式、合并单元格或隐藏列。

- `progress_pct` 为数值，正常范围为 0 到 100。

- 使用 LibreOffice 打开检查时，不要将 ID、编码列自动转换为数值或日期；如出现导入提示，将这些列按文本读取。

## 6. G0：环境基线检查

先打开 `evidence-register.md`，填写操作者、环境地址、开始时间。逐项检查：

| 检查项 | 合格条件 | 失败处理 |
| --- | --- | --- |
| DTS 服务与登录 | 页面可访问，当前用户可正常登录 | 停止；先恢复运行环境或账号 |
| 数据源 | 有可写的数据湖/仓库数据源，允许在 `public` 建表 | 停止；先配置连接并验证 |
| 默认数据湖 | 已设置默认数据湖，质量页面能读取其资产 | 停止；质量规则将无法绑定 |
| 数据分级 | 用户具有可用的数据分级权限，至少可选择“公开” | 停止；文件上传或资产治理可能不可用 |
| 建模上下文 | 有当前建模上下文/规划方案，且允许新建模型 | 停止；先创建或切换到有效方案 |
| 基础规划对象 | 可创建或复用业务分类、数据域、业务过程 | 停止；DWD 事实模型不能完整定义 |
| 标准与单位 | 可复用或新建百分比、人民币、计数等标准/单位 | 可先准备，但 DWD/DWS 发布前必须完成 |
| 权限 | 操作者具备当前环境所需的读、写权限 | 停止；不要绕过权限 |
| 取证 | 浏览器允许截图，能记录页面对象 ID 和运行 ID | 停止；没有证据不能判定 Demo 完成 |

只有关键项全部为 `PASS` 才进入文件接入。服务健康或页面能打开，不等于生命周期已验收。

## 7. 阶段一：上传 CSV 并生成 ODS 表

### 7.1 新建文件接入任务

1. 进入 `数据基础 → 文件接入`，直接路径为 `/foundation/data-sources/files`。
2. 点击新建文件接入任务。
3. 上传 `prjdemo_project_task_clean.csv`。当前文件接入支持 `.csv` 和 `.xlsx`，单文件不超过 50 MB。
4. 填写任务名称：`PRJDEMO 项目任务快照导入`。
5. 数据分级选择系统已有的“公开”或同等等级。
6. 描述填写：`项目任务进度最小生命周期 Demo；仅含公开演示数据。`
7. 如果页面提供加密上传开关，按当前环境策略选择；不要在 README 或截图中记录密钥。
8. 检查文件解析结果：必须识别到 12 个字段和 8 行数据。字段名和第 5 节完全一致。

如果上传按钮不可用，优先检查用户数据分级权限；不要把业务标签当作数据分级填写。

### 7.2 配置落表

1. 目标数据源选择 G0 已确认的可写数据源。
2. 结构方式选择“手工编辑”。首次演示不要引用不存在的旧表结构。
3. 落表方式选择“新建目标表”。
4. 目标表填写 `public.ods_prjdemo_project_task_snapshot`。
5. 自动生成 ID 关闭，因为 `task_snapshot_id` 已是稳定业务快照主键。
6. 按下表确认类型；若页面只能先按字符串解析，至少保证日期和数值字段在后续 DWD 映射时显式转换。

| 字段 | 推荐 ODS 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| task_snapshot_id | STRING/VARCHAR | 否 | 一条任务快照唯一标识 |
| project_snapshot_id | STRING/VARCHAR | 否 | 项目日期快照标识 |
| snapshot_date | DATE | 否 | 快照日期 |
| project_code | STRING/VARCHAR | 否 | 稳定项目编码 |
| project_name | STRING/VARCHAR | 否 | 项目名称 |
| task_code | STRING/VARCHAR | 否 | 稳定任务编码 |
| task_name | STRING/VARCHAR | 否 | 任务名称 |
| task_status_code | STRING/VARCHAR | 否 | `TS-TODO/TS-DOING/TS-DONE` |
| progress_pct | DECIMAL | 否 | 完成百分比 |
| plan_end_date | DATE | 否 | 计划结束日期 |
| actual_cost | DECIMAL | 否 | 实际成本 |
| source_batch_id | STRING/VARCHAR | 否 | 接入批次标识 |

### 7.3 配置并执行计划

1. 文件接入属于全量导入，本 Demo 选择手工调度。
2. 保存并启用接入计划。
3. **保存并启用不代表已立即运行。** 保存后进入计划详情页，点击“立即执行”。
4. 等待运行结束，记录文件接入任务 ID、计划 ID、运行 ID、开始/结束时间和最终状态。
5. 在运行详情查看错误信息和写入统计；状态必须为成功。
6. 在数据源查询页或资产详情确认物理表存在且有 8 行。

本阶段通过条件：

- 物理表为 `public.ods_prjdemo_project_task_snapshot`；
- 12 个字段均存在；
- 行数为 8；
- `COUNT(DISTINCT task_snapshot_id) = 8`；
- 运行状态成功且有真实运行 ID。

## 8. 阶段二：补齐 ODS 资产治理属性

1. 进入数据目录/数据资产页面，在默认数据湖中搜索 `ods_prjdemo_project_task_snapshot`。
2. 如果搜索不到，先执行或等待元数据采集；不要在质量页面伪造另一个资产。
3. 打开资产详情，记录资产/数据集 UUID。后续质量规则必须使用该 UUID，而不是表名代替。
4. 设置业务名称：`项目任务原始快照`。
5. 设置说明：`由 PRJDEMO CSV 全量接入形成的项目任务进度原始快照。`
6. 设置负责人和责任部门，使用当前测试组织中的真实人员/部门。
7. 设置数据分级为“公开”或当前等价等级。
8. 添加业务标签 `PRJDEMO`、`PROJECT_PROGRESS`。
9. 检查生命周期状态为可用或当前状态；不要把已退役资产绑定给新模型。
10. 记录资产详情、字段列表、负责人、分级和标签截图。

通过条件：ODS 物理表已成为默认数据湖中的可选择资产，并具有资产 UUID、责任人、分级和业务标签。

规划对象编码创建后不要改为中文或自然语言主键。记录当前建模上下文 ID、规划方案 ID，以及三个对象的 ID/版本。

### 9.2 将 ODS 源纳入建模计划

1. 在当前规划方案的数据源或源表确认页面，选择阶段二登记的 ODS 资产。
2. 将其加入当前方案，并执行页面上的“确认”动作。
3. 确认源状态为当前有效版本；仅保存草稿、可见但未确认的源，不能作为已交付输入。
4. 记录源绑定 ID、源版本、确认人和确认时间。

如果模型编辑器的输入下拉框为空，先回到此处检查“当前方案 + 已确认源 + 当前版本”，不要跳过规划关系直接另建表。

## 11. 阶段五：手工建立 DWD 项目任务快照明细

详细字段映射见 `model-field-matrix.md`。

### 11.1 基本信息

| 配置项 | 值 |
| --- | --- |
| 模型类型 | FACT / 事实模型 |
| 数仓分层 | DWD |
| 模型名称 | 项目任务快照明细 |
| 物理表名 | `prjdemo_dwd_project_task_snapshot` |
| 数据域 | 项目进度 / `PRJDEMO_PROJECT` |
| 业务过程 | 项目进度快照 / `PRJDEMO_PROJECT_PROGRESS` |
| 业务定义 | 对项目任务在指定快照日期的状态、进度和实际成本进行标准化记录 |
| 粒度 | 一个项目任务在一个快照日期一行 |
| 物化方式 | TABLE |
| 加载策略 | FULL |
| 事实形态 | PERIODIC_SNAPSHOT / 周期快照 |
| 时间语义 | SNAPSHOT_DATE / 快照日期 |
| 时间字段 | `snapshot_date` |
| 实现输入 | PHYSICAL_ASSET |
| 输入资产 | 已确认的 `public.ods_prjdemo_project_task_snapshot` 当前版本 |

### 11.2 字段和转换

1. 从已确认 ODS 资产添加 12 个输入字段。
2. 输出字段保持 12 个，名称与 ODS 相同。
3. 所有字段一对一映射。
4. 对 `snapshot_date`、`plan_end_date` 显式转换为 DATE；对 `progress_pct`、`actual_cost` 显式转换为 DECIMAL，前提是 ODS 未正确识别类型。
5. 去重键使用 `task_snapshot_id`。
6. 本层不做 JOIN、不做聚合、不做业务过滤。
7. 字段角色、可空性和标准绑定严格按 `model-field-matrix.md` 设置。

### 11.3 模型生命周期动作

按页面动作逐步执行并分别取证：

1. **保存**：形成模型草稿；记录 ModelSpec ID 和草稿版本。
2. **校验**：确认必填项、字段角色、类型、事实形态、时间语义和转换全部通过。
3. **提交实现**：形成实现修订；记录实现修订 ID/版本和校验摘要。
4. **交付检查**：查看构建、模型测试、标准、权限、分级等检查项。某一项失败时不要直接宣称模型已交付。
5. **发布/物化**：按当前页面发布当前候选版本并执行物理构建；记录候选发布 ID、运行 ID 和模型版本。
6. 在物理资产或查询页面确认 `public.prjdemo_dwd_project_task_snapshot` 存在且有 8 行。

保存、校验、提交实现、交付检查、发布和物化是不同事实，不能用一次“保存成功”代替后续阶段。

通过条件：DWD 物理表 12 列、8 行、8 个唯一任务快照 ID，并能追溯到已确认的 ODS 源资产和当前模型版本。

## 12. 阶段六：手工建立并执行质量规则

### 12.1 页面录入

1. 进入 `数据治理 → 质量规则 → 规则目录`，打开 `/governance/rules/catalog/new`。
2. 逐项填写：

| 页面字段 | 值 |
| --- | --- |
| 规则名称 | 项目任务进度范围校验 |
| 规则编码 | `PRJDEMO_PROGRESS_RANGE` |
| 质量维度 | VALIDITY / 有效性 |
| 严重性 | HIGH / 高 |
| 数据分层 | `DWD` |
| 规则分类 | `PROJECT_PROGRESS` |
| 规则说明 | 项目任务完成进度必须非空且位于 0 到 100 |
| 负责人 | 当前真实测试负责人 |
| 执行器 | `SQL`，如当前环境要求留空使用默认，则按页面提示留空 |
| 调度表达式 | 首次 Demo 可留空，使用手工执行；不要把自然语言误当 Cron |
| 检测对象 | 默认数据湖中的 DWD 数据资产 UUID |
| 启用规则 | 开启 |
| 保存后发布 | 发布 |

3. 将 `quality-rule.sql` 的完整内容粘贴到“检测 SQL”。该 SQL 返回不符合规则的记录，不是返回合格记录。
4. 保存并发布，记录规则 ID、规则版本和绑定的数据集 UUID。

### 12.2 执行和判定

1. 从规则详情或质量监控页面创建/选择一个手工执行任务。
2. 确认任务指向刚发布的规则版本和 DWD 数据集，而不是 ODS 表。
3. 执行一次，记录质量任务 ID、运行 ID、规则版本、开始/结束时间。
4. 干净数据的预期结果：SQL 执行成功，扫描 8 行，失败记录数 0。
5. 如果页面显示 SQL 执行错误，该结果不是“数据质量失败”，应修复限定表名、权限或字段类型后重新运行。

`quality-rule.payload.template.json` 仅用于人工核对请求结构，或在具备合法登录凭证时手工调用单规则创建接口 `POST /governance/quality/rules`。当前页面没有“导入 JSON 创建规则”的合同，也没有批量原子创建合同，因此不要把该文件描述为可直接导入的规则包。手工 API 调用前必须替换数据集 UUID、负责人和责任部门；不能把登录令牌写入本目录。

本 Demo 的操作约束是：质量规则成功后才继续 DWS。除非当前运行环境提供了可验证的发布门禁证据，否则只能声称“操作者按 Runbook 停线”，不能声称质量规则已经自动阻断模型发布。

## 13. 阶段七：手工建立 DWS 项目进度汇总

### 13.1 基本信息

| 配置项 | 值 |
| --- | --- |
| 模型类型 | SUMMARY / 汇总模型 |
| 数仓分层 | DWS |
| 模型名称 | 项目进度汇总 |
| 物理表名 | `prjdemo_dws_project_progress` |
| 数据域 | 项目进度 / `PRJDEMO_PROJECT` |
| 业务定义 | 按项目和快照日期汇总任务数量、平均进度和实际成本 |
| 粒度 | 一个项目在一个快照日期一行 |
| 物化方式 | TABLE |
| 加载策略 | FULL |
| 实现输入 | UPSTREAM_MODEL |
| 上游模型 | 已发布的 DWD `项目任务快照明细` 当前版本 |

### 13.2 分组和聚合

输出 7 个字段：

- 分组字段：`project_snapshot_id`、`snapshot_date`、`project_code`、`project_name`；
- `task_total = COUNT(task_code)`；
- `avg_progress_pct = AVG(progress_pct)`；
- `actual_cost_amount = SUM(actual_cost)`。

所有非度量输出必须配置为分组字段，所有度量输出必须配置聚合函数。本层不做 JOIN、不做过滤、不做去重。字段类型、角色和标准绑定见 `model-field-matrix.md`。

### 13.3 保存、检查和物化

依次执行保存、校验、提交实现、交付检查、发布/物化，并分别记录模型 ID、模型版本、实现修订、候选发布 ID 和运行 ID。最终确认物理表 `public.prjdemo_dws_project_progress` 有 2 行，结果应为：

| project_code | task_total | avg_progress_pct | actual_cost_amount | snapshot_date |
| --- | ---: | ---: | ---: | --- |
| PRJ-A | 4 | 72.50 | 91000.00 | 2026-09-01 |
| PRJ-B | 4 | 53.75 | 51000.00 | 2026-09-01 |

如平均数或成本不一致，先检查 DWD 行数与 DWS 分组/聚合配置，不要在 BI 层修改展示值掩盖模型错误。

## 16. 阶段十：血缘、权限、审计和运行证据

### 16.1 血缘

若产品只展示其中一部分，逐段记录可见血缘，并把缺失段记为 `BLOCKED` 或 `NOT_PROVED`，不要手工画图后声称系统血缘已验证。

4. 如有可用的无权测试用户，再验证其无法读取或导出；没有第二账号时将负向权限项标记为 `NOT_RUN`，不要伪造结果。

### 16.3 审计和运行

在审计证据或运维页面检查以下事件，并记录真实事件 ID/时间/操作者：

- 文件上传、接入计划保存和立即执行；
- ODS 资产治理属性修改；
- DWD/DWS 保存、校验、提交实现、交付检查、发布和物化；
- 质量规则创建、发布和执行；

找不到某类审计事件时记录 `NOT_PROVED`，不要用普通应用日志替代审计事实。

## 17. 可选负向演练：质量失败和恢复

仅在第 7 至 16 节干净主链路全部通过、证据已保存后执行。本步骤会对隔离的 Demo ODS 表做全量重建，具有破坏性；不要对共享业务表执行。

### 17.1 注入脏数据

1. 确认目标仍是专用表 `public.ods_prjdemo_project_task_snapshot`。
2. 编辑原文件接入计划或按页面允许的同一计划重跑方式，上传 `prjdemo_project_task_bad.csv`。
3. 结构方式引用当前表结构；落表方式选择“全量重建现有表”。
4. 页面提示将删除并重建表时，复核目标名称后再确认。
5. 立即执行，确认 ODS 仍有 8 行且坏记录进度为 120。
6. 重新执行 DWD 物化，使当前 DWD 反映脏批次。
7. 执行质量规则，预期 SQL 成功但失败记录数为 1，失败样本为 `PTS_PRJB_T03_20260901`。
8. 记录失败运行 ID 和样本截图，**不要继续刷新 DWS、指标或 BI**。

如果全量重建导致资产 UUID 或源版本变化，停止演练，重新采集/确认资产并显式更新模型输入版本；不要通过建立第二套旁路资产绕过治理链路。

### 17.2 恢复干净数据

1. 用同样的全量重建方式重新上传 `prjdemo_project_task_clean.csv`。
2. 确认 ODS 8 行且所有进度位于 0 到 100。
3. 重新执行 DWD 物化。
4. 重新执行质量规则，预期失败记录数恢复为 0。
5. 再执行 DWS 物化，确认两行汇总恢复到 72.50 和 53.75。
6. 刷新指标和 BI，保存恢复后的运行证据。

完成负向演练的证据必须成对出现：一次 1 条失败的运行和一次恢复到 0 条失败的运行。

## 18. 常见问题定位

| 现象 | 优先检查 | 判定 |
| --- | --- | --- |
| 上传按钮不可用 | 用户数据分级权限、文件格式、50 MB 限制 | 未解决前停止 |
| 保存计划后没有 ODS 数据 | 是否进入计划详情点击“立即执行” | 保存启用不等于立即执行 |
| 质量规则检测对象为空 | 默认数据湖、元数据采集、资产 UUID | 不要手填不存在的数据集 |
| 模型输入资产为空 | 当前规划方案、源是否已确认、是否为当前版本 | 回到规划阶段处理 |
| 事实模型校验失败 | 业务过程、周期快照事实形态、快照日期语义、TIME 字段 | 逐项补齐 |
| DWS 聚合校验失败 | 每个输出是否明确为分组字段或聚合字段 | 不要保留悬空输出 |
| 质量运行失败 | 先区分 SQL_EXECUTION_FAILED 与有失败样本 | SQL 错误不等于数据不合格 |
| 页面已保存但无物理表 | 是否只保存草稿、未提交实现/发布/物化 | 补齐生命周期动作 |
| DWS 数值错误 | DWD 行数、分组键、COUNT/AVG/SUM 字段 | 不在 BI 层修数 |
| 看不到完整血缘 | 各阶段对象版本或运行是否真实关联 | 标记缺口，不伪造系统证据 |

## 19. 完成标准

只有同时满足以下条件，才能宣布 Demo 主链路完成：

- 文件接入有成功运行 ID，ODS 表 12 列、8 行；
- ODS 在默认数据湖有资产 UUID、责任人、分级和标签；
- 规划对象和已确认源属于当前有效方案；
- DWD 已发布并物化，物理表 8 行；
- 质量规则已发布，绑定 DWD 当前数据集，干净数据失败记录数为 0；
- DWS 已发布并物化，物理表 2 行且汇总值精确匹配；
- 原子指标存在已发布版本并指向 DWS 当前版本；
- BI 看板显示 2 个项目、8 个任务和正确进度/成本；
- 可见血缘与实际执行顺序一致；
- 权限和审计按实际能力完成验证，未验证项明确标记；
- `acceptance-checklist.md` 已逐项填写，`evidence-register.md` 中关键对象均有真实 ID、版本和截图位置。

可选负向演练不影响主链路是否完成，但一旦执行，就必须恢复到干净状态后才结束本次测试。

## 20. 清理原则

默认不清理 Demo 对象，以便复核证据。需要清理时，先确认没有其他人复用这些对象，再按下游到上游顺序人工处理：

`BI 看板 → 指标 → 质量任务/规则 → DWS → DWD → 规划绑定 → ODS 资产/接入计划 → ODS 物理表`

清理属于单独的破坏性操作，不在本 Runbook 中提供自动删除脚本。删除后应记录删除人、时间、对象 ID，以及物理表是否仍可恢复。
