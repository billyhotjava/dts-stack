# 项目任务进度最小生命周期 Demo Runbook

## 1. 目标

本目录用于在一套刚重置、无历史业务数据的 DTS 环境中，完全通过页面手工走通一次最小数据生命周期：

`CSV 文件接入 → ODS 落表 → 资产登记与治理属性 → 规划对象 → DWD 明细模型 → 质量规则 → DWS 汇总模型 → 指标 → BI 看板 → 血缘、权限、审计与运行证据`

业务场景固定为“项目任务进度快照”。整个 Demo 只使用：

- 1 份干净测试数据；
- 1 份可选脏数据，用于验证质量失败与恢复；
- 1 张 ODS 源表；
- 1 张 DWD 项目任务快照明细表；
- 1 张 DWS 项目进度汇总表；
- 1 条质量规则；
- 1 个原子指标；
- 1 个简单 BI 看板。

本 Runbook 的目标是验证 DTS 的真实操作链路和证据链，不是展示复杂业务模型。所有编码、表名和主键都使用稳定 ASCII 值；中文仅用于名称和说明。

## 2. 阅读和执行方式

**执行时只按本文从上到下操作。** 本文包含完整的页面录入值、DWD/DWS 字段、转换、质量 SQL、通过条件和停线条件，不需要在多个说明文件之间查找步骤。

本目录只保留这一份 `README.md`：

- 第 5 节内嵌干净和脏数据的完整 CSV，可复制到本地文件后上传；
- 第 11、13 节是 DWD/DWS 页面逐项录入卡；
- 第 12 节内嵌质量规则全部页面输入、SQL 和 API 结构参考；
- 第 21 节是随执行填写的证据登记表；
- 第 22 节是最终验收清单。

> 需要上传 CSV 时，从第 5 节代码块复制内容，分别保存为 `prjdemo_project_task_clean.csv` 或 `prjdemo_project_task_bad.csv`，编码选择 UTF-8 BOM。生成的本地 CSV 是临时测试输入，不再纳入本目录。

不要因为重新打开本文而重建已经存在的对象，先按当前页面状态定位：

## 4. 唯一执行顺序和停线规则

按下面顺序执行，不跳阶段：

1. 阅读并核对干净 CSV 和预期结果；
2. 完成环境基线检查；
3. 上传干净 CSV，配置、保存并立即执行文件接入计划，得到 ODS 表；
4. 补齐 ODS 资产治理属性；
5. 创建或复用业务分类、数据域和业务过程；
6. 配置或复用最少的数据标准、计量单位和状态码；
7. 新建 DWD 明细模型，在模型编辑器中把 ODS 登记为规划来源并选为模型输入；
8. 完成 DWD 字段和转换，依次保存草稿、校验、提交实现，并在“发布与物化”中完成构建和工程验证；
9. 手工建立、发布并执行主质量规则，确认规则进度 `1/1` 且未通过规则为 0；回到模型刷新质量证据并完成发布登记；
10. 手工建立并物化 DWS 模型；
11. 建立原子指标和 BI 看板；
12. 检查血缘、权限、审计和运行证据；
13. 主链路验收通过后，再选择是否进行脏数据负向演练。

遇到以下任一情况应停止向下游推进，在本文第 21 节记录为 `BLOCKED`：

- 上游任务失败或实际数据行数不符合预期；
- ODS 资产未进入默认数据湖，导致质量规则不能选择；
- 源资产未在当前建模计划中确认；
- 模型校验、提交实现或“发布与物化”任一阶段失败；
- 质量执行是 SQL 执行错误，而不是正常的数据质量失败；
- 干净数据的质量失败记录数不为 0；
- 页面显示成功，但找不到对应运行 ID、版本或物理表结果。

## 6. G0：环境基线检查

先在本文第 21 节填写操作者、环境地址、开始时间。逐项检查：

| 检查项 | 合格条件 | 失败处理 |
| --- | --- | --- |
| DTS 服务与登录 | 页面可访问，当前用户可正常登录 | 停止；先恢复运行环境或账号 |
| 数据源 | 有可写的数据湖/仓库数据源，允许在 `public` 建表 | 停止；先配置连接并验证 |
| 默认数据湖 | 已设置默认数据湖，质量页面能读取其资产 | 停止；质量规则将无法绑定 |
| 数据分级 | 用户具有可用的数据分级权限，至少可选择“公开” | 停止；文件上传或资产治理可能不可用 |
| 建模上下文 | 有当前建模上下文/规划方案，且允许新建模型 | 停止；先创建或切换到有效方案 |
| 基础规划对象 | 可创建或复用业务分类、数据域、业务过程 | 停止；DWD 事实模型不能完整定义 |
| 标准与单位 | 可复用或新建百分比、人民币、计数等标准/单位 | 可先准备，但 DWD/DWS 发布前必须完成 |
| 权限 | 操作者具备当前环境所需的读、写权限 | 停止；不要绕过权限 |
| 取证 | 浏览器允许截图，能记录页面对象 ID 和运行 ID | 停止；没有证据不能判定 Demo 完成 |

只有关键项全部为 `PASS` 才进入文件接入。服务健康或页面能打开，不等于生命周期已验收。

## 7. 阶段一：上传 CSV 并生成 ODS 表

### 7.1 新建文件接入任务

1. 进入 `数据基础 → 文件接入`，直接路径为 `/foundation/data-sources/files`。
2. 点击新建文件接入任务。
3. 上传 `prjdemo_project_task_clean.csv`。当前文件接入支持 `.csv` 和 `.xlsx`，单文件不超过 50 MB。
4. 填写任务名称：`PRJDEMO 项目任务快照导入`。
5. 数据分级选择系统已有的“公开”或同等等级。
6. 描述填写：`项目任务进度最小生命周期 Demo；仅含公开演示数据。`
7. 如果页面提供加密上传开关，按当前环境策略选择；不要在 README 或截图中记录密钥。
8. 检查文件解析结果：必须识别到 12 个字段和 8 行数据。字段名和第 5 节完全一致。

如果上传按钮不可用，优先检查用户数据分级权限；不要把业务标签当作数据分级填写。

### 7.2 配置落表

1. 目标数据源选择 G0 已确认的可写数据源。
2. 结构方式选择“手工编辑”。首次演示不要引用不存在的旧表结构。
3. 落表方式选择“新建目标表”。
4. 目标表填写 `public.prjdemo_ods_project_task_clean`。
5. 自动生成 ID 关闭，因为 `task_snapshot_id` 已是稳定业务快照主键。
6. 按下表确认类型；若页面只能先按字符串解析，至少保证日期和数值字段在后续 DWD 映射时显式转换。

| task_snapshot_id | STRING/VARCHAR | 否 | 一条任务快照唯一标识 |
| project_snapshot_id | STRING/VARCHAR | 否 | 项目日期快照标识 |
| snapshot_date | DATE | 否 | 快照日期 |

### 9.2 理解业务规划与物理来源的区别

完成业务分类、数据域和业务过程，只表示 DWD 模型的业务归属已经准备好，并不会自动把 ODS 表变成模型输入。两条关系会在 DWD 模型中汇合：

```text
业务分类 → 数据域 → 业务过程 ─┐
                              ├→ DWD 项目任务快照明细
ODS 目录表 → 规划来源绑定 ────┘
```

- 业务分类、数据域、业务过程回答“模型属于什么业务、描述哪个业务过程”。
- ODS 规划来源绑定回答“模型从哪张受治理的物理表读取数据”。
- ODS 是 DWD 的上游，但必须先成为**当前建模方案的已确认来源**，再由具体 DWD 模型勾选使用。

当前页面没有一个独立且明显的“源表确认页面”。实际入口位于第 11 节新建 DWD 明细模型后的：

`实现绑定 → 实现输入方式：关联数仓来源 → 物理来源 → 维护来源`

因此，本阶段只需要确认以下前置条件，然后继续第 10、11 节：

1. 当前存在一个可写的建模上下文/数仓规划方案，并记录其 ID；如有多个有效方案，先确认正在使用的是哪一个方案。
2. `PRJDEMO_PROJECT_MGMT`、`PRJDEMO_PROJECT`、`PRJDEMO_PROJECT_PROGRESS` 已存在且属于预期业务结构。
3. ODS 已完成第 8 节的目录登记，当前账号能看到对应数据集、表和字段。

如果你已经创建好了业务分类、数据域和业务过程，不要重复创建；记录实际 ID 后继续第 10 节。ODS 的“登记并确认”和模型勾选操作统一在第 11.2 节完成。

这一步同时完成“ODS 纳入当前规划”和“DWD 使用该 ODS”两层关系：

三个状态分别表示：

| 状态 | 含义 | 是否可作为本模型输入 |
| --- | --- | --- |
| `CONFIRMED` | 操作者已确认该目录表属于当前规划来源 | 还需同时满足后两项 |
| `AVAILABLE` | 当前账号能够解析并访问该目录表 | 还需版本为当前 |
| `CURRENT` | 确认版本与当前目录表结构指纹一致 | 是 |

“源版本”是由表名、字段名、字段类型、可空性等目录结构计算的版本指纹，不是 CSV 批次号，也不是表中数据日期。数据行变化通常不会使它变成 `STALE`；表结构发生变化才需要重新确认。

弹窗排错：

- “来源数据集”为空：ODS 尚未进入当前账号可见的资产目录，优先检查元数据采集、负责人/责任部门、数据分级和权限。
- 已选“来源数据集”，但“目录资产”为空：该数据集下面还没有可读取的表结构/字段元数据，或当前账号没有该数据集的精确部门访问权限。
- 已登记但不是 `CURRENT`：重新加载来源；如显示结构变化且允许操作，检查变更后再点击“采用新结构”。
- 关闭弹窗后“物理来源”仍为空：确认登记行同时为 `CONFIRMED`、`AVAILABLE`、`CURRENT`，并确认操作发生在同一规划方案。

取证时记录规划方案 ID、目录资产 UUID、来源绑定 ID、确认版本、当前版本、验证时间和当前登录账号。弹窗不会完整展示这些字段；如页面看不到绑定 ID，可在浏览器开发者工具 Network 中查看路径以 `/baseline/sources` 结尾的保存响应。确认人以当前登录账号和审计记录为准，验证时间对应响应中的 `lastValidatedAt`。

### 11.6 模型生命周期动作

| 1 | 保存草稿 | 保存当前模型定义和字段修改 | 不校验、不生成 dbt 实现、不建表 |
| 2 | 校验 | 检查模型定义、字段、依赖和转换是否完整 | 不生成可执行修订、不建表 |
| 3 | 提交实现 | 根据已通过校验的草稿生成可执行实现修订和候选版本 | 不代表目标物理表已经构建 |
| 4 | 发布与物化 | 构建候选、调用 Airflow/dbt 物化目标表，并完成工程验证、质量治理、发布登记和上线就绪 | 不会替代独立质量规则的定义与运行 |

页面上方会显示当前“下一步”。按钮启用状态以页面提示为准；修改任何模型字段后，必须重新从“保存草稿”开始。不要在打开旧候选弹窗后继续使用过期选择；关闭弹窗、刷新模型状态，再操作当前候选。

点击“发布与物化”后，弹窗中的交付流程依次为：

1. **构建**：生成并运行候选构建，成功后状态为“完成”；
2. **工程验证**：构建完成后点击“运行工程验证”，检查实现和物理结果；
3. **治理数据质量**：必须存在绑定当前 DWD 物理资产且已发布、已成功执行的质量规则证据；
4. **发布登记**：登记通过门禁的当前版本；
5. **上线就绪**：确认该版本可以作为受治理的当前版本使用。

若“治理数据质量”显示 `MISSING`，说明物理表可能已经构建，但缺少当前资产的质量运行证据。先按第 12 节创建并运行规则，成功后回到弹窗点击“刷新状态”，继续当前允许动作。不要重新建立同名模型或绕过候选版本。

最后在物理资产或查询页面确认 `public.prjdemo_dwd_project_task_snapshot` 存在，包含 12 个业务字段、8 行数据和 8 个唯一 `task_snapshot_id`，并记录 ModelSpec ID、实现修订、候选发布 ID、Airflow/dbt 运行 ID。

> “物化成功”和“质量规则通过”是两件事。只要物理表已成功物化且查询账号有权限，SQL/报表在技术上可以查询该表；但没有质量证据时，模型的受治理发布流程可能仍停在“治理数据质量”，不能把它记为完整上线。

通过条件：DWD 物理表 12 列、8 行、8 个唯一任务快照 ID，并能追溯到已确认的 ODS 源资产和当前模型版本。

### 17.1 注入脏数据

3. 结构方式引用当前表结构；落表方式选择“全量重建现有表”。
4. 页面提示将删除并重建表时，复核目标名称后再确认。
5. 立即执行，确认 ODS 仍有 8 行且坏记录进度为 120。
6. 重新执行 DWD 物化，使当前 DWD 反映脏批次。
7. 执行第 12.3 节的“项目任务进度范围校验”，预期 SQL 成功但失败记录数为 1，失败样本为 `PTS_PRJB_T03_20260901`。

### 17.2 恢复干净数据

1. 用同样的全量重建方式重新上传 `prjdemo_project_task_clean.csv`。
2. 确认 ODS 8 行且所有进度位于 0 到 100。
3. 重新执行 DWD 物化。
4. 重新执行主完整性规则和可选进度范围规则，预期失败记录数均恢复为 0。

6. 刷新指标和 BI，保存恢复后的运行证据。

完成负向演练的证据必须成对出现：一次 1 条失败的运行和一次恢复到 0 条失败的运行。

## 18. 常见问题定位

| 现象 | 优先检查 | 判定 |
| --- | --- | --- |
| 上传按钮不可用 | 用户数据分级权限、文件格式、50 MB 限制 | 未解决前停止 |
| 保存计划后没有 ODS 数据 | 是否进入计划详情点击“立即执行” | 保存启用不等于立即执行 |
| 质量规则检测对象为空 | 默认数据湖、元数据采集、资产 UUID | 不要手填不存在的数据集 |
| “维护来源”的来源数据集为空 | ODS 是否进入当前账号可见的资产列表；负责人、部门、分级和权限是否完整 | 先修复资产可见性 |
| 已选来源数据集但目录资产为空 | 数据集下是否存在表结构和字段元数据；当前部门是否允许读取 | 先完成元数据采集/权限治理 |
| 来源已登记但模型物理来源为空 | 是否同时为 `CONFIRMED`、`AVAILABLE`、`CURRENT`，是否属于同一规划方案 | 重新加载并在维护来源中核对 |
| “字段关联”按钮不可用 | 新模型是否尚未首次保存 | 初次字段录入不依赖该按钮 |
| “从表/视图导入”按钮不可用 | 当前版本尚无字段级表结构导入契约 | 使用“插入行数 → 插入字段”手工录入 |
| 字段标准或字段密级看不到 | 是否点击了“字段显示设置” | 展开隐藏列后再配置 |
| 事实模型校验失败 | 业务过程、周期快照事实形态、快照日期语义、TIME 字段 | 逐项补齐 |
| DWS 聚合校验失败 | 每个输出是否明确为分组字段或聚合字段 | 不要保留悬空输出 |
| 质量运行失败 | 先区分 SQL_EXECUTION_FAILED 与有失败样本 | SQL 错误不等于数据不合格 |
| 页面已保存但无物理表 | 是否只保存草稿或提交实现，尚未完成“发布与物化”中的构建 | 回到操作流程执行当前下一步 |
| 提交实现提示 `MODEL_SPEC_PERSISTENCE_CONFLICT` | 运行镜像是否包含候选外键修复；是否仍在使用旧服务 | 重建并重启 dts-platform 后刷新页面，不直接改数据库 |
| 提交实现提示 `DBT_DRAFT_SYSTEM_FAILURE` | 查看关联 ID 对应服务日志；确认 dbt 草稿生成路径 | 不重复创建同名模型 |
| dbt 编译提示 source/table not found | 当前候选是否从已钉定来源生成完整 `source + table` 定义 | 刷新候选，不手工修改运行目录中的 YAML |
| 校验提示 `SOURCE_PROJECT_MODEL_DUPLICATE` | 是否有同一来源和物理目标的重复候选/草稿 | 刷新模型状态并只保留当前模型，不另建副本 |
| 物化提示 `MODEL_RELEASE_CANDIDATE_VERSION_CONFLICT` | 页面是否仍持有重新校验前的候选选择 | 关闭弹窗、刷新状态，重新使用当前候选 |
| 质量子规则成功但总流程仍运行中 | 刷新运行记录并检查收尾调度；执行器应归一为 `_system:scheduler` | 不把内部执行器当作登录用户 |
| DWS 数值错误 | DWD 行数、分组键、COUNT/AVG/SUM 字段 | 不在 BI 层修数 |
| 看不到完整血缘 | 各阶段对象版本或运行是否真实关联 | 标记缺口，不伪造系统证据 |

## 20. 清理原则

默认不清理 Demo 对象，以便复核证据。需要清理时，先确认没有其他人复用这些对象，再按下游到上游顺序人工处理：

`BI 看板 → 指标 → 质量任务/规则 → DWS → DWD → 规划绑定 → ODS 资产/接入计划 → ODS 物理表`

清理属于单独的破坏性操作，不在本 Runbook 中提供自动删除脚本。删除后应记录删除人、时间、对象 ID，以及物理表是否仍可恢复。
