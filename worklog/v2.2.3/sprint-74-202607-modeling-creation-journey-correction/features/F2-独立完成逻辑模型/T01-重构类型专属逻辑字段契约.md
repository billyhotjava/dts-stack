# T01：重构类型专属逻辑字段契约

**优先级**：P0  
**状态**：DRAFT  
**依赖**：F1

## 目标

建立不含实现设置的四类逻辑 schema，并区分技术字段编码和业务字段名称。

## 技术设计（Contract-first）

- **输入契约**：ModelSpec update v2；`fields[].name:string`、`displayName?:string`、`dataType`、`nullable`、`role`。
- **输出契约**：新 revision snapshot；新写 name 匹配 `^[a-z][a-z0-9_]{0,62}$`；displayName 非空。
- **引用规则**：grain keys、time fields、SCD fields、hierarchy levels、standardBindings、implementation mappings 统一引用 `name`。
- **数据流**：逻辑表单 → v2 decoder → validateView → snapshot codec → JSONB revision/checksum。
- **错误路径**：重复/非法编码 422；旧中文 name 可读并返回 compatibility issue，不在 GET 失败；旧字段未修改时可保留旧编码/缺失 displayName，新增或修改该字段时执行新规则；旧客户端省略已存在字段的 displayName 时由服务端保留原值。
- **复用点**：账本 L09/L10/L11；现有 ModelSpec fields JSONB 与 checksum。
- **实现方案**：expand `displayName` → codec 兼容 → UI 双字段 → 时间/SCD/层级改 Select → 最后禁止新中文 code。

## UI 交互规格

- 字段行基础区只显示：字段编码、业务名称、数据类型、作用、可空；
- 来源字段移动到数据实现映射；
- 安全等级和标准进入“治理要求”折叠区，不计 DESIGNED blocker；
- 业务时间只列 role=TIME 的字段；无选项时引导添加 TIME 字段。

## 影响范围

ModelSpecContract/codec/schema、ModelSpecFieldsTab、LogicalDesignStage、standard binding ref、tests。
