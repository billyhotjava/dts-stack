# T02：重构无默认类型的业务目的创建向导

**优先级**：P0  
**状态**：DRAFT  
**依赖**：F1/T01

## 目标

在用户理解“每行代表什么”后再选择模型类型，不允许模型中心默认 FACT。

## 技术设计（Contract-first）

- **输入契约**：`initialModelType?: ModelSpecType`；没有合法深链参数时为 `undefined`。
- **输出契约**：选择卡写入 `modelType`；提交仍调用现有 create API。
- **数据流**：点击新建 → 选择业务目的卡 → 加载类型专属上下文 → 最小草稿 → 进入逻辑页。
- **错误路径**：未选类型不触发 API；维度定义缺失提供受控 returnTo；服务端目标层解析失败时不由前端猜 layer。
- **复用点**：账本 L01/L02；现有 Drawer、plan/domain/dataMart/DimensionDefinition 选择器。
- **实现方案**：移除 fallback `"FACT"`；将下拉改为四张决策卡；锁定类型场景保留但显示“由入口带入”。

## UI 交互规格

- 卡片必须包含：
  - DIMENSION：项目、客户、组织；用于分类/筛选；不是一次事件；
  - FACT：付款、报销、立项事件；每行一次发生；
  - SUMMARY：按固定粒度聚合的指标结果；
  - APPLICATION：报表/API/应用专用输出。
- 卡片只解释业务模型类型；目标层以只读说明单独展示，当前版本不提供 DIM/五层切换。
- 键盘可聚焦和选择；不能只用颜色表达选中状态。
- 成功 toast 为“已保存逻辑草稿”，不说“已完成建模”。
