# T01：固定模型类型与目标层边界

**优先级**：P0  
**状态**：DRAFT  
**依赖**：F0

## 目标

让用户和契约明确区分 `modelType` 与 `layer`，同时保持 v2.2.3 已有经典分层映射，不在本 Sprint 引入 `DIM` 层或第二套分层策略。

## 技术设计（Contract-first）

- **输入契约**：`ModelType= DIMENSION | FACT | SUMMARY | APPLICATION`；建设计划继续使用既有 `CLASSIC_ODS_DWD_DWS_ADS`。
- **输出契约**：复用并提升既有 `public static ModelSpecContract.targetLayer(ModelType): Layer` 为唯一服务端解析点，固定为 `DIMENSION/FACT→DWD`、`SUMMARY→DWS`、`APPLICATION→ADS`。
- **数据契约**：不扩展 Layer 枚举、不新增 `DIM`、不新增分层策略字段或迁移；历史 revision 的 `layer` 原样保留。
- **错误路径**：缺失/未知 modelType 按创建契约返回 400；客户端提交 layer 与服务端解析不一致返回 422；不得由前端猜测或覆盖 layer。
- **复用点**：账本 L03/L04；既有 `ModelSpecContract.targetLayer/matchesTargetLayer`、ModelSpec create/update/import 校验与建设计划经典策略。
- **实现方案**：GitNexus 更新到 HEAD 后先对 `targetLayer/matchesTargetLayer/expectedLayer` 做 upstream impact；不新建 resolver；将 `ModelSpecContract.targetLayer` 提升为公开 canonical 函数，`WarehousePlanResource.expectedLayer` 改为调用它，创建、更新、导入共用；前端只展示服务端结果。独立 `DIM` 层作为未来单独 ADR/Sprint，不在本任务预埋半成品枚举。

## UI 交互规格

模型创建卡明确显示“模型类型描述业务语义，目标层由当前版本经典规则确定”；用户不选择 layer，也不出现 DataWorks 五层切换入口。详情页分别展示模型类型和目标层，避免把 `DIMENSION` 误解为必须落到 `DIM`。

## 影响范围

`ModelSpecContract.targetLayer/matchesTargetLayer`、`WarehousePlanResource.expectedLayer`、ModelSpec create/update/import layer validation、UI 与 tests；不修改 WarehousePlan policy schema、Layer 枚举或 Liquibase 约束。
