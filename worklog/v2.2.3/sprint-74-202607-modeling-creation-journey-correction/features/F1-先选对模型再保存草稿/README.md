# F1：先选对模型再保存草稿

**优先级**：P0  
**状态**：DRAFT

## 目标

让用户在提交前理解四类模型的业务含义，并由计划分层策略决定目标层，不再被默认 FACT 带入错误路径。

## 契约定义

| 类型 | 契约 | 关键字段/签名 |
|---|---|---|
| Policy | `WarehousePlanLayerScheme` | 新增 `DATAWORKS_5_LAYER_V1` |
| Resolver | `resolve(layerScheme, modelType)` | 经典与 DataWorks 映射见 Sprint README §7.1 |
| Create | `POST /api/modeling/model-specs` | modelType required；服务端解析 layer |
| UI | `/modeling/models` 创建抽屉 | 无默认值，先选业务目的卡 |

## UI/UX 规格

- **入口**：模型中心“新建模型”；不新增菜单。
- **布局**：

  ```text
  ┌ 新建模型：先确定要描述什么 ──────────────┐
  │ [稳定对象/维度] [业务事件/明细]           │
  │ [聚合结果/汇总] [消费输出/应用]           │
  │ 每张卡：适用场景 / 不适用场景 / 示例       │
  │ 下一步：计划、分类、名称、可选用途          │
  └──────────────────────────────────────┘
  ```

- **四态**：选项加载中 skeleton；策略失败保留用户选择并禁止提交；无维度定义提供返回安全跳转；保存成功进入逻辑设计。
- **操作走查**：进入 → 阅读卡片 → 选“稳定对象” → 选择项目维度 → 保存 → 详情显示 DIMENSION 和策略投影层。
- **兼容**：Chrome95；深链 `modelType` 只预选并显示来源，不隐式提交。
