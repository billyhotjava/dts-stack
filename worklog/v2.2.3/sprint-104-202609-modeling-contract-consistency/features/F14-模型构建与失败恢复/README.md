## 用户目标与场景

在现有模型工作台发起构建，执行前发现明确配置错误，执行后看到准备、加工、核验和结果回写的真实状态。SQL成功但后续步骤失败时，满足严格证据和权限条件后可继续核验或补写结果，不重复执行SQL；无法证明安全时明确拒绝自动续跑，并提供正常新构建路径。

覆盖新建明细/汇总、同模型重复构建、修改后新构建、旧模型以及结构创建模式。保留原版本、来源、密级和权限检查。物化完成即建模完成，后续治理质量由[F13](../F13-发布质量对账状态机与阻断可见性/README.md)处理。

## 界面与验收示例

入口按 [F15](../F15-构建与发布分离及交付状态解耦/README.md) 改为独立构建操作：F15-T02 负责摘要/命令边界，F15-T04 接入本 Feature 的进度与恢复内容。只显示构建内部准备/加工/核验/回写、首发原因、已完成结果和服务端允许动作，不嵌入登记、质量、治理、发布、上线表单。构建结果确认后即可返回列表。空态说明未发起；加载保留模型；读取失败显示未知；恢复受理后显示进行中，失败不清除历史成功，但当前目标有效性须核验。无新增页面菜单，Chrome95/1366×768/窄屏回归。

给定同批次SQL全部成功且目标/来源版本未变，制造sync-probe响应失败；用户选择继续核验，实际SQL调用数不变、目标数据校验和不变，关系重新核验并完成回写，F13可以继续处理质量。这是核心验收，不以HTTP返回200替代。
