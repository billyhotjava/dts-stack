# T27-统一准入判定与拒绝结果结构化

**优先级**：P0  **状态**：IN_PROGRESS  **依赖**：T25

## 目标

同一组已加载事实由一套判定规则服务保存、提交和投影，拒绝能说明具体上游；避免为批量可用性新增逐项查库或第二套规则。

## 输入、输出与数据流

既有实现保存/作者草稿/提交 HTTP 请求形状不变。保留原外层 code、HTTP 状态及既有 detail 字段，追加：

`detail.issues: [{modelSpecId: UUID|null, reason: string, expected: UpstreamPin|null, actual: UpstreamPin|null, fieldPath: string|null}]`，以及 `detail.totalIssues: int`、`detail.truncated: boolean`。最多返回 50 条，按 modelSpecId、fieldPath、reason 稳定排序，totalIssues 表示未截断数量。命令级输入方式错误允许 modelSpecId=null；不可读对象只回显请求已有 ID，expected/actual=null，不暴露名称、版本或 checksum。

数据流：既有生命周期/作者服务 → 批量加载 `AdmissionContext` → `ModelImplementationInputPolicy` 内纯判定 → 原有错误转换追加 issues。`AdmissionContext` 含 owner、候选当前设计与被引用修订、已提交实现、权限结果、依赖闭包，均属于同一一致性只读快照。新候选判定与已选锁定比较分别输出，不能因旧引用漂移就宣称最新候选也不可选。

## 技术设计与复用

- 将 validateUpstream 中的数据读取和规则运算分离；运算核心禁止 JDBC/仓储调用。批量读取继续使用 ModelSpecRepository、ModelLifecycleRepository 和现有权限/依赖 owner，不增加台账。
- ACTIVE 校验必须同时验证实现的设计 revision/modelChecksum 与当前候选匹配、实现 pin 非空、类型/分层、跨方案发布、自引用和闭包循环。不能因“投影不比较旧 pin”而跳过实现对设计的一致性检查。
- 已选锁定按六字段判定，设计不变但实现 revision/checksum/dbtUniqueId 改变仍拒绝。首次未锁定选择保留 pinCurrentUpstreamImplementations；已锁定对象不隐式升级。
- 批量 loader 一次准备共同闭包/权限结果；禁止每个候选调用现有递归 reachesOwner 再查库。预算与超限行为按 T26。
- 错误从所有不合格输入聚合；物化/发布入口复用同一 reason 映射但保留阶段规则，不强行合并成同一控制面。
- 不修改 ImplementationView.status 的持久化类型，不替换全仓字符串比较。仅对投影边界归一化原始状态，未知值拒绝；作者未提交草稿不撤销有效的 ACTIVE 实现。

## 影响范围与 UI

ModelImplementationInputPolicy、ModelLifecycleService、相关作者服务的调用适配；ModelSpecRepository/ModelLifecycleRepository 批量读取；现有 Resource 错误转换。T26 可直接复用纯判定；T28 把 issues 显示在上游行和提交提示中，保留用户输入。无数据库结构变更。
