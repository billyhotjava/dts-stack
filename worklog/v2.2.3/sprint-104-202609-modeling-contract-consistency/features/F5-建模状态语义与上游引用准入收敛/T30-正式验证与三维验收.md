# T30-正式验证与三维验收

**优先级**：P0  **状态**：DRAFT
**依赖**：T25–T29 源码全部进入 Git。

## 目标

在正式构建产物与运行实例上完成 F5 的架构、界面、端到端三维验收，留存可复查证据。

## 输入、输出与数据流

输入为开发目录已 commit 并 push 的提交 SHA。按项目路径约束执行：开发目录只做代码修改、静态检查、review、commit、push；部署目录确认分支与工作区状态后 `git pull --ff-only`，核对 SHA 后使用仓库正式构建、测试与打包入口。禁止复制未提交文件或编译产物到部署目录，禁止容器内改代码或打补丁镜像。

输出为 IT-29–IT-32 证据与镜像身份归档，落 `../../it/`。

## 技术设计

### 验收用例

| 用例 | 覆盖 | 关键判定 |
|---|---|---|
| IT-29 | 联合建模不被收紧 | 设计步骤勾选同规划未发布 DWD 并保存成功；实现步骤该上游置灰且原因可读 |
| IT-30 | 可用性投影正确 | 上游完成实现提交后，DWS 实现步骤该上游转为可选；勾选提交成功 |

| IT-32 | 契约与准入补洞 | 六字段载荷经真实保存与物化；归档上游发布预检被阻断 |

### 分阶段报告

按项目约定分别报告，未执行阶段不得宣称完成：源码与测试、正式构建与交付包、容器部署、真实页面验收。记录提交 SHA、镜像 ID 与 digest、版本清单、包校验和。在线与离线环境使用同一提交对应的正式产物，重打标签不等于一致性验证。
