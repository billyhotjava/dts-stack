# T28-上游选择器可用性与依赖变化展示

**优先级**：P0  **状态**：DRAFT
**依赖**：T26（消费可用性投影）、T27（消费 reason 文案源）。

## 目标

用户在实现步骤勾选上游前就能看出该上游可否引用及原因；设计步骤保持可引用未发布上游。

## 输入、输出与数据流

消费 `POST /api/modeling/model-specs/upstream-availability`（T26）与既有 `GET /api/modeling/model-specs/{id}/dependencies`（`ModelSpecResource.java`:154，返回 `DependencyGraph`）。不新增后端调用形态，不改写接口。

现状：候选列表数据源是 `listModelSpecs()`（`modelWorkbenchService.ts`:578），过滤条件只有 `status !== "ARCHIVED"`（`:583`）；实现步骤的候选过滤在 `ModelImplementationBindingFields.tsx`:116，仅判定兼容模式与分层规则，**不含任何实现信息**。`ModelSpecView` 本身不携带实现字段，因此界面在数据层面无从判断可用性。这是"选完保存才报错"的根因，不是前端遗漏渲染。

数据流：进入实现步骤 → 以当前候选 id 集合调用可用性投影 → 按 `implementationState` 与 `selectable` 渲染 → 勾选时仅允许 `selectable` 为真的行。

## 技术设计

### 1. 两个区块语义分离

- **设计步骤**（`ModelLogicalDependencies.tsx`:18 候选过滤）：不接入可用性投影，不按实现状态过滤或置灰。允许勾选无实现的同规划上游，这是 DWD/DWS 联合建模的正常路径，收紧即为回归。
- **实现步骤**（`ModelImplementationBindingFields.tsx`:302 起）：每行追加可用性标记与不可选原因。`ACTIVE` 正常可勾；`NONE`/`DRAFT`/`UNKNOWN` 置灰且 checkbox 禁用，就地显示一句可执行说明。

现有副标题只显示「类型 · 分层 · 第 N 版」（`:314`），追加实现状态一列，不改动既有三项的措辞与顺序。

### 2. 已选上游的三种变化分开呈现

现有 `staleDependencies`（`:138`）把全部异常合并为一句"当前不可作为上游"。按 `DependencyGraph` 的 `DependencyState` 与新增的 `implementationState` 拆为三类：上游实现已撤回、上游设计版本已前进、上游不可读。每类给出对应动作：前者提示等待上游重新提交实现，中者提供既有的「更新引用至 rN」按钮（`ModelLogicalDependencies.tsx`:41 已有该交互，复用不重写），后者提示联系授权。

### 3. 文案来源

不可选原因与拒绝提示统一取自 T27 的 `reason` 映射，前端维护一张 `reason` 到中文说明的表，禁止在组件内散写字符串。后端新增 `reason` 而前端未映射时，回退显示原始 `reason` 并保证不崩溃。

## UI交互规格

四态见 [F5 UI/UX 规格](README.md#uiux-与四态)。补充约束：

- 可用性投影失败时，候选列表仍须渲染，全部行标为"可用性未知"且允许勾选，由保存期后端判定兜底。界面不得因辅助查询失败而阻断建模，这与 F4 的失败隔离原则一致。
- 投影请求随候选集合变化重新发起；快速切换模型时旧响应不得覆盖新行。
- 置灰行仍显示模型名与版本，不隐藏，否则用户无法理解为何找不到目标上游。
- 分页与视觉沿用既有约定，不新增组件库依赖，Chrome 95 下无新语法。

走查：进入工作台 → 打开 DWS 模型 → 设计步骤勾选未发布 DWD 并保存 → 实现步骤确认该上游置灰且原因可读 → 另开该 DWD 完成实现提交 → 返回 DWS 实现步骤确认转为可选 → 勾选提交 → 观察三类已选变化提示。

## 影响范围

`ModelImplementationBindingFields.tsx`；`ModelLogicalDependencies.tsx`；`modelWorkbenchService.ts`（候选装配与投影调用）；新增 reason 文案映射模块；对应 Vitest 用例。无后端与数据变更。
