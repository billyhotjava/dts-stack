# T28-上游选择器可用性与依赖变化展示

**优先级**：P0  **状态**：IN_PROGRESS  **依赖**：T26、T27

## 目标、输入与 UI 落点

消费 T26 availability 与 T27 issues，沿用 ModelImplementationBindingFields、ModelLogicalDependencies 和 modelWorkbenchService。设计区保留未发布上游选择；实现区以 selectable 判定，绝不以 ACTIVE 或“草稿”代替准入。

## 交互与状态

- 候选显示设计版本、已提交实现版本、准入原因；有独立编辑草稿时，不把原有效实现显示为未提交。
- 已选引用保留自身六字段，与 currentPin 对照。分别呈现设计漂移、仅实现漂移、不可用；显示“当前引用设计 rN / 实现 iM”和最新可读版本。
- “更新引用”是显式动作：展示版本差异后，仅更新该上游的完整 pin；设计也前进时同步既有逻辑依赖版本操作。取消更新保持原 pin 和其他表单输入。移除不可用引用始终可操作，禁选不能锁死移除。
- DependencyGraph 继续用于逻辑依赖关系；它的 CURRENT 不代表实现锁定当前，不扩展节点状态来猜测实现漂移。
- reason 中文映射单一模块；未知 reason 显示“上游暂不可用”及可展开错误码，不把内部常量当主文案。具名错误只使用有读权限的信息。

## 四态、失败隔离与刷新

空列表说明无合规上游；初次加载只影响候选区，不清空已选和编辑内容；正常响应中的 NOT_AVAILABLE 等明确拒绝禁选并隐去不可读对象信息。

网络/超时导致整次投影失败时，显示“可用性读取失败，保存时将重新校验”。保留已选 pin；保留同一 owner/用户/候选版本下先前明确拒绝，不能把所有禁选行一律解禁。仅对已可读且无明确拒绝证据的新候选允许尝试选择，使用本任务的三字段首次锁定兜底；未知可读性不放行。此策略不绕过后端权限/版本校验。

重查触发：进入实现步骤、owner/候选版本或 ID 变化、显式更新引用、手动“刷新上游状态”、页面 focus/visibility 恢复、本端上游提交成功。事件合并去重，同一 owner 同时最多一个有效请求；以 owner ID/revision/checksum、候选及 selectedInputs 的快照和请求序号防串响应。刷新只更新辅助投影，绝不替换草稿/已选 pin。卸载或身份改变取消请求，迟到响应丢弃。

## 二轮评审补充：完整操作闭环

本任务接管原 T29 的六字段装配与保存回显，不再依赖后续任务。新选项保存实际选中完整 pin；已选引用只在明确更新时改变。正常路径外部 Chrome 走查：搜索上游 → 选择 → 保存 → 关闭重开 → pin 不变 → 上游更新 → 返回提示 → 明确更新并保存。

统一实际输入顺序，不按 ID/名称排序生成别名，不混入未进入 implementation.inputs 的逻辑维度引用。删除来源同步重映射 fieldMappings/aggregations/filters/joins；保留原来源身份，无法安全映射时提示并要求用户修复，不能无声改绑。列表分页默认 10、搜索及已选/可用筛选；明确拒绝可移除，有权限时可打开上游；网络失败不清除已知拒绝。与 T31 共用来源身份适配。
