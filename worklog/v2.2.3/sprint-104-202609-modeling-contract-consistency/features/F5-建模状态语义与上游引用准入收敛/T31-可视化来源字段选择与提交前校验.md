# T31-可视化来源字段选择与提交前校验

**优先级**：P0  **状态**：IN_PROGRESS  **依赖**：T25、T26、T27、T28

本任务消费 T28 草稿实际固定的输入，与展示/提交共用来源顺序；T26 最新候选不自动替换已有 pin。

## 目标与现象

`sum(cost_amount)` 引用不存在字段必须在提交实现之前报出目标字段、错误来源与上游，而不是直到物化才失败。现有单模型已通过 Chrome 改成 src_0.actual_cost 并物化成功，但系统校验缺口仍未关闭，见 [现场记录](../../assests/dws-cost-field-issue-20260909.md)。本任务不对用户字段名做猜测或自动替换。

## 契约与完整链路

字段目录计划使用只读 `POST /api/modeling/model-specs/upstream-fields`：

请求 `{ownerModelSpecId: UUID, ownerRevision: int, ownerChecksum: string, inputMode: InputMode, inputs: ImplementationInput[]}`；input 顺序决定既有 src_0/src_1 别名，去重不能改变别名映射；最多 200 输入，owner CAS、权限、pin 漂移处理沿用 T26/T27。

响应 `ApiResponse<{ownerModelSpecId: UUID, ownerRevision: int, ownerChecksum: string, sources: [{input: ImplementationInput|null, index: int, alias: string, schemaState: RESOLVED|UNAVAILABLE, fields: [{name: string, dataType: string, nullable: boolean|null}]}], issues: AdmissionIssue[]}>`。fields 来自固定修订及其匹配已提交实现的输出字段契约；不能偷用最新资产字段或把 placeholder 的字段当业务字段。无物化但输出契约可确定的上游可返回 RESOLVED，此处表示字段契约已解析，不表示已物化。不可读项不返回 pin/fields，统一放入脱敏 issues。

UI ModelVisualTransformationFields → modelInputInspectionApi 封装 → ModelInputInspectionResource 只读目录入口 → T27 pin 判定 → 既有模型/实现字段读取 owner。提交校验复用同一固定版本字段目录；ModelLifecycleService、ModelAuthoringDraftService/DbtImplementationDraftService 的可视化 validate/commit 与 ModelingDbtCompiler 前的校验共享一处语义检查，不新增 SQL parser。T25 已确认上述读取 owner；实际运行覆盖由 T30 验收。

## 校验规则与错误

覆盖 fieldMappings.sourceField、joins.leftField/rightField、聚合来源、groupBy、filters、去重键及现有类型转换所引用的来源；按现有转换阶段区分来源字段与投影后目标别名，不把合法目标别名错当源字段。

限定字段 `src_N.name` 必须属于该 alias 的固定目录；字段映射在多来源时必须限定别名；其余未限定 name 仅在可唯一解析时通过；多来源同名返回 SOURCE_FIELD_AMBIGUOUS，未知返回 SOURCE_FIELD_NOT_FOUND。目录不可确认返回 SOURCE_SCHEMA_UNAVAILABLE，不默许提交。当前来源标识符协议不支持 COUNT(*)，本轮不新增该语法；其他表达式沿用现有解析能力，不新增语法，无法确定依赖时返回 SOURCE_EXPRESSION_UNSUPPORTED。

可视化提交的字段错误返回 422，code=MODEL_IMPLEMENTATION_SOURCE_FIELDS_INVALID，detail.issues 复用 T27 形状并追加 `targetField: string|null, sourceField: string|null, inputAlias: string|null`；reason 取上述字段原因，fieldPath 精确定位设置项。pin 漂移仍返回既有 409，权限沿用原语义。不能把字段错误冒充版本冲突。

草稿暂存允许保留语法可解析但语义未完成的配置，沿用既有作者诊断容器提示；validate/commit 阻断，旧草稿再次提交同样校验。提交/编译再次核对固定 pin，前端下拉不是唯一防线。已提交旧实现的执行入口不得绕过现有校验边界，发现不合法时在进入执行前提供同形诊断，不自动改配置或改库。

本轮针对可视化支持的结构化输入，不声称解决任意 RAW_SQL 静态分析；代码模式继续沿用原校验与运行错误回传，不伪报字段已验证。

## 二轮评审补充：通用输入与完整字段检查

通用输入契约：请求增加 inputMode，inputs 复用既有 ImplementationInput 联合类型；响应 sources 使用 input（对应原始固定输入）、index、alias、schemaState、fields。UPSTREAM_MODEL 返回完整固定 pin；PHYSICAL_ASSET 返回 sourceBindingId/resolvedVersion；GENERATED 返回空外部目录并保留既有生成规则。不可读项不泄露字段或版本。

新增 joins.leftField/rightField 存在性校验；多源映射必须限定 src_N，字段/聚合/过滤通过既有目标到源映射解析，groupBy/deduplicateBy 校验输出字段。COUNT(*) 当前契约不支持，不扩展语法也不显示可选。用户通过字段候选选“模型/字段”，系统生成限定引用。

目录消费草稿实际 inputs，不从最新候选自动替换旧 pin；身份和别名适配由 T28 提供。来源无可验证字段返回明确不可确认原因；不以空目录误判所有合法字段不存在。语义错误草稿可暂存，validate/commit 422；代码模式维持原验证能力。IT-35 加入源表、生成模式、多来源反向选择/删改、错误关联字段与重开恢复。

## 首次创建与失效依赖的修复入口

创建作者草稿只建立可编辑内容，不要求旧设计引用已有匹配实现。首次实现从规范项目模板初始化；已有实现依赖失效时按精确版本及校验和恢复原始包/产物，不重编译旧引用、不自动切换最新版本。权限、模型与实现 CAS、原始产物校验保持。无初始 dependencySnapshot 的统一作者草稿也必须在 validate/commit 中重新解析并核对保存的依赖，不得因快照为空跳过校验。传统代码草稿创建的严格规则保持。

验收追加：先保存 DWS 引用无实现 DWD 的设计，再提交 DWD 实现使其设计从 r2 到 r3；DWS 明确选择 r3/i1 后应能创建、保存并提交作者草稿，无须先退出另存设计。未更新引用时允许保留编辑，但提交须给出依赖拒绝。已有实现仅升级后的新建作者草稿同样验证。

待保存设计依赖解析：readFacts 必须以传入候选设计为根，后续节点按固定修订读取；不能从使用方旧持久化快照重新展开而遗漏新选择。创建后保存失败须保留当前编辑输入，不得回填旧设计。

暂存诊断的事务边界：只读准备/依赖检查的预期领域错误应可由作者暂存消费，不能把保存事务预先标记 rollback-only。权限/CAS 与未处理错误继续由外层写事务阻断；数据库或系统错误不能吞掉。验收包含旧 pin 暂存保留、validate 拒绝和正确更新后的提交/物化。
