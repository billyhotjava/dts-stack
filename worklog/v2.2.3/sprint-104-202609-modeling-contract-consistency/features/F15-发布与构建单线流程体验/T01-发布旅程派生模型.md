# F15-T01：发布旅程派生模型

**状态**：IN_PROGRESS（模块与测试已完成；面板迁移随 T02）；**优先级**：P0；**依赖**：无

## 目标
新增纯函数 `deriveReleaseJourney(input)`，把现有工作台/计划/交付状态/运行绑定 DTO 推导为 8 个阶段、当前阶段、一句 headline 与最多两个动作。页面只渲染结果，不再各处自行判断。

## 技术设计
- 文件：`src/pages/data-modeling/prototype/releaseJourney.ts`（新增），类型见 F15 README §契约。
- 输入：`candidate`、`entryEvidence`、`governanceQuality`、`primaryBlocker`、`releaseActions`、`pageAction`、`buildAction`、`materializationPlan`、`planState`、`deliveryStatus`、`executionBinding`、`blockingWorkspace`、`loadState`（loading/error/ready）。
- 复用：`ModelReleaseWorkflowPanel` 现有 `stepState/governanceStepState/handoffText` 的判定迁入本模块，面板改为调用本模块，禁止两套判定并存。
- 规则：
  1. 阶段状态按候选状态序推进；阶段失败只落在出错阶段，后续阶段为 waiting。
  2. 治理质量：ADVISORY 下缺规则/不合格/过期 → `warning`；BLOCKING → `failed`；策略不可用 → `failed`（系统故障文案）。
  3. 动作只从 `releaseActions/pageAction/buildAction/allowedRecoveryActions/executionBinding.allowedActions/blockingWorkspace.allowedActions` 映射。
  4. `loadState != ready` 时不推进阶段，headline 为"正在读取状态…"/"状态读取失败"。
- 错误路径：未知候选状态 → current 取最后一个 passed 之后的阶段，headline "状态无法识别（<技术详情>）"。
