## 技术设计（Contract-first）

- **输入**：固定提交、目标镜像/运行包清单、当前租户模型版本与实现版本；it/README.md 的 IT-01–IT-07。
- **输出**：it/ 真实浏览器/API/dbt/质量证据；assets/release-plan.md、assets/runbook.md；每项以代码、测试、构建、部署、现场验收分状态记录。
- **数据流**：既有模型工作台→保存/草稿恢复→build-intents→运行时执行→质量/发布门禁→当前产物与资产证据；不新增控制面。
- **错误路径**：遵循 [Feature 共同错误/CAS 约束](README.md)；不得用回退旧值、伪造证据或跳过安全检查隐藏错误。
- **复用与影响范围**：账本 C06–C10 中列出的源码、已有 API/表/组件；不增加平行 owner。编辑已有符号前运行 GitNexus impact，HIGH/CRITICAL 先报告。
1. 完成一致变更集后做一次聚焦 review；契约测试覆盖整套共享样例，不保留无法解释的失败。
2. 按 Node/Vitest/JUnit 正确入口验证；前端生产构建与 Chrome 95、1366×768/窄屏走查分开记录。
3. 同模型连续点击两次物化：分别记录 request/candidate/run/idempotencyKey，按既有同键重放、并发控制或明确二次执行规则验收，不只看页面标签。
4. 编译及会触发编译的测试只在 `/opt/prod/s10/deploy`：开发目录 commit/push → 部署目录确认分支和工作区 → git pull --ff-only → 核对 SHA → 仓库正式测试/构建入口。不得复制未提交源码、产物或使用任意临时编译目录。如需重建运行容器，按会话授权执行；未授权时只完成构建验证。记录提交 SHA、镜像 ID/digest、版本清单和交付包校验和；在线/离线验收使用同一提交的正式包和镜像。
5. 记录失败恢复入口、关联 ID、模型/实现/候选版本和返回码；旧证据不得被标成当前成功。
