# T01：验收基线与契约失败归因

**优先级**：P1  
**状态**：IN_PROGRESS  
**依赖**：无；作为本 Feature 的前置基线任务  
**账本**：[Sprint 账本 C06、C08、C09](../../README.md)

## 目标

固定验收环境、真实数据画像及 13 项契约失败的根因，形成后续任务可复用的证据。

## 技术设计（Contract-first）

- **输入**：当前提交、部署镜像标识、获准使用的测试租户/账号与来源；既有契约测试日志。
- **输出**：it/baseline.md 的 P1–P8 探针结果；assets/domain-profile.md 的实测数据；assets/review-evidence.md 的逐项失败归因和责任 task。
- **数据流**：模型工作台 → 既有读取/阶段校验接口 → 当前租户模型和来源；只读探针先行，写入金丝雀前确认目标与清理边界。
- **错误路径**：遵循 [Feature 共同错误/CAS 约束](README.md)；不得用回退旧值、伪造证据或跳过安全检查隐藏错误。
- **复用与影响范围**：账本 C06、C08、C09 中列出的源码、已有 API/表/组件；不增加平行 owner。编辑已有符号前运行 GitNexus impact，HIGH/CRITICAL 先报告。
1. 用 Node 原生入口重跑契约测试；逐项分为实现缺陷、Schema 缺失、样例滞后或环境问题，不能用修改期望值掩盖缺陷。
2. 核对同一租户下的模型、草稿、实现版本以及 dbt/PostgreSQL 执行目标；记录登录、迁移、Chrome 95 与离线依赖基线。
3. 对获准样本统计字段数、复合键重复/空值、TYPE2 配置数量、旧 implementationPolicy 与当前 settings 差异；只汇总，不导出敏感明细。

## UI 交互与边界

使用模型工作台打开一个现有模型，读取当前配置和校验结果；不自动物化或重启服务。
四态和浏览器基线复用 Feature 规格；失败保留编辑，成功绑定当前版本。
