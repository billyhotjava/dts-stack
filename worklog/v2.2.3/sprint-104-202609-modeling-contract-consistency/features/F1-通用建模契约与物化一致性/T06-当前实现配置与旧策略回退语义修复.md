# T06：当前实现配置与旧策略回退语义修复

**优先级**：P1  
**状态**：IN_PROGRESS
**依赖**：T07 已冻结保存/执行能力边界；T02：字段存在性与空值语义  
**账本**：[Sprint 账本 C05、C07](../../README.md)

## 目标

用户选择全量或清空分区后，重开和编译仍使用明确的新值。

## 技术设计（Contract-first）

- **输入**：契约 K5；settings.loadStrategy:string；settings.partitionFields:string[]；materialization:string；可选旧 implementationPolicy。
- **输出**：当前实现配置优先；明确 FULL 与 [] 不触发历史回退；展示、保存、编译使用相同策略。
- **数据流**：物理实现控件→PUT implementation→settings_json/实现修订→加载 modelDraftFromView→执行计划→物化。
- **错误路径**：遵循 [Feature 共同错误/CAS 约束](README.md)；不得用回退旧值、伪造证据或跳过安全检查隐藏错误。
- **复用与影响范围**：账本 C05、C07 中列出的源码、已有 API/表/组件；不增加平行 owner。编辑已有符号前运行 GitNexus impact，HIGH/CRITICAL 先报告。
1. 按字段是否存在区分未设置、明确值、明确清空，不用 truthiness 合并有效 FULL/空列表。
2. 当前实现缺少字段时才读取旧 policy；旧模型无实现时保持兼容，不能同时维护两个写 owner。
3. FULL/INCREMENTAL 与 materialization 联动检查；当前适配器不支持分区时展示真实能力，禁止恢复旧分区。
4. 分别覆盖普通可视化实现和保留可视化快照的 DBT_MANAGED 模型回显路径。

## UI 交互与边界

加载方式改为全量→清空分区→保存→退出重开→查看编译预览，值始终一致。
四态和浏览器基线复用 Feature 规格；失败保留编辑，成功绑定当前版本。
