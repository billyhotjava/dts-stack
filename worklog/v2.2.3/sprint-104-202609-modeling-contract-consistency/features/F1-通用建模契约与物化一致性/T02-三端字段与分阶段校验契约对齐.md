## 目标

同一模型在相同操作阶段，经页面、Java 与 JSON Schema 校验得到相同结果。

## 技术设计（Contract-first）

- **输入**：契约 K1、K2；modelType；businessProcessId/subjectDomainId/dataMartId 为 UUID 或 null；grain、fields；当前操作阶段。
- **输出**：兼容现有 contractVersion=2 的字段白名单及分阶段规则矩阵；统一的 field/code/severity 校验结果，不新增平行验证 owner。
- **数据流**：保存/暂存/提交入口 → 前端契约 → ModelSpecResource / ModelAuthoringDraftResource → ModelSpecContract / 阶段门禁 → 既有模型与修订存储。
- **错误路径**：遵循 [Feature 共同错误/CAS 约束](README.md)；不得用回退旧值、伪造证据或跳过安全检查隐藏错误。
- **复用与影响范围**：账本 C01、C06、C07 中列出的源码、已有 API/表/组件；不增加平行 owner。编辑已有符号前运行 GitNexus impact，HIGH/CRITICAL 先报告。
1. 补齐 Schema 的创建、更新和视图字段；合法业务过程/主题域不得被 additionalProperties 拒绝，真正未知字段仍拒绝。
2. 按操作固定格式、阶段完整性、治理三类规则；保存草稿不套用发布条件；已填写的非法 UUID、错类型引用仍报错。
3. Java、TypeScript、Schema 复用同一组正反例，覆盖 DRAFT_SAVE、DESIGNED、IMPLEMENTATION_READY、RELEASE_READY 及创作草稿提交映射。
4. 明确 null、缺失、空数组和全量替换语义；保持已有 ETag/CAS、租户隔离与错误外壳，不改变既有审计。
5. 键的语义以完整 grain.keys 为粒度声明，fields 的 KEY 标记必须与其集合一致；不得自动取交集或并集。草稿中可暂存不一致并呈现修复项，进入 IMPLEMENTATION_READY/RELEASE_READY 和编译/执行前必须拒绝不一致、重复键、未知字段。T04 负责各消费端及反例验证。
6. 具体操作映射、空值与阶段约束见 [contract-matrix](../../assets/contract-matrix.md)。输入能力由 T07 先冻结保存与执行两层边界，不以新增历史引擎为前提。

## UI 交互与边界

模型基本信息→保存草稿→继续补齐→提交/发布与物化；字段旁提示缺失位置，阶段阻断显示当前阶段和可操作修复项。
四态和浏览器基线复用 Feature 规格；失败保留编辑，成功绑定当前版本。
