# T04：复合粒度键与质量测试生成一致

**优先级**：P1  
**状态**：DRAFT  
**依赖**：T02：键和加载方式规则；T01：复合粒度样本  
**账本**：[Sprint 账本 C03、C07](../../README.md)

## 目标

质量唯一性与模型完整粒度键一致，不把复合键首列当作唯一键。

## 技术设计（Contract-first）

- **输入**：契约 K4；grain.keys:string[]；KEY 字段；loadStrategy；字段空值约束；当前模型/实现 revision 和 checksum。
- **输出**：单键/复合键/无键对应的确定性 SQL/YAML 检测产物；复合唯一性覆盖全部键。
- **数据流**：字段管理配置 KEY→保存→lifecycle/compile→ModelSpecCompilerProjection→ModelingDbtCompiler→dbt 检测产物→lifecycle/tests/发布工程证据。
- **错误路径**：遵循 [Feature 共同错误/CAS 约束](README.md)；不得用回退旧值、伪造证据或跳过安全检查隐藏错误。
- **复用与影响范围**：账本 C03、C07 中列出的源码、已有 API/表/组件；不增加平行 owner。编辑已有符号前运行 GitNexus impact，HIGH/CRITICAL 先报告。
1. 复合键检查完整组合，不能 findFirst 后只对首列 unique；每个必需键分别非空。消费 T02 的键一致性约束，编译与执行前检查 grain.keys 与 fields.KEY 集合一致、无重复且均引用真实字段；不得分别选用不同键集合。
2. 统一 runnable schema 与独立 tests.yml 两条生成路径；无键全量不发明唯一性测试。
3. 检测完整重复组合，不通过字符串拼接制造碰撞；标识符继续走现有校验/引用机制。
4. 复用自有 SQL 或已打包宏；不得增加离线环境需要临时下载的依赖。若引入静态宏，T08 必须验证运行包完整性。

## UI 交互与边界

字段管理可设置多个键，质量结果能定位重复组合及涉及列；正常跨月项目数据不得失败。
四态和浏览器基线复用 Feature 规格；失败保留编辑，成功绑定当前版本。
