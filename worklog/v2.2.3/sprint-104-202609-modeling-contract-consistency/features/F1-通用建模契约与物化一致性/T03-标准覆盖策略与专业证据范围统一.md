## 目标

发布标准覆盖只约束策略要求的字段，且已声明标准引用的有效性不被遗漏。

## 技术设计（Contract-first）

- **输入**：契约 K3；StandardCoverage=NONE|KEY_AND_MEASURE|ALL_FIELDS；ModelField.name/role；StandardBinding 的引用 ID 与正整数版本。
- **输出**：必绑缺失、已有引用失效、专业服务不可用分开归因；GateBlocker 保留 code/field/message/repairRoute。
- **数据流**：发布与物化面板→stage-gates/发布准入→withGovernancePolicy→applyStandardCoverage→专业标准证据读取→当前版本门禁结果。
- **错误路径**：遵循 [Feature 共同错误/CAS 约束](README.md)；不得用回退旧值、伪造证据或跳过安全检查隐藏错误。
- **复用与影响范围**：账本 C02、C07 中列出的源码、已有 API/表/组件；不增加平行 owner。编辑已有符号前运行 GitNexus impact，HIGH/CRITICAL 先报告。
1. 使用两个集合：R=治理策略要求绑定的字段，B=模型中实际声明绑定的全部字段。只对 R 检查缺失；专业证据读取遍历 B，不能对未绑定的策略外字段强制补绑，也不能遗漏 B 中策略外字段。NONE 仅令 R 为空，不跳过 B。
2. 区分必绑缺失和已有引用有效性：普通属性未绑定不误报；已绑定但失效的引用按固定规则检查。
3. DRAFT_SAVE 允许暂存版本已失效的合法引用；RELEASE_READY 对 B 中 STALE/UNKNOWN 阻断并保留准确归因。NONE 且 B 为空不调用专业证据服务；缺失绑定和已有失效引用分别报告。格式非法或跨租户引用仍遵循既有校验。
4. 复用专业标准 owner；保留 UNKNOWN 与 STALE，不把不可用吞为成功或笼统缺标准。

## UI 交互与边界

四态和浏览器基线复用 Feature 规格；失败保留编辑，成功绑定当前版本。
