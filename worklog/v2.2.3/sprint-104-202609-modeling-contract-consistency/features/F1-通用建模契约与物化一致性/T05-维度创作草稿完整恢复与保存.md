# T05：维度创作草稿完整恢复与保存

**优先级**：P1  
**状态**：IN_PROGRESS
**依赖**：T07 已冻结保存/执行能力边界；T02：完整字段及 null/缺失语义  
**账本**：[Sprint 账本 C04、C07](../../README.md)

## 目标

维度的历史字段绑定和层级经暂存、关闭、恢复、提交后完整不变。

## 技术设计（Contract-first）

- **输入**：契约 K2；dimensionProfile.hierarchies[]；scdPolicy.type=NONE|TYPE1|TYPE2；effectiveFromField/effectiveToField/currentFlagField:string|null；草稿版本。
- **输出**：草稿拥有完整 dimensionProfile；保存提交使用当前草稿值，不从旧模型静默覆盖。
- **数据流**：模型工作台编辑→authoring-drafts 保存→authoring-context 恢复→modelDraftFromAuthoringSnapshot→modelDraftToUpdateCommand→草稿提交/模型修订。
- **错误路径**：遵循 [Feature 共同错误/CAS 约束](README.md)；不得用回退旧值、伪造证据或跳过安全检查隐藏错误。
- **复用与影响范围**：账本 C04、C07 中列出的源码、已有 API/表/组件；不增加平行 owner。编辑已有符号前运行 GitNexus impact，HIGH/CRITICAL 先报告。
1. 草稿完整承载历史字段与层级，初始化和恢复都复制全部有效配置，保持与基线隔离。
2. 优先级固定：当前编辑→当前创作草稿→模型基线→新建默认；只有确实缺失时回退。
3. TYPE2 改 TYPE1/NONE 时清理不适用绑定；删除/重命名被引用字段时显式校验和修复，不静默改回旧字段。
4. 保存失败保留用户编辑；过期草稿版本按既有冲突契约处理，不覆盖别人的更新。

## UI 交互与边界

历史策略与层级控件→暂存→关闭→重新打开→恢复草稿→提交；错误定位具体引用字段。TYPE2 元数据允许编辑、暂存和提交模型修订；提交配置不等于发布或启动历史维护，执行限制由独立门禁说明。TYPE2→NONE 仅清除配置中的专属绑定，不删除物理表字段或业务数据。
四态和浏览器基线复用 Feature 规格；失败保留编辑，成功绑定当前版本。
