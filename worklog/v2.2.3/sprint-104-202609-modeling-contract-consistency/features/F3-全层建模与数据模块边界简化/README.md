# F3：全层建模与数据模块边界简化

**优先级**：P1  
**状态**：IN_PROGRESS
**来源**：2026-09-07 用户确认 ODS 正向建模缺口，并要求物化后完成建模、数据资产工作归“数据”模块。  
**目标**：用户无需先创建接入任务就能设计 ODS→DWD→DWS→ADS，按“设计→实现配置→物化”完成建模，再按需进入数据管理办理接入、资产治理和分析使用。

## 契约与范围

唯一新增规范为 [F3 边界契约](../../assests/F3-modeling-data-boundary.md)：K31–K36 定义模型/逻辑依赖、结构物化、完成证据、接入绑定及资产交接；C19–C26 为可复用账本。K31–K36 已实施部分的冻结细节见实施审查记录；本轮候选占用协议增量按审查整改契约单独冻结。

只扩展现有 ModelSpec、草稿/实现/候选、接入、目录/质量/serving owner；首批无数据结构物化限定现有 PostgreSQL 普通表。接入适配器不新增类别，ODS 不被当作 FACT。四层可共同设计，不增加一键全链调度。

F2 的四步向导和模型页治理表单作为既有实现基线保留记录；与新边界冲突的页面/完成条件由本 Feature 接续收敛，不重复登记为新服务开发，也不删除原有证据。产品“建模完成”与工程 Task/Sprint DONE 不同，后者仍需正式测试、发布和实际验收。

## UI/UX 规格

- 入口：现有模型工作台；启用“创建贴源表”，ODS 字段页只显示贴源定义所需项目。
- 三个内容页：模型设计 / 实现配置 / 物化；每页一个主动作，只在需要时检查当前条件。可先暂存多层草稿，再补映射与目标。
- 物化成功：显示当前版本与真实目标结果，“返回模型列表”为主动作，“去数据管理”为次动作；不要求继续填写规则、资产负责人或分析配置。
- 数据落点：`/catalog/search?view=table` 及既有详情/接入/治理入口。资产和模型双向导航必须保留身份、环境与返回位置；不新增菜单。
- 四态、历史 step 兼容及帮助统一遵循 [契约第 4 节](../../assests/F3-modeling-data-boundary.md#4-ui-落点)。加载失败不能当成空数据，未保存输入和真实错误不因页面精简丢失。
- 主走查：无接入新建 ODS→设计 DWD/DWS/ADS 并引用版本→创建表结构→结束建模→数据模块绑定接入→写数→维护同一资产。治理/分析失败只在数据模块处理。
