# T18：三步建模页面与分阶段约束收敛

**优先级**：P1  
**状态**：IN_PROGRESS
**依赖**：T15 的阶段/导航/深链契约、T16/T17；复用 F2/T10 的草稿保护、单主动作和帮助能力。

## 目标

工作台仅以“模型设计→实现配置→物化”呈现建模主流程；物化完成后用户可以离开，不再进入资产治理必填步骤。

## 技术设计

遵循 [F3 阶段矩阵与 UI](../../assets/F3-modeling-data-boundary.md)，不在前端建立另一套业务判定。

- 输入：现有 authoring-context、capabilities、delivery-status/K34、当前 modelSpecId/revision/环境与草稿；服务提供阶段能力和允许动作。
- 输出：对应阶段的已有保存/实现/物化命令；只读导航不发写请求，资产字段不再混入模型提交。三步展示不改成三个持久化生命周期状态。
- 数据流：当前路由/上下文→已有页面组件→当前阶段契约→服务校验→重读当前结果。旧 definition/implementation/verification 保留；旧 delivery 页面按 T15 规则回看历史并导航到数据，不隐式发布。
- 各字段依 F3 阶段矩阵放置：设计页只处理结构/语义及适用标准；实现页在需要时补目标/映射/加载方式；物化页仅展示必要执行条件。源连接、质量配置、负责人、资产发布、分析连接不得都成为保存草稿的前置条件。
- 移走 W3/W4 中业务质量规则和资产/分析编辑入口到数据上下文；保留结构校验、当前执行错误、必要安全/版本提示。后端仍按阶段拒绝非法操作，不能只藏控件。
- 每页主操作最多一个；暂存/上一步为次操作，成功页主操作为返回模型列表，次操作为去数据管理。无新增全流程卡片、强制确认页或独立帮助系统。
- 编辑已发布模型沿用新草稿/修订；刷新/浏览器返回/跨页回跳保留模型和环境。治理/分析轮询不能把用户拉回模型步骤。

## UI 四态与走查

空模型可直接创建；加载保留当前页/输入并禁重复提交；错误就地可操作，说明进入右上角帮助；成功只显示当前阶段真实结果。ODS 不显示 SCD/事实形态等不适用字段。

走查：新建 ODS→暂存→重开→完成映射→选择目标→结构物化→返回列表；整个过程不要求接入、规则、负责人或分析连接。另走旧模型深链、发布历史、未保存离开、步骤前进后退和无权 URL。

## 影响范围

ModelingWorkbenchPage/Editor、ModelWorkbenchCreateMenu、实现/物化/结果组件、现有模型 API presentation、helpTopics、精确工作台路由兼容；不重做导航树和菜单权限。
