# T06：全层建模及模块边界验收

**优先级**：P1  
**状态**：IN_PROGRESS
**依赖**：T02–T05；复用 F1-T08、F2-T06 的交付机制、环境和证据，不重复计算历史通过范围。

## 目标

用一条最小 ODS→DWD→DWS→ADS 路径，证明无接入也能设计并物化，后续数据/资产工作有独立入口，正式交付后行为一致。

## 验收契约与数据流

输入为 T01 冻结的 K31–K36/阶段 fixtures、隔离模型与 PostgreSQL 目标、现有接入样例、受测 SHA/正式镜像/包。输出为 [IT-19–IT-24](../../it/README.md#f3-新增验收执行中) 的真实证据与缺口，不创建占位 PASS。

主线：零接入创建四层草稿及映射→逐模型结构物化→核对空表结构→结束建模→数据模块绑定离线接入写数→沿原支持方式运行下游加工→维护同一资产。API/数据库只补已有适配器的绑定正反例；不做全引擎或全站回归。

## 必测分支

- IT-19：无任务/物理来源保存全链，版本引用、缺失映射和循环拒绝。
- IT-20：四层空表真实结构、当前版本完成、无业务数据/规则仍能结束；原有数据加工成功与空表成功分开，冲突目标不覆盖。
- IT-21：三步页面一个主动作、当前阶段必填、无资产表单，成功后可以离开；Chrome 95、1366×768、帮助/焦点/返回。
- IT-22：同一目标接入/写数/登记，技术列和类型差异拒绝；重复操作/双窗口不产生副本、不损坏已有数据。
- IT-23：质量/分析失败、模型变更、资产普通字段修改、取消/迟到任务、旧发布/旧接入/旧 step 深链；验证各自失效范围与独立恢复。
- IT-24：正式交付包含新增 SOURCE/快照/迁移/结构物化资源和帮助，离线同包重现主线；不靠本机依赖或手工容器补丁。

## 执行与边界

1. 完成 coherent change set 后只做一次所需的聚焦 review；不逐文件重复审查，不默认多代理。
2. 开发目录只编辑/静态检查/提交推送；编译型测试、构建/包在 `/opt/prod/s10/deploy` 清洁分支 `git pull --ff-only`、核对 SHA 后走正式入口。
3. 先做对应行为专项，再正式构建/包、部署和登录真实页面；失败只针对受影响分支重跑。
4. 仅用隔离样例；不修改已有生产业务模型、数据、权限或候选。未授权部署时记录待执行，不把规划当部署授权。
5. 包内资源/必要前向迁移、旧版本兼容、恢复路径和运行手册沿用现有 assests/release-plan、runbook 补差异，不另建发布体系。

## 证据与 DoD

每次记录模型/实现修订及 checksum、环境、目标身份、buildMode、运行/候选 ID、接入任务/运行、资产身份/ETag、实际表字段/行数、状态 GET 与写请求、SHA/镜像/包校验和。证据按实际执行创建目录。

- [ ] 源码/测试：K31–K36 与拒绝分支通过；必要迁移在清洁库/升级库通过。
- [ ] 正式构建/交付包：资源和版本可追溯，包校验及离线差异验证通过。
- [ ] 容器部署：受测 SHA/镜像与交付包一致，实际运行服务可核对。
- [ ] 真实页面：IT-19–IT-24 与数据库/运行记录一致，旧能力必要回归通过。
- [ ] 同步 Feature、Sprint、IT、队列状态；只把真正完成的 Task 标 DONE。
