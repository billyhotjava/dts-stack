# T15：建模完成边界与增量契约冻结

**优先级**：P1  
**状态**：IN_PROGRESS
**依赖**：F1/T02/T07、F2/T09–T13 的既有契约；复用验收基线，不沿用历史通过结论。

## 目标

把“物化完成即结束建模、资产工作在数据模块”落到可实施的命令、DTO、存储和页面边界，关闭 [F3 契约第 6 节](../../assets/F3-modeling-data-boundary.md#6-开工前必须关闭的技术问题) 的四项技术缺口。

## 技术设计与交付

- 输入：C19–C26、K31–K36、F2 现有 DTO/命令、当前目标实例及隔离样例可用性；禁止重复全仓勘察。
- 输出：在同一 F3 契约中将已核实部分标 FROZEN；逐项记录准确 Java/TS/Schema 字段、路由、请求/响应/错误样例、CAS/幂等、表列/约束、前向迁移路径和共享行为 fixtures。未决项明确关联下游任务，不能以拟定字段冒充现有 API。
- 数据流：模型设计→逻辑依赖→结构物化/原有数据运行→完成证据→数据登记/治理；对每个命令列明是否创建候选、写业务数据、发布、登记、触发质量/分析，确认 GET 无副作用。
- 固定 SOURCE 枚举与模型修订/引用协议；检查 ModelSpec 持久化约束、快照与现有导入导出兼容，禁止第二模型台账。
- 固定结构物化 DDL 的字段类型、键、分区支持边界，显式拒绝不支持组合；DATA_BUILD 缺省兼容原客户端，错误不得回退成结构物化成功。
- 固定 API raw_record/技术列和离线目标绑定的适配范围；已绑定模型目标不得走隐式 DROP/重建分支。新增绑定字段在哪个现有 DTO、如何防并发漂移必须明确。
- 固定无目录记录时的登记命令与现有记录的精确深链；质量/发布政策在数据模块校验，身份/安全/DDL 可执行性在物化操作时校验，不复制 owner。
- 所需迁移先给前向兼容与回退方案；纯前端隐藏治理步骤无法解开服务端副作用时，记录准确改动 seam 后再开工。
