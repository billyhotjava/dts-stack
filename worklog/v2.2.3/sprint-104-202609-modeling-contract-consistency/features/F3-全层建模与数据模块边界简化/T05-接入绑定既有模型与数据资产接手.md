# T19：接入绑定既有模型与数据资产接手

**优先级**：P1  
**状态**：IN_PROGRESS
**依赖**：T15 冻结 K35/K36、T16/T17；与 T18 共用精确深链，复用 F2/T11 规则、T12 目录 CAS、T13 分析恢复。

## 目标

从“数据”模块为已物化 ODS 绑定现有接入任务，在同一物理表/资产上办理写数、治理和发布；这些工作不再成为完成建模的附加步骤。

## 技术设计

遵循 [F3 K35/K36](../../assests/F3-modeling-data-boundary.md)，复用 C22–C26；本 Task 收敛入口和绑定，不重写接入、规则或资产服务。

- 输入：服务解析的模型 ID/修订、目标连接/schema/table 身份、既有接入配置及字段映射；已有资产使用 datasetId/ETag。绑定 DTO 的精确嵌入位置和错误码以 T15 冻结结果为准，不用自由文本表名猜测。
- 输出：现有接入任务/执行记录、同一目标物理数据、现有资产登记/治理记录及独立质量/发布/分析状态；不新建 ModelSpec 副本或同表第二资产。
- 数据流：模型成功页次入口→数据目录/详情或现有登记动作→已物化目标→接入页绑定→原执行器校验/写入→数据模块查看治理结果；“编辑模型”返回原 modelSpecId/版本上下文。
- 数据接入选择“已有模型表”后预填并锁定目标身份，展示源/目标字段差异；仅在此时配置连接、采集参数、映射和执行所需约束。重复打开/保存不重建目标或启动采集。
- 已绑定目标与模型修订不符、必需列缺失、类型不可兼容、技术列碰撞、目标尚未物化时拒绝执行并保留输入；不通过任意新增列、隐式 DROP/清空来强行匹配。结构变更返回建模修订流程。
- API 保留现有 raw_record/技术列模式，仅接纳已冻结的兼容结构；文件和数据库接入沿用现有映射/加载能力。不增加通用嵌套 API 展平、增量算法或自动结构迁移。
- 未登记数据复用既有登记命令与 CatalogAssetKey；已有记录直接维护。owner/description 等人工值不被再次物化或接入覆盖；PATCH/ETag、规则版本/权限和分析幂等由 F2 原 owner 处理。
- 业务质量、资产对外发布、分析准备的操作界面在数据模块；分析失败只重试分析，质量不通过只限制相应数据操作，已完成的模型仍可见。

## UI 四态与走查

复用 `/catalog/search?view=table`、AssetLedgerView/详情及既有接入/治理页，不新增菜单和第二资产台账。数据视图显示可办理事项，不强制新建一个全流程向导。

未登记与登记读取失败分别显示；加载禁覆盖保存；字段差异/并发错误保留输入；写数/治理成功显示同一目标结果。模型只保留只读摘要/跳转，数据页不嵌回整套模型字段编辑器。

走查：从已物化 ODS 进入数据→绑定离线样例→写入→维护负责人→回看模型完成→再进同资产核对；API、数据库各验证既有兼容样例与不匹配拒绝，不扩展数据源类别。

## 影响范围

IngestionTaskProxyResource/IngestionTaskService、TargetTableProvisioner/API landing 对模型型目标的保护、接入目标选择组件；DataSearchPage/AssetLedgerView/资产详情、既有登记/治理/serving 导航；按 T15 冻结绑定存储和唯一性，不新建平行关系 owner。
