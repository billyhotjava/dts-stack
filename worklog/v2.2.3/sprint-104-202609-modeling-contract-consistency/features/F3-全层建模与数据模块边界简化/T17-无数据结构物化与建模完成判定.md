# T17：无数据结构物化与建模完成判定

**优先级**：P1  
**状态**：IN_PROGRESS
**依赖**：T15 冻结 K33/K34 及原发布副作用边界；T16 提供全层逻辑模型。

## 目标

在现有 PostgreSQL 目标上，四层模型可依据声明创建普通空表；当前版本结构物化成功后即可结束建模，不要求业务数据、资产治理或分析准备已经完成。

## 技术设计

遵循 [F3 K33/K34 与完成证据](../../assets/F3-modeling-data-boundary.md)，复用 C23–C25 的实现/候选/运行 owner。

- 输入：既有 build-intents 命令、模型/实现快照、目标环境、ETag、幂等键；拟增 buildMode=SCHEMA_ONLY，旧请求保留既有数据加工语义。
- 输出：真实运行与目标表结构核验、只读 modelingResult；保留原 ModelStatus/发布引用，不写一个前端自有完成标记，不把 BUILT 翻译成 PUBLISHED。
- 数据流：物化页→现有命令与执行计划→按声明输出 DDL→目标数据库建表/核验→运行证据→delivery-status 只读聚合。SCHEMA_ONLY 不查询上游、不加载业务数据；DATA_BUILD 继续要求真实物理来源与原执行条件。
- ODS/DWD/DWS/ADS 的结构物化使用同一契约输出字段、类型、键和支持的分区；不实现新的视图/跨引擎/批量调度能力。无法表达的声明直接报告，不静默去掉。
- 区分物化结束与资产质量/发布/分析命令：必要技术表身份与血缘可自动记录，业务治理失败不能清除当前成功证据；对外发布政策仍在数据模块由原 owner 执行。
- 已有目标只在身份和结构证据符合冻结协议时复用；同名结构冲突、权限不足、部分输出失败不得标完成。不得自动 DROP、清空、覆盖已有表或补造已成功运行。
- 修改模型/实现/环境后重算完成资格；修改资产描述、规则、连接恢复不重物化。旧取消/失败/迟到任务不能覆盖当前结果；同键重放按既有幂等策略处理。

## UI 交互

物化页选择当前支持的“创建表结构”或“生成数据”，说明放帮助；简短显示目标、进度和真实结果。结构模式无来源/无规则仍可运行；数据模式缺来源时定位接入条件。成功后可返回列表，数据管理为次入口。

空态未物化；加载/运行态防重复提交；错误态保留当前计划并显示差异或失败环节；成功态明确“表结构已创建”，不显示“数据已就绪”。原有数据物化结果仍如实呈现。

## 影响范围

ModelBuildIntentResource、ModelDeliveryStatusResource、现有输入策略/ExecutionPlanner/DbtCompiler/候选运行与投影、物化结果组件；只按 T15 冻结的 seam 扩展，不新建发布/任务控制面。
