# T10：交付状态与四步建模向导一致呈现

**优先级**：P1  
**状态**：IN_PROGRESS（T10-A/T10-B1/T10-B2；完整四步页面待实施）
**依赖**：T09 冻结的视图、动作映射与共享 fixtures

## 业务目标

用户从模型列表或发布步骤页看到同一版本的真实交付结果，并根据同一个后端判定执行下一步。

## 统一规则与技术设计

遵循 [共享业务/界面契约](../../assets/delivery-workflow-contract.md)，复用账本 C11–C18；本文不另定义状态机。

- 输入：GET `/api/modeling/model-specs/{id}/delivery-status` 及批量同名入口（共享契约的拟定接口）；modelSpecIds 为 UUID 集合，租户由服务端确定。
- 输出：共享 DeliveryStatus DTO；以模型、候选、质量证据、目录记录、serving 投影分别派生 steps，返回 actions、证据版本与读取时间。列表和详情消费同一规则。
- 数据流：扩展既有建模应用查询层，以批量方式读取既有 owner→DTO→列表/发布步骤页；不新增持久化总进度表。读取不到与读取失败必须区分，不能均回 NOT_REGISTERED。
- 复用：C11/C16/C17、ModelPublishDialog、ModelReleaseWorkflowPanel、ModelAssetDeliveryResult、ModelServingSyncStatus、modelSpecApi；旧 serving API 保持兼容。
- 发布/物化/重试按钮仍调用 T09 固定的既有命令；沿用原版本头和幂等键。前端不能根据某个颜色或 BUILT 字符串开放发布。
- 一致性：旧候选或旧修订的成功单独标记，不能计入当前编辑版本；部分子系统失败保留其他已确认步骤，UNKNOWN 不能变成 FAILED 或 SUCCEEDED。
- 错误路径：401/403/404 按现有范围处理；版本过期提示重载；网络中断保留未确认提交状态，查询原请求结果后决定重试，避免另建幂等键重复提交。

## UI 交互规格

- 入口：模型工作台列表→四步建模向导。W1 设计、W2 实现、W3 构建与检查、W4 发布与交付各自一个独立步骤页；共用身份/版本及顶部导航，每页一个主按钮。具体路由、按钮和 N01–N08 导航规则以共享契约为准。
- “开始物化”“配置质量规则”“执行检查”“发布模型”“重试分析准备”的启用及原因来自 actions；T11–T13 提供具体动作执行，不设置无功能按钮。
- 空态显示下一步；加载态保留已知内容；错误态定位失败步骤并可重读；成功态展示真实模型/资产/分析结果。没有规则时显示“待配置”，而非一直检查中。
- 走查：打开已登记且分析失败的模型→看到资产已登记→打开交付详情→仅分析准备失败→刷新/重开保持相同结论。
- “重新物化”作为次操作，保留运行中/版本约束；不因发布或分析准备失败默认重新构建。
