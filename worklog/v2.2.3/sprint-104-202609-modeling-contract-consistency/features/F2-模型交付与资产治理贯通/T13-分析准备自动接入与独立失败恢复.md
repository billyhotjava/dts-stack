## T13-A：内置数仓启动失败有界恢复（本轮窄切片）

本切片只处理已确认的启动时序故障：analytics 于 22:55:07 调用 platform `/infra/data-sources` 发生 I/O 失败，单次 `DataLakeDatabaseInitializer` 初始化失败后没有自动恢复；23:04 随后的 semantic publish 返回 HTTP 400，本轮只读查询 `analytics_database` 为 0 行。请求 payload 已带 `platformDataSourceId`，因此本轮不把根因归为 `dataSourceName=null`。

- 范围：应用就绪时首次尝试，失败后每 30 秒重试，合计最多 6 次；注册事务提交后停止。耗尽后记录明确日志，依赖修复后重启 analytics 可重新尝试；源注册成功不代表目标元数据或分析已就绪。
- 不在范围：任意平台源按需接入、平台源/租户唯一约束、存量重复关系处理、目标表和字段实际验证、语义发布 HTTP 400 的完整归因或修复、W4 页面整合、浏览器/部署/离线验收。
- 约束：重试沿用现有受信任平台源边界，不按名称猜测来源，不扩张 DatabaseResource 权限，单实例重试成功后停止；不触发物化或发布（多实例唯一性仍属完整 T13）。若现有实现无法在该边界内满足幂等和有界性，停止扩大本切片，回到完整 T13 DoR。

## 统一规则与技术设计

遵循 [共享业务/界面契约](../../assets/delivery-workflow-contract.md)，复用账本 C11–C18；本文不另定义状态机。

- 输入：既有 POST `/api/semantic/publish` 的 modelSpec/版本、platformDataSourceId、schemaName、tableName 及字段语义；服务身份和目标范围按现有受信任发布边界校验。
- 输出：平台源到分析连接的确定性关联、指定目标的元数据/语义、查询数据集投影及 serving 当前版本结果；不能只创建连接/占位表就标为可分析。
- 复用 C12–C14：提取 DatabaseResource 中平台源接入的共享应用服务，供现有用户入口和语义发布使用；不复制凭据处理，不扩大整个 database API 的服务令牌权限。
- 数据流：已提交发布结果→既有异步 serving 工作流→按平台源 ID 获取/建立关联→准备并验证指定目标/字段→语义发布→查询投影→当前版本标记成功。缺失源不是目录登记失败。
- 接入过程幂等且可恢复；唯一性、租户边界、服务端源策略和存量重复关系在编码前定案。不能凭同名源关联，不能因一次模型发布默认注册全库目标或扩张读权限。
- 失败分类：依赖未就绪/临时连接失败采用有上限退避；认证拒绝/非法目标/配置错误显示修复原因；不能将全部 HTTP400 视为永久失败，也不能全部无限重试。
- 重试入口沿用 POST `.../{id}/serving-sync/retry` 和当前 If-Match。超时/断线后的重入应复用已成功步骤；旧版本任务完成不得污染新版本。
- 分析功能未启用按 T09 冻结的配置显示 NOT_APPLICABLE；已启用但服务异常显示失败/不可用，不伪装未启用。登记与模型发布保持原结果。
- 如果需新增约束/列，先补前向迁移、重复映射预检和兼容策略；不得修改已执行 changeSet 或人工直改库作为交付方案。

## UI 交互规格

- 发布步骤页显示“分析准备中/已就绪/准备失败”，失败解释数据源关联、目标准备或服务连接等真实步骤，技术错误码在详情中查看。
- “重试分析准备”受版本及任务状态保护；处理中显示进度，失败保留重试原因，成功后刷新权威状态。重复点击不触发物化或再次发布。
- 走查：未有分析关联的已发布模型→自动准备→故障失败→资产仍可维护→依赖恢复后重试→目标实际可查询；整个过程不访问大屏数据源选择器。
