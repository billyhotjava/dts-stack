# T11：模型目标质量规则配置与检查闭环

**优先级**：P1  
**状态**：DRAFT  
**依赖**：T09 的规则写契约；T10 的质量步骤与 actions

## 业务目标

用户在模型向导当前步骤对正确输出资产配置有效质量规则、执行检查并解除真实发布阻断，不必到通用列表重新选表。

## 统一规则与技术设计

遵循 [共享业务/界面契约](../../assets/delivery-workflow-contract.md)，复用账本 C11–C18；本文不另定义状态机。

- 输入：modelSpecId/candidateId/候选版本与服务端解析的输出 datasetId/assetKey、当前资产规则的已发布 ruleVersionId/规则业务版本。精确绑定和执行路由、DTO、CAS/幂等协议以 T09 冻结版本为准；未冻结不可实现。
- 输出：持久化到既有规则绑定 owner；执行返回真实运行 ID/状态，质量证据与当前输出/规则版本绑定。规则保存/发布成功不等于质量通过，旧版本规则或旧运行不能释放新候选门禁。
- 数据流：模型向导当前步骤→复用当前资产规则管理组件→既有规则服务校验目标/版本/适用范围→既有执行器→当前质量证据→候选质量协调与交付视图。
- 复用 CandidateQualityAssetRegistrationService、ModelPublicationQualityReconciler、JdbcGovernanceQualityEvidenceAdapter 和既有规则服务；资产未登记时由候选登记流程恢复，不用假 dataset 或普通资产新建入口绕过。
- SQL 按平台实际执行器、方言和只读/作用域校验执行；检测对象固定为当前输出，不能默认上游表。不为了兼容一次 DBeaver 成功而整体放宽 SQL 安全限制。
- 错误路径：ASSET_NOT_REGISTERED 与 ASSET_MISMATCH 的语义分开（最终错误名由 T09 冻结）；无绑定为 WAITING_INPUT，规则失败有失败记录；连接/执行错误有可操作原因，不伪装数据不合格。
- 并发：用户选择期间候选变化或规则新版本发布，服务端核验原版本；不能静默替换规则版本。多输出逐项校验并显示阻断对象。

## UI 交互规格

- “配置质量规则”在当前步骤页展示目标来源/schema/table、属于该资产的规则及版本；可查看/新建/维护，目标不可悄悄切换。
- 无规则给“新建规则”入口；复杂编辑进入现有规则页，携带完整上下文和安全 returnTo，保存后返回原候选并刷新绑定，不自动宣称检查成功。
- 空态解释无可用规则；加载态禁重复绑定；错误态保留选择/SQL并就近提示；成功态区分“已绑定”“检查通过”。执行中展示运行状态与取消/重试的实际能力。
- 走查：已物化→待配置→绑定快照目标规则→检查失败→看错误→修复并重新检查→门禁通过→按真实发布动作继续。

## 向导落点与生命周期约束

本任务固定落在 W3“构建与检查”。配置/执行规则不会自动发布；规则版本变更按 I03 仅失效相关证据。复杂规则页返回 W3，保留模型、候选、输出资产与未提交输入。

## T09 已核实的写入口约束

以 [核验记录 B](../../assets/T09-contract-freeze.md) 为准：规则和发布版本绑定同一资产，不存在可直接复用的“任意已发布规则重绑”接口。配置既有规则是维护当前资产规则，选择用于查看/执行，不另写候选私有绑定；借用其他资产规则仅复制内容创建新规则，目标固定为当前输出。

使用既有 `/api/governance/quality/rules` 新建、`/{id}` 修改及 `/{id}/versions/{version}/status` 发布；规则定义/版本为原服务所有。候选执行使用 `/quality` 与 `/governance-quality/runs` 的当前状态/CAS/幂等协议。规则修改会新建版本，其并发保护未冻结，不能将“绑定”实现为读取旧完整对象后覆盖 PUT。
