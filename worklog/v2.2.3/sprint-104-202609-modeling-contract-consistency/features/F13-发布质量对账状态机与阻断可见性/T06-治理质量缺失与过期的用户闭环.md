# F13-T06：治理质量缺失与过期的用户闭环

**优先级**：P1
**状态**：DRAFT（待 T01 关闭 Q2）
**依赖**：T03（wake 与分类）、T05（按钮与责任区）
**估算**：1 人日

## 目标

治理质量处于 MISSING / FAILED / EXPIRED 时，数据管理员能在面板一步发起处理；处理成功后发布单在 30 秒内自动推进，不需要人盯着刷新。

## 技术设计

- **输入**：`qualityReconcile.blocker.actionHint`、`governanceQuality.evidence[*]`（ruleId、ruleVersionId、bindingId、runId）。
- **闭环规则**：
  | 阻断码 | 前置条件 | 用户动作 | 后端调用 | 推进条件 |
  |---|---|---|---|---|
  | `…_QUALITY_MISSING` 且无规则绑定 | 资产已登记 | 配置质量规则 | 跳规则目录（带 assetKey） | 绑定后变为 `RUN_GOVERNANCE_QUALITY` |
  | `…_QUALITY_MISSING` 且已有绑定 | — | 运行治理质量 | `POST …/governance-quality/runs` | 运行 PASSED |
  | `…_QUALITY_FAILED` | 有 runId | 查看运行 → 处理数据后重新运行 | 同上 | 运行 PASSED |
  | `…_QUALITY_EXPIRED` | 有绑定 | 重新运行治理质量 | 同上 | 运行 PASSED |
- **后端**：
  - 目录分类时区分“MISSING 且无绑定”与“MISSING 且有绑定”，分别给 `CONFIGURE_QUALITY_RULES` / `RUN_GOVERNANCE_QUALITY`（绑定信息取自 `governanceQuality.evidence`，已在 reconciler 可得）。
  - `CandidateGovernanceQualityRerunService`（`:26` 允许状态含 `QUALITY_RUNNING`）提交成功后 `wake`（T04 已接）；治理质量运行完成回调处 `wake`（T01 定位回调点）。
  - Q2 若结论为“EXPIRED 单缺少 bindingId 等字段导致前端不显示重跑”，在本 task 补齐证据字段来源，而不是放宽前端判断。
- **错误路径**：重跑提交被拒（权限、规则版本已变）→ 按钮恢复并显示后端消息；规则版本已变（`VERSION_MISMATCH`）→ actionHint 改为 `CONFIGURE_QUALITY_RULES`，提示先确认规则版本。

## 影响范围

`ReleaseQualityBlockerCatalog`（细分 MISSING）、`ModelPublicationQualityReconciler`（传入绑定信息）、`CandidateGovernanceQualityRerunService`、治理质量运行完成回调处；前端无新增控件（T05 已覆盖）。

## 验证（RED→GREEN）

- [ ] 单测：四种阻断 × 有/无绑定 → actionHint
- [ ] IT：EXPIRED → 提交重跑 → 模拟运行 PASSED → 下一次对账 ≤ 30 s 内迁到 QUALITY_PASSED，并冻结新快照
- [ ] 回归：`VERSION_MISMATCH` 时不给重跑按钮
