# F13-T09：质量策略默认提示与管理端手动切换

**状态**：IN_PROGRESS（源码与测试完成，待本机正式构建部署验收）；**类型**：开发（platform + admin + admin-webapp）；**优先级**：P0。
**依赖**：无（F13 冻结快照语义不变）。
**决策（2026-09-24 用户确认）**：默认 `ADVISORY`；系统管理员可手动切换为 `BLOCKING`；**系统永远不主动/自动切换到 BLOCKING**。管理页面放在 dts-admin-webapp；策略数据仍由 dts-platform 持有（方案 B，不做 admin 侧副本同步）。

## 目标

1. 新安装与"从未被人修改过"的现有安装，治理质量策略为 `ADVISORY`。
2. 系统管理员在「基础管理 → 系统配置 → 模型发布治理」查看并切换策略，切换有审计、有并发保护、切到 BLOCKING 前显示影响预览。
3. 代码中不存在任何自动落到 BLOCKING 的默认值或迁移。

### platform 内部接口（仅 dts-admin 服务令牌可调用）

| 方法 | 路径 | 请求 | 响应 |
|------|------|------|------|
| GET | `/api/internal/modeling/governance-policy` | - | `{ qualityGate, standardCoverage, revision, lastModifiedBy, lastModifiedDate, systemDefault: boolean }` |
| GET | `/api/internal/modeling/governance-policy/impact` | - | `{ unfrozenCandidates: n, frozenCandidates: n }`（按状态计数：BUILDING/BUILT/QUALITY_RUNNING/QUALITY_FAILED 将按新策略判定；QUALITY_PASSED/REVIEW_PENDING/APPROVED/PUBLISHING 保留冻结策略。实施时放弃"逐个评估会被拦几个"，因需逐候选调用质量服务，成本高且结果随时间变化） |
| PUT | `/api/internal/modeling/governance-policy` | `{ qualityGate, expectedRevision, actor, reason }` | 200 同 GET；409 `GOVERNANCE_POLICY_REVISION_CONFLICT`；400 非法取值 |

- `ServiceDependencyAuthenticationFilter.isServicePathAllowed` 为 `dts-admin` 增加上述 3 个路径，必须校验 `X-DTS-Service-Token`（沿用 `svcTokenAuthService`）。
- PUT 使用 `UPDATE ... SET quality_gate=?, revision=revision+1, last_modified_by=?, last_modified_date=now() WHERE policy_key='PLATFORM_DEFAULT' AND revision=?`，0 行 → 409。时间按 UTC 口径写入（`timestamptz`，不涉及 +8h 问题）。
- 本期只开放 `qualityGate`；`standardCoverage` 只读展示。

### admin-webapp

- 菜单：`nav-data-frontend.tsx`「基础管理 → 系统配置」下新增「模型发布治理」，路由 `/admin/model-governance-policy`，与「数据湖配置」「集成设置」并列。
- 页面：当前策略（提示 / 阻断）单选 + 说明文字 + 最后修改人/时间 + "系统默认"标记；"原因"必填；保存。
- 切到"阻断"时弹确认框，显示 impact 数字："切换后，新发起的发布前检查将要求业务质量通过。当前 n 个进行中的发布单会因缺少/不合格/过期的质量结果被阻断；已冻结的 m 个发布单按原策略继续。"
- 切回"提示"无需预览，仍需原因。
- 409 → "策略已被他人修改，请刷新后重试"。

## 代码中消除自动 BLOCKING 默认

- `ModelSpecStageGateService.resolveGovernancePolicy()`：`governancePolicy == null` 时的兜底质量门禁由 `BLOCKING` 改为 `ADVISORY`；标准覆盖范围保持 `ALL_FIELDS` 不变（该兜底只在未注入策略时生效，改覆盖范围会改变既有阶段门禁行为，不在本任务范围）。
- 策略**读不到**（表缺失/查询失败）保持现有 `SYSTEM_BLOCKED`（故障保护，显示"策略不可读"，不是质量不通过，也不改写策略值）。已向用户说明，未提异议。
- `WarehousePlanContract` 中的 BLOCKING 为已退役仓库计划流程，实施时核对是否仍被模型发布路径引用；若被引用则同样改为读策略而非常量。

## 验证（先写测试）

- platform：迁移在三种初始状态（无行 / 种子未改 / 人为设过 BLOCKING）下的结果（Postgres IT）；PUT 乐观锁 409；dts-admin 以外服务或无令牌调用被拒；stage gate 兜底为 ADVISORY。
- admin：非系统管理员 403；审计记录前后值；actor 不取自请求体。
- admin-webapp：切 BLOCKING 必经确认框并展示 impact；原因必填；409 提示。
- F13 回归：已冻结候选在切换后结论不变（F13-IT 冻结快照用例）。
