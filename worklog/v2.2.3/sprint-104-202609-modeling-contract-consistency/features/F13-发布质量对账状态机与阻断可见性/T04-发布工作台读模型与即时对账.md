# F13-T04：发布工作台读模型与即时对账

**优先级**：P1
**状态**：DRAFT（待 T01 关闭 Q3：`refresh` 现有语义）
**依赖**：T03（消费状态表与目录）
**估算**：1 人日

## 目标

发布工作台读接口如实返回质量对账阶段、阻断归属和可执行动作；用户点“刷新状态”或提交治理重跑后立即对账，不必等下一轮调度。

## 技术设计

- **输出契约**：`WorkbenchView` 增加 `qualityReconcile`（主契约 §6 JSON，字段名与类型以此为准；时间为 ISO-8601 UTC）。
  - `QUALITY_RUNNING` 且有状态行 → 由状态行 + 目录组装。
  - `QUALITY_RUNNING` 且尚无状态行 → `phase=ENGINEERING_PENDING`、`blocker=null`（首轮对账前的短暂窗口）。
  - 其他状态 → `null`。
- **兼容**：`primaryBlocker` 在 `QUALITY_RUNNING` 时取 `qualityReconcile.blocker` 的 `{code, message}`；`previewBlocker` 仅在无状态行时作为回退（`ModelReleaseCandidateApplicationService.java:1378-1380`）。`state=BLOCKED` 的判定逻辑不变。
- **读路径**：`withPersistedEvidence`（`ModelReleaseCandidateApplicationService.java:1368`）增加一次按主键的状态表读取；不在读路径调用 `evaluateLive` 或登记（避免 F4 已治理过的读事务膨胀问题）。
- **即时对账**：
  - `POST …/{candidateId}/refresh`：`QUALITY_RUNNING` 时 `wake` + 同步执行一次 `reconcile`（复用 reconciler 的同一方法与执行身份），返回最新 `WorkbenchView`；其他状态保持现有行为（Q3 核对后冻结）。
  - `POST …/{candidateId}/governance-quality/runs` 成功后 `wake`。
  - 治理质量运行完成的既有回调/事件处（T01 定位）调用 `wake`。
- **投影对齐**：`ModelDeliveryStatusQueryService.java:106` 由“只认 GOVERNANCE_QUALITY_MISSING”改为按 phase：`ACTION_REQUIRED → WAITING_INPUT`、`SYSTEM_BLOCKED → BLOCKED`（如该投影无此值，则用 `FAILED` 并在 T01 确认下游含义）、其余 `RUNNING`。
- **权限**：沿用现有接口鉴权；`detail_json.causeMessage` 只对具备平台运维职责的角色返回，其他角色只见 `correlationId`（与 F9/F11 权限链一致，T01 确认职责判定入口）。
- **错误路径**：状态表读取失败 → `qualityReconcile=null` 并记 WARN，不影响其他字段返回。

## 影响范围

`ModelReleaseCandidateContract`（`WorkbenchView` 记录）、`ModelReleaseCandidateApplicationService`、`ModelReleaseCandidateResource`（refresh 分支）、`CandidateGovernanceQualityRerunService`（wake）、`ModelDeliveryStatusQueryService`；前端 `src/api/modelSpecApi.ts` 类型。
