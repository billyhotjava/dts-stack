# F13-T03：对账状态持久化、分类与退避

**优先级**：P0
**状态**：DRAFT（待 T01 冻结主契约 §3 阻断目录）
**依赖**：T01（消费冻结目录）；与 T02 可并行（T02 提供 `failureType`/`causeMessage`，T03 未拿到时写空）
**估算**：2 人日

## 目标

每次质量对账都把结果落到 `modeling_release_quality_reconcile_state`，按阻断类别退避重试，只在状态变化时记日志，平台故障持续 30 分钟升级 ERROR，并提供指标。

## 技术设计

- **迁移**：`dts-platform/src/main/resources/config/liquibase/changelog/20260924_01_release_quality_reconcile_state.xml`，DDL 见主契约 §4；登记到 master changelog。仅前向，无回填（首次对账时自然产生行）。
- **新组件**：
  - `ReleaseQualityBlockerCatalog`（`service/modeling`）：`Classification classify(String code)` → `record Classification(Category category, OwnerRole ownerRole, ActionHint actionHint)`；目录即主契约 §3；未登记码 → `SYSTEM/PLATFORM_OPERATOR/CONTACT_OPERATOR`。
  - `ReleaseQualityReconcileStateRepository`（`repository/modeling`，JdbcTemplate，与同包风格一致）：
    - `Optional<ReconcileState> find(tenantId, candidateId, candidateVersion)`
    - `ReconcileState record(ReconcileObservation obs, Instant now)`：upsert；同码 `attempt_count+1`、更新 `last_seen_at`；码变化时 `first_seen_at` 重置；按 §5 计算 `next_attempt_at`
    - `void markResolved(tenantId, candidateId, candidateVersion, Instant now)`
    - `void wake(tenantId, candidateId, Instant now)`：当前版本行 `next_attempt_at = now`
- **改造**：
  - `ModelPublicationQualityEvidenceRepository.findQualityRunning(limit)`：left join 状态表，条件 `state is null or state.next_attempt_at <= now()`，按 `next_attempt_at nulls first` 排序。
  - `ModelPublicationQualityReconciler.reconcile`：
    - PENDING → `record(phase=ENGINEERING_PENDING, category=WAITING)`
    - BLOCKED → `classify(code)` → phase=`ACTION_REQUIRED`/`SYSTEM_BLOCKED`/`GOVERNANCE_WAITING`，`record(...)`，`detail_json` 取异常 details
    - PASSED/FAILED 迁移成功或 STALE → `markResolved`
  - 日志：由 `record` 的返回值判断“码是否变化”，变化时 WARN；同码按小时 INFO 摘要；`SYSTEM` 且 `now - first_seen_at > 30min` 且本小时未升级过 → ERROR `event=model_publication_quality_system_blocked_escalated`。
  - 指标（Micrometer，项目已有注册表）：`dts_release_quality_blocked`（gauge，tag: category, code）、`dts_release_quality_blocked_age_seconds`（gauge，最大值）。
- **错误路径**：状态表写入失败不得影响状态迁移本身——迁移优先；写入失败记 ERROR 并在下一轮重写。并发：`@Scheduled` 单实例部署；多实例时 upsert 以主键冲突为界，不引入分布式锁（与现有 reconciler 假设一致，需在 T01 确认部署拓扑）。
- **复用点**：既有 reconciler、Micrometer、JdbcTemplate 风格；不新建调度框架。

## 影响范围

新增：迁移 XML、`ReleaseQualityBlockerCatalog`、`ReleaseQualityReconcileStateRepository` 及测试（需登记 `pom.xml` `<testIncludes>`）。修改：`ModelPublicationQualityReconciler.java`、`ModelPublicationQualityEvidenceRepository`、`application*.yml`（退避参数可配：`dts.modeling.publication.quality-reconcile.backoff.*`）。
