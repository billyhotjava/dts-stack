## 目标

关闭 F13 开放问题 Q1–Q5，用自动化测试复现资产登记失败（RED），把[主契约](../../assests/F13-release-quality-reconcile-contract.md) §3 阻断目录与 §7 登记幂等改法冻结为 FROZEN，使 T02–T06 满足 DoR。

## 技术设计

- **输入**：账本 C05–C08；本机候选单 `d0af4a93-fd8d-4f53-b549-78a12b6498f0`；openEuler 候选单（`QUALITY_RUNNING`=1）。
- **输出**：
  1. 在既有 `CandidateQualityAssetRegistrationServiceTest`（已在 `pom.xml:729` 白名单）新增 `reRegistersSamePhysicalOutputAfterCandidateVersionAdvance`：以 v3 登记成功、v4 重新登记同一物理产物，期望幂等成功。当前实现下 RED，并在失败信息中打印被吞掉的真实异常类型与消息。
  2. 主契约 §3 目录逐码核对：码值、产生位置（文件:行）、类别、责任角色、`actionHint`；补齐源码中存在但表中遗漏的码。
  3. 主契约 §7 冻结登记幂等改法（二选一，附理由）：
     - 方案 A：`evidenceRef` 去掉候选版本，改为 `materialization:{pipelineRunId}:metadata:{metadataChecksum}`；需评估历史行（含 `:v3:` 的 ACTIVE 行）与新格式并存时台账的行为。
     - 方案 B：保留 `evidenceRef`，在观测台账准入中把“同资产、同通道、同 pipelineRun+metadataChecksum、仅候选版本不同”视为同一观测的续期。
  4. Q2：在 openEuler 上读取 `EXPIRED` 单的 `WorkbenchView.governanceQuality.evidence`，判断面板是否给出“重新运行治理质量”；如果没有，写明缺哪个字段。
  5. Q3：列出 `POST /{candidateId}/refresh` 当前实现与前端调用点，给出扩展兼容结论。
  6. Q4：确认质量规则目录页（`#/governance/rules/catalog`）是否支持 `assetKey` 预筛选；不支持则写入 T05 范围。
  7. Q5：本机其余 2 张 `QUALITY_RUNNING` 与 3 张 `BUILT` 单各自的阻断原因（只读 SQL + 日志），写入账本增量。
- **数据流**：只读 SQL（`modeling_model_release_candidate*`、`catalog_asset_registration_evidence`、`catalog_dataset`）+ 平台日志 + 源码阅读；不改任何运行数据。
- **错误路径**：若本机无法复现（例如台账已被其他操作修正），改用测试夹具构造 v3 已登记 → v4 重登记，不依赖现场数据。
- **复用点**：`CandidateQualityAssetRegistrationService`、`CatalogPhysicalDatasetObservationAdapter.observe`（C05、C06）；远端执行复用 `rx.sh` 两跳方式（见记忆 openeuler-test-server-jump）。
