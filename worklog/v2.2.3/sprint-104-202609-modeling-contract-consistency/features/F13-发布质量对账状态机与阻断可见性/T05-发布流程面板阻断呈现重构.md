# F13-T05：发布流程面板阻断呈现重构

**优先级**：P1
**状态**：DRAFT（待 T01 关闭 Q4：规则目录页 `assetKey` 预筛选）
**依赖**：T04（消费 `WorkbenchView.qualityReconcile`）
**估算**：2 人日

## 目标

发布面板的步骤条、“当前责任”、动作按钮与证据标签全部由后端对账状态驱动，不再出现“标红需处理 + 服务端推进中”的矛盾，不再把“缺少运行记录”显示成“物理对象缺失”。

## 技术设计

- **输入契约**：`qualityReconcile`（主契约 §6）、既有 `candidate`、`evidence`、`governanceQuality`、`releaseActions`、`binding`。
- **步骤状态**（`ModelReleaseWorkflowPanel.tsx:43-89`）：
  - 工程验证：优先看 `evidence` 中 `type=QUALITY_RUN` 的 `state`——PASSED 即“已完成”，FAILED 即“需处理”，否则按候选状态（修正 C12）。
  - 治理数据质量：`QUALITY_RUNNING` 时按 phase 映射——`GOVERNANCE_WAITING`→处理中；`ACTION_REQUIRED`→需处理；`SYSTEM_BLOCKED`→新状态 `system-blocked`（文案“平台故障”，图标与“需处理”区分）；`ENGINEERING_PENDING`→等待。其他状态沿用现有 `governanceStepState`。
- **当前责任**（`handoffText`，`:108-129`）：`QUALITY_RUNNING` 时改为由 `blocker.ownerRole` + `message` 组装：
  - `DATA_ADMIN` → “当前由数据管理员处理：{message}”
  - `MODEL_MAINTAINER` → “当前由模型维护者处理：{message}”
  - `PLATFORM_OPERATOR` → “平台处理中遇到故障，已通知管理员；你无需操作。关联 ID：{correlationId}”
  - `NONE`/无 blocker → “系统正在运行，无需操作”
  - 下方一行时长信息：“已等待 {formatDuration(now-firstSeenAt)} · 最近检查 {lastSeenAt} · 下次检查 {nextAttemptAt}”
- **动作按钮**（按 `actionHint`）：
  | actionHint | 控件 | 调用/跳转 |
  |---|---|---|
  | `CONFIGURE_QUALITY_RULES` | 配置质量规则 | `#/governance/rules/catalog?assetKey={encodeURIComponent(assetKeys[0])}` |
  | `RUN_GOVERNANCE_QUALITY` / `RERUN_GOVERNANCE_QUALITY` | 运行/重新运行治理质量 | 既有 `onRerunGovernanceQuality` → `POST …/governance-quality/runs` |
  | `VIEW_QUALITY_RUN` | 查看质量运行 | 既有 `#/governance/rules/runs/{runId}` |
  | `SET_CLASSIFICATION` | 补充密级 | 数据资产治理页（T01 确认路由） |
  | `CREATE_REPLACEMENT` | 创建替代发布单 | 既有 replacement 动作 |
  | 任意 | 刷新状态 | `POST …/{candidateId}/refresh`（T04） |
  重跑按钮的可用性改为以 `actionHint` 为准，`canRerunGovernanceQuality`（`:173-188`）仅作为后端未返回 `qualityReconcile` 时的回退。
- **标签**：新增 `governanceEvidenceStatusLabel`（`utils/customerDisplayLabels.ts`）：`MISSING=缺少质量运行记录`、`EXPIRED=运行记录已过期`、`FAILED=质量未通过`、`RUNNING=运行中`、`PASSED=已通过`；面板 `:295` 改用它。全局 `STATUS_LABELS.MISSING` 保持“物理对象缺失”（物理关系观测仍在用）。
- **时长**：新增 `formatDuration(seconds)`，“有效期：86400 秒”改为“有效期：24 小时”。
- **顶部资产登记列**（`ModelPublishDialog.tsx`）：`PENDING_GOVERNANCE` 显示“已登记（待治理）”。
- **规则目录页深链**：若 Q4 结论为不支持，本 task 在规则目录页读取 `assetKey` 查询参数并预填筛选（只读筛选，不新增路由）。

## UI 交互规格

- 四态：加载时责任区骨架；读失败保留上次数据并显示“状态读取失败 [重试]”；空/成功见 F13 README UI 规格。
- 点击重跑后按钮立即禁用并显示“正在创建新运行…”；成功后责任区切到“系统正在运行”；失败时显示后端消息并恢复按钮。
- 视觉：沿用 `PrototypePrimitives` 与 `dmx-release-*` 样式；`system-blocked` 新增一个状态类，颜色与 `failed` 区分（琥珀色，不用红色）。
- 走查脚本见 F13 README“操作走查”，另补 SYSTEM_BLOCKED 与 WAITING 两条。
