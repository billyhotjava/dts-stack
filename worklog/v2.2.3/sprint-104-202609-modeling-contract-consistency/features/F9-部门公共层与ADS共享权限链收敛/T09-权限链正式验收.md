## 执行安排

1. 数据与角色准备可随设计开展：两部门（含 1153/153/真实父子编码）、A/B/L/C/D/I/P/E、低密级建模人员、ADMIN、应急 opadmin、自定义角色账号、稳定 ID/用户名不同、旧会话/同名重建、各自 ADS 与混合候选。仅使用隔离样例，不修改客户业务数据。
2. 按切片开发目录 commit/push → /data/dts-stack 确认分支/工作区 → git pull --ff-only → 核对 SHA → 正式测试、构建、打包。包含平台/admin 目录与会话适配、前端、模型/会话迁移、审计字典；在线/离线同包，记录版本清单、镜像 ID/digest、包校验和。
3. T02 可以先验并独立交付；T03–T06 完整授权链在测试环境尽早集成，不能以半套授权开放生产建模。T07/T08 分批测试，最终汇总原 IT，不重复无关通过项。
4. 清洁库/升级库：计划规范部门/唯一/生命周期、旧会话稳定 ID、旧会话重新登录、模型 owner 解析、授权表与审计迁移；未知身份/部门和重复上下文预检 HALT。建模现场无存量，测试数据不假称客户迁移证明。
5. 经授权按正式部署目录流程部署测试环境；真实账号执行正向、反向、并发、故障、后台与 Chrome 95/1366×768。仅变更、失败或未覆盖项重跑。
6. 性能：20/200 模型 ACL SQL 次数、每请求主体目录查询数、2 秒超时拒绝和无重试。安全：旧会话撤权、不可见和不存在响应一致、所有引用别名、批量无副作用拒绝、伪造 SYSTEM/owner/tenant/grantId。
7. 密级链：目录并发只升、低密级 EDITOR、上游提高后大屏/消费检查、越级不扩散；大屏发现问题建独立缺陷，IT-62 不以“已登记”转通过。
8. release-plan/runbook 补旧会话重登录影响、目录依赖故障、授权排障、后台撤权处置、发布与回退。回退不得重新开放已修权限漏洞；必要时关闭建模写入口并保留数据/消费。Q5 未采集/未处置单列现场 GAP。
