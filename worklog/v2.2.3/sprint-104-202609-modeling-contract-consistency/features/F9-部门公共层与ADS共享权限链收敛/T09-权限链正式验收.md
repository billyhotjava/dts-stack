## 目标

## 使用场景

## 技术设计与契约

- **契约引用**：K73–K85 全部；契约第 8 节非功能约束。
- **账号准备**：部门甲数据管理员 A、B；部门甲领导 L；部门甲普通员工 C；部门甲低密级员工 E；部门乙数据管理员 D；研究所数据管理员 I；大屏创建者 P；应急 opadmin（仅 S14）。账号只在隔离租户或隔离部门样例中使用，不修改客户真实业务模型。
- **执行流程**：
  1. 开发目录 commit/push → `/data/dts-stack` 确认分支与工作区干净 → `git pull --ff-only` → 核对 SHA。
  2. 专项测试与正式构建（dts-platform、dts-platform-webapp、dts-admin 迁移与审计字典）→ 记录镜像 ID/digest 与包校验和。
  3. 迁移验证：清洁库执行；升级库先跑 T01 预检，再执行迁移；记录 T04 部分唯一、T06 增列回填与建表结果。
  4. 按部署目录正式流程部署到测试环境（需用户授权）。
  5. 按 IT-55–IT-63 真实页面走查，Chrome 95 与 1366×768。
  6. 审计查询：K84 全部动作归类非“未分类”，IP 正确。
  7. 非功能：模型列表 20/200 行权限计算 SQL 次数；跨部门 ID 直接访问全部 404。
- **错误路径**：任一阶段未执行只标 NOT_RUN 并注明原因；页面失败只针对受影响 IT 重跑，不整体重复。
- **复用点**：F7-T04、F8-T07 的正式交付与证据记录格式。
