# T05：公共层维护范围与跨部门引用暂停

**优先级**：P0
**状态**：IN_PROGRESS
**类型/责任**：资源授权、来源准入、后台边界开发；平台负责人待排定。
**依赖**：T01 冻结 K75/K77/K88/K89/K92、Q9/Q10；T03 当前身份、T04 部门上下文。

## 目标与场景

本部门公共模型可共同维护；所级可跨部门管理但不能建立跨部门数据引用。不同形式引用同一受治理产出得到一致结果。覆盖 S02/S08/S09/S13/S17/S20/S22/S24。

## 设计与实施

1. [K75](../../assests/F9-permission-chain-contract.md)：计划维护适配器保留入口签名，内部使用可信当前主体、真实 tenant 和精确部门；所级/ADMIN/OP_ADMIN 管理分支明确；部门角色仅同部门。计划可维护不代表可操作其中每个 ADS。
2. K77 在模型引用、sourceRefs、导入、SQL/dbt 实际读集、候选展开和执行计划生成统一生效。复用既有 CatalogAssetType/Key、来源 resolver、模型发布血缘和 dbt parser；把目录表/连接表/dbt 节点解析到受治理模型所属部门。不能只检查 dependsOn/dimensionRefs 或另造资产映射表。
3. 已有资产 READ 不能豁免跨部门公共层引用。普通外部来源维持原来源权限；受治理来源缺归属/血缘 422 `MODEL_SOURCE_SCOPE_UNRESOLVED`，解析服务故障 503；两者都不放行。选择部门不等于放宽实际用户的来源或密级权限。
4. 错误先判可见性：任一不可见上游 → 通用 404，不含模型/部门详情；全部可见但跨部门 → 422 `MODEL_SPEC_CROSS_DEPARTMENT_REF_PENDING_APPROVAL`，仅列可见违规项。所级可见而不可引用；部门用户选择器不出现他部门行，T07 保留通用入口。
5. 测试清单内历史 pin 仅允许同一模型引用集合不变的无副作用重保存；新引用、改 pin、复制或重新物化/发布/运行不获此豁免。历史模型/产出不迁移删除，原数据读取权限保留。
6. 建立 K88 的实际读/写/执行集解析与 K89 的 USER/SYSTEM 分类，供 T06 接入 ADS 判定。后台不能因 SecurityContext 为空就接受任意 plan.owner；可信系统仅能执行已部署绑定。用户任务记录稳定发起人，执行/重试前复核；无证据即阻断。

## 影响范围

ModelSpecPlanWriteAccessAdapter、ModelSpecApplicationService、来源绑定/目录资产读取适配、既有 SQL/dbt/候选/运行解析、后台协调器及 T01 全调用表；前端只消费可见候选和错误。修改符号前 impact 并报告高风险；C76“约 23 处”不作为遗漏新增入口的理由。
