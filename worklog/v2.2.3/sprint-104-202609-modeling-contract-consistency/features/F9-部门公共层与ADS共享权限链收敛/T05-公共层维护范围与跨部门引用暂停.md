# T05：公共层维护范围与跨部门引用暂停

**优先级**：P0
**状态**：DRAFT
**依赖**：T03（角色集合）、T04（部门公共层与可见范围）

## 目标

部门数据管理员与部门领导只能维护本部门公共层；所级角色可维护全部部门；任何模型都不能新增对其他部门模型的引用，存量引用只读保留。

## 使用场景

- **S02**：部门甲数据管理员 B 修改 A 创建的 DWD 字段说明并保存 → 允许，审计操作人为 B。
- **S08**：部门乙数据管理员 D 在 DWS 上游选择器中看到部门甲已发布 DWD 为禁用，旁边显示“申请跨部门引用（待开放）”；绕过页面直接提交含该引用的保存 → 422 `MODEL_SPEC_CROSS_DEPARTMENT_REF_PENDING_APPROVAL`，输入保留。
- **S09**：所级数据管理员 I 维护部门乙 DWD → 允许；I 在部门乙模型中引用部门甲模型 → 同样拒绝（Q1 已确认：所级不豁免）。
- **S13**：调岗后的 A 以部门乙身份提交部门甲模型的修改 → 403（资源不可维护）或 404（不可见），不写入。
- **存量**：部门乙某 DWS 已 pin 部门甲 DWD r3 → 原样重保存允许；改 pin 到 r4 → 422 同上。

## 技术设计与契约

- **契约引用**：C75、C76、C80、K75、K77、K84；F5 上游准入结构化拒绝结果。
- **输入**：`ModelSpecPlanWriteAccessPort.canMaintain(tenant, planId, actor)` 的全部调用；模型创建/更新/草稿提交中的 `dependsOn`、`dimensionRefs`；上游可用性投影查询。
- **输出**：
  - `canMaintain`：所级角色 → true；部门数据管理员/部门领导 → 计划 `owner_department_id` 与 JWT 部门匹配；其他 → false；无主体后台任务 → 原 owner 回退。
  - 引用准入：被引用模型所属计划部门 ≠ 当前模型计划部门 → 422 `{code:"MODEL_SPEC_CROSS_DEPARTMENT_REF_PENDING_APPROVAL", details:[{field, referencedModelSpecId, referencedDepartmentCode}]}`；审计 `MODEL_SPEC_CROSS_DEPARTMENT_REF_REJECTED`。
  - 存量：请求中的跨部门引用与当前修订已持久化引用的 `{modelSpecId, revision}` 完全相同则放行。
  - 上游可用性投影：跨部门候选输出 `selectable:false, reasonCode:"MODEL_SPEC_CROSS_DEPARTMENT_REF_PENDING_APPROVAL", departmentCode`。
- **数据流**：保存请求 → 接口角色准入（T03）→ `canMaintain`（本任务）→ 引用准入（本任务，位于既有 F5 准入之后）→ 写入 → 审计。
- **错误路径**：无维护权 403（沿用各服务既有拒绝码，T01 统一列表）；不可见计划 404；跨部门引用 422；多个违规引用一次返回全部 details。
- **复用点**：F5 上游准入的结构化拒绝与投影；`DepartmentUtils.matches`；审计既有写法。
- **实现方案**：先对 `canMaintain` 与 C76 所列调用运行 GitNexus impact 并报告风险 → 改判定实现（不改签名）→ 在引用校验处增加部门比较与存量豁免 → 上游投影增加跨部门字段 → 前端选择器消费 `selectable/reasonCode` 并渲染 K82 入口（入口文案与禁用态由 T07 统一）。

## UI 交互

- 上游选择器：跨部门候选显示名称与部门，单选框禁用，行尾显示禁用按钮“申请跨部门引用（待开放）”。
- 保存被 422 拒绝：在上游字段就地标红具体模型，保留全部输入。
- 维护被 403 拒绝：页面切换只读并提示“该公共层属于 {部门}，你没有维护权限”。

## 影响范围

`service/modeling/ModelSpecPlanWriteAccessAdapter.java`；C76 所列调用方（只验证行为不改签名）；`service/modeling/ModelSpecApplicationService.java` 引用准入；F5 上游可用性投影服务与前端上游选择器。
