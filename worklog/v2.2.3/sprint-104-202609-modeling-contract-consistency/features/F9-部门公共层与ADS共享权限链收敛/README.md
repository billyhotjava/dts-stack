# F9：部门公共层与 ADS 共享权限链收敛

**优先级**：P0（ADS 共享、跨部门入口 P1；重复建设提示 P2）
**状态**：DRAFT
**登记日期**：2026-09-12
**来源**：2026-09-09 至 09-12 用户关于“研究所—部门—员工”层级下数据连接、数据模型共享与 DWD 重复建设的讨论，决策 D1–D9 已确认。本次仅完成规划，不授权编码或部署。

## 目标与边界

具备建模角色的人只能在自己部门的公共层建模；同部门公共层 ODS/DWD/DWS 共同维护、不重复建设；ADS 归创建人，默认他人只读，创建人可把编辑权共享给同部门建模人员，部门领导与所级角色保留管理权；普通员工不能建模；任何入口都不能调低资产密级；跨部门引用与共享在审核模块建成前暂停，界面保留入口。

复用既有数仓计划、模型、创作草稿、发布与目录密级服务、资产授权与访问审批、大屏 ACL（[C71–C88](../../assests/F9-permission-chain-contract.md#5-context-ledger-c71c88)）。不新增菜单或页面；不改变大屏共享模型；不建设跨部门审核流程；不扩展权限矩阵为按钮级动作集；不改变 opadmin 应急能力。

## Review 结论与决策

- 当前没有一条完整权限链：F7 已把建模写权限改为“按菜单控制、服务端只校验已登录”（C74/C75），而测试环境建模菜单只绑定一个角色、种子里又是另一组角色码（C73），直接调用接口即可绕过菜单。F9 把角色判定收回服务端（K73），菜单只作导航。
- “一个部门一个公共层”在库里不成立：默认上下文是租户级（C77），计划没有部门唯一约束（C78），计划列表对所有人可见（C79）。F9 改为部门级默认上下文与部门范围可见（K74/K76）。
- 跨部门引用只要求上游已发布（C80），是未经审核的跨部门通道；F9 暂停并保留入口（K77/K82）。
- 目录全量保存可以直接调低密级（C83），与发布侧只升不降（C82）矛盾，是独立合规漏洞，最先修（K78）。
- ADS 个人归属需要模型级判定：现有维护判定按计划、约 23 处调用（C76），模型主表没有归属人（C81）。F9 新增模型级编辑端口与授权表，计划级操作保持原端口（K79–K81）。
- 模型编辑授权与资产数据授权是两件事：前者决定谁能改定义（新表 K80），后者决定谁能看数据（既有 C84），不合并、不双写。

## 完整权限链

```text
① 身份      Keycloak JWT：用户标识、realm 角色 ROLE_*、dept_code、personnel_level
② 角色授予  dts-admin 授权管理员授予内置角色与部门
③ 菜单导航  portal_menu_visibility 按角色码返回菜单，前端路由守卫（仅导航）
④ 接口准入  建模写接口 @PreAuthorize = MODEL_AUTHORS（K73）
⑤ 资源判定  计划部门范围（K75）→ ADS 归属/编辑授权（K81）→ 跨部门引用（K77）→ 发布职责（既有）
⑥ 密级传播  发布取上游最高并封存只升（既有）→ 目录只升不降（K78）
⑦ 数据可见  人员密级 ≥ 资产密级 ∧（显式授权 ∨ 所级角色 ∨ 同部门）（既有）
⑧ 消费出口  大屏 OWNER/MANAGER/VIEWER + 越级（既有）；跨部门申请入口（K82）
⑨ 审计      授予、撤销、拒绝、密级变更全部登记审计字典（K84）
```

上层通过不代表下层通过：菜单可见不等于接口可调；接口可调不等于可改某个计划或 ADS；可改模型不等于可看数据；大屏越级只在大屏展示生效。

## UI/UX 规格

沿用既有工作台、目录与数据集详情页，不新增菜单或页面。

```text
模型工作台（所级角色可见部门选择；部门角色显示本部门名称）
┌ 模型工作台 ──────────── 公共层：[部门甲 ▼] ─────────── [新建模型] ┐
│ 名称            层级  状态     归属      我的权限                 │
│ 项目任务快照明细  DWD  已发布   部门公共层  可编辑                 │
│ 项目月报         ADS  草稿     张三      只读（编辑需创建人授权）   │
└────────────────────────────────────────────────────────────────┘

ADS 工具栏  [保存设计] … [共享]
┌ 共享“项目月报” ───────────────────────────────┐
│ 添加可编辑成员： [搜索本部门建模人员或角色 ▼] [添加] │
│ 成员        权限     授予人  时间        操作      │
│ 李四        可编辑   张三   09-12 10:20  [撤销]    │
│ 部门领导（管理权，默认拥有，不可撤销）             │
│ [申请跨部门共享（待开放）]                         │
└──────────────────────────────────────────────┘

上游选择器
│ ○ 项目任务快照明细（部门甲，已发布）                │
│ ⊘ 合同台账明细（部门乙）  [申请跨部门引用（待开放）] │

资产编辑 · 密级
│ 密级 [机密 ▼]（只能调高；可选：机密、绝密）          │
```

- **四态**：工作台列表空（本部门尚无模型，显示“新建模型”）/加载/读取失败（保留已知内容并可重试）/成功；共享抽屉空（尚无授权成员）/加载/失败（保留输入，显示错误码对应文案）/成功（刷新列表）；无权限统一只读或 404，不显示可点击但必失败的按钮。
- **关键交互**：保存被 403 拒绝时保留输入并显示原因；撤销授权后被撤销人下一次写操作返回 403，页面切换只读；密级降级提交被拒时恢复原值；跨部门候选不可选但可见名称与部门。
- **帮助**：“公共层与共享规则”说明放入右上角既有帮助，页面只保留状态与原因。
- **兼容**：Chrome 95、1366×768、键盘可达；不引入新浏览器 API。

**主走查**：部门甲数据管理员 A 首次新建 DWD（自动建立部门甲公共层）→ 同部门 B 修改该 DWD → A 新建 ADS → B 打开 ADS 只读 → A 共享编辑给 B → B 修改成功 → A 撤销 → B 保存被拒 → 部门乙 D 在上游选择器看到部门甲模型不可选 → 普通员工 C 看不到建模菜单、直接调接口 403 → 目录维护者降密级被拒、升密级成功。完整场景见契约 S01–S16。

## 任务通用契约

以下四项对 T01–T09 统一生效，Task 只写差异。

- **数据流与复用**：登录身份 → 角色与部门声明 → 接口角色准入 → 服务端资源判定 → 既有 owner 写入 → 审计。每个 Task 只改其对应层，全部复用账本中的既有类；新增端口只在 K81 一处，不另建第二套计划或资产授权。
- **错误路径**：无建模角色 403 `MODELING_ROLE_REQUIRED`；有角色但无资源权限 403（K75/K81 对应码）；不可见资源 404 防枚举；业务规则拒绝 422 并回传 `reasonCode/field/details`；版本冲突 409 沿用既有 CAS。拒绝不得清空用户输入，不得显示成功，不得降级为 500。
- **存储与兼容**：只做前向 changeSet；存量计划、模型、已发布结果、资产授权与大屏共享保持可读，不静默改写；迁移前预检输出清单，无法判定时中止而非猜测。
- **UI 落点**：使用既有工作台、目录与数据集详情页；每个具名控件具备空、加载、错误、成功与无权限反馈；按钮启用状态来自服务端 allowedActions，不在前端重算权限。
