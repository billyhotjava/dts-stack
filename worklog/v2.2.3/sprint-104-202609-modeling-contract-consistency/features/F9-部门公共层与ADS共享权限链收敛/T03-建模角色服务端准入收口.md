# T03：建模角色服务端准入收口

**优先级**：P0
**状态**：IN_PROGRESS
**类型/责任**：跨服务身份适配与开发验证；dts-admin、dts-platform、前端负责人待排定。
**依赖**：T01 冻结 K73/K86/K87/K90、Q8 适配和角色/入口矩阵；与 Q5 解耦。

## 目标与场景

普通员工不能建模；四种建模角色在其资源范围内获得约定能力；旧会话的角色/部门快照不能继续放行已撤权人员。覆盖 S10/S14/S18/S19/S23，为 T04–T06 提供统一身份上下文。

## 设计与实施

1. 按 [K87 §6.1](../../assests/F9-permission-chain-contract.md#61-稳定主体旧会话与撤权) 在登录成功时记录服务端确认的稳定 directoryUserId；扩展现有会话实体/记录与前向迁移，不改变其他消费者的 sub/username。旧会话缺 ID 时仅建模边界返回 401 `MODELING_REAUTHENTICATION_REQUIRED`，不静默按用户名回填。
2. 落地 K86：admin 目录精确 ID 解析当前 roles/enabled/deptCode/personnelLevel，Gateway/Client 全链字段适配。返回缺字段、服务故障不当作空白有效身份；总超时 2 秒，无自动重试，不跨请求缓存允许结果。
3. 建模受保护读写请求均先认证，再按稳定 ID 取当前权威属性，构造请求内上下文；方法准入、服务端资源判定和建模相关数据访问共用。不能由旧会话角色提前作最终放行/拒绝，不全局改变大屏/目录会话策略。
4. C74 作为起点补齐 Q9 接口清单，角色准入用 MODEL_AUTHORS，实际发布动作再按 K90 分工。同步平台/admin 三组职责、ReleaseDutyResolver、ReleaseDutyInternalResource、后台目录检查和 allowedActions；使用同一矩阵契约测试。
5. 普通员工/纯自定义角色 403 `MODELING_ROLE_REQUIRED`；停用/删除主体 401 `MODELING_IDENTITY_INACTIVE`；当前属性不可取 503 `MODELING_IDENTITY_UNAVAILABLE`，不回退快照。角色撤销后的旧请求应失败；角色新增后的新判定无需借过期会话角色放行。
6. 菜单只作导航：保留历史人工配置，迁移只补内置绑定；建模导航结果与当前建模能力取交集。历史给员工/自定义角色的菜单绑定不能成为授权或可用建模入口。
7. 授权、拒绝、身份失效审计登记字典；opadmin 应急审计保留，ADMIN 不等同于 OP_ADMIN，不能意外扩大发布职责。

## 影响与验收

范围：两服务 AuthoritiesConstants、目录 Resource/Gateway/Client、现有门户会话与建模认证扩展点、C74/Q9 Resource 清单、菜单输出/前端入口、审计/会话迁移。均为计划影响面，本轮未修改源码；实施前按符号 impact。

IT-57：四种内置建模角色、ADMIN、opadmin、普通员工、纯自定义角色及组合角色，逐动作核对 K90；旧会话撤角色/调岗/停用/降人员密级，旧会话无 ID、目录超时、新授角色、用户名不同于 ID、同名重建账号。验证请求中伪造 actor/部门/角色无效，平台/admin 职责一致；会话改动还回归既有非建模登录消费路径。

## Ready 与完成标准

- Ready：身份字段与会话适配、方法准入顺序、目录访问权限、职责矩阵和专项用例冻结；实现估算按清单后补。
- Done：稳定 ID、当前属性授权、入口/后台职责与导航契约验证完成；迁移清洁库/升级库和 IT-57 证据分项记录。
- F7 IT-46 的“普通菜单用户可保存”在本切片正式交付后由 IT-57 替代；历史证据不改写。
- T03–T06 完整后才开放新的建模权限切片，不能先上线半套收紧逻辑。
