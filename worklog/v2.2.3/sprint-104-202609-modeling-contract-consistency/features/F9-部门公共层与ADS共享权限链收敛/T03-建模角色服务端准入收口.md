# T03：建模角色服务端准入收口

**优先级**：P0
**状态**：DRAFT
**依赖**：T01（K73 冻结）；Q3 已确认：自定义角色不算建模角色

## 目标

只有部门数据管理员、部门领导、研究所数据管理员、研究所领导（及应急 opadmin）能调用建模写接口；普通员工看不到建模菜单，直接调接口得到 403。

## 使用场景

- **S10**：普通员工 C 登录后菜单中没有“模型与标准”；直接调用 `POST /api/modeling/model-specs/draft-operations` 返回 403 `MODELING_ROLE_REQUIRED`；C 仍可按部门与密级查看本部门已发布资产和被授权大屏。
- **S01 前置**：部门甲数据管理员 A 可见建模菜单并能发起保存（部门范围判定由 T04/T05 负责）。
- **S14**：opadmin 应急登录后建模能力不变，写入审计标注应急账号。

## 技术设计与契约

- **契约引用**：C72、C73、C74、C75、K73、K84；替代 F7 契约 §1。
- **输入**：JWT realm 角色；C74 列出的全部建模写接口。
- **输出**：
  - `AuthoritiesConstants.MODEL_AUTHORS = {ROLE_INST_DATA_OWNER, ROLE_INST_LEADER, ROLE_DEPT_DATA_OWNER, ROLE_DEPT_LEADER, ROLE_ADMIN, ROLE_OP_ADMIN}`。
  - C74 中使用 `isAuthenticated()`、`CATALOG_MAINTAINERS`、`MODEL_MAINTAINERS` 的建模写方法统一改为 `hasAnyAuthority(MODEL_AUTHORS)`；发布职责接口 `MODEL_RELEASE_DUTIES` 保持，但集合需包含部门领导（与 D2 一致，T01 冻结）。
  - 读接口保持已认证，范围由 T04/T05 限定。
  - 拒绝：403 `{code:"MODELING_ROLE_REQUIRED"}`，审计 `MODELING_ROLE_DENIED`。
  - 菜单：dts-admin 建模菜单可见性绑定与 `MODEL_AUTHORS` 一致，前向 changeSet 只插入缺失绑定，不删除管理员已有的自定义绑定；与 K73 不一致的绑定输出清单由授权管理员处理。
- **数据流**：登录 → JWT 角色 → Spring 方法级准入 → 服务端资源判定（T04/T05/T06）→ 写入。
- **错误路径**：无角色 403；JWT 缺角色声明按无角色处理；后台无主体任务不经过接口层，保持原 owner 回退。
- **复用点**：`AuthoritiesConstants` 既有角色集合定义方式；dts-admin 菜单可见性表与既有绑定 changeSet 写法。
- **实现方案**：新增集合常量 → 逐个替换 C74 所列表达式 → 前端 `useDataModelingMenuGrant` 保持导航职责，另在新建/保存按钮上消费服务端 403 显示“当前角色无建模权限” → 菜单绑定 changeSet → 审计字典登记。

## UI 交互

- 无建模角色：建模菜单不可见；通过书签直达工作台时显示只读提示“当前角色无建模权限”，不显示新建与保存按钮。
- 有角色但被 403（例如角色刚被撤销、令牌未刷新）：保留输入，提示重新登录或联系授权管理员。

## 影响范围

`security/AuthoritiesConstants.java`；C74 所列 `web/rest/` 文件；dts-admin 菜单可见性 changeSet 与审计字典；`dts-platform-webapp` 模型工作台新建与保存入口。修改前对每个 Resource 类运行 GitNexus impact。
