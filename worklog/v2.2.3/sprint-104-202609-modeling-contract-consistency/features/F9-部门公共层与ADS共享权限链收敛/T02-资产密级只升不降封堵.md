# T02：资产密级只升不降封堵

**优先级**：P0
**状态**：DRAFT
**依赖**：T01（K78 冻结、Q5 历史降级清单）

## 目标

任何用户入口都不能把资产目录中数据集的密级调低；调高经密级服务记录人工下限并审计。

## 使用场景

- **S11**：目录维护者把机密资产改为内部 → 409 `CLASSIFICATION_DOWNGRADE_FORBIDDEN`，原值不变，页面恢复原密级并提示“密级只能调高”；改为绝密 → 成功，审计记录前后值。
- **S12 前置**：ADS 发布后的机密密级不会被人为调低，保证低密级员工在目录中始终看不到该资产。

## 技术设计与契约

- **契约引用**：C82、C83、C84、K78、K84。
- **输入**：`PUT /api/catalog/datasets/{id}`，请求体 `classification`（以及 T01 列出的其他写 `catalog_dataset.classification` 的用户入口）、If-Match。
- **输出**：
  - 新值 < 当前有效密级：409，`{code:"CLASSIFICATION_DOWNGRADE_FORBIDDEN", details:{current, requested}}`，数据集任何字段均不写入。
  - 新值 > 当前：调用 `CatalogClassificationService` 提升人工下限后写入，200。
  - 新值 = 当前或未传：密级不变，其余字段按原逻辑保存。
- **数据流**：资产编辑表单 → `CatalogDatasetResource.updateDataset` → 密级比较（以当前有效密级为基准，`SecurityLevelCatalog.isDataDowngrade`）→ `CatalogClassificationService` → `catalog_dataset.classification` → 审计。
- **错误路径**：非法密级码 400；无编辑权 403 沿用；版本冲突 409 `CATALOG_DATASET_VERSION_CONFLICT` 沿用，与降级 409 以错误码区分。
- **复用点**：`CatalogClassificationService` 的只升逻辑与 `CLASSIFICATION_DOWNGRADE_FORBIDDEN` 错误码；不另写密级比较。
- **实现方案**：在全量保存写 classification 前增加比较；T01 列出的其他入口同样收口到同一方法。审计动作 `CATALOG_CLASSIFICATION_RAISE`、`CATALOG_CLASSIFICATION_DOWNGRADE_REJECTED` 在 dts-admin 审计字典登记。

## UI 交互

- 资产编辑的密级下拉只列出不低于当前密级的选项，当前值高亮。
- 服务端返回降级 409 时，表单恢复原密级，显示“密级只能调高，当前为 {current}”，其他已编辑字段保留。
- 四态：加载中禁保存；错误保留输入；成功刷新详情并显示新密级。

## 影响范围

`web/rest/catalog/CatalogDatasetResource.java`、`service/catalog/CatalogClassificationService.java`（仅复用）、资产编辑表单组件、dts-admin 审计字典 changelog。
