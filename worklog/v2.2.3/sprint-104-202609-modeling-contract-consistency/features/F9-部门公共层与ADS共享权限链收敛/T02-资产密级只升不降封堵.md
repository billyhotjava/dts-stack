# T02：资产密级只升不降封堵

**优先级**：P0
**状态**：IN_PROGRESS
**类型/责任**：缺陷修复、开发验证；dts-platform 与审计字典负责人待排定。
**依赖**：T01 冻结 K78、全部密级写入口及相关审计子集；不依赖其余权限契约、Q5 扫描完成或历史恢复决定。

## 目标与场景

S11：机密改内部被拒、改绝密成功；S12/S26：ADS 的数据可见性不能因人工保存降级而放宽。目录是既有功能，必须保护存量；历史降级恢复另按 Q5 处理。

## 设计与实施

- [K78/K84](../../assests/F9-permission-chain-contract.md)：CatalogDatasetResource 全量保存及 T01 列出的其他用户入口统一复用 CatalogClassificationService / SecurityLevelCatalog，只升人工下限，不新建密级比较实现。
- 输入为 classification 与既有 If-Match。低于当前有效密级返回 409 `CLASSIFICATION_DOWNGRADE_FORBIDDEN`，整次表单修改不提交；提高走人工下限服务；相等或未传不修改；显式空值/非法码 400。
- 保留既有编辑权限与 AssetAction 门禁，过期版本沿用 CAS 冲突。并发提升人工下限与表单保存不能覆盖成较低值；用户输入不是有效密级的事实源。
- 提升和拒绝审计在 dts-admin 字典登记；拒绝事件不能因业务事务回滚而消失，复用现有可持久化失败审计机制，具体落点由 T01 核实。
- 前端下拉只列不低于当前值，降级拒绝后恢复当前密级、保留其他输入；加载/错误/成功/无权限态沿用原表单。

## 影响与验证

范围：CatalogDatasetResource、现有密级服务的调用点、资产编辑表单、审计字典；不处理未经授权的历史数据恢复。编辑源码符号前运行 GitNexus impact。

IT-56：所有写入口的降级/升级/不传/空值/非法值，旧 If-Match、并发人工提升与全量保存、失败审计。检查数据库有效密级和人工下限、整次修改原子性、审计归类及 Chrome 95 反馈。

## Ready 与完成标准

- Ready：密级最小契约和入口清单冻结，可设计专项用例；Q5 不设为开工条件。
- Done：源码与专项验证、正式包/部署/真实 IT-56 分项留证；若只完成编码，仅记录编码完成。
- 本任务可独立构建发布。Q5 未执行/未处置始终单列，不伪称现场历史降级已恢复；回退不可恢复降级漏洞。
