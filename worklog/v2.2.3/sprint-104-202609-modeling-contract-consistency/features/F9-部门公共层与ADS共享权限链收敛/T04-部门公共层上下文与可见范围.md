# T04：部门公共层上下文与可见范围

**优先级**：P0
**状态**：DRAFT
**类型/责任**：公共层生命周期与查询范围开发；平台/前端负责人待排定。
**依赖**：T01 冻结 K74/K76/K91/K92、测试预检与 Q10 部门标识；T03 当前身份上下文。

## 目标与场景

每租户每部门至多一个可写公共层，首次保存创建、后续共用；所级角色可选择真实部门建模。覆盖 S01/S09/S13/S16/S17/S24/S25。现场建模无存量，只对测试环境旧上下文做预检转换。

## 设计与实施

- 按 [K74/K91/K92](../../assests/F9-permission-chain-contract.md) 使用权威部门编码严格相等。禁止 DepartmentUtils.matches、尾号匹配和父子部门继承；未知部门拒绝，不把前端显示名称当身份。
- 部门角色取 K87 当前部门；所级/ADMIN/OP_ADMIN 必须选择目录内有效部门，无需本人隶属所选部门。选择不改变真实 actor；来源检查同时保留实际人员权限与目标计划范围。未知部门 400、部门角色越范围 403，显式 planId 与部门不一致拒绝。
- GET creation-context → `{planId,departmentCode,writable}`，不创建对象。首次保存使用规范部门幂等键与租户/部门事务锁，初始化/保存失败整体回滚。
- 所有创建入口（手工建计划、导入、草稿首次保存）统一复用键与锁；不能自定义幂等键建第二公共层。部分唯一索引排除 ARCHIVED；预检空/未知部门、重复计划和旧键冲突，失败 HALT 清单，不猜归属。
- 默认公共层所属部门不可变；正常接口整体发布/归档该容器返回 K91 的 409，模型自己的状态流不受此限制。已异常归档或发布的默认上下文返回 `MODELING_CONTEXT_NOT_WRITABLE`，不释放固定键另建；恢复走具体运维方案。
- K76 查询范围服务端统一：计划/模型列表详情、版本、草稿、关系图、计数、交付状态、辅助查询均过滤。不允许先取全部信息再只隐藏前端行；部门用户不返回他部门名称/ID/部门/数量，不存在与不可见同为通用 404。

## UI 与影响范围

部门角色显示只读部门名称；所级/兼容管理角色显示部门选择。切换保留离开保护；四态与无部门错误明确。上游选择器只列可见对象，通用待开放入口由 T07 提供。

ModelingContextInitializationService、WarehousePlanAuthorizationGuard、WarehousePlanApplicationService/Resource、ModelSpec 与辅助查询、前端上下文/页头、计划迁移；实施前 impact。不要改全产品 DepartmentUtils 的兼容语义来完成本任务。

## 验证与完成标准

- Ready：上述契约/调用清单冻结，T03 当前主体可用；测试库预检，非现场建模预检。
- IT-58：两部门初始化、同部门并发、所有直接创建入口、所级无本人部门但合法选择；1153/153/父子部门不串权；旧会话调岗后访问；列表/图/计数 404 防枚举；改部门/归档/发布公共层/异常上下文重试。
- Done：初始化和迁移原子性、可见范围、生命周期专项验证及清洁库/升级库证据齐全；正式交付与 Chrome 95 另记，不能由设计文档替代。
