# T48：保存前静态校验与编辑页契约提示

**优先级**：P0
**状态**：IN_PROGRESS
**依赖**：T44

## 目标

SQL 不合规在保存前就被指出，页面写明真实契约，用户不必靠运行失败来发现约束。

## 技术设计与契约

- **契约引用**：C56、C57、C67、C68、C70；K67、K68，见 [统一契约与账本](../../assests/F8-quality-rule-execution-contract.md)。
- **通用契约**：数据流与复用、错误路径、存储与兼容、UI 落点见 [任务通用契约](README.md#任务通用契约)；本文件只写差异。
- **本任务输入/输出**：入参 `{sql, datasetId}`；出参 `{valid, reasonCode, detail, message, requiresIdColumn, warnings}`。保存不通过返回 400 并回传 reasonCode/detail。
- **方案**：新增静态校验端点，复用 C70 的 checkScope 与 C57 的只读正则，纯静态、不连库、零副作用；规则保存以其替换 C56 的非空校验。编辑页在「检测 SQL」区增加「校验」按钮与契约提示（允许函数清单、结果集要求、schema.table 限定），并接入既有试跑接口 C68；占位示例改为在无 id 列的表上也能跑通的形态（C67）。存量规则按 T44 冻结策略处置，默认只对本次提交内容生效，不回溯改写历史规则。
- **本任务差异**：静态校验须断言允许只读平台元数据查询，禁止目标数据源连接和用户 SQL 执行且单次 ≤200ms；不得成为探测他表存在性的旁路；试跑按钮按权限禁用而非报 403（T44 开放问题 4）。

## UI 交互与影响范围

GovernanceResource、QualityRuleService.requireExecutableDefinition、QualitySqlScopeValidator、RuleEditorPage.tsx、ModelTargetQualityPanel.tsx。本任务具名控制项的状态反馈要求见 [任务通用契约](README.md#任务通用契约)。

## 验证与验收

含 btrim 以外越界函数的 SQL 保存被拒并点名函数；跨表引用被拒；合规 SQL 保存成功；校验按钮四态可用；试跑走通并不生成工单；无权限时按钮禁用且说明原因；存量规则按冻结策略表现一致；校验过程无目标数据源连接。

映射 **IT-52**，见 [F8 验收清单](../../it/F8-质量规则闭环验收.md)。实现任务先用对应缺陷场景建立失败证据，再进行一次成组验证，不重复全仓检查。编译性测试只在 deploy 经 Git 同步后执行；验收样本仅用于隔离测试，不预置为客户页面演示数据。
