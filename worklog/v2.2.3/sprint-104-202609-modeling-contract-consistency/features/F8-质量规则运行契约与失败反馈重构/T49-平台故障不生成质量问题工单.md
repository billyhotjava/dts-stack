# T49：平台故障不生成质量问题工单

**优先级**：P1
**状态**：DRAFT
**依赖**：T44、T46

## 目标

只有真实数据质量问题才产生待认领工单，平台自身故障走运维提示。

## 技术设计与契约

- **契约引用**：C64；K71，见 [统一契约与账本](../../assests/F8-quality-rule-execution-contract.md)。
- **通用契约**：数据流与复用、错误路径、存储与兼容、UI 落点见 [任务通用契约](README.md#任务通用契约)；本文件只写差异。
- **本任务输入/输出**：入参为 T46 产出的双维度结论；出参为是否建单及单据类型。
- **方案**：按 K71 准入：仅 `qualityOutcome=VIOLATION` 生成质量问题工单；`executionOutcome=FAILED` 且无违规结论时不建待认领业务工单，改为运维可见的失败提示。试跑维持不建工单（C68）。已存在的错误工单不自动删除，处置方式由 T44 冻结。
- **本任务差异**：涉及既有工单数据，须明确历史误建工单的处置口径并留证；不得静默批量删除。

## UI 交互与影响范围

QualityRunService.createIssueForFailedRun、QualityRunAuditCoordinator、问题处置进度区。本任务具名控制项的状态反馈要求见 [任务通用契约](README.md#任务通用契约)。

## 验证与验收

纯平台故障不建业务工单且运维提示可见；查出违规行时正常建单；两者同时发生时按业务结论建单且执行故障单独提示；重复运行不产生重复工单；审计事件完整。

映射 **IT-53**，见 [F8 验收清单](../../it/F8-质量规则闭环验收.md)。实现任务先用对应缺陷场景建立失败证据，再进行一次成组验证，不重复全仓检查。编译性测试只在 deploy 经 Git 同步后执行；验收样本仅用于隔离测试，不预置为客户页面演示数据。
