# F8：质量规则运行契约与失败反馈重构

**优先级**：P0（页面反馈项 P1）
**状态**：DRAFT
**登记日期**：2026-09-10
**来源**：2026-09-10 两次真实运行失败（`727cbc0c-…` DATASET_SCOPE_BLOCKED、`a06452ba-…` RESULT_ID_REQUIRED）及用户提出的"编辑时输入的是普通 SQL，为什么不能兼容"。本次仅完成规划，不授权编码或部署。

## 目标与边界

业务人员在规则编辑页写 SQL，**保存前**就知道它能不能跑、哪一条约束不满足、该怎么改；运行失败时页面直接给出具体原因和改法，而不是笼统兜底句；平台自身故障不再冒充数据质量问题，也不再掩盖同一次运行已经查出的违规数据。

复用既有规则/运行模型、既有 `gov_quality_run.error_category`、既有作用域校验器与试跑接口（[C68](../../assests/F8-quality-rule-execution-contract.md)）。不重写领域模型、不更换执行引擎、不新增菜单、不引入方言转换层、**不放宽只读与绑定表作用域的安全边界**。

## Review 结论与决策

- 问题不是两个 bug，是**契约从未被声明也从未被前置校验**：保存只查非空（C56），全部约束推迟到运行时引爆（C57、C60）。
- 约束分三类，处置不同：**真实安全边界**（只读、只引用绑定表）保留并前移到保存期；**实现过窄**（函数白名单按拼写而非能力，C58）已由提交 `4c58ce207` 修正 trim 家族并结构化拒绝原因（C70）；**实现泄漏**（必须返回 `id` 列，C60）零安全价值，直接去掉。
- `id` 要求只服务于跨语句去重，而报错发生在**规则已经查出违规行之后**（C61）——检测成功、统计失败，却整次判失败。修复后单语句规则不再执行该查询。
- 基础设施错误压制业务结论（C63）与无差别生成待认领工单（C64）是同一病根：**平台故障与数据质量问题共用一条结论通道**，必须拆成两个维度。
- 试跑能力后端已有、前端从未接入（C68）。不新建预检服务，接现成的。
- 存量规则的兼容策略不预设：先出计数（T44 开放问题 1），再决定拦截/告警/仅新保存生效。

## UI/UX 规格

沿用既有质量工作台，不新增页面。

```text
规则编辑 · 检测 SQL
┌──────────────────────────────────────────────┐
│ [SQL 文本域]                                  │
│ 契约提示：只读查询 / schema.table 完整限定 /   │
│           允许函数清单 / 结果集要求            │
│ [校验]  [试跑]            校验结果：✔ 或 ✘+原因 │
└──────────────────────────────────────────────┘
保存：未通过校验则拒绝保存并定位到问题处

运行详情
┌ 业务结论 ─────────┐ ┌ 执行状态 ──────────────┐
│ 通过 / 发现 N 条   │ │ 正常 / 失败：<分类>     │
│ [查看失败样本]     │ │ 原因：<detail>          │
└───────────────────┘ │ 建议：<可执行改法>      │
                      └────────────────────────┘
```

四态：校验中/通过/不通过/无权限；运行详情的空、加载、错误、成功均须走查。占位示例改为在无 `id` 列的表上也能跑通的形态。键盘操作与 Chrome95 沿用既有约束。

走查：编辑规则 → 写入含越界函数的 SQL → 点校验 → 页面点名该函数并给出允许清单 → 改正 → 校验通过 → 试跑 → 保存 → 正式运行 → 查出违规行且执行状态正常 → 制造一次平台故障 → 业务结论仍可见、执行状态单列；纯故障不建单，混合场景按违规建单。

## 任务通用契约

以下四项对 T44–T50 统一生效，Task 只写差异。

- **数据流与复用**：规则编辑页 → 静态校验/保存准入 → 质量运行触发 → `QualityDatasetStatementExecutor` 两道预检 → 只读连接执行 → 结论分类 → 运行详情与工单。每个 Task 只承担其对应段，全部复用账本中的既有类，禁止另建平行实现。
- **错误路径**：输入非法 400 并回传 `reasonCode/detail`；未认证/越权沿用 401/403；不可见对象沿用既有防枚举策略，静态校验不得成为探测他表存在性的旁路；并发保存冲突 409。失败不得显示成功、不得清空用户已输入的 SQL。
- **存储与兼容**：复用 `gov_rule` / `gov_rule_version` / `gov_quality_run` / `gov_quality_failing_row`；`error_category` 列与既有取值不变，只扩展取值集合。新增字段仅按 T44 冻结内容落地，禁止双写形成第二事实源。
- **UI 落点**：使用既有质量工作台页面与深链，不另建工具页面；每个具名控制项必须有空、加载、错误、成功及无权限反馈。T44/T50 的界面工作限于只读走查与证据记录。
