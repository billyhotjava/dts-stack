# T03：业务结论与执行故障双维度分离

**优先级**：P0
**状态**：IN_PROGRESS
**依赖**：T01、T02

## 目标

同一次运行里，已查出的违规数据与平台自身故障各自呈现，互不覆盖。

## 技术设计与契约

- **契约引用**：C63、C65；K70，见 [统一契约与账本](../../assests/F8-quality-rule-execution-contract.md)。
- **通用契约**：数据流与复用、错误路径、存储与兼容、UI 落点见 [任务通用契约](README.md#任务通用契约)；本文件只写差异。
- **本任务输入/输出**：入参为语句结果集合；出参为 `qualityOutcome`（PASSED/VIOLATION）与 `executionOutcome`（OK/FAILED+分类）两个独立维度及其落库位置。
- **方案**：修正 `dominantFailureCategory` 返回首个非 QUALITY_VIOLATION 分类导致的压制（C63）：业务结论与执行结论分别求值并分别保存，基础设施故障不得清除已得出的违规结论。`classifyExecutionError` 的英文子串匹配（C65）保留为兜底，但凡有结构化 errorCode 一律优先，不新增子串规则。两个维度的持久化位置由 T01 冻结，优先复用既有列。
- **本任务差异**：如 T01 判定需要持久化第二维度，必须给出正式 changeSet 并验证历史数据；不得为此新增业务表。

## UI 交互与影响范围

QualityRunOutcomeSemantics、QualityRunService（resolveErrorCategory、run 落库）、GovQualityRun。本任务具名控制项的状态反馈要求见 [任务通用契约](README.md#任务通用契约)。

## 验证与验收

已查出违规行且随后统计/连接失败时，业务结论仍为 VIOLATION 且失败样本可见，执行状态单列为对应分类；纯平台故障时业务结论为空而非伪装通过；纯违规时执行状态为 OK；历史运行记录读取不报错。

映射 **IT-50**，见 [F8 验收清单](../../it/F8-质量规则闭环验收.md)。实现任务先用对应缺陷场景建立失败证据，再进行一次成组验证，不重复全仓检查。编译性测试只在 deploy 经 Git 同步后执行；验收样本仅用于隔离测试，不预置为客户页面演示数据。
