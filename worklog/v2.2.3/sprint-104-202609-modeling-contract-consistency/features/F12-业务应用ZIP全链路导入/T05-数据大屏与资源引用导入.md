## 原 DoR 缺口（历史发现，修订结果见文末）

按[目标契约实测对照](领域载荷与接口契约.md#目标契约实测对照2026-09-22-源码核对)，本任务**未通过 Definition of Ready，保持 DRAFT**。与 T04 不同，这里不是补字段，而是 **v1 `dts.screen/v1` 载荷与目标 ScreenSpec 整体不同构，须重做**：

1. **结构层级不符**：v1 `canvas:{width,height}` 与 `Component.frame:{x,y,width,height}` 两层包装在目标中都不存在；目标为根级扁平 `width`/`height`（`ScreenSpecValidator.java:98`–`:99`，范围 200–7680 / 120–4320）与组件级扁平 `x`/`y`/`width`/`height`（`:174`–`:177`）。
2. **组件类型枚举完全不匹配**：v1 的 `CARD|TEXT|IMAGE` 三值在目标白名单中均不存在。目标 `COMPONENT_TYPES` 为 48 项具体类型（`:17`–`:70`），如 `line-chart`/`bar-chart`/`table`/`image`/`title`/`markdown-text`/`richtext`/`number-card`/`stat-card`/`filter-select` 等。v1 须改为"目标白名单的受支持子集"，并明确子集范围。
3. **卡片引用位置不同**：目标通过 `components[].dataSource.sourceType`（枚举 `static/api/card/sql/dataset/metric/database`，`:71`、`:208`）表达，不是独立的 `card` 字段。
4. **交互模型不同**：目标为 `components[].interaction`/`drillDown`/`actions`（`:180`–`:182`）加根级 `globalVariables`（`:101`，类型仅 string/number/date）；v1 的 `filters`/`interactions` 无对应。
5. **字段归属待实测**：v1 的 `theme`、`backgroundResource` 在校验器中无对应分支，是否被目标接受须实测确认，不得假定。
6. **schemaVersion 缺失**：目标根级要求 `schemaVersion`（`:97`），v1 载荷未携带。
7. **安全口子必须显式关闭**：目标白名单含 `iframe`、`video`，且 `config` 内的 plugin marker 可放行白名单外类型（`:165`、`:170`）。这与"不导入任意 URL 跳转或脚本"直接冲突。**须在导出预检查中显式阻断 `iframe`/`video` 及带 plugin marker 的组件**，只在散文里声明禁止不算实现。

重做后的 SCREEN 载荷须回写[领域载荷与接口契约](领域载荷与接口契约.md)并经 T03 冻结，方可转 READY。
