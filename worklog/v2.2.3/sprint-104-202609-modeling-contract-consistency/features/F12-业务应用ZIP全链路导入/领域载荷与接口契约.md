# F12 领域载荷与接口契约

版本：v1设计基线，2026-09-22。本文规定新增导入协议；已有普通创建API不能直接视为具备幂等、CAS或暂存能力。T03–T06必须用契约测试落实适配，不直接跨库写数据。

## 公共载荷规范

UTF-8 JSON，拒绝重复键及未知schemaVersion。标识localKey为ASCII `[A-Za-z][A-Za-z0-9_.:-]{0,127}`；kind枚举固定，名称1–128字符，描述最多4000字符。业务配置JSON采用指定schema白名单，不能承载任意脚本。v1每种载荷均带schemaVersion、name、description、references；禁止目标租户、用户、连接密码和原环境ID参与写入。

Ref = `{localKey, kind}` 或 `{requireKey, kind}`，二者互斥；前者必须出现在objects中，后者必须出现在requires中。外部依赖用requireKey:string、kind、stableCode、versionConstraint（v1仅精确版本或CURRENT）表示；CURRENT在preview解析并固定到具体版本，apply再校验。每个引用均可定位fieldPath（JSON Pointer），替换只发生于schema声明位置，不对SQL/JSON全文做字符串替换。

contentChecksum：SHA256，对该对象载荷执行RFC8785规范化；字符串不隐式trim、数组顺序保留、拒绝非有限数字。文件sha256计算原始字节；模型项校验和使用现有规范化模型契约。源码ZIP hash与业务内容hash不同，ZIP重压不应引发业务UPDATE。packageVersion为SemVer，旧schema不支持时拒绝并返回支持列表，版本升级通过显式迁移器，不能猜测字段。

### 查询数据集字段映射

FieldRef=`{model:Ref(MODEL),fieldCode:string}`；MeasureRef=`{model:Ref(MODEL),measureCode:string}`。度量必须已经注册在目标语义版本，导入不创建聚合口径、不扩展 F6。Dimension=`{field:FieldRef,granularity?:string}`，granularity 必须是目标字段已支持粒度。

| 包字段 | 目标 SemanticQueryBody / 创建请求 | 转换及失败规则 |
|---|---|---|
| baseModel | state.base | 解析为目标语义模型 ID 并固定版本；未就绪进入暂存，禁止使用原环境 ID |
| query.joins:[{to:Ref(MODEL),relationshipCode,type}] | state.joins:[{to,via,type}] | 仅唯一已确认关系；type 必须是该关系允许类型；无关系/歧义报 FIELD_MAPPING_INVALID，不拼接 SQL |
| query.measures:MeasureRef[] | state.measures:string[] | 稳定代码→目标已注册度量 ID；缺失或自带 aggregation 阻断 |
| query.dimensions:Dimension[] | state.dimensions | 无粒度写 id，有粒度写 {id,granularity}；不丢失粒度 |
| query.filters:[{field,op,value?,valueTo?}] | state.filters:[{field,op,value?}] | field 解析目标 ID；包 op 为 EQ/NE/GT/GE/LT/LE/IN/BETWEEN/IS_NULL，显式映射 EQ→=、NE→!=、GT→>、GE→>=、LT→<、LE→<=、IN→in、BETWEEN→between、IS_NULL→is_null；T04 用真实解析器验证，不直接透传枚举 |
| query.orderBy:[{field:FieldRef 或 MeasureRef,direction:ASC或DESC}] | state.order_by | 已选维度/度量解析后写 field；direction 显式转 asc/desc |
| query.timeRange:{field,start,endExclusive,timezone} | state.timeRange:{fieldRef,start,endExclusive,timezone} | ISO8601 半开区间，start < endExclusive，IANA 时区显式携带且可解析；日期字段类型核对 |
| query.limit | state.limit | 整数 1–10000；不依赖目标缺省值 |
| 已确认目标工作区映射 | workspace_id | 来源为本次授权目标上下文，不从 ZIP 信任目标 ID |

query 必含 dimensions/measures/filters/orderBy 数组及 limit，至少一个维度或度量；joins/timeRange 可选。BETWEEN 包中恰好两个同类型端点 value/valueTo，转换为目标 value:[下界,上界]；IN 为非空同类型数组；IS_NULL 不带值；其余操作恰好一个类型匹配值。字段必须属于 base/joins 的已确认闭包。除名称等公共元数据外不接受未声明查询字段。

v1 明确拒绝：数据集 parameters、卡片 parameterBindings、indicatorRefs、derived_metrics、cache_hint、非 json format、原生 SQL。原因是当前导入设计没有这些能力的持久化/解析闭环；不把参数偷偷搬到 globalVariables，也不自动创建指标。format 缺省或 json 均规范化为 json。导出和导入检查均返回 PACKAGE_CAPABILITY_UNSUPPORTED + fieldPath + 原因；允许用户明确移除受影响对象及依赖后重新导出，不能静默降级。

### 卡片解析与创建

新增分析领域端口 `resolveSavedQuery(datasetPin, actorContextRef, targetContextId)`，这是 T04 计划实现的能力，不是已存在接口。返回固定版本的 savedSemanticState、唯一正整数 databaseId、依赖 pins 与字段元数据。解析必须使用领域内部的语义模型→授权连接关系；不执行 SQL 来猜 database，不依赖客户端提供的数据库 ID；多数据库关系、歧义或无权阻断，未物化则暂存。

写入 `dataset_query={type:"semantic", database:<解析出的目标ID>, semantic_query:<savedSemanticState>}`、display、visualization_settings、name、description 和已确认 collection_id（可选）。在领域事务校验 datasetPin/连接权限及保存回执；沿用卡片字段元数据与密级派生规则。预览不调用会执行查询的普通创建 API。真正创建可能计算结果元数据，因此依赖未 READY 前不创建卡片。QUERY_DATASET 的目标 ID 只用于解析与审计，不能当作 databaseId。

### 大屏与资源转换

spec 根字段为 `schemaVersion:2,width,height,components`；width 为 200–7680，height 为 120–4320。组件必含 `id,type,x,y,width,height,config`；id 在屏内唯一，坐标为有限数字，宽高为正；不擅自把目标允许的负坐标改为非负约束。首版组件子集为 `title/table/line-chart/bar-chart/pie-chart/number-card`。title 只允许纯文本和目标原生样式；图表/表格/数值卡仅允许 card 数据源。静态图片首版通过大屏背景资源支持，`image` 组件因其配置适配未冻结而暂不支持。

卡片数据源使用 `dataSource.sourceType="card"`、`dataSource.type="card"`、`dataSource.cardConfig.cardId`。可携带目标已支持且经 schema 验证的刷新间隔；拒绝 parameterBindings、metricId/metricVersion。包中 cardId 必须为 null 占位，且 references 恰好含一个 `{fieldPath:"/spec/components/0/dataSource/cardConfig/cardId",ref:{localKey:"budget.card",kind:"CARD"}}`；转换后写目标数值 ID，再调用目标 ScreenSpecValidator。JSON Pointer 只允许这些声明的引用槽，不能指向 type/config 任意键；组件排序与指针共同参与内容 hash，重排必须重新导出引用。

可选 `backgroundResource:ResourceRef` 转换为 ScreenResource 创建请求的 `backgroundImage`，而不是凭空插入 spec；受控资源先通过授权存储再取得 URL。同屏可不设背景；完整夹具的两张资源由两次背景替换/资源共享子场景验证，不要求一个屏同时展示两张。

首版不支持有业务行为的 globalVariables、interaction、drillDown、actions、config.visibility，也不支持 theme、自定义插件、iframe/video、外部 URL 和 api/sql/dataset/metric/database 数据源；缺省/空集合可以规范化，不得把非空配置抹掉。导出预检查、导入检查均逐项阻断并标注 PACKAGE_CAPABILITY_UNSUPPORTED。**这意味着 v1 支持模型→查询数据集→卡片→只读展示大屏，不承诺带过滤联动的大屏无损迁移。** 后续扩大子集必须同时补目标适配与往返用例；未支持能力不以“预览通过”掩盖。

ResourceRef=`{path:string,sha256:string}`，path必须出现在manifest.files。首版允许PNG/JPEG/WebP，按实际文件头验证、单张≤10MiB且宽高≤8192，禁止SVG/HTML/JS/字体和外部URL自动下载。相同hash只可在同租户权限范围去重；导入者确认具有使用权。资源由领域服务存储并返回目标resourceId/受控URL，包中路径不可直接作为网页URL。

## 领域命令与权限

ImportCommand必需：operationKey:string、actorContextRef（服务器生成）、targetContextId、identity:{packageId,kind,localKey,generation}、action:CREATE|UPDATE|REUSE、payload、resolvedReferences[]、expectedTargetPin（UPDATE/REUSE必需）、confirmedGovernance。TargetPin={targetId:string,revision:string,checksum:string}，不强迫所有领域使用同一版本类型。

返回 OperationReceipt={operationKey,status:SUCCEEDED|BLOCKED|FAILED,targetPin?,dependencyPins[],error?}。同键同请求返回原回执；同键异请求409；创建对象与成功回执必须同领域事务。GET operationKey可确认超时结果。REUSE也验权限和pin。服务间使用现有可信身份传播，不复用浏览器Cookie到后台作业，不向调用者泄露不可见对象详情。

治理包含目标部门、数据域、工作区/集合的显式映射及密级；owner由当前执行者和领域规则决定。卡片/大屏有效密级不得低于依赖最大密级；整包设置只能提高或保持，不能降级绕过治理。公开链接、共享授权、原owner和角色绑定不随包迁移。发布、物化、对外共享均为独立用户动作，导入不自动执行。

错误码基线：PACKAGE_SCHEMA_UNSUPPORTED、REFERENCE_UNRESOLVED、FIELD_MAPPING_INVALID、TARGET_VERSION_CONFLICT、PERMISSION_DENIED、UPSTREAM_NOT_READY、RESOURCE_UNSUPPORTED、RESET_REQUIRED。统一响应带fieldPath/localKey、影响项、中文建议和correlationId；领域原始码保留于折叠诊断，不作为主要页面提示。

### QUERY_DATASET → 语义虚拟数据集

目标写入契约：`analyticsApi.createSemanticVirtualDataset`（`source/dts-platform-webapp/src/analytics/api/analyticsApi.ts:2104`）body = `{name, description?, workspace_id?, state: SemanticQueryBody}`；`SemanticQueryBody` 定义见同文件 `:181`–`:194`。

| v1 载荷字段 | 目标字段 | 差异与处理 |
|---|---|---|
| `baseModel:Ref(MODEL)` | `state.base:string` + `state.joins[]` | 目标用语义模型 id 字符串，且跨模型走 `joins:[{to,via?,type?}]`；v1 缺 joins 表达，须补 |
| `query.measures:MeasureRef[]` | `state.measures:string[]` | **不同构**：目标只接受度量 id，聚合内建于语义层度量定义；v1 的 `{field,aggregation}` 自带聚合无处落位。须改为引用已注册度量，不支持的聚合在导出期阻断 |
| `query.dimensions:FieldRef[]` | `state.dimensions:Array<string \| {id,granularity?}>` | 目标支持粒度下钻；v1 缺 `granularity`，须补 |
| `query.filters:Filter[]` | `state.filters:[{field,op,value?}]` | BETWEEN 在目标用 `value`+`value_to` 两字段，v1 单 `value` 须拆 |
| `query.orderBy` | `state.order_by` | 命名风格不一致（目标 snake_case）。映射层显式转换，不靠巧合 |
| `query.limit` | `state.limit` | 一致 |
| `parameters:Parameter[]` | 无直接对应 | 目标未暴露参数集合；须确认由 `globalVariables`/调用期传入还是不支持。**T04 未澄清前该字段不得进入 Schema** |
| 无 | `state.indicatorRefs:[{id,version}]` | 目标支持指标引用（带版本），v1 完全缺失。与 F6 指标口径相关，须决定 v1 是否支持 |
| 无 | `state.timeRange:{fieldRef,start,endExclusive,timezone}` | 目标有显式时间窗与时区；v1 缺失 |
| 无 | `state.derived_metrics[]`、`cache_hint`、`format` | v1 不支持，导出遇到须逐项阻断 |
| 治理映射 | `workspace_id` | 上文治理只写"工作区/集合的显式映射"，须落到该具体字段 |

### CARD → 卡片

目标写入契约：`CardResource`（`source/dts-analytics/src/main/java/com/yuzhi/dts/analytics/web/rest/CardResource.java:59` `@RequestMapping("/api/card")`，创建见 `:167`）。

| v1 载荷字段 | 目标字段 | 差异与处理 |
|---|---|---|
| `dataset:Ref(QUERY_DATASET)` | `dataset_query.database:Long`（`:184`–`:186` 强制必填且 >0） | **卡片绑定的是数据库 id，不是数据集 id**。导入须由 QUERY_DATASET 目标对象解析出其底层 `database`，再连同已保存查询体写入。该解析路径当前无现成接口，T04 须落实 |
| `visualization:object` | `visualization_settings`（`:200`、`:258`） | 字段名不同，v1 须改名 |
| `display:string` | `display`（`:197`，缺省 `"table"`） | 一致；但目标有缺省值，导入不得依赖缺省，须显式携带 |
| 无 | 卡片查询体 `dataset_query` 其余部分 | v1 未定义查询体如何从 QUERY_DATASET 派生，须补 |

### SCREEN → 大屏

目标写入契约：`ScreenResource`（`source/dts-analytics/src/main/java/com/yuzhi/dts/analytics/web/rest/ScreenResource.java:233` validate-spec），校验器 `ScreenSpecValidator`（`source/dts-analytics/src/main/java/com/yuzhi/dts/analytics/service/ScreenSpecValidator.java`）。

**上文 `dts.screen/v1` 与目标 ScreenSpec 不同构，须整体重做，不是补字段。** 实测差异：

| v1 载荷 | 目标 ScreenSpec | 差异 |
|---|---|---|
| `canvas:{width,height}` | 根级扁平 `width` / `height`（`:98`–`:99`） | **无 `canvas` 包装层**；且有范围约束 width 200–7680、height 120–4320，v1 只写"坐标在 canvas 内" |
| `Component.key` | `components[].id`（`:160`） | 字段名不同 |
| `Component.frame:{x,y,width,height}` | 扁平 `x` / `y` / `width` / `height`（`:174`–`:177`） | **无 `frame` 嵌套层**；width/height 须 >0，x/y 允许任意数值（校验器未强制非负） |
| `Component.type: CARD\|TEXT\|IMAGE` | `COMPONENT_TYPES` 白名单 48 项（`:17`–`:70`） | **v1 三个枚举值在目标中均不存在**。目标实际值形如 `line-chart`/`bar-chart`/`table`/`image`/`title`/`markdown-text`/`richtext`/`number-card`/`iframe`/`video`/`filter-input` 等。v1 须改为引用目标白名单子集 |
| `Component.card:Ref(CARD)` | `components[].dataSource`，`sourceType ∈ {static,api,card,sql,dataset,metric,database}`（`:71`、`:208`） | 卡片引用是 dataSource 的一种 sourceType，不是独立字段 |
| `filters` / `interactions` | `components[].interaction` / `drillDown` / `actions`（`:180`–`:182`）+ 根级 `globalVariables`（`:101`，类型仅 string/number/date） | 结构与命名均不同；下钻动作与可见性规则另有校验分支 |
| `theme` / `backgroundResource` | 校验器无对应分支 | 目标是否接受须实测，不得假定 |
| 无 | 根级 `schemaVersion`（`:97`） | v1 未携带目标 schemaVersion |
| 无 | `config` 内 plugin marker 可放行白名单外类型（`:165`、`:170`） | 存在受控扩展口；v1 须明确是否禁用该口 |

安全影响：目标白名单含 `iframe`、`video`，与上文"不导入任意 URL 跳转或脚本"直接冲突。**v1 须显式把 `iframe`/`video` 及带 plugin marker 的组件列入导出阻断项**，不能只在散文里声明禁止。

## 本轮修订结论与实施准入

### 后端补核：BETWEEN 的实际执行形态

`SemanticQueryService.ALLOWED_FILTER_OPS` 及普通语义查询筛选分支（约963–1000行）要求 `between` 的 value 为长度2数组。前端类型暴露 value_to，公共指标适配分支也处理 value_to，但不能据此推断普通查询执行路径接受它。本版不支持 indicatorRefs，所以统一写 `value:[lo,hi]`。历史对照表中“须拆 value/value_to”在普通语义查询范围被本条纠正。UT-17 检查精确请求；IT-24 用真实查询断言端点行为。
