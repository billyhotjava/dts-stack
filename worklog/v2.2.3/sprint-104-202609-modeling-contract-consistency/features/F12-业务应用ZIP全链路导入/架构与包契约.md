# F12 架构与包契约（设计草案）

## 当前基线与复用

- 建模沿用 `ModelSpecImportPreviewService` / 既有 inspect、preview、apply、retry、forward-undo 运行，不另造模型台账或 dbt parser。
- 来源沿用 `ModelSourceInventoryDialog`、`saveWarehousePlanSources` 和现有目录资产标识/可见性检查；物理表存在不等于已确认来源。
- 前端沿用 `ReverseModelingPage`；当前源绑定按建模环境隔离。纯模型导入保留原 inspectionProof、包校验和、模型 revision pin。
- 分析消费通过现有查询数据集、卡片 API；大屏通过 `analyticsApi` / `ScreensPage` 的对象与资源服务。T03/T04/T05 必须冻结具体命令、版本及权限映射后编码，以下统一接口是待实现契约，不声称线上已存在。
- 统一编排仅保存跨域运行与对象映射，模型/数据集/卡片/大屏仍由原领域服务创建和校验；不直接跨服务写库。

## 包结构

```text
application.zip
  manifest.json
  models/dbt-project.zip
  datasets/<localKey>.json
  cards/<localKey>.json
  screens/<localKey>.json
  resources/<sha256>.<ext>
```

schemaVersion=`dts.application-package/v1`；只含模型的旧 ZIP 进入旧解析器并规范化到同一预览视图，无需改包。嵌套 dbt 包只允许上述一层，复用原检查器并计入统一解压预算。

manifest 必需字段：schemaVersion、packageId（稳定 UUID）、packageVersion、objects、files、requires。可选字段：title、description、producerVersion、defaults。包校验和由上传原始字节计算，不能在 manifest 中自引用。files 每项含 path、size、sha256；校验覆盖全部载荷，拒绝未声明文件和重复路径。

objects 每项：localKey（包内稳定且唯一）、kind（MODEL/QUERY_DATASET/CARD/SCREEN）、payloadPath、payloadSchemaVersion、dependsOn（localKey 列表）、contentChecksum。MODEL 的 localKey 与 dbt unique_id 映射必须显式保留，不改签名包内容。requires 描述外部依赖 kind/stableCode/versionConstraint，不携带生产 ID 或连接凭据。依赖必须有唯一解析，拒绝循环、孤立引用、重复身份。旧 ID 只可保留为审计信息，不能直接写入目标对象关系。

defaults 仅为建议，不代表用户同意：domainCode、businessProcessCode、dataMartCode、subjectDomainCode。发布密级需要操作者显式确认；包内标签不能替代密级/部门授权。

## 目标环境配置与合并

TargetContext：modelingContextId、targetConnectionId、targetNamespace、sourceMappings、domainMappings、businessProcessId、dataMartId、subjectDomainId、confirmedSecurityLevel。
ObjectOverride：localKey、显式字段集合及对应值。优先级为单项覆盖 > 用户确认的整包值 > 合法包内业务定义。整包仅修改可批量的归属/治理字段，不统一修改模型类型/粒度/业务键。数据域变更使业务过程待重选；数据集市变更清空主题域；环境变更撤销旧环境身份映射。

IdentityMap 保存 `(runId, kind, localKey) → targetId, targetRevision, targetChecksum, action`；targetId 只由领域服务返回。引用绑定使用这张映射，不使用名称模糊匹配。更新策略：CREATE / REUSE / UPDATE / SKIP；冲突项必须用户选择，UPDATE 提交 expectedRevision。复用需校验类型、结构、版本及当前权限。依赖 SKIP 不等于缺失对象自动跳过校验。

## 拟议编排接口与状态

以下接口为 T03/T06 待实现设计，确切路由在 API 评审冻结：

| 命令 | 输入 | 输出/约束 |
|---|---|---|
| inspect | multipart ZIP | inspectionId、hash、对象清单、兼容性和诊断；无业务写入 |
| preview | inspectionId/hash、context、selectedKeys、overrides、conflictPolicies | previewId/revision、计划DAG、根因与受影响项；无对象创建 |
| apply | previewId/revision、idempotencyKey | runId；服务器重新验权和校验预览未过期 |
| get run | runId | 对象结果、目标ID/版本、进度、审计及就绪状态 |
| retry | runId、失败项、expectedRunRevision | 仅重试可重试项，成功项复用日志 |
| forward undo | runId、对象revision/checksum pins | 前向补偿报告；冲突项停止，保留复用对象 |

运行状态 INSPECTED → PREVIEWED → APPLYING → SUCCEEDED / PARTIAL_FAILED / FAILED；项状态 PENDING → APPLYING → CREATED / UPDATED / REUSED / SKIPPED / BLOCKED / FAILED。重试沿用 runId、对象幂等键 `(tenantId, runId, kind, localKey)`，网络超时先查询实际结果再重试。跨服务没有伪全局事务：采用持久执行日志与领域幂等命令，局部成功可见且可恢复。

独立就绪状态 DRAFT / WAITING_UPSTREAM / READY / FAILED；SUCCEEDED 只表示导入计划执行完成。QueryDataset 是否可发布、模型是否物化、大屏是否能查询由各领域事实驱动；不凭草稿 ID 宣称完成建模或可用。缺失上游运行定义时只能创建允许暂存引用的草稿；不支持悬挂引用的领域适配器将对象保留在导入暂存区 WAITING_UPSTREAM，不向领域写入非法对象。

## 权限、安全与恢复

复用 F9/F11 的租户、当前主体、部门和对象权限；预览不产生执行授权，apply 和后台每次恢复均重新验权。日志记录actorId/部门快照、package hash、runId、localKey、targetId/revision、错误码、重试次数，不记录令牌/密码。包不包含数据库数据、账号、Cookie、Token、绝对路径或可执行安装脚本。

检查 zip slip、绝对路径、符号链接、重复规范化路径、解压炸弹、文件数量/深度、资源类型；禁止解压执行宏或 ODS DDL，模型宏只在既有受控构建链执行。静态资源不允许导入可执行脚本，外部 URL 按现有资源策略重新确认。

初始预算（待基准验证）：旧模型 ZIP 保持 32MiB；完整包首版同上，解压上限 256MiB、文件数 5000、层级 12、压缩比 100，跨层累计。不能只放宽 Nginx 而忽略应用/解析预算。100 模型+20 卡片+3 大屏为标准性能夹具，preview P95 ≤ 10 秒，导入草稿 P95 ≤ 60 秒（排除物化/外部采集，环境规格随报告记录）；每服务/租户限流及 worker 并发初始 2，超出返回可恢复排队。未实测前不是性能承诺。

撤销仅归档本次新建且未被外部引用对象；更新通过领域新修订恢复旧内容，必须匹配当前 revision；不 DROP ODS、不删复用资产/数据源、不撤销他人变更。失败保留对象清单供人工处理。导入失败、卡住、重复尝试和等待上游超时均有可查询运行记录和告警，阈值待 T06 性能实测冻结。
