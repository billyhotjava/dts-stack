# F12 架构与包契约（v1设计基线，待实现）

## 当前基线与复用

- 建模沿用 `ModelSpecImportPreviewService` / 既有 inspect、preview、apply、retry、forward-undo 运行，不另造模型台账或 dbt parser。
- 来源沿用 `ModelSourceInventoryDialog`、`saveWarehousePlanSources` 和现有目录资产标识/可见性检查；物理表存在不等于已确认来源。
- 前端沿用 `ReverseModelingPage`；当前源绑定按建模环境隔离。纯模型导入保留原 inspectionProof、包校验和、模型 revision pin。
- 分析消费通过现有查询数据集、卡片 API；大屏通过 `analyticsApi` / `ScreensPage` 的对象与资源服务。T03/T04/T05按v1载荷补齐领域命令、版本及权限映射实现，新增领域端口、载荷及适配要求见[领域载荷与接口契约](领域载荷与接口契约.md)，不声称线上已存在。
- 统一编排仅保存跨域运行与对象映射，模型/数据集/卡片/大屏仍由原领域服务创建和校验；不直接跨服务写库。

## 包结构

```text
application.zip
  manifest.json
  models/dbt-project.zip
  datasets/<localKey>.json
  cards/<localKey>.json
  screens/<localKey>.json
  resources/<sha256>.<ext>
```

schemaVersion=`dts.application-package/v1`；只含模型的旧 ZIP 进入旧解析器并规范化到同一预览视图，无需改包。嵌套 dbt 包只允许上述一层，复用原检查器并计入统一解压预算。

manifest 必需字段：schemaVersion、packageId（稳定 UUID）、packageVersion、objects、files、requires。可选字段：title、description、producerVersion、defaults。包校验和由上传原始字节计算，不能在 manifest 中自引用。files 每项含 path、size、sha256；校验覆盖全部载荷，拒绝未声明文件和重复路径。

objects 每项：localKey（包内稳定且唯一）、kind（MODEL/QUERY_DATASET/CARD/SCREEN）、payloadPath、payloadSchemaVersion、dependsOn（localKey 列表）、contentChecksum。MODEL项额外包含dbtUniqueId，payloadPath指向共享嵌套ZIP；MODEL 的 localKey 与 dbt unique_id 映射必须显式保留，不改签名包内容。requires 描述外部依赖 requireKey/kind/stableCode/versionConstraint，不携带生产 ID 或连接凭据。依赖必须有唯一解析，拒绝循环、孤立引用、重复身份。旧 ID 只可保留为审计信息，不能直接写入目标对象关系。

defaults 仅为建议，不代表用户同意：domainCode、businessProcessCode、dataMartCode、subjectDomainCode。发布密级需要操作者显式确认；包内标签不能替代密级/部门授权。

## 目标环境配置与合并

TargetContext：modelingContextId、targetConnectionId、targetNamespace、sourceMappings、domainMappings、businessProcessId、dataMartId、subjectDomainId、confirmedSecurityLevel。
ObjectOverride：localKey、显式字段集合及对应值。优先级为单项覆盖 > 用户确认的整包值 > 合法包内业务定义。整包仅修改可批量的归属/治理字段，不统一修改模型类型/粒度/业务键。数据域变更使业务过程待重选；数据集市变更清空主题域；环境变更撤销旧环境身份映射。

跨批次有效身份键为 `(tenantId,targetContextId,packageId,kind,localKey)`，代际、重命名、升级及归档处理见[导入重置与重复导入](导入重置与重复导入.md)。IdentityMap仅为运行快照，保存 `(runId, kind, localKey) → targetId, targetRevision, targetChecksum, action`；targetId 只由领域服务返回。引用绑定使用这张映射，不使用名称模糊匹配。更新策略：CREATE / REUSE / UPDATE / SKIP；冲突项必须用户选择，UPDATE 提交 expectedRevision。复用需校验类型、结构、版本及当前权限。依赖 SKIP 不等于缺失对象自动跳过校验。

## 拟议编排接口与状态

以下为 T03/T06 待实现命令；统一拟议路由、持久状态、恢复授权及保留策略见[运行恢复与就绪衔接](运行恢复与就绪衔接.md)。模型重置路由见[重置契约](导入重置与重复导入.md)。

| 命令 | 输入 | 输出/约束 |
|---|---|---|
| inspect | multipart ZIP | inspectionId、hash、对象清单、兼容性和诊断；无业务写入 |
| preview | inspectionId/hash、context、selectedKeys、overrides、conflictPolicies | previewId/revision、计划DAG、根因与受影响项；无对象创建 |
| apply | previewId/revision、idempotencyKey | runId；服务器重新验权和校验预览未过期 |
| get run | runId | 对象结果、目标ID/版本、进度、审计及就绪状态 |
| retry | runId、失败项、expectedRunRevision | 仅重试可重试项，成功项复用日志 |
| forward undo | runId、对象revision/checksum pins | 前向补偿报告；冲突项停止，保留复用对象 |

运行状态 INSPECTED → PREVIEWED → APPLYING → WAITING_UPSTREAM / SUCCEEDED / PARTIAL_FAILED / FAILED；项状态 PENDING / STAGED_WAITING → APPLYING → CREATED / UPDATED / REUSED / SKIPPED / BLOCKED / FAILED。重试沿用 runId、run 内请求去重键 `(tenantId, runId, kind, localKey)`（不是跨 run 业务身份；领域 operationKey 见下文），网络超时先查询实际结果再重试。跨服务没有伪全局事务：采用持久执行日志与领域幂等命令，局部成功可见且可恢复。

独立就绪状态 DRAFT / WAITING_UPSTREAM / READY / FAILED；SUCCEEDED 只表示导入计划执行完成。QueryDataset 是否可发布、模型是否物化、大屏是否能查询由各领域事实驱动；不凭草稿 ID 宣称完成建模或可用。v1固定采用导入暂存区；上游未就绪时数据集/卡片/大屏为STAGED_WAITING，不计作领域对象已创建。依赖就绪、pins一致且授权仍有效才继续；不向领域写入悬挂引用。

## 权限、安全与恢复

复用 F9/F11 的租户、当前主体、部门和对象权限；预览不产生执行授权，apply 和后台每次恢复均重新验权。日志记录actorId/部门快照、package hash、runId、localKey、targetId/revision、错误码、重试次数，不记录令牌/密码。包不包含数据库数据、账号、Cookie、Token、绝对路径或可执行安装脚本。

检查 zip slip、绝对路径、符号链接、重复规范化路径、解压炸弹、文件数量/深度、资源类型；禁止解压执行宏或 ODS DDL，模型宏只在既有受控构建链执行。静态资源不允许导入可执行脚本，外部 URL 按现有资源策略重新确认。

初始预算（待基准验证）：旧模型 ZIP 保持 32MiB；完整包首版同上，解压上限 256MiB、文件数 5000、层级 12、压缩比 100，跨层累计。不能只放宽 Nginx 而忽略应用/解析预算。100 模型+20 卡片+3 大屏为标准性能夹具，preview P95 ≤ 10 秒，导入草稿 P95 ≤ 60 秒（排除物化/外部采集，环境规格随报告记录）；每服务/租户限流及 worker 并发初始 2，超出返回可恢复排队。未实测前不是性能承诺。

撤销更新与重置新建对象分开设计；重置保留回执、退役符合条件的本次对象并关闭有效映射，成功后新generation可重新CREATE。既有forward-undo不能处理CREATE，不能当作已实现重置。具体准入、事务、部分失败和页面见[重置契约](导入重置与重复导入.md)。不DROP ODS、不删除复用资产/数据源、不撤销他人变更。恢复与告警使用[运行契约](运行恢复与就绪衔接.md)初版阈值，经T07实测校准。

## 跨服务传输与命名边界（2026-09-22 补）

编排器在 dts-platform，QUERY_DATASET/CARD/SCREEN 三类目标对象在 dts-analytics，是**跨进程调用**。dts-platform 已有到 analytics 的服务端出站通道，F12 必须复用，不得另建第二套传输：

| 既有通道 | 位置 | 已具备 |
|---|---|---|
| 语义发布客户端 | `source/dts-platform/src/main/java/com/yuzhi/dts/platform/service/modeling/serving/AnalyticsSemanticPublishClient.java:23` | RestTemplate + connect/read 超时（`:36`–`:37`，取自 `DtsAnalyticsProperties`）、内部端点、专用异常 `SemanticPublishException`（`:79`） |
| 大屏对账同步 | `source/dts-platform/src/main/java/com/yuzhi/dts/platform/service/integration/ScreenReportLinkSyncService.java:36` + `ScreenSyncClient` | 大屏侧既有同步与分类默认值（`:45`） |

决策：新增领域端口 `previewImport/executeImport/getOperation/retireImported` **在上述客户端之上扩展方法**，复用同一份连接/超时配置与身份传播机制；不新建 RestTemplate/WebClient 实例，不引入第二套鉴权。若现有客户端的超时、重试或身份传播不足以支撑导入（如需要更长的 apply 超时、需要 operationKey 幂等头），**以扩展既有客户端的方式补齐并说明原因**，不是绕开它另写一个。该约束由 T06 在编码前落实并在 review 中核对。

命名边界：本设计的 `ImportIdentityRegistry` 与既有 `source/dts-platform/src/main/java/com/yuzhi/dts/platform/service/catalog/CatalogExternalAssetIdentityRegistry.java` 是两回事——后者管数据目录外部资产身份，前者管导入包对象到目标对象的跨批次身份与代际。实施期不得互相复用或混用表结构；新类名必须带 `Import` 前缀，避免在同一仓库出现两个"IdentityRegistry"。

## Q7 补充：服务认证与用户授权分离

AnalyticsSemanticPublishClient 当前使用 X-DTS-Service/X-DTS-Service-Token 识别服务；它不证明导入者有权限。复用既有客户端的连接、凭据配置与超时管理，不等于照搬服务 token 就可以执行用户命令。计划扩展的 actorContextRef 由服务器生成、绑定操作者/租户/部门/目标上下文/批准动作与期限，分析领域通过可信内部解析验证来源和有效期，并按当前权限重新授权。请求体中的 actorId/departmentId、浏览器传来的同名头、包内 owner 均不能扩大授权。

服务认证失败拒绝；服务认证通过但用户已撤权也拒绝。后台不保存或转发浏览器 Cookie。当前客户端尚无 F12 命令与 actorContextRef 解析能力，T06 须补领域接收与可验证授权链；不另造独立凭据系统。错误对不可见对象不披露名称、连接或目标 ID。对应 UT-31/32、IT-12/27。

## 操作身份补充

operationKey 由已持久化的确认计划生成，包含目标业务身份、generation、计划动作标识；同一动作的超时重试沿用原键。requestHash 单独存储用于“同键异请求”409 校验，不能修改 payload 后换 hash 生成新键绕过冲突。不同 run 的同身份竞争由 ImportIdentityRegistry 有效唯一约束串行化，失败方重读并重新预览，不重复 CREATE。
