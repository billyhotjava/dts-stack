# F12 导入重置与重复导入

设计版本：2026-09-22。以下为待实现契约，不表示当前系统支持。责任：T08 建模重置先行，T06 扩展到各领域。

## 已证实的限制

PJM runId `5c092f54-935b-465d-a6a3-671dd4475ca0` 创建43个DRAFT r1模型。现有 `ModelSpecImportForwardUndoWorker` 对 CREATE 返回 `CREATED_MODEL_NO_BASE_REVISION`；普通草稿删除会遇到实现外键及回执追加写保护。2026-09-22 清理尝试被 `MODEL_IMPLEMENTATION_COMMAND_RECEIPT_APPEND_ONLY` 拒绝，整个事务回滚，43模型保持原状。该事实不是重置成功证据。

禁止删改历史回执、关闭触发器、取消外键、直接改业务数据库来实现重置。历史导入成功与对象后来退出使用是两个独立事实。

## 三种操作

| 操作 | 用途 | 结果 |
|---|---|---|
| 重试失败项 | 同一运行网络失败/部分失败 | 同一run、同一对象幂等键，成功项不重建 |
| 撤销更新 | 恢复本次UPDATE前内容 | 领域追加新修订，当前版本必须等于导入后pin；不删除历史 |
| 重置本次新建对象 | 清空本轮草稿，重新手工导入 | 下游到上游退出使用，历史可查；关闭有效身份映射后允许下一代新建 |

“重置”不是物理删除或数据库回滚。界面显示“移出当前模型列表，保留历史审计”；历史对象可在归档/导入历史查看，原run仍显示当时成功，并关联resetRunId。默认模型列表不再显示已重置对象。

## 重置准入与范围

1. 输入 targetRunId、selectedKeys；空列表表示该run全部成功项。服务端从不可变执行结果计算范围，不能信任前端传入任意对象ID。
2. 仅本次CREATE且当前revision/checksum与导入后pin相同、未发布、无物化/发布候选/交付执行、无包外有效引用的对象可重置。定义和静态资源也是独立依赖，须统计真实引用。
3. UPDATE只能走“撤销更新”；REUSE/SKIP永远保留。混合run明确显示三组，不能称为“完全恢复首次导入”。跨租户/跨部门、权限不足、版本漂移均阻断。
4. 包内依赖可一并选入范围；部分选择必须包含其当前有效下游，预览展示自动扩展项并由用户确认。包外引用绝不自动扩展或删除。
5. ODS表、业务数据、连接、已确认来源绑定保持不变。既有维度定义保留；本次自动创建的维度定义只有确有创建回执、无范围外引用且版本未漂移时才能退役。旧版导入缺少定义创建归属证据时保留定义并标注“后续复用”，不能猜测后删。
6. 当前PJM应清除43模型的有效列表与映射；已有3个模型、12个已确认来源及物理ODS不变。维度定义如复用，下一轮预览必须显示出来；模型仍应43项CREATE。

## 协议与执行

新增拟议接口（均未上线）：

| 方法/路径 | 必需输入 | 返回 |
|---|---|---|
| POST /api/modeling/model-spec-imports/{runId}/reset-preview | selectedKeys:string[] | resetPreviewId:UUID、revision:int、expiresAt、eligible/blocked/preserved、对象pins、范围hash |
| POST /api/modeling/model-spec-imports/{runId}/reset | resetPreviewId、expectedPreviewRevision、scopeHash、idempotencyKey:UUID | resetRunId、status、items |
| GET /api/modeling/model-spec-imports/resets/{resetRunId} | 无 | 逐项结果、原因、保留对象、可否重新导入 |
| POST /api/modeling/model-spec-imports/resets/{resetRunId}/retry | expectedRevision:int、idempotencyKey | 原resetRun继续执行，仅处理未完成项 |

预览有效期15分钟；执行时重新验权、检查全部pins和引用，持久记录用户确认的范围。重复幂等键+同请求返回原结果；不同请求返回409。错误返回code/message/affectedKeys/recoveryAction/correlationId；无权限403，版本/引用冲突409，预览过期410。界面必须翻译常见错误并定位阻断对象。

模型首切片在单库事务内锁规划、模型和有效映射，重新检查所有前置条件，然后调用领域退役命令并追加重置事件；任一不满足整体不变。退役模型、关闭当前映射和记录结果同事务提交。不得把已有append-only回执改成可修改记录。

跨服务重置按SCREEN→CARD→QUERY_DATASET→MODEL→独占资源逆拓扑执行，各领域事务+幂等回执；全局不是原子事务。预检查不承诺消除执行期并发。状态 PREVIEWED→RESETTING→SUCCEEDED/PARTIAL_FAILED/FAILED；项 RETIRED/PRESERVED/BLOCKED/FAILED。中途失败保留已完成结果，同一reset可恢复；仅SUCCEEDED且有效映射全部关闭的范围可进入新一代导入。部分失败不能展示“已全部清空”。

纯草稿无实现时沿用领域允许的删除；有实现/回执时采用领域退役状态，保留实现、制品和审计链。对退役对象的编辑、发布、构建命令应拒绝。历史详情只读。恢复历史对象不属于本轮重置功能；如需恢复必须作为新受控运行，不能复活已失效的幂等键。

## 跨批次身份与并发

持久有效身份键：`(tenantId, targetContextId, packageId, kind, localKey)`。包版本与内容hash不是身份。纯dbt旧包使用稳定projectKey映射到服务器分配的packageId，同一规划再次上传同项目复用该身份，不因ZIP时间戳换身份。不同规划各自独立；同一规划刻意复制须另行选择“复制为新应用”并显式分配新packageId，默认禁止隐式复制。

IdentityRegistry保存generation、targetId、acceptedPackageVersion、acceptedContentChecksum、targetRevision/checksum、ACTIVE/RETIRED、createdRunId/resetRunId。历史映射追加保存；有效键唯一约束/锁防止两个新run同时CREATE。run内IdentityMap只是该次快照，不能代替跨run注册表。

| 输入/现状 | 决策 |
|---|---|
| 同run重复提交 | 返回已持久化结果，不重复命令 |
| 新run、同有效身份、包内容和目标pins均未变 | REUSE并重新验权，不创建重复对象 |
| 包内容改变、目标未漂移 | 展示UPDATE差异，用户确认后CAS新版本 |
| 目标被手工修改，或包/目标同时改变 | CONFLICT；保留、人工合并或显式新身份，不静默覆盖 |
| 包中少了旧对象 | 旧对象保留，提示“本包未包含”；不隐式删除 |
| 明确oldKey→newKey重命名 | 一对一、同kind、目标身份无冲突时迁移有效键并追加审计；名称变化不是身份变化 |
| 普通手工归档、未完成重置 | BLOCKED，需要明确重置/恢复策略，不自动当不存在 |
| 重置SUCCEEDED、旧映射RETIRED | generation+1，分配新targetId，旧历史保持可查；不能重新用已归档ID |
| reset进行中/部分失败 | 相关身份暂不允许新建；继续reset或人工处理 |

领域命令幂等键包含有效身份+generation+operation+请求hash；网络重发沿用原键。新generation必须进入模型ID、实现ID及操作回执的分配，不能只更换前端runId。T08需验证既有确定性ID及projectKey唯一约束，新增历史/有效映射的兼容迁移，不能靠删旧记录避冲突。
