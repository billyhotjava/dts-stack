# F11-T05 对象级授权决策点收敛

**状态**：DRAFT（等待 Q18 确认）
**对应方案**：R4、R5　**对应问题**：P6、P3

## 目标

把六套并行的对象级授权收敛为单一决策点，并把部门与密级作为独立的范围条件求值。

## 现状（待收敛的六套）

`AccessChecker`（部门+密级+数据集授权）、`AssetGrant`+`AssetPermissionService`、`IamAssetActionPolicy`、`IamDatasetPolicy`、`CatalogDomainAccessPolicy`、`ModelSpecAccessService`。

## 计划内容

1. **统一接口**：定义 `AccessDecision(subject, action, resource)`，返回允许/拒绝与理由，理由进审计。
2. **provider 迁移**：六套实现改为该接口下的 provider，逐个迁移并保留既有语义；迁移期间新代码一律走新接口。
3. **范围条件独立**：部门归属与密级从角色判断中剥离，作为 ABAC 条件参与决策；角色决定动作，范围决定数据。
4. **密级收口**：人员密级与数据密级的映射收敛到单一入口，消除 `SecurityLevelCatalog` 的双向混用。

## 验收要点

- 每次拒绝都能说明是哪个 provider、哪条条件导致的。
- 迁移前后对同一批样本资源的判定结果一致，有对比用例。
- 新增模块无需再写第七套机制。
