# F11-T05 对象级授权决策点收敛

**类型/状态**：领域授权适配与集成开发 / DRAFT

**owner/估算**：platform 领域后端负责人待指派；L。

**设计**：[架构 §7、§9](../../assests/F11-permission-architecture.md)；P3/P6、R4/R5。

**输入**：T01 实际策略组合图、T02 当前上下文、T03 动作/范围矩阵；Q22 按密级迁移范围冻结。输出供 T04 各入口、列表与后台使用。

## 工作内容

1. 按资源类型/动作冻结 AccessChecker、AssetActionPolicyEvaluator、AssetPermissionService、PolicyService、CatalogDomainAccessPolicy、ModelSpecAccessService 的实际适用和嵌套关系，避免重复调用/循环。
2. 实现统一 evaluate/evaluateBatch/查询约束入口；返回 ALLOW/DENY/NOT_APPLICABLE/INDETERMINATE 及原因/政策版本。无必需策略拒绝，适用 DENY 优先，依赖错误失败关闭。
3. 权限与授权范围按同一绑定匹配，再叠加租户、部门、密级、对象 ACL、状态和职责；不得展平权限/范围组合，不从 EDITOR 推导读取/导出/审核。
4. 列表在分页/计数前应用范围，按页批量读取 ACL；混合写/执行先展开全部目标并授权再产生副作用，锁/版本与撤权确定先后。
5. USER 任务、重试、幂等重放重新授权；SYSTEM 只限可信服务已有部署绑定。数据查询/导出、下载、大屏展示例外的边界单列，保留稳定资源键。
6. 密级独立政策端口，未知/非法值不降级；Q22 未定时只保留已确认语义并记录 GAP，不自行发布新映射或扩大管理员豁免。

数据消费的 ALLOW 必须保留适用字段/行过滤与有效期；PolicyService 已存在 OBJECT/FIELD/ROW 定义，需要核验真实执行路径。不能将受限 ALLOW 展平为全表读取，执行器不支持必需约束时拒绝；IT-74/75 同时验证预览、查询、导出的一致结果。

## 验证与完成标准

- IT-74/75/78：决策表覆盖允许、明确拒绝、无适用策略、缺必需策略和异常；审计定位原因但外部不可枚举资源。
- 用真实数据库证明批量原子拒绝、并发撤权、分页总数隔离；20/200 行无逐对象远程身份调用。
- 新旧结果比较以明确业务政策为准，已知错误不因“保持一致”被接受。
- 首切片与 T04 联调通过后再逐域扩展，保留独立领域存储和状态机。
