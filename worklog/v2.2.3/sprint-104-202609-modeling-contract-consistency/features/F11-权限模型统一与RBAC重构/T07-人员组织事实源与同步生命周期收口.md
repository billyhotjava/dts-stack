# F11-T07 人员组织事实源与同步生命周期收口

**类型/状态**：目录/同步开发及组件集成 / DRAFT

**owner/估算**：admin 后端与 MDM 对接负责人待指派；L。

**设计**：[架构 §3–4](../../assests/F11-permission-architecture.md)；人员/部门职责讨论、P1/P8。

**输入**：T01/Q21 来源与字段语义、T08 扩展迁移设计；输出为 T02 当前身份的权威业务属性。

## 工作内容

1. 保留 organization_node；演进 admin_keycloak_user 的本地身份、来源/版本、业务状态及账号绑定，支持 kc_id 为空的待开户人员；不创建第三套人员当前目录。
2. 建立字段级写入权限：MDM 只写已确认人事/组织字段，Keycloak 回读只写账号字段和投影结果，旧 profile 不再在线覆盖；本地受控人员有显式来源，不与 MDM 同记录抢写。
3. 分离 mdm_enabled 原始状态、经政策映射的 lifecycleState、dtsAccessState、Keycloak enabled；保持现有新账号禁用/人工启用，不把未知 status 解释成离职或复职。
4. 目录有效变更与待同步操作同事务提交，先复用批次/行记录并验证持久化重试能力，必要时补最小操作记录；Keycloak 请求在可恢复流程执行，不能假装与本地有分布式事务。
5. 稳定键和版本 CAS 防重复/乱序；外部成功回执丢失先核对绑定，不按同名认领；无源版本无法判顺序时冲突隔离。全量缺失与显式删除有不同语义。
6. 调岗立即更新业务授权范围，Keycloak 属性/组可异步重试且不回灌；同步失败、冲突、开户待处理在既有人员/导入页面显示中文状态和可追踪记录。

同步只修改受管字段/部门组，保留其他组/角色；部门组不得隐含授三员或保留角色。相关现场继承规则先核验，回归覆盖“普通调岗不提权、不删除非受管组”。

## 验证与完成标准

- IT-68/69：重复、乱序、进程中断、远端成功本地失败、部门先后依赖和部分批次失败；无重复账号、授权或静默丢记录。
- 真实数据库验证唯一约束/事务/CAS；Keycloak 替身用于错误注入，真实开户/组投影/保留人工禁用状态由 T09 集成验证。
- 部门删除具备完整目录及关联资源证据，旧快照全空/部分覆盖或同步失败不能误判无人。
- 交付字段归属表、操作状态、恢复方法与接口版本；尚未冻结的生命周期/密级政策保持 GAP。

**实际结果**：仅架构与任务设计。未改变同步方向、账号状态或人员数据。
