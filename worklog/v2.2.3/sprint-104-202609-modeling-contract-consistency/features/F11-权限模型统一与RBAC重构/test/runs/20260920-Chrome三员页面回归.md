## 缺陷 F11-UI-001：403 页返回首页没有按三员职责选择落点

- 优先级 P2；关联 T09、ST-020 的错误状态恢复体验。已验证 authadmin 与 auditadmin 两个账号，不扩展为所有角色都受影响。
- 预期：点击“返回首页”进入该角色允许的起始页；authadmin 应可回任务审批，auditadmin 应可回日志审计。
- 实际：拒绝页链接固定指向 `/admin/my-changes`，两个账号都再次显示无访问权限。当前可用恢复路径为左侧各自允许菜单。
- 最小复现：authadmin 登录 → 地址栏 `/admin/roles` → 403 → 点击“返回首页” → URL `/admin/my-changes` → 仍 403；auditadmin 以 `/admin/approval` 重复同样过程。
- 证据：会话中的“验证拒绝页面的返回首页操作”截图、紧随的实际 URL 输出，以及“复验审计员拒绝页的返回首页缺陷”DOM/URL 输出。403 是页面展示结果，未把它表述为已抓取到 HTTP 403。
- 本轮只记录，未修改应用生产代码或部署。修复时需按当前角色选择有效起始页，并针对两个账号复验；不能通过放宽 `/admin/my-changes` 权限掩盖导航错误。
