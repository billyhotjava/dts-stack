状态：21 条目标用例。已在真实 Chrome 执行 sysadmin/authadmin/auditadmin 的管理端基线与 ST-003/004/009/019/020 部分前置/子项，发现 F11-UI-001 返回首页缺陷，见 [本轮实测](runs/20260920-Chrome三员页面回归.md)。员工门户 [Chrome 脚本](automation.md) 仍因缺门户/业务账号夹具而未执行；其他未测子项 `NOT_RUN`。**用户明确本轮不测 PKI，ST-001 记 N/A，仅核对源码未改；下文 PKI 步骤保留为历史目标规格，不作为本轮执行要求。** 共用 [夹具](fixtures.md) 和 [记录模板](execution-record.md)，页面操作不能由 API 或静态断言替代。

## 统一执行规则

1. 使用有界面的真实 Chrome。独立 profile A/B/C 分别代表业务用户、申请人、审批人；记录实际版本、视口和账号别名，不共享 Cookie。Chrome 95 单独记录，伪造 UA 不算兼容证据。
2. 像人工一样从登录页/导航进入，点击、输入、选择、翻页、确认、返回、刷新和下载。允许浏览器自动化点击真实可见元素；禁止注入 token、改存储、执行页面 fetch、隐藏控件强行点击、mock 权限响应或直接数据库写来完成受测主流程。
3. 控件按当前页面实际可见文字/标签定位；执行前记录标签与 URL。本文方括号中的“权限配置、作用范围”等为 F11 目标业务控件，当前页面未实现时记 BLOCKED 并关联任务，不能虚构已存在按钮，也不能自行改成 API 绕过。
4. 每例保存起始页、关键提交/拒绝、最终页的脱敏截图；记录账号、时间、URL、对象/申请 ID、实际结果及必要的脱敏网络状态/requestId。控制台异常和网络错误分类记录，不把预期 403/404/503 当作“零错误”，也不忽略意外异常。
5. 页面不能证明的副作用由授权的只读审计/数据库/任务记录辅助核验。下载需打开实际文件核对内容。缺少必要独立证据时相应断言未完成，不能仅看成功 toast。
6. 外部 MDM 输入、部署切换和网络故障由测试环境操作者按集成用例提供，是明确的外部刺激；页面侧仍须按本例实际操作。不得用本机改库或前端拦截响应伪造系统结果。
7. 每例独立准备/恢复夹具；实际授权变更完成审批并生效后才判断“下一边界”。旧页面已加载的信息不等于新请求泄露；验证变更后新的读取/操作，不能假定服务端可撤回用户此前已看到的数据。
8. PKI 始终沿用原入口、证书、映射、插件和配置。原生证书选择/介质交互若无法自动化，由真实操作人完成并记录交接；整段未完成则 BLOCKED，不用密码、假 Cookie 或 mock 替代。
