## 环境分层

| 标识 | 用途 | 必要条件 |
|---|---|---|
| E-UT | 规则/组件 | 固定时钟、内存替身；无真实网络、证书或共享数据库 |
| E-DB | 事务、并发、迁移 | 与目标一致的数据库种类/主版本和真实 Liquibase schema；一次 runId 的专属库/schema；不能用 H2 代替数据库语义 |
| E-CHAIN | 系统集成 | 真实 admin/platform/Keycloak、隔离 realm、持久化存储及必要后台执行器；服务凭证由环境注入 |
| E-UI | Chrome 系统 | 正式受测制品、真实后端和登录入口；三组隔离 Chrome profile；能保存脱敏截图和请求关联号 |
| E-PKI | 既有 PKI 兼容 | 已配置的原 PKI 登录环境和授权测试证书/介质，冻结原配置/账号映射；不为跑用例改认证流程 |

E-UI 分别记录当前受支持 Chrome 和实际 Chrome 95 运行结果。1366×768 为主视口，390×844 为窄视口；改 User-Agent 或仅启用 legacy 构建不能证明实际 Chrome 95 已测试。没有真实 Chrome 95 或证书介质时，对应子项 `BLOCKED`，其余可独立执行。

## 账号、部门和资源

|---|---|

| DEPT-A / DEPT-B | 精确编码 1153 / 153，测试后缀误匹配；另设 DEPT-A-CHILD，父子关系不授予跨部门范围 |
| U-EMP | A 部门普通员工；仅有矩阵明确授予的导航/业务读取，不能建模 |
| U-A / U-B | A/B 部门的内置建模角色，非三员；拥有各自测试模型；逐动作授予按冻结矩阵记录 |
| U-LEAD / U-INSTITUTE | 部门领导/所级数据角色；范围和审批能力依 F9/冻结矩阵，不假设全部数据可读 |
| U-EDITOR | A 部门内置建模角色；仅对 MODEL-A2 获得 EDITOR，未获得该模型对应数据的消费、审核、再授权或降密能力 |
| U-CUSTOM | 纯自定义业务角色，允许隔离测试资产的特定动作；不得取得建模准入或三员能力 |
| U-SYS / U-AUTH / U-AUDIT | 既有三员职责的三个不同账号；页面分别用于提交、审批、审计；不能共用一个会话冒充三人 |
| U-PENDING / U-DISABLED | 目录存在但无账号 / 账号已停用；两者都不能访问受保护业务，不能伪造 kc_id |

| MODEL-A1 / MODEL-A2 / MODEL-B | A 的两个模型、B 的模型，稳定 ID 和版本固定；分开准备可编辑、待审核、已部署状态 |
| ASSET-A / ASSET-B / ASSET-HIGH | A/B 为同属 DEPT-A 的不同资源，用于逐 grant 范围验证，不隐含跨部门许可；另设 DEPT-B 的隐藏资产。HIGH 的等级及人员映射须 Q22 确认，不从中文等级名推定大小 |

| LIST-20 / LIST-200 | 20/200 条可见对象，另有隐藏对象；排序唯一且固定，预先保存可见 ID 集合，列表总数只计可见集合 |

## 来源与迁移数据包

- `SRC-NORMAL`：有明确来源、人员主键、部门引用和已确认源版本的正常批次；同一人姓名/部门更新保持稳定记录绑定。
- `SRC-ORDER`：同一记录 v12/v11/v12；另设无版本而内容冲突的两条记录。摘要仅做去重。
- `SRC-PARTIAL`：三条合法行和一条未知部门行；先冻结该错误是否允许待处理或必须拒绝，预期按批准协议逐行核对，不能凭 HTTP 200 判整批成功。
- `SRC-FIELDS`：字段未传、允许清空、禁止清空分别构造；全量缺行分别有/无可信完整批次标记。
- `SRC-CASE`：同源 `ABC123`、`abc123` 两条记录，在两个干净副本按相反顺序导入，再在每个副本重放。预期各自绑定稳定，不要求两个副本的首次用户名相同；不自动转移旧授权。
- `SRC-MANAGED-GROUPS`：人员同时在 DTS 部门组、非受管组，另有人工保留角色；调岗只改变受管映射。
- `MIGRATION`：有历史主体证据、无证据、同名重建、孤儿、双表重复授予、带组织/数据集/动作范围、旧 profile 差异各一组；记录升级前可见资源与权限集合。
- `PKI-BASELINE`：受控保存既有登录步骤、配置版本/校验摘要、主体 ID 和证书映射证据；不保存证书私钥或会话令牌。

## 共用执行和清理

使用 `F11-{runId}-` 标识测试拥有的对象；实际编码长度/字符集以接口约束为准。每例独立恢复角色/审批/资源/会话起点，不能依赖上一个用例碰巧留下状态。角色变更先走受测审批并确认已生效，再触发下一授权边界；提交申请不等于撤权已生效。

稳定身份、字段源、权限期望集合在运行前写入受控清单；独立校验请求主体、数据库记录和 Keycloak 映射。PKI 基线保持不变。真实 MDM 输入和后台调度可作为环境准备或明确的外部刺激，不通过写数据库制造“已审批/已授权”的业务通过结果。

完成后通过受控业务入口撤销本次授权、停用测试账号、移除本次模型/资产；保留需审计的申请和证据。故障代理/调度暂停等控制恢复原值，截图脱敏。迁移恢复只作用测试副本，不清理正式数据或卷。
