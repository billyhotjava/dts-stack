## 三个层次的证明范围

- UT：依赖使用显式替身/固定时钟，验证规则和输出；不证明数据库约束、事务或真实 PKI。后端依既有 JUnit/Mockito、前端组件依既有测试框架落地。
- 集成：数据库事务与并发使用真实数据库；Keycloak 协议组使用真实隔离 realm；跨服务组使用真实 admin/platform。错误注入可用受控代理，但须注明哪些依赖被模拟，不把协议 mock 结果写成真实系统通过。
- 系统：使用有界面的真实 Chrome、真实后端及受控测试账号，按可见页面点击、输入、选择、提交、刷新、下载。API、SQL和日志只能做数据准备/故障控制/独立取证，不替代被测页面动作。禁止注入 token、改 localStorage、调用页面内 fetch 或伪造权限响应完成主流程。

**PKI 不改**：登录入口、证书校验、证书/账号映射、回调、插件、认证配置及会话衔接保持现状。PKI 只做兼容回归；证书和实体介质不可用时记录阻断，不能换成密码登录或 mock 登录后宣布 PKI 通过。F11 仅消费既有认证结果执行后置业务授权。

## 版本、执行与状态

开发目录 `/opt/prod/s10/v2.2.3` 只编辑与静态检查。编译型测试在代码 commit/push 后，由 `/data/dts-stack` 核对分支、工作区、`git pull --ff-only` 和 SHA，再走仓库正式测试入口。系统用例针对 `/opt/dts/release/dts-stack` 正式部署的同 SHA 制品；不得向容器打补丁。

每次执行记录应用/测试源码 SHA、包校验和、镜像 ID、配置/政策版本、环境、realm、浏览器实际版本、夹具 runId、执行者、起止时间。升级用例还记录旧版本。未实现/未执行子项记 `NOT_RUN`；执行时前置不满足记 `BLOCKED`，已满足前置而行为不符记 `FAIL`，全部参数化子项有证据才记 `PASS`。无法执行的子项不能静默跳过或合并成通过。

P0 为授权泄露、身份串用、职责绕过、不可恢复或关键登录链风险；P1 为重要功能/可操作性/兼容风险。责任人为职能占位，实际 owner 待排期，不代表已有业务签认。
