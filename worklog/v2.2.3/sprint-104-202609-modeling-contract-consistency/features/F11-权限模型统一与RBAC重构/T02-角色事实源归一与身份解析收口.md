# F11-T02 角色事实源归一与身份解析收口

**类型/状态**：开发及组件验证 / DRAFT

**owner/估算**：admin/platform 后端负责人待指派；L，入口清单冻结后重估。

**设计**：[架构 D02/D05、§3、§5](../../assests/F11-permission-architecture.md)；问题 P1/P2/P8，方案 R1/R2。

**输入**：T01 角色/账号分类；T07 当前目录契约；T08 稳定主体预检。输出供 T03–T05 与后台认证消费。

**PKI 边界**：只在既有认证成功后的业务授权层接入当前身份，不更改 PKI 登录、证书校验/账号映射、回调、插件、认证配置或会话衔接协议。缺少既有可信主体关联时记录兼容缺口，不能通过改 PKI 或同名回退解决。

## 工作内容

1. 在 admin 收口 IdentityResolutionService；保留 Keycloak 账号/三员权威源与 DTS 数据角色权威源，EMPLOYEE 迁移按来源清单处理，禁止无条件 union 注入保留角色。
2. 实现架构 §5 v2 请求/响应及旧目录适配。返回稳定账号 ID、当前状态/部门/人员密级、带范围 grants 和版本；继承服务认证及调用用途限制，不开放用户枚举。
3. 成员/授权改为稳定账号键，保留用户名展示、历史授予记录；role_assignment 的组织/数据集/动作限制不能被展平。记录双表重复/冲突来源，撤销不得漏掉仍生效的重复授予。
4. 登录/profile、ModelingDirectoryResource、PortalOpaqueTokenIntrospector/认证扩展、ModelingIdentityService、worker 共用当前解析；旧会话无稳定 ID 要重新登录，不能用同名补 ID。
5. 候选构建将 `candidate_version + to_status` 的命令反查改为按执行身份（派发/attempt）读取封存发起人，与 [建模版本语义草案](../../tbd.md) 阶段 2 同期冻结。手工运行 `operational` 已按 tenant + 派发 ID 读取 initiator_id，复用该记录并接入当前身份；保留 binding_id/version、scope_checksum、MANUAL 与有效部署检查，不能因身份收口移除执行范围守卫。
6. 提供统一的建模身份测试夹具，使 `ModelMaterializationStartServiceIT` 具备可运行的回归基线；夹具由本任务交付，执行归 T09。草案记录该类缺少身份导致失败；“10 条全部失败”属于待补 SHA、命令和日志的历史报告，本轮未重跑，不作为当前测试结论。
7. 保留每边界 2 秒总预算、一次远程身份读取、无自动重试、请求内复用；部门/角色/启停/密级在下一边界生效。停用 401、无动作 403、不可见 404、目录故障 503；不从快照恢复允许。

## 验证与完成标准

- IT-70/71：同一身份在登录、菜单、建模及后台一致；改名不丢授权，同名新账号不继承；缺部门/非法密级按动作拒绝。
- 用真实持久化验证授权范围和并发撤销；外部目录替身覆盖超时/不存在/不匹配，真实 Keycloak 联调由 T09 补齐。
- 旧 portal_session/sub=username 与大屏身份兼容，保留 F9 K87/K89；当前员工、三员、服务主体不得混用准入模型。
- 输出受测版本、接口契约及未迁移入口；实现完成不等于切片发布完成。
