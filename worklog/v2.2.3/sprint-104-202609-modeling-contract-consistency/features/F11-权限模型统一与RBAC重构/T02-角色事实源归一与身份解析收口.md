# F11-T02 角色事实源归一与身份解析收口

**状态**：DRAFT（等待 Q16、Q18 确认）
**对应方案**：R1、R2　**对应问题**：P1、P2、P8

## 目标

消除角色双事实源，建立唯一的身份解析入口，让登录、建模目录和后续新模块看到同一份角色。

## 计划内容

1. **单一身份解析接口**：dts-admin 提供唯一实现，返回账号状态、角色全集、部门、人员密级。账号存在与启用状态以 Keycloak 为准；角色为 Keycloak 角色与 DTS 数据角色的并集。
2. **调用方收口**：登录合并逻辑、`ModelingDirectoryResource.resolve`、`ModelingIdentityService` 全部改为调用同一实现，删除各自的合并代码。
3. **关联键迁移**：`admin_role_member`、`admin_role_assignment` 从 username 改为 `kc_id` 关联，保留 username 仅作展示；存量数据迁移并校验孤儿行。
4. **命名统一**：`EMPLOYEE` 统一为带 `ROLE_` 前缀，Keycloak 与库内一致。
5. **缓存与失效**：调用方按会话缓存解析结果，角色变更或账号停用时失效。

## 验收要点

- 同一账号在登录、建模、其他模块看到的角色完全一致，有对比测试。
- 改名或删号重建后，授权行不再被新同名账号继承。
- 身份解析失败时按失败关闭，不降级放行。
