## 工作内容

1. 修正 S4/S6/S7/S9/S10/S12：有权限码写入和目录、有嵌套策略、有多个旧 profile 读取，组织删除已查新来源；常量相同不证明全部接口无对象门禁。
2. 分开记录源码、历史运行报告和本次目标实测。冻结环境/realm/提交/查询时间与脱敏结果，包括账号类型、改名/重建/孤儿、部门空值、旧角色来源和 scoped assignment。
3. 固定 Q21 的人员稳定标识、MDM status/版本/全量语义；未知值有明确拒绝或隔离策略，不猜测“离职”。现有代码按大小写区分 personCode 来源记录，admin 分配用户名并保留既有绑定；首次分配受顺序影响。仍需补齐来源协议、编码复用/重复清单、调岗标记与实际登录账号关系、缺失绑定的恢复证据；不能把大小写区分当作永久人员标识已核实。
4. 汇总 Q22 新密级政策、Q23 特殊账户、Q24 Ranger/外部数据消费路径的缺口，标记具体受阻切片。
5. 建立真实调用链和入口矩阵，覆盖认证过滤器、路径级/方法级准入、服务/任务、菜单、查询与导出；不能仅统计注解。后台执行列出 `ModelingExecutionAuthorization.candidate`（按 tenant/candidate/version/to_status 查命令发起人）、`.operational`（按 tenant + 派发 ID 读取已封存 initiator_id，并检查绑定版本/范围）、`ModelingSystemExecution`（受限 plan 系统域）。与 [建模版本语义草案](../../tbd.md) 共同冻结候选构建的执行身份，不删除手工运行的范围校验，也不默认并入草案全部改造。
