# F11-T03 权限点模型与菜单绑定重构

**状态**：DRAFT（等待 Q17、Q18 确认）
**对应方案**：R3　**对应问题**：P5、P7

## 目标

引入"权限点 → 角色 → 用户"三层模型，让菜单绑定成为权限模型的一部分，而不是唯一的权限表达方式。

## 计划内容

1. **权限点字典**：新增权限点表，命名按 `模块:对象:动作`，例如 `catalog:asset:write`、`modeling:model:publish`。
2. **角色-权限映射**：新增映射表，内置角色给出默认映射；自定义角色（`admin_custom_role`）可配置映射。
3. **菜单改绑权限点**：`portal_menu_visibility.permission_code` 从空壳变为真实引用，菜单可见性由权限点决定；保留 role_code 作为兼容期字段。
4. **菜单接口收口**：`/api/menu` 取消 `permitAll`，角色、权限、密级一律取自安全上下文，不再接受调用方传参。
5. **授权页面**：管理端角色管理页增加权限点配置，变更仍走变更单审批。

## 前置

- Q17 决定权限点粒度（模块+动作约 40–60 个 / 按钮级数百个）。粒度直接决定字典规模与前端改造量。

## 验收要点

- 菜单可见性与接口放行由同一份权限点驱动，不会出现"看得见点不动"或"看不见却能调"。
- 匿名调用 `/api/menu` 被拒绝；传入 roles 参数不再影响返回结果。
- 存量角色迁移后可见菜单与迁移前逐条一致（结构快照 diff）。
