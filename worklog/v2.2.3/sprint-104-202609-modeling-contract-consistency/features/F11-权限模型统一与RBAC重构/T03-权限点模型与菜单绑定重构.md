# F11-T03 权限点模型与菜单绑定重构

**类型/状态**：开发、配置迁移与组件验证 / DRAFT

**owner/估算**：admin/platform 后端、两端前端负责人待指派；L。

**设计**：[架构 §6](../../assests/F11-permission-architecture.md)；P5/P7、R3。

**输入**：T01 角色/菜单现状、T02 v2 身份契约；输出供 T04/T05 首切片及 T08 菜单迁移。

## 工作内容

1. 收口已有 permissionCatalog，定义唯一权限码、资源类型/业务动作、可授予类别、状态及角色映射；默认角色矩阵与各动作包含关系明确，不按按钮数量倒推字典。
2. 复用角色管理页/变更单。权限变更包含 before/after、基线版本、申请/审核职责，禁止自审/自授权、保留权限注入；过期审批拒绝，应用幂等，失败不记 APPLIED。
3. 同时改造 platform PortalMenuClient 与 admin 内部菜单委托：稳定主体来自已认证服务端会话，服务身份只证明调用方；不得简单移除 permitAll 后继续用旧服务头请求用户接口。菜单 v2 一次返回当前身份上下文及菜单树，认证扩展在本请求内复用；不得先做独立身份解析再由菜单接口重复解析，保持每边界一次远程解析和 2 秒总预算。
4. 改造 role_code 非空及角色必填写入约束；每切片明确旧角色规则或新权限规则，禁止 OR 放宽，空绑定不可见，读取不补种子。
5. 既有页面消费服务端权限/allowedActions；菜单可见不保证每个对象动作允许。保存/导出/审核等反馈中文，保留 F10 菜单结构与稳定 ID，不新增页面。

角色-权限版本原子生效，授权版本和运行政策版本不兼容时重新解析或拒绝；不能拼接旧权限/新范围。配置缓存不得绕过当前主体授权复核，补并发改权和实例版本落后的回归。

## 验证与完成标准

- IT-72/73：匿名/伪造 roles/permissions/dataLevel 不影响授权；真实 platform 服务调用按员工身份返回正确菜单，服务故障与无菜单状态区分。
- 默认角色菜单 diff 按批准的权限变化解释；旧错误授权不要求原样保留；直接 URL/API 负例必须通过。
- 权限字典/映射使用真实数据库约束和并发审批验证；管理端角色配置及门户导航真实联调由 T09 负责。
- 首切片权限与菜单上线依赖 T04/T05 完整链，不以页面配置完成代替后端授权生效。
