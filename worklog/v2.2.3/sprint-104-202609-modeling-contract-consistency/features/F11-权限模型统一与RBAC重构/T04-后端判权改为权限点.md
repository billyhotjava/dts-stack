# F11-T04 后端判权改为权限点

**类型/状态**：按资源域分批开发及回归 / DRAFT

**owner/估算**：各业务模块后端负责人待指派；L，按入口清单分批重估。

**设计**：[架构 §5–8](../../assests/F11-permission-architecture.md)；P3/P4、R3。

**输入**：T02 当前身份、T03 权限/范围矩阵；与 T05 对齐资源判定；输出为完整资源域切片。

## 工作内容

1. 形成路径级匹配、方法注解、服务内判断、后台/内部入口到“业务动作+范围+状态+职责”的清单，包含 GET/列表、预览、导出、下载和非 HTTP 任务。原 508 计数只作线索。
2. 首切片选择建模定义读取/编辑及其既有菜单：统一动作准入、ModelSpecAccessService 与 allowedActions，保留发布/审核/执行职责和纯自定义角色不得建模的 F9 规则。
3. 用统一权限检查替换共用角色数组的粗门禁；路径层与方法层同时核对，不让旧数组提前拒绝已有效授权的用户，也不只删旧门而漏新门。
4. 每批纳入 admin 对应目录/审批/菜单和平台直接入口；三员/保留权限沿明确矩阵，不新增通配“管理员全放行”。
5. 识别后台 USER/SYSTEM、服务调用、旧客户端和外部消费者；切片的全部入口使用同一政策版本，再切到下一批。

## 验证与完成标准

- IT-73/75：每个入口有允许/拒绝及范围反例，拒绝没有业务副作用；审批/编辑/执行不互相代替。
- 改前/改后接口集合及政策差异逐条说明，无法解释差异不切换；旧注解数量归零不是验收充分条件。
- 单元/接口契约覆盖动作映射，真实模块集成覆盖代理、直接 API 与 worker；不得只有 mock allowedActions。
- 输出本批入口清单、剩余域、代码/测试版本，配合 T08/T09 首切片发布验收。

**实际结果**：仅任务设计，未编码、未运行测试。Ready 以本批矩阵和 T05 接口足够可测为条件，不等待所有模块详细设计完成。
