# F11-T06 历史角色与冻结事实源清理

**类型/状态**：兼容收缩与历史归档 / DRAFT

**owner/估算**：admin/platform、运维负责人待指派；M。

**设计**：[架构 §3.2、§8](../../assests/F11-permission-architecture.md)；P4/P8/P9、R6。

**前置**：对应切片 T07/T02–T05 已迁移，T08 兼容/回退证据和 T09 验收齐全；不是身份收口前的先行清理。

## 工作内容

1. 核验 ROLE_GOV_ADMIN、ROLE_DATA_STEWARD、ROLE_INFRA_ADMIN 来源和消费者，已映射到正确权限后删除旧判断；不得仅因测试 realm 未见就宣布不可授予。
2. ROLE_AUDITOR_ADMIN、ROLE_AUDIT_ADMIN、ROLE_AUDITADMIN 等别名必须核对目标 realm、旧令牌、活跃会话、排队任务及旧客户端；先迁移，再下线，不换成更宽角色兜底。
3. 移除 person_profile 的全部运行读取/回填：建模目录、快照刷新、姓名解析、组派生等；保留历史审计与可恢复归档，不仅检查两个旧调用点。
4. 当前组织删除已经使用新快照/Keycloak，需证明新目录覆盖完整、关联人员/子部门/资源判定与并发受控，保持查不准不删。
5. 清理旧角色/菜单写者和版本适配，登记仍需长期支持的历史读取用途；实际删表/删列另列操作，不随普通部署执行。

## 验证与完成标准

- IT-76/77：正常回放/运行链无旧表依赖，旧别名消费者清零，目标角色仍可完成职责。
- 只读归档前后数据数量/校验及可恢复性有证据；未完成现场旧版本核验不得删除兼容分支。
- 回退不恢复旧授权漏洞，旧版本不可兼容时关闭受影响写动作并按 T08 恢复。

**实际结果**：仅计划，没有下线角色、停表、删表或变更数据。
