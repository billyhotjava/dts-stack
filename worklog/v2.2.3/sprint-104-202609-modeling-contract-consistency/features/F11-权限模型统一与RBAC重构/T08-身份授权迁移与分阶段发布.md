# F11-T08 身份授权迁移与分阶段发布

**类型/状态**：迁移设计、工具与发布验证 / DRAFT

**owner/估算**：后端迁移、发布与运维负责人待指派；L，按真实行数/版本矩阵重估。

**设计**：[架构 §8–9](../../assests/F11-permission-architecture.md)。

**依赖**：预检/设计依赖 T01；每个执行阶段依赖对应切片实现、正式制品与 T09 的准入证据，不能把发布执行排在开发之前。

## 工作内容

1. 形成只读预检及逐项转换清单：旧 username 的历史主体证明、角色双表/作用范围、待执行审批/任务、菜单规则、空部门和旧 profile 差异。孤儿、同名重建、无法证明主体的记录隔离。
2. 设计可重复执行的扩展迁移、分批回填、版本约束和写入追踪；不直接 DROP/覆盖历史，不靠当前用户名自动认领旧授权。
3. 列出 admin/platform/worker/前端及外部消费者版本兼容矩阵。先升级兼容接口和受控写者，再切权威目录；旧刷新任务不得继续覆盖 MDM 字段。
4. 新旧判定对比时只有旧规则生效，新规则无副作用；获批政策差异与缺陷分开。按完整资源域切换，不能任意实例同时用互相冲突的规则。
5. 为 A 身份目录、B 首个权限闭环、C 扩面分别记录前置、切换标志、停止条件、备份、恢复操作；回退不复活撤权/离职/旧匿名入口，新语义不兼容时关闭受影响动作。
6. 按项目路径正式交付：开发目录 commit/push 后，/data/dts-stack 检查分支/工作区、git pull --ff-only 并核对 SHA，测试/构建/打包；/opt/dts/release/dts-stack 正式部署。记录 SHA、版本清单、镜像 ID/digest、包校验和及配置版本。

## 验证与完成标准

- IT-76/77：脱敏真实结构副本上完成预检、升级、并发写入、失败恢复/回退演练；记录映射/隔离/冲突数量及权限集合差异。
- PKI 仅做兼容核验：认证配置、证书/账号映射及既有登录协议不变，迁移前后仍认证为同一账号；不得把 PKI 改造作为迁移或回退步骤。无法证明兼容的接入点不得切换。
- 在线/离线用同提交正式制品验证，包内包含迁移与运行依赖；不复制未提交文件、不向容器打补丁、不强删被引用镜像或数据卷。
- 收缩前保留足够兼容期证据；T06 只在对应切片可安全退出时执行，不提前删历史列/表。

**实际结果**：仅规划。无迁移 SQL 执行、备份、制品、部署或回退演练证据。
