## 目标与边界

实施人员和数据管理员从上到下浏览一级菜单，看到的顺序就是业务实施顺序：工作台、数仓规划、数据集成、数据建模、数据开发与运维、数据治理、数据分析与服务；大屏管理保持一级菜单。常见工作在一个菜单内完成；必须跨菜单的，每个方向一次直达目标对象，并能返回。

只调整菜单排序、实施引导顺序与少量跨菜单链接的落点。不改菜单名称、不新增或删除或移动菜单节点、不改页面地址与后端业务接口、不改角色可见性、不改大屏管理。

## Review 结论与决策

- 跳转困惑的根因是菜单顺序与实施顺序不一致，以及部分跨菜单链接只落到页面首页、用户要再找一次。
- 现有名称与技术协议基本一致（C125），不需要改名。
- 现有菜单有一处顺序错误：数据集成排在数仓规划之前，与实施和协议顺序相反。
- 数据治理应在数据分析与服务之前：资产登记前不能配质量规则，质量通过前不能发布（C120、C121）。
- 数据标准、关系图留在数据建模，避免建模时在两个菜单之间往返；协议也把模型关联关系归入数据模型（C125）。
- 质量配置已在资产侧（C122），但模型构建结果的按钮落到数据集详情首页（C123），需改为直达质量配置面板。
- 种子文件与库内哈希不一致时，读菜单会自动补齐并软删除种子外的根菜单（C111），因此排序迁移、种子文件与哈希必须同一提交（K97）。

## UI/UX 规格

- **导航**：一级顺序见上，不显示序号，不加分隔；名称不变。
- **实施引导**：工作台引导与端到端旅程按 规划、标准、集成、建模、指标、开发、服务、证据 排列（K100）。
- **跨菜单直达**：模型构建完成后点“配置质量规则”，直接进入该资产的数据运维面板并展开质量配置，面板上有“返回模型”入口；其余跨菜单链接按契约第 6 节核对（K101）。
- **四态**：导航与现在一致；直达链接的目标加载中保持面板骨架，目标资产尚未登记时显示“资产登记完成后可配置质量”，无权限时只读提示，成功时焦点落在质量配置区。
- **兼容**：Chrome 95、1366×768；旧书签全部可打开；键盘可操作。

**操作走查**：部门数据管理员登录 → 一级菜单依次为 工作台、数仓规划、数据集成、数据建模、数据开发与运维、数据治理、数据分析与服务、大屏管理 → 数据建模下首项为数据标准，关系图仍在数据建模 → 数据治理下分级分类在质量管控之前 → 在模型工作台完成构建后点“配置质量规则”，一次到达资产质量配置 → 点“返回模型”回到原模型 → 普通员工登录，可见页面与迁移前相同，大屏管理仍为一级菜单。

## 任务通用契约

- **数据流与复用**：管理端菜单表 → 管理端按角色过滤 → 平台转发 → 前端按 `externalLink` 渲染。复用既有菜单迁移范式（C112）与种子机制（C110、C111）；复用资产侧已有的数据运维面板与质量配置（C122），不另建质量入口。
- **错误路径**：定位不唯一、父节点与清单不符、快照已存在、回滚时行已被他人修改，全部 HALT 或拒绝并输出清单；直达链接目标不存在或无权限时给出明确提示，不落到空白页。
- **存储与兼容**：只改 `sort_order`；不增删节点与角色绑定；大屏管理行零改动；客户现场按 titleKey 定位。
- **UI 落点**：只动导航顺序、实施引导与指定的跨菜单链接；页面结构与名称不变。
