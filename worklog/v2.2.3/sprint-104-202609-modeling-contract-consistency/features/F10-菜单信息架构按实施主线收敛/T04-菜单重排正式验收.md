# T04：菜单重排正式验收

**优先级**：P1
**状态**：DRAFT
**依赖**：T02、T03 进入 Git；T01 基线已冻结

## 目标

在同一 SHA 的正式交付包上证明：一级与子级顺序正确，名称与层级不变，大屏管理零改动，七个角色可见页面集合不变，种子机制不被误触发，重置与回滚可用，关键场景跨菜单跳转不超过一次。

## 使用场景

契约第 4 节目标树、第 6 节跳转场景、F10 README 操作走查，以及 [IT-64–IT-67](../../it/F10-菜单重排验收.md) 全部分支。

## 技术设计与契约

- **契约引用**：K93–K101；契约第 11 节非功能约束。
- **执行流程**：
  1. 开发目录 commit/push → `/data/dts-stack` 确认分支与工作区干净 → `git pull --ff-only` → 核对 SHA。
  2. 专项测试与正式构建 dts-admin、dts-platform-webapp；记录镜像 ID/digest 与包校验和。
  3. 迁移验证：清洁库；当前测试库副本；已执行 `20260916_01` 的升级库。每次记录迁移前后树、快照内容、种子哈希、`biScreens` 摘要。
  4. 首次读菜单：管理端日志无“seed changed”“baseline missing”，根菜单数与节点数不变。
  5. 可见性比对：用 T01 脚本导出七个角色迁移后清单，与迁移前逐一比对，差异必须为零。
  6. 重置为种子：在隔离库执行，结果与迁移后树的父子与顺序一致。
  7. 回滚演练：执行回滚得到原顺序；另构造迁移后人工调序一行，回滚拒绝覆盖。
  8. 按正式部署流程更新测试环境（需用户授权），真实登录部门数据管理员与普通员工走查；按契约第 6 节逐个场景记录点击次数与落点；Chrome 95 与 1366×768 截图；打开旧书签清单。
  9. 客户现场升级前执行 T01 的唯一性核对 SQL；命中不唯一或父节点不符时先处理再升级。
- **错误路径**：任一阶段未执行标 NOT_RUN 并说明原因；失败只重跑受影响分支。
