## 已核对事实（2026-09-24，源码 `dc06a6277`）

- **工程验证阶段在持久层同时承担登记与治理**：`ModelPublicationQualityReconciler` 只处理 `QUALITY_RUNNING` 的发布单（第 99、195 行），在同一次对账中先 `qualityAssets.ensureRegistered(candidate)`（第 136 行），再 `governanceQuality.evaluateLive(candidate)`（第 137 行），通过后推进 `QUALITY_PASSED`（第 120 行）。因此登记故障会停留在"工程验证"阶段，表现为工程验证未完成——这是 D3 要找的后台耦合点，不只是页面呈现问题。
- **`RUN_QUALITY` 是 BUILT 之后的手动动作**：`ModelLifecycleContract` 第 140 行 `BUILT → [RUN_QUALITY, CANCEL_CANDIDATE]`。直接把它自动接到构建后会把登记和治理一起带进构建（D1 结论的依据）。
- **交付状态接口已分项**：`ModelDeliveryStatusQueryService` 返回 materialization / quality / publication / catalog / analysis 五个 step（第 83–191 行），`recommended()`（第 206 行）是唯一跨项汇总点，待核对。
- **旧七步实现仍在代码与本机镜像中**：`releaseJourney.ts`、`ReleaseJourneyView.tsx`、`ModelPublishDialog.tsx`（1020 行）来自 `f817a2421`、`90ef8361d`；本机 dts-platform-webapp 镜像构建自 `90ef8361d`。
