# F15-T03：模型版本发布与运行上线分离

**状态**：DRAFT；**类型**：开发/服务集成验证；**优先级**：P0；**估算**：L。
**负责人**：发布/运行前后端，人员待定。
**依赖**：T01 的 K4/K5；T02 构建事实；F13 发布准入与策略。
**依据**：[共享设计](模块划分与协作设计.md) M6a/M6b、K4/K5；**消费方**：T04 及运行管理。

## 目标与唯一责任

发布选定模型版本、开放资产访问、部署启用运行分别办理。本任务在原发布/运行服务调整命令及副作用归属，不另建发布状态机，不以一个成功标记代表三项业务完成。

## 工作内容

1. 发布检查使用指定模型/实现/构建引用；读取适用的资产、工程、质量与审批/安全证据。T04 默认只显示摘要，异常才展开；检查不自动构建、登记、执行质量或部署。
2. 沿用 ADVISORY/BLOCKING、冻结策略和命令时重新检查身份/版本/来源的规则。提示允许发布不等于质量合格，未知策略不自动降级；资产/工程/安全硬条件继续有效。
3. 按 T01 清单收口 CandidatePublicationCommitService：本地发布事实、必要引用/索引、审计及通知一起提交；M3 登记、M5 分析准备、M6b 执行配置/部署分别交接。最小物理映射需要原子提交时有明确依据，不能误删。
4. 核对并移交 rebuildManualBinding 等运行配置写入。发布完成仅产生可引用版本/可靠通知；运行侧明确部署/启用。兼容生成运行配置草稿时须未启用、独立状态，不能标成已上线。
5. 资产开放权限维持原授权模块独立准入，版本发布不扩大访问。版本回退只改变合法发布引用；运行版本切换另有明确命令与授权，不删物理数据或静默切换在跑任务。
6. 发布摘要可由 M1 本地读取，既有正式 v2 与设计/构建 v3 并存；发布、上线、每次运行各自记录及恢复。旧接口/在途记录按 T01 方案兼容。

## Ready 与完成标准

- [ ] K4/K5、发布最小事务、分析/运行交接和迁移/回退方案明确后才可 READY。
- [ ] 服务/真实持久化验证两策略、冻结证据、审批、权限/密级、版本/来源失配与并发发布。
- [ ] 发布不标记登记/质量/分析/运行成功，不自动开放权限或启用部署；查看发布记录不依赖运行服务健康。
- [ ] 发布失败只恢复发布；上线失败只恢复上线，构建/SQL和发布次数不无故增长，旧正式版本仍可查询。
- [ ] [IT-05/06/07/09/10/15/16](../../it/F15-独立流程验收.md) 对应分支留证；与 F13 共享代码/政策只实施一次。
