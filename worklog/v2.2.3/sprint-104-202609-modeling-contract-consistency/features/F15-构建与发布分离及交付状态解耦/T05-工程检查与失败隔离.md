## 唯一责任划分

- F14 负责 M2 构建、必要核验、结果回写/恢复；F15-T02 负责建模读写边界。
- F13-T02 负责 M3 登记从 QUALITY_RUNNING 独立出来及幂等、失败记录/重试；F8 保有 M4 规则/执行/报告，F13-T03/T06 负责发布证明消费和质量处置接入。
- F15-T03 负责 M6a/M6b 发布和运行交接；M5 需要调整的代码落在原分析同步模块，不新建引擎。
- 本任务负责 K3/K6 跨模块交接接入、所属功能可发现的处置路径、故障/升级集成验证；发现缺口回原责任任务修复，不能三边重复改同一状态机。

## 工作内容

1. 实现 T01 已冻结的“构建完成事实 + 待交接意图”持久机制；目录离线时照常保存构建完成和待办。构建提交尚不能可靠确认时保留待确认，不丢交接后伪报成功。
2. 独立消费登记结果，使用统一资产身份与构建引用幂等；重复、乱序、候选版本递增不能重复建资产或让旧结果覆盖新资产事实。
3. 资产现有功能提供待登记/失败/到期处理记录，包含对象、环境、运行、原因、最近尝试及允许动作；无资产 ID 时仍能定位。连接既有通知/巡检机制；没有自动告警能力不能声称已通知，不能等用户打开发布才能发现。
4. 质量、分析分别使用资产和适用版本，各自保存执行/业务结果；登记成功不顺带成功分析，发布策略不修改质量报告。所需正式版本由 M6a 独立提供。
5. 模拟服务超时、进程崩溃、响应丢失、重复/乱序事件、权限变化与旧回调；恢复仅操作失败模块，不增加构建 SQL 或不相关发布/部署次数。
6. 旧候选、旧统一读接口、旧深链和在途任务按 T01 方案兼容；必要升级/回退保留历史成功、待办、正在运行版本和审计，不手工改生产状态。
7. 分别记录失败事实与当前可用性；真实目标被覆盖/破坏时只能依据新核验更新有效性，不把历史成功作为永久可发布凭证。
