# F15-T02：建模摘要查询与独立构建

**状态**：DRAFT；**类型**：开发/单元与服务集成验证；**优先级**：P0；**估算**：L。
**负责人**：建模后端，前端协作，人员待定。
**依赖**：T01 的 K1/K2；F14 构建、必要核验和恢复。
**依据**：[共享设计](模块划分与协作设计.md) M1/M2、K1/K2；**消费方**：T04、M6a、T05。

## 目标与唯一责任

交付不用读取质量、目录、分析或运行总状态即可查询/保存模型和执行合法构建的路径。本任务负责模型摘要与建模命令边界；F14 负责执行器、目标核验和底层恢复，T04 负责页面，不能把本任务缩成拆弹窗。

## 工作内容

1. 在现有建模查询层提供 K1 分页/有界批量摘要：当前设计/实现版本、按版本/环境/目标区分的最近构建、已发布版本、本地允许动作和部分读取状态。移除列表必须逐行调用 getModelDeliveryStatus 的依赖。
2. 复用 ModelDeliveryStatusQueryService.modelingResult 的证据匹配语义，抽到可独立查询的原职责层；不得为得到构建结果先拉完整 workspace、质量上下文或 serving。旧综合接口按 T01 兼容，不继续供新模型列表使用。
3. 保存/校验只维护模型定义和实现；不要求已构建、登记或质量合格。构建命令冻结 K2 并调用 F14，缺少合法来源/目标、安全条件时仍拒绝。
4. 旧候选可作为内部兼容载体；隔离独立构建与发布意图，保留必要资源锁，但不能以治理待处理禁止无关草稿编辑。占用未发起时显示不可执行，不伪造一次构建失败。
5. 必要核验/结果回写未完成显示待确认，成功后可结束；SCHEMA_ONLY 不代表已有业务数据。历史成功与当前尝试、已发布版本独立保留。
6. 输出查询、构建/恢复的稳定契约供 T04；构建完成产生 T05 所需可重读结果，不同步等待目录、质量或分析完成。
