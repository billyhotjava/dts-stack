## 1. 目标

模型工作台只承担模型设计、版本管理和构建操作。设计保存/校验后可以结束；需要物理落地时再构建，结果确认后结束本次建模。登记、质量、治理、分析、上线和运行在各自功能独立处理。

用户看到当前设计版本、最近构建结果和已发布版本，不再看到跨业务总步骤、总失败或下游状态列。v3 构建失败时仍能看到已发布的 v2，不能把整个模型判为失败。

本轮替代旧“只拆构建/发布弹窗、后台解耦可后置”的方案。保留 Feature/Task 编号与目录以保持追溯，历史实现和原型不作为本版完成证据。

## 2. 模块与逻辑关系

**唯一共享设计**：[模块划分与协作设计](模块划分与协作设计.md)，包含关系图、状态/事务、K1–K6 契约、当前源码证据和责任映射。

| 模块 | 自己负责的结果 | 与其他模块的关系 |
|---|---|---|
| M1 建模与版本管理 | 模型/实现版本、设计校验 | 向 M2 发起构建；向 M6a 申请版本发布；读取二者摘要 |
| M2 构建执行 | 运行与工程核验、确认的目标结果 | 消费模型快照；将已提交结果可靠交给 M3；向 M6a 提供证据 |
| M3 数据资产 | 登记、统一资产身份、治理资料、开放使用入口 | 独立消费构建结果；为质量/分析提供资产；授权仍由既有权限模块决定 |
| M4 数据质量 | 规则、检查、真实报告与问题 | 消费资产和数据；发布服务按政策引用证明，不回写构建 |
| M5 分析服务 | 分析资源与可用性 | 消费合法资产/正式版本引用；成功不从登记或构建推导 |
| M6 发布与运行 | M6a 发布版本；M6b 部署、启用及每次运行 | 发布消费适用证据；运行明确选择已发布版本；两个状态各自维护 |

六类模块是职责划分，不新增六套服务或菜单。模块间引用成果，不共用一个推进全部业务的状态机。模型版本发布、资产开放使用、运行上线分别定义，既有权限/审批/密级/发布策略继续生效。

工作台显示：模型、分层、当前设计版本、最近构建结果、已发布版本、操作。主操作为编辑、校验、构建，版本发布/版本记录按需进入。没有登记、分析、质量、运行列或隐藏汇总面板。

构建面板只处理本次范围、目标、模式、进度、必要工程检查及恢复。发布默认显示版本/目标和检查结论，异常才展开缺项；需要处理时跳到所属功能，不嵌入其完整表单。成功、加载、空、读取失败分别呈现；关闭不取消任务，往返保留对象/版本/环境与返回位置。

[原型](prototype.html) 已于 2026-09-25 按共享设计修订：工作台为设计版本/最近构建/已发布版本三类信息；构建只交接登记；发布不开放资产、不准备分析、不上线；资产目录、数据质量、分析服务、运行管理各自发现并处理待办；v3 失败与 v2 已发布并存；「登记范围」作为待决策开关可体验两种选择。原型只证明交互与职责边界，不代替接口、持久化和故障验证；文档与原型冲突时以文档为准。

## 4. 关键架构规则

1. 建模摘要使用本地模型、构建和发布记录的有界查询；移除模型列表对综合 delivery-status 的逐行依赖。
2. M2 先持久化构建结果与可靠交接意图，M3 独立登记/重试；失败由资产侧待处理记录和运维机制发现。
3. 构建必要核验属于 M2，业务质量属于 M4，发布读取所需证据；不设置人工推进所有业务的工程验证阶段。
4. M6a 只提交必要发布事实/映射/审计及通知，部署、启用、分析同步分别由所属模块处理，不假报全部成功。
5. 老候选和旧接口可暂作兼容载体，但不能继续承担跨业务总成败；迁移方案不得丢失在途、历史成功与审计记录。
6. 复用 F3/F5、F8、F13/F14 既有能力，不另造模型台账、资产身份、质量引擎、执行器或平行状态机。
