## IT-01 四类模型与分阶段校验（T01/T02/T08）

**前置**：分别准备维度、明细、汇总、应用四类独立测试草稿；沿用页面支持的来源方式。应用需要有效的数据集市、主题域；无法选择时记录前置阻塞。

1. W1 先填写合法的部分定义，缺少一个阶段必填项，点击暂存；关闭后重开，确认已暂存输入仍在。
2. 不补该必填项，点击“保存并继续”：应就地指出缺少内容，不进入下一步。
3. 补齐业务定义后推进；W2 缺少目标表名或必要来源时提交，应拒绝并保留输入。
4. 输入非法字段名、重复字段名或错误类型组合，确认页面阻止提交或展示后端具体错误；字段不能被静默删除后当作成功。
5. 修正后保存、重开，核对名称、字段类型/作用、标准及业务归属。

**预期**：暂存、设计推进、实现提交、发布分别检查各自条件；普通全量明细不被强制添加假时间字段或假主键。Java/TS/Schema 的逐项一致性由研发补验，页面通过不能代替该证明。

## IT-02 历史配置保存恢复（T05/T08）

1. 在独立维度草稿配置 TYPE2、生效起止字段、当前标志和层级；暂存 → 关闭 → 重开，逐项对比。
2. 更改其中两个配置，再完成同样过程；两轮都应完整恢复，提交后读取的新修订应一致。
3. 另一测试草稿把 TYPE2 改为 NONE，保存重开：不再保留不适用的 TYPE2 专属绑定，也不删除普通业务字段。
4. 两窗口先加载同一草稿；窗口 A 保存，窗口 B 用旧版本保存：应提示冲突、保留 B 的输入，不能覆盖 A。

**预期**：配置保存成功与历史执行能力分开；不能因保存了 TYPE2 就显示已支持历史维护。上述主要分支已有历史通过证据，可在新修改影响时复验。

## IT-03 当前 FULL/空分区不回退（T06/T08）

1. 使用独立旧增量模型或测试副本，将加载方式明确改为“全量”，清空分区，保存并重开 W2。
2. 再次提交实现并查看构建计划/实现代码：仍为全量，不回退旧增量设置，不出现旧分区。
3. 在另一测试草稿去掉所有粒度键，选择增量并提交：必须明确拒绝无键增量，不能悄悄改成全量成功。

**预期**：显式全量和空分区优先于历史配置；若当前界面不能清理旧分区，记录为入口缺口。缺少旧分区样例时填阻塞，研发补充夹具。

## IT-04 复合粒度键质量检查（T04/T08）

1. 新建项目/月明细，粒度键为 `project_id + month_id`，来源选样例表；完成提交、物化及工程检测。
2. 在样例仍为三行的前提下，P001 跨月出现两次应通过组合唯一性；不能仅因 `project_id` 重复而失败。
3. 交换两个粒度键的顺序后重新生成实现/检查，合法数据仍应通过。
4. 使用**独立输入表**分别准备同项目同月重复、project_id 空值、month_id 空值：对应组合唯一性或非空检查应失败，并能定位字段/记录。

**预期**：检查完整组合键，每个必需键检查非空；工程检查与治理规则结果分别显示。负向数据由独立夹具提供，不修改共享样例源表；无夹具时该分支记阻塞。

## IT-05 标准覆盖策略与失效引用（T03/T08）

**前置**：独立模型含主键、度量及普通属性 `remark`；主键和度量已绑定有效标准，remark 未绑定。

| 操作 | 预期 |
|---|---|
| 选择 KEY_AND_MEASURE，查看阶段校验/发布阻断 | 不要求 remark 补绑；只要求主键和度量 |
| 切到 ALL_FIELDS，再查看 | 明确指出 remark 缺少标准 |
| 在无标准绑定的独立模型选择 NONE | 不产生“必须绑定标准”的错误 |
| 给策略外 remark 绑定一个已失效的测试标准版本 | 即使策略是 KEY_AND_MEASURE 或 NONE，仍检查这个已声明引用；允许合法草稿暂存，发布必须阻断失效引用 |
| 专业标准服务不可用 | 显示无法获取证据，不能显示校验通过，也不能统一误报为缺绑定 |

最后一项及失效版本夹具由研发在隔离环境补验；不要为了测试停共享服务或废弃在用标准。

**预期**：完整限定名为 `schema.table`，规则目标与 SQL 作用域一致；跨目标引用不能绕过检查；错误能定位而非笼统“运行失败”。

## IT-15 新建四步向导与发布分离（T09/T10/T11/T14）

1. 新建 `S104手验_日期_01`，W1 只处理业务定义；暂存后仍在本阶段，完整“保存并继续”后进入 W2。
2. W2 配置实际来源、映射/SQL、目标表和加载方式；“提交实现并继续”成功后进入 W3。同版本无改动时继续前进不能重复生成实现版本。
3. W3 根据真实状态依次提供构建、规则配置、检查等当前主操作；运行时不开放冲突动作。全部必需检查通过后进入 W4。
4. **此时先不要确认发布**：检查模型/发布记录，不能已经产生新发布。
5. 在 W4 确认发布；成功后显示目录、分析各自结果。刷新不能重复新建模型或重复发布。
6. 分别在 W1 缺必填、W2 缺来源时尝试推进，失败停留并保留输入；保存失败/提交部分成功分支由研发注入补验。

**预期**：每页最多一个当前主动作；暂存、上一步等次要按钮可同时存在。访问某个步骤不等于已完成该阶段；W3 检查通过不自动发布。

## IT-16 跨步导航与未保存保护（T09/T10/T12/T14）

1. 已有有效证据的模型可直接回看 W1～W4；切换、刷新、前进后退不改变生命周期、不新增执行记录。
2. 新草稿尚未提交实现时，修改 URL 的 `step=delivery` 或点击未来步骤：只能查看缺少条件/返回入口，不能直接发布。四个 step 值为 `definition`、`implementation`、`verification`、`delivery`。
3. 独立草稿修改一个字段但不保存，尝试离页；分别验证“留在当前页”“放弃”“保存后离开”。放弃不落库，保存成功才承诺重开恢复。
4. 保存冲突/失败时，应停留并保留输入；不能自动跳页或把暂存当作实现提交。
5. 构建运行中离开再回来，应恢复原任务；离页不取消任务，轮询不能把主动选择的步骤抢走。
6. 从完整规则/目录页返回，仍指向原模型和步骤；无效候选不自动绑定其他模型。
