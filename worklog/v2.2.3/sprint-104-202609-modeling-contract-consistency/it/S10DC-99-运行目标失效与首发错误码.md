# S10DC-99（重新打开）：运行目标失效导致构建 HTTP 500

## 复现（2026-09-23，openEuler 192.168.62.43）

- 22:02 构建失败，页面仅显示 `MODEL_DBT_AIRFLOW_UPSTREAM_FAILED`；Airflow `prepare_runtime` 调用 `/api/internal/modeling/materialization/runtime-specs/consume` 得到 HTTP 500，dbt 未执行，平台日志无错误。
- `upload/dbt-config.json` 的 `targetDataSourceId=30444a99-…`（09-21 15:45 写入）；当晚数据库重新初始化后数仓为 `a0000000-…0001`。`upload/` 不随数据库重置。

## 根因

1. 配置查询/启动只在内存中匹配替代数仓（`hydrateResolvedConfig`），不写回文件；运行时 `loadRuntimeConfig()` 读原始文件。
2. `resolveRuntimeTarget()` 抛无码 `IllegalStateException`，租约服务统一包装为 `DBT_EXECUTION_TARGET_SECRET_UNAVAILABLE`，`consume()` 未捕获 `DbtRuntimeProfileException`，接口只处理 `ModelMaterializationRuntimeException` → 全局 500、丢码。
3. `consume()` 的任何失败都不写 `modeling_materialization_dispatch.last_error_code`，收尾只能取通用码（`ModelMaterializationRunArtifactService.java:450`）。
4. 当前版本没有 dbt 配置页面（`updateDbtConfig` 无页面调用），用户无法自助修正。

09-21 的修复 `63b3be35c` 只处理了回调系统执行域；本部分当时已诊断但未修。

## 修复（提交 `20400602b`）

| 项 | 改动 |
|---|---|
| 目标错误码 | 新增 `DbtRuntimeTargetException`（继承 `IllegalStateException`，其他调用方兼容）：`DBT_TARGET_NOT_CONFIGURED/DATASOURCE_NOT_FOUND/JDBC_MISSING/SECRET_UNPROTECTED/SECRET_UNAVAILABLE`；租约服务保留具体码 |
| 物化运行规格 | 租约失败返回 422+码并审计；令牌校验通过后的失败经 `ModelMaterializationRuntimeFailureRecorder` 在锁事务回滚后以新事务写入派发 `last_error_code`；三个来源可用性码不写，保持既有 STALE 流程 |
| 计划调度运行规格 | 租约失败返回 503+码，不再逃逸为 500 |
| 启动校正 | 配置目标不存在时，仅当 ACTIVE PostgreSQL 数据源中 JDBC 库名与配置 `database` 完全一致且唯一，才写回文件（WARN `event=dbt_config_target_reconciled`）；0 个或多个候选不改（ERROR `event=dbt_config_target_invalid`）。运行时仍不静默换库 |
| 页面 | 物化“原因”列为 `DBT_TARGET_*` 显示中文说明与处理人 |

升级脚本核对：`upload/dbt-config.json` 不属于托管运行文件，升级保留现场版本（`bin/lib/dts-runtime-files.sh`），交付包无需调整。

GitNexus：`resolveRuntimeTarget`、`loadConfig` 影响分析为 CRITICAL（公共入口）；方案保持异常类型兼容、不改 `loadConfig` 返回；`detect_changes` 风险 low。
