# S10DC-64：数据库接入展示源表注释

## 决策与范围

用户于 2026-09-23 确认 A 方案：别名取源库表注释 COMMENT。沿用工单已定位的数据库接入“发现源表”入口：并列展示物理表名与“表别名（源表注释）”。没有注释显示“—”，不从资产目录推测名称，不维护另一套人工别名。选择键、任务保存和执行仍使用 schema.table。

## 根因与修复设计

JdbcMetadataService.readTables 未读取 JDBC getTables 的 REMARKS；TableMeta、接口 TableInfo 和前端 TableInfo 未携带表注释。补充可选 comment 字段，从源库元数据直接读取，无需提前采集资产。元数据代理原样传递该字段。页面用文本展示注释，长内容允许换行，避免占满物理表名列。

GitNexus 将 readTables 标记 HIGH：listTables 直接调用，间接影响发现源表、自动发现全部表和表存在性检查。仅追加元数据字段，保留 TableMeta 原三参数构造，保持物理标识和选表逻辑。其他数据库驱动若不返回 REMARKS，则保留物理名；不伪造注释。

## 验证计划

- JDBC 单测：中文注释、空/空白注释、同名不同 schema、不改变物理表名。
- PostgreSQL 临时测试容器：实际 COMMENT ON TABLE 后首次发现即能读取；空注释对照。不得改业务数据库。
- HTTP：发现表响应保留 comment/name/schema，无需 includeColumns。
- 前端：展示注释和空值；选择/保存仍使用原物理标识；源文件回归、类型检查与 Chrome95 兼容构建。
