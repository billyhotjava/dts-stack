# F15 独立流程验收

**状态**：18 项全部 NOT_RUN；**修订**：2026-09-25。
**依据**：[F15 需求](../features/F15-构建与发布分离及交付状态解耦/README.md) R1–R6、[模块划分与协作设计](../features/F15-构建与发布分离及交付状态解耦/模块划分与协作设计.md) M1–M6 / K1–K6。
**本轮仅测试设计**：受测 SHA、镜像/包、环境、执行者、执行日期待实际执行填写。旧 F15 统一阶段用例和历史 PASS 不作为新版证据。

## 数据、观察与责任

使用隔离计划下的两类模型：结构构建模型 S、数据构建模型 D；保留 v1 历史成功、v2 已发布且运行、v3 当前设计。新版本失败不影响旧目标的场景使用隔离目标，另设覆盖同一物理目标后失败的夹具，不能假设所有失败均无物理影响。准备在途任务、批量独立对象及真实上游依赖对象。角色采用实际有权/无权账号，不能只用管理员覆盖所有路径。

测试前后记录模型/实现版本、目标/环境、构建运行、持久交接、登记尝试/资产标识、工程/质量记录、分析资源、发布记录、部署/执行关联，以及查询依赖、SQL、登记、质量、分析、发布、部署命令调用次数。跨服务或事务行为需真实持久化/集成证据，组件 mock 只证明展示和消费行为。故障只在受控夹具注入，执行后恢复夹具与配置。

开发承担单元/组件和集成验证；测试承担功能/异常/回归与缺陷确认；业务/运维承担实际使用验收，人员待指定。组件测试验证独立状态与动作映射，系统测试关注下表可观察结果，避免每一层重复同一整链流程。

## 执行与记录

1. T01 后细化实际输入/输出、查询/重试预算及夹具；先执行 IT-01/02/13 的最小独立建模切片，再按对应任务接 IT-03–10/14–17；IT-11/18 随页面和原型执行，IT-12 在正式制品就绪后执行。
2. 编译/转换测试、构建、打包均在 `/data/dts-stack`，确认分支/工作区，从已提交推送的开发分支 `git pull --ff-only` 并核对 SHA。部署前核对当前正式部署目录、Compose 项目、持久化和挂载，按正式交付配置更新并记录；历史路径不作为本次已验证基线，不从开发目录启动同用途容器或给容器打补丁。
3. 每项追加版本、环境、真实执行者、命令/步骤、实际结果、截图/日志/状态引用、缺陷和修复确认；本次不创建占位成功证据。
4. PASS、FAIL、BLOCKED、NOT_RUN 分别统计；mock、静态检查、正式服务和客户验收分别标明。测试执行完成而业务要求未满足时，Feature 保持未完成。
