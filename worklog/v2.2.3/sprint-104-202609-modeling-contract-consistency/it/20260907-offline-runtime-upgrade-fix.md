# 离线运行脚本更新与正式发布修复

日期：2026-09-07。源码基线：`e18896cd3`。承接 `307d00c61` 的物化收尾修复，本记录处理该修复如何进入在线与离线运行环境。

## 原因与修改

- Airflow 工厂通过部署目录的 `services/dts-airflow/extra` 只读挂载，更新平台镜像不能替换它。原 lite 升级器对已有脚本仅生成 `.new`，导致正式升级仍运行旧代码。
- 两个升级入口共用产品运行文件规则：备份并替换 Airflow 工厂、模板、静态构建 DAG、dbt 项目及静态依赖、宏和升级工具。现场配置及生成的业务 DAG、导入模型保留；已有非产品文件差异写入冲突目录。
- 完整升级器兼容旧字符串和当前对象形式的镜像清单，加载前验证清单、镜像校验和及完整运行文件清单。lite 使用 Bash 校验，不新增现场 Python 依赖。
- 新包声明 `runtimeFilesRequired`，升级前验证 `files-checksums.txt`，拒绝缺失、损坏和未登记的运行文件；旧包缺少该声明与清单时保留兼容警告，不宣称获得新版完整校验。
- 正式制包入口补入静态构建 DAG，并检查工厂、共享升级库是否存在，排除 Python 缓存。回滚清单记录新增文件，回滚恢复旧代码并删除本次新增文件；新版包保持不变，回执存放在现场备份目录。
- lite 停服务失败时中止更新。完整升级入口复制中途失败时通过退出处理保存回滚清单；不能把复制失败当作升级完成。

## 影响与检查

- GitNexus 对 `write_metadata` 的 upstream impact 为 LOW；Shell 函数未被索引收录，工具返回 UNKNOWN，未将其报告成低风险。源码调用点为两个升级入口及回滚，制包改动位于 `pack_deployment`。
- 本轮仅做源码审阅、Shell 语法检查、Python AST 解析与 `git diff --check`。
- 已补充回归用例源码：真实元数据格式、脚本校验、更新/回滚、现场配置保留、路径冲突、停服务失败、静态 DAG 制包。
- 按用户要求，不执行测试、编译、制包、镜像构建、容器重建或真实页面验收。上述回归用例尚未运行，运行结果待手动验证。

## 发布交接

1. 开发目录仅提交、推送本轮修改；部署目录仅通过 `git pull --ff-only` 获取已推送版本，不复制开发产物。交接 SHA 以本文件所属提交及部署目录核对结果为准。
2. 部署目录当前存在未跟踪的 `builds/__pycache__`、`dist`、验收/发布数据和本地 dbt 宏。本轮保留它们；正式构建前由发布人员处理并确认工作区及镜像导出目录，不把旧产物算作本提交的构建证据。
3. 同一目标 SHA 完成正式构建、制包，核对镜像架构、源码版本、镜像 ID 与包校验和，再将相同交付包用于在线/离线验收。
4. 从解压后的新包执行升级器，先查看 `plan`，任务结束后在维护窗口升级。无需现场改 Python、联网补依赖或向容器复制文件。
5. 更新后对原模型重新构建，核对四个 Airflow 步骤、Candidate BUILT、dispatch COMPLETED、pipeline BUILT。历史数据库表或旧成功记录不能替代本次验收。
