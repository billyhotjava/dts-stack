# 物化后目标质量规则入口修复

日期：2026-09-07。源码基线：`7c332d0a9`。用户截图显示项目任务快照明细 v2 的 r4 已物化，候选 BUILT v11，关系已核验；后续“配置质量规则”按钮及表单使用受阻。

## 源码发现与修改

- 原入口只调用 `scrollIntoView`，不展开下方 `<details>`。质量规则草稿的 dirty 状态还会通过全局 `commandsBlocked` 禁用该定位按钮，背景读取也会令入口暂时不可用。
- 向导现在发送显式打开请求，由目标质量面板展开表单、滚动到面板并聚焦规则名称。重复打开保留已输入内容，不触发构建或规则提交。
- 配置入口沿用维护权限、模型/实现已保存、当前候选匹配和服务端动作 enabled 条件；规则自身未保存状态及背景读取不再阻断返回表单。构建/检查等实际命令继续使用原禁用约束。
- 补齐目标表、规则列表、输入框、SQL 文本框、错误提示和操作区布局，使用 Chrome 95 已支持的 CSS 与 DOM API。默认数仓阻断文案的错误码与服务端统一为 `QUALITY_DATASET_NOT_DEFAULT_LAKE`。
- 提取构建区按钮组件 `ModelMaterializationActions`，发布组件从 824 行降到 781 行。原候选构建/重试/发布操作及质量规则创建 API、dataset 绑定没有改变。

## 手动发布与验收

代码先在开发目录提交并推送，再经 Git 同步部署目录。本次仅需正式构建和更新 `dts-platform-webapp` 镜像，无新增 Airflow 文件或后端镜像变更。

1. 对已物化、关系已核验且缺少质量规则的当前模型，点击“配置质量规则”，确认表单展开且焦点进入名称输入框。
2. 输入规则名称和 SQL，重复点击入口，确认内容保留；填写完整后“保存并发布规则”可用。
3. 保存后确认目标表的规则列表刷新，规则绑定当前 dataset；再执行质量检查并按实际运行结果判断是否通过。
4. 无维护权限、模型或实现未保存、候选不匹配及服务端禁止动作时，确认限制仍生效。执行构建/检查时入口不能绕过正在进行的命令。
5. 在 Chrome 95、1366×768 及窄屏下确认长表名、输入框和按钮可读；离开含未保存规则的页面时确认原导航保护仍存在。
