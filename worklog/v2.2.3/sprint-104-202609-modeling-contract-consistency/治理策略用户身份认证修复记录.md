# 模型发布治理：复用管理员身份，取消新增环境配置要求

日期：2026-09-25。问题：存量部署缺少 admin → platform 的静态服务凭据，导致管理页面读取策略失败。目标：保持管理入口、策略归属及发布流程，使用已有登录身份完成操作，无需新增 `.env` 配置。

## 职责和调用关系

1. admin 管理页面继续调用原有 `/api/admin/infra/model-governance-policy`。admin 验证系统管理员权限及会话，客户端只转发安全上下文中已验证的用户 JWT。
2. platform 仅为 `/api/internal/modeling/governance-policy` 及其子路径设置专用认证链，验证签名、签发方、接收方、有效期和用户身份；兼容顶层 `roles` 和 `realm_access.roles`，只授权精确包含 `ROLE_SYS_ADMIN` 的用户。治理接口显式使用 `DefaultBearerTokenResolver` 读取 Authorization；普通门户接口继续使用原 Cookie 认证。
3. 因注销、闲置超时和互斥登录由 admin 维护，platform 使用同一个用户令牌访问 admin 的 `/identity` 子接口确认会话仍有效。该接口仅返回当前操作人，不调用 platform，不构成递归。沿用已有 admin 网关地址与超时设置，不发送服务凭据。
4. platform 从认证身份取得操作人，忽略请求体中的伪造操作人；继续在本地数据库读取、更新策略并检查策略版本。发布质量校验仍读取本地策略，不依赖上述配置页面调用链。
5. admin 保留业务审计；platform 专用认证链复用现有访问审计过滤器，记录直接访问策略接口的用户操作。

## 配置与安全边界

- 不再使用 `DTS_ADMIN_TO_PLATFORM` / `DTS_INBOUND_FROM_ADMIN` 授权治理策略操作；旧服务凭据不再能访问该接口。
- 复用已有 Keycloak 签发方、接收方、OIDC 客户端和 admin 地址配置；接收方校验兼容既有令牌的 `azp`，仅接受已配置的客户端，不新增密钥、默认口令或匿名入口。
- 只允许读取策略、读取影响范围及更新策略三类请求；其他方法和子路径拒绝。
- 会话注销、超时、身份不一致或会话校验服务不可用时拒绝操作。
- 变更原因仍要求 1 至 200 字，更新仍要求有效版本号；没有修改现有策略值。

## 真实登录发现的补充修复

首次使用系统管理员登录成功，但治理接口仍返回 401。定位到三处原测试与现场差异：门户 Cookie 解析器作为全局 Bean 被治理认证链继承；现场令牌省略 `aud`，使用已配置客户端的 `azp`；系统管理员角色位于顶层 `roles`。补充提交 `72ffaa055d44e9fb24755b73454657f9db3eaeb3` 仅修改治理认证配置和测试，显式隔离 Bearer 解析器并兼容上述受信任令牌结构，保留签名、签发方、有效期、精确角色及会话注销校验。

补充后在正式构建目录执行全部相关回归：**79 项通过，0 失败、0 跳过**（platform 67 项、admin 12 项）；日志 `/tmp/governance-user-jwt-claims-tests.log`。测试配置已复现生产环境的全局 Cookie 解析器 Bean，新增缺少 `aud` / 顶层角色的成功路径、错误客户端、非系统管理员和注销拒绝用例。正式构建、交付包校验、两个服务部署及上述真实页面验收均已完成。
