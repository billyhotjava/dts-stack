## 统一规则与修改责任

| 问题 | 根因 / 产品规则 | 修改与跨模块保护 |
|---|---|---|
| B01 | 兼容链接属于导航合同，不能丢失对象和环境 | LegacyDataModelingRedirect 保留搜索参数、模型 ID 和 hash，复用现有工作台；不另建页面，不改变授权 |
| B02 | 尚未加载与真实不匹配被共用兜底文案 | 候选摘要区分加载、失败、空候选、不匹配；保留模型/环境/修订匹配校验与原动作门禁 |
| B03 | 接入提交只有短暂 toast；受测旧部署还缺 591d208c2 的文件来源身份修复 | 保留输入并增加持久错误区；正式发布包含此前已提交的封存修复，不通过改数据库补封存 |
| B04 | 第二步按旧文件配置显示新建/自动主键，第三步及执行器按 modelTarget 强制追加 | modelTarget 是有效目标规则的唯一来源；第二步固定目标、说明追加、隐藏 DDL 开关；序列化从绑定合同取得目标且自动主键为 false；保留服务端 ModelTargetGuard 的身份、结构、版本校验 |
| B04 × B03 | 将旧自动主键标记归零会触发来源变化，误清封存 | 托管文件具有 ID/hash 时，来源比较继续排除目标落地设置，并排除纯目标选项 _autoId；文件 ID/hash、字段、密级、来源类型仍参与比较；准入与执行安全校验不放松 |
| B05 | AirflowExecutionSyncService.markExecution 同步成功/失败与时间，不回填行数；现有 nullable DTO 表示执行器未提供统计 | 页面详情和历史列表明确“执行器未提供”，不以文件预览或全表行数推算本次写入。真实计数回传需要独立执行器证据合同，未在本次伪造补齐 |
| B06 | QualityRunQueryService 脱敏把所有失败映射为同一句话；SQL 范围校验将解析不支持与越界统一拒绝 | 在现有查询 DTO 边界按稳定错误分类给安全操作建议；DATASET_SCOPE_BLOCKED 说明语法、支持范围和绑定表检查，不断言仅为越权；不输出原始异常、SQL、连接凭据，不放宽 AST/只读限制 |
| B07 | 列表直接读取初始化的 failingRowCount=0，详情已有有效统计判断 | 列表复用 getQualityRunCounts，执行失败/未统计不显示 0；质量违规有有效统计时仍展示实际数量 |
| Q03 | 历史 executor 标记默认 hive，但实际 QualityRunService 使用绑定资产的 QualityDatasetStatementExecutor | 编辑和详情统一表达“使用检测资产的数据源”；旧字段保留隐藏传回以兼容，不修改运行路由 |
| Q04 | dataset.type 可能装有 dbt 的目标数据库类型；DTS_NATIVE 和 discovery 状态缺标签 | 详情优先使用统一合同 assetType；既有标签表补原生资产映射及 discovery/VERIFIED/MISSING，保留数据库字段的存量值，不做数据清洗 |

Q01：字段名称和失败后草稿恢复仍为待复验，不能从后台一次现象直接修改三端契约。源码确认定义保存和创作快照保存是不同操作，需要可见 Chrome 明确步骤、成功提示与刷新对象后再判断。Q02：错误 SQL 已在执行时被拒绝；本次保持发布与执行分离，不另造 SQL 解析器。

## 页面验收矩阵

1. 旧模型 test 深链进入同一模型和环境，刷新仍保持；列表链接仍可用。
2. 候选加载不闪现错误不匹配；真正不匹配、无候选、加载失败各有明确反馈；跨模型不可串证据。
3. 文件任务 6 重开第二步为追加且无自动主键/重建操作，第三步一致；不改文件保存并生效可到详情，失败时输入与错误区保留。
4. 同文件目标选项调整不丢封存；实际新文件/字段变化不能复用旧封存；不重复执行任务 6 以免重复主键。
5. 缺计数的历史运行明确未提供；有真实统计的 0 必须显示 0。
6. 正常规则 v3 试跑有扫描/通过统计；独立坏 SQL 试跑被阻断、详情说明可操作、列表与详情均未统计；坏规则测试后停用。
7. 质量编辑/详情执行方式一致，保存不改变已有检测目标；发布、CAS、正常试跑保持有效。
8. 原生资产类型/映射/发现状态可读，治理与消费门禁仍独立；DWS 分析查询仍可执行。
