## 身份与目录

- 新会话绑定 directory_user_id；旧会话缺列值，建模 401 需要重新登录。不能按 username 猜测补列，不能让同名重建账号继承原 ADS。
- dts-admin 精确 stable ID 查 Keycloak 启停/有效角色，并读取当前人员档案和有效非根组织。档案明确部门优先；只有确实无档案才走现有属性路径，查询故障不能当无档案。
- 部门码精确相等；无 dept_code 时只用已验证非根节点 ID，不使用名称/后缀/父子范围推断。
- 主体每请求解析一次；目录总截止 2 秒，无重试、无旧成功结果放行。503 排查 admin、Keycloak、人员档案查询及服务调用身份，不通过删除权限校验解决。

## ADS 排障

1. 区分 401（旧会话/停用）、503（目录故障）、404（不可见/不存在）、403（当前能力不足）、422（可见但违规来源）、409（版本/密级/状态冲突）。不泄露隐藏模型信息。
2. stable ID 核对当前部门、建模角色、ADS owner、有效 USER/ROLE EDITOR 和 allowedActions。EDITOR 不授予管理/审核/数据密级访问权。
3. 调岗/离职/撤权后新写入与 USER 任务重新判断。改名不换 owner；转出 ADS 撤销授权，转回不复活；不手工更新 owner 消除报错。
4. 授权与实际写入有事务锁，按提交顺序生效；核对授权提交点、模型/候选、审计 ID。失败审计独立落库，不因业务回滚删除。

## 队列执行

- USER 使用不可变命令或运行行封存的 initiator，执行/重试前查当前目录与完整范围，不借计划创建人或服务账号。
- MODEL_EXECUTION_AUTHORIZATION_REVOKED 在外部提交前阻断并审计。重新获权不改写旧命令；按既有入口发起/恢复经当前授权的请求。
- 目录 503 沿既有 UNKNOWN/retry 路径恢复。可能已提交时先核对外部执行事实，不假称零副作用，不盲目重复提交。
- SYSTEM CRON 仅可信内部入口及已部署 binding/version/checksum；USER 不能声明 SYSTEM，系统运行不新增定义/发布权。

## 密级与安全回退

- 低于有效密级返回 CLASSIFICATION_DOWNGRADE_FORBIDDEN；表单刷新当前值并保留其他输入。不传保持、显式空值拒绝。
- 保留稳定身份、owner、授权、密级事实、审计及扩展列。旧二进制不满足权限契约时先关闭建模写入口，再恢复兼容版本；不得重新开放已知降密级或菜单即授权漏洞。
- 仅正式包与 Compose 回退原服务版本并核对镜像 ID；保留业务卷/历史产出，不删除数据、不改容器内部文件、不用 hotfix 镜像。
- 恢复后重新登录，验证普通用户拒绝、部门与 ADS 撤权、密级只升、已提交执行事实和既有消费，再开放入口。当前未演练，不标 rollback PASS。
