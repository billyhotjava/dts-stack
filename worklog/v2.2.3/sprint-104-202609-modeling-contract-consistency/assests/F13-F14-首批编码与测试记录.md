## 第二批：准备阶段来源拒绝的事务收尾（2026-09-24）

本批范围为 F14-T03 第6项；已先修订 F14 设计§5。源码提交 `af9f9d281`，RED 用例提交 `8bcb7b6bd`。

- 原因：`requireDispatchCurrent` 或 `pinDispatchCurrent` 抛错后，运行规格事务回滚，只保存了拒绝审计，没有保存运行/候选终态；后续 Airflow 失败只能得到通用上游失败。不能只补写来源错误码，因为现有 finalize 会以来源失效拒绝继续处理。
- 处理：通过既有失败记录器，在外层事务确认回滚后启动独立事务，复用 `persistAvailabilityStale` 同时保存派发 FAILED、模型运行 FAILED_STALE、候选 STALE 与严格审计。审计边界为 PREPARE_RUNTIME，保留原始码；准备尚未提交来源版本，不编造代次差异。
- 并发保护：按候选→派发顺序加锁，只接受 BUILDING、候选版本相同、最新 attempt、活动派发且 runtime_consumed_at 为空的任务。迟到失败不得改变已消费运行规格、终态或被新尝试替代的执行。原任务的后续 finalize 不得覆盖来源失效历史。
- 事务失败：状态更新、候选命令与严格审计任一失败全部回滚，不回退为只写错误码；保留调用方原始错误。外层提交或提交结果未知时不按回滚处理。
- 复用与范围：未新增表、回调 API 或 Airflow 协议，未重跑 SQL；完整阶段 DTO、SQL/核验/清理首因归并、独立恢复操作、F13 检查轮次仍未实施。本批不等于 T03 或 F13/F14 全量完成。

影响检查：GitNexus 对结果服务/仓储返回 LOW；新近增加的失败记录器及 consumeWithinSystemScope 未被两个索引收录，补查实际调用点。修改限上述处理路径与测试；新增仓储锁顺序与现有构建/重试/放弃入口一致。
