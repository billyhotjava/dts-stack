# Sprint-82 集成验收基线

## 1. 当前源码基线

- 资产地图路由：/catalog/assets。
- 资产台账路由：/catalog/assets/ledger。
- 数据标签当前仍挂在资产地图 tab=catalog-tags。
- 台账每行存在申请权限、详情、治理、更多及更多菜单中的多个动作。
- 完整资产档案已有字段契约、治理责任、质量与 SLA、血缘与影响、权限申请等页签。
- 标签后端已有字典 CRUD、能力校验、单资产绑定/解绑、批量绑定和按标签检索。

## 2. 当前运行环境基线

- dts-platform 容器健康，管理健康端点返回 UP。
- dts-platform-webapp 可访问。
- 当前运行库标签分类、标签及资产标签绑定均为 0，不能作为标签旅程的现成验收数据。
- 本 Sprint 不通过重启、编译或直接写运行库制造验收结果。

## 3. 测试策略

### 编码期间

- 只执行与当次契约直接相关的源契约或组件测试。
- 先得到有效 RED，再实现 GREEN。
- 不执行整体 Maven、pnpm build、容器构建或全量 E2E。

### 全部编码完成后

1. 源契约和组件定向测试。
2. dts-platform-webapp 类型检查/构建。
3. 受影响 Java 测试（仅当本 Sprint 最终修改后端）。
4. Chrome 95 兼容检查。
5. 核心 E2E：
   - 地图聚合下钻台账；
   - 台账筛选和分页上下文保持；
   - 治理资产 → 当前任务 → 推荐下一步；
   - 标签查看资产；
   - 标签关联资产、单资产解绑和回查；
   - 完整资产档案各能力仍可达。

## 4. 不通过条件

- 地图仍出现标签字典管理或治理写操作。
- 台账行仍平铺多个模块按钮。
- 推荐动作指向不存在、无身份或无权限的资产页面。
- 标签关联后无法在台账筛选或资产工作台回查。
- 将标签误写为分类分级或密级。
- 为完成 UI 闭环新增重复后端 owner。
- 任何变更页面超过 800 行或引入逐行标签请求。
