# T03: 退役顺序与回滚边界

**优先级**: P0  
**状态**: DONE  
**依赖**: T02

## 目标

定义低风险退役顺序和回滚路径，确保现场旧链接和历史构建仍有可解释方案。

## 技术设计

退役顺序：

1. 菜单不可见：新入口只暴露平台 `modeling` 路由。
2. 旧链接兼容：旧 `bi-apps/metrics` 和 `semantic-center` 路由 redirect 到平台页面。
3. 默认运行退役：compose/init/build 不默认启动或构建 `dts-metrics`。
4. 能力接管：补齐平台页面的表映射、发布链路、黄金链路路由。
5. 物理删除评估：Sprint-55 再做。

回滚边界：

- 可保留显式 legacy/profile 或手工 image build。
- 不删除 `source/dts-metrics` 和历史 Liquibase。
- 旧链接保留 redirect，不直接 404。
