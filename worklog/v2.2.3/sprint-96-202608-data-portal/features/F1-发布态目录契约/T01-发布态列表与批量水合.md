# T01：发布态列表与批量水合

**优先级**：P0  
**状态**：READY  
**依赖**：F0/T01

## 目标

草稿大屏不会进入 `publishedOnly=true` 目录；发布后立即进入；旧列表仍返回该用户可管理的草稿。

## 技术设计（Contract-first）

- **输入**：`publishedOnly:boolean=false`，与现有 domain 过滤参数正交。
- **输出**：沿用 `ScreenListItem[]`；不引入门户专用影子 DTO。
- **数据流**：accessible screens → 一次 batch currentPublished 查询 → map → publishedOnly filter → `toListResponse`。
- **错误路径**：无会话 401；不可读过滤；重复 currentPublished 选择最高 versionNo 并由测试暴露数据异常。
- **复用点**：`ScreenPermissionService`、`AnalyticsScreenVersionRepository`、`toListResponse`。
- **范围**：`ScreenResource`、版本 Repository、`analyticsApi.listScreens`、相关 IT/契约测试。

## 验证（RED→GREEN）

- [ ] RED：创建两个草稿、发布一个；`publishedOnly=true` 预期只返回发布项。
- [ ] GREEN：旧列表仍含两项；published detail `sourceMode=published`；无 N+1。
- [ ] 403/409/401 边界保持既有语义。

## Definition of Done

- [ ] 聚焦 IT 绿，批量查询契约可证明。
- [ ] 前端 API client 只在显式参数时发送 `publishedOnly=true`。
- [ ] Sprint 证据回填。
