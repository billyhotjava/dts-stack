# T01: 消息中间件选型与架构设计

**优先级**: P1
**状态**: READY
**依赖**: 无

## 目标
选定消息中间件并设计异步通信架构，为核心链路的异步化改造奠定基础。

## 技术设计

### 现状
- 所有服务间通信为同步 REST（RestTemplate / Feign）
- 无消息队列、无事件总线
- 任务状态变更靠轮询，非事件驱动

### 设计要点
1. **中间件选型对比**:
   - Redis Streams: 轻量，若 F4 已引入 Redis 可复用
   - RabbitMQ: 成熟，支持复杂路由，ARM64 支持好
   - Apache Kafka: 高吞吐，但部署复杂
   - PostgreSQL LISTEN/NOTIFY: 零新增组件，但能力有限
2. **消息模式**: 点对点 vs 发布/订阅
3. **消息可靠性**: 至少一次 vs 恰好一次
4. **死信队列**: 失败消息的处理策略
5. **消息格式**: CloudEvents / 自定义 JSON
6. **Spring Integration**: Spring Cloud Stream / Spring AMQP / Lettuce
7. **离线环境**: 中间件的离线安装和 ARM64 支持

### 需要回答的问题
- 消息吞吐量预估？
- 是否需要消息持久化和回放？
- 是否可以接受引入新的基础设施组件？

## 影响范围
- `docker-compose.yml`: 新增消息中间件服务
- 所有 Spring Boot 服务: 引入消息客户端依赖
- `.env`: 新增中间件配置
