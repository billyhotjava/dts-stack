# M05 数据安全（协议 2.3.2.5）覆盖度核验

**核验时间**: 2026-06-07
**代码基线**: /opt/prod/s10/v2.2.3/source（branch v2.2.3, commit 8f563c0be）
**核验范围**: dts-platform / dts-admin / dts-analytics 后端 Java + dts-platform-webapp / dts-admin-webapp 前端
**对照 sprint**: sprint-32 ~ sprint-35（2026-05），与前序 2026-04-21 证据线索

> 结论速览：行/列级访问、密级分级、密级↔脱敏联动、备份策略台账等"框架性"能力真实存在且仍在线；但协议三大硬要求中的两项关键能力仍为缺口——
> 1）**操作权限矩阵**（资产×角色×完整动作集 新增/删除/修改/复制/导入导出/归档/销毁 集中配置）仍未建立，运行时动作集硬编码为 `read/write/export`；
> 2）**敏感数据自动识别引擎**（正则+字典+AI 推断扫描 + 监控查询）仍不存在，脱敏规则仍为人工逐字段标注；
> 3）**备份**仅为元数据台账（策略/运行记录/灾备演练），**无实际全量/增量备份恢复执行引擎**，应用与数据库备份均靠外部执行后回填结果。
> sprint-32/35 为指标语义工作台、sprint-34 为审计目录 DB 化、sprint-33 为角色成员分配 UI 重构——均未闭合本模块上述缺口。

### 1.2 基于资产目录/库表/行/列设权

- **status**: ✅ covered
- **当前证据**:
  - 行/列/对象级策略实体: `dts-platform/src/main/java/com/yuzhi/dts/platform/domain/iam/IamDatasetPolicy.java`（scope=OBJECT/ROW/FIELD，含 rowExpression、fieldName、effect、subjectType、validFrom/validTo）
  - 策略解析服务: `dts-platform/src/main/java/com/yuzhi/dts/platform/service/iam/PolicyService.java`（明确处理 ROW→rowExpression、FIELD→字段可见性、OBJECT；行表达式与字段可见性 DTO 装配）

### 1.3 操作权限含【新增/删除/修改/复制/导入导出/归档/销毁】集中配置（操作权限矩阵）
- **协议要求**: 操作权限须覆盖新增、删除、修改、复制、导入、导出、归档、销毁，并可按 资产×角色×动作 集中配置。
- **status**: 🔴 gap（前序 4 月已识别，至今未闭合）
- **当前证据（实证缺口）**:
  - `AdminRoleAssignment.operationsCsv` 注释即 `// comma-separated read/write/export`，运行时动作集被 `dts-admin/.../web/rest/platform/PlatformDirectoryResource.java:329` 硬编码为 `List.of("read", "write", "export")`，仅 3 个动作。
  - 资产授权请求 `CatalogDatasetAccessRequest` 仅有 `can_query` / `can_preview` 两个布尔动作位，无 删除/修改/复制/导入/导出/归档/销毁 维度。
  - 全仓未检索到任何 `ActionMatrix` / `PermissionMatrix` / `assetAction` 集中配置实体（命中的 `OperationType`/`ActionMatrix` 关键字均属**审计**操作类型归一化 `OperationTypeNormalizer` / `AdminAuditOperation`，非访问控制矩阵）。
  - 归档/销毁仅以**生命周期审批**形式存在（`CatalogLifecycleRequestResource` + `CatalogLifecycleRequest.requestType`），是逐资产工单，不是"角色×资产×动作"集中授权矩阵；导入导出/复制无独立授权动作位。
  - sprint-33 仅重构成员分配 UI（role-detail.tsx 只处理 memberAdds/memberRemoves），未引入动作矩阵。
- **gap**: 缺少统一的"资产/库表 × 角色 × 完整动作集（新增/删除/修改/复制/导入/导出/归档/销毁）"集中授权模型与配置界面；现网动作维度只有 read/write/export/query/preview。
- **优先级**: **P0**（协议明确列举的合规硬约束）
- **落地包建议**:
  1. 新增 `IamAssetActionPolicy`（或扩展 IamDatasetPolicy）实体：subject(role/dept/user) × resource(catalog/table/dataset) × action 枚举（CREATE/DELETE/UPDATE/COPY/IMPORT/EXPORT/ARCHIVE/DESTROY）× effect × 生效期。
  2. 后端在各业务动作入口接入 `AccessChecker.canPerform(resource, action)`（当前 `AccessChecker` 仅有 `canRead`）。
  3. 前端在角色详情/资产授权页提供动作矩阵勾选（沿用 sprint-33 审批流落库）。
  4. 复用现有 audit OperationType 枚举做动作对齐，避免再造语义源。

### 2.2 敏感数据识别规则定义 + 自动识别 + 监控查询
- **协议要求**: 可定义敏感数据识别规则；系统自动识别敏感数据；提供敏感数据监控查询。
- **status**: 🔴 gap（前序 4 月已识别"无自动 scan 引擎"，至今未闭合）
- **当前证据（实证缺口）**:
  - 全仓未检索到任何识别引擎类：`grep -ilE "sensitiveScan|SensitiveData|autoIdentif|columnScan|piiDetect|patternScan|dictionaryScan|RecognitionRule|IdentificationRule|DiscoveryRule"` 在 dts-platform/dts-admin/dts-analytics main/java 下 **0 命中**。
  - 无 `*Sensitiv*` / `*Discovery*` / `*Recognition*` / `*Identif*Rule*` 实体或服务文件。
  - 脱敏规则仍为人工标注：`CatalogMaskingRule` 仅 column/function/args 三字段，由 `CatalogMaskingResource.createMasking/updateMasking` 人工 CRUD（前端 data-security.tsx "脱敏规则" Tab 表单：数据集/字段/脱敏函数/参数，全人工填写）。
  - 仅有"缺口告警"（被动）：分类映射校验里对高密级数据集无脱敏规则给出 `MASKING_GAP` warning（`CatalogMaskingResource.validateClassificationMappingInternal`），但这是基于密级的提醒，非对真实数据内容的扫描识别。
- **gap**: 缺识别规则定义（正则/字典/AI 推断）+ 自动扫描引擎（对库表字段/样本数据扫描打标）+ 敏感数据监控查询视图。
- **优先级**: **P1**（协议明确要求，业务价值高；非阻断式合规，但属脱敏链路前置能力，应尽快补）
- **落地包建议**:
  1. 新增 `SensitiveRule`（type=REGEX/DICTIONARY/AI，pattern/dictRef/threshold，目标密级/脱敏函数建议）实体 + CRUD。
  2. 新增扫描引擎 `SensitiveScanService`（对 catalog 字段元数据 + 抽样数据执行规则匹配，产出候选敏感字段与建议脱敏规则），离线/定时任务化（可挂 airflow-om）。
  3. 扫描结果落 `SensitiveScanResult`，并提供"监控查询"页面（命中字段、规则、密级、是否已配脱敏）。
  4. 与 2.1 分类映射、2.3 脱敏规则联动：扫描建议一键转 CatalogMaskingRule。

### 2.3 脱敏规则自定义 + 脱敏任务 + 执行 + 查看结果
- **协议要求**: 自定义脱敏规则；建立脱敏任务；执行脱敏任务；查看执行结果。
- **status**: 🟡 partial
- **当前证据**:
  - 规则自定义（✅）: `CatalogMaskingRule`（function+args）、`CatalogMaskingResource` 全套 CRUD、preview（hash/mask_email/mask_phone）、`classification-masking/linkage` 联动总览；前端 data-security.tsx "脱敏规则" Tab。
  - 查询期生效（部分）: 行级/密级过滤 `ExploreResource.isRowLevelAllowed`；密级↔脱敏联动 `classificationMaskingLinkage`。
- **gap（实证）**:
  - 无脱敏**任务**实体/调度：未检索到 `*MaskingTask*` / `*MaskTask*` / `*MaskingJob*` / `*Desensitiz*` 任何文件（0 命中）。
  - 无脱敏**执行结果**记录与"查看结果"视图：preview 仅为单值在线试算，非批量任务执行 + 结果留痕。
  - 现状是"规则定义 + 查询时按规则即时脱敏"，缺协议要求的"任务编排 → 执行 → 结果查看"闭环（尤其离线批量脱敏导出场景）。
- **优先级**: **P1**
- **落地包建议**:
  1. 新增 `MaskingTask`（目标数据集/字段范围、规则集、触发方式 手动/定时、状态）+ `MaskingTaskRun`（执行结果、命中行数、产物 URI、审计）。
  2. 任务执行器复用 CatalogMaskingRule 函数库；结果页展示运行记录与差异样本。
  3. 与 2.2 扫描结果打通：扫描命中 → 生成脱敏任务建议。

## 协议子项 3 — 备份

### 3.1 应用与数据库备份恢复 / 手动+定时 / 全量+增量
- **协议要求**: 支持应用与数据库的备份恢复；支持手动与定时；支持全量与增量。
- **status**: 🟡 partial
- **当前证据**:
  - 策略台账（✅ 元数据）: `dts-platform/.../domain/security/SecurityBackupPlan.java`（targetKey/title/schedule/retentionDays/enabled/lastRunAt/lastResult）、`SecurityBackupRun.java`（startedAt/finishedAt/result/artifactUri/detailsJson）、灾备演练 `SecurityDisasterRecoveryDrill`
  - REST: `dts-platform/.../web/rest/SecurityBackupRecoveryResource.java`（plans CRUD、runs 记录/查询、drills、report 导出，全部 INSTITUTE_PRIVILEGED 鉴权 + 审计）
  - 服务: `SecurityBackupService`（createPlan/updatePlan/deletePlan/recordRun/recordDrill/exportReport）
  - `schedule` 字段（cron）支撑"定时"策略描述。
- **gap（实证）**:
  - **无实际备份/恢复执行引擎**：`SecurityBackupService.recordRun` 只是把外部已完成的结果（result/artifactUri/summary）回填入库，无触发备份、无执行恢复的代码路径（无 dump/restore/调度执行）。
  - **无全量/增量区分字段与逻辑**：SecurityBackupPlan/Run 均无 mode/type=FULL/INCREMENTAL 字段；schedule 仅为文本，无内建定时调度器执行。
  - **应用 vs 数据库备份无差异化处理**：仅 targetKey 字符串区分，无应用包/DB dump 的不同执行通道。
  - 恢复（recovery）仅体现为"灾备演练记录" recordDrill，无真正的恢复执行/校验。
- **优先级**: **P1**（协议明确列举；现为台账级，实际执行能力缺位，存在合规与可用性风险）
- **落地包建议**:
  1. SecurityBackupPlan 增加 `backupType`(FULL/INCREMENTAL)、`targetType`(APPLICATION/DATABASE)、`triggerType`(MANUAL/SCHEDULED) 字段。
  2. 引入实际执行器：DB（pg_dump/基于 WAL 的增量）、应用（制品/配置打包），手动触发 API + 定时调度（airflow-om 或 Spring Scheduler）。
  3. 增加恢复执行 API（dry-run + 实恢复 + 校验），结果写 SecurityBackupRun，与现有 report/drill 打通。
  4. 若维持"外部执行 + 平台台账"架构，需在协议交付说明中明确边界并补"恢复演练→实恢复"证据链。
