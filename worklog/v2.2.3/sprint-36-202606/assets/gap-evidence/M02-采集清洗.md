### 1) 多源采集：关系库 / API(Restful+消息队列) / 离线文件(日志/CSV/XLS/XLSX/JSON) — 🟡 partial

**前序证据复核（仍存在）:**
- `dts-ingestion/.../service/etl/ConnectorCapabilityService.java` 注册连接器: `addax`(JDBC+file)、`airbyte`(future/未启用)、`file`、`api`。
- `dts-ingestion/.../service/etl/api/ApiHttpSourceConnector.java` + `ApiConnectorTypes.java`：RESTful/HTTP 源连接器（api/http/https/rest/httpreader），支持 7 种鉴权(none/apiKey/bearerToken/basic/oauth2/customSignature/mtls)。
- `dts-ingestion/.../service/etl/connector/SourceConnectorRegistry.java`：连接器注册中心。
- `dts-admin/.../domain/InfraDataSource.java`、`dts-platform/.../domain/service/InfraDataSource.java`：数据源元数据。
- 关系库: `JdbcMetadataService.java` + Addax JDBC（`AddaxJdbcConfigNormalizer.java`）。
- 文件: `FileUploadService.java`、`ExcelParseService.java`、`CsvParseService.java`。

**缺口（实地确认）:**
- **消息队列(Kafka/RocketMQ/RabbitMQ)采集源：未找到。** `grep kafka/rocketmq/rabbitmq` 在 dts-ingestion 主源码无命中；platform 的 `PlatformEventKafkaDispatcher.java` 仅是**内部 outbox 事件外发**（`KafkaTemplate` 发平台事件），不是采集入口。
- **Webhook 采集源：未找到。** dts-ingestion 无 webhook；前端 start 节点 `description` 出现 "Webhook" 字样（`blocks.config.tsx:49 trigger:'manual'`）仅为标签，无后端触发实现。
- **文件格式: 仅 .xlsx/.xls/.csv。** `FileUploadService.java:75` 明确 `不支持的文件类型...仅支持 .xlsx, .xls, .csv`。协议要求的 **JSON 文件、日志(.log) 文件不支持**（API 连接器能解析 JSON 响应体，但不是"离线 JSON 文件"采集）。
- CDC 实时（airbyte cdc）在所有连接器 capability 中 `enabled:false`（`ConnectorCapabilityService.java:83,111,138,255`）。

**优先级 P1** | **落地包建议:** (a) 新增 `MessageQueueSourceConnector`(Kafka/RocketMQ，复用 SourceConnector SPI)；(b) 新增 Webhook 接收端点(dts-ingestion `web/rest`)落 ODS；(c) `FileUploadService` 扩展 JSON/JSONL/.log 解析(`JsonParseService`/`LogParseService`)。

### 2) 实时 + 定时 + 批量 — 🟡 partial

**前序证据复核（仍存在）:**
- 定时: `dts-platform/.../domain/service/InfraTaskSchedule.java`（cron 字段 + status ACTIVE/PAUSED + lastRunAt）、`InfraTaskScheduleRepository.java`；`AirflowDagService.java`/`AirflowExecutionSyncService.java` 调度执行。
- 批量: Addax 全量/增量批处理、`backfill`(历史回灌) API 见 `IngestionTaskProxyResource.java:254 backfillTask`。
- 实时状态: `dts-ingestion/.../service/etl/RealtimeTaskStatusService.java`（仅为任务状态实时回显，非实时流采集）。

**缺口:** **真正的实时流采集缺失**——CDC 全连接器禁用、无 Kafka/流消费、无 Webhook 推送。当前"实时"仅是任务运行状态轮询，不满足协议"实时采集"语义。

**优先级 P1** | **落地包建议:** 启用 airbyte CDC 或引入 Debezium/Flink-CDC 连接器；与子项 1) 的 MQ 连接器合并交付一个"实时采集"落地包。

### 3) 全量 / 增量更新 / 增量追加 — 🟡 partial

**前序证据复核（仍存在）:**
- `dts-ingestion/.../service/etl/IncrementalSyncService.java`：watermark 增量（`column > watermark`，`IngestionIncrementalState`/`IngestionIncrementalAudit`）。
- `IngestionIncrementalStateDTO.java` 仍在。
- 同步模式: `ingestionFormHelpers.ts:220` `SyncModeValue = full_refresh|incremental|cdc|backfill`；`SYNC_MODE_LABELS` 全量同步/增量同步。

**缺口（语义细分）:** 协议区分"**增量更新(upsert)**"与"**增量追加(append)**"。当前 `incremental` 只实现**基于水位列的追加**(`column > watermark`)，**未见 upsert/merge 主键去重更新模式**；ADS/DWS 侧 sink 有 merge(`blocks.config.tsx:94 mode:'append'/overwrite/merge`)但属加工层 sink，非采集层增量 upsert。

**优先级 P2** | **落地包建议:** 在 ingestion sync config 增加 `incrementalStrategy: append|upsert`，upsert 走目标表主键 merge；前端 `SYNC_MODE_LABELS` 拆出"增量追加/增量更新"。

### 6) 图形化加工（输入/输出/查询/转换/去重/合并/拆分/过滤/连接/统计/排序/批量加载/脚本/组件） — 🟡 partial

**缺口（实地确认）:** 协议明列的细粒度可视算子**未以独立节点实现**。
- 现有 `transform` 节点是**单一 SQL/脚本编辑器**(`blocks.config.tsx:77 {language:'sql',code:''}`、`TransformNode.tsx` 按换行计行数)，**没有**去重/合并(union)/拆分/过滤/连接(join)/统计(aggregate)/排序(sort)/批量加载 等独立拖拽算子；`grep dedup/union/split/join/aggregate/sort` 在 transform 节点目录无命中。

**优先级 P1** | **落地包建议:** 扩展 `blocks.config.tsx` transform 子类(dedup/join/union/split/filter/aggregate/sort/bulk-load)为独立 BlockDef + 对应表单(`panel/forms`)，由 `ModelGenerationService` 生成对应 SQL，保持可视化拖拽即可生成口径。
