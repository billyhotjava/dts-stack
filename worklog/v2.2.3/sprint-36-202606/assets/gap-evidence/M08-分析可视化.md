### 3-2) 节点编程 —— 事件(高亮/选中) / 动作(钻取/联动/跳转) / 逻辑(触发器/转换器/定时器) / 弹层 / 组件显隐 / 页面切换 —— 🟡 partial

**协议要求**：完整节点编程能力（事件、动作、逻辑、弹层、组件显隐、页面切换）。

**当前代码证据（已具备的部分）**：
- 动作模型：`.../pages/screens/types.ts` `ScreenActionType = set-variable | drill-down | drill-up | drill-view | jump-url | open-panel | emit-intent`；`ScreenComponentAction`。
  - **钻取**：`drill-down/drill-up/drill-view`，`DrillDownConfig/DrillLevel`，hooks `useDrillDown.ts`/`useDrillView.ts`。
  - **联动**：`ComponentInteractionConfig`（enabled + mappings → 全局变量），`.../components/propertyPanel/BehaviorConfigSection.tsx`「启用点击联动」，运行时 `.../renderers/InteractionLayer.tsx`、`renderers/shared/actionUtils.ts`。
  - **跳转**：`jump-url`（jumpUrlTemplate / jumpOpenMode self|new-tab），screen-ref 解析 `InteractionLayer.parseScreenReferenceUrl`，`.../components/propertyPanel/ScreenJumpPicker.tsx`。
  - **弹层**：`open-panel`（panelTitle/panelBodyTemplate），运行时 `.../components/RuntimeActionPanel.tsx` + `ScreenRuntimeContext.tsx`。
  - **页面切换**：多页模型 `ScreenPage[]` + `PageManagerPanel`（设计期切页），轮播 `useScreenCarousel.ts`（运行期自动切页）。
- 运行时事件总线：`ScreenRuntimeContext.tsx` `RuntimeEventKind = variable|filter|interaction|drill-down|drill-up|jump|action|panel|intent`。

**缺什么（gap 部分）**：
- **逻辑「触发器/转换器/定时器」三件套**：仍未实现为可视化节点编程能力。全仓 grep `触发器/转换器/定时器/trigger/converter/timer` 仅命中 ECharts tooltip.trigger、JS setTimeout/setInterval（轮播/采集/心跳）、mapping.transform（raw/string/number/lowercase/uppercase 取值转换，非通用转换器）。无「定时触发动作」「条件触发器」「数据转换器节点」。
- **事件「高亮/选中」**：无可配置的「高亮/选中」事件节点（grep `highlight/高亮/emphasis/选中` 在 InteractionLayer/RuntimeContext/BehaviorConfigSection 均无命中）；当前事件入口实质只有「点击→联动/动作」，ECharts 原生 hover 高亮非节点编程级可配置事件。
- **动作「组件显隐」**：`ScreenActionType` 不含 toggle-visibility；`deviceMode.isVisibleForDevice` 只按设备静态显隐，运行时无「点击→显示/隐藏目标组件」动作。
- **动作「页面切换」作为交互动作**：切页存在于设计期/轮播，但未作为 `ScreenActionType` 中的运行时交互动作（如「点击图元→跳到第 N 页」）。

**优先级**：P1（业务价值高且明确，大屏交互编程是协议显式列项，但非合规硬约束）。

**落地包建议**：
1. 扩展 `ScreenActionType` 增加 `toggle-visibility`（目标组件 id + show/hide/toggle）、`switch-page`（目标页 index/id），在 BehaviorConfigSection 增配置项、InteractionLayer/ScreenRuntimeContext 增运行时处理。
2. 新增「逻辑节点」：定时器（间隔/cron 触发动作）、触发器（变量/数据条件满足→触发动作链）、转换器（数据流字段映射/计算节点），落在 interactionGraph 之上做一个轻量节点编程编排层，复用现有 event bus。
3. 事件层补「高亮/选中」可配置事件（映射到 ECharts dispatchAction highlight/select + 自定义 emphasis 状态），与现有 click 事件并列。

**协议要求**：大屏 / PC / 电视多终端自适应。

- 设备模式：`.../pages/screens/deviceMode.ts` `DeviceMode = 'pc' | 'tablet' | 'mobile'`，`resolveDeviceModeByviewport`（<=768 mobile / <=1200 tablet / else pc），`isVisibleForDevice`（组件按 `config.visibleOn` 设备显隐），URL `?device=` 强制；切换器 `.../components/DeviceModeSwitcher.tsx`（自动/PC/平板/手机）。
- 大屏自适应缩放：`.../renderers/ScaleAdapter.tsx`、`runtimeScale.ts`、`runtimeCanvasStyle.ts`、`PreviewScaleControl`，模板含 4K(3840×2160)/720p/1080p，天然适配大屏与 TV 墙等比缩放。
- 响应式属性：propertyPanel `PropertyPanel.responsive-source.test.ts`、`hooks/useContainerFontSize.ts`。

**缺什么**：
- 「大屏/PC/电视」三态语义未与代码完全对齐：代码用 pc/tablet/mobile 三态，**无独立 TV 设备模式**。TV 墙目前靠等比缩放（大分辨率模板）覆盖，但缺 TV 专属布局/字号/安全区/遥控焦点导航等适配。
- 前序「sprint-12 BI 大屏响应式（多终端规划中）」未见在 sprint-32~35 进一步落地为 TV 专项。

**优先级**：P2（大屏/PC 已自适应，TV 可由大屏缩放近似覆盖，专属 TV 终端为可延后增强）。

**落地包建议**：在 `DeviceMode` 增 `tv` 模式（含安全区/大字号 token/遥控焦点序），或在文档层明确「电视=大屏等比缩放」收敛口径并补 TV 分辨率预设模板与焦点导航。

### 6) 报表格式 EXCEL/PDF/WORD + 自建报表/仪表盘/驾驶舱 —— 🟡 partial

**协议要求**：报表导出 EXCEL/PDF/WORD；支持自建报表、仪表盘、驾驶舱。

**当前代码证据（已具备）**：
- **EXCEL**：`dts-analytics/.../service/QueryExportService.java`（CSV/EXCEL(SXSSF xlsx)/JSON），卡片导出 `CardResource.java` `/{cardId}/query/xlsx`；`dts-platform/.../governance/QualityReportExportService.java` `exportExcel(...)`（POI）。
- **PDF**：大屏导出 `ScreenExportPage.tsx`（png/pdf/json），服务端 `dts-analytics/.../service/ScreenServerRenderExportService.java`（Apache PDFBox `PDDocument`），`ScreenResource.java` `/{id}/export-prepare`、`/{id}/export-report`、`/{id}/export-render`。
- **自建报表**：`dts-analytics/.../web/rest/ReportFactoryResource.java`（templates CRUD + runs + `POST /generate` + `GET /runs/{id}/export`），服务 `ReportFactoryService.java`。
- **仪表盘**：`DashboardResource.java`（含 `POST /{dashboardId}/copy`），前端 `.../analytics/pages/dashboard/`。
- **驾驶舱**：`ProjectCockpitResource.java`，前端 `.../analytics/pages/project-cockpit/`（ProjectCockpitPage/Layout/Context/views）。

**缺什么（gap 部分）**：
- **WORD/docx 导出仍未实现**。全仓 grep `XWPFDocument/poi-ooxml/exportToWord/exportDocx/.docx 导出` 在导出链路零命中；`docx` 仅出现在上传附件签名校验 `AttachmentSignatureValidator.java`（识别上传文件类型，非导出）。
- 注：前序称「QualityReportExportService Excel/PDF 有」——当前该类**只有 `exportExcel`，无 PDF 方法**；PDF 能力落在大屏 ScreenServerRenderExportService（PDFBox），质量报表本身仍只 Excel。
- 自建报表 `ReportFactoryService.exportRun` 当前只产出 **html/markdown**，未对接 Excel/PDF/Word 二进制导出。

**优先级**：P1（WORD 是协议显式列举的报表格式硬要求，且自建报表导出格式偏弱）。

**落地包建议**：
1. 引入 `poi-ooxml`(XWPFDocument) 为 QualityReportExportService、ReportFactoryService 增 Word 导出；统一一个 `ReportExportService`（format=excel|pdf|word）。
2. ReportFactoryService.exportRun 由 html/markdown 扩展到 excel(POI)/pdf(PDFBox 或 html→pdf)/word(POI)。
3. 质量报表补 PDF（复用 PDFBox/HTML→PDF），与大屏 PDF 统一渲染管线。

## 4 月以来（sprint-32~35）被闭合的前序缺口

经核验，前序识别的三大缺口（节点编程触发器/转换器/定时器、报表 Word 导出、TV 多终端适配）**在 sprint-32~35 均未闭合**：
- sprint-32 / sprint-35：dts-metrics React Flow 指标工作台（指标语义/DSL/DWS-ADS 建模），**强化了「指标管理」子项**，但不涉及大屏节点编程 / Word / TV。
- sprint-34：审计目录 DB 化，含 analytics 大屏/语义/报表「人工操作 actionCode」收敛（`ScreenAuditService`、`AnalyticsAuditForwarderService`），属审计治理，非可视化功能闭合。
- sprint-33：角色管理重构，与本模块无关。

**结论：本模块 4 月以来无前序 gap 被闭合；唯指标侧覆盖度因 React Flow 工作台而进一步增强（原已 covered）。**
