# T01: 采集源健康与待核验队列契约

**优先级**: P0
**状态**: READY
**依赖**: F1/T02（导入返回体扩展，避免运营台消费两套结构）

## 目标

提供两个查询接口，让运营台能回答"血缘从哪来、还有多少没核验"，且不引入新表。

## 技术设计 (Contract-first)

### 接口一：采集源健康

`GET /api/catalog/lineage/sources/health`

响应：

```jsonc
{
  "sources": [
    {
      "source": "ADDAX",            // ADDAX | DBT | AIRFLOW | AUTO_VIEW | MANUAL
      "edgeCount": 1204,            // valid_to is null 的边数
      "jobCount": 87,               // catalog_lineage_job 中该 engine/relationType 的作业数
      "lastObservedAt": "2026-08-11T06:12:00Z",  // max(last_observed_at)
      "status": "ACTIVE"            // ACTIVE | STALE | NOT_CONFIGURED
    }
  ],
  "totalActiveEdges": 1564,
  "generatedAt": "2026-08-11T08:00:00Z"
}
```

状态判定：

| 条件 | status |
|---|---|
| `edgeCount == 0 && jobCount == 0` | `NOT_CONFIGURED` |
| `lastObservedAt` 早于阈值（可配置 `dts.catalog.lineage.stale-hours`，默认 168） | `STALE` |
| 其余 | `ACTIVE` |

实现：两条聚合查询（按 `relation_type` group by 边表、按 `engine`/`relation_type` group by `catalog_lineage_job`），**不逐源查询**，避免 N+1。`MANUAL` 也纳入统计（人工登记也是一路来源）。

### 接口二：待核验队列

`GET /api/catalog/lineage/pending-verification?page=0&size=10&relationType=&status=`

| 参数 | 类型 | 说明 |
|---|---|---|
| `page`/`size` | int | 遵循平台既有分页约定；`size` 上限 100 |
| `relationType` | string? | 可选过滤 |
| `status` | string? | 可选，缺省同时含 `DECLARED` 与 `KNOWN_UNVERIFIED` |

响应：

```jsonc
{
  "content": [ /* edge DTO，与 toEdgeDto 同形 */ ],
  "page": 0, "size": 10, "total": 135,
  "statusCounts": { "DECLARED": 128, "KNOWN_UNVERIFIED": 7 }
}
```

**鉴权**：结果必须逐边过 `accessChecker.canRead + departmentAllowed`（两端数据集），不可见边剔除。为避免"分页后过滤导致页大小不稳"，采用**先按部门条件下推到 SQL、再分页**；若下推不可行，则在 Repository 层按可见数据集 ID 集合过滤后分页（该集合由既有鉴权组件提供）。

> 该点是本 Task 唯一的实现风险：若既有 `accessChecker` 无法提供"可见数据集 ID 集合"，改为查询后过滤 + 返回 `filtered: true` 标记，并在文档中如实说明 total 为过滤前值。实施时先确认，结论追加到账本。

### 接口三：Addax 同步返回体扩展

`POST /api/catalog/lineage/sync-addax` 的 `LineageWriteResult` 增加：

```java
List<UnmatchedItem> unmatched;   // {sourceKey, odsSchema, odsTable, reason}，上限 200
boolean truncated;
```

与 F1/T02 的 dbt 导入返回体保持**同构字段名**（`unmatched` / `truncated`），使运营台用同一个组件渲染两路结果。

### 错误路径

| 场景 | 行为 |
|---|---|
| 无任何血缘数据 | 健康接口返回全 `NOT_CONFIGURED`，不报错 |
| `size > 100` | 截断为 100，不报错 |
| 无 `CATALOG_MAINTAINERS` | 待核验队列返回 403（该队列是治理动作入口） |

### 复用点

- edge DTO 复用 `toEdgeDto`（账本#4 同文件），不新定义结构。
- 分页响应形状复用平台既有 `{content,page,size,total}` 约定。
- 不新增表、不加迁移。
