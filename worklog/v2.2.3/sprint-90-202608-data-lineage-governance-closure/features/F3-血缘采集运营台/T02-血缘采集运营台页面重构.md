# T02: 血缘采集运营台页面重构

**优先级**: P0
**状态**: DRAFT（阻塞于 G0 的 B1；AIRFLOW 卡片形态待开放问题 Q2 实测）
**依赖**: T01（健康/待核验契约）、F1/T02（dbt 导入分桶）、F2/T02（核验契约，供「去核验」链路成立）

## 目标

把 `LineageImportPage.tsx`（55 行、两个按钮）重构为运营台，使用户能自助判断"血缘为什么是空的"。

## 技术设计 (Contract-first)

### 输入契约（消费）

| 数据 | 契约 | 来源 |
|---|---|---|
| 采集源健康 | `GET /catalog/lineage/sources/health` | T01 |
| 待核验计数与队列 | `GET /catalog/lineage/pending-verification` | T01 |
| 血缘缺口 | `GET /catalog/assets-v2/lineage-failures` | 账本#13（前端首次消费） |
| Addax 同步结果 | `POST /catalog/lineage/sync-addax` | T01 扩展后 |
| dbt 导入结果 | `POST /catalog/lineage/import-dbt-manifest` | F1/T02 扩展后 |

### 输出契约（前端状态）

- 页面级状态：`health`、`pending`、`failures` 三份独立请求，**各自独立 loading/error**，一个失败不影响其余卡片（四态要求）。
- 「最近一次导入结果」为会话内内存态（`useState`），刷新即清空，UI 文案明确标注"仅本次会话"。**不落库**（无需求、不加表）。

### 组件拆分

`LineageImportPage.tsx` 现 55 行，重构后拆为：

```
pages/catalog/lineage/
  LineageOpsPage.tsx              // 装配，目标 ≤ 180 行
  ops/SourceHealthCard.tsx
  ops/PendingVerificationCard.tsx
  ops/LineageGapCard.tsx
  ops/ImportResultCard.tsx        // 同一组件渲染 Addax / dbt 两路结果（字段同构，见 T01）
  ops/UnmatchedTable.tsx
```

`LineagePage.tsx`（分发器，账本#3）的 `section === "import"` 分支改指向 `LineageOpsPage`。路由 `/catalog/lineage/import` 不变。

### 菜单文案

`dts-admin/src/main/resources/config/data/portal-menu-seed.json` 中 `lineage-import` 节点的 `title` 由「血缘导入」改为「采集与核验」，`titleKey` 同步更新对应 i18n 文案。**`key`、`path`、`externalLink` 一律不改**（账本#1：`role-menu-defaults.json` 按 route 授权，改 route 会导致角色授权失配）。

### 跳转契约

「去核验 →」跳转 `/catalog/lineage/impact?verification=KNOWN_UNVERIFIED`。该参数由 F4/T02 的统一 URL 协议解析并注入影响分析的筛选。

> **依赖顺序注意**：若 F4/T02 未完成，本 Task 的跳转会带上一个无人消费的参数。处置：本 Task 先实现跳转 + 影响分析页对 `verification` 参数的最小消费（仅前端过滤 `edges`），F4/T02 时并入统一协议。该最小消费需在 F4/T02 中删除，避免留下两套解析。

### 错误路径

| 场景 | UI |
|---|---|
| 健康接口 500 | 卡片内 Alert + 「重试」，其余卡片正常 |
| `lineage-failures` 403 | 卡片显示「无权限查看血缘缺口」，不报错弹窗 |
| 同步/导入失败 | 结果区显示错误摘要，**保留上一次成功结果**，不清空 |
| manifest 非法 JSON | 400 → 结果区显示「manifest 解析失败」+ 后端 message |

## UI 交互规格

线框、四态、走查见 F3 README。补充实现约束：

- 卡片使用既有 `MetricTile` / `CompactTable` 等已有组件，**不引入新依赖**（NFR 预算）。
- 状态徽标不单靠颜色：`ACTIVE`/`STALE`/`未接入` 均带文字。
- 未匹配明细表遵循分页统一约定（默认 10 条/页、切换条数刷新）。
- AIRFLOW 未接入时展示只读说明（接收端路径 `POST /api/internal/lineage/openlineage`、需 `CATALOG_MAINTAINERS`），**不提供配置表单**（非目标）。

### UI 走查（B1 关闭后执行）

1. 进入 数据治理 > 血缘与影响分析 > 采集与核验 → 四路采集源卡片渲染（**成功态**）
2. 断网/mock 500 → 健康卡片 Alert，其余卡片正常（**错误态**）
3. 全新库 → 四路全 `NOT_CONFIGURED` + 引导文案（**空态**）
4. 点「导入 ⬆」→ 上传 manifest → loading（**加载态**）→ 结果区分桶 + 未匹配明细
5. 未匹配明细可搜索、可翻页，条数与后端 `skippedReasons` 一致
6. 点「去核验 →」→ 跳影响分析且筛选生效
7. AIRFLOW 卡片按 Q2 实测结论呈现（有数据则 ACTIVE，无则「未接入」+ 只读说明）
