# Sprint-25: 数据接入 / 数据开发 / 数据治理 / 语义指标 / 血缘能力收敛

**时间**: 2026-05
**状态**: DONE
**类型**: IA / UX / Platform Architecture
**目标**: 收敛 DTS 现有数据接入、数据开发、数据治理、语义指标和血缘能力边界，减少功能堆叠和菜单发散，让客户能按角色和工作流找到正确入口。

## 背景

Sprint-19 到 Sprint-24 已经连续补齐了企业数据连接器、数据资产、血缘、dbt、指标语义建模、大屏可视化等能力。但近期 review 发现产品信息架构开始发散：

1. **功能入口重复**: 指标能力同时出现在数据治理中心、数据开发中心和语义建模页。
2. **页面承载过重**: 语义建模页、血缘分析页出现列表、画布、表单、预览、审核、导入、导出、运行等能力堆叠。
3. **角色边界不清**: 数据工程师负责 ELT/dbt/SQL，业务人员负责指标配置和可视化消费，两类角色的页面混在一起。
4. **血缘定位模糊**: 血缘既在资产详情、血缘页、语义模型发布、开发任务中出现，但缺少统一横向能力定位。
5. **中心职责不稳**: 数据接入中心、数据开发中心、数据治理中心、语义与指标中心的范围需要固定，后续迭代才不会继续扩散。

本 Sprint 先做产品架构和前端 IA 收敛，再做必要的页面拆分和路由整理。暂不追求新增大功能。

## 总体口径

### 四个中心职责

| 中心 | 核心职责 | 不负责 |
|------|----------|--------|
| 数据接入中心 | 数据源、连接器、驱动、采集、ODS、元数据采集、接入变更 | 指标定义、DWS/ADS 设计、BI Dataset |
| 数据开发中心 | SQL/dbt、ODS/DWD/DWS/ADS 工程加工、脚本开发、任务编排、调度运行 | 业务人员指标配置、指标市场、业务口径审批 |
| 数据治理中心 | 主题域、术语、数据元、码表、质量、分级分类、责任人、权限治理 | 独立指标中心、dbt 模型开发、BI 可视化 |
| 语义与指标中心 | 指标工作台、指标字典、业务对象、Join、指标配置、DWS/ADS 数据集、审核发布、指标血缘 | 接入任务、复杂 SQL 开发、完整血缘导入运维 |

### 指标可视化口径

- 默认链路: `DWD -> 业务对象 / Join / 指标语义建模 -> DWS/ADS -> BI / 大屏 / API`
- 兼容链路: 数据工程师已完成 `DWS/ADS` 时，业务人员可直接基于 `DWS/ADS` 配置指标和可视化数据集。
- 禁止链路: 不让业务人员在 BI 里随意 Join 多张 ODS/DWD 表来定义核心业务口径。

`DWD` 是语义建模主要输入层；`DWS/ADS` 是可视化消费层；BI 只负责图表、筛选、钻取和展示。

### ELT 与业务指标边界

- 数据工程师: ODS/DWD 清洗、复杂 SQL、dbt 模型、性能优化、调度发布、复杂 DWS/ADS 建模。
- 业务人员: 选择业务对象、拖拽维度、配置指标公式、定义预警、查看口径、提交审核、发布 BI Dataset。
- 工程师高级模式可以查看/修改生成 SQL/dbt，但这不是业务人员主流程。

### 页面约束

每个页面只承载 1-2 个主要功能。若同一页面同时出现列表、表单、画布、SQL、预览、审核、运行、血缘、导入、导出，应拆分。

## 血缘定位

血缘是平台级横向能力，不是单独业务中心。

| 场景 | 使用血缘的目的 |
|------|----------------|
| 数据接入中心 | 看数据从数据源、采集任务到 ODS 的来源链路 |
| 数据开发中心 | 看 ODS/DWD/DWS/ADS、dbt、SQL、调度任务的加工链路 |
| 数据治理中心 | 看治理变更影响的资产、权限、质量规则、责任人范围 |
| 语义与指标中心 | 看指标从 DWD/DWS/ADS 到 BI Dataset/API/大屏的消费链路 |
| 资产门户 | 提供全局血缘与影响分析工作台 |

全局血缘入口建议命名为 **血缘与影响分析**，保留在资产门户；各中心只展示上下文血缘，不重复承载完整血缘工作台。

## 非目标

- 不新增友商对标功能，如指标市场、AI 问答、指标消费统计、归因分析。
- 不重写后端血缘存储模型，除非页面拆分暴露明确 API 缺口。
- 不让业务人员直接编辑复杂 SQL。
- 不把完整血缘工作台塞进语义指标中心。
- 不删除旧兼容路由，避免已有链接失效；但菜单主入口要切换到新 IA。

## 验收标准

- 数据接入中心、数据开发中心、数据治理中心、语义与指标中心的菜单边界清晰，无重复指标主入口。
- `语义与指标中心` 是指标相关唯一主入口，和 `数据开发中心` 同级。
- `数据治理中心` 不再出现独立指标中心入口，只保留治理主题域、术语、数据元、码表、质量、分级分类等能力。
- `血缘与影响分析` 是全局血缘入口；语义指标、资产详情、开发任务只展示上下文血缘。
- 语义指标页面拆分后，每个页面只保留 1-2 个主要任务。
- `pnpm build` 通过；菜单 JSON 可解析；核心路由可访问。

## 风险与缓解

- **旧入口兼容风险**: 保留 `/governance/indicators/dictionary`、`/modeling/semantic-center` 等旧路由，菜单切换到新路径。
- **页面拆分导致状态丢失**: 拆分时复用 API 和 URL 参数承载上下文，避免只靠 React 本地状态。
- **血缘页拆分影响导入导出**: 先拆前端页面，不改后端 API；导入、图谱、字段血缘、diff 分别落页。
- **业务人员和工程师入口混淆**: 页面文案和菜单命名固定角色边界，工程师能力放数据开发中心，业务指标能力放语义与指标中心。
