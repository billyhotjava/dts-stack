# T01：建立计划执行绑定、范围快照与运行用途契约

**优先级**：P0
**状态**：DRAFT
**依赖**：F4/T02、F2/T04

## 目标

消费 F4/T02 原子发布已创建的 `PlanExecutionBinding`，补齐调度部署和
OPERATIONAL_RUN 契约；不重复创建 binding owner/table，也不回写发布资产。

## 技术设计（Contract-first）

- **持久化 owner**：binding/entry 基表、唯一身份、MANUAL_ONLY 初始 scope 由 F4/T02
  唯一拥有；本 Task 只做 additive runtime migration 与服务。
- **唯一身份**：复用
  `(tenant_id,plan_id,environment,execution_target_key)`；P0 不建 `schedule_key`。
- **单目标边界**：`executionTargetKey` 只能由服务端解析为当前唯一安全 target；其他值返回 `MODEL_EXECUTION_TARGET_UNAVAILABLE`。
- **binding 字段**：version、scheduleMode=`MANUAL_ONLY|CRON_ENABLED`、cron/timezone、desiredScopeChecksum、desiredDeploymentChecksum、dagId、deploymentStatus、deployedChecksum、lastDeploymentAt、lastErrorCode。
- **scope 表**：复用 F4/T02 的
  `modeling_plan_execution_binding_entry`，只补齐运行所需的 immutable checksum 字段，
  不新建平行表。
- **scope 规则**：每次 Candidate 发布/回滚都从 plan+environment+target 的全部 current PUBLISHED 模型重建；不能只保存最近 candidate/release。
- **状态**：`DEPLOYING→ACTIVE`；desired/effective 漂移→STALE；人工停用→DISABLED；部署失败→FAILED。Airflow unavailable 时实际调度状态是 UNKNOWN，不伪装 ACTIVE。
- **运行用途**：`modeling_pipeline_run.run_purpose=RELEASE_BUILD|OPERATIONAL_RUN`；后者包含 bindingId、bindingVersion、triggerType=`MANUAL|CRON`。
- **XOR/CHECK**：RELEASE_BUILD 必须关联 Candidate；OPERATIONAL_RUN 必须关联 execution binding/scope checksum；旧行只能回填 `UNKNOWN_LEGACY` 且不能满足新门禁。
- **并发约束**：同 binding 同时最多一个 active OPERATIONAL_RUN；相同 `(binding_id,airflow_dag_run_id)` 唯一。
- **事务边界**：mandatory local publication 与默认
  `MANUAL_ONLY + DEPLOYING` binding/scope 已由 F4/T02 同事务完成；本 Task 只在提交后
  异步部署 DAG 和创建生产运行。
- **调度真值**：binding 保存 desired schedule 和部署证据，不保存权威 nextRun，不运行本地 CRON。
- **上线投影**：READY 必须同时满足 current publication、binding ACTIVE、Airflow deployed checksum current、relation healthy。
- **安全**：CAS、Idempotency-Key、tenant/plan 权限、cron parser、IANA timezone、审计分类；PROD schedule enable/disable 只允许 F4 domain duty resolver 判定的 RELEASE_OPERATOR，客户端 role 无效；Sprint-36/F3 policy 不可用、缺失、过期或本地接入未完成时 production schedule fail-closed。

## 影响范围

- F4 binding 的 additive runtime Liquibase/entity/repository
- pipeline run contract/repository
- Candidate publication commit
- PostgreSQL/security tests

## 验证（RED→GREEN）

- [ ] clean upgrade/rollback 与旧 run 回填。
- [ ] binding 唯一约束、scope entry 唯一约束、CAS、跨租户测试。
- [ ] 连续发布模型 A、模型 B 后 scope 同时包含 A+B；只包含 B 的旧错误行为为 RED。
- [ ] run purpose XOR、active-run 唯一和 dagRunId 幂等测试。
- [ ] 客户端 executionTargetKey/selector/target 注入被拒；非当前 target fail-closed。
- [ ] 未发布、STALE、DISABLED、FAILED binding 均不能创建手工 OPERATIONAL_RUN。
- [ ] Publish Intent 注入 cron/timezone 被拒；独立 schedule command 幂等。
- [ ] maintainer/reviewer/auditor 不能启停 PROD schedule；operator 越权/跨租户/客户端 role 注入被拒。

## Definition of Done

- [ ] 调度配置不污染 ModelSpec/Implementation revision。
- [ ] pipeline run 是业务运行唯一真值，Airflow 是调度唯一真值。
- [ ] binding scope 不因单模型增量发布丢失已有已发布模型。
- [ ] PUBLISHED 与 onlineReadiness READY 明确分离。
- [ ] 每个状态有稳定错误码、owner 和 repair action。
- [ ] schema/history 证明 F4 与 F7 没有重复 binding migration 或 repository owner。
