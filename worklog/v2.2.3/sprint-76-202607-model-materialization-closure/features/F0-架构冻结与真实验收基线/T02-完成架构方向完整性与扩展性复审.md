# T02：完成架构方向完整性与扩展性复审

**优先级**：P0
**状态**：DONE（2026-07-27；DEV/TEST 实施 GO，PROD NO-GO）
**依赖**：T01（消费真实基线）

## 目标

对快捷入口 owner、状态机、dbt/Airflow 双图边界、运行可靠性、relation probe、上线后计划执行、adapter 扩展和回滚边界给出 GO/REVISE/NO-GO，避免实施中出现第二套控制面。

## 技术设计（Contract-first）

- **输入契约**：Sprint README ADR/契约链、Context Ledger、domain profile、NFR、baseline。
- **输出契约**：`assets/architecture-review-agenda.md` 追加结论、接受 ADR、修改项、Feature/Task 调整和 READY 前置。
- **生产门槛输出**：`assets/production-readiness-gates.md` 对 PG-01 凭据、PG-02 单一 DAG runtime、PG-03 权限职责逐项给出事实、决策、PASS 证据和阻断范围。
- **必须回答**：
  1. 复核已接受的 ReleaseCandidate 决策：唯一 START_BUILD owner、无状态 Build Intent、SINGLE/BATCH 严格隔离和 active claim；
  2. Publish Intent 是否只记录发布请求并推进 RUN_QUALITY→SUBMIT_REVIEW，在人工边界停止；
  3. artifact overlay 是否优于持久化 SQL model 投影，source/ref graph 是否准确；
  4. 一 candidate 一 Airflow run、多 entry 多 pipeline run 是否合理；
  5. dbt dependency graph 与 RELEASE_BUILD/OPERATIONAL Airflow DAG 是否职责清晰且共用任务模板；
  6. relation probe 在 runtime target context 还是 platform JDBC 执行；
  7. Candidate 是否是唯一审核/批准/发布 owner，旧 lifecycle routes 是否只兼容委托；
  8. mandatory local publication 是否全有或全无，external sync failure 是否只降级健康；
  9. PUBLISHED、binding ACTIVE、relation healthy 是否形成准确 onlineReadiness，而非混成一个状态；
  10. PUBLISHED 后 MANUAL_ONLY binding 是否聚合全部 current PUBLISHED scope；独立 CRON command 是否只修改 Airflow 同一 DAG；
  11. 手工先落 run、CRON 首任务 open run 的顺序是否消除外部孤儿；
  12. 单 target/secret backend/atomic DAG deployment 是否达到生产门禁；
  13. MySQL/达梦扩展是否只需新增 inspector/compiler capability 和安全 target resolver；
  14. 回滚不自动 DROP、但使 execution binding STALE 并 pause Airflow DAG 是否满足安全边界。
  15. profile lease 是否只落宿主机 tmpfs，且 Airflow 只能用固定根目录 + UUID leaseId 挂载；
  16. RELEASE_BUILD 与 plan DAG 是否只 import 一个 Airflow Python task factory，而不是复制 Java/Bash 模板；
  17. Airflow internal callback 是否使用 pairwise service token、principal/path allowlist，失败是否真实传播；
  18. Candidate domain duty role 与 Sprint-36/F3 资产动作矩阵是否都完成，未完成时 PROD 是否硬阻断。
- **错误路径**：任一关键层为 TBD、证据 owner 冲突或无法 fail-closed，则结论不得为 GO。
