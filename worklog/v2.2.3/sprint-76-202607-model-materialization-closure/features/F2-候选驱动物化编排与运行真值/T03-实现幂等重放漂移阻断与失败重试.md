# T03：实现幂等重放、漂移阻断与失败重试

**优先级**：P0
**状态**：IN_PROGRESS
**依赖**：T02

## 目标

保证重复点击、网络重试、并发提交、revision 漂移和构建失败都不会产生重复关系、错版本证据或不可恢复 candidate。

## 技术设计（Contract-first）

- **幂等输入**：candidateId + candidateVersion + Idempotency-Key。
- **重放输出**：返回首次 CommandResult 和同一 current run 引用，不重复 prepare/submit。
- **漂移判定**：candidate entry 的 model、implementation、artifact、dependency snapshot 或 execution target 任一变化 → candidate STALE；旧 run/observation 不可发布。
- **retry**：既有 `/retry` 只从 candidate BUILD_FAILED 在原 candidate 创建新 attempt；current pipeline run 为 UNKNOWN 时必须先对账，确认失败并迁移 candidate 后才可 retry；确定性 dagRunId 的 attempt 递增，保留全部旧 pipeline run。
- **replacement**：STALE 不允许 retry；同一事务先锁定并校验旧 claim owner，再释放旧 claim、写入新 snapshot/claim，提交前由唯一约束兜底，不存在已提交的无保护窗口。
- **cancel**：新增 `CANCEL_CANDIDATE`，仅允许 DRAFT/BUILD_FAILED/QUALITY_FAILED；迁移到 CANCELLED、释放 claim、登记 actor/reason/idempotency，不删除 relation/run/observation。
- **并发**：entry `active_claim_key` 数据库唯一约束 + candidate CAS + command ledger 三重保护。
- **部分失败**：candidate build 任一物理 entry 失败则 candidate BUILD_FAILED；retry 默认重建完整 selector，避免依赖图部分状态不可重现。
- **错误路径**：stale retry 必须先 replacement；PUBLISHED 不允许重新 START_BUILD，返回 OPERATIONAL_RUN repair action；BATCH/SINGLE 冲突不允许自动合并。

## 当前实现证据（2026-07-28）

- `/retry` 已进入与 `START_BUILD` 相同的事务边界；重放只读取既有运行，新请求锁定最新 dispatch 并在原 Candidate 上生成 `attempt + 1` 的 QUEUED pipeline rows 与 PENDING dispatch。
- 最新 dispatch 为 `UNKNOWN/PENDING/SUBMITTED/RUNNING` 时返回稳定错误 `MODEL_MATERIALIZATION_RETRY_RECONCILIATION_REQUIRED`；事务回滚 Candidate 的 BUILDING 迁移。
- retry 在 canonical Candidate 命令写入前重验 model/implementation/artifact/dependency/target 与 active claim snapshot；仓储只返回漂移原因，Candidate 用原 retry 幂等键直接写 `STALE_DETECTED`，不先提交 BUILDING，也不生成新 pipeline/dispatch。
- `CANCEL_CANDIDATE/CANCELLED` 已通过 append-only command、数据库约束和真实 PostgreSQL 用例证明：只开放于 DRAFT/BUILD_FAILED/QUALITY_FAILED，释放 active claim，保留 pipeline run、observation、relation 与不可变 snapshot，replacement 可重新取得 claim。
- 聚焦单测：`ModelMaterializationStartServiceTest` 5/5、`ModelReleaseCandidateApplicationServiceTest` 14/14。
- 真实 PostgreSQL：`ModelMaterializationStartServiceIT#retryRequiresReconciledFailureAndCreatesAttemptTwo` 1/1；`#retrySnapshotDriftTransitionsCandidateStaleWithoutAttemptTwo` 在一次容器启动内覆盖 model/implementation/artifact/dependency/target 五类漂移；`#cancellationReleasesClaimsButRetainsRunObservationSnapshotAndRelation` 已通过。
- claim transfer 使用数据库事务把旧终态 Candidate 的 claim 清空并写入 replacement DRAFT 的 claim-only reservation；START_BUILD 只接受服务端派生的同一 claim，随后补齐 current implementation/artifact/dependency/target snapshot。迁移 `20260728_03_model_release_candidate_claim_transfer.xml` 保持唯一索引为最终并发围栏。
- 同一 PostgreSQL 场景现已额外覆盖三组双线程竞争：STALE replacement 只产生一个新 DRAFT/claim/command；相同 START_BUILD/retry key 收敛为一次 durable run/attempt；不同 key 返回稳定 409 version conflict，且只保留一个 attempt 2。测试结果 1/1、0 failure、0 error。
- 测试白名单已纳入本 Task 新增的 start/application/cancel migration/resource 测试，避免 Surefire 使用旧 class 或在常规构建中静默跳过。
