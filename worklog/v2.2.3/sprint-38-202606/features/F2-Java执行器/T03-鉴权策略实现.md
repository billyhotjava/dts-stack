# T03: 鉴权策略实现

**优先级**: P0
**状态**: DONE
**依赖**: T02, F1-T02

## 目标

策略模式实现鉴权注入：**JWT 登录换 token 为 P0 主路径**（客户对接已确认），加上 bearer/apiKey/basic/OAuth2，共五种 GA；签名/mTLS 预留接口。凭据全部来自 F1-T02 的解密 secrets。

## 技术设计

- `ApiAuthStrategy` 接口：`apply(HttpRequest.Builder, ResolvedApiSource)`；按 `auth.provider` 路由。
- bearer/apiKey(header|query)/basic：迁移旧 Python `_build_headers` 语义，凭据从 `decryptedSecrets.get(secretRef)` 取（不再读 env）。
- **`JwtLoginAuthStrategy`（P0 主路径）**：`POST loginUrl`（body 按 `loginBodyTemplate` 渲染，凭据占位符从解密 secrets 填充）→ 按 `tokenPath` 取 token → 数据源粒度内存缓存。过期判定：优先 `expiresInPath` 字段；缺省 **base64 解 JWT payload 取 `exp` claim**；两者皆无则按可配置 TTL（默认 30min）。提前 60s 刷新；业务请求 401 时强制重新登录重试一次（防时钟漂移/服务端提前吊销）；登录失败归类 `API_RUNTIME_AUTH`。token/密码不落库不落日志。
- **`OAuth2ClientCredentialsStrategy`**：与 JwtLogin 同形态（标准 token endpoint + form 报文），共享 TokenCache 基类。
- 预留：`SignatureAuthStrategy`/`MtlsAuthStrategy` 接口占位抛 UNSUPPORTED，注册表保持 PREVIEW（F1-T03）。
- mTLS 的 SSLContext 注入点在 T06 一并预留。
- **待对方确认的对接参数**（见 assets/api-auth-negotiation-proposal.md）：登录端点 URL、登录报文格式、token 字段名、expiresIn 字段名、token 放置方式——拿到后填入数据源配置即可，不阻塞本任务开发（WireMock 先按通用形态测）。
