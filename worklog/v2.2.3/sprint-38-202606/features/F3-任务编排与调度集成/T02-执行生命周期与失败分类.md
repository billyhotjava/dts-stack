# T02: 执行生命周期与失败分类

**优先级**: P0
**状态**: IN_PROGRESS
**依赖**: F2-T01

## 目标

API 执行完整接入 `IngestionExecution` 生命周期：状态机、行数统计、`API_RUNTIME_*` → `ExecutionFailureClassifier` 类别映射、自动重试白名单。

## 技术设计

- 执行器在开始/结束/异常时写 IngestionExecution（status/rowsRead/rowsWritten/failureCategory/failureAdvice），多资源任务记录资源级明细（成功 n/失败 m），整体状态语义：全部成功 SUCCESS、部分失败 FAILED+明细（资源级重跑靠 checkpoint 天然支持）。
- 失败分类：`API_RUNTIME_AUTH→PERMISSION`、`RATE_LIMIT/NETWORK/SERVER→CONNECTION(可重试)`、`BLOCKED_URL/CONFIG→GOVERNANCE_LIMIT(不可重试)`、`SCHEMA/RESPONSE_TOO_LARGE→DATA_QUALITY`；接入 `IngestionRetryService` 的 retryableCategories 白名单。
- 注意：分类基于结构化错误码（执行器自产），不再依赖文本关键字匹配——比 JDBC 路径的文本分类更可靠。

## 进展

### 2026-06-12

- 新增结构化 API 运行时错误分类：鉴权归 `PERMISSION_ERROR`，限流/网络/服务端归 `CONNECTION_ERROR`，策略/配置/分页/重定向归 `GOVERNANCE_LIMIT`，响应/游标/客户端契约问题归 `DATA_QUALITY_ERROR`。
- 默认自动重试白名单移除 `GOVERNANCE_LIMIT`，避免 API SSRF/配置/策略类不可恢复失败被调度器反复重试。
- 补充 `IngestionTaskServiceTest#execute_shouldClassifyApiNetworkFailureAndScheduleRetry`：API 执行器抛 `API_RUNTIME_NETWORK` 时，执行记录写入 `failed`、`CONNECTION_ERROR`、对应 failureAdvice，并调用 `IngestionRetryService.scheduleRetryIfEligible`。
- 已跑通分类器、Airflow 同步、内部 API 执行入口与 HTTP 引擎相邻回归；执行监控页可见性仍待 UI/集成证据。
