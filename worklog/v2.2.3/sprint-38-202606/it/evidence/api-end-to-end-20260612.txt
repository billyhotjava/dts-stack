## 结论

- PASS: API 数据源 + 入湖任务 + Java API executor + raw landing + checkpoint 增量推进已跑通。
- PASS: 生成的 Airflow 瘦 DAG 已由 Airflow scheduler 真实触发，DAG task 成功，并通过内部 API 创建第三次 ingestion execution。
- PASS: 生成 DAG 使用内部 HTTP opener 禁用代理，避免 Airflow 容器 `HTTP_PROXY/HTTPS_PROXY` 干扰 `dts-ingestion`/OpenLineage 内部回调。

## 失败复现与根因

前一版 live Airflow 触发失败:

```text
airflow_run_id=s38-api-e2e-airflow-89-1781248881
airflow task addax_s38_api_it_ods_api_orders failed for run s38-api-e2e-airflow-89-1781248881
```

Airflow task 日志:

```text
File "/opt/airflow/dags/dts_api_e2e_orders.py", line 119, in _trigger_api_ingestion
  response = _call_ingestion_api("POST", "/internal/api-ingestion/executions", payload)
urllib.error.URLError: <urlopen error [Errno -2] Name or service not known>
```

Airflow 容器代理环境:

```text
HTTPS_PROXY=http://host.docker.internal:10808
NO_PROXY=
HTTP_PROXY=http://host.docker.internal:10808
```

根因: Python `urllib` 默认读取代理环境变量，内部服务回调被错误发往代理路径；容器内 `host.docker.internal` 不可解析，导致 DAG 未进入 dts-ingestion。
