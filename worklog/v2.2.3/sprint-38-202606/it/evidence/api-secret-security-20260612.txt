# Sprint-38 IT-02 API 凭据安全 live 证据

时间：2026-06-12
环境：`/opt/prod/s10/v2.2.3`，compose project `v223`

## 发现与修复

- 代码侧 API 数据源已经禁止在 `props` 中提交明文 token/password，并通过 `InfraSecretService` 写入 `secure_props`。
- live 平台容器原先未绑定 `dts.platform.infra.encryption-key` 对应 env，启动日志出现过 `dts.platform.infra.encryption-key is not configured; secret fields will not be persisted`。
- 修复：
  - `source/dts-platform/src/main/resources/config/application.yml` 增加 `dts.platform.infra.*` 绑定，优先读取 `DTS_INFRA_*`，兼容旧 `DATA_STANDARD_*`。
  - `docker-compose-app.yml` / `docker-compose.dev.yml` / `docker-compose.legacy.yml` 的 `dts-platform.environment` 增加 `DTS_INFRA_ENCRYPTION_KEY` 与 `DTS_INFRA_KEY_VERSION` 透传。

## 结论

- API 数据源通过真实平台 API 创建，`hasSecrets=true`。
- DB 仅保存 AES-GCM 密文与 IV，`secure_key_version=v1`，不是 `PLAINTEXT`。
- `props.__apiSecretMeta` 只保存 masked display / secretVersion / rotatedAt / status，不含明文。
- 用户详情接口与 analytics 脱敏详情接口均不回显明文；analytics 详情返回 `secrets={}` 与 `secretSummaries`。
- `runtime-detail` 缺服务 token/错服务 token 均拒绝；只有 `dts-ingestion` 携带有效服务 token 时能解密到运行时 secrets。
- platform 日志、Airflow DAG 文件、扫描容器 env 与 Airflow Variables 均未出现测试凭据明文。
