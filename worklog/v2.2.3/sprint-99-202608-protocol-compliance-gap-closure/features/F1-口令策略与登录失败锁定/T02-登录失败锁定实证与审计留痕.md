# T02: 登录失败锁定实证与审计留痕

**优先级**: P0
**状态**: READY
**依赖**: T01（消费其 realm 暴力破解配置）

## 目标
连续登录失败达阈值后账号被真实锁定，锁定与解锁事件在 dts-admin 审计中可检索，且提示信息不泄露账号是否存在。

## 技术设计 (Contract-first)
- **输入契约**: Keycloak 暴力破解事件（`LOGIN_ERROR` / `USER_DISABLED_BY_PERMANENT_LOCKOUT` / `USER_TEMPORARILY_DISABLED`）
- **输出契约**（审计条目）:
  | 字段 | 值 |
  |---|---|
  | `action` | `SECURITY_LOGIN_LOCKED` / `SECURITY_LOGIN_UNLOCKED` |
  | `actor` | 被锁账号（脱敏：保留前 2 位 + `***`）|
  | `clientIp` | **必须走 `IpAddressUtils.resolveClientIp`**（domain-dts D3；现场代理用 RFC 7239 `Forwarded`）|
  | `result` | `DENY` |
  | `metadata` | `{failureCount, lockoutSeconds, realm}` |
- **数据流**: Keycloak event → dts-admin 事件监听/轮询 → 审计写入。**优先复用 dts-admin 既有 Keycloak 事件消费路径**；若不存在，则用 Keycloak Admin REST 定期拉取 events（间隔可配），不新建第二套认证事件通道。
- **错误路径**: 事件拉取失败 → 记录降级日志并计数，不影响登录；连续失败 N 次上报 F4 的告警规则。
- **复用点**: 审计动作码必须在 dts-admin 审计资源字典登记（账本#16），否则落「未分类」。
- **实现方案**: 1) 确认既有事件消费点 → 2) 映射事件到审计动作 → 3) 字典登记 changelog → 4) 前端登录页统一失败文案。

## UI 交互规格
- 登录页失败提示统一为「用户名或密码错误」；达阈值后改为「账号已锁定，请 15 分钟后重试或联系管理员」。
- **不得**出现「该用户不存在」「密码错误」这类可用于账号枚举的差异化文案。

## 影响范围
- `dts-admin`：事件消费 + 审计字典 changelog
- `dts-platform-webapp`：`pages/sys/login/` 失败文案
- 审计资源字典 changelog
