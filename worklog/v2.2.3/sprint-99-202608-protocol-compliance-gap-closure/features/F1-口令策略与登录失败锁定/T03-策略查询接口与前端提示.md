# T03: 策略查询接口与前端策略提示

**优先级**: P0
**状态**: READY
**依赖**: T01（消费其 realm 策略配置）

## 目标
用户在改密时能实时看到自己还差哪一条策略未满足，而不是提交后收到一句英文报错；平台启动时若 realm 策略缺失，运维能在日志与安全基线页看到告警。

## 技术设计 (Contract-first)
- **输入契约**: Keycloak Admin REST `GET /admin/realms/{realm}` → `passwordPolicy` 字符串 + 暴力破解字段
- **输出契约** `GET /api/admin/security/password-policy`:
  ```json
  {"minLength":12,"requireUpper":true,"requireLower":true,"requireDigit":true,
   "requireSpecial":true,"notUsername":true,"historyCount":5,"expireDays":90,
   "lockoutThreshold":5,"lockoutWindowSeconds":900,"source":"KEYCLOAK_REALM"}
  ```
  - 鉴权：已登录用户可读（改密场景需要）；不返回任何密钥或 realm 内部标识
  - 缓存：进程内缓存 60s，避免每次改密都打 Admin REST
- **Service**: `KeycloakSecurityPolicyValidator`
  - 启动期执行一次：解析 `passwordPolicy` 串 → 与内置 BMB 基线期望比对
  - 不满足 → `log.warn` + 写审计 `SECURITY_POLICY_BASELINE_VIOLATION`
  - **不阻断启动**（ADR-99-05：仅 PKI 登录的现场不应因口令策略停机）
  - 产出结果供 F2 的 `BaselineAutoVerifier(SEC_BASELINE_ACCOUNT_PASSWORD)` 直接消费
- **错误路径**: Admin REST 不可达 → 接口返回 503 + 前端降级为静态兜底文案；**前端降级不得导致弱口令被放行**（最终判定权在 Keycloak）
- **复用点**: dts-admin 既有 Keycloak Admin 客户端（不新建 HTTP client）

## UI 交互规格
见 F1/README §UI/UX 规格。要点：
- 触发控件：改密弹窗的新密码输入框 `onChange`
- 调用契约：页面挂载时拉一次 `/password-policy`，之后纯本地校验
- 四态：空（中性灰）/ 加载（骨架）/ 错误（静态兜底文案）/ 成功（全 ✓ 后按钮可用）
- 历史重复项标注「提交时校验」，不做本地预判

## 影响范围
- `dts-admin`：新增 Resource + Validator + 审计动作码登记
- `dts-platform-webapp`：改密弹窗组件 + `api/services/` 新增 service 方法
- `dts-admin-webapp`：若也有改密入口，同步接入（勘察时确认，不重复实现）

## 验证 (RED→GREEN)
