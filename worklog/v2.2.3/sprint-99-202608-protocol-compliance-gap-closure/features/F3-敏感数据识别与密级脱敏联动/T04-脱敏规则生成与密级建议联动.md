# T04: 脱敏规则生成与密级建议联动

**优先级**: P0
**状态**: DRAFT
**依赖**: T03

## 目标
确认发现项后自动生成的脱敏规则在查询期真实生效；密级建议通过既有密级控制面提交，只升不降的约束不被绕过。

## 技术设计 (Contract-first)
- **脱敏侧**:
  - 输出：为每个确认项创建 `CatalogMaskingRule`（既有实体，账本#10），字段取自规则的 `suggestedMaskingStrategy`
  - 冲突：同一列已有脱敏规则 → 不覆盖，计入 `skipped`，理由 `MASKING_RULE_EXISTS`
  - 生效：不新增生效路径，沿用既有查询期脱敏（`CatalogMaskingResource` / 查询执行链）
- **密级侧**（ADR-99-03，硬性）:
  - **禁止**直接写 `classification` 字段
  - 走既有 `CatalogClassificationService` 提交密级变更；由 `CatalogClassificationPropagationService` 按 `maxDataCode` 只升不降处理（账本#4）
  - 建议密级 ≤ 当前密级 → 直接 `skipped`，理由 `CLASSIFICATION_DOWNGRADE_REJECTED`
  - 提交后的传播由既有传播作业异步完成，本 Task **不实现任何传播逻辑**
- **错误路径**: 密级服务不可用 → 该项 skipped 且理由明确，脱敏规则创建不回滚（两者解耦）
- **复用点**: `CatalogMaskingRule`、`CatalogClassificationService`、`CatalogClassificationPropagationService` —— 三者都已存在，本 Task 只做编排
- **影响分析**: 改动 `CatalogClassificationService` 调用面前**必须跑 `gitnexus_impact`**（domain-dts A1；该服务是密级控制面核心，预期 HIGH 风险，须先告警）

## UI 交互规格
- 确认弹窗明确区分两件事：
  ```
  将执行：
    ✓ 创建 12 条脱敏规则（立即在查询期生效）
    ✓ 提交 5 项密级变更建议（由密级控制面处理，只升不降）
    ⊘ 跳过 3 项（已有脱敏规则 / 建议密级低于当前密级）
  ```
- 成功后提供两个跳转：「查看脱敏规则」「查看密级变更」
- 四态：加载（提交中）/ 错误（部分失败明细）/ 成功（结果分项统计）/ 空（无可执行项时按钮禁用）

## 影响范围
- `dts-platform`：`SensitiveFindingService` 的确认编排逻辑
- 既有 `CatalogMaskingRule`、密级服务的**调用方**（不改其实现）
- `dts-platform-webapp`：确认弹窗

## 验证 (RED→GREEN)
- [ ] 端到端：确认身份证列 → 生成脱敏规则 → 用普通用户查询该表 → **返回值确实被脱敏**（这是本 Feature 的最终断言）
- [ ] 降级拒绝：建议 INTERNAL 但当前 SECRET → skipped 且理由正确
- [ ] 升密：建议 SECRET 当前 INTERNAL → 密级变更被提交，传播作业可查
- [ ] 冲突：已有脱敏规则的列 → 不覆盖
- [ ] 密级服务不可用 → 脱敏规则仍创建成功，密级项 skipped
