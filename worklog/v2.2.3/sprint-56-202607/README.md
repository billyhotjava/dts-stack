# Sprint-56: 指标工作台拖拽建模闭环

**时间**: 2026-07  
**状态**: DONE  
**目标**: 将指标工作台从“可视化关系画布”推进为可拖拽、可连线、可回写绑定关系的建模工作台。

## 背景

Sprint-54 已完成指标建模统一工作区和三栏页面，但指标画布仍主要是展示关系：节点位置由数据重算，拖动后不保留；指标与业务对象的关系只能通过后台字段体现，不能在画布中直接拖拽或连线完成绑定。

本 sprint 在现有 React Flow 画布和语义建模 API 上做最小闭环，不新增独立后端 API。指标绑定复用 `PUT /api/semantic/metrics/{id}`，并补齐前端全量更新 payload，避免后端全量更新语义下误清空字段。

## 完成标准

- [x] 画布节点可拖动，并在浏览器会话中保留位置。
- [x] 指标关系画布与属性面板改为上下工作区，减少横向挤压。
- [x] 左侧目录指标可作为拖拽源，未绑定指标有明确分组。
- [x] 拖指标目录项、拖动画布指标节点到业务对象节点，或用 React Flow 连线时，回写指标 `objectId`。
- [x] 指标更新请求保留 `code/name/formula/status` 等全量字段，符合后端全量 PUT 契约。
- [x] source-contract、helper 单测、TypeScript、生产构建和浏览器 smoke 通过。

## 决策

- 先用浏览器本地 `localStorage` 保存画布节点位置；后续如果需要多人协作或跨端同步，再补平台侧 layout API。
- 绑定关系是业务事实，必须回写后端；节点位置是个人操作偏好，暂不进入后端模型。
- 未绑定指标必须出现在左侧目录，否则用户无法通过拖拽完成首次挂载。
- React Flow `MiniMap` 在当前画布尺寸下会覆盖右下角节点并吞掉鼠标拖拽事件，本 sprint 先移除小地图，优先保证关系编辑可用。
