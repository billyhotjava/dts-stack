# T01: 补齐来源状态、差异与重确认契约

**优先级**: P0
**状态**: DRAFT
**依赖**: F2/T02

## GET 扩展

每个 binding 在现有字段上增加：

- `currentVersion`、`confirmedVersion`
- `freshness` 与 `changeImpact`
- `diffSummary {added, removed, changed}` 与结构化 `changes[]`
- `allowedActions[]`（由服务端权限与状态计算）
- `reasonCode`（稳定机器码）与业务可读摘要

列表增加向后兼容的 `page/size/totalElements/totalPages`，`size` 限制 1..200。同步更新反向建模客户端按页加载确认且 AVAILABLE 的来源，不能静默只取第一页。

## PUT 扩展

沿用既有批量保存端点，每个重确认项必须携带：

```json
{
  "bindingId": "uuid",
  "action": "RECONFIRM",
  "expectedConfirmedVersion": "old-hash",
  "expectedCurrentVersion": "new-hash"
}
```

服务端事务内重新解析 currentVersion：不一致返回 `409 WAREHOUSE_PLAN_SOURCE_VERSION_CHANGED`；相同请求重放保持幂等。成功后更新 confirmedVersion、关闭关联 drift ticket，并写审计 actor/tenant/binding/assetKey/old/new/correlationId。

## 错误与权限

- 不存在、跨租户或无目录权限：不返回字段级 diff。
- MISSING/BREAKING 不允许 RECONFIRM，除非 mapping 已修复并重新评估为可确认。
- read-only 用户 `allowedActions=[]`，PUT 返回 403。
- API 不返回 JDBC URL、凭据、token 或业务行值。
