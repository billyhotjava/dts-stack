# T02: 建立兼容与破坏性变更判定

**优先级**: P0
**状态**: IN_PROGRESS
**依赖**: F2/T01 稳定字段身份

## 输出契约

既有 `catalog_schema_drift_event.details_json` 增加版本化 payload：

```json
{
  "contractVersion": 1,
  "impactLevel": "COMPATIBLE|BREAKING|REVIEW_REQUIRED",
  "changes": [
    {"field": "amount", "kind": "TYPE_CHANGED", "before": "decimal(10,2)", "after": "decimal(18,2)", "impact": "COMPATIBLE"}
  ]
}
```

API 只返回结构化字段，不要求前端解析自由文本。comment/tags/owner/classification 变化不进入 schema fingerprint，也不生成结构 drift。

## 判定规则

| 变化 | 基础判定 | 消费覆盖 |
|---|---|---|
| add nullable | COMPATIBLE | 无 |
| add non-null/default 未知 | REVIEW_REQUIRED | 若目标执行引擎确认安全可重判 |
| remove | BREAKING | 未被任何当前 ModelSpec 引用时降为 COMPATIBLE |
| varchar/decimal 安全扩宽 | COMPATIBLE | 方言无法确定时 REVIEW_REQUIRED |
| 缩窄、类型族变化、nullable 收紧 | BREAKING | 无 |
| remove+add 疑似 rename | REVIEW_REQUIRED | 人工确认 mapping 后关闭 |

## 实现边界

- 优先扩展既有 `SchemaDriftDetector` 与 event payload；如职责明显冲突，可新增一个无持久化 owner 的 classifier service。
- 消费影响从现有 WarehousePlan source mapping / ModelSpec revision 读取，不新增引用台账。
- 判定失败默认 REVIEW_REQUIRED，不默认兼容。
- ticket 由重确认/映射修复动作关闭，并记录 actor/handledAt；不由 UI 本地状态关闭。
