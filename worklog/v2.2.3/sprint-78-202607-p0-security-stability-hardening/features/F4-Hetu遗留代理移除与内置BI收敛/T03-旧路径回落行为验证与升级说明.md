# T03：旧路径回落行为验证与升级说明

**优先级**：P0
**状态**：READY
**依赖**：T01/T02（代理移除 + 前端收敛完成）

## 目标

验证移除后的实际行为与契约一致：旧 hetu 路径不再命中代理、不出现网关错误，回落到平台 SPA；升级说明告知现场路径变更。

## 技术设计（Contract-first）

- **输入契约**：T01 后的运行栈（`docker compose -f docker-compose-app.yml up -d`）。
- **输出契约**：路径行为矩阵（每条旧路径 → 实际状态码/落点）；升级说明章节。
- **数据流**：curl/浏览器 → Traefik → 平台 UI SPA（预期 200 + SPA 引导）→ 用户被引导至 `/bi`。
- **错误路径**：某条旧路径仍 502/504 → 说明路由删除不彻底，回查 T01；SPA 404 页体验差 → 记录改进项（不阻塞本任务）。
- **复用点**：`.skills/dts-devops-runbook/scripts/dts_healthcheck.sh` 做栈健康前置；F4 契约表的路径清单即验证清单。
- **实现方案**：
  1. 启动/复用运行栈，逐条 curl F4 契约表中的旧路径与主路径（`/`、`/bi`），记录状态码与落点。
  2. 浏览器 smoke（登录基线恢复后执行；未恢复则按 GAP 记录，见 `it/baseline.md`）。
  3. release-plan 增加"旧路径变更"章节：受影响路径清单、用户告知话术、回滚方式（git revert compose/dynamic yml）。
- **禁止**：以"代理已删所以不用验"为由跳过逐路径 curl。

## 影响范围

- 证据：`it/evidence/it-06-hetu-removal/`
- `assets/release-plan.md`（路径变更章节）

- [ ] 升级说明章节完成。
