# T02：部署期证书生成与注入链路打通

**优先级**：P0
**状态**：READY
**依赖**：T01（仓库已清空私钥材料）

## 目标

tls profile 需要启用时，私钥由部署期 `services/certs` 产物经 compose 挂载与环境变量注入，现场无需从源码获取任何密钥材料。

## 技术设计（Contract-first）

- **输入契约**：`services/certs/keystore.p12`（账本#10 已有产物）；`.env` 中 `SERVER_SSL_KEY_STORE_PASSWORD`。
- **输出契约**：compose 服务在 tls profile 激活时：挂载 `services/certs` 为容器内只读路径（如 `/run/certs:ro`），注入 `SERVER_SSL_KEY_STORE=file:/run/certs/keystore.p12` 与 `SERVER_SSL_KEY_STORE_PASSWORD`。
- **数据流**：init.sh/gen-certs.sh 生成 p12 + 随机口令 → 口令写入 .env（init.sh 既有密钥写入路径，账本#11 同类机制）→ compose env/卷 → 容器。
- **错误路径**：p12 缺失或口令错误 → 服务启动失败并给出明确错误（不静默回退 HTTP）；gen-certs.sh 幂等（已存在则跳过，除非显式 `--force`）。
- **复用点**：`services/certs/gen-cert.sh` / `gen-certs.sh`（账本#10）；init.sh 既有 .env 写入与 Fernet key 生成段（账本#11 附近）。
- **实现方案**：
  1. 核对 gen-certs.sh 产物口令与 .env 的一致性（当前口令是否硬编码在脚本中——实施期以账本外一次 grep 确认并修正为写入 .env）。
  2. docker-compose-app.yml 为 dts-admin/dts-platform 增加注释化示例块（默认不激活）：tls 挂载 + env 三行，注明启用方式。
  3. init.sh 增加/确认 `SERVER_SSL_KEY_STORE_PASSWORD` 生成与写入（复用既有随机密钥生成函数）。
  4. runbook 记录启用步骤与验证命令（`assets/runbook.md`）。
- **禁止**：把 p12 复制进镜像构建上下文；在 compose 中明文写死口令。

## 影响范围

- `services/certs/gen-cert.sh` / `gen-certs.sh`（口令一致性，如需）
- `init.sh`（env 生成）
- `docker-compose-app.yml`（注释化示例块）
- `assets/runbook.md`
