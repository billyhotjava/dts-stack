# T02：审批结果一次性口令交付与前端适配

**优先级**：P0
**状态**：READY
**依赖**：T01（消费其 detail 契约与一次性口令来源）

## 目标

授权管理员在审批执行结果中一次性看到新用户初始口令并确认复制；口令不持久化、不可二次查看。

## 技术设计（Contract-first）

- **输入契约**：T01 的执行响应（内存中的一次性口令 + `initialPasswordDelivered`）。
- **输出契约**：审批执行 HTTP 响应体包含一次性口令字段（如 `initialPassword`，仅本次响应）；该字段**不得**进入审批记录 detail 持久化、列表接口、导出或审计负载。
- **数据流**：applyCreate 局部口令变量 → 执行响应装配（仅内存拼接）→ 前端弹窗 → 丢弃；后端在响应发出后丢弃明文引用。
- **错误路径**：响应装配失败不泄露部分口令；前端展示失败时提示"口令未送达，请使用重置密码流程（temporary）"——重置路径已有 temporary 支持（账本#4）。
- **复用点**：审批详情/执行结果既有渲染（账本#6 白名单机制）；dts-admin-webapp 既有弹窗与复制交互组件（勘察点：审批详情对 detail 的渲染方式，见 sprint README 开放问题）。
- **实现方案**：
  1. 后端：执行响应 DTO 增加一次性字段；序列化与持久化路径隔离（detail 白名单只保留 `initialPasswordDelivered`）。
  2. 前端：审批执行成功弹窗新增"初始口令"区块：口令明文 + 复制按钮 + "已复制，关闭后不再显示"确认；未确认前禁止关闭（ESC/遮罩点击拦截）。
  3. 文案遵循既有中文术语（frontend-product-consistency）。

## UI 交互规格

- 触发控件：审批"执行/通过"按钮（既有）。
- 四态：成功（口令区块 + 复制确认）；错误（Keycloak 失败原因，无口令）；加载（执行中骨架）；空（不适用）。
- 走查：1. 执行创建审批 → 2. 弹窗显示用户名与初始口令 → 3. 点击复制 → 4. 勾选"已复制" → 5. 关闭 → 6. 重新打开审批详情，仅见"初始口令已交付"，无明文。

## 影响范围

- `source/dts-admin`：审批执行响应装配处（applyCreate 返回链）
- `source/dts-admin-webapp`：审批执行结果弹窗组件、（如需）审批详情渲染
