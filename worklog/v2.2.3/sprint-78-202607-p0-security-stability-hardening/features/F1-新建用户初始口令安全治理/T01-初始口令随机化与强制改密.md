# T01：初始口令随机化与强制改密（后端）

**优先级**：P0
**状态**：READY
**依赖**：无

## 目标

`applyCreate` 创建用户时以 SecureRandom 生成一次性强随机初始口令，并以 `temporary=true` 写入 Keycloak；`DEFAULT_INITIAL_PASSWORD` 常量删除。

## 技术设计（Contract-first）

- **输入契约**：既有审批 applyCreate payload（不变）；无新增外部输入。
- **输出契约**：Keycloak 用户凭据 = 随机口令 + `temporary=true`；执行结果 detail 中 `initialPasswordDelivered: true`（替代 `defaultPasswordApplied`，账本#6 的脱敏白名单同步更名）。
- **数据流**：审批执行 → `AdminUserService.applyCreate`（账本#2）→ 口令生成器 → `KeycloakAdminClient.resetPassword(..., true, ...)`（账本#3）→ detail 仅记录 delivered 元数据。
- **错误路径**：Keycloak 设密失败 → 保留既有行为：创建整体失败并抛出（账本#2）；口令生成不得 swallow 异常后退化为任何常量——无 fallback。
- **复用点**：`SecureRandom` 先例（账本#5）；`resetPassword` 三实现（接口/REST/InMemory 桩，账本#3）签名不变，仅调用点改参。
- **实现方案**：
  1. 新增私有方法 `generateInitialPassword()`：SecureRandom，16 字符，字符集 `[A-Za-z0-9]` + 少量安全符号（避免 shell/URL 转义问题），拒绝弱模式。
  2. `AdminUserService.java:112` 删除 `DEFAULT_INITIAL_PASSWORD`；`:3957` 调用改为 `resetPassword(target.getId(), generateInitialPassword(), true, accessToken)`，明文仅保存在局部变量，用毕置空。
  3. detail 字段 `defaultPasswordApplied` → `initialPasswordDelivered`（账本#6 白名单同步）。
  4. `InMemoryKeycloakAdminClient`（账本#3）行为对齐：记录 temporary 标志供测试断言。
- **禁止**：口令明文写入 LOG/detail 持久化/审计明细/异常 message（security-compliance）。
