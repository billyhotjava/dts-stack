# T03：存量弱口令风险账号处置工具

**优先级**：P0
**状态**：ABANDONED（ADR-78-09，随 F1 放弃）
**依赖**：T01（新口令策略落地后，存量处置才有意义）

## 目标

提供可选、幂等、可审计的存量账号处置能力：现场可为指定范围用户批量设置 Keycloak `UPDATE_PASSWORD` required action，强制下次登录改密。

## 技术设计（Contract-first）

- **输入契约**：用户范围（显式 username 列表，或"全部非内置用户"过滤）；dry-run 标志（默认 true）。
- **输出契约**：逐用户结果 `{username, requiredActionAdded, skipped, reason}`；汇总计数；审计事件 `USER_FORCE_PASSWORD_UPDATE`（actor、范围、结果、timestamp，不含任何口令）。
- **数据流**：管理端运维入口 → 列举用户（排除内置三员/opadmin 等服务账号，账本#1 的 `HIDDEN_USERNAMES_IN_USERLIST` 集合可复用排除口径）→ 逐用户调用 Keycloak required actions → 审计。
- **错误路径**：单用户失败不中断批次，记录 reason；dry-run 只报告不修改；重复执行幂等（已含该 action 者 skipped）。
- **复用点**：`KeycloakAdminClient` 既有用户更新能力；`AdminUserService` 审计方法（账本#4 的审计调用形态）。
- **实现方案**：
  1. dts-admin 新增运维端点（`ROLE_AUTHADMIN` 限定）或运维脚本二选一——实施期按最小面选择，默认倾向端点 + dry-run。
  2. 默认不执行：升级包只在 release notes 说明风险与执行方式，由现场决定范围与时机（ADR-78-03）。
  3. 升级说明：建议现场优先对"创建后从未改密"的账号执行；无法探测口令本身，不得声称能识别弱口令账号。
- **禁止**：全量强制重置内置管理员账号；任何"检测谁还用 sa"的实现（口令不可探测）。

## 影响范围

- `source/dts-admin`（运维端点/服务 + 审计）
- `assets/release-plan.md`（现场执行说明）
- 测试：dry-run、幂等、单用户失败不中断、内置账号排除

## 验证（RED→GREEN）

- [ ] 契约测试：dry-run 无副作用；执行后目标用户含 `UPDATE_PASSWORD`；重复执行 skipped。
- [ ] 拒绝路径：非授权角色调用被拒；内置账号在排除集合内。
- [ ] 审计：每次执行产生 `USER_FORCE_PASSWORD_UPDATE` 事件且无明文。
