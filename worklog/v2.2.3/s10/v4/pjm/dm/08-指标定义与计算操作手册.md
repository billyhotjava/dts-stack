# 指标定义与计算操作手册

## 1. 目标与边界

PJM 模型发布和物化完成后，在“数据建模 → 数据指标”登记 `metric-registry.json` 中的稳定指标。指标定义、模型物化和指标计算是三类不同事实：

1. 模型发布/物化负责生成可查询的 DWD、DWS、ADS 物理关系；
2. 指标发布负责冻结业务口径、上游指标版本和实现字段引用；
3. “提交计算”读取已物化模型的最新业务周期，写入独立运行记录；它不重新创建逻辑模型，也不代替模型发布。

`pjm_qual_count` 是随图表分组变化的辅助序列，`indicatorEligible=false`，不得登记为独立指标。应登记的稳定指标总数为 76。

## 2. 登记顺序

1. 先登记原子指标：选择业务分类、数据域、真实业务过程、已发布模型修订、MEASURE 字段和聚合方式。
2. 再登记派生指标：选择固定上游指标版本、受控公式、已发布实现模型和结果字段。
3. 最后登记复合指标：至少选择两个固定上游指标版本；跨域时不虚构单一数据域，同时绑定综合 ADS 的结果字段。
4. 每个指标依次执行“保存 → 校验 → 发布”。已发布指标修改时产生新版本，不直接覆盖已发布快照。

派生/复合指标同时维护两组不互相替代的关系：

| 关系 | 用途 | 示例 |
|---|---|---|
| 上游指标固定版本 | 冻结业务语义和依赖 | `pjm_prog_on_time_cnt@v1` |
| 模型结果字段固定修订 | 追溯真实物理实现 | `biz_ads_progress_derived_v2.pjm_prog_on_time_rate` |

## 3. PJM 特殊实现字段

项目看板的三个计数在 `biz_ads_progress_kpi_v2` 中直接输出：

| 指标 | 结果字段 | 口径 |
|---|---|---|
| `pjm_project_total` | `project_total_cnt` | 周期内项目编号去重计数 |
| `pjm_project_active` | `project_active_cnt` | 存在未完成节点的项目编号去重计数 |
| `pjm_project_delay` | `project_delay_cnt` | 存在超期未完成节点的项目编号去重计数 |

若字段尚未出现在模型编辑器和物理表中，必须先发布 `biz_ads_progress_kpi_v2` 新修订并二次物化，不能把表达式粘贴到普通指标表单绕过实现绑定。

## 4. 提交计算

### 4.1 单指标

打开已发布指标，点击“提交计算”。页面显示本次请求号、状态、计算值、模型字段来源、处理行数、耗时和错误信息，并在“计算历史”追加记录。

### 4.2 批量指标

在指标 Table 中勾选一个或多个 `PUBLISHED` 记录，点击“提交计算（N）”。草稿、废止指标不可选择。一个请求可提交 1～64 个指标；派生依赖由服务端按固定版本关系解析。

### 4.3 计算口径

- 有固定模型字段实现时，按模型时间语义或粒度中的年/月/日期键选取最新业务周期，再按指标聚合方式读取结果；派生 ADS 结果字段按最新周期单值读取。
- 旧派生指标尚未补实现字段时，可按受控公式和已发布上游指标计算；后续修订必须补齐模型字段实现。
- 每次重复提交都会生成新的运行记录和请求号，不会重复创建模型或破坏已有物理关系。
- 物理表不存在、字段漂移、结果为空或依赖计算失败时，运行记录为 `FAILED`，不得把失败当作无数据成功。

## 5. 验收清单

- [ ] 指标状态为 `PUBLISHED`，业务分类、数据域/业务过程符合指标类型边界。
- [ ] 派生/复合指标的固定上游版本与受控公式一致。
- [ ] 指标具有固定模型修订和 MEASURE 结果字段引用。
- [ ] 首次提交产生 `SUCCESS` 运行记录，可看到物理关系、字段、值、处理行数和请求号。
- [ ] 二次提交产生不同请求号和新的历史记录，逻辑模型数量不变。
- [ ] 目标物理表的最新周期和值可与数据库只读查询对账。
- [ ] 浏览器控制台和计算网络请求无异常。
