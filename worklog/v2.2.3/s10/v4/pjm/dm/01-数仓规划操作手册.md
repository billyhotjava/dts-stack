# 数仓规划操作手册

> 适用范围：当前版本已取消“数仓计划”和“建模策略”。数仓规划按平台全局目录维护，实施人员直接维护业务分类、数据域、业务过程、数仓分层、数据集市和主题域，不再选择规划实例或配置默认分类。

## 1. 目标关系

```text
平台全局数仓规划
  └─ 业务分类：研究所业务
       ├─ 数据域：研究项目域
       │    ├─ 项目计划执行
       │    ├─ 项目风险处置
       │    └─ 项目跟进/风险措施闭环（二期）
       ├─ 数据域：质量管理域
       │    ├─ 质量问题处置
       │    └─ 质量措施闭环（二期）
       ├─ 数据域：产品技术域
       │    ├─ 技术状态更改
       │    └─ 技术状态措施闭环（二期）
       ├─ 数据域：物料供应域
       │    └─ 重要物料交付跟踪（二期）
       └─ 数据域：财务管理域
            └─ 预算执行快照

应用层
  └─ 项目管理分析集市
       ├─ 项目进度主题
       ├─ 质量分析主题
       ├─ 技术状态主题
       ├─ 风险管控主题
       ├─ 预算执行主题
       └─ 项目综合健康主题
```

业务分类是数据域的上级治理范围；数据域是日常建模主对象；业务过程是 FACT 和原子指标的真实活动上下文；数据集市和主题域用于组织应用消费。这些对象职责不同，不能互相替代。

## 2. 操作前检查

开始写入前，由实施人员逐项确认：

- 当前账号有数仓规划维护权限；后续建模、导入和发布权限按实际任务另行确认。
- “研究所业务”是否已存在；已存在时复用其稳定 ID，不按名称重复创建。
- 10 张 ODS 表是否已登记为当前来源绑定；来源状态、版本和可读权限是否有效。
- 数据负责人、过程负责人和安全负责人已明确。手册中的负责人不代填。
- 同名数据域、业务过程、集市和主题域是否已存在，避免重复创建。

## 3. Step 1：确认业务分类

### 3.1 已有“研究所业务”

1. 进入“数仓规划 → 业务分类与数据域”。
2. 在业务分类列表中查找“研究所业务”。
3. 记录其稳定 ID/编码，检查未停用。
4. 不重新创建、不修改稳定编码。

### 3.2 尚未创建

1. 点击“新建业务分类”。
2. 录入：

| 页面字段 | 建议值 | 说明 |
|---|---|---|
| 业务分类编码 | `INSTITUTE` | 仅在不存在时建议；最终编码由规划负责人确认 |
| 业务分类名称 | `研究所业务` | 研究所平台全局治理范围 |
| 负责人 | 由规划负责人确认 | 不使用开发人员账号代填 |
| 说明 | `覆盖研究所科研生产、质量、供应、财务和组织运营等业务能力。` | 不写具体来源系统名 |

3. 点击“新建业务分类”。
4. 重新读取列表，确认只产生一个稳定对象。

## 4. Step 2：创建数据域

按下表逐个创建。编码使用稳定 ASCII 大写标识，名称表达业务能力，不使用 ERP/PLM/QMS 等系统名。

| 数据域编码 | 数据域名称 | 负责范围 | 本批 ODS |
|---|---|---|---|
| `PROJECT` | 研究项目域 | 项目计划、节点执行、项目风险及跟进闭环 | `project_subject_domain`、`progress_measure`、`risk_info`、`risk_measure` |
| `QUALITY` | 质量管理域 | 质量问题、归零和措施闭环 | `quality_issue`、`quality_measure` |
| `PRODUCT_TECH` | 产品技术域 | 技术状态更改、文件签署和整改 | `tech_state`、`tech_state_measure` |
| `MATERIAL_SUPPLY` | 物料供应域 | 重要物料合同、交付、检验、上装 | `material_info` |
| `FINANCE` | 财务管理域 | 科研经费预算与三本账执行 | `budget` |

对每个数据域执行：

1. 进入“数仓规划 → 业务分类与数据域”。
2. 点击“新建数据域”。
3. 填写“数据域编码”“数据域名称”“所属业务分类”“负责人”“说明”。
4. 在“所属业务分类”中选择“研究所业务”。如果页面因当前只有一个业务分类而自动预选，仍应核对归属是否正确；页面允许按实际情况调整。
5. 点击“新建数据域”。
6. 回到列表核对上级分类、编码、名称和负责人。

数据域通过“所属业务分类”直接建立稳定归属，不依赖额外的计划或默认策略。已有数据域需要调整归属时，应先评估下游模型、资产、指标和质量规则的影响，再执行修改。

说明建议写清“包含什么、不包含什么”。例如财务管理域不负责项目质量问题，研究项目域不接管质量和财务事实，只在 ADS 组合跨域结果。

数据域建好后，在来源绑定或 dbt 逆向映射时再建立 ODS 与数据域的关系。同一来源系统可以向多个数据域供数，同一数据域也可以汇聚多个系统的数据。本批 10 张 PostgreSQL ODS 默认都标记来源 `excel`，但它们分属 5 个数据域，这正说明不能按“一个系统=一个数据域”建模。

## 5. Step 3：创建业务过程

业务过程按照“独立业务活动 + 独立事实粒度”划分。只有对应 ODS 已准备进入模型链时才启用，不能为了消除空态批量创建占位过程。

### 5.1 当前主链必须创建

| 英文缩写 | 中文名称 | 数据域 | 业务定义/事实粒度 |
|---|---|---|---|
| `project_plan_execution` | 项目计划执行 | 研究项目域 | 跟踪项目分系统/任务节点从计划到实际完成的状态；一个项目×分任务×节点×计划日期一行 |
| `project_risk_handling` | 项目风险处置 | 研究项目域 | 识别、应对并释放项目风险；一条项目风险一行 |
| `quality_issue_handling` | 质量问题处置 | 质量管理域 | 记录质量问题、归零计划及完成状态；一条质量问题一行 |
| `technical_state_change` | 技术状态更改 | 产品技术域 | 记录一项技术状态更改及签署、整改里程碑；一项更改一行 |
| `budget_execution_snapshot` | 预算执行快照 | 财务管理域 | 记录预算编号当前三本账状态；一个预算编号在一个业务快照日一行 |

### 5.2 二期按需创建

| 英文缩写 | 中文名称 | 数据域 | 启用前提 |
|---|---|---|---|
| `project_follow_up_closure` | 项目跟进闭环 | 研究项目域 | 措施表补充稳定措施 ID |
| `quality_measure_closure` | 质量措施闭环 | 质量管理域 | 措施表补充稳定措施 ID/质量问题 ID |
| `technical_state_measure_closure` | 技术状态措施闭环 | 产品技术域 | 措施表补充稳定措施 ID/更改单 ID |
| `risk_measure_closure` | 风险措施闭环 | 研究项目域 | 措施表补充稳定措施 ID/风险 ID |
| `material_delivery_tracking` | 重要物料交付跟踪 | 物料供应域 | 明确 PBS 物料稳定键和快照语义 |

对每个业务过程执行：

1. 进入“数仓规划 → 业务过程”。
2. 点击“新建业务过程”。
3. 填写“英文缩写”“中文名称”“数据域”“业务定义”。
4. 确认业务定义能回答“一行代表什么”。
5. 点击“新建业务过程”。
6. 检查状态为有效/已确认，并确认 FACT 表单能读取该过程。

研究项目域有多个过程，因此新建项目 FACT 时会出现过程选择器；这是正确行为。不要为隐藏选择器而合并不同粒度的过程。

## 6. Step 4：确认数仓分层

1. 进入“数仓规划 → 数仓分层”。
2. 检查系统内置层至少包含：

| 系统类型 | 分层归属 | 可创建模型 |
|---|---|---|
| `ODS_RAW` / `ODS_STANDARDIZED` / `STG` | 贴源层 | 仅规划展示；本项目由数据接入和 dbt 管理 |
| `DWD` | 公共层 | 维度、维度表、明细表 |
| `DWS` | 公共层 | 汇总表 |
| `ADS` | 应用层 | 应用表 |

3. 如果这些系统内置层已存在，结束本步骤，不新建同义层。
4. 只有在企业确认了新的加工责任边界后，才使用“分层编码、名称、所属系统类型、命名前缀、加工责任”创建自定义层。

## 7. Step 5：规划应用层集市和主题域

### 7.1 创建数据集市

1. 进入“数仓规划 → 数据集市”，点击“新建数据集市”。
2. 填写：

| 页面字段 | 建议值 |
|---|---|
| 英文缩写 | `PJM_ANALYTICS` |
| 中文名称 | `项目管理分析集市` |
| 业务分类 | `研究所业务` |
| 用途说明 | `面向项目执行、质量、技术状态、风险、预算和综合健康分析的统一消费集市。` |

3. 保存后在列表选中草稿，点击“确认发布”。只有 CURRENT 集市才能作为稳定规划基线。

### 7.2 创建主题域

进入“数仓规划 → 主题域”，逐个创建并绑定 `PJM_ANALYTICS`：

| 主题域编码 | 主题域名称 | 主要 ADS |
|---|---|---|
| `PROJECT_PROGRESS` | 项目进度主题 | progress KPI/derived |
| `QUALITY_ANALYSIS` | 质量分析主题 | quality KPI/derived |
| `TECH_STATE_ANALYSIS` | 技术状态主题 | tech-state KPI/derived |
| `RISK_CONTROL` | 风险管控主题 | risk KPI |
| `BUDGET_EXECUTION` | 预算执行主题 | budget KPI/derived |
| `PROJECT_HEALTH` | 项目综合健康主题 | composite derived |

主题域字段为“主题域编码、主题域名称、数据集市、用途说明”。每个主题域保存后再“确认发布”。

当前应用模型基础表单没有集市/主题域选择器，因此本步骤先建立应用规划目录；不要在验收记录中声称 ADS ModelSpec 已与主题域直接绑定，除非服务端事实确实返回该关联。

## 8. 规划验收清单

- [ ] 平台全局业务分类中只有一个稳定的“研究所业务”，且未停用。
- [ ] 5 个数据域均通过“所属业务分类”明确归属“研究所业务”。
- [ ] 5 个数据域按业务能力创建，没有 ERP/PLM/QMS 同名数据域。
- [ ] 当前 5 个主链过程都能说明业务活动和一行粒度。
- [ ] 研究项目域的多个过程在 FACT 表单中可明确选择。
- [ ] 未创建 `<domain>_default`、`其他过程` 等占位过程。
- [ ] 内置 ODS/STG/DWD/DWS/ADS 分层未被重复创建。
- [ ] 数据集市和 6 个主题域已确认发布；如果暂不需要应用规划，应明确记录为“未创建”，不能标记完成。
- [ ] 负责人、密级和来源关系均由对应责任人确认，不由实施人员猜测。
