# 项目管理测试数据：第二版业务快照

本目录基于上一级 `test/` 的 10 表测试数据生成，定义为**截至 2027-06-30 的第二版完整快照**，用于验证同一批项目数据再次入湖后的全量替换、状态更新、跨表联动和新增记录。

## 与基础版本的关系

- 文件名和表结构保持不变，可继续对应原来的 10 张 ODS 表。
- 保留项目、节点、问题、技术状态、风险、物料和预算业务键。
- 原有业务行顺序保持不变，唯一新增预算追加在末尾，避免 ODS 自增行号导致下游测试 ID 无谓漂移。
- 不是简单复制：第二版推进部分业务状态，并新增一条预算记录。
- 上一级文件不会被覆盖。

## 第二版变化

| 领域 | 变化 |
|---|---|
| 进度 | 4 个节点由待完成/超期未完成推进到按时完成或超期已完成 |
| 质量 | `C02`、`C04`、`C08` 完成技术和管理归零，措施台账同步闭环 |
| 技术状态 | `C02`、`C04`、`C06`、`C10` 完成文件签署或整改闭环；`C03`、`C09` 补齐已有闭环日期 |
| 风险 | `C02`、`C04`、`C08` 完成风险释放；`C06` 保持跟踪 |
| 物料 | `C03`、`C06`、`C08` 完成到货、检验和装配 |
| 预算 | 原 25 条预算执行额发生变化，新增 `YS-2026-C01-03`，合计 26 条 |

`manifest.json` 记录每张表的行数，以及相对基础版本的更新、新增、删除和未变化数量。

生成器同时固定工作簿属性和 XLSX ZIP 元数据；输入脚本不变时，重复生成的 CSV、XLSX 与 `manifest.json` 哈希保持一致。

## 重新生成

```bash
cd worklog/v2.2.3/s10/v4/pjm/test/v2
python3 generate_test_data_v2.py
```

脚本会自动校验：

- 10 张表的字段顺序与基础版本一致；
- 业务键非空且唯一；
- 事实表与措施表能够关联；
- 技术状态措施标记为已闭环时必须具备闭环日期；
- 日期与 ISO 周一致，实际发生日期不晚于 2027-06-30；
- 原有业务行顺序不变，新增业务行只能追加；
- 10 个项目覆盖完整；
- 预算编号全局唯一、金额非负且保留两位小数，保留 4 条行级超支场景；
- CSV 与 XLSX 的表头、行数和全部单元格内容一致。

## 加载到测试库

上一级加载脚本使用相对 CSV 路径，因此从本目录执行即可加载第二版数据：

```bash
cd worklog/v2.2.3/s10/v4/pjm/test/v2
psql -h <host> -U <user> -d <db> \
  -v ON_ERROR_STOP=1 \
  -f ../load_test_data.sql
```

该脚本会清空 10 张 ODS 测试表，只能在测试库使用。
第二版应作为完整快照全量加载，不应与基础版 CSV 直接追加合并。
