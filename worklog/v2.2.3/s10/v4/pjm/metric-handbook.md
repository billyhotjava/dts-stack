# GPMC 大屏指标说明手册 v1.0

> 口径冻结日期: **2026-05-18**
> 权威源: `v3/metrics/原始指标大表.xlsx` + `v3/metrics/二次指标大表.xlsx`

## 进度域 (17 个指标)

### 异常节点数  ·  `pjm_prog_abnormal_cnt`

| 项 | 内容 |
|---|---|
| 业务定义 | 处于异常状态(不正常待变更 + 超期未完成未变更)的节点数 |
| 计算公式 | 完成情况∈('不正常待变更','超期未完成未变更') 的节点计数 |
| 统计范围 | 受顶部时间筛选器控制,不含一般节点 |
| 单位 | 个 |
| 评价方向 | 越低越好 |
| 阈值 | 无 |
| 数据来源 | 进度信息汇总表 |
| 更新频率 | 每日 01:00 刷新 |
| 历史别名 | 异常 |
| Excel 出处 | 原始指标 #12 + #13 |

### 节点不正常率  ·  `pjm_prog_abnormal_rate`

| 项 | 内容 |
|---|---|
| 业务定义 | 已到时间节点中,处于危险状态但尚未走变更流程的节点占比 |
| 计算公式 | (不正常待变更 + 超期未完成未变更) ÷ 已到时间节点数 × 100% |
| 统计范围 | 不含一般节点 |
| 单位 | % |
| 评价方向 | 越低越好 |
| 阈值 | 关注线 ≥ 20.0%  ·  预警线 ≥ 30.0% |
| 数据来源 | 进度信息汇总表 |
| 更新频率 | 每日 01:00 刷新 |
| 历史别名 | 异常率, 不正常率 |
| Excel 出处 | 二次指标 #3 pjm_prog_abnormal_rate |

## 字段字典(枚举字段含义) — 11 个字段

> 用途: 明细表枚举类列的取值含义对照(完成情况/风险等级/整改状态等)。鼠标悬浮明细表列头 ℹ️ 即可查看。


### 完成情况  ·  `completion_status`

**定义**: 节点在统计时点的完成状态。'已变更'表示已走过变更流程并获批。

| 取值 | 含义 |
|---|---|
| 正常待完成 | 节点未到计划时间,状态正常,还能正常完成 |
| 按时完成 | 节点已在计划时间内完成 |
| 超期已完成已变更 | 超过计划时间但已完成,且已走过变更流程 |
| 超期已完成未变更 | 超过计划时间但已完成,未走变更流程 |
| 不正常待变更 | 已到计划时间但未完成,需走变更流程(异常状态) |
| 超期未完成未变更 | 已超过计划时间且未完成,未走变更流程(严重异常) |
| 超期未完成已变更 | 已超过计划时间且未完成,已走过变更流程 |

**数据来源**: 进度信息汇总表

**业务备注**: 排序权重: 正常待完成=1 < 按时完成=2 < 超期完成=3-4 < 不正常/超期未完成=5-7


### 节点类型  ·  `node_type`

**定义**: 节点在项目中的重要等级,影响考核权重与异常判定。

| 取值 | 含义 |
|---|---|
| 里程碑节点 | 项目对外承诺的关键交付点,权重最高,单独考核完成率 |
| 重大节点 | 影响项目交付的关键节点 |
| 重要节点 | 重要技术或管理节点 |
| 一般节点 | 常规工作节点,通常不参与超期/不正常率统计 |

**数据来源**: 进度信息汇总表

**业务备注**: 重要程度: 里程碑 > 重大 > 重要 > 一般


### 风险等级  ·  `risk_level`

**定义**: 风险按业务影响程度的分级。

| 取值 | 含义 |
|---|---|
| 高风险 | 影响项目目标的重大风险,需重点关注与即时响应 |
| 中风险 | 影响范围有限的中等风险,定期跟进 |
| 低风险 | 潜在风险,持续观察 |

**数据来源**: 风险信息汇总表 / 进度信息汇总表(节点风险)

### 风险状态  ·  `risk_status`

**定义**: 风险的当前生命周期状态。

| 取值 | 含义 |
|---|---|
| 已释放 | 风险已闭环,不再影响项目 |
| 未释放 | 风险仍在跟踪中(默认状态) |

**数据来源**: 风险信息汇总表

**业务备注**: 数据规范化: 仅'已释放'是显式标识,其余值统一归为'未释放'


### 风险类别  ·  `risk_category`

**定义**: 风险按业务领域的分类。

| 取值 | 含义 |
|---|---|
| 技术风险 | 技术方案/技术难题/技术指标相关 |
| 进度风险 | 节点延期/计划偏差相关 |
| 成本风险 | 预算超支/成本上升相关 |
| 设计风险 | 设计变更/方案返工相关 |
| 质量风险 | 产品/工艺质量相关 |
| 其他风险 | 未归入以上分类的风险 |

**数据来源**: 风险信息汇总表

### 质量问题状态  ·  `quality_status`

**定义**: 质量问题的归零状态。'归零'指问题完全闭环。

| 取值 | 含义 |
|---|---|
| 未完成归零 | 问题未闭环,仍在处理中 |
| 已完成技术归零 | 通过技术手段完成归零 |
| 已完成管理归零 | 通过管理手段完成归零 |
| 已完成技术和管理归零 | 同时完成技术与管理双归零 |

**数据来源**: 质量信息汇总表

**业务备注**: 数据规范化: '处理中'/'进行中'/'未闭环'等统一归为'未完成归零'


### 质量问题分类  ·  `quality_category`

**定义**: 质量问题按发生原因的分类。

| 取值 | 含义 |
|---|---|
| 设计 | 设计阶段引入的问题 |
| 工艺 | 工艺设计或执行偏差 |
| 管理 | 流程/制度执行不到位 |
| 元器件 | 元器件本体质量 |
| 操作 | 人员操作失误 |
| 外协外购 | 外协外购件质量 |
| 软件 | 软件缺陷 |
| 环境 | 环境因素引起 |
| 其他 | 未归入以上分类 |

**数据来源**: 质量信息汇总表

### 更改类别  ·  `change_category`

**定义**: 技术状态更改的影响等级分类。

| 取值 | 含义 |
|---|---|
| Ⅰ类更改 | 影响最大的更改,需走完整评估评审签署流程 |
| Ⅱ类更改 | 影响中等的更改,需评审签署 |
| Ⅲ类更改 | 影响最小的更改,简化流程,不涉及整改要求 |

**数据来源**: 技术状态信息汇总表

**业务备注**: 数据规范化: 罗马数字/阿拉伯数字/汉字一/二/三都归一化为 I/II/III


### 文件签署状态  ·  `signature_status`

**定义**: 技术状态变更文件的签署流程节点。I/II 类与 III 类流程不同。

| 取值 | 含义 |
|---|---|
| 已提出需求,未评估评审 | I/II 类: 已发起更改但未完成评估评审 |
| 已评估评审,未签署 | I/II 类: 已完成评估评审但未签署 |
| 已评估评审,已签署 | I/II 类: 评审与签署均完成(已闭环) |
| 已提出需求,未签署 | III 类: 已发起但未签署 |
| 已提出需求,已签署 | III 类: 已签署(已闭环) |

**数据来源**: 技术状态信息汇总表

### 整改状态  ·  `reform_status`

**定义**: I/II 类技术状态变更单的整改落实状态。III 类不涉及整改。

| 取值 | 含义 |
|---|---|
| 已落实整改 | I/II 类: 已完成整改落实 |
| 未落实整改 | I/II 类: 整改尚未落实 |
| 不涉及 | III 类变更单,不涉及整改要求 |

**数据来源**: 技术状态信息汇总表

**业务备注**: 数据规范化: '已完成'/'完成' 归为'已落实整改';'无' 归为'不涉及'


### 是/否(布尔)  ·  `boolean_yesno`

**定义**: 通用布尔字段,如'是否完成签署'。

| 取值 | 含义 |
|---|---|
| 是 | 肯定/已完成/已签署 |
| 否 | 否定/未完成/未签署 |

**数据来源**: 通用

**业务备注**: 数据规范化: Y/YES/TRUE/已*/是 → 是; N/NO/FALSE/未*/否 → 否
