# 数据管理平台数据模型设计文档（v4 PostgreSQL 重构版）

文档版本：V4.1

文档状态：重构稿

适用范围：项目管控、采购库存、考勤、专利、财务一体化数据平台

## 核心设计原则

### 设计原则

最新记录原则：进度 / 质量 / 风险 / 技术变更仅保留最新状态，更新时覆盖原有记录；

业务主键：

| 原则 | 说明 |
| --- | --- |
| 最新记录原则 | 进度 / 质量 / 风险 / 技术变更仅保留最新状态，更新时覆盖原有记录 |
| 业务主键 | 为每个任务 / 问题 / 风险 / 变更生成唯一标识，作为覆盖更新依据 |
| 简化存储 | 减少数据冗余，降低存储成本 |
| 实时查询 | 直接查询 DWD 表即可获取最新状态，无需视图过滤 |
| PostgreSQL 适配 | DDL、索引、注释、布尔、时间、自增键统一使用 PostgreSQL 语法；更新时间由 trigger 或 ETL 显式维护。 |

### 数据域更新策略

| 数据域 | 更新方式 | 业务主键 | 说明 |
| --- | --- | --- | --- |
| 进度 | 覆盖更新/按批次重算 | node_id / source_row_id | 同一 ODS 行经 STG/DWD 解释为项目节点事实 |
| 质量 | 覆盖更新/按批次重算 | issue_id / source_row_id | 同一质量问题经 DWD 归一状态与原因分类 |
| 风险 | 覆盖更新/按批次重算 | risk_id / source_row_id | 同一风险台账经 DWD 归一等级、分类和释放状态 |
| 技术变更 | 覆盖更新/按批次重算 | tech_state_id / source_row_id | 技术状态事实经 DWD 归一更改类别、签署和整改状态 |
| ERP采购/库存 | 追加新增 | 单据号 | 事务数据不覆盖 |
| 考勤 | 覆盖更新 | 人员 + 日期 | 同一人同一天覆盖 |
| 专利 | 覆盖更新 | 专利号 | 状态变化时更新 |
| 财务 | 覆盖更新 | 科目 + 部门 + 月份 | 同周期覆盖 |

### 分层架构全景

ADS 应用服务层：项目域 v4 KPI/Derived 指标、项目全景看板、科室绩效看板、考勤分析看板、专利分析看板、质量分析看板、风险分析看板、库存分析看板、成本分析看板

DWS 汇总指标层：项目域按进度/质量/技术状态/风险月度汇总，其他域沿用 v3 的科室综合、考勤汇总、专利汇总、库存汇总、成本汇总

DWD 明细事实层：项目域 v4 使用 biz_dwd_project_node_v2、biz_dwd_quality_issue_v2、biz_dwd_risk_info_v2、biz_dwd_tech_state_v2；采购、库存、成本、考勤、专利、财务明细沿用 v3

DIM 维度层：sys_department、sys_employee、dim_project、dim_wbs、dim_date、dim_enum、dim_material、dim_supplier、dim_warehouse、dim_patent、dim_account；项目域新增 dim_*_v2 canonical 维表与 dim_*_alias 别名维表

Standard 标准层：由 PostgreSQL 数据类型标准、STG 字段收敛规则、DWD canonical/alias 维表和数据质量规则共同承担

ODS 贴源层：ERP 在线（30张表，沿用 v3）、PMO 项目域 v4 离线（9张表）、考勤离线（1张表）、专利离线（1张表）、财务离线（4张表）

## 数据标准体系

### 命名规范标准

| 规范项 | 标准 | 示例 |
| --- | --- | --- |
| ODS 表命名 | ods_{系统或主题}_{源表名} | ods_project_subject_domain_v2 |
| DIM 表命名 | dim_{实体名} | dim_project_master |
| DWD 表命名 | biz_dwd_{主题}_{事实}_v{版本} | biz_dwd_project_node_v2 |
| DWS 表命名 | biz_dws_{主题}_{粒度}_v{版本} | biz_dws_progress_monthly_v2 |
| ADS 表/视图命名 | biz_ads_{主题}_{kpi\|derived}_v{版本} | biz_ads_progress_kpi_v2 |
| 字段命名 | 小写字母 + 下划线 | project_uid |
| 主键命名 | {实体名}_id / {实体名}_uid | task_id、project_uid |
| 外键命名 | {关联实体名}_id | responsible_dept_id |
| 布尔字段 | is_{含义} | is_delayed |
| 时间字段 | {动作}_time / {动作}_date / *_at | create_time、update_time、imported_at |

### 数据类型标准

| 数据类型 | 使用场景 | PostgreSQL 标准定义 |
| --- | --- | --- |
| 主键 / 外键 | 唯一标识 | varchar(50)；跨系统自然键可用 varchar(100)，内部代理键可用 bigint GENERATED BY DEFAULT AS IDENTITY |
| 编码字段 | 业务编码 | varchar(50) |
| 名称字段 | 短文本 | varchar(200) |
| 长文本 | 描述信息 | text |
| 日期字段 | 仅日期 | date |
| 时间字段 | 日期 + 时间 | timestamp without time zone；跨时区接口字段使用 timestamp with time zone |
| 月份字段 | 年月 | varchar(7)，格式 YYYY-MM；也可冗余 period_year/period_month 便于分区和索引 |
| 金额字段 | 货币 | numeric(28,8) |
| 数量字段 | 物料数量 | numeric(28,8) |
| 比率字段 | 百分比 | numeric(7,4) 存比例或 numeric(7,2) 存百分数，需在字段说明中明确 |
| 计数字段 | 整数 | integer；大计数使用 bigint |
| 布尔字段 | 是 / 否 | boolean，不再使用 tinyint(1) |
| 枚举外键 | 关联枚举表 | integer 或 varchar code；项目域 v4 优先 canonical code + *_id |

### PostgreSQL DDL 适配规则

| 场景 | 原 MySQL 写法 | PostgreSQL 写法 |
| --- | --- | --- |
| 字段注释 | col varchar(50) COMMENT '说明' | col varchar(50); COMMENT ON COLUMN table.col IS '说明'; |
| 表注释 | ) COMMENT '表说明'; | ); COMMENT ON TABLE table IS '表说明'; |
| 自增主键 | BIGINT AUTO_INCREMENT PRIMARY KEY | bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY |
| 时间类型 | DATETIME | timestamp without time zone |
| 布尔类型 | TINYINT(1) / TINYINT DEFAULT 1 | boolean DEFAULT true；季度、月份等小整数用 smallint |
| 金额/数量 | DECIMAL(28,8) | numeric(28,8) |
| 更新时间 | ON UPDATE CURRENT_TIMESTAMP | PostgreSQL 通过 BEFORE UPDATE trigger 维护 update_time |
| 索引 | INDEX idx_col (col) 写在 CREATE TABLE 内 | CREATE INDEX idx_table_col ON table_name (col); |

### 项目季度综合指标表

v4 项目域季度指标由月度 ADS 聚合生成，避免重复维护旧版项目季度宽表。以下为 PostgreSQL 视图模板，生产可按物化视图或 dbt table 落地。

```sql
CREATE VIEW biz_ads_project_quarterly_v2 AS
SELECT
  period_year,
  ceil(substring(period_month from 6 for 2)::numeric / 3)::smallint AS period_quarter,
  format('%s-Q%s', period_year, ceil(substring(period_month from 6 for 2)::numeric / 3)::int) AS stat_period,
  avg(pjm_composite_health) AS avg_composite_health,
  max(pjm_risk_warning_index) AS max_risk_warning_index,
  sum(CASE WHEN health_warning_level = 'red' THEN 1 ELSE 0 END) AS red_health_months,
  sum(CASE WHEN risk_warning_level = 'red' THEN 1 ELSE 0 END) AS red_risk_months
FROM biz_ads_composite_derived_v2
GROUP BY period_year, ceil(substring(period_month from 6 for 2)::numeric / 3)::smallint;
```

```sql
  avg(pjm_composite_health) AS avg_composite_health,
  max(pjm_risk_warning_index) AS max_risk_warning_index,
  sum(CASE WHEN health_warning_level = 'red' THEN 1 ELSE 0 END) AS red_health_months,
  sum(CASE WHEN risk_warning_level = 'red' THEN 1 ELSE 0 END) AS red_risk_months,
  count(*) AS month_count
FROM biz_ads_composite_derived_v2
GROUP BY period_year;
```

## 总结

### 核心设计要点

| 要点 | 说明 |
| --- | --- |
| 保留 v3 总体设计 | 核心原则、总体架构和数据标准体系沿用 v3，并按 PostgreSQL 语法优化。 |
| 项目域 v4 化 | 项目 ODS/STG/DWD/DWS/ADS 以 pjm dbt 模型为准，旧项目手写明细表不再作为口径来源。 |
| 非项目域沿用 v3 | ERP、采购、库存、成本、考勤、专利、财务等非项目章节沿用 v3 设计，仅转换 PostgreSQL DDL 表达。 |
| ODS 保留历史 | ODS 层保留所有导入记录，STG/DWD/ADS 可按批次重算。 |
| PostgreSQL 标准化 | 注释、索引、自增、布尔、时间字段统一采用 PostgreSQL 语法。 |
