# 项目看板（综合态势）— 指标映射表

> 来源大屏：`gpmc-strategic-overview.json`（GPMC 战略层大屏）
> 用途：记录项目看板上每个指标的名称、来源表、来源字段和对应 SQL，便于在新大屏框架中复用

---

## 一、涉及的 ADS 表（共 5 张）

| 表名 | 说明 | 数据粒度 |
|------|------|---------|
| `biz_ads_project_kpi_overview` | 项目节点 KPI 汇总 | 每行 = 一个 plan_year + plan_month |
| `biz_ads_major_project_overview` | 重大项目总览 | 每行 = 一个 major_project |
| `biz_ads_quality_kpi` | 质量问题 KPI | 每行 = 一个 period_year + period_month |
| `biz_ads_risk_kpi` | 风险 KPI | 每行 = 一个 period_year + period_month |
| `biz_ads_tech_state_kpi` | 技术状态 KPI | 每行 = 一个 period_year + period_month |

---

## 二、KPI 卡片（6 个）

### 2.1 项目总数

| 属性 | 值 |
|------|---|
| 组件 ID | `gpmc-overview-kpi-total` |
| 来源表 | `biz_ads_major_project_overview` |
| 取值字段 | `COUNT(*)` 或 `COUNT(DISTINCT major_project_id)` |
| 业务含义 | 重大项目总数 |

```sql
SELECT
    COUNT(*) AS project_count
FROM biz_ads_major_project_overview;
```

### 2.2 进行中项目

| 属性 | 值 |
|------|---|
| 组件 ID | `gpmc-overview-kpi-active` |
| 来源表 | `biz_ads_project_kpi_overview` |

## 三、图表区域

### 3.1 周度完成趋势（柱状图）

| 属性 | 值 |
|------|---|
| 组件 ID | `gpmc-overview-weekly-chart` |

## 五、biz_ads_project_kpi_overview 字段速查

这是项目看板最核心的表，几乎所有项目执行类指标都来自此表。

| 字段 | 类型 | 业务含义 |
|------|------|---------|
| `plan_year` | INT | 计划年度 |
| `plan_quarter` | INT | 计划季度 |
| `plan_month` | TEXT | 计划月份 (YYYY-MM) |
| `total_cnt` | INT | 总任务数 |
| `pending_normal_cnt` | INT | 正常待完成数 |
| `due_cnt` | INT | 到期数（计划日期 ≤ 当前日期） |
| `outside_completed_cnt` | INT | 跨期完成数（非本期计划但本期完成） |
| `incomplete_cnt` | INT | 未完成数 |
| `on_time_cnt` | INT | 按时完成数 |
| `overdue_completed_cnt` | INT | 超期完成数 |
| `completed_total_cnt` | INT | 完成总数 = completed_cnt + outside_completed_cnt |
| `completion_rate` | NUMERIC(6,4) | 完成率 = completed_total / (due + outside) |
| `on_time_rate` | NUMERIC(6,4) | 按时率 = on_time / (due + outside) |
| `overdue_completion_rate` | NUMERIC(6,4) | 超期完成率 = (overdue + outside) / (total + outside) |
| `abnormal_pending_cnt` | INT | 异常待完成数 |
| `overdue_incomplete_unchanged_cnt` | INT | 超期未完成且状态不变数 |
| `overdue_incomplete_changed_cnt` | INT | 超期未完成且状态已变更数 |

## 七、两套模型对比

| | 项目看板（第一套，可用） | 项目执行监控（第二套，有问题） |
|---|---|---|
| 大屏文件 | `gpmc-strategic-overview.json` | `gpmc-execution-board.json` |
| 核心 ADS 表 | `biz_ads_project_kpi_overview` | 同左 + 下面 3 张 |
| | `biz_ads_major_project_overview` | `biz_ads_major_project_tree_snapshot` |
| | | `biz_ads_project_milestone_kpi` |
| | | `biz_ads_project_incomplete_risk` |
| 辅助 ADS 表 | `biz_ads_quality_kpi` | — |
| | `biz_ads_risk_kpi` | — |
| | `biz_ads_tech_state_kpi` | — |

**结论：** 执行监控比项目看板多依赖 3 张 ADS 表（`tree_snapshot`、`milestone_kpi`、`incomplete_risk`），这 3 张表的 dbt 模型有问题导致数据出不来。在新框架中可以：
1. 用 `biz_ads_project_kpi_overview` 覆盖大部分执行指标
2. 用 `biz_ads_major_project_overview` 替代 `tree_snapshot` 的项目概览功能
3. 里程碑和阻塞指标需从 `biz_ads_project_kpi_overview` 中近似计算
