# 原始指标 SQL 查询手册

> 67 个原始指标的可执行 SQL 查询，对应 `metrics/原始指标大表.xlsx` 的指标编号顺序。
> 每个指标对应一段独立、可直接执行的 SQL，直接打到 ODS 层。

---

## 使用说明

### 1. 修改时间范围

所有 SQL 中只有两个日期常量需要修改：

| 占位符 | 含义 |
|---|---|
| `{{dateFrom}}` | ★开始时间 |
| `{{dateTo}}` | ★结束时间 |

**操作**：用编辑器（VSCode / DBeaver / Sublime）的全局替换功能，把这两个字符串替换成你要的统计周期，然后整篇文档的 67 段 SQL 一次性更新。

### 2. 执行方式

复制单段 SQL 到 `psql` / `DBeaver` / `Navicat` / `pgAdmin` 中执行。每段 SQL 都返回单个数值（计数 / 比率）或带分子分母的多列结果。

### 3. 数据来源

| 域 | ODS 表 | 关键日期字段 |
|---|---|---|
| 进度域 (#1-33) | `ods_project_subject_domain_v2` | `plan_date` / `actual_date` |
| 质量域 (#34-48) | `ods_quality_issue_v2` | `issue_date` |
| 技术状态域 (#49-67) | `ods_tech_state_v2` | `change_submit_time` |

### 4. 时间窗口语义

不同指标对时间窗口的解释不同，**已严格按 `metrics/原始指标大表.xlsx` 实现**：

| 模式 | 表达式 | 适用指标 |
|---|---|---|
| 周期内 (BETWEEN 开始 AND 结束) | `xxx_date::date BETWEEN {{dateFrom}} AND {{dateTo}}` | #1-11、#18-33、#34、#36-40、#49-51 |
| 截止结束时间 (累计快照) | `xxx_date::date <= {{dateTo}}` | #12-15、#52-67 |
| 全量状态快照 (无日期) | `WHERE status=...` | #35、#41-48 |

### 5. 日期字段类型

ODS 中日期字段类型是 TEXT。SQL 中统一使用 `::date` 进行类型转换。
**如果实际 ODS 数据中存在脏数据**（如 `#N/A` / 空字符串 / `2025/01/15` 格式），请先用以下兜底过滤再 cast：

```sql
WHERE plan_date ~ '^\d{4}-\d{2}-\d{2}$'
  AND plan_date::date BETWEEN ...
```

### 6. 枚举值 ⚠️

某些指标依赖具体的中文状态字符串。**当前 SQL 使用的是 `原始指标大表.xlsx` 文档定义的字符串**。如果生产 ODS 数据的实际取值不同，需要把 WHERE 子句里的字符串替换成实际值。**有风险的指标已在备注中用 ⚠️ 标注**：

- **#36-39 / #41-48** 质量问题状态 `status` — 文档要求 `'未完成归零'` / `'已完成技术归零'` / `'已完成管理归零'` / `'已完成技术和管理归零'`，**测试数据是** `'处理中'` / `'已归零'`
- **#40** 归零计划 `zero_plan` — 文档要求 `'无'` 字符串判断，**实际可能是自由文本**，需要按 `'无' OR NULL OR ''` 兜底
- **#52-56** 文件签署状态 `file_signature_status` — 文档要求 5 种带类别后缀的中文枚举，**测试数据是** `'已签署'` / `'未签署'`
- **#65-67** 整改落实状态 `reform_status` — 文档要求 `'已落实整改'` / `'未落实整改'` / `'不涉及'`，**测试数据是** `'已完成'` / `'未开始'` / `'实施中'`
- **#60-64** `completion_signature` — 文档要求 `'是'` / `'否'`，与测试数据一致

### 7. 节点类型 / 风险等级 / 完成情况枚举（已确认与测试数据一致）

| 字段 | 取值 |
|---|---|
| `node_type` | `'一般节点'` / `'重要节点'` / `'重大节点'` / `'里程碑节点'` |
| `risk_level` | `'高'` / `'中'` / `'低'` |
| `completion_status` | `'正常待完成'` / `'按时完成'` / `'超期已完成已变更'` / `'超期已完成未变更'` / `'不正常待变更'` / `'超期未完成未变更'` / `'超期未完成已变更'` |
| `change_category` | `'I'` / `'II'` / `'III'` |
| `issue_category` | `'设计'` / `'工艺'` / `'管理'` / `'元器件'` / `'操作'` / `'外协外购'` / `'软件'` / `'其他'` |

> ODS 表：`ods_project_subject_domain_v2`

## #1 项目本周期节点总数

**维度**：项目（含一般节点）  
**依赖字段**：`plan_date`  
**计算逻辑**：`plan_date IN [开始,结束]` 的节点总数

```sql
SELECT COUNT(*) AS "项目本周期节点总数"
FROM ods_project_subject_domain_v2
WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
  [[AND project_no ILIKE '%' || {{projectNo}} || '%']]
```

## #8 节点完成总数

**维度**：项目（含一般节点）  
**依赖字段**：`plan_date`、`actual_date`、`completion_status`  
**计算逻辑**：`#4 + #6 + #7`

```sql

  -- #4 周期外完成
  COUNT(*) FILTER (
    WHERE actual_date IS NOT NULL
      AND actual_date::date BETWEEN {{dateFrom}} AND {{dateTo}}

  -- #6 周期内按时完成

    WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}

  )
  -- #7 周期内超期完成
  + COUNT(*) FILTER (
    WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
      AND completion_status IN ('超期已完成已变更','超期已完成未变更')
  )
  AS "节点完成总数"
FROM ods_project_subject_domain_v2
  [[AND project_no ILIKE '%' || {{projectNo}} || '%']]
```

## #9 节点完成百分比

**维度**：项目（含一般节点）  
**依赖字段**：`plan_date`、`actual_date`、`completion_status`  
**计算逻辑**：`#8 / (#3 + #4)`

```sql
WITH stats AS (
  SELECT
    COUNT(*) FILTER (
      WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
        AND completion_status != '正常待完成'
    ) AS due_cnt,
    COUNT(*) FILTER (
      WHERE actual_date IS NOT NULL
        AND actual_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
        AND NOT (plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}})
    ) AS outside_cnt,
    COUNT(*) FILTER (
      WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
        AND completion_status = '按时完成'
    ) AS on_time_cnt,
    COUNT(*) FILTER (
      WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
        AND completion_status IN ('超期已完成已变更','超期已完成未变更')
    ) AS overdue_completed_cnt
  FROM ods_project_subject_domain_v2
)
SELECT
  (outside_cnt + on_time_cnt + overdue_completed_cnt) AS "完成总数_分子",
  (due_cnt + outside_cnt) AS "已到时间加周期外_分母",
  CASE WHEN (due_cnt + outside_cnt) = 0 THEN 0
       ELSE ROUND((outside_cnt + on_time_cnt + overdue_completed_cnt)::numeric
                / (due_cnt + outside_cnt)::numeric * 100, 2)
  END AS "节点完成百分比"
FROM stats
  [[AND project_no ILIKE '%' || {{projectNo}} || '%']]
```

## #16 节点已经不正常待变更的百分比

**维度**：项目（除一般节点）  
**依赖字段**：`plan_date`、`completion_status`、`node_type`  
**计算逻辑**：`(#12 + #13) / #3`

> ⚠️ 分子用 `<= 结束时间` 累计快照（不含一般节点），分母用 `BETWEEN [开始,结束]` 周期内（含一般节点）。这是文档原文的口径，存在分子分母维度不一致问题。

```sql
WITH stats AS (
  SELECT
    -- #12 + #13 分子
    COUNT(*) FILTER (
      WHERE plan_date::date <= {{dateTo}}
        AND completion_status IN ('不正常待变更','超期未完成未变更')
        AND node_type != '一般节点'
    ) AS abnormal_numerator,
    -- #3 分母
    COUNT(*) FILTER (
      WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
        AND completion_status != '正常待完成'
    ) AS due_cnt
  FROM ods_project_subject_domain_v2
)
SELECT
  abnormal_numerator AS "不正常待变更加超期未变更_分子",
  due_cnt AS "已到时间节点_分母",
  CASE WHEN due_cnt = 0 THEN 0
       ELSE ROUND(abnormal_numerator::numeric / due_cnt::numeric * 100, 2)
  END AS "节点已经不正常待变更的百分比"
FROM stats
  [[AND project_no ILIKE '%' || {{projectNo}} || '%']]
```

## #26 里程碑节点完成总百分比

**维度**：项目（本周期内节点）  
**依赖字段**：`plan_date`、`completion_status`、`node_type`  
**计算逻辑**：`(#23 + #24) / (#20 + #23 + #24)`

```sql
WITH stats AS (
  SELECT
    COUNT(*) FILTER (
      WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
        AND node_type = '里程碑节点'
        AND completion_status = '按时完成'
    ) AS milestone_on_time_cnt,
    COUNT(*) FILTER (
      WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
        AND node_type = '里程碑节点'
        AND completion_status IN ('超期已完成未变更','超期已完成已变更')
    ) AS milestone_overdue_completed_cnt,
    COUNT(*) FILTER (
      WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
        AND node_type = '里程碑节点'
        AND completion_status IN ('不正常待变更','超期未完成未变更','超期未完成已变更')
    ) AS milestone_incomplete_cnt
  FROM ods_project_subject_domain_v2
)
SELECT
  (milestone_on_time_cnt + milestone_overdue_completed_cnt) AS "里程碑完成数_分子",
  (milestone_incomplete_cnt + milestone_on_time_cnt + milestone_overdue_completed_cnt) AS "里程碑总数_分母",
  CASE WHEN (milestone_incomplete_cnt + milestone_on_time_cnt + milestone_overdue_completed_cnt) = 0 THEN 0
       ELSE ROUND((milestone_on_time_cnt + milestone_overdue_completed_cnt)::numeric
                / (milestone_incomplete_cnt + milestone_on_time_cnt + milestone_overdue_completed_cnt)::numeric * 100, 2)
  END AS "里程碑节点完成总百分比"
```

如果需要一次性导出全部 67 个指标的当前值，可以把上面所有 SQL 包成 UNION ALL，但更推荐的是按域分组运行。下面给一个**进度域所有计数指标**的合并示例（不包含比率类）：

```sql
-- 进度域 #1-8, #12-15, #18-31 的所有计数（合并查询）
WITH params AS (
  SELECT {{dateFrom}}::date AS start_date, {{dateTo}}::date AS end_date
), src AS (
  SELECT
    plan_date::date AS pd,
    actual_date,
    completion_status,
    node_type,
    risk_level
  FROM ods_project_subject_domain_v2
), p AS (SELECT * FROM params)
SELECT
  -- #1
  (SELECT COUNT(*) FROM src, p WHERE pd BETWEEN start_date AND end_date)
    AS "#1_项目本周期节点总数",
  -- #2
  (SELECT COUNT(*) FROM src, p WHERE pd BETWEEN start_date AND end_date AND completion_status='正常待完成')
    AS "#2_正常待完成",
  -- #5
  (SELECT COUNT(*) FROM src, p WHERE pd BETWEEN start_date AND end_date
    AND completion_status IN ('不正常待变更','超期未完成未变更','超期未完成已变更'))
    AS "#5_未完成总数",
  -- #6
  (SELECT COUNT(*) FROM src, p WHERE pd BETWEEN start_date AND end_date AND completion_status='按时完成')
    AS "#6_按时完成数",
  -- #7
  (SELECT COUNT(*) FROM src, p WHERE pd BETWEEN start_date AND end_date
    AND completion_status IN ('超期已完成已变更','超期已完成未变更'))
    AS "#7_超期完成数",
  -- ... 其他指标按需添加
  '修改 params CTE 中的 start_date / end_date' AS "用法提示"
  [[AND project_no ILIKE '%' || {{projectNo}} || '%']]
```

## C. 常见问题排查

### Q1: 执行报错 `invalid input syntax for type date: "..."`
原因：ODS 数据中存在非标准日期格式（如 `'2025/01/15'` 或 `'#N/A'`）。
解决：在 WHERE 中加正则兜底过滤：

```sql
WHERE plan_date ~ '^\d{4}-\d{2}-\d{2}$'
  AND plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
```

### Q2: 某个指标返回 0，但应该有数据
排查顺序：
1. 去掉所有 WHERE 条件，确认表有数据：`SELECT COUNT(*) FROM ods_xxx_v2;`
2. 单独检查日期范围：`SELECT COUNT(*) FROM ods_xxx_v2 WHERE plan_date::date BETWEEN ...;`
3. 单独检查枚举值：`SELECT DISTINCT completion_status FROM ods_xxx_v2;` 看实际值是否与文档一致
4. 如果是 #36-39、#41-48、#52-67，检查是否是 ⚠️ 标注的枚举不一致问题

### Q3: 想按"项目"或"科室"维度细分
在每个 SQL 的 SELECT 子句中加 `project_no` 或 `dept`，并在末尾加 `GROUP BY project_no, dept`。例如 #1：

```sql
SELECT project_no, dept, COUNT(*) AS "项目本周期节点总数"
FROM ods_project_subject_domain_v2
WHERE plan_date::date BETWEEN {{dateFrom}} AND {{dateTo}}
  [[AND project_no ILIKE '%' || {{projectNo}} || '%']]
GROUP BY project_no, dept
ORDER BY project_no, dept
```
