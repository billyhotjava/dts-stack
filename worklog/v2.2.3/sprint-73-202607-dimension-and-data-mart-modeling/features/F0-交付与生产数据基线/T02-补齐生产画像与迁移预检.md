# T02: 补齐生产画像与迁移 dry-run

**优先级**: P0  
**状态**: READY  
**依赖**: T01（数据库只读访问）

## 目标

用客户生产脱敏副本确定 DataMart/维度迁移的真实容量、空值、重复和未解析引用，禁止自动猜测。

## 技术设计 (Contract-first)

- **输入契约**: 只读数据库；表 `catalog_domain`、`modeling_warehouse_plan*`、`modeling_dimension_definition*`、`modeling_model_spec*`。
- **输出契约**: `assets/migration-dry-run.md`，含 `runId/sourceChecksum/counts/unresolved[]/warnings[]`。
- **数据流**: 只读 SQL → 聚合统计 → checksum → 人工审查清单。
- **错误路径**: 表/列缺失、权限不足、查询超时均停止，不用当前本地数据替代。
- **复用点**: Sprint-67 维度 migration ledger、DTS C3/C4 dry-run 规则。
- **实现方案**:
  1. 统计分类/计划/维度/维度表/引用数量与增长；
  2. 统计分类 code/owner 空值和重复；
  3. 统计同 plan+definition 的活动实现重复；
  4. 输出未绑定 definition 和不可解析 domain 的模型；
  5. 只形成报告，不更新任何表。

## 影响范围

只读数据库；新增 `assets/migration-dry-run.md`。

## 验证

- [ ] SQL 可重复运行且无写权限
- [ ] 总数与分组数守恒
- [ ] unresolved 每项包含稳定 ID，不含敏感业务数据

## Definition of Done

- [ ] 生产画像回写 `assets/domain-profile.md`
- [ ] 迁移策略按实测结果确认
- [ ] F2～F4 容量假设不再依赖本地样本
