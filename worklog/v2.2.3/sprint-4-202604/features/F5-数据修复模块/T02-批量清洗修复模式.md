# T02: 批量清洗修复模式

**优先级**: P0
**状态**: READY
**依赖**: F2, F3

## 目标
湖内数据修复的主路径——自动匹配清洗函数，预览修复效果，确认后批量执行，残余转人工。

## 技术设计

### 流程
```
选择修复任务（来自失败的 QualityRun）
  → 系统匹配可用清洗函数
  → 预览前10行修复前后对比
  → 显示"可自动修复 N 行 / 无法修复 M 行"
  → 用户确认执行
  → 执行完成 → 提示"剩余 M 行需人工处理"→ 跳转人工编辑
```

### 函数匹配逻辑
根据规则类型自动推荐：
- 完整性（REQUIRED）→ `FILL_DEFAULT`
- 准确性（枚举）→ `ENUM_MAP`
- 一致性（日期格式）→ `DATE_NORMALIZE`
- 文本清洗 → `TRIM` / `UPPER_CASE`
- 数值含单位 → `STRIP_UNIT`

### 预览 API
```
POST /api/governance/quality/cleansing/preview
{
  runId, functionId, limit: 10
}
→ {
  affectedRows: 144,
  unresolvableRows: 12,
  samples: [{ rowId, before, after }]
}
```

### 安全约束
- 仅允许对 `ods_*` 前缀表执行
- 执行前记录 snapshot（审计日志）
- 不可回滚，但可通过审计日志追溯

## 影响范围
- `DataCleansingService`：新增 preview + 按 runId 批量执行
- 新增前端 `BatchCleansingDialog.tsx` 组件
- `GovernanceResource`：新增 preview API

## 验证
- [ ] 日期格式异常 → 推荐 DATE_NORMALIZE → 预览正确
- [ ] 执行后失败行减少，残余行标记
- [ ] 审计日志记录修复操作

## 完成标准
- [ ] 匹配 → 预览 → 执行 → 残余转人工 全流程
