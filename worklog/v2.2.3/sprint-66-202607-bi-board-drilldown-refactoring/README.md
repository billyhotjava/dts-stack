# Sprint-66：BI 大屏通用下钻重构

**时间**：2026-07
**状态**：DONE
**类型**：Frontend Refactor / Generic Interaction / Backward Compatibility
**目标**：将大屏下钻建设为领域无关、数据源无关的交互通道，使新业务接入只需配置字段映射和目标动作，不再开发专用下钻代码。

## 1. 背景

当前大屏已经具有组件动作、运行变量、Card 下钻、页面跳转、详情面板和多数据源查询能力，但下钻仍绑定 `cardId + paramName + clickedValue`，设计器也只允许 Card 配置下钻。项目管理、PLM、ERP、财务、考勤、专利、MES 等只是可接入系统示例，DTS 核心不得理解或固化这些领域知识。

本 Sprint 只建设以下通道：

```text
组件点击 → 提取点击记录 → 映射目标参数 → 执行目标动作
         → 记录历史状态 → 上卷 / 返回 / 重置
```

## 2. 设计决策

| 方案 | 结论 | 原因 |
|---|---|---|
| A. 前端通用交互内核 | 采用 | 复用现有 ScreenConfig、数据源适配器和运行变量，改动最小 |
| B. 后端下钻编排服务 | 不采用 | 增加服务、存储和发布复杂度，不符合最小功能原则 |
| C. 语义模型自动推断层级 | 不采用 | 形成业务语义前置依赖，容易绑定领域知识 |

详细设计见 [最小通用下钻设计](assets/minimal-generic-drilldown-design.md)，执行步骤见 [实施计划](assets/implementation-plan.md)。

## 4. 全局约束

1. 核心类型、运行时代码和配置协议不得出现项目、BOM、凭证、工单等领域专属字段或判断。
2. 不新增数据库表、后端编排服务或语义模型前置依赖。
3. 复用 `ScreenComponentAction`、`ComponentInteractionMapping`、`DataSourceConfig` 和运行变量，不建立第二套交互协议。
4. SQL、API、Card、Dataset、Metric 数据源必须使用同一套参数映射和下钻状态。
5. `cardId + paramName` 历史配置必须在读取时兼容，禁止批量破坏式迁移。
6. 外部跳转只传递白名单映射字段；目标页面或数据源继续执行自身权限校验。
7. Chrome 95 是交付约束；不得引入其不支持且构建未转译的语法。
8. 所有实现任务遵循先红后绿的测试闭环，最终提交前执行 GitNexus 变更范围检查。

### 6.1 UI 组件下钻完成标准

| UI 组件 | 用户触发方式 | 必须传递的通用点击载荷 | 通过条件 |
|---|---|---|---|
| 柱状图、条形图、堆叠柱状图 | 点击具体柱体或堆叠分段 | `name`、`seriesName`、`value`、`data` | 只下钻被点击的数据项，下一层刷新且面包屑增加一级 |
| 饼图、环图 | 点击具体扇区 | `name`、`value`、`percent`（可取得时）、`data` | 只下钻被点击扇区，不因点击圆心空白或图例触发 |
| 折线图、面积图 | 点击具体数据点 | `name`、`seriesName`、`value`、`data` | 参数来自被点击数据点，不使用当前可视范围猜测值 |
| 散点图 | 点击具体散点 | `name`、`seriesName`、`value`、`data` | 多维 value 和原始 data 均可通过 `sourcePath` 映射 |
| 漏斗图 | 点击具体阶段 | `name`、`value`、`data` | 只下钻被点击阶段，排序和视觉位置不改变参数含义 |
| 雷达图 | 点击可识别的系列数据项 | `name`、`seriesName`、`value`、`data` | 映射来源是事件载荷，不把指标名称硬编码为参数 |
| 组合图 | 点击柱体或折线数据点 | `name`、`seriesName`、`value`、`data` | 柱系列与线系列走同一动作执行器且不会重复触发 |
| 矩形树图、旭日图 | 点击具体节点或扇区 | `name`、`value`、`data`、节点路径（可取得时） | DTS 使用实际节点载荷推进，不理解节点业务含义 |
| 地图 | 点击具体区域或标记点 | `name`、`value`、`data` | 区域/点位名称可映射；拖拽、缩放和空白点击不触发下钻 |
| 普通表格、滚动表格 | 点击数据行或已配置的操作单元格 | 列名字段、`row[n]`、完整 row | 参数来自被点击行；表头、分页、滚动条点击不触发 |
| KPI、数字卡、统计卡、仪表盘 | 点击卡片的数据展示区域 | 当前组件的数据记录或标量值 | 允许进入详情视图/面板；装饰区域点击不重复执行 |

所有 UI case 还必须同时满足：

- [x] 仅配置了下钻或动作的组件显示可点击光标/悬浮反馈；未配置组件保持原样。
- [x] 单次点击只推进一级，加载期间连续点击不得生成重复面包屑或重复查询。
- [x] 点击图表空白区、图例、坐标轴、标题、表头、滚动条和分页控件不得误触发下钻。
- [x] 点击项缺少必需映射字段时保持当前层，并给出可理解提示或运行事件，不发送空参数查询。
- [x] 查询失败时保留当前画面和返回/重置能力，不出现白屏或无法退出的下钻层级。
- [x] 下钻、上卷、重置后，图表 tooltip、图例切换、地图缩放、表格滚动和分页等原生交互不受破坏。
- [x] 上述 UI case 在设计器预览和发布后大屏中行为一致，并至少完成一次 Chrome 95 实机验收。

## 7. 明确不做

- 不建设业务对象、维度层级、关系路径或行业知识模型。
- 不让 DTS 自动推断下一层业务含义。
- 不新增项目、PLM、ERP、财务、考勤、专利或 MES 专用页面与组件。
- 不改造指标、数据集或 SQL 的业务口径。
- 不移除 `jump-url`、旧 `interaction` 或旧 `cardId` 配置。
- 不在本 Sprint 引入跨大屏 URL 状态分享和长期持久化历史。
