# T03: 指标监控与告警方案设计

**优先级**: P1
**状态**: READY
**依赖**: 无

## 目标
设计基于现有 Prometheus 端点的指标收集、仪表盘展示和告警通知方案。

## 技术设计

### 现状
- Traefik 已暴露 Prometheus metrics（port 9100）
- Spring Boot Actuator 已开启 `/management/prometheus` 端点
- 但无 Prometheus 实例采集、无 Grafana 展示、无告警规则
- 服务健康状态仅依赖 Docker healthcheck（无外部告警）

### 设计要点
1. **指标采集**: Prometheus 部署和 scrape 配置
2. **应用指标**:
   - JVM 指标（heap、GC、线程）
   - HTTP 请求指标（QPS、延迟、错误率）
   - 数据库连接池指标（HikariCP）
   - 业务指标（任务执行数、失败率）
3. **基础设施指标**:
   - PostgreSQL: pg_exporter
   - Docker: cAdvisor
   - 主机: node_exporter
4. **Grafana 仪表盘**: 预置 dashboard 模板
5. **告警规则**:
   - 服务宕机（up == 0）
   - 高错误率（5xx > 阈值）
   - 数据库连接池耗尽
   - 磁盘空间不足
   - ETL 任务连续失败
6. **告警通知**: 离线环境下的通知渠道（邮件 / webhook / 企业微信）
7. **资源开销**: Prometheus + Grafana 的内存/存储需求

## 影响范围
- `docker-compose.yml`: 新增 Prometheus、Grafana、exporter 服务
- Traefik 配置: 确保 metrics 端点可被 Prometheus 访问
- Spring Boot: 确认 actuator 指标端点开启
- `.env`: 新增监控相关配置
