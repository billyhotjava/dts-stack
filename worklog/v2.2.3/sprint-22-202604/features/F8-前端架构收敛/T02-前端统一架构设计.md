# T02: 前端微前端/统一架构设计

**优先级**: P2
**状态**: READY
**依赖**: 无

## 目标
设计三个前端 webapp 的架构统一方案，解决 UI 库不统一、状态隔离、用户体验断裂问题。

## 技术设计

### 现状
- 三个独立 webapp: admin-webapp、platform-webapp、analytics-webapp
- UI 库不统一: admin/platform 用 antd，analytics 用自研 UI 库（`modern/src/ui/`）
- 状态隔离: 各 webapp 独立维护 Keycloak token 和用户状态
- 路由隔离: 各 webapp 独立的路由和构建配置
- Sprint-21 计划: React 19.1 + Tailwind 全量

### 设计要点
1. **架构模式选型**:
   - Module Federation（Webpack 5 / Vite）: 运行时组合
   - single-spa: 微前端框架
   - iframe 嵌入: 最简方案但体验差
   - 合并为单体: 最彻底但改动最大
2. **共享层设计**:
   - 认证/会话: 统一 Keycloak token 管理
   - 主题/样式: 统一设计系统（Tailwind 对齐 Sprint-21）
   - 路由/导航: 统一顶部导航 + 侧边栏
   - 状态: 跨应用共享用户上下文
3. **analytics-webapp UI 收敛**: 自研 UI -> antd/Tailwind 的迁移策略
4. **构建优化**: 共享依赖的 chunk 策略
5. **Chrome 95 兼容**: 微前端方案的浏览器兼容性
6. **渐进式迁移**: 从当前架构到目标架构的分步计划

### 需要回答的问题
- admin-webapp 和 platform-webapp 是否可以合并？
- analytics-webapp 的自研 UI 组件数量和复杂度？
- 是否需要支持独立部署（某些客户只需部分功能）？

## 影响范围
- 三个 webapp 的构建配置（vite.config.ts）
- 前端路由体系
- Keycloak 客户端配置
- Traefik 路由规则
