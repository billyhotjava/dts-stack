# T18: 执行流程与轮询优化（适应性退避 + 取消）

**优先级**: P0
**状态**: READY
**依赖**: T16

## 目标

改造执行流程：适应性轮询退避、可靠取消、状态流畅更新。

## 技术设计

### 轮询退避策略

当前 1.5s 硬编码 → 改为：

```
500ms → 1.5s → 3s → 5s → 5s ... (封顶 5s)
```

- 目的：短查询响应快，长查询少发请求
- 实现：`useSqlExecution` hook 内 setTimeout 递推

### 执行 Hook

```typescript
function useSqlExecution(tabId: string) {
  const [state, setState] = useState<'idle'|'running'|'success'|'failed'|'canceled'>();
  const submit = async (sql: string) => { ... };
  const cancel = async () => { ... };
  return { state, elapsedMs, rowCount, executionId, submit, cancel };
}
```

### 取消可靠性

- 前端 `cancel()` 调 `POST /api/sql/cancel/{id}`
- 后端已有 `markCanceled()`（`SqlExecutionService`）
- 前端取消后立即停止轮询，UI 状态转 `canceled`
- 服务端 future.cancel + 标记表，现有逻辑不改

### 状态与 UI

- 执行按钮按下 → `Run` 变 `Cancel`（红色）
- 结果区显示 loading + "已耗时 X.Xs" 实时刷新
- 状态转最终态时停止轮询，加载结果

### 取消审计

- `SQL_EXECUTE_CANCEL` 字段增加 `reason`: `user` / `timeout`（预留）

## 影响范围

- 新增 `hooks/useSqlExecution.ts`
- 在 `SqlEditor` 的 Ctrl+Enter 和工具栏 Run 按钮调用
