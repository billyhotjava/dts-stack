# T03: 慢查询熔断 + 使用度统计

**优先级**: P0
**状态**: READY
**依赖**: F2, F3/T04

## 目标

三件事：
1. **超时熔断**：单查询最长 30 秒（默认），超过杀掉并告警
2. **并发限流**：每用户最多 3 个并发查询，超出排队
3. **使用度统计**：每个 VDS / Card / metric 的查询次数、平均耗时、最近使用时间，面板可见，供 T04 promote 决策参考

这些是"治理"的数字基础——没数据就没办法管理 VDS 的生命周期。

## 技术设计

### 1. 查询超时

- 默认 30s，通过 `application.yml` 可配 `semantic.query.timeout_seconds`
- 实现：
  - Spring `@Async` + `CompletableFuture.orTimeout`
  - 或用 JDBC `Statement.setQueryTimeout(int)`（推荐：DB 侧 cancel query）
- 超时触发：
  - 响应 504 + `X-Semantic-Timeout: true`
  - 审计 `semantic.query.timeout` 记下 SQL fingerprint + user + model
  - 记录到"慢查询榜"

### 2. 并发限流

每个用户同时最多 N 个 running query（默认 3）。超过返回 429 + "当前查询过多，请稍候"。

实现：
- Redis 计数器：`semantic:running:<user_id>`，查询开始 INCR，结束 DECR
- 设置 TTL 45 秒（防止异常导致的泄漏）
- Limiter 写成 AOP 切面包 `SemanticQueryResource.query()`

### 3. 使用度统计表

```sql
CREATE TABLE gov_semantic_query_stat (
    id BIGSERIAL PRIMARY KEY,
    stat_day DATE NOT NULL,
    user_id VARCHAR(64) NOT NULL,
    virtual_dataset_id VARCHAR(32),     -- 可为空
    card_id VARCHAR(64),                 -- 可为空
    base_model VARCHAR(128) NOT NULL,
    measure_ids TEXT,                    -- comma-separated
    dimension_ids TEXT,
    query_count INT NOT NULL DEFAULT 0,
    total_elapsed_ms BIGINT NOT NULL DEFAULT 0,
    cache_hit_count INT NOT NULL DEFAULT 0,
    timeout_count INT NOT NULL DEFAULT 0,
    error_count INT NOT NULL DEFAULT 0,
    UNIQUE (stat_day, user_id, virtual_dataset_id, card_id)
);
```

每天一条记录，UPSERT。查询后台 task 聚合 Redis 计数器刷到这张表，保留 180 天。

### 4. Redis 实时计数

每次查询结束（含成功/失败）：
```
INCR semantic:qstat:<date>:<user>:<vds_or_card>:count
INCRBY ... :elapsed elapsed_ms
INCR ... :cache_hit (if hit)
```

定时任务每 5 分钟 dump 到 PG 表。

### 5. 面板端点

- `GET /api/semantic/virtual-datasets/:id/stats` — 单 VDS 使用度
- `GET /api/semantic/cards/:id/stats` — 单 Card 使用度
- `GET /api/admin/semantic/slow-queries?since=7d` — 管理员慢查询榜
- `GET /api/semantic/my/usage` — 当前用户自己的查询统计

### 6. Promote 决策支持

VDS 详情页显示：
```
┌────────────────────────────────────────┐
│ 使用度（近 30 天）                     │
│ ─────────────────────                  │
│ 查询次数：       124                    │
│ 被 Card 引用：   3                      │
│ 平均耗时：       456 ms                 │
│ 缓存命中率：     72 %                   │
│                                        │
│ 💡 该 VDS 已稳定使用 30+ 天，建议提升  │
│    为 dbt model                        │
│                                        │
│ [提升到 dbt]                            │
└────────────────────────────────────────┘
```

"建议提升"触发条件（T04 会接）：
- 创建后 ≥ 30 天
- 近 30 天查询 ≥ 50 次
- 被 ≥ 2 个 Card 引用

### 7. 熔断告警

慢查询 p99 超过 10 秒（5 分钟窗口）或 QPS > 100 → 主动告警：
- 审计表写 `semantic.alert`
- 钉钉/企微 webhook（若已配）
- 管理员面板红点

### 8. 前端显示

- Card 详情页显示 "近 7 天查询 X 次 / 平均耗时 Y ms"
- VDS 列表显示用量条形图
- 慢查询对用户侧透明（只在失败时提示）

### 9. 熔断开关

`application.yml`:
```yaml
semantic:
  query:
    timeout_seconds: 30
    max_concurrent_per_user: 3
    circuit_breaker:
      enabled: true
      p99_threshold_ms: 10000
      qps_threshold: 100
```

所有默认值可在 dev / staging 调整。
