# T02: 密级传导与脱敏视图策略

**优先级**: P0
**状态**: READY
**依赖**: F2/T04

## 目标

把 F2/T04 SecurityInjector 的基础能力在**端到端**层面补全：
- 查询结果密级 = 所有参与表的最高密级（传导规则）
- 用户密级超限查询在 **compile 阶段** 拦截（不让 SQL 跑）
- 高密级列通过 **数据库视图** 脱敏（`<model>_masked`），编译器切换引用
- 画布节点 / 指标树节点 **视觉标注密级**
- 密级变更审计

## 技术设计

### 1. 密级传导规则

```
query.effective_security_level
  = max(
      base_model.security_level,
      each(joined_model.security_level),
      each(column.security_level referenced)
    )
```

**拦截逻辑**（前置到编译前）：

```java
if (effectiveLevel.compareTo(user.getSecurityLevel()) > 0 && !isOpAdmin(user)) {
    throw new SemanticException(422, "SECURITY_LEVEL_EXCEEDED",
        "Query requires " + effectiveLevel + " but user is " + user.getSecurityLevel());
}
```

### 2. 脱敏视图策略

dbt 侧约定：
- 对有敏感列的 model，dbt 生成 `<model>_masked` 视图
- 视图里敏感列替换为 `'***'::text AS <col>`
- 其他列照常
- 脱敏视图在 manifest 里有 `meta.dts.masked_of = "<original_model>"` 标记

编译时：
- 若某列 `security_level > user.security_level` 但列的 model 密级本身 user 能访问：
  - 不让 SQL 引用原始列，改引用 `<model>_masked.<col>`
  - 若该 model 无脱敏视图：编译失败（dbt 侧缺视图是工程师 bug）

### 3. SecurityInjector 扩展

```java
public CompiledQuery inject(CompiledQuery q, UserClaims user) {
    q = checkOverallLevel(q, user);      // 422 if exceed
    q = rewriteMaskedColumns(q, user);   // 替换列引用为 masked 视图
    q = injectRowLevelPredicates(q, user); // F2/T04 已实现
    return q;
}
```

### 4. 前端视觉

**指标树节点**：
- 密级徽章：绿 PUBLIC / 蓝 INTERNAL / 橙 SENSITIVE / 红 CONFIDENTIAL
- 超限字段：灰色 + 🔒 + "你的访问密级不足"

**画布节点**：
- 卡片左上角密级色条
- 当前用户密级不足 → 节点整体灰色 + 禁止拖拽

**SQL 预览**：
- 顶部 Banner 显示：`当前查询有效密级 = INTERNAL`
- 若启用了脱敏视图：`注意：列 [phone_number] 将被脱敏`

**Card 展示**：
- Card 详情页顶部显示密级徽章
- 导出数据时如果包含脱敏列，CSV 里也是 `***`，不泄漏

### 5. 密级变更审计

若 dbt 改了某 model 的 `meta.dts.security_level`：
- `ManifestIngestor.diff()` 检测到变更
- 记审计 `semantic.security.level_change`
- 失效该 model 所有相关 cache（`ResultCache.invalidateByModel(modelName)`）
- 给所有引用该 model 的 Card / VDS owner 发通知（用现有消息中心）

### 6. OP_ADMIN 旁路显示

OP_ADMIN 执行查询时：
- SQL 预览顶部显示红色 Banner "⚠ 管理员模式：安全上下文未应用"
- 结果表格右上角加水印
- 审计日志记录

### 7. dbt 侧工具

配合本 Task，在 `source/dts-dbt/macros/` 下加一个 macro：

```jinja
-- create_masked_view.sql
{% macro create_masked_view(original_model, masked_columns) %}
  SELECT
    {% for col in columns -%}
      {% if col in masked_columns -%}
        '***'::text AS {{ col }}
      {%- else -%}
        {{ col }}
      {%- endif -%}
      {% if not loop.last %},{% endif %}
    {%- endfor %}
  FROM {{ ref(original_model) }}
{% endmacro %}
```

使用：
```sql
-- models/marts/ads_sales_daily__masked.sql
{{ config(materialized='view', alias='ads_sales_daily_masked') }}
{{ create_masked_view('ads_sales_daily', ['phone_number', 'email']) }}
```

这张视图被 `ManifestIngestor` 识别，自动建立"原始 → 脱敏"映射。

### 8. 测试矩阵

| 场景 | 用户密级 | 查询 | 期望 |
|---|---|---|---|
| 查 INTERNAL model | INTERNAL | OK | 200 |
| 查 CONFIDENTIAL model | INTERNAL | 拒绝 | 422 |
| 查含 SENSITIVE 列的 INTERNAL model | INTERNAL | 脱敏 | 列返回 *** |
