# T03: 函数白名单执行器与错误码

**优先级**: P0
**状态**: READY
**依赖**: T01

## 目标

把 F1-T03 规定的函数白名单实现为**一个集中注册表**，让 grammar 的 `FunctionCall` 节点在 parse/semantic/compile 三个阶段都有统一的校验依据。任何白名单外的函数直接拒绝，任何签名不匹配直接拒绝。

## 技术设计

### 1. 函数注册表

```java
public enum FunctionRegistry {
    INSTANCE;

    private final Map<String, FunctionSpec> functions = new HashMap<>();

    public record FunctionSpec(
        String name,
        ArgSchema[] args,                  // 参数规范
        ValueType returnType,
        boolean isAggregate,
        boolean isWindow,
        boolean implementedInPhase1
    ) {}

    public record ArgSchema(
        String name,
        EnumSet<ValueType> allowedTypes,   // {NUMBER}
        boolean nullable,
        boolean mustBeMetricRef            // 如 sum 的参数必须是 metric 引用
    ) {}
}
```

初始化（见 spec F1/T03）：
```java
register(new FunctionSpec("sum", new ArgSchema[]{metricNumber}, NUMBER, true, false, true));
register(new FunctionSpec("count", new ArgSchema[]{metricAny}, NUMBER, true, false, true));
register(new FunctionSpec("count_distinct", new ArgSchema[]{metricAny}, NUMBER, true, false, true));
register(new FunctionSpec("ratio", new ArgSchema[]{number, number}, NUMBER, false, false, true));
register(new FunctionSpec("growth", new ArgSchema[]{metricNumber, positiveInt}, NUMBER, false, true, true));
register(new FunctionSpec("share", new ArgSchema[]{metricNumber, dimension}, NUMBER, false, true, true));
register(new FunctionSpec("if", new ArgSchema[]{boolean_, any, any}, INFERRED, false, false, true));
register(new FunctionSpec("coalesce", new ArgSchema[]{any, any, any_variadic}, INFERRED, false, false, true));
register(new FunctionSpec("case_when", ..., INFERRED, false, false, true));
register(new FunctionSpec("format_number", ...));
register(new FunctionSpec("format_percent", ...));
register(new FunctionSpec("format_currency", ...));
// 保留但 Phase 1 不实现：
register(new FunctionSpec("cumulative", ..., implementedInPhase1=false));
register(new FunctionSpec("moving_avg", ..., implementedInPhase1=false));
register(new FunctionSpec("median", ..., implementedInPhase1=false));
```

### 2. 三阶段校验

**Parse 阶段**（T01）：语法允许任意 ident 作为函数名。

**Semantic 阶段**（T01 的 SemanticAnalyzer）：
```java
FunctionSpec spec = FunctionRegistry.INSTANCE.lookup(name);
if (spec == null) throw DslError.E010("Function not whitelisted: " + name);
if (spec.args.length != actualArgs.size() /* or variadic check */)
    throw DslError.E011("Arg count mismatch");
for (each arg) check type;
if (arg.mustBeMetricRef && !(argAST instanceof Reference))
    throw DslError.E052("Argument must be metric reference");
```

**Compile 阶段**（T02）：
```java
if (!spec.implementedInPhase1)
    throw DslError.E050("Function not implemented in Phase 1");
```

### 3. 错误码（补充 T01 清单）

| 码 | 含义 |
|---|---|
| DSL_E010 | 函数不在白名单 |
| DSL_E011 | 函数参数数量错 |
| DSL_E050 | 函数 Phase 1 不支持（但 grammar 里保留） |
| DSL_E051 | 聚合函数不能嵌套聚合函数 |
| DSL_E052 | 参数必须是 metric reference |
| DSL_E053 | `growth()` / `share()` 需要 time_dimension / 相应 dimension 上下文 |

### 4. 不可嵌套规则

```
sum(count([x]))          → DSL_E051 聚合嵌套
sum([x] + [y])           → OK（聚合内非聚合）
if(sum([x]) > 0, ..., ...) → OK（if 内聚合）
```

在 SemanticAnalyzer 做 walk-down 检测。

### 5. 函数文档输出

把 FunctionRegistry 的内容序列化成 JSON：`GET /api/semantic/functions`，供前端派生指标编辑器做自动提示和文档 tooltip。

格式：
```json
[
  {
    "name": "ratio",
    "category": "比例",
    "signature": "ratio(numerator: number, denominator: number) → number",
    "description_zh": "安全比例，分母为 0 时返回 null",
    "description_en": "...",
    "examples": ["ratio([revenue], [order_count])"]
  }
]
```

### 6. 版本化

FunctionRegistry 绑 `spec_version`。grammar 或函数表改动 → spec_version bump → 老虚拟数据集如用到被移除的函数，加载时提示用户迁移。

### 7. 测试矩阵

| 场景 | 期望 |
|---|---|
| 未知函数 `raw_sql(...)` | DSL_E010 |
| 参数少 | DSL_E011 |
| 参数多 | DSL_E011 |
| `sum` 参数非 reference | DSL_E052 |
| 聚合嵌套聚合 | DSL_E051 |
| Phase 2 未实现函数被调用 | DSL_E050 |
| 类型错 `sum([region])` | DSL_E020 (string) |
| variadic 函数（coalesce）多参数 OK | 通过 |
