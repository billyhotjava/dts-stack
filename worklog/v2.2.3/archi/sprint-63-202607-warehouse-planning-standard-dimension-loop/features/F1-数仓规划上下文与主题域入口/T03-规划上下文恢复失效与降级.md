# T03: 规划上下文恢复、失效与降级

**优先级**: P0  
**状态**: DONE
**依赖**: T01

## 目标

让客户刷新或 session storage 不可用时仍能得到明确的恢复结果，不出现伪成功。

## 技术设计

- 版本不兼容时丢弃旧草稿并提示重新创建。
- storage 异常时使用 URL 的最小上下文，提示刷新后需要重新选择规划。
- 缺少 `domainId` 或建模模式不一致时显示 blocker（session 草稿为权威，见设计文档 3.2）。
- **跨存储失效场景**：旅程快照（localStorage）恢复出带 `planningId` 的 URL 但 session 草稿已失效（重开浏览器）——按 URL 最小上下文降级并提示重新确认规划。

## 影响范围

- `warehousePlanningContext.ts`（恢复/降级分支）与其测试
- `SubjectAreasPage.tsx` blocker 呈现（与 T02 同文件协作）

## 验证

- [x] 覆盖版本失效、storage 抛错、快照恢复但 session 失效三类场景。
- [x] blocker 包含恢复动作，不显示 done。
