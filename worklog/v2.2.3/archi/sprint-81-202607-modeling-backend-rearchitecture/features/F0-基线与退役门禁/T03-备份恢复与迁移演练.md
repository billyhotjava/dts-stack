# T03：备份恢复与迁移演练

**优先级**：P0
**状态**：PLANNED
**依赖**：T02；隔离恢复库与受控备份位置

## 目标

证明待删数据可从精确备份恢复，并让 dry-run/apply/verify/rollback 在代表存量库上可重复执行。

## 技术设计（Contract-first）

- **输入契约**：通过校验的 data profile、source table manifest、目标 schema revision。
- **输出契约**：`BackupEvidence`、`MigrationManifest`、restore/rollback result。
- **备份**：只含待删 schema/data 及必要依赖；记录 databaseId、URI、size、SHA-256、起止时间、操作者。
- **演练**：旧版本代表库 → backup → dry-run（零写）→ apply（有界批次）→ verify → drop → 隔离 restore → checksum 对账。
- **回滚**：按 manifest 精确撤销本批 target，不清空整库，不覆盖演练期间他人数据。
- **错误路径**：备份不可读、checksum 不符、restore 失败、RTO 超窗、manifest conflict/orphan 均阻断 F5。

## 影响范围

隔离数据库、迁移命令和备份存储；生产只在批准维护窗口执行精确备份。

## 验证

- [ ] dry-run 的数据库写计数为 0。
- [ ] 重复 apply 不新增 revision/candidate/outbox。
- [ ] source/target count、主键、revision、payload checksum、CatalogAssetKey 一致。
- [ ] restore 后对象级 checksum 与备份一致，记录实测 RTO/RPO。

## Definition of Done

- [ ] 当前环境和代表存量环境演练通过。
- [ ] 客户 RTO/RPO 与维护窗口获确认；否则客户 DROP 保持 NO_GO。
- [ ] 备份可定位、可校验、可恢复且访问受控。
