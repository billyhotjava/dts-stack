# T02：客户存量画像与停机判定

**优先级**：P0
**状态**：PLANNED
**依赖**：T01；客户只读数据库、日志与调用方清单授权

## 目标

逐环境证明待退役数据是零数据或已精确迁移，并在维护窗口内阻断任何画像漂移。

## 技术设计（Contract-first）

- **输入契约**：environmentId、databaseId、schema revision、待退役表/route 清单、只读连接。
- **输出契约**：`EnvironmentDataProfile` 与 `PreDropDecision {decision:GO|NO_GO,reasons,profileChecksum,observedAt}`。
- **画像维度**：tenant 总数、状态、空值、孤儿 FK、源/目标映射、最大更新时间、30/90 天 route/caller/last_seen。
- **停机判定**：写屏障生效后复跑；`source>0 && mapped!=source-ignored`、conflict/orphan>0、caller>0、checksum 漂移任一出现即 NO_GO。
- **安全**：SQL 只读、statement timeout、有界结果、脱敏汇总；不采集业务 payload。
- **错误路径**：权限不足、schema 不匹配、超时或缺日志均视为未知并阻断，不降级为本地 0 行结论。

## 影响范围

客户/测试数据库和访问日志只读；不修改业务 metadata，不开启删除。

## 验证

- [ ] 当前环境与每个客户环境结果分开，不混写。
- [ ] 每张表按 tenant 对账而非只跑总 count。
- [ ] route 使用量含 30/90 天和 last_seen。
- [ ] 维护窗口二次画像与预检 checksum 一致。

## Definition of Done

- [ ] 所有 F5 删除项有环境级 GO/NO_GO；未知环境保持 NO_GO。
- [ ] 用户/客户确认停机窗口和外部调用清单。
- [ ] 报告不含凭据、token、业务原始行。
