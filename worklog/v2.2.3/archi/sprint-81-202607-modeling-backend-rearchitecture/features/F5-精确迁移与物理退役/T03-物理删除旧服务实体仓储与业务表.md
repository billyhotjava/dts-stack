# T03：物理删除旧服务、实体、仓储与业务表

**优先级**：P0
**状态**：PLANNED
**依赖**：T01～T02；目标环境 `PreDropDecision=GO`

## 目标

在维护窗口内物理删除 semantic/old plan/SQL model/business object/vNext/old dbt run 的剩余运行代码与业务表。

## 技术设计（Contract-first）

- **输入契约**：pre-drop manifest checksum、caller=0、source=0 或 fully migrated、conflict/orphan=0、BackupEvidence、审批。
- **代码删除**：resource/service/entity/repository/mapper/DTO/route config/old test fixture；不得留未装配类或 shim interface。
- **schema 删除**：新 forward-only Liquibase changeset 精确 drop FK/index/table；历史 changelog 不修改。
- **顺序**：冻结旧写 → 复跑 manifest → 部署无 caller 代码 → drop FK/index/table → context/schema/canonical smoke。
- **回滚**：release 回切 + 备份 restore/forward recovery；不依赖旧代码长期共存。
- **错误路径**：manifest 漂移、active RUNNING/UNKNOWN、备份不可读或中央审计不可用均停止。

## 影响范围

retirement matrix 批次 B/C 精确列出的 code/schema；绝不使用通配 DROP。

## 验证

- [ ] compile/context load 无旧 bean/entity/repository。
- [ ] information_schema 中旧表/FK/index=0，canonical 表/约束完整。
- [ ] old URL 普通 404；无 410/tombstone/redirect/flag。
- [ ] 空库与存量升级路径通过，历史 Liquibase checksum 不变。

## Definition of Done

- [ ] 旧业务运行面物理不存在。
- [ ] canonical API/state/materialization smoke 通过。
- [ ] 备份、manifest、审计和恢复证据入 IT-06/07。
