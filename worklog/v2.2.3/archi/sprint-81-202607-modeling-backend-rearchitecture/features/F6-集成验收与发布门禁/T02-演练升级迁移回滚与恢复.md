# T02：演练升级、迁移、回滚与恢复

**优先级**：P0
**状态**：PLANNED
**依赖**：F0/T03；F5 全部删除完成

## 目标

证明空库、代表存量库和备份恢复都能到达目标 schema，且历史 changelog、中央审计和 canonical 数据无损。

## 技术设计（Contract-first）

- **输入契约**：目标 commit/migrations、empty DB、旧版本代表 DB、BackupEvidence、MigrationManifest。
- **输出契约**：upgrade/restore report；schema diff；count/key/revision/checksum/audit comparison；RTO/RPO。
- **路径 A**：empty DB 从 master 全量应用。
- **路径 B**：旧版本存量库 upgrade → dry-run/apply/verify → physical drops。
- **路径 C**：drop 后隔离 restore → forward recovery 到目标 schema。
- **错误路径**：checksum drift、missing include、manifest mismatch、audit loss、RTO 超窗均 NO_GO；不修改历史 changelog 修错。

## 影响范围

隔离 PostgreSQL、Liquibase、备份/迁移命令；不对生产执行未批准写操作。

## 验证

- [ ] empty/existing/restore 三路径结果一致。
- [ ] canonical count/revision/checksum 和 CatalogAssetKey 不变。
- [ ] legacy 表按目标 absent；central audit 与 DATABASECHANGELOG 完整。
- [ ] rollback 不覆盖并行新写入。

## Definition of Done

- [ ] IT-07 PASS，实测 RTO/RPO 符合批准窗口。
- [ ] release/rollback artifact 可复用且命令幂等。
- [ ] 任何失败环境明确 NO_GO，不用本地成功替代。
