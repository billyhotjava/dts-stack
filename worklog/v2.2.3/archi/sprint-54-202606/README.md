# Sprint-54: 指标建模产品化 UI 与运行监控收敛

**时间**: 2026-06  
**状态**: DONE  
**目标**: 将指标工作台、业务对象、指标管理、模型管理、发布审核打磨成统一的指标建模工作区；主题域统一来自数据治理中心，并把运行监控收敛到任务运维中心统一管理。

## 背景

Sprint-53 已完成 `dts-metrics` 默认退役和平台路由接管，但当前指标建模页面仍偏“分散表格 + 技术画布”：页面之间缺少统一流程、状态摘要和客户可理解的操作路径。运行监控也仍挂在“指标建模”菜单下，容易把模型运行治理和任务运维割裂。

本 sprint 以现有页面和现有 API 为第一事实源，不新增 `/v2` 路由，不回引旧 `dts-metrics` iframe。后端只补页面验收所需的缺口。

## 完成标准

- [x] 指标工作台具备统一流程导航、关键计数、画布状态和右侧业务详情。
- [x] 指标建模不再维护独立主题域模块；主题域唯一维护入口是数据治理中心“主题域管理”。
- [x] 业务对象、指标管理、模型管理、发布审核页面使用一致的指标建模工作区头部和业务语言。
- [x] “运行监控”不再作为指标建模主菜单项；指标模型运行进入任务运维中心统一查看。
- [x] 旧 `/modeling/semantic/runs`、`/metrics/operations` 等兼容入口仍可到达运维监控。
- [x] source-contract、TypeScript 和 Chrome 95 语法扫描通过。

## 决策

- 指标建模是建模/发布工作区；运行实例、日志、失败、补数统一归入“任务运维中心”。
- 指标工作台保留快捷入口到任务运维中心，但不在指标建模菜单中维护独立运行监控页面。
- 数据治理中心 `/governance/subjects` 是主题域 canonical 页面；指标建模只引用治理主题域，不提供新建/编辑主题域入口。
- `/semantic/subject-domains` 仅作为语义建模兼容投影接口，数据源来自 `catalog_domain` / `/api/catalog/domains/tree`。
