# Task 详细设计标准

Sprint-67 的每个 Task 必须独立回答以下问题，不允许只写一句“修改页面/API”：

1. **目标与用户结果**：完成后用户能做什么；
2. **范围/非范围**：本 Task 改什么、不改什么；
3. **前置条件与依赖**：依赖的上游契约和数据；
4. **输入条件**：页面/API 必填、可选、默认和禁止输入；
5. **输出产物**：记录、DTO、页面状态、证据或迁移报告；
6. **详细设计**：组件、接口、数据流、不变量、错误码、权限、恢复；
7. **影响范围**：准确到模块和候选文件；
8. **实施步骤**：先测试、最小实现、回归、提交；
9. **验证矩阵**：正向、空态、错误、权限、兼容和 Chrome 95；
10. **完成标准**：可由 reviewer 独立判断通过或拒绝。

Task 中列出的文件是实施候选范围。编码前仍必须重新读取当前 HEAD，并按 AGENTS.md 对将修改的 symbol 执行 GitNexus impact；不得把文档中的行号当作永久事实。

禁止出现 `TBD`、`TODO`、“适当处理错误”“补充测试”等占位表述。若目标契约仍有未决选择，Task 状态必须是 BLOCKED 并写明决策人和解除条件，不能把歧义留给实现者。
