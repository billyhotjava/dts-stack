# T07：统一 OpenMetadata 远端元数据部门可见性

**优先级**：P1
**状态**：READY
**依赖**：F4-T03、F6-T06

## 目标与用户结果

目录元数据无论来自平台本地同步表还是 OpenMetadata 远端查询，都使用同一套认证部门、机构特权和精确归属规则。部门用户不能通过省略 `sourceId`、构造远端 FQN 或伪造 `X-Active-Dept` 查看其他部门元数据；无法证明归属时 fail closed。

## 问题来源

F6-T06 安全复审确认，建模来源候选链始终携带连接 `sourceId`，已被本地正式目录和提交时 resolver 封闭；但通用 `/api/catalog/metadata/tables` 在未传 `sourceId` 且本地结果为空时会回退到 OpenMetadata，非本地 FQN 详情也会直接查询远端。远端结果当前没有可验证的部门映射，因此属于平台级残留，不能混入 F6-T06 的已完成边界。

## 实施范围

1. 为 OpenMetadata table/FQN 建立稳定的本地来源和 owner department 映射，不以名称后缀猜测归属。
2. 列表与详情统一使用认证令牌部门；只有机构特权角色可显式选择部门范围。
3. 部门归属缺失、映射漂移或 provider 异常时返回稳定空态/404，不回退为全量远端结果。
4. 本地目录与远端目录共用规范化后的精确部门比较，禁止 `dept-a/dept-ba`、`10/10010` 碰撞。
5. 保留机构管理员跨部门治理能力，并记录显式部门切换审计。

## 验证矩阵

| 场景 | 预期 |
|---|---|
| 部门账号省略 `sourceId` | 只返回映射到认证部门或 global 的远端表 |
| 部门账号构造其他部门 FQN | 返回遮蔽 404，不泄露表名、字段和归属 |
| 伪造 `X-Active-Dept` | 部门账号仍使用 token claim；机构账号可显式切换 |
| 无 owner 映射 | fail closed，不回退为远端全量查询 |
| 部门编码后缀碰撞 | 严格视为不同部门 |
| provider 失败 | 显示可恢复错误，不伪装为空目录或放宽权限 |

## 完成标准

- [ ] 远端列表/详情部门映射契约与失败策略评审通过。
- [ ] 服务端列表、详情和显式部门切换测试通过。
- [ ] 部门越权、FQN 枚举、后缀碰撞和缺映射均 fail closed。
- [ ] 机构角色跨部门治理和审计回归通过。
- [ ] 真实账号 Chrome 95/API 证据完成并纳入增量 Go/No-Go。
