# T03：落实页面输入、输出与唯一主动作

**优先级**：P0
**状态**：DONE
**依赖**：F4-T01、F4-T02、F3-T05

## 目标与用户结果

用户进入每页都能立即知道“现在需要输入什么、完成后生成什么、下一步是什么”，不再面对按钮墙和多套向导。

## 范围与不做

- 范围：页面矩阵定义的主线与专业支撑页面输入状态、产物摘要、主动作、次级操作、保存后刷新。
- 不做：计划详情不复制所有专业模块表单；专业页不复制九站总览。

## 输入/输出权威

完全采用 `assets/page-input-output-navigation-matrix.md`。页面实现不得自行放宽必填或发明下一跳。

## 预期输出

- page capability map；
- 每页 primaryAction/secondaryActions 状态模型；
- artifact/evidence summary；
- 保存成功后的 projection refresh 协议。

## 详细设计

1. 建模工作台创建计划后只显示“完善规划基线”。
2. 计划详情六 Tab 保留摘要/编辑边界：baseline/architecture 可编辑规划；models/implementation/deliverables 以真实摘要和深链为主。
3. 维度目录主动作“登记维度”；模型中心主动作“新建模型”，随后选择四类表。
4. 模型详情按 DRAFT/IMPLEMENTATION_READY/RELEASE_READY 显示唯一主动作，不同时展示生成、发布、运行等多个蓝色按钮。
5. 专业页页头只显示 compact plan context 和返回计划；StageProjection 的下一步由后端返回。
6. 行级编辑、导入、归档等放入表格行操作/更多菜单；概念说明首次折叠。

## 影响范围

- ModelingWorkbenchPage、WarehousePlanDetailPage
- SubjectAreasPage、DimensionCatalogPage、ModelCenter/Detail
- SqlModeling/dbt workbench、publish、MetricWorkbench、OpsInstances
- common plan context/primary action components
- 相关 source-contract tests

## 异常、权限与恢复

- 保存中防重复提交；失败保留输入和当前页面。
- 无权限时不显示可写主动作，提供返回/申请。
- projection 刷新失败不撤销已成功保存，状态标 UNKNOWN 并可重试。

## 实施与测试设计

1. 为每页写输入/输出/主动作 source-contract 测试。
2. 抽取小型 plan context 与 primary action 组件，不创建巨型通用工作台。
3. 按页面逐一接真实 API/状态。
4. 浏览器测试空态、活跃态、失败、权限、保存中和恢复。
