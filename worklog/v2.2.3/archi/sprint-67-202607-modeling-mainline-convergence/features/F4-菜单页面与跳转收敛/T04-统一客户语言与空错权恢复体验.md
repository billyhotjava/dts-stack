# T04：统一客户语言与空态、错误、权限、恢复体验

**优先级**：P0
**状态**：DONE
**依赖**：F4-T03

## 目标与用户结果

页面在首次使用、失败、无权限、刷新和窄屏时仍可操作；提示语说明业务缺口和修复动作，不堆叠术语解释。

## 范围与不做

- 范围：客户文案、loading/empty/error/permission/conflict/stale 状态、恢复卡和 Chrome 95。
- 不做：不把架构分析文字放进产品页，不用示例行业内容填满空态。

## 输入契约

输入为页面状态码、blocker、permission decision、last successful data 和 recovery context；页面不得从异常 message 字符串猜状态。

## 输出产物

- 中性客户文案表；
- 六类状态组件和动作规则；
- retired-term UI guard；
- Chrome 95/390px 响应式验收矩阵。

## 详细设计

1. 空态固定回答：当前为空、创建产物、所需前置、创建后去哪；只保留一个创建按钮。
2. 错误态保留上次成功内容，不将 API 失败显示为零条；提供重试和返回。
3. 权限态区分不可见/只读/可申请；禁止灰色按钮无解释。
4. 并发冲突显示当前 revision 和重新加载选择，不静默覆盖草稿。
5. 业务对象/语义对象不得出现在用户可见标题、字段、toast 和修复链接。
6. 兼容 Chrome 95，避免未转译语法；390px 下主动作、Tabs 和表单不横向溢出。

## 影响范围

- modeling/governance pages 和 common empty/error/permission components
- toast/error code mapping
- CSS/Tailwind/Ant Design responsive layout
- Chrome regression specs/source-contract tests

## 异常与权限

组件本身发生错误时回退到页面级 Result；不得吞掉权限/租户错误。恢复上下文过期时回到工作台，不循环恢复。

## 实施与测试设计

1. 写状态矩阵组件测试和退役词扫描。
2. 逐页替换提示墙/按钮墙，保持真实 API 行为。
3. 执行生产构建与 Chrome 95 1280px/390px smoke。
4. 人工评审文案是否回答任务而非解释架构。
