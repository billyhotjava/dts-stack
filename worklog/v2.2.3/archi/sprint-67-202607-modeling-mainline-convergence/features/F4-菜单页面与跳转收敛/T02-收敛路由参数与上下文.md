# T02：收敛路由、参数与上下文

**优先级**：P0
**状态**：DONE
**依赖**：F2-T04、F3-T01

## 目标与用户结果

用户从任何专业页返回都回到同一计划；刷新、后退和旧深链不会丢上下文，也不会重新触发业务对象流程。

## 范围与不做

- 范围：静态/动态路由、redirect、plan context、参数白名单、旧 context 退役。
- 不做：不新增 sessionStorage 事实源，不让 redirect 永久成为新入口。

## 输入契约

新参数只允许 `planId/domainId/modelSpecId/revision/modelType/returnTo`。旧 `objectId/processId/planningId/warehouseLayer/modelingMode` 仅兼容解析；objectId 必须查迁移映射后才能决定目标。

## 输出产物

- `/modeling/dimensions`、`/modeling/models` canonical routes；
- 旧 semantic/low-code/sql/dbt 路由映射；
- planId/modelSpecId 上下文工具；
- redirect usage telemetry 和退出条件。

## 详细设计

1. 静态/动态路由必须注册同一目标，source-contract 防止只改一处。
2. `/modeling/semantic/objects` 根据 legacy map 跳维度目录或模型中心；无映射回工作台并给可恢复说明。
3. `/modeling/semantic/models|metrics|publish|runs|subjects` 按矩阵定向，不保留旧页面双写。
4. `/studio/low-code-development` 进入模型中心 guided mode；`/studio/sql-modeling` 和 `/modeling/dbt-files` 收敛到 dbt workbench 的对应 Tab。
5. `businessModelingContext/modelingJourneyContext/warehousePlanningContext` 仅保留一次性兼容读取，消费者归零后删除。
6. returnTo 只允许站内白名单，URL 编码/解码一致，禁止开放重定向。

## 影响范围

- `static-routes.tsx`、`dynamic-resolver.tsx`
- `metricsServiceRoutes.ts` 和 tests
- 三套 modeling/planning contexts 及 tests
- SemanticWorkspaceFrame、SemanticModelingCenterPage
- 页面 route builders/source-contract tests

## 异常与权限

- 迁移映射缺失：显示 NEEDS_CLASSIFICATION/人工处理入口，不猜测。
- 目标无权限：403 状态，不回退到可能泄露数据的旧页。
- redirect 循环测试必须覆盖所有兼容路径。

## 实施与测试设计

1. 先写 route table 参数化测试和循环检测。
2. 写新参数白名单和旧 objectId 映射测试。
3. 实现 canonical routes/redirects，逐步移除旧 context 消费者。
4. Chrome 95 验证深链、刷新、后退、returnTo 和无权限。
