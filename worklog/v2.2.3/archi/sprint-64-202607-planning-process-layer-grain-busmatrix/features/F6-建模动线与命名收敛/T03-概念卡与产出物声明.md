# T03: 概念卡与产出物声明

**优先级**: P1
**状态**: DONE
**依赖**: 无

## 目标

用一句话+PJM 示例讲清三层概念链，并让普通用户知道低代码产出与专业用户是同一个 dbt 模型。

## 技术设计

- 概念卡（可关闭，sessionStorage 记忆，复用 joinable 提示模式）三处：
  - 主题域页："主题域是业务的版图——管什么业务（如项目管控）。"
  - 业务过程（规划卡区）："业务过程是版图里发生的事——如节点计划闭环，它决定事实表。"
  - 业务对象（台账页+过程卡登记区）："业务对象是事里涉及的人和物——如项目、节点、科室，它决定维度表，也是指标的挂载点。"
- 低代码模型草稿卡增加产出物声明："产出物：dbt 模型（SQL + schema.yml），与高级建模同一份产物。"
- 文案集中为常量模块（如 `modelingConceptCopy.ts`），三页引用，避免漂移。

## 影响范围

- `SubjectAreasPage.tsx` / `SemanticObjectsPage.tsx` / `LowCodeDevelopmentPage.tsx` + 新增文案常量模块
- 各页 source-contract 增补

- [x] 草稿卡产出物声明可见。
