# T01: 监控栈编排与指标采集接入

**优先级**: P0
**状态**: DRAFT
**依赖**: F0/T01

## 目标
Prometheus 能稳定抓取四个 Java 服务的指标，Alertmanager 与 Grafana 可访问，且整套配置随离线部署包交付。

## 技术设计 (Contract-first)
- **输入契约**: 已暴露的 actuator 端点（账本#8）——`management.endpoints.web.exposure.include` 含 prometheus
- **输出契约**:
  - `services/dts-prometheus/prometheus.yml`:
    ```yaml
    global: {scrape_interval: 30s, evaluation_interval: 30s}
    rule_files: ["rules/*.yml"]
    alerting:
      alertmanagers: [{static_configs: [{targets: ["dts-alertmanager:9093"]}]}]
    scrape_configs:
      - job_name: dts-platform
        metrics_path: /management/prometheus
        static_configs: [{targets: ["dts-platform:8080"]}]
      # dts-admin / dts-ingestion / dts-metrics 同构
    ```
  - compose 新增三服务，均 `restart: unless-stopped`，配置以**只读**卷挂载
  - 数据卷：prometheus 保留期 15d（磁盘水位见 T02 预算）
- **鉴权**: actuator 端点若当前对内网开放，须确认不经 `dts-proxy` 对外暴露；如已鉴权，prometheus 配置 basic_auth（密钥走 secrets，不进环境变量，domain-dts D6）
- **错误路径**:
  - 某服务未暴露端点 → prometheus target DOWN，作为 T02 的 `ServiceDown` 告警来源（这是特性不是缺陷）
  - 端口冲突 → 部署前在 `imgversion.conf` 相关端口表登记
- **复用点**: 沿用既有 compose 网络与健康检查约定；离线镜像走既有镜像清单机制
- **不做**: HA/多副本（P0-12 属 Sprint-101）

## 影响范围
- `docker-compose-app.yml`（新增 3 服务）
- `services/dts-prometheus/`、`services/dts-alertmanager/`、`services/dts-grafana/`（新建）
- 离线镜像清单与部署文档
- 主机资源：新增约 1.5～2GB 内存占用，须在 `assets/nfr-budget.md` 记账
