# T03: 业务指标埋点与只读看板

**优先级**: P0
**状态**: DRAFT
**依赖**: T01

## 目标
监控看板显示的是"平台在做什么"而不只是"JVM 在做什么"：入湖成功率、审计写入速率、登录锁定次数、基线检查状态一眼可见。

## 技术设计 (Contract-first)
- **输出契约**（Micrometer 指标，命名遵循 `dts_` 前缀 + snake_case）:
  | 指标 | 类型 | 标签 | 埋点位置 |
  |---|---|---|---|
  | `dts_ingestion_task_total` | Counter | `taskType`,`result` | 入湖任务结束处 |
  | `dts_ingestion_task_failed_total` | Counter | `taskType`,`reason` | 同上失败分支 |
  | `dts_audit_write_failed_total` | Counter | - | 审计写入异常分支 |
  | `dts_login_locked_total` | Counter | - | F1/T02 锁定事件消费处 |
  | `dts_sensitive_scan_duration_seconds` | Timer | `status` | F3/T02 扫描结束 |
  | `dts_baseline_check_status` | Gauge | `checkKey` | F2/T02 校验结果（1=PASS,0=FAIL,-1=UNKNOWN）|
- **基数控制**（硬性）: 标签取值必须有限枚举。`reason` 须归一为错误码而非自由文本，**禁止把 assetKey / userId / 表名作为标签**（会引发指标基数爆炸）
- **看板产物**: `services/dts-grafana/dashboards/dts-overview.json`，随离线包交付，Grafana 以 provisioning 方式自动导入
- **错误路径**: 埋点自身异常绝不影响业务流程（全部 try/catch 吞掉并只记 debug 日志）
- **复用点**: 复用 Spring Boot 已有的 MeterRegistry，不引入第二套指标库
- **平台入口**: 既有运维/系统页加一个外链按钮（ADR-99-07），不新增菜单、不内嵌 iframe

## UI 交互规格
- 按钮位置：既有运维页工具栏；文案「打开监控看板」；`target=_blank`
- 无四态（纯外链）；Grafana 地址来自运行时配置项，不硬编码

## 影响范围
- `dts-platform` / `dts-ingestion` / `dts-admin`：埋点（各服务少量代码）
- `services/dts-grafana/`（新建，含 provisioning 与 dashboard JSON）
- `dts-platform-webapp`：一个外链按钮
- **每个埋点所在方法改动前跑 `gitnexus_impact`**（domain-dts A1）

## 验证 (RED→GREEN)
- [ ] 指标可见：`curl /management/prometheus | grep dts_` 能看到全部 6 个指标
- [ ] 基数断言：`dts_ingestion_task_failed_total` 的 `reason` 取值集合有限（跑一批失败任务后确认标签组合数 < 上限）
- [ ] 埋点无副作用：故意让 MeterRegistry 抛异常 → 业务流程不受影响
- [ ] 看板：Grafana 自动导入且四个面板有数据
- [ ] 外链按钮在 Chrome95 下可点且新窗口打开
