# T03: 发现结果与确认闭环

**优先级**: P0
**状态**: DRAFT
**依赖**: T02

## 目标
管理员能筛选、批量勾选发现项并做出确认或忽略的决定，决定过程可追溯，重复扫描不产生重复处理。

## 技术设计 (Contract-first)
- **输入契约** `GET /api/security/sensitive/findings?scanId=&status=&assetKey=&page=&size=`（默认 size=10）
- **输入契约** `POST /api/security/sensitive/findings/confirm`:
  `{findingIds[], applyMasking:bool, applyClassificationSuggestion:bool}`
- **输出契约**: `{maskingRulesCreated:int, classificationRequestsSubmitted:int, skipped:[{findingId, reason}]}`
- **幂等**: `catalog_sensitive_finding` 唯一约束 `(scan_id, asset_type, asset_key, column_name, rule_code)`；重复扫描产生新 scan，但已 CONFIRMED 的同锚点发现项在新 scan 中默认折叠为"已处理"，不重复提示
- **错误路径**:
  - 已处理的 finding 再次确认 → 计入 `skipped`，不报错整批失败
  - 部分成功 → 返回 200 + `skipped` 明细（**不做全或无**，避免一条失败阻塞批量）
  - 越权 → 403
- **审计**: 每次确认/忽略写审计，`detail` 记录 findingId 与决定，**不记样本值**
- **复用点**: 分页遵循 domain-dts 分页统一约定（默认 10 条/页，切 size 重置第 1 页）

## UI 交互规格
- 「发现结果」子页签：筛选条 + 可勾选表格 + 底部批量操作条
- 表格列：资产 / 字段 / 规则 / 命中率 / 置信度 / 当前密级 / 建议密级 / 状态
- 建议密级低于当前密级 → 该行密级建议列显示"不可降级"且勾选框对密级动作禁用（账本#4）
- 四态：空（该 scan 无发现 → "未发现敏感字段"）/ 加载 / 错误（部分失败 → 结果弹窗列出 skipped 明细）/ 成功
- 走查：1. 选扫描任务 → 2. 筛选待确认 → 3. 全选当页 → 4. 点批量确认 → 5. 二次确认弹窗 → 6. 看到成功数与跳过明细

## 影响范围
- `dts-platform`：`SensitiveFindingService` + REST + repository
- `dts-platform-webapp`：发现结果子页签
- 审计字典

## 验证 (RED→GREEN)
- [ ] 契约测试：批量确认返回创建数与 skipped 明细
- [ ] 幂等：同一 finding 确认两次 → 第二次计入 skipped 而非报错
- [ ] 分页：默认 10 条；切换每页条数触发刷新且回到第 1 页
- [ ] 密级降级：建议密级 < 当前密级的行，确认时被拒并说明原因
- [ ] 审计 detail 中无样本值

## Definition of Done
- [ ] 架构：契约 + 幂等测试绿
- [ ] UI：四态与批量结果弹窗证据入 `it/evidence/`
- [ ] 切片：真实实例上完成一次批量确认
- [ ] 无占位证据
