# T02: 扫描引擎（正则 + 字典 + 列名启发）

**优先级**: P0
**状态**: DRAFT
**依赖**: T01

## 目标
对选定范围的数据资产采样扫描，按规则库产出带命中率与置信度的发现项，且扫描过程不把敏感原文写进日志或结果表。

## 技术设计 (Contract-first)
- **输入契约** `POST /api/security/sensitive/scans`:
  `{scope:{assetType,assetKeys[]}|{domainId}, ruleCodes[]?, sampleRows:int(默认1000,上限10000)}`
- **输出契约**: `catalog_sensitive_scan` 一行 + N 行 `catalog_sensitive_finding`
- **数据流**:
  1. 解析范围 → 展开为列清单（**复用 `CatalogColumnSchema`**，账本#10；不重新做元数据发现）
  2. 逐列采样：`SELECT {col} FROM {table} LIMIT {sampleRows}`（走既有查询执行通道，受既有查询预算与权限约束）
  3. 逐规则匹配 → 命中率 = 命中行数/采样行数
  4. 置信度 = f(命中率, matchType)；`COLUMN_NAME` 类上限 60
  5. 命中率 ≥ 阈值（默认 30%）落 finding
- **样本脱敏**（硬性）: 落库前对样本做掩码，`samples_json` 只保留脱敏后前 3 条；**原文不得出现在日志、异常栈、审计 detail**
- **错误路径**:
  - 某表不可读（权限/表已删）→ 记入 scan 的 `error` 明细，继续扫其余表，最终 `status=PARTIAL`
  - 扫描超时 → PARTIAL + 保留已产出 finding
  - 目标库压力：单次扫描并发上限可配，默认串行；大表只采样不全表扫
- **权限**: 发起扫描需安全域权限；扫描以发起人身份读数据，**不得用超级账号绕过行级/密级过滤**
- **复用点**: 查询执行走既有 explore/查询通道；列元数据走 `CatalogColumnSchema`
- **审计**: 扫描发起、完成写审计（动作码字典登记，账本#16）

## UI 交互规格
- 「扫描任务」子页签：任务列表（状态/范围/发现数/耗时）+ 「发起扫描」抽屉（选范围、选规则、采样行数）
- 四态：空 / 加载（进度条 已扫列数/总列数）/ 错误（PARTIAL 显示黄色徽标 + 可展开失败明细）/ 成功
- 进行中任务可查看实时进度，不阻塞页面

## 影响范围
- `dts-platform`：`service/security/sensitive/SensitiveScanService.java` + 异步执行器 + repository + REST
- 目标数据库：只读采样查询
- **改动查询执行通道前跑 `gitnexus_impact`**

## 验证 (RED→GREEN)
- [ ] 契约测试：造一张含身份证列的表 → 扫描后产出 finding，命中率 > 90%
- [ ] 负样本：纯数字序号列不得被判为身份证（校验位过滤生效）
- [ ] 脱敏断言：`samples_json` 与全量日志中**不含**任何完整身份证号（这是本 Task 的关键断言）
- [ ] PARTIAL：故意让一张表不可读 → status=PARTIAL 且其余表结果保留
- [ ] 权限：无权限用户发起 → 403

## Definition of Done
- [ ] 架构：契约测试绿，含脱敏断言与 PARTIAL 用例
- [ ] UI：扫描四态证据入 `it/evidence/`
- [ ] 切片：真实 catalog 上跑一次扫描并产出发现
- [ ] 日志中无敏感原文（人工抽查 + grep 断言）
