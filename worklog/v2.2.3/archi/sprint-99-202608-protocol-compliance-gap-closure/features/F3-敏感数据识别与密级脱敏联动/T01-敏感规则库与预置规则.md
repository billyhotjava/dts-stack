# T01: 敏感规则库领域模型与预置规则

**优先级**: P0
**状态**: DRAFT
**依赖**: F0/T01

## 目标
平台具备可维护的敏感数据识别规则库，开箱预置常见个人信息与涉密字段规则，管理员可增删改启停。

## 技术设计 (Contract-first)
- **输出契约**: 表 `catalog_sensitive_rule`（字段见 F3/README 契约表），REST `/api/security/sensitive/rules` CRUD
- **预置规则**（seed，随内容包交付）:
  | code | category | matchType | 说明 |
  |---|---|---|---|
  | `ID_CARD_CN` | ID_CARD | REGEX | 18 位身份证含校验位验证 |
  | `PHONE_CN` | PHONE | REGEX | 11 位手机号号段校验 |
  | `BANK_CARD` | BANK_CARD | REGEX | Luhn 校验 |
  | `EMAIL` | EMAIL | REGEX | 常规邮箱 |
  | `ADDRESS_CN` | ADDRESS | DICT | 省市区词典命中 |
  | `NAME_CN` | NAME | COLUMN_NAME | 列名启发（`name`/`姓名`/`xm`）+ 值长度分布 |
- **匹配类型语义**:
  - `REGEX`：对采样值做正则 + 可选校验函数（身份证校验位、Luhn）
  - `DICT`：词典命中率
  - `COLUMN_NAME`：仅看列名/注释，置信度上限 60（**列名启发不得单独定为高置信**）
- **错误路径**: 正则非法 → 400 且提示具体位置；正则可能灾难回溯（ReDoS）→ 保存时用超时沙箱试跑，超时拒绝
- **复用点**: 规则的 `suggestedMaskingStrategy` 取值必须与既有 `CatalogMaskingRule` 支持的策略一致（账本#10），不新造策略枚举
- **安全**: 规则 `pattern` 属配置不属密钥，可明文存；但样本值任何时候不得落规则表

## UI 交互规格
- 「规则库」子页签：表格 + 新建/编辑抽屉 + 启停开关
- 四态：空（引导"载入预置规则"）/ 加载 / 错误（正则非法行内提示）/ 成功
- 编辑抽屉含「测试」区：贴一段样例文本，实时显示是否命中（**测试输入不落库**）
