# T03: 测评轮次与整改登记（无审批链）

**优先级**: P0
**状态**: DRAFT
**依赖**: T01

## 目标
不符合项可被登记为整改单，指派责任人与期限，补充整改证据后关闭；同一控制项在多轮测评中的历史可对比。

> **本 Task 明确不做审批链**（ADR-99-01）：客户审批模型未定。谁能关闭整改单由 `AssetAction`（账本#6）判定，不引入多级审批、会签或外部 OA 对接。

## 技术设计 (Contract-first)
- **输入契约** `PUT /api/security/baseline/checks/{checkKey}`（扩展既有端点）:
  ```json
  {"assessmentRound":1,"clauseNo":"5.2.3","status":"FAIL",
   "remediation":{"owner":"zhangsan","dueDate":"2026-09-10",
                  "state":"OPEN|IN_PROGRESS|RESOLVED|ACCEPTED|WAIVED",
                  "note":"...","evidenceRefs":["file://..."]}}
  ```
- **状态流转**（无审批，权限即闸门）:
  ```
  OPEN → IN_PROGRESS → RESOLVED → ACCEPTED
                    ↘ WAIVED（须填 waiveReason）
  ```
  - `RESOLVED → ACCEPTED` 需 `AssetAction.UPDATE` 于安全域的权限
  - 每次流转写审计（动作码须在字典登记，账本#16）
- **输出契约**: `security_baseline_remediation` 行更新 + 审计条目
- **错误路径**: 非法状态跳转（如 OPEN → ACCEPTED）→ 409；`WAIVED` 未填理由 → 400；越权关闭 → 403
- **复用点**: 既有 `SecurityBaselineRemediation` 实体与 `PUT /checks/{checkKey}`；**不新建整改单表**
- **多轮对比**: 按 `(standard_code, clause_no, assessment_round)` 组织；`GET /checks?round=` 切换轮次

## UI 交互规格
- 触发：条款表行内「登记整改」按钮 → 右侧抽屉
- 抽屉字段：责任人（人员选择器，复用既有组件）/ 期限（日期）/ 说明 / 证据附件
- 四态：空（未登记 → 显示"登记整改"）/ 加载（保存中按钮 loading）/ 错误（400/403 行内红字，不吞错）/ 成功（行内出现状态徽标 + toast）
- 状态徽标配色须与既有治理状态徽标一致，不新造一套色板
