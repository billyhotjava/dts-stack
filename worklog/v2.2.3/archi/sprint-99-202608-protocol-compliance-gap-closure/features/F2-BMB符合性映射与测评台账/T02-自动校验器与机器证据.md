# T02: 自动校验器（AUTO 判定 + 机器证据）

**优先级**: P0
**状态**: DRAFT
**依赖**: T01（消费条款字典）、F1/T03（消费 `KeycloakSecurityPolicyValidator` 结果）

## 目标
让至少 4 项检查由平台自动判定并产出机器证据，使测评现场不再依赖"人工填写 + 截图"。

## 技术设计 (Contract-first)
- **输出契约** `POST /api/security/baseline/checks/{checkKey}/verify`:
  ```json
  {"status":"PASS|FAIL|PARTIAL|NA|UNKNOWN",
   "evidence":[{"kind":"CONFIG|LOG|QUERY|FILE","label":"realm passwordPolicy",
                "value":"length(12) and ...","collectedAt":"2026-08-24T10:12:00Z"}],
   "verifiedAt":"..."}
  ```
  - MANUAL 项调用 → 409 + `{"message":"该检查项需人工确认"}`
- **首批 AUTO 校验器**:
  | checkKey | 判定依据 | 证据来源 |
  |---|---|---|
  | `SEC_BASELINE_ACCOUNT_PASSWORD` | realm `passwordPolicy` 满足最小基线 | F1/T03 Validator 结果（**不重复实现 realm 读取**）|
  | `SEC_BASELINE_LOGIN_LOCKOUT`（新增）| `bruteForceProtected=true` 且 `failureFactor<=阈值` | 同上 |
  | `SEC_BASELINE_AUDIT_LOG` | 审计开关 + 近 24h 审计条数 > 0 + 「未分类」占比 < 阈值 | 审计表查询 |
  | `SEC_BASELINE_BACKUP` | 最近一次备份成功时间在 SLA 内 + 最近一次恢复验证记录存在 | `bin/dts-backup` 产物与 `logs/backup/` |
  | `SEC_BASELINE_TLS` | 对外端点协议版本与套件 | 探测结果 |
- **数据流**: verify → 各 verifier 采集 → 落 `security_baseline_verification` 一行留痕 → 返回
- **错误路径**:
  - 依赖不可达（Keycloak/DB/备份目录）→ `status=UNKNOWN` + evidence 记录失败原因，**绝不返回 PASS**
  - 单个 verifier 异常不得影响其他条款校验（逐项 try/catch）
- **复用点**: F1/T03 的 Validator；审计查询走既有 repository；备份状态读既有 `bin/dts-backup` 产物。**禁止为合规校验另建一套配置读取层**。
- **实现方案**: `BaselineAutoVerifier` 接口 + 每项一个实现 + 注册表按 `checkKey` 分发；新增 `SEC_BASELINE_LOGIN_LOCKOUT` 检查项。

## 影响范围
- `dts-platform`：`service/security/baseline/` 新增 verifier 包 + `SecurityBaselineResource` 新端点 + 新表实体/repository/changelog
- **改动 `SecurityBaselineService` 前跑 `gitnexus_impact`**

## 验证 (RED→GREEN)
- [ ] RED：realm 未配策略时 verify 返回 FAIL
- [ ] GREEN：F1/T01 配置后同一调用返回 PASS，evidence 含实际策略串
