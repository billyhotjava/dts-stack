# T02：在交付工作台呈现真实构建与关系核验证据

**优先级**：P0
**状态**：IN_PROGRESS（服务端 entryEvidence 投影与页面消费已实现；真实 Airflow/Chrome95 证据待验收）
**依赖**：F2/T03、F3/T03

## 目标

让用户在既有计划交付工作台看到快捷入口创建的同一候选范围、每模型运行和关系核验真值，并能安全开始、刷新和重试构建；为 F7 的计划 DAG 与持续计算保留同页区域。

## 技术设计（Contract-first）

- **入口**：`/modeling/plans/:planId/implementation` 构建区。
- **主动作**：allowedActions 含 START_BUILD 才显示“开始构建”；RETRY_BUILD 才显示“重试构建”。
- **entry view**：业务模型名、model/implementation revision、target relation、run state、relation state、dag/run/invocation id、observedAt、repairCode。
- **来源标识**：candidate 显示“单模型快捷构建/批量交付”（底层 SINGLE_MODEL_INTENT/BATCH_WORKBENCH），但状态、commands、runs 完全共用。
- **范围保护**：快捷候选不可在工作台直接扩展为批量；如需批量，显式终止/释放 claim 后新建 BATCH candidate。
- **状态**：
  - empty：未创建候选；
  - ready：范围已锁定；
  - queued/running/probing；
  - failed/unknown/stale；
  - BUILT。
- **交互**：提交后按钮 loading 防双击；HTTP timeout 后刷新 workspace，不本地猜测结果；poll 可见时启用、离页停止。
- **错误文案**：结构化 code → 中文原因和唯一修复入口；隐藏 secret/stack。
- **可访问性**：状态非仅靠颜色；run id 可复制；Chrome95。

## 当前实现证据（2026-07-28）

- `WorkbenchView.entryEvidence` 由只读 JDBC 投影器读取最新 dispatch、同一 run group 的每模型 pipeline run 与追加式物理关系观测；不触发调度、不改写 Candidate。
- `/modeling/plans/:planId/implementation?candidateId=...&modelSpecId=...` 严格核对深链范围，候选或模型不匹配时停止动作和证据替代。
- “开始构建/重试构建”只按服务端 `allowedActions` 展示，分别复用既有 lock/retry 命令；超时后刷新服务端 workspace，不本地推断结果。
- 后端定向测试 `ModelReleaseCandidateApplicationServiceTest,ModelBuildIntentServiceTest`：30/30；前端相关 source-contract：34/34；TypeScript 与定向 Biome 通过。
