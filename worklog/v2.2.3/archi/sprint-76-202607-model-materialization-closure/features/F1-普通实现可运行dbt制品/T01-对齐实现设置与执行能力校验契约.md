# T01：对齐实现设置与执行能力校验契约

**优先级**：P0
**状态**：DONE
**依赖**：F0/T02

## 目标

让服务端对真实页面保存的 ModelImplementation settings 作唯一、可执行的能力判定，不再出现保存成功但 compile 必然失败。

## 技术设计（Contract-first）

- **输入契约**：`SaveImplementationCommand` 的 `casts,deduplicateBy,dedupBy,joins,targetPhysicalName,loadStrategy,partitionFields,retentionDays`、`materialization`，以及当前 ModelSpec KEY 字段。
- **输出契约**：兼容扩展 `ImplementationValidationView(valid,code,blockers,executionPlan)`，字段见 Sprint §5。
- **数据流**：Implementation → canonical validator → adapter capability registry → execution plan；compiler 只能消费 execution plan，不重复解释 settings。
- **错误路径**：
  - 无目标名：`IMPLEMENTATION_TARGET_REQUIRED`
  - INCREMENTAL 无 KEY：`IMPLEMENTATION_INCREMENTAL_KEY_REQUIRED`
  - SNAPSHOT 缺策略：`IMPLEMENTATION_SNAPSHOT_STRATEGY_REQUIRED`
  - adapter 不支持 partition：`IMPLEMENTATION_PARTITION_UNSUPPORTED`
  - 物化/装载冲突：`IMPLEMENTATION_MATERIALIZATION_CONFLICT`
- **兼容**：保留 `valid/code`；历史 SNAPSHOT 可读但 validation=false；未知 settings 仍拒绝。
- **复用点**：`ModelLifecycleContract.validatedSettings`、`ModelSpecCompilerProjection`、实现门禁。

## 影响范围

- `ModelLifecycleContract.java`
- `ModelLifecycleService.java`
- `ModelSpecCompilerProjection.java`
- implementation API/前端类型与 source-contract tests

- 历史兼容迁移改用系统生成的合法 dbt node identity，禁止“迁移成功、compile 必败”。
