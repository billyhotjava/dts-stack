# F5: 大 CSV 性能准入

**优先级**: P0  
**状态**: IN_PROGRESS

## 目标

让正式版地铁小模型链路支撑运营商常见 CSV 文件规模：单文件 100MB-500MB，几十万到 100 万行，并给出可复验的性能证据。

## 性能目标

| 指标 | 目标值 |
|---|---|
| 单文件大小 | 100MB-500MB |
| 单文件行数 | 300,000-1,000,000 行 |
| 上传限制 | 服务端、网关、前端提示统一不低于 600MB |
| 预检方式 | 流式解析 + 抽样推断，不全量载入 JVM 内存 |
| 入湖方式 | 流式/批量写入，避免一次性持有全量行数据 |
| 快照导出 | 流式写 `data.csv`，默认上限 1,000,000 行，可配置 |
| 验收证据 | 至少覆盖 100MB 样例；正式交付前覆盖 500MB 或 1,000,000 行样例 |

## 当前评估

当前 DTS 不能直接承诺稳定支撑 100MB-500MB / 百万行 CSV 的完整预检入湖链路：

- `dts-ingestion` multipart 默认限制为 50MB/60MB。
- `dts-platform-webapp` Nginx `client_max_body_size` 为 25MB。
- `dts-platform` 数据标准附件默认限制为 200MB，和前两者不一致。
- `CsvParseService` 预检解析硬编码 `MAX_ROWS=100_000`。
- `CsvParseService` 会把 CSV 全量读入 `List<List<String>>`，`StagingTableService.bulkInsert` 再把全量行列表批量插入，百万行时存在明显内存和事务风险。
- Addax `txtfilereader` 路径具备批处理潜力，但还缺少 500MB/百万行文件的实测证据和 UI/预检链路配套。

- [ ] dbt 模型和 `data.csv` 快照导出在 1,000,000 行内有可复验证据。
