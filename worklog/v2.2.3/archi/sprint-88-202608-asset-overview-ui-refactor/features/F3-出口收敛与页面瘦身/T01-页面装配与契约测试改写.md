## 技术设计 (Contract-first)

### 输入契约

页面保留的取数（**由 3 个降为 2 个请求**）：

```ts
getDomainTree({ withStats: true })
  → { tree: DomainNode[], stats: { all, unassigned, byDomain, truncated } }

getCatalogAssetsOverview({ domainId?, domainUnassigned? })
  → AssetOverview   // 含 T01 补齐的 byDomain
```

删除：`listCatalogAssetsV2({page:0,size:50,...})`（原为「待处置 Top5」服务）。

### 输出契约（唯一出口的 URL 构造）

页面只保留**一个** URL 构造函数，替代原有的 `drillToLedger` + `drillToLedgerByReason` 两套：

```ts
/**
 * 资产概览的唯一出口。ADR-88-05：目标恒为数据查询的表格视图。
 * 当前范围（domain）恒被携带，额外筛选由 extra 追加。
 */
const gotoDataSearch = (extra?: Record<string, string>) => {
  const params = new URLSearchParams();
  params.set("view", "table");
  if (domain) params.set("domain", domain);      // 含 __UNASSIGNED__
  for (const [k, v] of Object.entries(extra ?? {})) params.set(k, v);
  router.push(`/catalog/search?${params.toString()}`);
};
```

调用点仅 4 处，与 Sprint README §出口参数映射表一一对应：

| 调用点 | 参数 |
|--------|------|
| 主 CTA | `gotoDataSearch()` |
| KPI「未定密」 | `gotoDataSearch({ unclassified: "1" })` |
| 环形扇区 | `gotoDataSearch({ governance: status })` |
| 条形域条 | `gotoDataSearch({ domain: domainKey })`（覆盖当前范围，用于跨域下钻） |

`router.push` 的路径字面量因此**只有一个**，正是 F3 README 新契约条款中「push 路径去重 == 1」守卫的实现基础。

### 数据流

URL `?domain=` → `loadOverview()` 组装 `scope` → `getCatalogAssetsOverview` → `overview` state → 四卡 + 两图；`getDomainTree` → `domainMap`（域名映射，同时供左侧导航与条形图）→ 单一事实源。

### 错误路径

| 情形 | 行为 |
|------|------|
| `overview` 请求失败 | 全局拦截器 toast；页面结构保留，各组件走各自错误态；不白屏 |
| `getDomainTree` 失败 | 左侧导航空态；条形图 `domainNames` 为空 Map → 显示「未知主题域」而非裸 uuid |
| `?domain=` 指向不存在的域 | 后端返回空统计；页面显示 0 与空态，不报错（现网行为，保持不变） |
| `?view=table` / `?tab=catalog-tags` 深链 | 保持现有 `router.replace` 重定向（`:93-101`），不得改动 |
