# T01: 黄金链路状态机与验收契约

**优先级**: P0
**状态**: DONE
**依赖**: 无

## 目标

把结构化数据黄金链路定义成稳定状态机，作为 Sprint-39 后续所有 Feature 的共同契约。

## 技术设计

- 状态主线：`DRAFT -> SOURCE_READY -> INGESTION_READY -> ODS_READY -> MODEL_READY -> GOVERNANCE_READY -> RELEASE_READY -> CONSUMABLE -> OPERATED`。
- 阻断状态覆盖 source、ingestion、model、governance、permission、consumption。
- 每个阶段必须定义：输入、输出、证据、失败原因、可恢复动作。
- 契约先落 platform 侧可编译代码和 focused test；库表与聚合接口留给 T02/T03。

## 落地内容

- `GoldenChainStage`: 固化 `DRAFT -> SOURCE_READY -> INGESTION_READY -> ODS_READY -> MODEL_READY -> GOVERNANCE_READY -> RELEASE_READY -> CONSUMABLE -> OPERATED` 阶段顺序。
- `GoldenChainStageStatus`: 固化 `PENDING / READY / BLOCKED / SKIPPED` 阶段状态。
- `GoldenChainBlockerCode`: 覆盖 source、ingestion、model、governance、permission、consumption 六类阻断。
- `GoldenChainStageSnapshot`: 固化阶段、状态、负责人、证据引用、阻断码、阻断原因字段，并校验阻断码与阶段匹配。
- `GoldenChainContract`: 提供阶段顺序、阻断码列表、阶段阻断码查询和前向流转判断。
