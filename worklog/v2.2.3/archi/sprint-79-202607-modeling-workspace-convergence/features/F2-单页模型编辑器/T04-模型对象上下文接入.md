## 可验收目标

用户在统一建模工作台的逻辑模型列表中打开模型后，仍停留在 `/modeling/workbench`：刷新恢复同一模型，数据实现/发布结果只改变阶段状态，返回后保留计划、模块和列表视图。

## 冻结契约

### URL

```text
列表：
?planId=P&module=models&workspaceView=model-specs

打开：
?planId=P&module=models&workspaceView=model-specs
&assetKind=model&assetId=M&activeStage=logical

抽屉：
activeStage=implementation|physical

返回：
精确删除 assetKind/assetId/activeStage，保留 planId/module/workspaceView
```

- 打开模型使用 history push。
- 阶段切换和明确返回使用 history replace。
- 切换建设计划必须清除旧资产对和 `activeStage`。
- ModelSpec 加载成功后以服务端返回的 `model.planId` 校正 URL，不信任 query 中伪造或陈旧的计划。

### 受控适配器

| Owner | 新增可选输入/回调 | standalone fallback |
|---|---|---|
| `ModelCenterPage` | `embedded`、`planIdOverride`、`onOpenModel`、`onOpenModelImport` | 继续使用既有 `/modeling/models/:id` 与自身导入向导 |
| `ModelSpecDetailPage` | `embedded`、`modelSpecIdOverride`、`onBack`、`onStageChange`、`onResolvedContext` | 继续从 route params 取 ID，并使用既有详情深链 |
| `ModelingWorkspacePanels` | `assetKind`、`assetId` 及上述受控回调 | 非 `model` 资产或无 ID 时继续显示 `ModelCenterPage` |

`ModelingWorkbenchPage` 是 URL 唯一 owner；不得增加 `selectedModel` 业务状态，不得把 ModelSpec API 或表单草稿提升到 Shell。

## 竖向数据流

```text
ModelCenter 行操作
  → Workbench 更新 asset pair
  → Panels exact-match model asset
  → canonical ModelSpecDetailPage
  → 既有 ModelSpec GET/stage-gates/PUT/CAS
  → 阶段 replace / 返回清理 URL
```

本任务不新增或修改后端 API、DTO、数据库表、权限角色和发布状态机。

## UI 与错误路径

- embedded 列表和详情隐藏重复页头/JourneyContextBar，但保留模型标题、状态、门禁、逻辑画布和抽屉。
- embedded 模式只挂载工作台现有导入向导；不得出现两个导入弹窗。
- 无效/不可读 ID 保留原 URL，显示“模型标识无效/模型不可访问”、重试和返回逻辑模型；不得自动选择其他模型。
- 403、字段 blocker、CAS 冲突、历史 revision 继续由 `ModelSpecDetailPage` owner 处理。
- 未保存草稿离开保护属于详情 owner；禁止在 Workbench 复制表单状态。
