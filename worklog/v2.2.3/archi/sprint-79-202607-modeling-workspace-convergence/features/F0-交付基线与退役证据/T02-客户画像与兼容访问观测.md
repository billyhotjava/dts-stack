# T02：客户画像与兼容访问观测

**优先级**：P0  
**状态**：DRAFT  
**依赖**：T01；客户只读数据库/访问日志授权

## 目标

用客户真实规模和旧入口访问决定可删除范围，不以本地 0 行代替生产证据。

## 技术设计

- **输入契约**：`POST /api/modeling/compatibility-usage` body `{route:string,target:string,result:"REDIRECT"|"RECOVERY"}`。
- **输出契约**：`204 No Content`；服务端从身份解析 tenant/caller，写既有 `modeling_legacy_api_usage`。
- **校验**：route 必须属于 `LEGACY_MODELING_PATHS`，target 必须是对应映射目标；非法 400，越权 403。
- **画像**：按表统计 count/status/null/legacy refs；按 route 统计 30/90 天 count、caller 数、last_seen。
- **复用点**：`LegacyObjectMigrationService.recordApiUsage(...)`，禁止新表。
- **错误路径**：观测 API 失败不得阻塞重定向，但必须产生日志/指标告警。

## 影响范围

`ModelingCompatibilityPage`、`LegacyObjectMigrationService` 及一个受控 REST 边界；实施前分别做 GitNexus impact。

## 验证

- [ ] route allowlist、跨租户、重放和失败降级测试。
- [ ] 客户画像 SQL 只读、脱敏并归档。
- [ ] 90 天报表可给出“保留/移除候选”结论。

## Definition of Done

- [ ] 观测写入既有 ledger 且审计分类正确。
- [ ] `assets/domain-profile.md` 更新客户实测值。
- [ ] F5 的每个删除项都有对应数据证据。
