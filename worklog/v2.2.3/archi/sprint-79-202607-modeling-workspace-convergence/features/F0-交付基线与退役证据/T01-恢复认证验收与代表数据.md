# T01：恢复认证验收与代表 Demo 数据

**优先级**：P0  
**状态**：IN_PROGRESS  
**依赖**：无

## 目标

证明正式 DTS 的登录、API、浏览器和 DEV 发布链可验收，并用项目/财务 Demo 覆盖四类 ModelSpec。

## 技术设计

- **输入**：部署后的 Keycloak/DTS、受控测试账号、既有项目/财务 Demo 材料。
- **输出**：`it/baseline.md` 转 PASS；DIMENSION/FACT/SUMMARY/APPLICATION 各至少 1 个 canonical 模型，至少 1 个 implementation/candidate。
- **数据流**：登录 → 受保护 API → WarehousePlan/DimensionDefinition/ModelSpec → PostgreSQL；Candidate 走既有 intent。
- **错误路径**：401/403、DNS、共享浏览器冲突、目标库不可用均记录真实 blocker，不用 mock 冒充。
- **复用**：现有 compose、测试身份、Demo 文档和 canonical API。
- **安全**：账号口令、token、profile、数据源 secret 只在进程内使用。

## 验证

- [x] 一次性受控身份完成认证，正式 workbench/model center 的受保护 API 未出现 4xx/5xx。
- [x] 系统 Chrome 150 打开 `/modeling/workbench` 和 `/modeling/models`，无 page error、request failure 或 API error。
- [ ] Chrome 95 在 F1 壳层实现后完成四态兼容回归。
- [ ] SQL 断言四类表和 Candidate 行均属于测试 tenant/plan。
