## 对标矩阵

| 能力 | DataWorks 设计 | DTS 当前能力 | Sprint-73 取舍 |
|------|----------------|--------------|----------------|
| 概念维度 | 独立创建；选择分层、业务分类、数据域/数据集市、缩写和名称 | `DimensionDefinition` 已独立，但只有业务分类、名称、定义、责任人、复用范围 | 增加 DOMAIN/DATA_MART 范围与语义属性；系统编码继续服务端生成 |
| 数据集市 | 应用层的业务组织视角 | 无；资产台账仅登记已存在资产 | 新增 DataMart 规划对象；不复用资产台账 |
| 维度表 | 选择分层、业务分类、域/集市、维度、存储策略、命名规则、生命周期、责任人 | 新建仅选计划、分类、维度、模型名称和说明 | 建立分步向导，并把物理配置放在模型详情的实现区 |
| 维度字段 | 支持新建、从已有表/视图导入 | ModelSpec 有字段和来源，但创建动线未串起 | 仅从已验证来源显式导入，导入只是候选，不自动确认来源 |
| 标准与码表 | 字段关联字段标准和标准代码 | 已有 version-pinned `standardBindings` | 复用现有契约，不建第二套 |
| 冗余字段 | 可从关联表选择高频字段，降低下游 JOIN | 当前无明确的冗余字段语义 | 首期增加显式来源字段/冗余标记与血缘，不复制值 |
| 分区 | 维度表可配置分区 | 当前 ModelSpec 无正式分区字段契约 | 在实现配置中加入 `partitionFields`，发布前校验字段存在 |
| 物化 | 设计完成后物化至存储引擎 | Sprint-69 已有发布候选/交付工作台 | 复用 Sprint-69，不建新发布链 |
| 下游消费 | 汇总表/派生指标可引用维度字段 | `dimensionRefs` 和指标引用已有基础 | 维度表发布后继续按 ModelSpec revision 引用 |

## 不照搬的点

1. **不新增 DIM 层**：DTS 当前 canonical 矩阵固定 `DIMENSION→DWD`，本 Sprint 只优化业务范围和建模体验。
2. **不把所有属性前置到创建弹窗**：概念维度登记保持轻量；属性/层级在详情中维护，物理字段在维度表详情维护。
3. **不在概念设计阶段选择连接表**：物理来源属于实现证据，草稿阶段允许为空。
4. **不让数据集市替代业务分类**：业务分类是语义 owner，数据集市是应用消费范围，二者多对多。
5. **不复制 DataWorks 引擎绑定假设**：DTS 继续支持当前多源/外部资产与 dbt 实现链。

## DTS 优化后的用户语言

| 术语 | 页面解释 |
|------|----------|
| 业务分类 | 这份模型由哪个业务范围负责 |
| 数据集市 | 这份模型面向哪个应用、主题或消费场景交付 |
| 业务维度 | 分析问题时观察业务的角度，例如组织、项目、日期 |
| 维度表 | 业务维度的一种可实现数据结构，包含字段、来源、历史处理和物化配置 |
| 物理表名规则 | 检查发布到存储引擎的表名，不检查中文模型名称 |
| 装载方式 | 全量覆盖、增量合并或只追加 |
| 维度历史处理 | SCD NONE/TYPE1/TYPE2，决定属性变化如何记录 |
| 数据保留期限 | 物理数据保留天数，不等于模型版本历史 |

## 产品结论

资产台账不需要承担数据集市管理。正确闭环是：

`业务分类/数据集市规划 → 业务维度 → 维度表 ModelSpec → 实现/发布 → 资产台账`

DataMart 的新增是补齐规划控制面，不是增加另一套资产目录。
