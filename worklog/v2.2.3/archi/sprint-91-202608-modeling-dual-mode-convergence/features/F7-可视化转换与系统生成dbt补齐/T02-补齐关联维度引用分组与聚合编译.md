# T02: 补齐关联、维度引用、分组与聚合编译

**优先级**: P0
**状态**: CODE_COMPLETE / E2E_PENDING
**依赖**: F7/T01

## 目标

让 DWD FACT、DWS SUMMARY 和 ADS APPLICATION 的多输入关系进入既有编译器，支持 ODS/上游事实与维度关联及受控聚合，补齐真实 `ODS → DWD/DIM → DWS → ADS` 链。

## 结构化配置

```text
joins: [{inputRef, type, leftField, rightField}]
groupBy: [targetField]
aggregations: [{targetField, function, sourceField, distinct}]
```

与 T01 的 `fieldMappings/casts/filters/deduplicateBy` 合并形成单一 designer settings；所有 `inputRef` 必须命中 F6 snapshot。

### 白名单

- join type：`INNER/LEFT`；本期不开放 CROSS/RIGHT/FULL。
- aggregation：`SUM/COUNT/MIN/MAX/AVG/COUNT_DISTINCT`。
- `distinct=true` 只允许 COUNT；其他函数使用各自稳定表达。
- 非聚合输出必须在 groupBy；粒度变更必须在 UI 明示目标粒度。
- DIM 引用必须使用 F6 `role=DIMENSION` 的固定实现；不允许按名称或当前最新版浮动连接。

## 编译规则

- 扩展既有 `ModelingDbtCompiler` 的结构化 settings 投影，不复制 compiler。
- source/ref 由 F6 snapshot 生成，STG 仍是系统 ephemeral 节点且不成为业务 ModelSpec。
- 输出 SQL/SCHEMA/TEST 与 CONFIG bundle 的路径、排序、checksum 必须确定性。
- 编译前再次校验字段、类型、关联键、粒度、聚合与 dependency checksum；失败不产生 implementation revision。

## Feature 关联

- F6 提供 fixed dependencies；T01 提供单来源转换。
- T03 负责将编译结果走统一 artifact/commit seam。
- F8 的 topological plan 直接使用 F6 图，不从生成 SQL 再建一张图。
- Sprint-93 的血缘投影消费提交后的解析证据，不能消费 UI 草稿。
