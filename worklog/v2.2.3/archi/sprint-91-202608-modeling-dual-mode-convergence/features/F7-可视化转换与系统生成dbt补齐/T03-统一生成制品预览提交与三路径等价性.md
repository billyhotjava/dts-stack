# T03: 统一生成制品预览、提交与三路径等价性

**优先级**: P0
**状态**: CODE_COMPLETE / E2E_PENDING
**依赖**: F7/T02、F6/T03

## 目标

将可视化配置编译出的制品通过与手工 dbt、ZIP apply 相同的 validator/freeze/import/commit seam 落成 implementation revision，并证明三种 authoring adapter 不会产生三套模型、依赖或发布语义。

## 技术设计 (Contract-first)

- 预览输入：immutable model pins + dependency checksum + designer settings checksum。
- 预览输出沿用 F2：3 个生成文件、路径、nodeKind、artifactTypes、previewChecksum，默认只读。
- 提交时补确定性 `dbt_project.yml`，组成 4 文件 canonical project，经既有 static validator、bundle freeze 与 artifact import seam 落地。
- implementation 必须记录 model、designer settings、dependency 和 artifact checksum；任何一项漂移均拒绝旧 preview commit。
- business view 不拼接或执行 SQL；工程用户可通过代码模式查看，并按现有显式接管改变 ownership。

## 三路径等价性

| 路径 | authoring 输入 | 必须相同的下游语义 |
|---|---|---|
| DESIGNER | 结构化转换配置 | ModelSpec identity、dependency snapshot、dbt uniqueId、candidate pins、asset key |
| 手工 DBT | 用户维护 SQL/SCHEMA | 同上 |
| ZIP apply | inspect→preview→apply 后的项目 | 同上；ZIP 不是独立发布/物化路径 |

允许 SQL 文本和 implementation checksum 因 authoring 方式不同而不同；不允许依赖图、目标身份、层级、粒度和资产身份不同。

## Feature 关联

- 上游：F2 预览/接管、F6 依赖/草稿、F7/T01/T02 转换配置。
- 下游：F8 planner 读取相同 pins；F5 用同一 candidate API 发布；Sprint-93 读取同一 artifact/observation 证据。

- [ ] 三路径的 dependency graph、dbt uniqueId、target selector 与 asset key 等价性测试。
- [ ] 重放同一 idempotency key 不新增 implementation 或 artifact。
- [x] 超出可视化白名单的配置拒绝生成，并保留可接管代码的明确路径。
