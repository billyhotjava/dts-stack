# T02: 收敛诊断定位、脏状态与并发冲突反馈

**优先级**: P1
**状态**: IN_PROGRESS（marker adapter 与 409/412 写锁完成；真实诊断位置与 IT-05 待补）
**依赖**: F4/T01

## 目标

使多文件编辑、服务端诊断、dirty guard、ETag 冲突和已提交只读状态保持一致，用户不会误以为失败修改已经保存。

## 技术设计 (Contract-first)

- **输入契约**: 现有 `DbtImplementationDraft` state/etag、local files、validation diagnostics、API HTTP status/error code。
- **输出契约**:
  - `DRAFT_DIRTY | DRAFT_SAVED | VALIDATED | CONFLICT | COMMITTED` 单一派生状态；
  - diagnostics 按 path 分组并转换为 Monaco markers；
  - 409/412 后禁止继续用旧 ETag 保存/提交。
- **数据流**: edit → dirty → save(new ETag) → validate(new ETag + diagnostics) → marker/list → commit(receipt) → readOnly；任一编辑清空旧 validation/commit。
- **错误路径**: 无 path/line 的诊断只进列表；path 不存在标为 project-level；冲突提供“重新读取模型 / 放弃本地修改”，不做自动 merge；过期/COMMITTED 草稿创建新草稿。
- **复用点**: 当前 `recordFailure`、dirty blocker、RequestState、draft API；抽取 reducer/纯函数，避免组件内继续堆叠条件。

## UI 交互规格

- 文件旁显示错误/警告数量；点击诊断切到文件并定位行列。
- 状态栏用客户可理解文案：“有未保存修改 / 已保存待校验 / 校验通过 / 版本冲突 / 实现已提交”。
- 关闭、切模式、返回列表和刷新均走同一 dirty confirmation。
