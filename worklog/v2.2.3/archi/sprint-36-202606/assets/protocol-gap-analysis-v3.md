## 0. 执行摘要

平台对协议 10 个功能模块的**主体能力已具备**：数据规划、采集清洗、数据存储、数据管理、数据安全、数据质量、数据服务、分析可视化、监控告警、安全保密均有真实落地的领域模型、服务与前端。

但对照协议**仍存在 13 项 P0（合规/验收硬约束）+ 19 项 P1（协议明列能力）缺口**。其中两类风险最高：

1. **安全保密合规（M10）+ 数据安全（M05）** — 机密级（BMB17.1/17.2-2024）测评是整个项目的**验收硬门槛**。当前 Keycloak **无强密码策略、未启用登录失败锁定**，**操作权限矩阵动作集硬编码为 read/write/export**，**无敏感数据自动识别引擎**，**无 BMB17.x 符合性映射与第三方测评整改台账**，且 sprint-22 已识别的会话 P0（token 裸存前端 / 生产 console 打印 Authorization / TEST_SESSION 旁路）仍未闭合。这些是机密级最基础的控制项，**不闭合则无法通过测评验收**。

2. **非功能（M11）** — 高可用（单点 PostgreSQL 无主从/无容灾、单 Traefik、Airflow LocalExecutor、单 Kafka）与协议性能指标（≥1000 在线 / ≥200 并发 / 单表 <3s / 复杂 <6s / ≥500 QPS）的**全平台压测达标证据**均缺失，属协议硬指标。

**sprint-32~35（指标/语义工作台、角色重构、审计目录 DB 化、数仓可视化）未闭合上述任何 P0 缺口**；它们闭合的是「ER 关系图前端展示（M03）」「信创多源 DB 接入（M11）」「浏览器兼容（M11）」「一键部署升级回滚（M11）」「审计目录治理（M09 日志要素）」等其他方向。

**本期 Sprint-36 聚焦决策**：选取**「数据安全与机密级合规整改」**（M05 + M10 安全域）作为单主题，理由是它是验收硬门槛、P0 最密集、技术内聚（Keycloak / IAM / Catalog masking / SecurityBaseline）、单 sprint 可落地（多为配置 + 中等规模功能，不涉及大规模架构改造）。其余 P0（M04 生命周期/销毁、M09 告警规则、M11 高可用/性能）与 P1 功能增强按 §6 roadmap 排入 Sprint-37+。

## 3. P1 缺口清单（协议明列能力，按模块）

**M01 数据规划**：流程模板未预置 seed；DOC/DOCX/PDF 在线预览缺失；文件分组/文件夹缺失；主题四级语义（业务域/职能/业务对象/分析主题）未明确；制度/规范生命周期无审批闭环。

**M02 采集清洗**：消息队列（Kafka/RocketMQ）采集源；Webhook 接收端点；JSON/日志文件离线采集（现仅 xlsx/xls/csv）；真正实时流采集（CDC 全禁用）；数据填报子系统（表单设计器/任务下发/汇总/统计，整模块缺失）；图形化细粒度算子（去重/合并/拆分/连接/统计/排序/批量加载，现需手写 SQL）。

**M04 数据管理**：数据标签管理（无 DataTag/标签目录/打标体系，仅自由文本 tags 字段）；元数据审核-发布工作流（REVIEW 为纯展示标签，无审批闭环）。

**M05 数据安全**：敏感数据自动识别引擎（正则+字典+AI 推断扫描 + 监控查询，现脱敏规则全人工标注）；脱敏任务闭环（任务编排→执行→结果查看，现仅查询期即时脱敏）；备份实际执行引擎（现 SecurityBackupPlan/Run 仅台账，无全量/增量备份恢复执行）。

**M06 数据质量**：监控预警主动推送通道（站内信/邮件/webhook + 预警触发规则）；问题工单下发主动通知责任人（与前者同根，可合并）；数据标准→质量规则事件式自动同步（现为模型生成时单向注入）。

**M07 数据服务**：内置接口聚合层（元数据/查询/更新/字典四类统一对外 Token 鉴权 + 格式协商）；数据更新对外面（ODS 编辑器现仅治理端内部端点）。

**M08 分析可视化**：节点编程逻辑三件套（触发器/转换器/定时器）+ 高亮/选中/组件显隐/页面切换交互动作；报表 Word/docx 导出（现 Excel/PDF 有，Word 零实现）+ 自建报表多格式（现仅 html/markdown）。

**M09 监控告警**：业务级监控仪表盘（现仅 JHipster JVM 脚手架，monitoring.yml 为开发态）；审计「异常原因」结构化错误码列（现依赖 summary 自由文本）。

**M10 安全保密**：密钥管理升级（密钥分级 + 轮换 + 禁明文落库回退）+ 国密 SM2/SM3/SM4 与 GM TLS 评估。

**M11 非功能**：信创多架构（amd64/arm64）镜像构建证据 + 信创真机兼容测试报告；浏览器下限（现 Chrome95 高于协议 360 极速 78 要求线，需现场确认内核版本）+ analytics/metrics 两 webapp 补 legacy 构建；交付级《测试计划》/《测试报告》主文档 + BUG 回归追溯台账。

## 6. 整改 Roadmap（建议排期）

### Sprint-36（本期）— 数据安全与机密级合规整改专项 ⭐
**目标**：闭合验收硬门槛的安全合规 P0，建立机密级测评整改底座。
- 强密码策略 + 登录失败锁定（P0-1、P0-2，Keycloak 配置 + 启动校验）
- 会话安全 P0 整改（P0-3，sprint-22 遗留）
- 操作权限矩阵（P0-6，资产×角色×完整动作集）
- 敏感数据自动识别引擎（M05 P1，规则+扫描+监控查询）
- BMB17.x 符合性映射 + 第三方测评整改台账（P0-4、P0-5，扩展 SecurityBaselineService）
- （视容量）脱敏任务执行闭环（M05 P1）

### Sprint-37（已立项）— 数据入湖上传文件加密专项 ⭐
现场实锤：入湖上传的 Excel/CSV 明文落盘，且宿主机（含 root）可从 bind 目录直接查看（world-readable），无任何自动清理机制。
- 上传文件 AES-GCM 加密存储（F1）+ Addax 运行期 tmpfs 解密（F2，宿主机目录不可见明文、不影响 Addax）+ 安全验证回归 IT（F3）
- 详见 `worklog/v2.2.3/sprint-37-202606/`（独立 sprint，不在 Sprint-36 范围内）

### Sprint-38（建议）— 数据管理生命周期与文件合规
- 生命周期 6 阶段统一闭环 + 资产专项监控（P0-7）
- 数据销毁临时/永久双态 + 一键还原沙箱（P0-8）
- DOC 旧格式支持（P0-9）+ 文件维护审批流接线（P0-10）
- 数据标签管理（M04 P1）+ 元数据审核发布工作流（M04 P1）

### Sprint-39（建议）— 可观测性与高可用
- 自定义告警规则 + 业务监控仪表盘（P0-11、M09 P1）
- 高可用集群 + 负载均衡（P0-12，PG 主从+PgBouncer / 多副本+LB / Airflow Celery / Kafka 多 broker）
- 协议性能指标全平台压测达标报告（P0-13）

### Backlog（P1 功能增强，按业务优先级穿插）
- M02 数据填报子系统、MQ/Webhook/JSON 采集、图形化算子
- M06 预警/通知推送统一能力（一次落地覆盖 M06-2/M06-4）
- M07 内置接口聚合层、数据更新对外面
- M08 节点编程三件套、Word 导出
- M11 信创多架构镜像 + 真机测试、测试计划/报告主文档、密钥管理/国密升级
