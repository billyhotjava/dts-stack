## 3. 协议子项逐项核验

### 3-1 多层级数据主题规划（业务域/职能/业务对象/分析主题）— 🟡 partial
- **后端**：`CatalogDomain` 自引用 `parent_id`（第31-33行），支持任意层级树。`CatalogDomainResource` 提供 CRUD + tree。
- **前端**：`dts-platform-webapp/src/pages/governance/SubjectAreasPage.tsx` 用 antd `Tree` 渲染 `getDomainTree()`，含 `parentId/children`、递归 `buildDomainIndex/flattenDomains/filterSystemDomains`，支持新建/编辑/删除域并挂父域。
- **缺口**：层级是「通用域树」自由建模，**没有按协议明确区分的「业务域 / 职能域 / 业务对象 / 分析主题」四类语义层级**（无 levelType/domainKind 字段，无四级模板约束）。业务对象、分析主题在 dts-metrics 语义层另起炉灶（SemanticObjects/SemanticSubjects），与 platform 主题域不是一棵统一规划树。
- **优先级**：P1

### 3-2 制度/标准/规范全生命周期管理 — 🟡 partial
- **生命周期状态机存在**：`DataStandardStatus`={DRAFT, IN_REVIEW, ACTIVE, DEPRECATED, RETIRED, ARCHIVED}（`domain/modeling/DataStandardStatus.java`）；版本状态 `DataStandardVersionStatus`={DRAFT,IN_REVIEW,PUBLISHED,ARCHIVED}。`DataStandardService` 有 create/update/archive/版本快照（createVersionSnapshot）。
- **缺口**：状态切换由 `update()` 直接写入（ModelingResource `PUT /standards/{id}` 透传 status），**不经过任何审批流转**；`IN_REVIEW` 只是一个可被任意 maintainer 直接设置的值。没有「制度/规范」独立实体——协议的"制度/规范"目前完全复用 DataStandard + 附件，没有专门的制度文档对象、生效日期、废止留痕、强制评审周期闭环（有 `reviewCycle/lastReviewAt` 字段但无到期触发器/提醒）。
- **优先级**：P1

### 3-3 多格式文件管理（DOC/DOCX/PDF）— 🔴 gap
- **当前允许格式**：`DataStandardProperties` 默认 `allowedExtensions = {docx, wps, pdf, xlsx, xls, md, txt}`（最大 200MB）。`AttachmentSignatureValidator` 校验魔数：docx/xlsx(ZIP)、xls/wps(复合文档)、pdf(%PDF)、txt/md(UTF-8)，并拦截 MZ 可执行头。
- **缺口（硬伤）**：协议明确要求 **DOC**（旧版 Word 复合文档），但 `doc` **既不在 allowedExtensions，也未在 AttachmentSignatureValidator 中处理**（复合文档魔数 D0CF11E0 当前只映射给 xls/wps）。上传 .doc 会被 `validateFile` 直接拒绝。
- **优先级**：P0（协议格式硬约束，"DOC/DOCX/PDF" 三选其一缺一不可）

### 3-4 文件分组 / 上传 / 下载 — 🟡 partial
- **上传/下载已实现**：`DataStandardAttachmentService.upload/list/download/getMetadata/delete`，落库或文件系统两种策略（`storageStrategy`），AES 加密 + IV + sha256 + keyVersion。前端 API：`uploadStandardAttachment / listStandardAttachments / deleteStandardAttachment`（platformApi.ts 529-538）。
- **缺口**：附件**只能挂在单个 DataStandard 之下**（`findByStandardOrderByCreatedDateDesc`），**没有独立的「文件分组 / 文件目录 / 文件夹」概念**——无 fileGroup/folder/category 实体，无法跨标准做制度/规范文件的分组归档与浏览。**无下载列表的批量打包/分组下载**（download 单文件）。
- **优先级**：P1

### 3-5 在线预览 — 🔴 gap
- ModelingResource 附件相关端点仅 `attachments`(list) / `attachments/{id}/download`(下载)；**无任何 preview / inline / onlyoffice / kkfileview / pdf.js 端点或前端预览组件**（grep 全空）。下载强制 `ContentDisposition.attachment`。
- **缺口**：协议「文件管理」隐含的 DOC/DOCX/PDF 在线预览能力完全缺失。
- **优先级**：P1

### 3-6 文件维护审批流程 — 🔴 gap
- **工作流引擎存在但未接线**：`AdminWorkflowTemplate`(workflow_type/name/enabled/priority/ownerScope/classification min-max) + `AdminWorkflowStep` + `AdminWorkflowConfigService`(CRUD)；建表 changelog `20260116-01_workflow_config_tables.xml`。
- **缺口**：`AdminWorkflowConfigClient`（platform 侧）唯一消费者是 `DatasetDataAccessApprovalService`（数据集访问审批）。**附件上传/删除、数据标准/制度文件维护没有任何一处调用工作流模板**——`DataStandardAttachmentService.upload/delete` 直接落库无审批；`DataStandardService` 状态变更无审批。**文件维护审批流为 0 覆盖。**
- **优先级**：P0（协议明确要求"文件维护审批流程"）

### 3-7 数据管理流程落地（流程模板预置）— 🔴 gap
- **引擎可配置**：`AdminWorkflowConfigService.listTemplates(type, onlyEnabled)` 当无模板时返回 `List.of()`（空）；模板需运行时手工创建。
- **缺口**：changelog 只建表，**无任何流程模板 seed 数据**（grep `INSERT ... workflow_template` / `workflowType DATA_STANDARD` 均空）。即「数据标准评审」「制度文件审批」「主题规划评审」等流程**没有预置模板**，开箱即用为空。这正是前序"流程模板待预置"缺口，**仍未闭合**。
- **优先级**：P1

### 3-8 数据标准定义维护（填写 + 模板导入）— ✅ covered
- **手工填写**：`POST/PUT /modeling/standards`（ModelingResource 254/276）+ 前端 `createStandard/updateStandard`（platformApi 524-525），类型见 `pages/modeling/data-standards-utils.ts`，治理前端 ElementsPage/GovernanceCenterPage。
- **模板导入**：`GET /standards/import-template`、`GET /standards/template`（带 UTF-8 BOM）、`POST /standards/import`（CSV，`DataStandardImportService.importCsv` 返回 created/updated/skipped/errors）；元数据标准模板 `GET /metadata-standards/template`(zip) + `POST /metadata-standards/import`。前端 `importStandards/importMetadataStandards`。
- **结论**：填写与模板导入双路径齐全，审计埋点完整（MODELING_STANDARD_IMPORT 等）。**已覆盖。**

## 5. 模块结论

整体 **partial**。数据主题树（多层级）、数据标准定义维护（填写+模板导入）、附件上传/下载/加密/版本快照、生命周期状态枚举均已落地且仍存在。但协议硬要求项存在三处真实缺口：(1) **DOC 旧格式不支持**（P0，allowedExtensions 与签名校验均无 doc）；(2) **文件维护审批流未接线**（P0，工作流引擎仅服务数据集访问审批）；(3) **流程模板未预置 + 在线预览缺失 + 文件分组缺失 + 主题四级语义未明确**（P1）。前序三大缺口在近四个 sprint 中均未闭合。
