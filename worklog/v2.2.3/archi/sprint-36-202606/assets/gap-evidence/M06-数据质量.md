## 子项逐条核验

### 子项 2.3.2.6-1 规则定义/发布/维护 + 内置规则(非空/唯一/正则/阈值) + 联动数据标准自动同步

**status: covered(联动数据标准为单向、生成时注入,非事件式实时同步 — 记 partial 风险点)**

核验过程与证据:

1. **规则定义/发布/维护 + 版本化**:`service/governance/QualityRuleService.java`
   - CRUD: `createRule` / `updateRule` / `deleteRule` / `toggleRule`(L328-443)
   - 版本化: 每次 upsert 写 `GovRuleVersion`(`persistVersion` L526),`changeRuleVersionStatus`(L445)实现 DRAFT→PUBLISHED→ARCHIVED 状态机(`ensureStatusTransitionAllowed` L595),发布时自动归档旧已发布版本(`archiveOtherPublishedVersions` L559)。
   - 实体: `domain/governance/GovRule.java`(code/type/dataset/severity/dataLevel/frequencyCron/enabled/latestVersion/template/autoTrigger) + `GovRuleVersion.java` + `GovRuleBinding.java`(数据集/字段/过滤/调度覆盖绑定)。
   - 全程审计: `auditService.auditAction("GOV_RULE_MANAGE"/"GOV_RULE_VERSION_STATUS", ...)`。
   - 部门/密级可见性与写权限: `isRuleVisible` / `ensureRuleWritable` / `enforceOwnerDept`(institute/department scope)。

2. **内置规则(非空/唯一/正则/阈值)**: 以"内置质量模板 + SQL 模板渲染"实现,**确认覆盖**。
   - 实体: `domain/governance/GovQualityTemplate.java`(`builtin` 标志 / `paramSchema` jsonb / `sqlTemplate` / `severityDefault` / `actionDefault` / `dialect`)。
   - 渲染: `service/governance/SqlTemplateRenderer.java`(`{{param}}` 占位符 + 标识符白名单正则防注入)。
   - 内置种子: `resources/config/liquibase/changelog/20260404_02_gov_quality_template_seed.xml`,实测含 **非空 / 唯一 / 正则 / 阈值**(另含 枚举 / 范围),与协议要求一一对应。
   - 模板管理 REST: `GET/POST/PUT/DELETE /api/governance/quality/templates` + `/{id}/preview`(GovernanceResource L556-631)。

3. **联动数据标准自动同步**(协议要求): **单向、生成时注入,非事件式实时同步**。
   - 正向证据: `service/modeling/ModelFileService.java` 的 `writeAutoQualityTemplate` / `buildAutoQualityYaml`(L153/L476):为生成模型逐列读取 `column.standardId()` / `column.standardRule()`,产出 dbt `not_null` / `unique` / `relationships` 测试,并把 standard_id / standard_rule 写入列 `meta`(L505-511)。即"数据标准绑定 → 自动生成 dbt 质量测试元数据"。
   - DataStandard 体系健在: `service/modeling/DataStandardService.java`(+ Mapper/Import/Version/Attachment/Crypto/Security)。
   - **不足**: `QualityTaskService` 注入的 `DataStandardSecurity` 仅用于 dept/scope 鉴权(`security.resolveActiveDept` L79),**并非**标准→规则的内容同步;`service/modeling/*` 中无 "data standard 变更 → 质量规则/绑定自动刷新" 的事件式监听(检索 `quality|GovRule|syncRule` 无反向命中)。当数据标准(如码值域、正则)变更后,已存在的质量规则不会自动重算/重绑,需重新生成模型或人工维护规则。

缺口: "联动数据标准自动同步"目前是**模型生成时一次性单向注入**,缺少标准变更驱动的实时/增量同步与"受影响规则"提示。
优先级: **P1**(业务价值明确;协议明文要求"自动同步"。非合规硬约束,故非 P0)。
落地包建议: 增加 DataStandard 版本发布事件 → 订阅器扫描引用该 standardId 的 GovRule/GovRuleBinding → 标记 stale 并生成"待复核"提示或可选自动重算阈值/正则;前端规则列表展示"标准已更新,建议同步"角标。

### 子项 2.3.2.6-2 可视化检查任务定义/执行 + 监控预警

**status: partial(任务定义+执行+调度+仪表盘监控完整;主动预警推送缺失)**

核验过程与证据:

1. **任务定义/执行**: `service/governance/QualityTaskService.java` + `domain/governance/GovQualityTask.java` / `GovQualityRun.java`。
   - REST: `GET/POST/PUT /api/governance/quality/tasks`、`/{id}/toggle`、`/{id}/trigger`、`DELETE`(`web/rest/GovernanceQualityTaskResource.java`)。
   - 运行执行: `service/governance/QualityRunService.java`(`triggerRun` / `doExecuteRun`,独立事务 PROPAGATION_REQUIRES_NEW + 事务后异步执行 L155-169),按规则 severity 落 run(L140),计算 rowsTotal/failingRowCount/通过率(L671-)。
   - 执行器抽象: `QualityStatementExecutor`(接口) → `PgStatementExecutor`(入湖预检)/ Hive(湖内巡检);`IngestionQualityBridge` 在入湖前做 PRECHECK。
   - 入湖即检 / 自动触发: `POST /api/governance/quality/auto-trigger`(GovernanceResource L1028)联动自动清洗 + 检测。

2. **调度**: `service/governance/QualityTaskScheduler.java` — `@Scheduled(fixedDelayString=...)` 定期 `taskService.runDueTasks()`(默认 60s,可配 `dts.platform.governance.quality.task-scheduler-delay-ms`);规则/绑定支持 `frequencyCron` / `scheduleOverride`。

3. **可视化任务定义(前端)**: `pages/governance/components/QualityTasksPanel.tsx`(435 行)/ `QualityTasksTab.tsx`、`components/RuleCreateWizard.tsx`(规则向导,含 BLOCK 阻断 / WARN 仅告警 动作选择)、`TemplatesTab.tsx`。

4. **监控**: `service/governance/QualityDashboardService.java`(ruleCount / coveredDatasets / today passed-failed / 趋势 TrendPoint / 失败数据集 FailingDataset)→ `GET /api/governance/quality/dashboard`;前端 `components/QualityDashboard.tsx`(177 行)。`GovernanceCenterPage.tsx` 展示合规检查的"实际值 vs 阈值"告警条(L135-143)。

5. **预警**(协议明文"监控预警"): **被动式存在,主动推送缺失**。
   - 已有: 规则级 action `WARN(仅告警)` / `BLOCK(阻断)`(前端 RuleCreateWizard L69、TemplatesTab L54;模板 `actionDefault`);失败在仪表盘可见;失败自动生成问题工单(见子项4)。
   - 缺失: 检索 `service/governance/` 全量,**无 alert/notify/email/webhook/站内信 发送逻辑**;全平台无 Notification/Message/Inbox 实体(`find domain -iname "*Notification*"/*Message*/*Inbox*` 空)。即阈值越界/连续失败不会**主动推送**给责任人/订阅者,只能登录后在仪表盘/工单中被动发现。

缺口: 缺主动预警推送通道(站内信/邮件/webhook)与预警规则(连续失败 N 次、通过率跌破阈值、SLA 超期触发)。
优先级: **P1**(协议明文"监控预警";业务价值高、口径明确;非合规硬约束)。
落地包建议: 新增轻量 Notification/订阅 模型 + QualityRunService 完成后评估 severity/通过率阈值触发 → 站内信(优先,无外部依赖)+ 可选邮件/webhook;预警订阅可复用 ownerDept/assignedTo;前端governance 增"我的预警"入口。

### 子项 2.3.2.6-4 向责任人下发问题处理任务 + 记录结果

**status: covered(下发为"分派+审计+工单动作",无主动推送 — 推送部分与子项2同根)**

核验过程与证据:

1. **问题工单 + 下发**: `service/governance/IssueTicketService.java` + `domain/governance/GovIssueTicket.java`。
   - 自动生成: 质量检测失败时 `QualityRunService` 调 `issueTicketService.createOrTouch("QUALITY_RUN", run.getId(), req, actor, "系统自动生成:质量检测失败")`(QualityRunService L390-416)。
   - 责任人分派: `assignedTo` + 默认受理人 `properties.getIssue().getDefaultAssignee()` + `assignedAt`(IssueTicketService L190-194);按 assignedTo/owner/status 过滤查询(L117-123)。
   - SLA: 按 severity/priority 计算 `dueAt`(`resolveSlaDuration`,L197/310)。

2. **记录结果 / 处理动作**: `domain/governance/GovIssueAction.java` + `appendAction`(actionType NOTE/AUTO_NOTE,L357-368);状态机 OPEN→IN_PROGRESS→RESOLVED→CLOSED(`ensureStatusTransition` L293),`resolution` 必填、`resolvedAt`,`close`(L330);指标 `/issues/metrics`(L850)。
   - REST: `GET/POST/PUT /api/governance/issues`、`/{id}/close`、`/{id}/actions`、`/{id}`、`/metrics`(GovernanceResource L731-850)。
   - 全程审计: `GOV_ISSUE_CLOSE` 等。
   - 前端: `pages/governance/GovernanceCenterPage.tsx`(186 行,工单中心)。

3. **"下发"的不足**: 下发=工单分派 + assignedTo + 审计事件 + AUTO_NOTE,**无主动通知推送**(同子项2根因,无 email/站内信/webhook)。责任人需主动进入工单中心查看。

缺口: 下发缺主动通知(责任人不登录则不知有新工单/超期);处理结果留痕完整。
优先级: **P1**(与子项2共用一套通知能力即可闭合)。
落地包建议: 工单 createOrTouch / 状态变更 / SLA 临期 → 站内信通知 assignedTo;复用子项2的 Notification 模型,一次落地覆盖两项。
