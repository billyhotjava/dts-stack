## 3. 子项逐项核验

### 2.3.2.7-1 数据查询（多场景/统一查询/即席查询）— ✅ covered

证据:
- 即席查询(SQL IDE/探索): `web/rest/ExploreResource.java` (`/api/explore`) `POST /query/preview`、`POST /execute`、`POST /explain`、保存结果集、`web/rest/SqlResource.java` (`/api/sql/query`)、`web/rest/sql/SqlIdeExecutionController.java`。统一经 `service/query/QueryGateway.execute(sql)` 执行。
- 统一查询网关: `service/query/QueryGateway`(被 ExploreResource、SqlResource、SvcApiQueryService 共同复用,构成统一查询入口)。
- 多场景: 探索预览(preview)、执行(execute)、解释(explain)、结果集保存/复用/清理(`/result-sets`)、Token 化对外查询(OpenApiResource)多入口覆盖。

判定: 覆盖。统一查询入口(QueryGateway)+ 即席查询(Explore/SQL IDE)+ 多场景(预览/执行/解释/结果集)齐全。

### 2.3.2.7-2a 数据交换 — 界面自定义数据 API — ✅ covered

证据(完整闭环):
- 前端建模: `dts-platform-webapp/src/pages/services/ApiServicesPage.tsx` 创建表单支持 服务名称/编码/HTTP方法/路径/分类/数据集(datasetId)/policy/字段 配置;`api/services/apiServicesService.ts` 对接后端。
- 后端 CRUD + 发布: `web/rest/ApiServicesResource.java` (`/api/services/apis` list/detail/try/metrics) + `web/rest/ApiGatewayResource.java` (`/api/apis/{id}` test/publish/execute);`service/services/ApiCatalogService.java` create/update/disable/publish。
- 对外消费: `web/rest/OpenApiResource.java` (`/openapi/{code}`) Token 鉴权 + `service/services/SvcApiQueryService.java` 基于绑定数据集(`CatalogDataset`)动态拼装 SELECT(`buildSelectSql`)经 `QueryGateway.execute` 真实查询,带脱敏(CatalogMaskingService)、配额(enforceQuota)、批量(batchQuery)。

判定: 覆盖。这是真实数据查询(非 mock),用户在界面自定义字段/数据集即生成对外可调用的数据 API。

> 备注: `ApiCatalogService.tryInvoke/execute`(管理端"测试调用",`/api/apis/{id}/execute`)返回 `sampleValue` 样例行,非真实查询;但真实对外查询走 `OpenApiResource`+`SvcApiQueryService`,二者职责不同,不构成缺口。

### 2.3.2.7-2b 数据交换 — 内置接口（元数据/数据查询/数据更新/数据字典）— 🟡 partial

四类能力**均在代码中存在**,但**未被打包为一组统一的"内置数据接口"对外服务(无统一 Token 鉴权/统一目录/统一格式协商)**,而是分散在各自的内部管理端点:

| 内置接口 | 当前实现 | 暴露端点 |
|----------|----------|----------|
| 元数据查询 | `service/catalog/CatalogMetadataService.java` (listLocalTables/列计数等) | 经 `web/rest/catalog/CatalogDatasetResource.java` 暴露 |
| 数据查询 | `SvcApiQueryService` / `ExploreResource` / `SqlResource` | `/openapi/{code}`、`/api/explore`、`/api/sql/query` |
| 数据更新 | `service/governance/OdsDataEditorService.java` updateRow/insertRow(真实 UPDATE/INSERT + 编辑日志 GovDataEditLog) | `web/rest/GovernanceResource.java` `/api/governance/data-editor/tables｜columns｜rows｜{table}/rows/{id}` |
| 数据字典 | `service/governance/ReferenceCodeService.java` 码表目录/码值 CRUD | `web/rest/GovernanceReferenceCodeResource.java` |

差距:
1. 四类接口分散在 catalog / explore / governance 三个不同 Resource,**没有一个"内置接口"统一注册目录 / 统一对外契约**;协议语境下"内置接口"通常指与自定义 API 并列、对外可订阅的一组标准化数据交换接口。
2. "数据更新"内置接口走的是治理端 ODS 数据编辑器(`/api/governance/data-editor`),面向内部治理操作,**未以对外数据交换 API 形式(Token 鉴权 + 统一格式)开放**,与协议"数据交换-内置接口"语义存在错位。
3. 元数据/字典查询同样仅作为内部管理端点,**未纳入 `/openapi` 这一对外 Token 鉴权交换面**。

判定: 部分覆盖。四类能力实现存在且真实可用,但缺少"统一内置接口对外服务面"的聚合层。

### 2.3.2.7-2c 数据交换 — 格式（JSON + XML + CSV）— ✅ covered

证据:
- JSON: 默认。`OpenApiResource.buildResponse` 默认 `ApiResponses.ok(payload)`(JSON);`SqlResultStreamServiceImpl.exportJson`(流式 JSON 导出)。
- XML: `OpenApiResource.buildResponse` 当 `Accept: application/xml` 时调用 `toSimpleXml(payload)` 返回 `MediaType.APPLICATION_XML`(含 escapeXml)。类头注释明确"JSON/XML for technical agreement 5.4"。
- CSV: `service/sql/SqlResultStreamService.exportCsv` + `SqlResultStreamServiceImpl.exportCsv`(UTF-8 BOM + escapeCsv)。

判定: 三种格式齐全。XML 在 OpenApiResource 已实现内容协商,前序"复核 XML 是否齐全"得到确认——XML 已实现。

> 小提示: XML 当前为简单内联拼装(`toSimpleXml`,固定 code/name/rows 结构),非通用 XmlMapper 序列化;对复杂嵌套 payload 表达力有限。属可优化项,非缺口。

## 5. 落地包建议（针对 partial 项）

- P1 内置接口聚合层: 新增 `/openapi/builtin/{type}` 或在数据服务目录中注册"内置接口"分组,把 元数据查询/数据查询/数据更新/数据字典 四类统一收口到与自定义 API 同一套 Token 鉴权 + 格式协商(JSON/XML/CSV)契约下,提供统一调用目录与审计。
- P1 数据更新对外面: 将 `OdsDataEditorService` updateRow/insertRow 以受控对外数据交换 API 形式暴露(Token 鉴权 + 字段白名单 + 编辑日志 + 审批/配额),而非仅治理端内部端点。
- P2 XML 序列化通用化: 用 `XmlMapper`(Jackson dataformat-xml)替换 `OpenApiResource.toSimpleXml` 内联拼装,支持任意 payload 结构。
- P2 CSV 纳入 /openapi 内容协商: 当前 CSV 仅在 SQL IDE/Explore 导出可用,建议 `OpenApiResource.buildResponse` 也支持 `Accept: text/csv`,使三格式在对外交换面一致。
