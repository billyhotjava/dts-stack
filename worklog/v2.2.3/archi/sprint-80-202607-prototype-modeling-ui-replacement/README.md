# Sprint-80：原型驱动的数据建模前端替换

**时间**：2026-07  
**状态**：READY_FOR_UI_REVIEW  
**类型**：Frontend Architecture / Information Architecture / Controlled UI Retirement  
**目标**：以 `worklog/prototype/dm` 为唯一 UI 规格，将原型页面迁入 DTS 主产品；删除旧建模展示页面，并把“数据建模”提升为与“数据开发与运维”同级的顶级菜单。

## 用户确认的范围

1. 原 DTS 建模展示页面全部由原型页面替换。
2. 原“数据开发与运维”下的建模菜单全部删除。
3. 新增顶级菜单“数据建模”。
4. 原型“首页”收敛为直属“数据建模”的“建模概览”，其余 6 个模块成为能力分组。
5. 各模块内部菜单继续成为三级或四级菜单。
6. 本 Sprint 先完成界面、路由和导航重构，不修改 Java、API、业务表、状态机或物化流程。
7. 前端全部编码结束后再集中执行 E2E，避免反复扫描和重复验证。

## 与 Sprint-79 的关系

Sprint-80 取代 Sprint-79 中以下 UI 决策：

- 不再把 7 个模块放在单一“建模工作台”的内部 Tab。
- 不再保留旧建模菜单作为并行入口。
- 不再限制为“不新增一级菜单”。
- 不再复用旧建模展示页面作为正式 UI。

Sprint-79 已形成的后台 owner、权限边界、状态机、发布/物化职责分离和审计约束仍保持不变；本 Sprint 不修改这些后台契约。

| ID | 决策 | 说明 |

| ADR-80-04 | 原型导航壳不进入页面内容 | DTS 全局侧栏承载二至四级菜单，内容区只迁移原型业务画布 |
| ADR-80-05 | 无后台能力的最终动作必须失败关闭 | 保存、提交、发布、物化、导入、导出等不模拟成功；显示“后台能力待接入” |
| ADR-80-06 | 原型 Demo 数据不作为生产事实 | 开发评审可使用明确标识的 fixture；正式默认展示空态或只读样例态 |

| ADR-80-08 | 旧 URL 只保留一版前端重定向 | 菜单和旧组件立即移除；书签跳转到最接近的新页面，不继续渲染旧 UI |
| ADR-80-09 | 菜单数据配置属于本 Sprint 导航范围 | 允许修改 seed/Liquibase 菜单配置；禁止修改 Java 服务、API 或业务数据库结构 |
| ADR-80-10 | 正式页面按能力拆分 | React/TSX/CSS 文件保持可审阅边界，单文件不超过 800 行 |
| ADR-80-11 | 保留一级根菜单，隐藏重复视觉 Label | 根菜单继续承载权限、图标、折叠和路由；仅当单根菜单与分组 Label 同名时隐藏 Label |
| ADR-80-12 | 管理端默认只展示活动菜单 | `dts-admin-webapp` 默认使用活动树，并通过“显示已禁用菜单”开关保留审计和恢复入口 |

## 实施顺序

1. 冻结原型到页面/路由/组件映射。
2. 新建 `pages/data-modeling`，实现共享视觉、建模概览与 6 个能力工作区。
3. 建立 `/data-modeling/**` 静态路由和动态菜单解析。
4. 将“数据建模”提升为顶级菜单并从 `studio` 删除旧节点。
5. 替换工作台等外部嵌入点。
6. 迁移仍被复用的 contract/helper，删除旧展示页面和失效测试。
7. 所有编码结束后统一执行定向测试、构建和 E2E。

## 当前非阻断假设

- “最近访问”和“我的任务”作为建模概览内的独立面板，不再占用菜单层级。
- 数据标准 5 个菜单使用各自正确的表头和空态，不复制“字段标准”表。
- 关系图 3 个路由复用同一画布组件，但关系类型、标题和筛选器不同。
- 逆向建模补齐 4 步纯前端向导外观；任何“生成”动作保持禁用。
- 通用工具的 6 个工具保留为工具箱卡片，不成为更深层菜单。
- 新菜单沿用原建模菜单的角色可见范围；权限模型本 Sprint 不扩张。
- DataWorks 截图中的“行业模型模板”未进入当前原型顶部导航，本 Sprint 不增加。
