# Sprint-82：数据资产地图与治理台账工作台重构

## 1. Sprint 目标

把数据资产域收敛为两个职责明确、可以闭环的入口：

1. **资产地图**只承担“看全局、找方向”：展示资产分层、主题域、类型、治理状态和标签覆盖的概要分布，并把用户引导到资产台账。
2. **资产台账**承担“找资产、看详情、做治理”：统一承载检索筛选、资产档案、标签、责任、质量、血缘、权限、密级与生命周期。
3. 将台账每行分散的 7～8 个动作收敛为一个“治理资产”入口，由治理工作台根据缺口给出当前任务、推荐下一步和上下文操作。
4. 打通数据标签的“维护标签 → 查看关联资产 → 选择资产 → 绑定/解绑 → 回查”旅程。

## 2. 范围

### 2.1 本 Sprint 包含

- 数据地图概要页的信息架构与跳转重构。
- 数据标签从地图迁入资产台账，保留旧 URL 的兼容跳转。
- 资产台账导航、筛选、行操作和资产治理工作台重构。
- 资产档案中的标签、治理责任、质量、血缘、权限、密级与生命周期入口收敛。
- 数据标签按资产身份 CatalogAssetType + CatalogAssetKey 绑定。
- 页面能力矩阵、按钮/组件矩阵、源契约、单元测试和最终集中 E2E。

### 2.2 本 Sprint 不包含

- 新增第三个资产一级菜单或重复详情页。
- 改造数据集成、连接、数据建模、数据质量的业务控制面。
- 新建第二套标签、分类分级、权限、质量或血缘后端 owner。
- 在资产地图中执行治理写操作。
- 未经确认的数据库删除、历史数据迁移和容器部署。

## 3. 产品原则

| 原则 | 约束 |
|---|---|
| 地图是概要，不是详情 | 地图只显示聚合和导航，不承载标签字典维护、资产编辑和治理表单 |
| 台账是唯一资产工作入口 | 搜索、筛选、详情和治理动作全部在台账或资产档案完成 |
| 一条资产一个主入口 | 表格行只保留“治理资产”，不平铺模块菜单 |
| 任务驱动治理 | 工作台先解释阻断原因，再给一个推荐下一步 |
| 标签与分类分级分离 | 标签用于业务发现；分类分级/密级用于治理和访问控制 |
| 身份统一 | 所有跨模块动作使用 CatalogAssetType + CatalogAssetKey |
| 复用 canonical owner | 标签、权限、质量、血缘、生命周期均复用现有 API/服务 |
| 失败关闭 | 缺少身份、权限或能力时明确提示，不模拟保存成功 |

## 4. 信息架构

### 4.1 资产地图

- 顶部：资产总数、可消费资产、治理阻断、标签覆盖率等概要指标。
- 主体：按主题域、数仓分层、资产类型、治理状态形成可下钻的分布视图。
- 交互：点击聚合项跳转资产台账并携带筛选条件。
- 不展示：标签字典维护、资产字段详情、治理表单、权限申请、发布动作。

### 4.2 资产台账

- 一级页签：资产列表、数据标签。
- 资产列表：搜索、主题域/分层/类型/治理状态/标签筛选、分页、治理入口。
- 数据标签：分类与标签字典、使用量、关联资产、批量绑定。
- 行操作：仅保留“治理资产”。
- 治理工作台：当前治理任务、阻断原因、推荐下一步、概要事实、数据标签和关联模块入口。
- 完整资产档案：字段契约、治理责任、质量与 SLA、血缘与影响、权限申请、密级与生命周期。

## 5. 架构决策

### ADR-82-01：不新增页面和菜单

沿用 /catalog/assets 与 /catalog/assets/ledger。旧 /catalog/assets?tab=catalog-tags 跳转到 /catalog/assets/ledger?tab=catalog-tags。

### ADR-82-02：标签能力迁入台账

标签字典和资产关联属于资产治理，不属于概要地图。标签在台账中既是筛选条件，也是可治理属性。

### ADR-82-03：单入口治理工作台

表格行不再暴露权限、详情、治理、更多、血缘、报表、产品、API 等并列动作。工作台依据资产就绪度决定“继续治理”的目标，同时保留进入完整资产档案的能力。

### ADR-82-04：第一阶段不新增后端 API

优先复用现有标签检索、能力校验、单资产绑定/解绑和批量绑定接口。只有在契约测试证明现有 API 无法闭环时，才新建后端 Task 并重新做影响分析。

### ADR-82-05：集中验证

Feature/Task 编码期间只执行必要的 RED/GREEN 定向测试；全部编码结束后统一执行类型检查、模块测试、Chrome 95 回归和 E2E。不编译或重启容器。

## 7. Definition of Done

- 资产地图不再承载标签管理或资产治理详情。
- 地图所有下钻都进入资产台账，并保留筛选上下文。
- 资产台账可按标签过滤，数据标签页可查看关联资产并发起关联。
- 台账每行只有一个治理主入口。
- 治理工作台能解释阻断原因、显示当前治理任务并提供一个推荐下一步。
- 标签可在治理工作台中绑定/解绑，并能回查。
- 原有资产档案、密级与生命周期、质量、血缘、权限能力仍可达。
- 旧标签 URL 兼容跳转，无重复页面。
- 变更页面的 source-contract 已更新，单文件不超过 800 行。
- 全部编码结束后，定向测试、类型检查、Chrome 95 和核心 E2E 通过。

## 8. 风险与门禁

| 风险 | 门禁 |
|---|---|
| 地图和台账职责再次混杂 | 页面能力矩阵禁止地图出现写操作 |
| 行操作减少后能力不可达 | 按钮/组件矩阵逐项映射到治理工作台或完整档案 |
| 标签与分类分级混淆 | UI 分区、接口和文案保持独立 |
| 资产身份缺失导致 404 | 工作台在跳转/写入前校验 assetType + assetKey |
| 批量绑定越权或过量 | 先做 capability 校验，限制为当前页选择，失败关闭 |
| 大文件继续膨胀 | 新能力提取独立组件，页面文件保持 800 行以内 |
| 旧链接失效 | source-contract 覆盖兼容跳转 |
| 测试干扰并行重构 | 不做容器编译；最终只对本 Sprint 影响模块集中验证 |
