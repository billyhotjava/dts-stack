# 数据资产域画像

## 1. Canonical Owner

| 能力 | Canonical owner | 本 Sprint 处理 |
|---|---|---|
| 资产身份 | CatalogAssetType + CatalogAssetKey | 全部跳转、筛选和标签写入复用 |
| 资产检索/台账 | Catalog asset query/resource | 只调整前端组织与现有查询参数 |
| 主题域/数仓分层 | Catalog domain / classification facts | 地图聚合、台账筛选和治理阻断复用 |
| 数据标签 | CatalogTagResource / CatalogAssetTagService | 复用字典、能力校验、绑定、解绑、批量绑定 |
| 分类分级/密级 | 现有 classification 与 lifecycle owner | 与业务标签分区展示，不复制状态 |
| 质量与 SLA | 现有质量控制面 | 只提供资产上下文入口和证据摘要 |
| 血缘与影响 | 现有 lineage owner | 只提供资产上下文入口 |
| 权限申请 | 现有访问申请 owner | 只提供资产上下文入口 |
| 审计 | 公共 AuditService | 写操作继续由现有后端审计 |

## 2. 核心身份与状态

### 2.1 资产身份

- assetType：资产类型。
- assetKey：该类型下稳定、可路由的资产键。
- datasetId 只在数据集专属能力中使用，不替代统一资产身份。
- 缺少 assetType 或 assetKey 时，标签治理和跨模块跳转失败关闭。

### 2.2 标签

- 标签是业务发现属性，可多选。
- 标签可绑定和解绑，但不改变分类分级和密级。
- 标签使用量是聚合事实，关联资产必须经可见性过滤。

### 2.3 治理就绪度

工作台沿用现有就绪度解析结果：

- BLOCKED：存在阻断，例如缺少主题域、责任人或必要分类事实。
- WARNING：可继续使用，但存在映射、质量或治理提示。
- READY：已满足当前可消费条件。
- FALLBACK：证据不足，必须明确提示，不能伪装成 READY。

## 3. 生命周期与密级约束

- 数据在接入时继承字段或文件的密级。
- 后续 ETL/ELT、建模、质量、资产和大屏链路只能保持或升高密级，不能降低。
- 派生资产密级由输入数据的最高密级决定。
- 大屏密级由展示数据的最高密级决定。
- 本 Sprint 只保证资产治理工作台可以到达既有“密级与生命周期”能力，不重建该控制面。

## 4. 权限与失败语义

- 读操作遵循现有资产可见性过滤。
- 标签写入前使用现有 capability 契约判断可管理性。
- 批量操作任一资产不可见或无权限时，不显示虚假成功。
- 404“资产不存在或无权访问”必须保留明确语义，前端不得吞掉。
- 工作台显示的推荐动作必须对应真实可达页面或真实写接口。

## 5. 数据量与性能约束

- 台账默认分页 10，不改为一次性加载全部资产。
- 标签批量水合沿用后端批量查询，禁止逐行请求。
- 标签关联最多选择当前页资产，天然小于现有批量接口上限。
- 地图只消费聚合接口，不为绘图拉取全量资产详情。
- 新增组件不得制造 N+1 请求。
