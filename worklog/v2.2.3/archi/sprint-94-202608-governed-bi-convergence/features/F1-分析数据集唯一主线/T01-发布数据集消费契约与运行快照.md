# T01：发布数据集消费契约与运行快照

**优先级**：P0
**状态**：DRAFT
**依赖**：F0/T01、F0/T02、F0/T03

## 可测试目标

平台提供稳定的已发布数据集分页/详情 DTO 和 service-auth 运行契约；Analytics 可按 `datasetId+version+checksum` 获取运行快照，任何归档、越权或漂移均 fail-closed，且平台仍是唯一数据集 owner。

## 契约与实现边界

- 按 F1 README 实现 `GET /api/sql/query-datasets/published`、published detail、`/api/internal/analysis-datasets/{id}/versions/{version}`。
- 在 QueryDataset publish 事务中从结果 Schema、canonical 模型/指标和 policyRefs 构造 `dts.query-dataset-contract/v1` snapshot，并写入 F1 README 钉定的五个 Expand 字段；不得建新 repository/table。
- projection/assembler 只能读取指定 `QueryDatasetVersion` 已保存 snapshot；禁止按当前 canonical model 重算历史 version。
- 存量 PUBLISHED version 采用 expand/backfill/validate/contract：可证明完整的回填 READY；无法证明的标记 UNRESOLVED 并从新 Analysis 创建入口排除，不猜测补齐。
- `baseSql` 仅存在 internal DTO；controller log、public DTO、审计 payload 均不得包含。
- Query Dataset 发布/归档后按 `id:version:checksum` 失效缓存；旧版本不会自动解析成 latest。
- 为 `QueryDatasetAsset` 校验 `CatalogAssetType.BI_DATASET + CatalogAssetKey.biDataset(id)` 与现有 mapping/access/classification/report-link 解析一致；不得调用 `CatalogAssetRegistrationService.observe(BI_DATASET)` 或直写 catalog semantic store。

## RED → GREEN 测试

1. RED：混合 DRAFT/PUBLISHED/ARCHIVED fixture 时当前无 published projection。
2. GREEN：分页只含 PUBLISHED+enabled，筛选/total/排序正确，公开 JSON schema 无 `baseSql/sql`。
3. RED：无 service auth、无 read、错误 checksum、归档版本仍可被现有链模糊获取。
4. GREEN：分别返回 401/403/409；内部契约字段/指标/policy/checksum 完整。
5. RED：上游 canonical model 变化会让当前 `toDto` 对同一历史 version 计算出不同 contractVersion。
6. GREEN：历史 version 始终读取发布 snapshot/checksum；策略收紧可拒绝但不改历史 checksum；UNRESOLVED 存量版本不能创建新 Analysis。
7. GREEN：发布/归档使 cache 失效；并发重复获取结果一致；平台不可用不回退裸数据源。

## 影响范围与先决 impact

预计 owner：`QueryDatasetService`、`QueryDatasetVersion`、SqlWorkbench resource、Query Dataset DTO/mapper、安全配置、mapping/access identity seam 与 Liquibase changelog。实施前对每个实际 symbol 运行 fresh upstream impact；若 `QueryDatasetService` HIGH/CRITICAL，先报告调用方和进程，再以新 snapshot assembler/projection service 委托，避免把现有发布语义散落到资源层。

禁止：修改 QueryDataset publish/archive 状态含义、复制业务 SQL到 Analytics、扩展第二套权限动作。

## 错误与审计

- 400/401/403/404/409/502 采用稳定 errorCode 和 correlationId。
- 内部调用记录 actor=service identity、datasetId/version/checksum/outcome，不记录 SQL。
- 对归档/漂移拒绝计数，以便 F6 告警。

## Definition of Done

- [ ] 三个 API 的 schema/authorization/pagination/cache/错误矩阵测试通过。
- [ ] Expand/backfill/validate/contract 可在 clean DB 与存量 fixture 上执行；READY/UNRESOLVED 判定可对账。
- [ ] 同一 published version 在上游模型变化前后返回相同 snapshot/checksum；当前策略收紧仍 fail-closed。
- [ ] 公开响应与日志无 raw SQL，internal endpoint 只允许受信 service identity。
- [ ] published/archived/stale/denied fixture 全部通过 IT-01/IT-02。
- [ ] 无新数据集表/repository/生命周期 owner。
- [ ] logical BI_DATASET 未进入物理 observation admission；impact 与 detect_changes 只显示预期数据集发布/消费流程。
