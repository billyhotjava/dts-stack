# T01：建立分析/看板版本、校验和发布状态机

**优先级**：P0
**状态**：DRAFT
**依赖**：F2/T01、F3/T01

## 可测试目标

Analysis 和 Dashboard 可独立保存草稿、校验、发布、列出版本和基于历史创建新草稿；发布钉定数据集与 Analysis revision 依赖，并发发布只产生一个 current PUBLISHED，任何 blocker/故障不产生半发布。

## 状态与数据契约

- 实体：DRAFT/PUBLISHED/ARCHIVED；Revision：DRAFT/PUBLISHED/SUPERSEDED；VALIDATING 不作为持久化可消费状态。
- 按 F4 README Expand `analytics_revision` 和 entity pointer；唯一约束保护版本号和 current published。
- `dependency_snapshot_json` 至少包含 datasetId/version/checksum、Analysis id/revision/checksum、parameter mappings、classification 和 query budget version。
- 已发布 revision immutable；回退=读取历史→创建新 DRAFT→重新 validate/publish。
- Dashboard 最多 50 个分析组件/20 个参数，批量加载依赖，避免 N+1。

## 校验与发布契约

`validate` 返回 `{valid, blockers[{code,path,message}], warnings[], dependencySnapshot}`，不改变 lifecycle/revision pointer。
`publish` 必须复用相同 validator 并重新检查防 TOCTOU；成功后原 PUBLISHED → SUPERSEDED、新 revision → PUBLISHED、entity pointer 原子推进。受众登记由 T02 参与最终可消费状态。

blocker 覆盖：未发布/失效依赖、checksum 漂移、字段失效、参数类型、权限、classification、RLS、预算、query dry-run、缺受众。

## RED → GREEN

1. RED：当前 revision 无正式 version/status/dependency snapshot，保存对象可被直接消费。
2. GREEN migration：旧 Card/Dashboard snapshot backfill 可证明项；不可证明项保持 DRAFT/legacy 状态。
3. GREEN state-machine test：非法迁移全部拒绝；validate 无副作用；published immutable。
4. GREEN concurrent IT：20 个并发 publish 仅一个 current PUBLISHED、版本不重复。
5. GREEN fault IT：在 revision/pointer/outbox 各故障点无半发布，可恢复/reconcile。
6. GREEN dependency IT：v1 发布后数据集 v2 不漂移；失效依赖阻断新发布。

## 影响范围与先决 impact

预计 symbol：`RevisionService`、Card/Dashboard services/entities/resources、Liquibase、validation service。逐 symbol fresh impact；RevisionService 的 Card/Dashboard 共用影响须在编码前列出，优先新增 lifecycle service 而非改变旧 snapshot/revert 行为。

## Definition of Done

- [ ] Expand migration、唯一约束、旧数据兼容和 rollback 应用验证通过。
- [ ] validate/publish/version/state-machine/并发/故障注入测试通过。
- [ ] published revision immutable 且依赖快照完整可审计。
- [ ] Dashboard 无 N+1，50/20 上限适应度函数通过。
- [ ] 保存不等于发布，旧 current published 在新发布失败时保持可用。
