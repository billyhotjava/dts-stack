# T01: 画布方案收敛（复用 vs 移植）

**优先级**: P1
**状态**: READY
**依赖**: F1

## 目标
确定治理建模路径的可视化画布来源——复用平台已有 analytics `SemanticModelCanvas` 还是移植 dts-metrics `SemanticDesignerPage`——并产出可复用的组件接口。**这是 F2 的分叉，先定再动手。**

## 技术设计
- 评估两个候选：
  - **A 复用 analytics**（`src/analytics/pages/semantic/SemanticModelCanvas.tsx`，已 `@xyflow/react`，Chrome 95 兼容已处理）→ 泛化其 props 接受治理模型（`/api/semantic` 的 model/object/dimension/metric/binding）+ 受控态。**倾向 A**（不引第三套、复用已验证的 Chrome95 兼容画布）。
  - B 移植 dts-metrics `SemanticDesignerPage` 画布 → 适配 `/api/semantic`（工作量大、引入第二套画布栈）。
- 产出：选型结论 + 抽出的画布组件接口（节点=资产/业务对象、边=join、props=受控态/诊断），供 T02/T03/T04 消费。
- 关注 Chrome 95 兼容（analytics 画布注释已记录 `structuredClone` 兼容处理——复用即继承）。

## 影响范围
- `dts-platform-webapp`：画布组件抽取/泛化（analytics → 共享 or modeling 内）。

## 验证
- [ ] 选型有依据（复用 A 的理由：兼容性 + 不重复）。
- [ ] 画布组件接口可被治理建模页接入（占位渲染通）。

## 完成标准
