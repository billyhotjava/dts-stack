# T04: 画布建模保存贯通 /api/semantic

**优先级**: P1
**状态**: READY
**依赖**: T01, T02, T03

## 目标
画布上的建模动作（选 base 资产、加 join、绑维度/指标、设 grain/governanceMode）保存贯通平台 `/api/semantic`（创建/更新 model + bindings + 提交评审），让图形建模成为治理建模的一等入口。

## 技术设计
- 画布状态 → `semanticModelingApi` 调用：business-object/model 创建更新、`models/{id}/bindings`、`submit-review`。
- 复用 F1 的 governanceMode（画布建模默认 CONTROLLED）+ F1-T03 分层诊断 + F2-T02 受控公式。
- 与现有表单（`ModelEditDrawer` 等）的关系：T01 决定"替代"还是"并存"（建议并存：画布为主、表单为高级/回退）。
- 保存即走受控校验（后端 Sprint-41）：画布建模天然受控，违规走 F1 的引导式提示。

## 影响范围
- `dts-platform-webapp`：画布页 ↔ `semanticModelingApi` 贯通；与 pages/modeling 现有流编排。

## 验证
- [ ] 画布建一个 DWS 模型 + 绑维度/指标 + 受控派生指标 → 保存 + 提交评审成功。
- [ ] 画布建非法（ODS 源 / 原始 SQL）→ 走 F1 引导式拒绝。
- [ ] permissive/表单路径不受破坏。

## 完成标准
- [ ] 画布建模端到端贯通 /api/semantic、受控校验生效、与表单关系明确、构建+测试通过。
