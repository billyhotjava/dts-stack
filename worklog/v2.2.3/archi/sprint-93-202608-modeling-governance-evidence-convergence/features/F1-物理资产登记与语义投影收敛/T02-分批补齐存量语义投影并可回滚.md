# T02：分批补齐存量语义投影并可回滚

**优先级**：P0
**状态**：COMPLETE / IT-03_PASS
**依赖**：F0/T01（真实 preview）、F1/T01（生产 writer 已接入）

## 目标

不清库、不猜测 producer、不覆盖治理结果地补齐现有目录资产的语义投影，并能够按批次安全回滚。

## 技术设计（Contract-first）

- **API 契约**：在既有 `/api/catalog/asset-normalization-migrations` owner 下兼容增加：
  - `GET /semantic-projection/preview?limit=1..500`
  - `POST /semantic-projection/apply` body `{previewHash:string,limit:int,resolutions:[...]}`
  - `POST /semantic-projection/{batchId}/rollback`
- **preview 输出**：`{previewHash,totalPending,truncated,rows:[{resourceId,assetKey,relationType,producerResolution,evidenceResolution,currentGovernance,currentLifecycle,resolutionStatus,reasonCodes}]}`。
- **apply 输出**：`{batchId,previewHash,previewed,applied,skipped,issueCount,appliedAt}`；只处理 `UNIQUE_RESOLUTION`。
- **rollback 输出**：`{batchId,removed,rolledBackAt}`；当前 projectionVersion 不匹配时 409。
- **数据流**：扩展既有 `CatalogAssetNormalizationMigrationService` 和 batch owner；逐行调用 `registrations.observe`；歧义/缺失写既有 normalization issue 或兼容扩展其 code，不新建迁移框架。
- **错误路径**：preview stale、AssetKey 多映射、用户状态漂移、batch 非 APPLIED、projection version 漂移均 fail-closed。
- **迁移纪律**：首批 20，再 100，最后 ≤500；每批先备份/preview，apply 后立刻对账；不触碰已有人工 governance/classification/domain。

## UI 交互规格

本期无客户页面。运维调用返回中文摘要和机器错误码；用户在现有资产目录中看到补齐结果和待处置原因。

## 影响范围

既有 normalization migration resource/service/repository、审计字典、migration IT；可能需要 Expand 列/索引，必须 Liquibase 注册并可回滚。

## 验证（RED→GREEN）

- [x] 相同数据重复 preview hash 稳定；数据漂移后旧 hash 返回 409。
- [x] 501 超限失败；歧义/缺 producer 不 apply。
- [x] apply 重放不重复；rollback 仅删除本批且不覆盖后续用户修改。
- [x] 受控批次运行前后目录、projection、pending 和 issue 可对账。

## Definition of Done

- [x] 真实存量按批次补齐或产生明确 issue。
- [x] apply/rollback/audit 证据落入 IT-03。
- [x] 无清库、无全表猜测回填、无第二 migration owner。
