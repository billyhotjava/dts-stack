# T01：冻结第六步输入输出与完成语义

**优先级**：P0
**状态**：DONE
**依赖**：-

## 目标

冻结第六步消费的稳定模型引用、候选范围、证据类型和 StageProjection 完成策略，避免实施期再次混用 READY、测试通过和已发布。

## 技术设计

- 输入固定为 `planId/candidateId/modelSpecId/revision/checksum/implementationMode/environment`。
- 输出分为 artifact、build run、quality run、review、publication、registration、rollback 七类证据。
- 完成策略按候选范围计算；草稿和未选模型不阻塞，STALE/PARTIAL/ROLLED_BACK 不算完成。
- 定义稳定错误码、状态迁移表、Actor 权限矩阵和审计字段。

## 影响范围

- `ModelLifecycleContract.java`
- `WarehousePlanDownstreamEvidencePort.java`
- `assets/build-quality-release-workbench-design.md`
- 对应 contract/service 单元测试

## 实施步骤

1. 先写状态迁移、完成策略和错误码契约测试，证明旧 RELEASE_READY 语义失败。
2. 冻结 Java contract 与 API schema，不在本任务写持久化。
3. 编写对应测试源码并完成静态审查；运行验证统一留到 F6 整体测试窗口。

## 完成标准

- [x] 契约能区分“可提交”“质量通过”“已批准”“已发布”。
- [x] 完成策略及负向样例获得后端、前端和产品共同评审。
- [x] **UI 契约验收**：交付工作台阶段头、状态标签、首要阻塞和主动作具有逐状态 fixture；同一状态不能在不同页面出现冲突文案或动作。
