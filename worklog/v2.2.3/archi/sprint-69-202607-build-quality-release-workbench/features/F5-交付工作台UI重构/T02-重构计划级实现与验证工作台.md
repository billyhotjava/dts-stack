# T02：重构计划级实现与验证工作台

**优先级**：P0
**状态**：READY
**依赖**：T01、F1-T04

## 目标

将 `/modeling/plans/:planId/implementation` 从跳转卡重构为真实候选驱动的交付工作台壳层。

## 技术设计

- 保留 `WarehousePlanDetailPage` 路由和计划上下文，不新建一级菜单。
- 新增 `PlanDeliveryWorkbench`，由 candidate 聚合查询驱动。
- 支持创建候选、选择/移除模型、锁定范围和版本冲突刷新。
- loading/empty/error/stale/forbidden 均有页内恢复路径，不只 toast。

## 影响范围

- 修改 `WarehousePlanDetailPage.tsx`
- 新增 `delivery/PlanDeliveryWorkbench.tsx`
- 新增 `delivery/DeliveryCandidatePanel.tsx`
- 修改 `api/modelSpecApi.ts`
- 新增 source-contract/view-model tests

## 实施步骤

1. 先写实施页不再只展示跳转卡、候选写入携带 ETag 的失败测试。
2. 接入只读聚合查询，再逐步开放候选写动作。
3. 运行相关 `node --import tsx --test` 测试并执行 `pnpm build`。

## 完成标准

- [ ] 用户在计划上下文内看见本次交付范围、状态、阻塞和下一步。
- [ ] 并发冲突保留本地选择并提示刷新/重放，不静默覆盖。
- [ ] **UI 实现验收**：用户可在页面内完成创建候选、选择/移除模型、锁定范围和 409 恢复；首次进入、无模型和无权限都有业务可读空态。
