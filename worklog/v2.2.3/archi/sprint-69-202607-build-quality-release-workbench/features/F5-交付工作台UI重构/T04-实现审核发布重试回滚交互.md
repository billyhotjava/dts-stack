# T04：实现审核发布重试回滚交互

**优先级**：P0
**状态**：READY
**依赖**：T02、F4-T04

## 目标

提供显式提交、批准/拒绝、发布、PARTIAL 重试和回滚交互，完整表达权限、影响范围和异步结果。

## 技术设计

- allowedActions 决定按钮，后端仍为最终授权者。
- 批准/拒绝显示候选 checksum、构建/质量摘要和职责分离提示。
- PARTIAL 展示各注册步骤及 attempt，只对失败步骤提供重试。
- 回滚要求选择目标发布、填写原因并二次确认影响。

## 影响范围

- 新增 `delivery/DeliveryReviewPanel.tsx`
- 新增 `delivery/DeliveryTimeline.tsx`
- 新增 command hooks 与 component/source-contract tests

## 实施步骤

1. 先写同人无批准动作、PARTIAL 精确重试、回滚原因必填和 409 恢复测试。
2. 实现命令对话框、pending 状态和结果刷新。
3. 在 mock-API Chrome 95 中覆盖所有分支，再进入真实 E2E。

## 完成标准

- [ ] UI 不再自动 submit/approve/publish，且不能伪造允许动作。
- [ ] 异步失败、超时未知和并发冲突均保留可恢复上下文。
- [ ] **UI 实现验收**：批准、拒绝、发布、PARTIAL 重试和回滚均展示权限、影响摘要和确认步骤；重复点击被抑制，超时未知不得显示成功。
