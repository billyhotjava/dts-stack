# T04：构建失败与精确修复闭环

**优先级**：P0
**状态**：READY
**依赖**：T02、T03

## 目标

把构建失败定位到候选条目、文件和错误位置，并在修复后产生新 run，而不是覆盖失败证据或整批重做。

## 技术设计

- 规范化 compile、database、test、timeout 和 infrastructure 错误类别。
- 错误详情保存模型、文件、行列、日志引用、可重试性和推荐修复路由。
- 修复链接携带 plan/candidate/model/revision，不允许丢失上下文。
- 重试只选择失败/失效条目，已成功且未漂移条目可复用。

## 影响范围

- `ModelLifecycleService.java`
- `ModelLifecycleResource.java`
- build diagnostics contract
- `sqlModelBuild.helpers.ts` 及测试

## 实施步骤

1. 先写部分失败、可重试和修复后新 run 的服务测试。
2. 实现诊断归一化、重试选择器和上下文链接。
3. 验证失败历史保留且新 run 不覆盖旧 run。

## 完成标准

- [ ] 用户能从失败证据一步到达正确模型和文件修复位置。
- [ ] 精确重试不会重复执行仍有效的成功条目。
- [ ] **UI 契约验收**：错误详情显示模型、文件、行列、日志引用和可重试性；修复与重试按钮携带 plan/candidate/model/revision 并只选择失败条目。
