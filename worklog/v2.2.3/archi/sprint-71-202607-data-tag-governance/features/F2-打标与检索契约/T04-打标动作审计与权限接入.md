# T04: 打标动作审计与权限接入

**优先级**: P1
**状态**: READY
**依赖**: T02

## 目标

使标签管理与打标动作全部可审计、受权限约束，满足协议对数据管理操作留痕的要求。

## 技术设计

### 审计

沿用 sprint-34 建立的审计目录 DB 化机制。需在 `dts-admin` 审计资源字典中登记标签相关动作，
否则日志会落到「未分类」。参照
`dts-admin/src/main/resources/config/liquibase/changelog/20260105-01_audit_operation_mapping_platform_catalog.xml` 的登记格式。

需登记的动作：
- 标签分类 创建 / 修改 / 删除
- 标签 创建 / 修改 / 删除（含 force 级联删除）
- 资产打标 / 取消打标 / 批量打标

审计内容须包含操作对象标识（标签 code、资产 assetType+assetKey）与操作人，
批量打标记录资产数量而非逐条刷屏。

### 权限

- 标签目录与标签的 **写操作**（增删改）应限定为治理角色，普通用户只读
- 资产打标权限沿用该资产既有的写权限判定，不新造一套权限模型
- 越权请求返回 403，且审计记录该次拒绝

### 已知约束

项目当前操作权限矩阵仍硬编码为 `List.of("read","write","export")`
（`dts-admin/.../PlatformDirectoryResource.java:52/59/66`，属 M05 P0 缺口，见 Sprint-36）。
本 task **不修复该缺口**，仅在现有 read/write 粒度内接入；
待权限矩阵专项完成后，标签动作可平滑纳入更细的动作集。此约束须在实施时确认，避免误以为已具备细粒度控制。

## 影响范围

- 修改 dts-admin 审计资源字典 changelog（新增标签动作分类）
- 修改 `.../web/rest/catalog/CatalogTagResource.java`（权限注解）
- 修改 `CatalogTagService` / `CatalogAssetTagService`（审计埋点）
