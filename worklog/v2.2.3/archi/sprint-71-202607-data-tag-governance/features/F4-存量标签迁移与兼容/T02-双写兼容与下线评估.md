# T02: 双写兼容与下线评估

**优先级**: P2
**状态**: READY
**依赖**: T01

## 目标

明确新旧两套标签在过渡期的共存规则，并给出 `CatalogDataset.tags` 字段的下线条件。**本 task 不执行下线。**

## 技术设计

### 过渡期规则

| 场景 | 规则 |
|------|------|
| 新增打标 | 只写结构化标签表，**不回写** `tags` 自由文本 |
| 读取展示 | 优先展示结构化标签；`tags` 自由文本作为次要信息保留展示 |
| 检索 | 结构化标签检索与 `tags` 模糊检索并存（F2/T03 已实现） |
| 既有消费方 | `CatalogMetadataService:191/238/253` 透传逻辑保持不变 |

**不做双写**：回写自由文本会让两套数据持续分叉，且没有消费方需要新标签以文本形式出现。

### 下线条件（供后续 sprint 决策）

`CatalogDataset.tags` 字段可下线，当且仅当以下全部满足：

- [ ] F4/T01 迁移已在现网执行完毕，未命中清单已由治理人员处置完成
- [ ] 全仓 grep 确认无其他模块依赖该字段（须包含 dts-platform-webapp、dts-analytics-webapp、对外 API）
- [ ] 对外数据服务接口响应中不含该字段，或已完成契约变更通知
- [ ] 结构化标签检索已上线并稳定运行一个发布周期

### 产出

在 `assets/` 下产出一份下线评估报告，列出：
- 该字段当前的全部消费点（grep 证据，含文件行号）
- 每个消费点的迁移方案
- 建议下线时间点与前置条件
