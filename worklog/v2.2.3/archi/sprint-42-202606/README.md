# Sprint-42: 数据管理主题看板

**时间**: 2026-06
**状态**: DONE
**类型**: Product Architecture / Implementation（dts-platform-webapp + dts-admin menu seed）

## 目标

把 Sprint-39 黄金链路和 Sprint-40 消费工作台从“技术中心入口”重构为面向数据管理员的“业务主题看板”，让客户按经营分析、质量管理、项目交付、客户服务等业务主题理解数据交付状态。

## 背景

平台的主要使用者不是专职数据工程师，而是偏业务的数据管理员。客户熟悉业务主题、交付结果和风险状态，不熟悉 ODS/DWD/DWS/ADS、dbt、血缘、API 授权等技术对象。

Sprint-39 已建立黄金链路状态机和治理/消费/运维能力，Sprint-40 又补了业务消费工作台，但入口仍落在“数据服务中心”，容易变成新菜单堆叠。本 sprint 将主对象调整为业务主题，资产、接口、报表和运维只作为主题交付物与下一步动作。

## 完成标准

- [x] 工作台一级菜单下出现“数据管理工作台”，数据服务中心不再新增孤立“业务消费工作台”。
- [x] 首页以业务主题卡片为第一视图，默认出现经营分析、质量管理、项目交付、客户服务。
- [x] 主题卡片展示数据可用、治理状态、消费状态、运行健康和最近更新。
- [x] 主题详情/动作区能跳转到资产、治理、报表、API、数据产品、运维，不要求客户先理解技术中心。
- [x] 页面由 `/api/golden-chains` 真实运行状态驱动；没有链路时呈现主题空态，不使用静态假成功数值。
- [x] 前端 source-contract、主题聚合单测、菜单 seed 契约和构建验证通过。
