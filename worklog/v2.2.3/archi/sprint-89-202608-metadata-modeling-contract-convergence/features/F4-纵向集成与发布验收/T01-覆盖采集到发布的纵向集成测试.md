## 集成夹具

使用隔离 PostgreSQL/Testcontainers 或专用非敏感 schema；不修改当前业务 catalog 样本。固定 table.id 与 dataset.id 不相等，并保存 v1/v2 schema 快照。

## 场景

1. v1 采集创建稳定 dataset/table/columns、asset key、fingerprint 与 drift evidence。
2. CATALOG_TABLE 加入 plan 并确认；反向导入形成 ModelSpec source binding/mapping。
3. 编译、分类发布门禁与物化 generation 读取同一 sourceBinding/version。
4. v2 新增 nullable 字段：compatible，既有模型继续，新字段可在刷新后选择。
5. v3 删除已引用字段：breaking，compile/publish/materialize 都以稳定 code 阻断。
6. 修复 mapping 并重确认：门禁恢复。
7. 表消失/重现：STALE/MISSING → 同 ID 恢复；不产生 orphan binding。
8. 跨租户、无权限和并发重确认：404/403/409 与脱敏符合契约。
