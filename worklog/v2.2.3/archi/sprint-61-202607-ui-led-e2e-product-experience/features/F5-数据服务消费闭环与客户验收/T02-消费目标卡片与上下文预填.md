# T02: 消费目标卡片与上下文预填

**优先级**: P1
**状态**: DONE
**依赖**: T01

## 目标

在低代码向导和工作台中把报表、API、大屏、数据产品作为明确消费目标，并预填来源上下文。

## 技术设计

- 低代码页面消费目标卡片保留 `standardDraftId`、`modelId`、`metricId`。
- API/数据产品页面显示“来源模型/指标”上下文 banner。
- 后端不支持预填时，用 blocker 显示缺少的字段或 API。

## 影响范围

- `LowCodeDevelopmentPage.tsx`
- `ApiServicesPage.tsx`
- `DataProductsPage.tsx`
- 报表工厂相关页面

## 验证

- [x] source-contract 断言消费目标卡片携带上下文。
- [ ] 浏览器 smoke 打开服务页面不丢失来源信息。

## 完成标准

- [x] 消费目标不再是孤立入口，而是数据产品旅程的自然出口。

## 实施证据

- API 与数据产品页面读取 `modelId`、`metricId`、`datasetId`，JourneyContextBar 标记服务阶段。
- 低代码页保持标准草稿和模型上下文；浏览器来源信息验证归入 F9。
