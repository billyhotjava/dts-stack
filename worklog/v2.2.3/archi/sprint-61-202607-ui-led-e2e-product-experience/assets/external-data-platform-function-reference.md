## 图中总述

围绕数据全生命周期建设统一入口，覆盖接入采集、质量管控、开发编排、资源地图、建模实验、数据服务、报表分析、智能体应用与系统治理，支撑从数据生产到服务发布的闭环运营。

## 图中能力标签

- 数据全生命周期
- AI 模型增强
- 资源画像与血缘
- 服务化与可视化输出

## 图中功能卡片

| 功能 | 图中描述 | 对 DTS 的参考价值 |
|------|----------|-------------------|
| 数据接入 | 统一纳管数据源、库表对象、接入任务、文件上传、接入概览与接入模型配置。 | 对应 DTS 的数据源、文件/API 接入、接入任务和 ODS 规划入口，需要在旅程中形成“来源已确认”的证据。 |
| 质量管控 | 覆盖质量数据源、规则管理、策略配置、任务调度、结果分析和模型管理。 | 对应 DTS 的质量规则、质量任务、发布门禁和验收包证据，应该与模型/服务上下文绑定。 |
| 数据开发 | 提供 SQL 工作台、数据编排、实例监控、开发数据源和开发模型管理。 | 对应 DTS 的 SQL 建模、低代码开发、实例运行、任务编排和发布前检查。 |
| 数据地图 | 管理部门、业务系统、独立数据源、组织分类、资源检索、画像与血缘分析。 | 对应 DTS 的资产目录、资源检索、血缘、影响分析和业务域/部门维度。 |
| 数据建模 | 支撑行业调研、逻辑模型、物理模型、模型部署、数据预览和质量报告。 | 对应 DTS 从标准包/数据元到逻辑模型、物理模型、SQL/dbt 草稿、模型预览和质量报告的闭环。 |
| 数据服务 | 沉淀服务运营、服务目录、应用授权、调用审计、服务测试与模型配置。 | 对应 DTS 的 API 服务、服务目录、授权、调用审计、服务测试和验收包服务证据。 |
| 报表平台 | 覆盖报表数据源、数据集市、图表资产、报表开发、主题模板和模型管理。 | 对应 DTS 的数据产品、报表数据集、BI/大屏消费和指标可视化输出。 |
| 智能体与治理 | 整合智能体规划、应用广场、用户角色、模型服务和知识库治理。 | 对应 DTS 后续 AI/Agent 能力入口、知识库、模型服务、权限角色和治理控制面；授权/商业细节本阶段不展开。 |

## 对 Sprint-61 的直接启发

- 这张图强调“统一入口 + 全生命周期 + 闭环运营”，与 Sprint-61 的工作台主线一致。
- 图中能力顺序可用于校验 DTS 菜单和旅程是否覆盖：接入、质量、开发、地图、建模、服务、报表、智能体/治理。
- 对 DTS 更有价值的是功能卡片的覆盖面，不是电商详情页本身。
- 后续如果需要转成 Feature，应围绕“功能总览图驱动的能力矩阵/缺口补齐”，而不是轻量商品详情页或购买转化。
