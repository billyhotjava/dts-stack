# T03：执行分阶段发布回滚演练并闭合运维材料

**优先级**：P0  
**状态**：PENDING  
**依赖**：T01、T02

## 目标

按 schema→backend→frontend→migrate 顺序完成发布和真实回滚演练，验证旧/new 组合兼容，并使 runbook 可由未参与开发者执行。

## 技术设计（Contract-first）

- **输入契约**：`assets/release-plan.md`、`assets/runbook.md`、镜像标签、migration preview、IT 证据。
- **输出契约**：部署记录、old/new 兼容矩阵、rollback/re-apply 结果、告警/日志字段实测、Go/No-Go 决策。
- **数据流**：expand → backend → contract smoke → frontend → browser smoke → migrate batch → observe → rollback drill → restore。
- **错误路径**：任一门禁失败立即停止后续阶段；回滚不 DROP 新列、不删除 revision/audit；数据已被后续修改时前向修复。
- **复用点**：现有 Docker/Compose 服务、health、日志和 scoped webapp/backend rebuild 流程。

## 影响范围

目标环境的 nullable migration、`dts-platform`/`dts-platform-webapp` 镜像、部署/回滚证据和 Sprint-92 runbook；不重建无关服务，不执行 Contract 删除。

## 验证

- [ ] old backend/expanded schema；new backend/old frontend；new backend/new frontend 三组 smoke。
- [ ] frontend rollback、backend rollback、migration batch rollback/re-apply。
- [ ] 告警阈值/查询、correlationId、COMMITTING/receipt 对账可由第二人执行。

## Definition of Done

- [ ] G3 发布安全和 G4 可运维性由 PENDING 变 PASS。
- [ ] 回滚演练有实际日期、命令、输出和恢复结果。
- [ ] no-go 时服务仍可用，旧模型/候选/资产证据不丢失。
