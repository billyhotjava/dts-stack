## 3. 达到 IMPLEMENTATION_READY

| 内容 | 普通配置 | 高级 dbt | 是否当前必填 |
|---|---|---|---|
| 实现方式 ownership | `DESIGNER_GENERATED` | `DBT_MANAGED` | 必填 |
| 输入模式 | PHYSICAL_ASSET/UPSTREAM_MODEL/GENERATED 按类型矩阵 | 同左 | 必填 |
| 输入 revision | 系统锁定 | dbt artifact + 系统锁定 | 必填 |
| 字段映射 | 可视化配置 | SQL/schema 声明并投影 | 目标字段必须覆盖 |
| 目标物理名 | 表单配置 | dbt node/alias 投影 | 必填 |
| materialization | 受支持枚举 | dbt 配置 | 必填 |
| 装载/增量/分区/保留 | 按物化方式 | dbt 配置并投影 | 条件必填 |
| 编译/输入校验 | 系统执行 | dbt 编译/manifest | 必填 |
| 质量、审核、发布 | 下一阶段 | 下一阶段 | 当前不阻断保存实现 |

## 4. 达到 RELEASE_READY

| 内容 | 默认规则 | 用户是否需要逐项手填 |
|---|---|---|
| 当前模型/实现 revision 一致 | 硬门禁 | 否，系统校验 |
| 构建与测试证据 | 硬门禁 | 否，由运行产生 |
| 质量证据 | 按计划发布策略 | 否，由质量运行产生 |
| 字段标准 | 按计划 `standardCoverage` | 只修复策略要求的字段 |
| 密级 | 硬门禁，允许继承/传播满足 | 不要求已有可信证据的字段重复填写 |
| 审核批准 | 复用 Sprint-69 | 按角色执行 |
| 外部登记 | 发布后执行，可部分失败重试 | 否 |

## 5. 页面呈现规则

- 默认门禁卡只显示“当前阶段、下一道门禁、阻断数量、修复动作”；
- “全部门禁”折叠区可预览未来要求，但未来项显示“以后处理”，不计入当前待修复数量；
- 可选建议使用普通提示，不使用黄色 blocker Tag；
- 同一根因只显示一次，例如没有 ModelImplementation 时不再同时显示“没有 sourceRefs”和“没有实现输入”；
- blocker 文案全部中文，隐藏 implementation revision 等内部术语；技术详情放展开区。
- “数据实现”在 DESIGNED 前禁用并解释原因；“发布结果”在无任何实现/发布证据时禁用，有历史发布证据时保持只读可访问。
