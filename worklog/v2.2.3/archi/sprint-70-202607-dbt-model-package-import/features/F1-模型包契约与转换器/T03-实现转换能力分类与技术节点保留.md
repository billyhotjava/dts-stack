# T03：实现转换能力分类与技术节点保留

**优先级**: P0  
**状态**: DONE  
**依赖**: T01、T02

## 目标

为每个 dbt 节点给出可解释的转换结论，并保证 STG/ephemeral 依赖不丢失。

## 技术设计

- 分类为 `DESIGNER_GENERATED`、`DBT_BACKED`、`BLOCKED`、`TECHNICAL_ONLY`。
- 安全子集仅允许字段选择、别名、cast、受控 join 和去重。
- 聚合、窗口、CASE、常量、宏、VALUES、自定义 materialization 默认 DBT_BACKED。
- 缺粒度、类型、来源或消费场景等业务语义时 BLOCKED。
- STG、ephemeral、macro、test 放入 technicalNodes，并保留依赖和 checksum。

## 影响范围

- 模型包转换器与 reason-code 契约。
- 普通实现能力边界测试。

## 验证

- [ ] 同一节点分类结果稳定且包含 reason code。
- [ ] PJM 预算 DWD/DWS/ADS 不被错误标为纯普通实现。
- [ ] STG 不创建 ModelSpec，但下游 dependency 仍可解析。

## 完成标准

- [ ] 分类器不靠命名规则直接写入业务语义。
- [ ] BLOCKED 候选不能进入 apply。
