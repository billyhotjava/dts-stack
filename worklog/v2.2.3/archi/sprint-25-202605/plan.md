# Sprint-25 Implementation Plan

## 设计原则

1. **先 IA 后功能**: 先定中心职责、菜单和页面任务，再补具体功能。
2. **先前端结构后后端扩展**: 客户先看到清晰工作流，后端 API 只补真正暴露出的缺口。
3. **角色边界固定**: 数据工程师走数据开发中心；业务人员走语义与指标中心；治理人员走数据治理中心；平台管理员维护血缘来源。
4. **页面低负载**: 一个页面 1-2 个主功能，超过就拆。
5. **血缘横向复用**: 血缘是统一底座，各中心只使用上下文视图。

## 信息架构目标

### 数据接入中心

主菜单建议:

- 连接器目录
- 数据源管理
- 驱动管理
- 元数据采集
- 数据入湖配置
- 接入变更记录

保留边界:

- 只处理数据进入平台和落 ODS 的链路。
- 仅展示接入链路血缘，不承载模型开发或指标定义。

### 数据开发中心

主菜单建议:

- 项目空间管理
- 逻辑建模 SQL
- dbt 文件浏览
- 脚本开发
- 任务编排
- 运行监控 / 执行历史

保留边界:

- 面向专业数据工程师。
- 负责 ODS/DWD/DWS/ADS 工程加工。
- 提供 SQL/dbt/调度能力。
- 不做业务人员指标配置主入口。

### 数据治理中心

主菜单建议:

- 主题域管理
- 标准管理: 业务术语、数据元、公共码表
- 标准模板
- 质量管控
- 质量报告
- 分级分类
- 资产权属 / 权限审计

保留边界:

- 提供治理规则、治理标准和责任约束。
- 指标只引用治理主题域、术语、数据元，不在治理中心形成独立指标主入口。

### 语义与指标中心

主菜单建议:

- 指标工作台
- 指标字典
- 主题域映射
- 业务对象 Join
- 指标可视化配置
- DWS/ADS 数据集
- 审核发布与血缘
- 模型运行监控

保留边界:

- 面向业务人员、数据产品经理、指标负责人。
- 业务人员不用写 SQL。
- 以 DWD/DWS/ADS 为输入，发布 DWS/ADS、BI Dataset、API 和指标血缘。

### 资产门户 / 血缘与影响分析

主菜单建议:

- 资产地图
- 数据搜索
- 血缘与影响分析
- 数据产品
- 权限申请

血缘工作台拆分:

- 血缘图谱: 资产选择、方向、深度、图谱查看。
- 字段血缘: 字段级来源和表达式。
- 影响分析: 变更影响范围和上下游风险。
- 血缘导入: dbt manifest、Addax、OpenMetadata、OpenLineage 同步。
- 快照对比: 时间旅行和 diff。

## 交付顺序

### Phase 1: 菜单与路由收敛

- 将 `语义与指标中心` 确认为根菜单。
- 移除治理中心中的指标主入口。
- 移除开发中心中的指标语义建模主入口。
- 保留旧路由兼容但不作为菜单主入口。
- 将 `血缘视图` 改名为 `血缘与影响分析`。

### Phase 2: 语义指标页面拆分

- 将 `SemanticModelingCenterPage` 从 `section` 大页改为真实页面组合。
- `指标工作台` 只做流程入口、待办、状态概览。
- `主题域映射` 只做治理主题域引用和自建主题域兜底。
- `业务对象 Join` 只做对象选择和 Join 画布。
- `指标可视化配置` 只做字段池、维度、指标配置。
- `DWS/ADS 数据集` 只做模型组合、生成预览、dbt 产物。
- `审核发布与血缘` 只做审核、发布、写血缘、注册 BI/API。
- `模型运行监控` 只做运行记录、状态、重试和日志入口。

### Phase 3: 血缘工作台拆分

- 从 `LineagePage` 拆出独立页面或子路由。
- 图谱、字段血缘、影响分析、导入同步、快照 diff 分页承载。
- 资产详情保留轻量血缘预览。
- 语义指标发布页只展示指标发布上下文血缘。
- 数据开发任务页只提供模型/任务上下文血缘跳转。

### Phase 4: 开发与治理页面回收

- 数据开发中心检查所有指标相关入口，移到语义与指标中心。
- 数据治理中心检查所有指标字典/指标工作台入口，移到语义与指标中心。
- 治理中心主题域与语义主题域建立“引用优先、非强制绑定”口径。

### Phase 5: 验收

- 菜单 JSON 校验。
- `source/dts-platform-webapp` 构建。
- 核心路由手工或脚本冒烟。
- 截图验收: 四中心菜单、语义指标工作台、血缘与影响分析、指标字典。

## API 原则

本 Sprint 先尽量复用现有 API:

- 语义建模: `/api/semantic-modeling/**`
- 指标中心: 现有 indicators API
- 血缘: catalog lineage impact / diff / import / sync API
- dbt: 现有 publish / run / artifact API

只有当页面拆分后出现清晰缺口时再新增后端接口。
