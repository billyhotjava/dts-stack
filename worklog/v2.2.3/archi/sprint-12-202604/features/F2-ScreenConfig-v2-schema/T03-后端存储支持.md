# T03: 后端 DTO 支持 v2 存储 + 版本字段透传

**优先级**: P0
**状态**: DONE（2026-04-21）
**依赖**: T01

## 执行纪要

- 用方案 A：加一列 `v2_spec_json` 透传 v2 扩展字段（schemaVersion / layout / referenceViewport）
- Liquibase migration `0045_screen_v2_spec.xml` 给 `analytics_screen` + `analytics_screen_version` 加 `v2_spec_json` TEXT 列（可 null，v1 大屏不填）
- `AnalyticsScreen.java` / `AnalyticsScreenVersion.java` 加字段 + getter/setter
- `ScreenResource.java`：
  - POST create / PUT update 读 `body.v2Spec` 存入
  - `toDetailResponse` 从 draft 或 version 快照回吐 `v2Spec`（新增 `parseV2Spec` helper）
  - 发布 version 时快照包含 `v2SpecJson`；回滚时从 version 恢复
- v1 向前兼容：v1 大屏 `v2_spec_json` 为 null，响应里无 `v2Spec` 字段
- **需要 dts-analytics 重启并 run Liquibase 0045 migration（用户在外部编译/部署时做）**

## 目标

后端 `ScreenResource`（dts-analytics）能原样存取 v2 大屏的 JSON，不做字段级校验（前端负责），但 `version` 字段必须透传。

## 技术设计

### 当前后端

`ScreenResource.java` 已经把 `spec` 作为 JSON string 透明存取（没有按字段反序列化）。意味着 v2 理论上**不需要改后端**。

**必做 check**：
1. 读取 `ScreenResourceIT` 测试，确认没有把 spec 里的字段反序列化成 Java 对象
2. 确认 `screen.version` 字段能透传存取
3. 确认大屏列表 API 不按 `version` 过滤
4. 确认公开链接 API 不因 `version === 2` 报错

### 可能要改的地方

- `ScreenDetail` DTO 如果有字段级反序列化 → 增加 `version` 字段（默认 1）
- 若序列化框架遇到新字段报错，给 `@JsonIgnoreProperties(ignoreUnknown = true)`
- 校验器（若存在）若只认 v1 schema → 加 v2 旁路

### 数据迁移

**不做**。demo 期，旧记录 `version` 缺省即视为 v1。
