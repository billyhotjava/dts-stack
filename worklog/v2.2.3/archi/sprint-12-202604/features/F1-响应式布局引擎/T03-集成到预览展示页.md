## 执行纪要

- 新建 `v2/loader.ts` + `tryLoadV2()`：从后端响应合并 `v2Spec` + 顶层 flat 字段 → `ScreenConfigV2`
- `ScreenPreviewPage.tsx` 加 `v2Config` state，load 时优先走 v2，命中则设 v2Config
- `PublicScreenPage.tsx` 同上（公开链接也支持 v2）
- 两个页面在 loading/error 检查之后、v1 scale 逻辑之前加 v2 分流 early return

- v1 大屏回归：`tryLoadV2` 返回 null，走原 `normalizeScreenConfig` 路径，行为不变

## 目标

ScreenPreviewPage 和 PublicScreenPage 按 `screen.version` 分流 — v2 走 `ResponsiveScreenLayout`，v1 保留现有 transform-scale 路径（只读，兼容旧数据）。

## 技术设计

### 分流逻辑

```tsx
// ScreenPreviewPage.tsx（以及 PublicScreenPage）
if (screen.version === 2) {
  return <ResponsiveScreenLayout screen={screen} theme={screenTheme} deviceMode={deviceMode} />
}
// 既有 v1 渲染分支保持不动
return <LegacyScreenRenderer ... />
```

### v1 分支收束

为清理代码，把现有大量 preview 渲染逻辑抽成 `LegacyScreenRenderer`（就是现在的那一坨 transform+stretch+manualScale），让 PreviewPage 本体变薄：

```tsx
function ScreenPreviewPage() {
  ...hooks and state fetch...
  if (screen.version === 2) return <ResponsiveScreenLayoutShell ... />
  return <LegacyScreenRendererShell ... />
}
```

这样 v1 代码不需要删（demo 期旧大屏还能看），v2 走新路径。
