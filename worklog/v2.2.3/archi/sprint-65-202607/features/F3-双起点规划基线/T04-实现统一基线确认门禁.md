# T04：实现统一基线确认门禁

- **状态**：READY
- **优先级**：P0
- **依赖**：T02、T03
- **影响模块**：PlanningBaseline domain/API/UI、stage projection

## 目标

将业务范围、来源盘点、来源业务映射和规划策略汇合为唯一可解释的 baseline READY 门禁。

## 实施内容

1. 建立来源到主题域/过程的多对多映射和明确排除原因。
2. 实现分层、命名、历史、时区/日期等规划策略确认。
3. 后台按最低完成条件计算缺失项，原子执行 confirm。
4. UI 只显示一个首要缺失项和一个继续动作，其余问题折叠展示。
5. 基线确认后生成版本快照；结构修改触发失效/复核而非静默保持 READY。

## 验收标准

- BUSINESS_FIRST 和 ASSET_FIRST 使用同一个 confirm 命令；
- 未映射来源、未确认候选或缺失策略会阻止 READY；
- 重复 confirm 幂等；
- 基线失效有原因、影响和修复入口；
- 前端不能本地伪造 READY。

## 验证证据

- 门禁组合参数化测试；
- 原子性和幂等测试；
- 基线失效/恢复测试；
- 双起点同结果 E2E。
