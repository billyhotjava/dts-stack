# T04：建立失败定位、修复与恢复回路

- **状态**：READY
- **优先级**：P0
- **依赖**：T01、T03
- **影响模块**：工作台、模型/标准/运行详情、diagnostics API

## 目标

把编译、标准漂移、质量、发布和运行失败定位到责任对象，提供修复入口，并在修复后刷新同一计划的证据。

## 实施内容

1. 统一失败摘要：阶段、对象、错误码、发生时间、证据和建议动作。
2. 将失败映射到模型、字段、标准绑定、dbt test、pipeline run 或服务实例。
3. 专业页面携带诊断上下文定位具体 Tab/对象。
4. 修复后触发重新校验或运行，保留历史失败和新结果。
5. 网络中断、刷新和重新登录后可以从 planId 恢复修复流程。

## 验收标准

- 失败不只展示日志文本；
- 每个可修复失败有明确责任对象和入口；
- 成功修复不会删除历史证据；
- 重新运行不会重复创建业务模型；
- 恢复后仍回到同一计划和主阻塞。

## 验证证据

- 四类失败 fixture；
- failure-to-fix Playwright；
- 历史证据和重新运行测试；
- 刷新/重新登录恢复测试。
