# T01：扩展规划聚合数据库结构

- **状态**：IN_PROGRESS
- **优先级**：P0
- **依赖**：F1-T02
- **影响模块**：dts-platform Liquibase、PostgreSQL、ModelSpec FK

## 目标

通过向前兼容的 Liquibase 变更把 `modeling_warehouse_plan` 扩展为方案级主表，并建立域、过程、来源、映射、策略、指标需求、版本、评审、证据和旧计划映射结构。

## 实施内容

1. 新增方案基本信息、起点、生命周期、`plan-head` 乐观锁、审计和 legacy 引用字段。
2. 新建多值绑定表并添加租户、唯一键、外键、查询索引，以及与 API 编辑单元一致的 `business-scope/sources/source-mappings/policy` 版本字段。
3. 保留原 `domain_id/process_id/layer` 字段作为迁移期只读兼容，不立即删除。
4. 编写旧字段到绑定表的可幂等 backfill，并为冲突建立报告表或输出。
5. 验证空库、存量库、重复执行和回滚脚本边界。

## 验收标准

- 主表不再以单个过程/分层为唯一粒度；
- 一个计划可以关联多个域、过程和来源；
- 原 ModelSpec FK 继续有效；
- 所有表有 tenant 边界、审计字段和必要索引；
- 五个锁资源的 version/ETag 均有明确持久化来源，不存在整计划单锁；
- migration checksum、幂等和升级路径测试通过。

## 验证证据

- Liquibase updateSQL；
- 空库和存量库升级日志；
- schema/constraint 查询；
- backfill 前后核对报告。
