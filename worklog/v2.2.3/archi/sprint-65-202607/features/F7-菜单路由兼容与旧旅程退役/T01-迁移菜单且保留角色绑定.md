# T01：迁移菜单且保留角色绑定

- **状态**：READY
- **优先级**：P0
- **依赖**：F1-T03
- **影响模块**：portal menu seed、角色菜单绑定、前端菜单解析

## 目标

上线“数据建设工作台、数仓规划、模型中心、高级 dbt、运行记录”的新信息架构，同时保留既有菜单 ID、角色绑定和最小权限。

## 实施内容

1. 盘点现有菜单 ID、父子关系、路由、排序、角色/租户可见性和 seed hash。
2. 优先更新既有菜单 target 或重挂父级，不删除再重建已有 ID。
3. 新增必要菜单时显式定义权限，不继承过宽的父级权限。
4. 为普通建模、治理兼任、高级 dbt、只读审核角色建立可见性矩阵。
5. 运行 seed 幂等和现有绑定保留测试。

## 验收标准

- 升级后旧角色的授权集合不意外减少或扩大；
- 菜单 seed 重跑不重复；
- 高级 dbt 只对有工程权限的用户显示；
- 数据建设工作台是实际页面 target；
- breadcrumb 和直接 URL 与菜单一致。

## 验证证据

- 迁移前后 menu/binding diff；
- seed tests；
- 四类角色截图；
- 权限拒绝用例。

## 命名归一（2026-07-18 评审增补）

菜单迁移时同步收敛"工作台"称谓：全局仅保留"个人工作台（总览首页）"与"数据建设工作台（建模域主场）"；"建模工作台""端到端数据产品工作台"等旧称谓在菜单与页面标题中废弃，旧菜单 ID 按本任务映射规则保留兼容。
