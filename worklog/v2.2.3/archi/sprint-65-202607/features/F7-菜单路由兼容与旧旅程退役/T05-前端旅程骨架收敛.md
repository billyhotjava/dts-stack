# T05：前端旅程骨架收敛

**优先级**：P0
**状态**：IN_PROGRESS
**依赖**：T02；T03；F5-T02

## 目标

把前端并存的四套上下文/多套阶段导航收敛为 `planId` 单一新上下文和九站 `StageProjection` 单一状态源，按退役登记表 R03、R11-R13 达成目标状态，杜绝"新架构落地即第五套骨架"的复发。

## 技术设计

- **R03**：`warehousePlanningContext` 只允许一次性读取并映射到 canonical planId；禁止新增读写消费者，映射完成后不再决定页面状态。
- **R11**：在 `JOURNEY_CONTEXT_PARAM_KEYS` 显式加入 `planId`；`planningId/warehouseLayer/modelingMode/processId` 标记 deprecated（保留只读透传），新链路仅由 `planId` 承载；e2e 旅程条（JourneyContextBar）在建模域页面降级为单行"返回数据产品旅程"链接，不再渲染八阶段状态。
- **R12**：`businessModelingContext` 提供 → planId 的兼容映射函数，源码标注 deprecated，禁止新增消费者。
- **R13**：`modelingJourneyContext`/SemanticWorkspaceFrame 四阶段导航的处置按 spec 取代声明执行——Frame 保留期间仅作为模型中心内部导航，上下文一律来自 planId；不自持 stage 事实。
- **守卫契约**：新增 source-contract——①建模域页面不得同时渲染 JourneyContextBar 八阶段与 Frame 阶段导航；②四套旧 context 模块消费者清单固定（快照断言），新增即红；③ `/workbench` 不得直接调用 URL 参数完成度计算，八阶段状态必须来自 StageProjection 映射。
