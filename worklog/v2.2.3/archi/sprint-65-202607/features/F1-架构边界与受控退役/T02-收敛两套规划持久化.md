# T02：收敛两套规划持久化

- **状态**：READY
- **优先级**：P0
- **依赖**：T01
- **影响模块**：Liquibase、modeling plan 服务、ModelSpec 外键、旧规划 API

## 目标

确认 `modeling_warehouse_plan` 为 canonical 运行态聚合，设计 `modeling_plan*` 到新聚合的迁移和兼容方案，禁止再创建第三套主计划表。

## 实施内容

1. 盘点两套计划表的字段、数据量、外键、API、页面和写入者。
2. 形成字段映射、合并规则、冲突规则和无法自动迁移字段清单。
3. 将主表粒度从“过程 + 分层”调整为“一个数仓建设方案”，多值关系下沉绑定表。
4. 设计 `legacy_source/legacy_ref` 与稳定迁移映射，保证旧深链可解析到 canonical planId。
5. 规定旧表保留、只读冻结、调用审计和后续物理删除条件。

## 验收标准

- 每个旧字段有迁移、派生、废弃或人工确认结论；
- ModelSpec 的 `plan_id` 不需要改指向另一主表；
- 同一业务计划不会继续在两表独立写入；
- 冲突处理不使用无提示“最后写入胜出”；
- 迁移与回滚不删除 canonical 数据。

## 验证证据

- schema/consumer inventory；
- 字段映射和样本迁移报告；
- 外键与调用者 GitNexus 分析；
- 架构决策记录。
