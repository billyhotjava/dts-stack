# T01: 四级密级与只升不降契约

**优先级**: P0
**状态**: IN_PROGRESS
**编码状态**: DONE（统一验证延后）
**依赖**: 无

## 目标

在 `dts-common` 固化四级密级的规范化、比较、最高值和未知值处理，禁止各模块自行维护 rank。

## 技术设计

- 保持 `PUBLIC < INTERNAL < SECRET < CONFIDENTIAL`。
- 新增或收敛 `max/current-or-higher/isDowngrade` 契约。
- 未知、null、blank 不再默认为 PUBLIC；业务入口必须显式决定隔离或默认下限。
- 在修改 `SecurityLevelCatalog` 前执行 GitNexus impact；当前已知风险为 CRITICAL。

## 影响范围

`dts-common`、`dts-admin`、`dts-platform`、`dts-metrics`、`dts-analytics` 的密级比较和兼容别名。

## 验证

- [ ] 四级两两比较、max、别名和未知值契约测试。
- [ ] 全仓不再新增独立密级阶梯实现。

## 完成标准

- [ ] 所有新密级流程只调用共享契约。
- [ ] 不改变人员密级与数据密级的既有映射语义。
