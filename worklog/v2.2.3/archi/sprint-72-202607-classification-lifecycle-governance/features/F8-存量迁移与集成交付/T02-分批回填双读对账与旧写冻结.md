# T02: 分批回填、双读对账与旧写冻结

**优先级**: P0
**状态**: IN_PROGRESS
**依赖**: T01,F2-F7

## 目标

按资产类型和部门分批建立初始事实，在对账稳定后冻结旧写入口。

## 技术设计

- migration run 保存游标、批次、checksum、统计和状态。
- 计算值使用 `max(old,declared,detected,upstreams)`。
- 支持暂停、恢复、失败重试和重复 apply 幂等。
- 分批启用新读，达标后将旧写入口改为兼容 raise/拒绝。

## 影响范围

迁移服务、旧 classification upsert/patch/sync、feature flag 和对账 API。

## 验证

- [ ] 中断恢复、重复批次、并发升密和版本冲突。
- [ ] old/new 读取差异报告。

## 完成标准

- [ ] 不发生任何有效密级降低。
- [ ] 每个冻结入口有影响分析和回滚说明。

## 编码进展

已实现运行游标、批次 apply、幂等 item checksum、暂停/恢复、失败重试、双读差异报告和逐表冻结；
数据库触发器在对账通过后阻断旧 classification 清空或降低。运行验证待统一测试阶段执行。
