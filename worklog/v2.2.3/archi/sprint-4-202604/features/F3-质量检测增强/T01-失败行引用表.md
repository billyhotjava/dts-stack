# T01: 失败行引用表 + 检测结果记录

**优先级**: P0
**状态**: READY
**依赖**: 无

## 目标
创建 gov_quality_failing_row 表，检测执行时记录失败行的主键引用和原因（不存完整行数据）。

## 技术设计

### 表结构
```sql
CREATE TABLE gov_quality_failing_row (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    run_id       UUID NOT NULL REFERENCES gov_quality_run(id) ON DELETE CASCADE,
    rule_id      UUID REFERENCES gov_rule(id),
    table_name   VARCHAR(200) NOT NULL,
    row_id       VARCHAR(64) NOT NULL,    -- ODS 行主键值
    column_name  VARCHAR(200),            -- 问题列（可选）
    actual_value TEXT,                     -- 实际值（截断 500 字符）
    fail_reason  VARCHAR(500) NOT NULL,
    created_date TIMESTAMP DEFAULT now()
);
CREATE INDEX idx_gqfr_run_id ON gov_quality_failing_row(run_id);
CREATE INDEX idx_gqfr_table_row ON gov_quality_failing_row(table_name, row_id);
```

### 写入逻辑
在 `QualityRunService.doExecuteRun()` 中，检测 SQL 返回的失败行结果：
- 提取每行的主键值（id 列）
- 提取失败列名和实际值
- 批量 INSERT 到 gov_quality_failing_row
- 单次检测最多记录 10000 行（超出截断 + 记录总数）

### SQL 模板要求
模板 SQL 必须返回包含 `id` 列的结果集（即失败行的主键）。模板渲染时自动加入 `SELECT id, {{column}} AS actual_value FROM ...`。

## 验证

- [ ] 失败行 > 10000 时截断并记录总数
- [ ] run 删除时级联清理失败行记录
