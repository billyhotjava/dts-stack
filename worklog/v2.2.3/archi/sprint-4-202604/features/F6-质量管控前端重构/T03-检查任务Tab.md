# T03: 检查任务 Tab（调度计划 + 执行历史 + 详情）

**优先级**: P1
**状态**: READY
**依赖**: F3

## 目标
独立的检查任务 Tab，上半区调度管理，下半区执行记录，点击可查看详情（含失败行预览和执行 SQL）。

## 技术设计

### 页面布局
```
上区：调度计划列表
  - 名称、关联规则、数据集、周期、状态、操作（暂停/立即执行/编辑）

下区：执行记录列表
  - 筛选：触发方式(调度/手动/入湖预检) + 状态 + 规则 + 数据集 + 日期
  - 列：运行ID、状态、触发方式、规则、数据集、开始时间、耗时、操作

执行详情（展开或侧边抽屉）：
  - 规则 + 数据集 + 触发方式 + 状态 + 时间
  - 检查结果：总行数/通过/失败 + 通过率进度条
  - 失败行预览表格（前100行）+ "去修复"按钮
  - 执行的 SQL 展示
```

### 触发方式
执行记录中 triggerType 区分：`SCHEDULE` / `MANUAL` / `INGESTION_PRE_CHECK`

### "去修复"跳转
跳转到"数据修复"Tab，URL 参数：`?tab=repair&runId={id}`
