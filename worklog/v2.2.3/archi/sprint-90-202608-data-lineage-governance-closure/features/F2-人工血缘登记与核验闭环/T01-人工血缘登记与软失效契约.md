# T01: 人工血缘登记与软失效契约

**优先级**: P0
**状态**: READY
**依赖**: 无

## 目标

把已存在但无人调用的 `POST/DELETE /api/catalog/lineage`（账本#6）补成可安全对外的契约：默认 `MANUAL` 关系、拒绝自环与重复边、删除默认软失效、全程审计。

## 技术设计 (Contract-first)

### 输入契约

`POST /api/catalog/lineage`，沿用既有 `LineageCreateRequest`（`CatalogLineageResource.java:93`）：

| 字段 | 类型 | 约束（本 Task 新增） |
|---|---|---|
| `upstreamDatasetId` | UUID | 必填；须存在且当前用户可读 |
| `downstreamDatasetId` | UUID | 必填；须存在且当前用户可读；**≠ upstream** |
| `relationType` | string | 缺省 `MANUAL`；仅允许 `MANUAL`（其余类型由采集器写入，不开放人工指定） |
| `direction` | string | 缺省 `UPSTREAM_TO_DOWNSTREAM` |
| `notes` | string(≤512) | 可选 |
| `projectName` | string(≤128) | 可选 |
| `upstreamAssetType` / `downstreamAssetType` | string | 缺省 `DATASET` |

`DELETE /api/catalog/lineage/{id}?force=false`：

| 参数 | 默认 | 语义 |
|---|---|---|
| `force` | `false` | `false` → 置 `valid_to = now()`（软失效）；`true` → 物理删除（既有行为，保留，需 `CATALOG_MAINTAINERS`） |

### 输出契约

- `POST` → `ApiResponse<Map>`，body 为 edge DTO，与 `toEdgeDto` 同形（保证前端可直接并入现有边表）。落库时 `verification_status = 'DECLARED'`、`valid_from = now()`、`valid_to = null`。
- `DELETE` → `ApiResponse<Map>`：`{ "id": "...", "softDeleted": true, "validTo": "2026-08-11T..." }`（既有返回 `Boolean`，本次扩展为对象；前端无既有消费方，无兼容风险）。

### 错误路径

| 场景 | 状态码 / 错误码 | 说明 |
|---|---|---|
| 上游或下游数据集不存在 | 404 | 与 `impact` 一致 |
| 任一端不可读 / 部门不允许 | `RESOURCE_NOT_VISIBLE` | 复用 `accessChecker.canRead + departmentAllowed`，不泄露存在性 |
| `upstream == downstream` | 400 `LINEAGE_SELF_LOOP` | 自环无意义 |
| 已存在同 `(upstream, downstream, relationType)` 且 `valid_to is null` | 409 `LINEAGE_DUPLICATE` | 复用 `findFirstByUpstreamDatasetIdAndDownstreamDatasetIdAndRelationTypeIgnoreCaseAndValidToIsNull`（`CatalogDatasetLineageRepository.java:26-33`） |
| 删除不存在的 id | 404 | - |
| 软失效已失效的边 | 200 幂等 | 返回既有 `validTo`，不重复写 |

### 数据流

```
Drawer 提交
  → POST /api/catalog/lineage
  → accessChecker 双端校验 → 自环/重复校验
  → CatalogDatasetLineage(valid_from=now, valid_to=null, verification_status=DECLARED, relation_type=MANUAL)
  → audit CATALOG_LINEAGE_CREATE
  → 前端 runSearch 重查 impact（新边自动进入 BFS 结果，无需额外查询路径）
```

### 复用点

- 表、BFS、时间旅行、鉴权全部复用既有实现（ADR-90-02），**不新增表、不新增查询路径**。
- 重复边检测复用既有 Repository 方法，不新写查询。

### 环检测（明确不做）

不做血缘环检测。理由：真实数仓存在合法回流（如回写维表），且现有 BFS 用 `visited` 集合天然防死循环。若未来需要，另立 task。
