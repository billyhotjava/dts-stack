# T02: 血缘核验状态流转契约

**优先级**: P0
**状态**: READY
**依赖**: T01（共用迁移文件 `20260811_01_catalog_lineage_verification_actor.xml`）

## 目标

让 `verification_status` 从"只写不改"（账本#10：6 个写入点、0 个更新入口）变成治理员可显式流转的状态，且人工结论不被后续采集覆盖（ADR-90-04）。

## 技术设计 (Contract-first)

### 输入契约

**新增** `PATCH /api/catalog/lineage/{id}/verification`

```jsonc
{
  "verificationStatus": "VERIFIED",   // 必填，枚举 DECLARED | KNOWN_UNVERIFIED | VERIFIED
  "note": "已比对 Addax 作业日志确认"    // 可选，≤512
}
```

权限：`CATALOG_MAINTAINERS`（与 `OpenLineageReceiverResource` 同一表达式，见账本#12 该文件的 `CATALOG_MAINTAINER_EXPRESSION`），另需通过两端数据集的 `accessChecker`。

### 输出契约

更新后的 edge DTO（`toEdgeDto` 同形），新增三个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `lastVerifiedBy` | string | 操作人 login |
| `lastVerifiedAt` | string(ISO Instant) | 复用既有 `last_verified_at`（若列不存在则本迁移新增） |
| `verificationNote` | string | 核验说明 |

### 数据契约

迁移 `20260811_01_catalog_lineage_verification_actor.xml`（与 T01 共用文件）：

```xml
<addColumn tableName="catalog_dataset_lineage">
  <column name="last_verified_by"   type="varchar(64)"/>
  <column name="verification_note"  type="varchar(512)"/>
</addColumn>
```

> `last_verified_at` 是否已存在需在实施时按账本#23 的 `20260429_01_catalog_lineage_verification_status.xml` 核对；不存在则一并 `addColumn`（`timestamp`）。**Expand-only，无默认值、无回填、无 down migration。**

### 状态流转规则

任意状态可流转到任意状态（治理场景允许纠错撤回），但每次流转必须：

1. 写 `last_verified_by = 当前用户`、`last_verified_at = now()`、`verification_note = note`；
2. 落审计事件 `CATALOG_LINEAGE_VERIFY`，payload 含 `{from, to, note}`；
3. **不改** `valid_from` / `valid_to`（核验不是版本变更）。

### 采集不覆盖人工结论（ADR-90-04 落地）

在四个采集写入点（账本#10）更新**既有**边时插入统一守卫：

```java
// 伪代码：置于每个写入点更新既有 link 的 setVerificationStatus 之前
if (!"VERIFIED".equalsIgnoreCase(link.getVerificationStatus())
        || link.getLastVerifiedBy() == null) {
    link.setVerificationStatus(computedStatus);
}
// 观测字段照常更新
link.setLastObservedAt(observedAt);
```

涉及位置：
- `IngestionLineageWriter.java:541/545/548`
- `CatalogAutoLineageService.java:105`（当前只在**新建**时 set，需确认更新路径）
- `CatalogDbtLineageService.java:135`（当前只在新建时 set）
- `OpenLineageReceiverResource.java:104`

> 为避免四处重复，抽一个 `LineageVerificationGuard.applyComputedStatus(link, computedStatus)` 静态工具，四处共用（复用点，禁止四份平行实现）。

### 错误路径

| 场景 | 状态码 / 错误码 |
|---|---|
| id 不存在 | 404 |
| 边已软失效（`valid_to` 非空） | 409 `LINEAGE_EDGE_EXPIRED`（不允许核验历史边） |
| `verificationStatus` 非法枚举 | 400 |
| `note` 超 512 | 400 |
| 无 `CATALOG_MAINTAINERS` 或任一端不可读 | `RESOURCE_NOT_VISIBLE` |
