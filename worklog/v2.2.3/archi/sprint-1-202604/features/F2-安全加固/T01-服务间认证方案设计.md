# T01: 服务间认证方案设计（mTLS / JWT）

**优先级**: P0
**状态**: READY
**依赖**: 无

## 目标
设计安全的服务间认证机制，替代当前仅靠 `X-DTS-Service` 请求头的认证方式。

## 技术设计

### 现状
- 服务间通过 `X-DTS-Service` 请求头标识调用方，无签名验证
- `/api/platform/**` 和 `/api/admin/platform/**` 允许无认证的服务间调用
- Docker 网络内任何容器可冒充合法服务

### 设计要点
1. **方案选型对比**:
   - mTLS（双向 TLS）: Traefik 原生支持，强身份验证
   - JWT Service Token: Keycloak 签发 service account token
   - HMAC 签名: 共享密钥 + 请求签名，轻量级
2. **证书/密钥生命周期**: 签发、分发、轮换、吊销
3. **Traefik 集成**: 如何在反向代理层面实现服务间 TLS 校验
4. **Spring Security 集成**: 如何在应用层面验证服务身份
5. **第三方服务适配**: Airflow、OpenMetadata、Keycloak 是否支持 mTLS/JWT
6. **性能影响**: mTLS 握手开销评估

### 需要回答的问题
- 是否有内部 CA 基础设施？
- Keycloak 的 service account 机制是否能满足需求？
- 离线环境下证书轮换如何自动化？

## 影响范围
- Traefik 动态配置: TLS 相关路由规则
- 所有服务的 `application.yml`: 安全配置
- `IngestionServiceClient`, `AdminAuthClient`, `AirflowClient` 等客户端
- Docker Compose: 证书 volume 挂载
