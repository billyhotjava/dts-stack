# T02: 密钥管理方案设计

**优先级**: P0
**状态**: READY
**依赖**: 无

## 目标
设计集中式密钥管理方案，消除 `.env` 文件中明文存储密码/密钥的风险。

## 技术设计

### 现状
- 所有敏感信息明文存储在 `.env`:
  - PostgreSQL 密码（8 组）
  - Keycloak admin 密码
  - OAuth2 Client Secret
  - Airflow Fernet Key
  - Audit 加密密钥
  - OpenMetadata JWT Secret
- 无密钥轮换机制
- 自签名 TLS 证书无自动续期

### 设计要点
1. **方案选型**:
   - Docker Secrets（Swarm 模式）: 简单但需要 Swarm
   - HashiCorp Vault: 功能全面，但引入新组件
   - SOPS + age: 加密 `.env`，无额外组件
   - Ansible Vault: 适合离线环境
2. **密钥分类**: 数据库密码、OAuth Secret、加密密钥、TLS 证书
3. **轮换策略**: 各类密钥的轮换周期和自动化方案
4. **离线环境约束**: 方案需支持无网络环境部署
5. **TLS 证书管理**: 自签名证书的自动续期方案（cfssl / step-ca）
6. **审计**: 密钥访问日志

### 需要回答的问题
- 是否有企业级密钥管理基础设施？
- 客户环境是否支持额外部署 Vault？
- 密钥轮换的业务影响容忍度？

## 影响范围
- `.env` 文件: 密文替代明文
- `docker-compose.yml`: 密钥注入方式变更
- `init.sh`: 初始化流程适配密钥管理
- 所有服务的启动配置: 密钥获取方式变更
