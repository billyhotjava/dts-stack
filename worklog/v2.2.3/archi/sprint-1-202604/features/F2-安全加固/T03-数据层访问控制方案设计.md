# T03: 数据层访问控制方案设计

**优先级**: P1
**状态**: READY
**依赖**: 无

## 目标
设计数据库/查询引擎层面的行列级访问控制，弥补当前仅在应用层实现策略的安全缺口。

## 技术设计

### 现状
- 行列级策略在 `IamDatasetPolicy` 中定义（OBJECT / FIELD / ROW 三种 scope）
- 策略仅在应用层（Spring JPA 查询拼装）生效
- 绕过应用直接查数据库则无任何保护
- Ranger 集成未实现（`/services/dts-ranger/` 仅 `.gitkeep`）

### 设计要点
1. **PostgreSQL RLS（Row-Level Security）**:
   - 基于 `current_setting()` 传递用户/部门上下文
   - 策略与 `IamDatasetPolicy` 的映射关系
   - 性能影响评估
2. **Trino 层访问控制**:
   - Trino 内置 access control（file-based / OPA）
   - 列级掩码（Column Masking）
   - 行级过滤（Row Filtering）
3. **Ranger 集成评估**:
   - Apache Ranger + Trino plugin
   - 部署复杂度和离线环境适配
   - 与 Keycloak 的用户/角色同步
4. **策略同步**: 应用层 `IamDatasetPolicy` -> 数据层策略的同步机制
5. **信创兼容性**: ARM/鲲鹏环境下各方案的支持情况

### 需要回答的问题
- 用户是否通过 Trino 直接查询数据？
- PostgreSQL RLS 对 Airflow/dbt 执行的影响？
- Ranger 的 ARM64 支持情况？

## 影响范围
- PostgreSQL: RLS 策略定义
- Trino 配置: access control 规则
- dts-platform `PolicyService`: 策略下推逻辑
- `IamDatasetPolicy` 实体: 可能需要扩展字段
