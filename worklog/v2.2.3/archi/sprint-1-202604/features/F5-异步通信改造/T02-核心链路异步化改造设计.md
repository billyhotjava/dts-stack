# T02: 核心链路异步化改造设计

**优先级**: P1
**状态**: READY
**依赖**: T01

## 目标
设计核心业务链路从同步 REST 到异步事件驱动的改造方案。

## 技术设计

### 现状
- 数据接入链路: Platform -> Ingestion -> Airflow -> Addax -> OpenMetadata (全同步)
- 执行状态: Airflow 状态靠 15 秒轮询获取
- 失败恢复: 简单重试计数器，无死信队列

### 需要异步化的链路
1. **任务执行通知**: Airflow 执行完成 -> callback 推送状态（替代轮询）
2. **元数据变更事件**: 数据源/表结构变更 -> 通知元数据采集
3. **质量检查触发**: dbt 运行完成 -> 触发质量规则检查
4. **血缘更新**: dbt 模型变更 -> 触发血缘图刷新
5. **告警通知**: 任务失败/质量不达标 -> 通知相关人员

### 设计要点
1. **事件定义**: 每条链路的事件类型、payload 格式
2. **Saga 模式**: 长链路操作（接入 -> 建模 -> 质量检查）的编排
3. **幂等性设计**: 消费者的幂等处理
4. **补偿机制**: 链路中某环节失败时的回滚策略
5. **向后兼容**: 同步/异步并存的过渡方案
6. **监控**: 消息积压、消费延迟的可观测性

## 影响范围
- `dts-ingestion`: AirflowAdapter 改为事件驱动
- `dts-platform`: 接收任务完成/元数据变更事件
- Airflow DAG: 增加 callback 机制
- 新增: 事件消费者服务或集成到现有服务
