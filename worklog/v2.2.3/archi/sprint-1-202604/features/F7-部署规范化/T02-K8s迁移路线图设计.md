# T02: K8s 迁移路线图设计

**优先级**: P2
**状态**: READY
**依赖**: F1（高可用方案）, F4（调度引擎升级）

## 目标
设计从 Docker Compose 到 Kubernetes 的分阶段迁移路线图。

## 技术设计

### 现状
- 全部服务通过 Docker Compose 单机编排
- 无滚动更新、无自愈、无水平扩展
- 客户环境为离线/信创（ARM/鲲鹏 + 麒麟 OS）

### 设计要点
1. **K8s 发行版选择**:
   - 标准 K8s（kubeadm）
   - K3s: 轻量，适合边缘/单机
   - OpenShift: 企业级，信创兼容
2. **分阶段迁移**:
   - 阶段 1: 无状态服务（platform, admin, ingestion, webapp）
   - 阶段 2: 调度服务（Airflow + KubernetesExecutor）
   - 阶段 3: 有状态服务（PostgreSQL, Elasticsearch）
3. **Helm Chart 设计**: 各服务的 Chart 结构
4. **配置管理**: ConfigMap / Secret 替代 .env
5. **存储方案**: PV/PVC 规划（PostgreSQL 数据、日志、上传文件）
6. **网络方案**: Ingress 替代 Traefik（或 Traefik as Ingress Controller）
7. **信创 K8s**: ARM64 镜像、麒麟 OS 内核兼容性
8. **CI/CD 集成**: Helm + ArgoCD / FluxCD
9. **回退方案**: K8s 部署失败时回退到 Docker Compose

### 需要回答的问题
- 客户环境是否有 K8s 集群？
- 是否需要支持 Docker Compose 和 K8s 双模式部署？
- CI/CD 工具链是什么？

## 影响范围
- 新增: `deploy/k8s/` 或 `charts/` 目录
- 所有 Dockerfile: 可能需要适配
- 配置管理: .env -> ConfigMap/Secret
- 网络: Traefik 路由 -> Ingress 规则
