# T02: 数据质量统一执行引擎设计

**优先级**: P2
**状态**: READY
**依赖**: 无

## 目标
设计统一的数据质量规则执行引擎，整合当前分散在 dbt tests / OpenMetadata profiler / 应用层的质量检查。

## 技术设计

### 现状
- `GovRule` 在 dts-platform 中定义（DRAFT -> PUBLISHED -> ARCHIVED）
- 实际执行分散在三处:
  - dbt tests: SQL 级别的数据质量检查
  - OpenMetadata profiler: 统计级别的数据剖析
  - 应用层 `ComplianceService`: 合规检查
- 三者之间无统一编排，规则定义与执行脱节

### 设计要点
1. **统一规则模型**: 将三类检查统一到 `GovRule` 框架下
2. **执行引擎选型**:
   - 扩展 dbt tests: 将 GovRule 编译为 dbt test YAML
   - Great Expectations: 独立的质量引擎
   - Soda Core: 轻量级质量检查
   - 自研: 基于 SQL 的规则执行器
3. **规则编排**: 规则绑定 -> 触发条件 -> 执行 -> 结果回写
4. **与 Airflow 集成**: 质量检查作为 DAG 中的 task
5. **结果统一**: 检查结果统一写入 `GovComplianceCheck`
6. **告警联动**: 质量不达标自动创建 `GovIssueTicket`

## 影响范围
- `dts-platform` 治理模块: 规则执行逻辑
- Airflow DAG: 新增质量检查 task
- dbt: 可能新增 macro 用于规则生成
- `GovRule` / `GovComplianceBatch` 实体: 可能需要扩展
