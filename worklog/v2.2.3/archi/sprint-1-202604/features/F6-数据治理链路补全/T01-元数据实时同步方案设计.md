# T01: 元数据实时同步方案设计

**优先级**: P2
**状态**: READY
**依赖**: F5-T01（消息中间件选型）

## 目标
设计元数据变更的实时同步机制，替代当前 cron 每小时同步的方式。

## 技术设计

### 现状
- OpenMetadata 通过 cron 定时同步（每小时）
- dbt artifacts 由 `DbtArtifactSyncScheduler` 每 60 秒轮询
- 数据源结构变更到元数据中心的延迟可达 1 小时
- 手动注册的元数据与自动采集的不一致

### 设计要点
1. **事件触发同步**: 数据源/表结构变更事件 -> 触发元数据采集
2. **dbt 模型变更**: dbt run 完成 -> 立即同步 artifacts
3. **OpenMetadata Webhook**: 利用 OM 的 webhook 机制反向通知平台
4. **增量同步**: 仅同步变更部分，避免全量刷新
5. **冲突处理**: 手动注册与自动采集的元数据冲突解决策略
6. **一致性保障**: 最终一致性模型和补偿机制

## 影响范围
- `DbtArtifactSyncScheduler`: 改为事件触发
- OpenMetadata 配置: webhook / event listener
- `dts-ingestion`: 任务完成后发送元数据变更事件
- `dts-platform`: 元数据消费者
