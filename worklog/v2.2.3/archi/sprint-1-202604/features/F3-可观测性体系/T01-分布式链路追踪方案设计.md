# T01: 分布式链路追踪方案设计

**优先级**: P1
**状态**: READY
**依赖**: 无

## 目标
设计跨服务调用链追踪方案，使请求从前端到后端全链路可追踪。

## 技术设计

### 现状
- 10+ 微服务之间的调用链无法追踪
- 一个请求从前端 -> Traefik -> Platform -> Ingestion -> Airflow -> Addax，出问题只能逐个服务查日志
- 无 TraceID / SpanID 传播

### 设计要点
1. **方案选型**:
   - OpenTelemetry（Spring Boot 3 原生支持）+ Jaeger: 标准化，社区活跃
   - OpenTelemetry + Tempo（Grafana）: 与 Grafana 生态集成
   - Zipkin: 轻量，但功能较弱
2. **Spring Boot 3 集成**: Micrometer Tracing + OpenTelemetry Bridge
3. **Traefik 追踪集成**: Traefik 原生支持 OpenTelemetry
4. **第三方组件追踪**: Airflow / OpenMetadata 的追踪支持情况
5. **采样策略**: 全量 vs 采样（离线环境存储有限）
6. **存储**: 追踪数据的存储和保留策略
7. **信创兼容**: Jaeger/Tempo 的 ARM64 镜像可用性

## 影响范围
- 所有 Spring Boot 服务: 引入 micrometer-tracing 依赖
- `docker-compose.yml`: 新增追踪后端服务
- Traefik 配置: 开启 OpenTelemetry tracing
- 前端: 可选的前端追踪（Browser SDK）
