# T02: 集中式日志收集方案设计

**优先级**: P1
**状态**: READY
**依赖**: 无

## 目标
设计集中式日志收集和查询方案，替代当前日志分散在各服务 bind mount 的现状。

## 技术设计

### 现状
- 各服务日志分散在不同目录:
  - `/logs/traefik/` (Traefik access/error)
  - `/logs/airflow/` (DAG 执行日志)
  - `/logs/postgresql/` (数据库日志)
  - `/logs/openmetadata/` (元数据服务日志)
  - `/logs/dbt/` (dbt 运行日志)
  - `/logs/addax/` (数据接入日志)
- 无集中查询入口，排查问题需 SSH 到各目录逐个查看
- 无日志关联（无法将同一请求的不同服务日志串联）

### 设计要点
1. **方案选型**:
   - Loki + Promtail（Grafana 生态）: 轻量，适合中小规模
   - EFK（Elasticsearch + Fluentd + Kibana）: 功能强大，但已有 ES 实例
   - 复用现有 Elasticsearch 8.11.4 + Kibana: 零新增组件
2. **日志格式统一**: 所有服务输出结构化 JSON 日志
3. **日志采集**: 文件采集 vs Docker 日志驱动
4. **与链路追踪关联**: TraceID 注入日志，实现 log-to-trace 跳转
5. **存储和保留**: 日志保留策略（天数、容量上限）
6. **告警集成**: 关键错误日志触发告警
7. **离线环境**: 所有组件的离线镜像和安装包

## 影响范围
- 所有服务的 logback/log4j 配置: JSON 格式 + TraceID
- `docker-compose.yml`: 新增日志采集服务
- 可能复用现有 Elasticsearch
