# T03：恢复演练与验证证据

**优先级**：P0
**状态**：DONE
**依赖**：T01（存在可恢复的备份产物）

## 目标

用真实备份产物完成一次恢复演练：恢复到隔离库、校验数据一致性、清理现场，形成可复用的恢复 runbook。

## 技术设计（Contract-first）

- **输入契约**：T01 产物 `<ts>/<db>.dump`；演练目标库 `<db>_restore_check`（隔离、不与业务同名）。
- **输出契约**：校验报告（每库：关键表行数比对 PASS/FAIL、恢复耗时）；runbook 恢复章节；演练后隔离库已删除。
- **数据流**：选取最新备份 → 创建隔离库 → `pg_restore` → 行数/表数比对（与源库 `pg_stat` 或 count 抽样）→ 报告 → 删除隔离库。
- **错误路径**：恢复失败 → 报告 FAIL 并保留现场变量供排查（隔离库仍须在演练收尾删除）；源库比对查询只读，避免长事务。
- **复用点**：T01 产物布局；init.sh 的 psql 调用形态（账本#11）。
- **实现方案**：
  1. 演练脚本或手工步骤二选一——优先固化为 `bin/dts-backup --restore-check <ts>`（可重复执行的演练即文档）。
  2. 至少覆盖 dts_platform、dts_keycloak 两个代表性库；其余库抽一。
  3. runbook 写明真实灾难恢复步骤（新建库 → restore → 切换连接 → 验证）与注意事项（扩展、角色、owner）。
- **禁止**：恢复到业务库同名实例上；演练后遗留隔离库。

## 影响范围

- `bin/dts-backup`（restore-check 能力）
- `assets/runbook.md`（恢复章节）
- 证据：`it/evidence/it-05-restore-drill/`

## 验证（RED→GREEN）

- [ ] 演练执行：隔离库恢复成功，行数比对 PASS，报告完整。
- [ ] 收尾检查：隔离库已删除；源库无影响。
- [ ] runbook 步骤与演练输出一致。

## Definition of Done

- [ ] 架构：恢复演练报告 PASS
- [ ] UI：无
- [ ] 切片：证据入 `it/evidence/it-05-restore-drill/`
- [ ] runbook 恢复章节可复现，无占位证据
