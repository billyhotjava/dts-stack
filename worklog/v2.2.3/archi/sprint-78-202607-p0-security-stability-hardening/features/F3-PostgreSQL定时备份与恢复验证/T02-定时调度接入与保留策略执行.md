# T02：定时调度接入与保留策略执行

**优先级**：P0
**状态**：DONE
**依赖**：T01（备份脚本可用）

## 目标

备份每日自动执行，超期备份按保留策略自动清理，调度与清理的每一次动作可追溯。

## 技术设计（Contract-first）

- **输入契约**：`bin/dts-backup --retention-days N`（默认 14）；crontab 行（runbook 提供，现场复制安装）。
- **输出契约**：每日一个 `<ts>/` 目录；清理动作删除 `mtime > N 天` 的目录并在日志记录删除清单；清理失败不影响当日备份结果（分开退出码语义）。
- **数据流**：cron → flock 保护的备份执行 → 日志 `logs/backup/dts-backup-<date>.log` → 保留清理 → 日志。
- **错误路径**：cron 环境缺 PATH/docker → 脚本自检并明确报错；连续失败由日志与退出码供外部巡检发现（observability-sre：异步作业必须有状态可查），本 Sprint 不接告警系统（非目标，P1 统一做）。
- **复用点**：T01 脚本参数；`logs/` 既有目录约定。
- **实现方案**：
  1. T01 脚本补齐 `--retention-days` 清理逻辑（只删符合 `backups/postgres/<ts>/` 命名形态的目录，防止误删手工放置的文件）。
  2. runbook 提供 crontab 行（建议避开整点，如 `17 3 * * *`）与安装/卸载步骤。
  3. 提供 `--dry-run` 清理预览。
- **禁止**：删除不匹配命名形态的任何目录；把清理失败与备份失败混为一个退出码。

## 影响范围

- `bin/dts-backup`（扩展清理逻辑）
- `assets/runbook.md`（crontab 安装/卸载/巡检）
