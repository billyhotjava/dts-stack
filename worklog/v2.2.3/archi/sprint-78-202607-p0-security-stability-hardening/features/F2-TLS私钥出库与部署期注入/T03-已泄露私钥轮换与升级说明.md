# T03：已泄露私钥轮换与升级说明

**优先级**：P0
**状态**：READY
**依赖**：T01/T02（新链路就绪后才可轮换）

## 目标

Git 历史中出现过的旧私钥视为已泄露：重新生成部署期证书材料，并在升级说明中明确轮换动作与回滚方式。

## 技术设计（Contract-first）

- **输入契约**：现有部署的 `services/certs/`；gen-certs.sh 的重新生成能力（T02）。
- **输出契约**：新 ca/server 证书与 p12；轮换记录（时间、操作者、涉及服务）；release-plan 中的客户现场轮换步骤。
- **数据流**：备份现有 `services/certs` → 重跑 gen-certs.sh → 重建/重启使用证书的服务（Traefik 等）→ 验证 HTTPS 与 PKI 登录。
- **错误路径**：新证书导致客户端不信任或 PKI 登录失败 → 回滚到备份的 certs 目录并重启（回滚步骤先演练，ADR-78-08）。
- **复用点**：`bin/dts-upgrade-rollback` 的回滚思路；`services/certs` 目录即全部状态，备份/恢复成本低。
- **实现方案**：
  1. 本仓库环境执行一次轮换演练并记录输出（证据入 it/）。
  2. release-plan 写明：为何轮换（Git 历史泄露声明）、何时轮换（升级窗口）、如何轮换（命令序列）、如何回滚。
  3. 明确"不重写 Git 历史"的取舍（非目标），以轮换消除实际风险。
- **禁止**：在未备份原 certs 的情况下执行重新生成。

## 影响范围

- `services/certs/`（部署期产物，非 Git 跟踪部分）
- `assets/release-plan.md`（轮换与回滚步骤）
- 验证证据：`it/evidence/it-03-tls-keystore/`

## 验证（RED→GREEN）

- [ ] 轮换演练：备份 → 重新生成 → 服务重启 → HTTPS 访问与 PKI 登录链路验证。
- [ ] 回滚演练：恢复备份 → 服务恢复 → 验证通过。
- [ ] release-plan 步骤与演练输出一致。

## Definition of Done

- [ ] 架构：轮换与回滚各演练一次并有输出
- [ ] UI：无
- [ ] 切片：演练证据入 `it/evidence/it-03-tls-keystore/`
- [ ] 升级说明含泄露声明，无占位证据
