# T03: 开发项目入口产品化

**状态**: DONE  
**优先级**: P0  
**涉及路由**: `/studio/projects`

## 目标

把“开发项目”从假菜单整改为数据开发入口。若当前后端没有项目实体，也要给出基于现有建模/任务能力的真实聚合页面，不能落空。

## 按钮清单

| 按钮 | 类型 | 目标行为 |
|------|------|----------|
| 新建项目 | 主按钮 | 创建项目或进入项目创建向导；接口缺失时明确禁用原因 |
| 导入项目 | 次按钮 | 导入已有 SQL/dbt/任务配置 |
| 进入 SQL 建模 | 次按钮 | 跳转 `/studio/sql-modeling` 并带上项目上下文 |
| 查看任务 | 次按钮 | 跳转任务编排或实例列表 |
| 归档项目 | 危险按钮 | 二次确认后归档，不直接物理删除 |

## 组件清单

- `ProjectListPage`: 项目入口页。
- `ProjectCard` / `ProjectTable`: 展示名称、负责人、环境、最近运行、发布状态。
- `ProjectCreateModal`: 新建项目表单。
- `ProjectImportDrawer`: 导入文件/配置入口。
- `ProjectStatusTag`: 草稿、开发中、待治理、已发布、异常。
- `ProjectEmptyState`: 首次进入给出“新建项目”和“进入 SQL 建模”。

## 实现要点

- 若已有项目 API，接入真实 CRUD。
- 若没有项目 API，先用现有 SQL 建模、dbt 文件、ETL 编排对象聚合为“开发空间”，并在 task 记录后端缺口。
- 保证项目入口能继续进入 SQL 建模、ETL 编排、dbt 文件管理。

## 验收

- [x] `/studio/projects` 有真实页面。
- [x] 主按钮不做静态假创建；接口缺失时展示禁用原因。
- [x] 任一项目/开发空间能跳转到 SQL 建模或任务编排。
- [x] 空态提供可执行下一步。
