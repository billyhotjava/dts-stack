# T03: 数据产品双入口语义收口

**状态**: DONE  
**优先级**: P0  
**涉及路由**: `/catalog/data-products`, `/services/products`

## 目标

统一资产门户的数据产品和服务中心的数据产品表达，避免一个对象被拆成两个客户看不懂的页面。

## 按钮清单

| 按钮 | 类型 | 目标行为 |
|------|------|----------|
| 新建数据产品 | 主按钮 | 从资产或数据集创建数据产品 |
| 发布 | 主按钮 | 通过门禁后发布 |
| 申请使用 | 主按钮 | 消费方申请权限/订阅 |
| 查看消费方式 | 次按钮 | 查看 API、报表、文件、共享方式 |
| 下线 | 危险按钮 | 二次确认并展示影响消费者 |

## 组件清单

- `DataProductCatalog`: 统一数据产品列表。
- `DataProductDetailDrawer`: 来源资产、治理状态、消费方式。
- `ProductPublishGate`: 质量、权限、血缘、责任人门禁。
- `ConsumptionMethodList`: API、BI、下载、共享令牌。
- `ConsumerImpactModal`: 下线影响消费者。

## 收口策略

- 若保留两个路由，`/services/products` 应是服务视角，复用同一产品数据和详情组件。
- 若合并入口，服务中心菜单应跳转统一数据产品页并带 `source=services`。
- 菜单名不再使用“数据推送”指代数据产品。

## 验收

- [x] 两个入口看到同一类产品状态和生命周期。
- [x] 页面标题、面包屑和按钮语言一致。
- [x] 发布门禁结果可见。
- [x] 下线前展示消费者影响。
