# T02: 资产门户动作闭环

**状态**: DONE  
**优先级**: P0  
**涉及路由**: `/catalog/assets`, `/catalog/search`, `/catalog/assets?view=table`, lineage routes

## 目标

让资产门户从“能查到资产”升级为“能围绕资产完成权限、血缘、治理、消费”的入口。

## 按钮清单

| 按钮 | 类型 | 目标行为 |
|------|------|----------|
| 申请权限 | 主按钮 | 打开权限申请流程 |
| 查看血缘 | 次按钮 | 进入血缘图 |
| 创建报表 | 次按钮 | 跳转 BI 数据/问题分析 |
| 生成数据产品 | 次按钮 | 创建或关联数据产品 |
| 发布数据 API | 次按钮 | 跳转 API 创建并带资产上下文 |
| 下线资产 | 危险按钮 | 二次确认并展示消费影响 |

## 组件清单

- `AssetSearchPage`: 搜索与筛选。
- `AssetTable`: 表格视图。
- `AssetDetailDrawer`: 资产详情、字段、质量、权限、血缘。
- `LineagePreview`: 小型血缘预览和完整血缘入口。
- `AssetActionPanel`: 权限、报表、产品、API 动作。
- `AssetGovernanceBadges`: owner、分级、质量、血缘状态。

## 数据约束

- 资产详情必须来自 catalog API。
- 消费动作必须携带 asset ID，不让用户重复选择。
- 下线前必须查询消费影响。

## 验收

- [x] 任一资产详情有权限、血缘、消费动作。
- [x] 权限不足时展示申请权限而不是空数据。
- [x] 血缘入口能打开真实血缘页面或明确缺失原因。
- [x] 资产生成消费物后能回链到工作台或服务中心。
