# T03: 鉴权注册表与运行时能力对齐

**优先级**: P0
**状态**: DONE
**依赖**: T01

## 目标

消除「契约宣告 7 种鉴权、运行时只实现 3 种」的断层：注册表为每个 provider 标注 enabled/preview，UI 只能配置已实现项，未实现项可见但禁用。

## 技术设计

- `ApiAuthProviderDescriptor` 增加 `enabled`/`stage`（GA/PREVIEW）字段。
- **新增 `jwtLogin` provider**（客户对接确认的主路径）：字段 = `loginUrl`(登录端点)、`loginBodyTemplate`(登录报文模板，凭据用 secretRef 占位)、`tokenPath`(响应中 token 的 JSON 路径)、`expiresInPath`(可选，过期秒数字段；缺省从 JWT exp claim 解析)、`tokenPlacement`(默认 `Authorization: Bearer`，可自定义 header 名)。敏感字段(密码/secret)标 `sensitive=true` 存 secretRef。
- 本 sprint 状态：`none/bearerToken/apiKey/basic/jwtLogin` = GA；`oauth2ClientCredentials` = GA（与 jwtLogin 同形态，F2-T03 实现后翻转）；`customSignature`/`mtls` = PREVIEW(disabled)。
- 任务保存校验：`sourceConfig.auth.provider` 为 disabled 项时拒绝保存（后端校验，不只靠前端）。
- 运行时执行器遇到未实现 provider 仍抛 `API_RUNTIME_AUTH_UNSUPPORTED`（双保险）。
