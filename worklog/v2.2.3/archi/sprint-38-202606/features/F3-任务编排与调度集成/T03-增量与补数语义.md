# T03: 增量与补数语义

**优先级**: P0
**状态**: IN_PROGRESS
**依赖**: F2-T04, F2-T05

## 目标

冻结 API 增量口径：游标推进时机、backfill 窗口透传、重跑幂等三件事有明确语义并可验证。

## 技术设计

- 游标推进：**仅资源成功提交后**推进该资源 checkpoint（F2-T05 事务内），失败资源保持旧游标下轮重抓——at-least-once + 落地幂等键 = 实际 exactly-once 行为。
- 常规增量：执行前读取 `dts_api_ingestion_checkpoint`，有 checkpoint 时用 `checkpoint - lookbackSeconds` 作为请求起点；无 checkpoint 时用 `initialValue - lookbackSeconds`。
- backfill：触发 conf 透传 `backfill_window_start/end`（沿用现有字段），补数执行请求窗口显式覆盖 checkpoint/initialValue，且**不读取/不推进** checkpoint（对齐 JDBC `IncrementalSyncService` 补数语义）。
- `lookbackSeconds` 与 backfill 的叠加规则：backfill 显式窗口优先，lookback 仅常规增量生效。
- 文档化到 assets/api-incremental-semantics.md（含时序图），作为 IT 用例依据。
