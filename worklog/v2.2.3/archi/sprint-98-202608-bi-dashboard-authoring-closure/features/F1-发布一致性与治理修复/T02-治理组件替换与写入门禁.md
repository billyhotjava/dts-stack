# T02：治理组件替换与写入门禁

**优先级**：P0  **状态**：DONE  **依赖**：T01

## 技术设计

- Dashboard detail 的嵌套 Card 增加 `type/lifecycle_status/published_revision_id`。
- 旧的非治理绑定显示“需替换”；选择已发布分析后复用原 dashcard ID 和布局，仅替换 `card_id` 并清空旧映射/覆盖。
- `/dashboard/save` 在删除或写入前预检新建/改绑目标；非 `analysis + PUBLISHED + revision` 返回 422 `DASHBOARD_ANALYSIS_REQUIRED`。
- 未改绑的历史旧组件允许保存，便于作者分步修复，但仍被发布门禁拒绝。

## 验证（RED→GREEN）

- [x] Java 测试：拒绝新旧式绕过、接受已发布分析、保留未改历史绑定。
- [x] UI 测试：名称/状态/替换操作可见，替换后布局不变。
