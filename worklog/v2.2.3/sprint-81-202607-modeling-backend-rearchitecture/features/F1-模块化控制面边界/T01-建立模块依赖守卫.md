# T01：建立模块依赖守卫

**优先级**：P0
**状态**：PLANNED
**依赖**：F0/T01 调用图

## 目标

用可执行测试固定模块依赖方向，阻止重构过程中继续产生跨域 repository/entity 和环形依赖。

## 技术设计（Contract-first）

- **输入契约**：architecture-overview §2 模块矩阵；F0 caller manifest。
- **输出契约**：ArchUnit rules：`integration→catalog`、`quality→catalog`、`modeling→catalog/quality ports`、`materialization→execution port`；无反向依赖。
- **禁止项**：跨模块 entity/repository import；resource 直接 repository；modeling import Airflow/dbt client；audit 与 domain event 共用 entity/table。
- **错误路径**：现有例外必须逐项有 owner、删除 Task 和截止点；不允许 `..legacy..` 全包白名单。
- **复用点**：既有测试框架与 Maven test profile。

## 影响范围

`dts-platform` 架构测试与内部 package 依赖；不改业务行为。

## 验证

- [ ] 对每条禁止依赖编写 RED fixture，确认测试先失败。
- [ ] 当前允许端口 GREEN，依赖图无环。
- [ ] CI/模块单测默认执行守卫。

## Definition of Done

- [ ] forbidden import 新增即构建失败。
- [ ] 例外清单为空或全部关联 F2～F5 删除 Task。
- [ ] GitNexus detect_changes 显示仅预期模块流程受影响。
