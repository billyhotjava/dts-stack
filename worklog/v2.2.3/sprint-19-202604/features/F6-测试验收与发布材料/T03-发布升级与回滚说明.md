## 发布说明

### 配置变更

- 修复 `DTS_PLATFORM_OPENMETADATA_TABLE_FQN_PATTERN` 默认值，推荐值为 `{service}.{database}.{table}`。
- 存量 `.env` 若存在 `{service`，重新执行 `init.sh` 或手工改为 `{service}.{database}.{table}`。
- 明确配置：
  - `DTS_PLATFORM_OPENMETADATA_AUTH_TOKEN=<redacted>`
  - `DTS_OPENMETADATA_AUTH_TOKEN=<redacted>`
  - `DTS_OPENMETADATA_ALLOW_NO_AUTH=false`
  - `DTS_OPENMETADATA_INGEST_DATABASE=biadmin`（或现场实际数仓/分析库）
  - `DTS_OPENMETADATA_FORBIDDEN_DATABASES=dts_platform,dts-platform,dts_admin,dts-admin,dts_common,dts-common,dts_analytics,dts-analytics,...`
- 只有 OpenMetadata server 确认无认证时，才可设置 `DTS_OPENMETADATA_ALLOW_NO_AUTH=true`。
- 禁止把 `dts_platform`、`dts_admin`、`dts_common`、`dts_analytics` 等平台业务/内部库配置为 OpenMetadata PostgreSQL ingestion 目标库。

### 升级步骤

1. 更新代码和 compose 配置。
2. 修正 `.env` 中 OpenMetadata FQN pattern、token、no-auth 开关和 `DTS_OPENMETADATA_INGEST_DATABASE`。
3. 执行 `docker compose -f docker-compose-app.yml config --quiet`。
4. 重启 `dts-platform`、`dts-ingestion`、`dts-openmetadata-ingestion` 相关服务或重新运行 one-shot ingestion。
5. 按 `F4/T04-现场冒烟Runbook.md` 验证 OpenMetadata API、PostgreSQL ingestion、dbt ingestion 和平台来源展示。

### 回滚策略

- 不删除 OpenMetadata 数据。
- 回滚应用代码时保留 `.env` 中修复后的 FQN pattern，避免再次生成 `{service`。
- 若 OpenMetadata 暂不可用，设置平台读取回退到本地 catalog；前端会显示 `metadataSource=catalog` 和 fallback reason。
- 若 ingestion 作业失败，先停用/不运行 `dts-openmetadata-ingestion` one-shot，不影响平台本地 catalog 查询。

### 已知限制

- dbt manifest 的 FQN 必须与 OpenMetadata 已采集表一致；当前现场 artifacts 中部分 `hive.biadmin.public.*` 表未先采集，会产生 table-not-found 告警。
- OpenMetadata PostgreSQL ingestion 目标库必须是数仓/分析库；误配为平台业务/内部库会以退出码 2 失败，这是预期保护。
- owner/domain/tags 当前不写入 OpenMetadata，只在 ingestion 响应中以 `not_supported` 显式回传。
- PostgreSQL query usage 依赖 `pg_stat_statements`；缺失时会告警，但元数据采集可继续。
