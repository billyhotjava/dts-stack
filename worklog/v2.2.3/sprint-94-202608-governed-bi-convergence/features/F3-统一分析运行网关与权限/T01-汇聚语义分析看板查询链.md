## 可测试目标

语义预览、Analysis 和 Dashboard 的每次执行都进入同一个 `AnalysisQueryGateway`，返回统一结果/错误/审计；现有 `QueryExecutionFacade` 继续负责低层只读合规，资源层不存在 direct `runNative` 绕行。

## 输入/输出/调用契约

| 输入 | 内容 |
|---|---|
| Preview | actor + AnalysisQuerySpec + requestContext |
| Saved asset | actor + type/id/revision + parameters + requestContext |
| Dataset runtime | service-auth contract pinned by id/version/checksum |
| 输出 | `AnalysisQueryResult {queryId,columns,rows,rowCount,truncated,cacheHit,durationMs,contractChecksum}` |

执行 pipeline 按 F3 README 固定。semantic compiler 只产参数化执行计划；`QueryExecutionFacade` 做 read-only/compliance；gateway owner timeout/concurrency/cache/audit。Dashboard 先解析 pinned revision，再逐 query 执行；不得从 mutable entity current spec 猜依赖。

## 实现边界

- 新建小型 gateway/ports/adapters，不把规则堆入 `SemanticQueryService`。
- 将 `SemanticQueryService` 的 4 处 `runNative` 使用点改为委托 gateway/low-level adapter；资源类只做 HTTP mapping。
- 保持 Card/Public/Embed 兼容读，但也必须进入相同安全 pipeline；公开策略由 T02 决定。
- cache key 至少含 actor policy context hash、dataset version/checksum、query hash；敏感数据默认不跨用户。
- 结果最多 10k 行，超出 truncated；慢查询 30s 取消并释放 permit。
