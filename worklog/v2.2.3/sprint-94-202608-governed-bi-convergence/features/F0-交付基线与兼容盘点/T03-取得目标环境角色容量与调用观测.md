# T03：取得目标环境角色、容量与调用观测

- **优先级**：P0
- **状态**：BLOCKED
- **依赖**：目标环境只读权限、A1～A4 账号或等价角色绑定、Traefik/Nginx/access-log/应用指标之一及其保留窗口
- **阻断**：当前没有已确认的目标环境观测来源、历史保留期和四角色账号，现有 `QueryMetricsService` 只能统计查询链，不能反推 32 条前端路由的历史调用。

## 可测试目标

在不读取敏感业务值的前提下，取得目标环境资产规模、角色/部门/密级矩阵、P95/并发和旧路由/旧写 surface 的可观测覆盖。每一项必须记录 source、查询窗口和结果；没有历史数据时保留 UNKNOWN，并建立从当前时刻开始的观测入口，作为退役 S1 的等待门禁。

## 输入、输出与安全契约

| 项目 | 契约 |
|---|---|
| 输入 | A1～A4、目标环境只读资产/API、代理 access log 或应用指标、保留策略 |
| 输出 | 匿名化角色矩阵、资产量与分布、P50/P95/并发、逐 surface 的 `source/window/value/status`、观测起始时间 |
| 状态 | `MEASURED`、`NO_CALLS_IN_OBSERVED_WINDOW`、`UNKNOWN_NO_SOURCE`、`UNKNOWN_RETENTION_TOO_SHORT`；后两者不得写成 0 |
| 敏感边界 | 不记录成员名单、原始 URL 参数、SQL、凭据或业务行值；账号仅保留脱敏标识 |
| 失败 | 无权限或无来源时保持 BLOCKED，登记 owner 与取得方式；不得新增埋点后伪称拥有过去 30 天数据 |

## 实施步骤

1. 验证 A1 维护、A2 独立发布、A3 授权消费、A4 非授权负向的部门/角色/密级与 `read/write/export` 绑定。
2. 对 QueryDataset、Card/Analysis、Dashboard、Screen、ReportLink 执行只读数量、状态、版本、依赖和空值分布探针。
3. 为 32 条路由及后端旧写 surface 建立 observation coverage 表：来源、保留起止、查询表达式、是否能区分 actor/route/method。
4. 若有足够历史窗口，回填实际调用；若没有，写明 UNKNOWN 原因并记录观测起始时间。
5. 回填 `domain-profile.md` 与 `nfr-budget.md`；超出预算时重新过 G1，不用本地空库值覆盖目标事实。
6. 只有连续至少 14 天观测可读后，才允许 roadmap S1 申请进入；S4 的连续 30 天零调用重新独立计时。

## RED → GREEN

- RED：A1～A4、目标资产规模、P95/并发和路由调用全部未知，且没有可证明的数据来源。
- GREEN：每个指标都能追溯到 source/window/query；无历史项保持 UNKNOWN 并有观测起点；角色正负向可执行；NFR 已按目标事实重新裁定。

## Definition of Done

- [ ] A1～A4 的职责分离、部门、角色、密级和 read/write/export 正负向可执行。
- [ ] 目标环境资产量、依赖、P95、并发和导出分布已匿名化归档。
- [ ] 32 条路由与后端旧写 surface 均有观测来源和窗口，或有明确 UNKNOWN 原因与 owner。
- [ ] 没有把 UNKNOWN、无来源或保留期不足写成 0。
- [ ] `domain-profile.md`、`nfr-budget.md`、Gate Registry 和 roadmap 进入条件同步更新。
