# T02：完成灰度发布、回滚与运维收口

**优先级**：P0
**状态**：DRAFT
**依赖**：T01、全部 NFR 适应度函数

## 可测试目标

以 feature flag 和版本化镜像完成 shadow→指定部门 pilot→默认 governed BI 的灰度；在故障演练中可恢复旧读/写策略和旧镜像，Expand 数据与已发布资产不丢失，并交付可执行 runbook、告警、日志和容量边界。

## 发布/回滚契约

| 阶段 | 开关与准入 | 退出条件 |
|---|---|---|
| Shadow | governed gateway/registration 旁路计算与对账，不改变用户结果；**legacy write 保持 on** | 结果/schema/policy mismatch=0，性能预算可接受 |
| Pilot | 指定部门 governed on；**legacy write 仍保持 on** | 三角色旅程、48h 指标、无 P0/P1、回滚演练通过 |
| Default | governed on；旧读旧写**全部保持 on** | 7 天稳定、backlog/错误符合阈值 |
| 退役 S1～S4 | **非本 Sprint** | 见 `../../assets/metabase-retirement-roadmap.md` 各阶段门禁 |

本 Sprint 只切 `DTS_ANALYTICS_GOVERNED_BI_ENABLED` 一个开关；`DTS_ANALYTICS_LEGACY_CARD_WRITE_ENABLED` 只登记与观测，**不关闭**（关闭属 S1/S2）。

部署只影响确需的 dts-platform、dts-analytics、dts-platform-webapp；保留旧 image ID/标签和 compose 参数。数据库首轮 Expand-only；应用回滚不删除列。

## 运维契约

- 产物须实际落盘：`../../assets/release-plan.md`（G3）、`../../assets/runbook.md`（G4）。Gate Registry 的 PENDING 由这两个文件关闭。
- Runbook 覆盖：Platform contract 502/503、query 429/504、registration backlog、revision drift、public link denial、RLS/cache mismatch。
- 指标/告警与日志字段按 F6 README；阈值回填 NFR 实测，不使用空库默认值。
- correlationId/queryId/assetKey/revision/dataset checksum 可搜索；严禁 SQL、凭据、未脱敏业务值。
- 明确 on-call、业务 owner、回滚 operator；维护者不能自行批准/发布生产。

## RED → GREEN

1. RED：无 feature-flagged governed BI 发布证据、无 rollback image/runbook/alert fitness。
2. GREEN config test：governed 开关默认值、部门 override、紧急回切和旧客户端兼容；legacy write 开关保持 on 且可观测。
3. GREEN deployment IT：shadow/pilot/default 健康与关键 API/UI/DB/audit 对账。
4. GREEN fault drill：平台不可用、网关超时、registration backlog 后按 runbook 恢复。
5. GREEN rollback：恢复 flags/旧 image 后已发布旧资产可消费、Expand 数据保留。

## 影响范围与发布安全

实施前对配置、compose、security/gateway、registration 的实际 symbol 做 fresh impact；提交前 detect_changes。迁移 scheduler 不属于本 Sprint。不得未经用户明确请求直接 commit/push/rebuild 生产容器；本 Task 文档定义流程，实际部署另按授权执行。
