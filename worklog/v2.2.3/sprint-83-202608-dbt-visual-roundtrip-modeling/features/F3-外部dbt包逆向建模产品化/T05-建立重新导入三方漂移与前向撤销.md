# T05：建立重新导入、三方漂移与前向撤销

**优先级**：P1
**状态**：DRAFT  
**依赖**：T04、F1/T05、D05/D07

## 目标

同一外部项目再次导入时，基于最近一次已接受合并检查点 base、DTS 当前技术实施 current 和新 ZIP incoming 判定 SKIP/UPDATE/CONFLICT；ModelSpec 业务语义独立保留并重验映射。已应用结果用受资格约束的前向修订纠正，不删除历史。

## Contract-first

- **稳定身份**：tenant + projectKey + dbtUniqueId；重命名必须作为显式 old→new 决策，不能靠名称、路径或 SQL 猜测。
- **base 合并检查点**：逐项保存 `acceptedExternalChecksum + acceptedImplementationRevision/checksum + mappedModelSpecRevision/ETag`。只在 apply 成功或用户显式解决冲突后推进；inspect/preview/PARTIAL 失败不得推进失败项 base。
- **变化向量**：`externalChanged = incomingExternalChecksum != acceptedExternalChecksum`；`internalTechnicalChanged = currentImplementationChecksum != acceptedImplementationChecksum`。ModelSpec ETag 变化单独触发映射重验，不计入技术双边变化。
- **三方判定**：

  | externalChanged | internalTechnicalChanged | current 与 incoming | Action | reasonCode |
  |---|---|---|---|---|
  | 否 | 否 | 相同 | SKIP | NO_CHANGE |
  | 否 | 是 | - | SKIP | CURRENT_ONLY_CHANGED |
  | 是 | 否 | - | UPDATE | INCOMING_ONLY_CHANGED |
  | 是 | 是 | 规范化技术实现相同 | SKIP | CONVERGED_CHANGE |
  | 是 | 是 | 规范化技术实现不同 | CONFLICT | BOTH_CHANGED_DIVERGED |

- **业务语义**：重新导入不反写 ModelSpec 的业务定义、粒度、标准和治理绑定；业务变化本身不构成技术 CONFLICT。外部结构导致映射无效时 BLOCKED_REMAP，用户修复映射后重新 preview。
- **缺失/重命名**：incoming 中缺失的节点不等于删除；本期不自动删除。重命名只有显式 old→new 映射确认后才能进入新 preview。
- **冲突解决**：CONFLICT 必须逐项选择保留 current、接受 incoming 技术实现或取消；接受 incoming 仍不得清除 DTS 业务语义，且必须重新校验字段映射与依赖闭包。选择保留或接受后才创建新的合并检查点；取消不推进 base，避免同一决策被系统偷偷记为已接受。
- **前向撤销输入**：`targetAttemptId + selectedItemIds + expectedCurrentRevisions + idempotencyKey`；selectedItemIds 缺省为目标 attempt 的全部写入成功项，服务端重新冻结逆拓扑闭包和资格，不信任前端列表。
- **前向撤销输出**：复用现有 run/attempt/item result 台账，以 `operationType=FORWARD_UNDO` 记录新的 attempt；返回 undoAttemptId/status/summary/items 和每项新 revision/checksum 或失败对象，不新建撤销历史表。
- **CAS/幂等**：每项当前 ModelSpec/Implementation revision 必须等于 expectedCurrentRevisions 且仍指向目标 apply 结果；同 key+同规范化请求 replay 原结果，同 key+不同请求 409；重复撤销不得产生第二组恢复修订。
- **UPDATE 撤销**：按逆拓扑顺序为仍具资格的 UPDATE 项追加恢复到 pre-attempt 的 ModelSpec/Implementation 修订和公共审计，任何历史均不物理删除。
- **CREATE 撤销**：CREATE 没有 pre-attempt revision，本期不发明删除/归档语义，必须 BLOCKED，reasonCode=`CREATED_MODEL_NO_BASE_REVISION`、recoveryAction=`OPEN_MODEL`；是否增加 DRAFT 废弃能力另立决策/Feature。
- **SKIP 撤销**：SKIP 没有写入，为 no-op，结果仍记 SKIPPED。
- **撤销资格**：除 CREATE 外，仅 DRAFT、未发布/物化、未被下游 revision pin 且导入后未再次修改的 UPDATE 项可自动前向撤销；已发布、已物化、被引用或后续已变更的项 BLOCKED，转入现有生命周期/发布回退流程。
- **部分撤销**：一个 attempt 中仅部分项具备资格时可返回 PARTIAL，但每个未撤销项必须返回统一失败明细，不得声称整包撤销成功。
- **错误路径**：base 缺失、ETag 漂移、发布中、被下游 pin 或恢复依赖不闭合时 BLOCKED，展示具体影响、恢复动作和 correlationId。

## 验证

- [ ] FX-04 三方矩阵、重命名、删除、下游引用、重复撤销。
- [ ] PARTIAL apply 后只有成功项推进各自 base；失败项 retry 成功后才独立推进。
- [ ] 前向撤销覆盖 UPDATE 全可撤销、CREATE 明确阻断、混合 attempt 部分可撤销、全部阻断、CAS 漂移、同 key 重放/冲突和逆拓扑顺序。
- [ ] 历史 revision 和 audit 仍可追溯。
