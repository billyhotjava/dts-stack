# T03：展示首次导入依赖闭包、差异与阻断选择

**优先级**：P0  
**状态**：DRAFT  
**依赖**：T02、F1/T04

## 目标

把 artifact-rich 首次导入的 CREATE/SKIP/CONFLICT/BLOCKED、dependency closure 和 capability 损失明确展示，防止用户只勾选下游却遗漏必要上游。重新导入三方比较、缺失与重命名处理由 P1/T05 承担。

## Contract-first

- **输入**：preview runId/hash/items 与用户选择；技术节点来自固定 artifact-rich package，当前 ModelSpec revision/ETag 只用于映射一致性校验。
- **输出**：selectedUniqueIds 与服务端重新冻结的 selectedClosure；每项显示技术 checksum、action、reasonCode 与 recoveryAction。
- **动作兼容**：继续使用现有 CREATE/UPDATE/SKIP/CONFLICT/BLOCKED 五类动作，不新增平行状态机；P0 不提供三方 UPDATE 决策，检测到已有外部检查点或竞争性技术变化时稳定阻断并引导 P1 重新导入流程。
- **业务语义保护**：外部 ZIP 只拥有 DBT_MANAGED 技术实现；ModelSpec 中 DTS 已补充的业务定义、粒度、标准或治理绑定发生变化，不单独构成技术 CONFLICT，也不得被覆盖；结构变化使映射失效时标记 BLOCKED_REMAP，要求重新映射。
- **错误路径**：选择缺失依赖、跨计划节点、未确认删除/重命名、双边分歧、映射失效或 BLOCKED 项均禁止 apply。
- **UI**：依赖被自动加入时必须可见；冲突不能用“全部覆盖”绕过；每个阻断项必须符合统一失败契约。

## 验证

- [ ] FX-01 覆盖 CREATE、SKIP、身份碰撞、依赖阻断和已有模型冲突。
- [ ] 拓扑链、菱形依赖、循环和缺失依赖 fixture；动态/macro/package 深层传播由 T06 验收。
- [ ] 前端选择与服务端 closure 不一致时服务端拒绝/纠正。

## Definition of Done

- [ ] 用户在 apply 前能知道将创建、跳过、冲突和阻断哪些模型；重新导入 UPDATE 不在 P0 界面伪开放。
