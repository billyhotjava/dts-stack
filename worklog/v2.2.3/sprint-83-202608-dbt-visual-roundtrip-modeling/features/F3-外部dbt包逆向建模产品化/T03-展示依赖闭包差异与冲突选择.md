# T03：展示依赖闭包、差异与冲突选择

**优先级**：P0  
**状态**：DRAFT  
**依赖**：T02、F1/T04

## 目标

把 CREATE/UPDATE/SKIP/CONFLICT/BLOCKED、dependency closure 和 capability 损失明确展示，防止用户只勾选下游却遗漏必要上游。

## Contract-first

- **输入**：preview runId/hash/items、用户选择。
- **输出**：selectedUniqueIds 与服务端重新冻结的 selectedClosure；每项显示 base/current/incoming checksum 与 recoveryAction。
- **错误路径**：选择缺失依赖、跨计划节点、删除/重命名、双边变化、BLOCKED 项均禁止 apply。
- **UI**：依赖被自动加入时必须可见；冲突不能用“全部覆盖”绕过。

## 验证

- [ ] 拓扑链、菱形依赖、循环/动态依赖、重命名/删除 fixture。
- [ ] 前端选择与服务端 closure 不一致时服务端拒绝/纠正。

## Definition of Done

- [ ] 用户在 apply 前能知道将创建、更新、跳过和阻断哪些模型。
