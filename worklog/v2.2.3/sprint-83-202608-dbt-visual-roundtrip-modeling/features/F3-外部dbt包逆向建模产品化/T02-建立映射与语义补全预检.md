# T02：建立计划、域、来源映射与语义补全预检

**优先级**：P0  
**状态**：DRAFT  
**依赖**：T01、F1/T03

## 目标

让用户把外部项目绑定到现有 WarehousePlan、数据域和来源资产，并只人工补充无法从 dbt 推断的业务语义。

## Contract-first

- **输入**：artifact-rich package、三轴 compatibility、`inspectionProof`、`context`（plan/domain/source mappings）、`selection`（selectedUniqueIds）和 `semanticOverrides`。source-only 的 enforced contract 字段恢复由 P1/T06 扩展同一 seam。
- **proof 门禁**：preview 在读取映射前先验证签名及其绑定的 tenant、canonical actor、proof/canonicalization version 与规范化技术包 checksum，再读取已认证的 expiry。签名/绑定无效返回 409 `DBT_IMPORT_INSPECTION_PROOF_INVALID`；只有签名有效且主体/技术包匹配但超时才返回 410 `DBT_IMPORT_INSPECTION_PROOF_EXPIRED`；两者均不创建 run，恢复动作都是重新上传并 inspect。
- **业务补全白名单**：`semanticOverrides` 只允许模型类型/分层、业务名称/定义、grain、字段 role/key、标准绑定和消费场景；字段引用必须属于已验证技术字段。`context` 和 `selection` 继续做 tenant、权限、版本与依赖闭包校验。
- **技术事实不可变**：SQL/Jinja、字段名/类型、依赖、uniqueId/resourceType、project/config/materialization、artifact 内容与 checksum 禁止覆盖；禁止按表名自动确认，也禁止手工重建未知技术字段或动态依赖。
- **输出**：复用 preview response；每项包含 proposedModelSpec、ownership 固定为 `DBT_MANAGED` 的 proposedImplementation、compatibility/issues 与受影响依赖闭包。
- **错误路径**：plan/source/domain 不属于 tenant 403/404；缺业务主键/粒度/来源 422 BLOCKED；artifact 字段或依赖证据缺失时 fail-closed；source-only/complex 在 T06 完成前返回稳定未支持/阻断结果；映射版本漂移 409。
- **UI**：批量默认值必须逐项可查看；推断值标“建议”，未经确认不得 apply。

## 验证

- [ ] FX-01 artifact-rich 缺失业务语义时稳定 BLOCKED，用户只能补业务语义，不能改写技术证据。
- [ ] 仅白名单 context/selection/semanticOverrides 可进入 preview；修改技术字段、SQL、依赖、dbt 标识或 package metadata 即使重算 checksum 仍被 proof 拒绝。
- [ ] proof 过期、跨 actor/tenant 重放和签名篡改均返回冻结的 HTTP/code，且无 run/item 副作用。
- [ ] source-only/complex 未完成时不能录入未知字段后强行 apply；其完整矩阵由 T06 验收。
- [ ] 映射跨租户、已失效来源和版本漂移测试。

## Definition of Done

- [ ] preview 不修改 ModelSpec；proof 验证成功后才把规范化技术包与允许的用户输入固定到现有 import run/item；用户能解释每个补充值来源；技术事实不可人工豁免，artifact-rich applyable 项 ownership 固定为 `DBT_MANAGED`。
