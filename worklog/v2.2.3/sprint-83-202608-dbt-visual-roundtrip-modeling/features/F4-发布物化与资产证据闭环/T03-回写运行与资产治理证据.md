# T03：回写运行、结构、血缘、质量与 Catalog 证据

**优先级**：P1
**状态**：DRAFT  
**依赖**：T02

## 目标

PUBLISHED 后投影可发现逻辑资产；物化成功并取得 relation/quality evidence 后才切换可消费 serving，把固定运行产生的结构、血缘、质量和运行证据投影到表示读模型与 Catalog，而不覆盖逻辑设计或丢失旧成功 serving。

## Contract-first

- **契约**：生命周期、身份与双指针以 [`assets/catalog-serving-and-preview-contract.md`](../../assets/catalog-serving-and-preview-contract.md) 为唯一口径。
- **输入**：稳定逻辑 CatalogAssetKey、latestPublishedRef、candidate/version/attempt、artifact refs、relation evidence、quality evidence、source pins、expectedServingRef。
- **PUBLISHED 输出**：upsert 同一逻辑资产的业务定义、域、负责人、表级密级、标准绑定和 latestPublishedRef；新修订标记待物化，不创建虚假 relation。
- **MATERIALIZED 输出**：runtimeObservation、servingRef、既有物理 relation CatalogAssetKey/physicalAssetRef、lineage refs、quality refs、evidence checksum。
- **错误路径**：relation 不存在、字段漂移、质量未通过、build-only 或 stale 只记录失败尝试，不切换 serving；有旧 serving 时继续消费旧版本。
- **CAS/乱序**：切换 serving 必须匹配 candidate/version/attempt、latestPublished 资格和 expectedServingRef；旧/乱序 callback 拒绝，不得回退或覆盖新 serving。
- **同步**：内部事实与 outbox 同事务；外部 Catalog sync 在事务外幂等重试并显示 SYNC_PENDING/FAILED，不回滚发布/物化事实、不重新运行 dbt。
- **身份**：revision 是同一逻辑资产的属性；物理 relation 使用既有 datasource/catalog/schema/relation identity，禁止新建 revision/dbtUniqueId 资产台账。

## 验证

- [ ] declared/compiled/observed 字段差异可见。
- [ ] Catalog identity/quality binding 使用同一 asset key。
- [ ] r1 serving → r2 published/materializing/failed/succeeded 矩阵；失败保持 r1，成功才 CAS 到 r2。
- [ ] external sync retry 不重复 relation/资产，不回滚物化或再次运行 dbt。

## Definition of Done

- [ ] 运行证据可由 F2/T04 安全预览和追溯。
