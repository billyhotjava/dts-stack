# T04：接入候选固定的物理表结构与样例数据

**优先级**：P1
**状态**：CODE_COMPLETE
**依赖**：F4/T02～T03、T01

## 目标

在“物理资产”阶段展示 evidence 固定的真实字段，并在用户显式操作后读取有限受控样例：普通业务可视化只读当前 serving；高级 dbt 维护者可以预览成功但未 serving 的 candidate 并明确标记非正式。页面不展示生成或导入的 SQL，也不把实时样例冒充历史快照。

## Contract-first

- **契约**：完整请求、响应、错误码和 UI 规则以 [`assets/catalog-serving-and-preview-contract.md`](../../assets/catalog-serving-and-preview-contract.md) 为唯一口径。
- **输入**：modelSpecId/modelRevision/implementationRevision、scope=`SERVING|CANDIDATE`、candidateId/version/attempt(int)、pipelineRunId(UUID)、observationAttempt(int)、relationEvidenceId/evidenceChecksum、limit(1..500，缺省 100)。`attempt` 不是 import apply attempt，也不是 UUID。
- **输出**：精确版本上下文、CatalogAssetKey、relationRef、observedAt/queriedAt、columns、maskedRows、maskingSummary、returnedRows/truncated、driftStatus、correlationId。
- **结构/行分离**：结构来自固定 relation evidence；样例行在点击时实时查询。历史 revision 只展示结构，固定返回 `PHYSICAL_PREVIEW_HISTORICAL_ROWS_NOT_REPRODUCIBLE` 而不是查询当前 relation。
- **视图范围**：普通业务可视化只能请求当前 servingRef；CANDIDATE 仅限现有建模维护者 authority，candidate 必须成功且显示“候选结果，非正式资产”。未发布 candidate 只派生稳定 CatalogAssetKey 用于策略和审计，不创建 Catalog 资产记录。
- **UI**：物理结构先展示；样例区必须点击“加载样例”才查询。可选 20/50/100/500，不提供 offset/cursor、下载、批量复制或导出；提示“实时样例，不保证排序，不是历史快照”。
- **权限顺序**：tenant/model read → SERVING 的 Catalog 资产可读或 CANDIDATE 的维护者 authority → 表级 classification → 按稳定 CatalogAssetKey 解析列 ALLOW/MASK/DENY；UNKNOWN/服务不可用阻断整次样例响应，绝不回退原值。
- **缓存/审计**：结构可按 evidenceChecksum 使用 ETag；样例 `private, no-store`，样例值不进缓存、日志、审计或持久存储。
- **错误路径**：未物化、candidate 未成功、evidence mismatch、stale/historical 409；relation 不存在 404；越权 403；密级/脱敏不可用 423/业务 BLOCKED；limit 超限 400；超时 504。全部返回 0 行和 correlationId。
- **Evidence 固定**：服务端按 relationEvidenceId 读取物理 observation，并在访问目标数据库前校验 tenant、model/revision、implementation revision、candidate/version、attempt、pipelineRunId、observationAttempt 和 checksum 全部匹配；不匹配时目标数据库查询数为 0。
- **Relation 来源**：database/schema/identifier 只取 observation 的分段字段；禁止客户端 relation/schema/table、relationRef、dbt manifest 或模型名直接进入 SQL。
- **Identifier 防线**：连接和查询前重新执行现有规范 identifier 白名单；非法返回 `PHYSICAL_PREVIEW_IDENTIFIER_INVALID`、目标数据库查询数为 0。PostgreSQL database 只做固定 datasource/catalog 等值复核且不进入 SQL；schema/identifier 合法值仍须由 adapter 专属引用器逐段引用，禁止复用 `DbtPreviewService` 手写 quote 或自行字符串转义。
- **Metadata 复核**：执行样例 SELECT 前，先以参数化 catalog/DB metadata 查询确认 database/schema/identifier/relation type 仍与 observation 一致；不存在或漂移时 fail-closed，不读取样例行。

## 验证

- [ ] 显式加载、缺省 100、20/50/100/500、501、无分页/导出/no-store。
- [ ] 引号、分号、SQL 注释符、点号、超长、Unicode 等恶意模型名在连接/查询前以 `PHYSICAL_PREVIEW_IDENTIFIER_INVALID` 阻断且目标数据库查询数为 0；保留字等合法白名单值经 adapter 引用后只读取 evidence 固定 relation。
- [ ] 客户端 relation/schema/table、relationRef 和 manifest/model name 无法改变查询目标；evidence 的 tenant/model/implementation/candidate/version/attempt/pipelineRunId/observationAttempt/checksum 任一不匹配均返回 `PHYSICAL_PREVIEW_EVIDENCE_MISMATCH`、0 行且不访问目标数据库。
- [ ] serving 与成功未发布 candidate 隔离；普通用户不能请求 candidate；历史 revision 永不返回样例行。
- [ ] 跨租户、表级密级、ALLOW/MASK/DENY/UNKNOWN、策略不可用和审计零样例值。
- [ ] stale/build-only/失败 candidate 无法预览为成功，所有错误返回 0 行。

## Definition of Done

- [ ] 页面将物理观测与逻辑/编译结构并列显示，不覆盖设计事实；实时样例不冒充 candidate 历史快照。
