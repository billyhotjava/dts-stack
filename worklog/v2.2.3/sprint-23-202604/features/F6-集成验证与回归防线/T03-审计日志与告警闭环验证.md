# T03: 审计、日志与告警闭环验证

**优先级**: P1
**状态**: READY
**依赖**: F5/T03

## 目标
确保会话异常发生时，平台、代理、analytics 三侧都能留下足够证据并触发正确告警。

## 技术设计
- 定义关键日志事件: 登录成功、续租成功、续租失败、takeover、idle timeout、proxy 认证失败、analytics bridge 失败
- 设计日志字段统一规范，至少包含 username、browser_id、session_id、reason code、route
- 定义关键告警: `session/current` 失败率、`/bi/api/screens/*` 401 比例、takeover 激增
- 用一次真实演练验证日志串联和告警触发

## 影响范围
- `source/dts-platform/src/main/resources/logback-spring.xml`
- `source/dts-analytics/src/main/resources/`
- `services/dts-proxy/`
- `worklog/v2.2.3/sprint-23-202604/assets/`

## 验证
- [ ] 至少一次演练能串起 platform、proxy、analytics 三侧日志
- [ ] 告警阈值能区分正常波动和异常风暴
- [ ] 审计事件可反查到具体 browser_id 和 session

## 完成标准
- [ ] 发布后若再次出现会话异常，可在 5 分钟内完成分层定位
- [ ] 告警和审计形成闭环，不再依赖临时 SSH 抓日志
