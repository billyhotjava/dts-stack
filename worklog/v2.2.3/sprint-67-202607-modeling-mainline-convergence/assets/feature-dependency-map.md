# Feature 与 Task 依赖图

```text
F1-T01 统一客户语言和 canonical 对象
 ├─> F1-T02 业务对象处置决策
 └─> F1-T03 业务分类/业务活动边界
       ├─> F2-T01 计划创建输入
       ├─> F2-T02 分类与分层基线
       └─> F3-T01 无对象 ModelSpec 契约

F2-T01 -> F2-T02 -> F2-T03 -> F2-T04

F3-T01
 ├─> F3-T02 维度目录与维度表
 ├─> F3-T03 明细表
 └─> F3-T04 汇总表与应用表
      └─> F3-T05 字段/标准/来源/门禁

F2-T04 + F3-T05
 ├─> F4-T01 菜单信息架构
 ├─> F4-T02 路由与上下文
 └─> F4-T03 页面状态和唯一主动作
      └─> F4-T04 客户语言/空错权/Chrome95

F2-T01 + F2-T04 + F4-T02/T03/T04
 └─> F2-T05 建设规划台账、计划头编辑与受控归档

F3-T05 + F4-T02
 └─> F5-T01 旧对象 dry-run
      -> F5-T02 API 冻结与适配
      -> F5-T03 数据迁移和退出门槛
      -> F5-T04 消费者与指标包清理

F2-T04 + F3-T05 + F4-T04 + F5-T04
 └─> F6-T01 四类标准 owner/指标交接
      -> F6-T02 构建/发布/运行证据
      -> F6-T03 双起点 E2E
      -> F6-T04 发布、回滚和交付决策
```

## 并行规则

- F2 与 F3 在 F1 完成后可并行；
- F4-T01 可与 F2/F3 后半段并行，但默认菜单切换等待目标页面可用；
- F5-T01 dry-run 可提前开发，冻结旧写入必须等待 F3/F4；
- F6-T01 可先做契约测试，端到端和发布决策必须等待 F2-F5。

## 评审门

| 门 | 必须通过的 Task | 判据 |
|---|---|---|
| G1 概念冻结 | F1 全部 | 对外词表没有业务对象/语义对象，内部映射无歧义 |
| G2 新主线可用 | F2、F3 全部 | 无 objectId 可完成四类表保存和门禁 |
| G3 UI 切换 | F4 全部 | 菜单、路由、页面状态和唯一动作一致 |
| G4 旧写冻结 | F5 全部 | 迁移校验通过，旧调用可审计且无新写 |
| G5 发布 | F6 全部 | 两条旅程、兼容、权限、Chrome95 和回滚证据齐备 |
| G6 人工测试增量闭环 | F2-T05 | canonical 规划可查找、编辑、归档，权限/CAS/Chrome95 证据齐备并复评 Go/No-Go |
