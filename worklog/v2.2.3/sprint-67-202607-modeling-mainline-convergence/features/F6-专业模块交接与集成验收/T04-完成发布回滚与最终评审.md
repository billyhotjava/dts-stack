# T04：完成发布、回滚与最终评审

**优先级**：P0
**状态**：READY
**依赖**：F6-T03、F5-T04

## 目标与用户结果

给出可复核的 Go/No-Go 决策，明确哪些能力已切换、哪些旧结构只读、哪些满足物理删除，避免用“页面看起来变了”宣称 Sprint 完成。

## 范围与不做

- 范围：测试/构建/迁移/浏览器/GitNexus/安全审计、回滚演练、状态更新和交付索引。
- 不做：不因截止日期跳过失败项，不把 REMOVAL_CANDIDATE 写成 RETIRED。

## 输入条件

24 个 Task 的证据、迁移 reconciliation、legacy API usage、zero-consumer scan、模块构建、Chrome 95 和 rollback drill 均可打开。

## 输出产物

- Go/No-Go review；
- 功能/测试/部署/浏览器四层完成状态；
- 兼容和物理删除清单；
- 回滚步骤/时限/责任；
- Sprint README/queue/IT evidence 索引更新。

## 详细设计

1. 分别判定：新主线可用、旧写冻结、旧读兼容、消费者归零、物理删除；不得合并成一个“完成”。
2. 运行 GitNexus detect_changes，核对只影响预期 modeling/menu/metrics/ops flows；HIGH/CRITICAL 差异单独评审。
3. 执行 `git diff --check`、后端测试、前端契约/构建、迁移和 Chrome 95。
4. 回滚演练验证菜单/读取切换、目标 ModelSpec 不丢、无双写和审计可追溯。
5. 更新每个 Task/Feature/Sprint/queue 状态时附证据链接；缺证据保持 READY/IN_PROGRESS。

## 影响范围

- Sprint-67 全部文档和 `it/evidence/`
- `worklog/v2.2.3/sprint-queue.md`
- release/runbook 和 feature flags
- GitNexus/report/build outputs

## No-Go 条件

- 新模型仍要求 objectId；
- 业务对象写 API仍产生新行；
- legacy 映射/校验和不一致；
- 指标/发布/运行丢失真实记录；
- 权限扩大、跨租户泄漏；
- Chrome 95 主线失败或回滚恢复双写。

## 实施与测试设计

1. 汇总并验证证据文件非空、日期/commit/环境一致。
2. 运行最终命令和 GitNexus 范围检查。
3. 演练回滚并记录 RTO/结果。
4. 召开最终 review，记录 Go/No-Go 和遗留项 owner/date。
