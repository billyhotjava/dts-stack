# T02：接通构建、发布、运行与血缘证据

**优先级**：P0
**状态**：DONE
**依赖**：F3-T05、F4、F5-T03

## 目标与用户结果

从模型详情进入 SQL/dbt 实现，构建、测试、审核、发布和运行全部回写同一 modelSpecId/revision；失败能回到模型定位修复。

## 范围与不做

- 范围：implementation ownership、artifact、compile/test/run、review/publish、asset/BI/lineage 注册和回链。
- 不做：高级 dbt 不创建第二 ModelSpec；文件浏览不成为一级主线。

## 输入契约

进入实现需 modelSpecId、revision、implementationMode 和 IMPLEMENTATION_READY gate。提交发布需当前 revision 的 compile/test/quality/permission/ownership evidence。

## 输出产物

- SQL/schema.yml/tests/docs/dbt artifacts；
- compile/test/pipeline run；
- review/publish record；
- catalog asset、BI dataset、lineage edge；
- ops instance 和模型修复链接。

## 详细设计

1. 设计器生成和 DBT_MANAGED 用明确 ownership，冲突时阻止覆盖。
2. dbt import 必须创建/关联真实 ModelSpec，不得返回不存在的 modelSpecId 或留下 null artifact owner。
3. artifact checksum/revision 与 ModelSpec 绑定；revision 变化使旧 evidence STALE。
4. 发布审核从旧 SemanticModelingService 拆到 ModelSpec lifecycle，保留评论、操作者和时间。
5. 资产/BI/血缘注册幂等；部分失败记录具体步骤并允许重试，不回滚已成功外部动作而不留记录。
6. Ops run 带 modelSpecId/planId，失败详情提供返回模型和重跑/补数权限入口。

## 影响范围

- ModelingVNext compile/run/artifact/lineage services/resources
- SqlModelingPage、DbtFileBrowserPage/目标 dbt workbench
- SemanticPublish/Runs 的目标替代
- AnalyticsServiceClient/SemanticContractPublishService（保留 BI 查询语义）
- OpsInstancesPage/route params

## 异常、权限与回滚

- artifact/revision 不匹配：阻止发布。
- 外部注册部分失败：状态 PARTIAL，按 step 幂等重试。
- 回滚发布生成新事件，不删除历史审计和运行。

## 实施与测试设计

1. 写 ownership、revision drift、partial publish 和 idempotency 测试。
2. 修 dbt import/modelSpec/artifact 关联。
3. 迁移 review/run/publish 能力到 model lifecycle。
4. 端到端执行 compile/test/publish/run/failure-repair。
