# T01：接通标准与指标专业模块

**优先级**：P0
**状态**：DONE
**依赖**：F3-T05、F5-T04

## 目标与用户结果

模型字段可以直接关联数据元、码表和度量单位；已发布模型可以直接创建/关联指标。用户不再经低代码或业务对象中转，标准模块也不再缺少传统行业常用的度量单位能力。

## 范围与不做

- 范围：四类标准入口、度量单位正文/API/页面、标准选择/绑定/漂移、指标模型锚点、返回链和 StageProjection 证据。
- 不做：不在模型页维护标准正文，不在指标页复制模型字段真值。

## 输入契约

| 交接 | 输入 | 输出 | 门禁 |
|---|---|---|---|
| 模型→标准 | modelSpecId+revision+fieldName | standardElementId/referenceCode/measurementUnitId（均带版本） | DWD/发布策略要求字段完整 |
| 模型→指标 | published modelSpecId/revision+measure field | metric definition/ref/version | FACT/SUMMARY/APPLICATION 可用 |
| 指标→模型 | metricRef@version | ModelSpec.metricRefs | 引用可访问且状态有效 |

## 预期输出

- DataElement/ReferenceCode/MeasurementUnit/NamingTerm 的稳定 ID 与版本；
- StandardBinding/metricRef；
- version drift 状态和 repair route；
- 数据标准/指标两站的真实 StageEvidence；
- planId/modelSpecId 返回链。

## 详细设计

1. 数据元、公共码表、命名词典复用现有 owner 页面/API；对外标签分别固定为“数据元”“公共码表”“命名词典”，不再制造同义菜单。
2. 新增标准模块度量单位注册表：`/api/governance/measurement-units` 持有 code、name、symbol、quantityKind、conversionFactor、baseUnitRef、precision、status、version；`/governance/standards/units` 提供查询、版本化新增/停用和引用影响查看。换算因子只用于口径说明，模型构建不会隐式换算业务值。
3. Elements/标准页从模型字段上下文进入，保存后返回模型详情并刷新 release gate；不跳低代码向导。模型仅在 standardBindings 保存 standardElementId、referenceCode、measurementUnitId 和各自版本。
4. 指标工作台选择模型和度量字段，不加载业务对象树；度量字段存在 measurementUnitId/version 时带入指标草稿，但仍由用户确认。
5. 原子指标定义 measure+aggregation；派生指标定义依赖、时间周期和修饰词，模型只保存引用。
6. 标准/指标版本漂移将证据置 STALE，不静默绑定最新版。
7. 专业模块不可用时模型显示 UNKNOWN，保留上次引用和修复入口。

## 影响范围

- ElementsPage/ReferenceCodesPage/GlossaryPage、标准 API 与 standard binding service
- 新 MeasurementUnit resource/service/repository/Liquibase、MeasurementUnitsPage 和菜单/权限种子
- MetricWorkbenchPage/metric canvas/helpers
- GovernanceIndicator APIs/dts-metrics contracts
- WarehousePlan StageProjection evidence providers

## 异常与权限

- 无权标准/指标只显示受限引用，不泄露正文。
- 模型字段删除/改名触发漂移，不自动重绑同名字段。
- 指标模块失败不回退旧 semantic metric 写入。

## 实施与测试设计

1. 写四类标准 owner contract、单位版本/引用/停用测试和 standards/metrics handoff 漂移测试。
2. 实现度量单位最小 owner 面，再改标准返回链与指标锚点，删除对象中转。
3. 接 StageEvidence 并验证失败/权限；单位被引用时禁止硬删除。
4. 浏览器完成字段→数据元/码表/单位、模型→指标、返回模型三段流程。

## 完成记录（2026-07-20）

- 数据元 owner 增加非空递增版本；公共码表复用稳定 `codeTypeId`、数值版本标签和启停状态；命名词典复用 UUID、版本快照、部门可见范围与维护权限；度量单位使用独立版本账本、强 ETag 和引用影响查询。
- ModelSpec 字段只保存三类标准的稳定 ID/版本；真实 owner 不存在、停用或版本不一致时返回 STALE，专业库不可访问时返回 UNKNOWN。
- 已发布 FACT/SUMMARY/APPLICATION 通过专用 CAS 接口绑定已发布指标精确版本，旧 revision 保持不变，不经过业务对象或旧 semantic metric 写路径。
- 后端 9 个相关测试类一次通过；前端生产构建及 Chrome95 legacy bundle 已通过；三个新增 mock 浏览器场景分别验证标准绑定、单位 owner 和模型→指标交接。
- 本 Task 的 Chrome95 证据使用精确 API mock；真实登录、权限、Liquibase/PostgreSQL 与新增 API 联调归入 F6-T03，不在此伪报为真实 E2E。
