# T03：设计明细表与粒度时间语义

**优先级**：P0
**状态**：DONE
**依赖**：F3-T01、F2-T03

## 目标与用户结果

用户直接创建明细表，通过“一行代表什么”、粒度键、事实形态、业务时间和来源说明业务发生了什么，不借助业务对象承载这些信息。

## 范围与不做

- 范围：FACT 表单、grain、factShape、timeSemantics、sourceRefs/dependsOn、dimensionRefs 和门禁。
- 不做：业务活动不成为独立建模产物；不默认所有行业都是事务事实。

## 输入契约

| 字段 | 保存 DRAFT | 进入实现 | 发布 |
|---|---|---|---|
| planId/domainId/name/layer | 必填 | 必填 | 必填 |
| grain.statement + keys | 必填 | 必填 | 必填且字段存在 |
| sourceRefs / dependsOn | 可均为空；已填写引用必须有效 | CURRENT 物理来源或锁定 revision 的上游 ModelSpec 至少一种有效 | 已填写引用均当前有效/版本匹配 |
| factShape | 可后补 | 必填 | 与粒度/时间一致 |
| timeSemantics.type+fields | 可后补 | 必填 | 字段类型和来源有效 |
| dimensionRefs | 可选 | 按查询需要 | 引用版本有效 |
| businessActivityRef | 可选 | 可选 | 只做说明，不查独立对象存在性 |

## 输出产物

- FACT ModelSpec/revision；
- 粒度、事实形态、时间语义，以及物理来源或上游模型映射；
- 事实到维度的派生关系；
- 实现/发布 blocker 列表。

## 详细设计

1. 主表单先问“一行代表什么”，再让用户选键；不以 object type 问卷代替粒度。
2. factShape 支持 TRANSACTION、PERIODIC_SNAPSHOT、ACCUMULATING_SNAPSHOT，并给中性模板。
3. timeSemantics 根据事实形态建议事件日期、快照日期、周期或里程碑日期，但仅为候选。
4. dimensionRefs 指向 DIMENSION ModelSpec；总线矩阵和 ER 关系从引用派生，只读展示。
5. activityRef 在“业务说明”折叠区，允许选择已有活动或文本说明；为空不阻止保存/发布，只保留可选治理规则扩展点。
6. DWD 默认层只作为建议；用户可按策略选择，服务端验证与计划 policy 一致。

## 影响范围

## 异常与权限

- 粒度键不在来源/字段列表：阻止实现，允许保存草稿并明确字段。
- factShape/timeSemantics 不一致：422 + repair field。
- 无权访问维度：不泄露详情，引用状态 UNKNOWN。

## 实施结果（2026-07-19）

- canonical FACT 直接保存 grain、sourceRefs、factShape、timeSemantics 与可选 dimensionRefs/businessActivityRef，不依赖 objectId/processId。
- 三类事实形态由服务端实现门禁校验时间语义兼容性，时间字段必须引用 `role=TIME` 字段；来源和维度引用按当前版本检查。
- `businessActivityRef` 仍为可选说明，聚焦测试证明为空不形成 blocker；字段级 blocker 提供稳定 code 和修复页签。

### 2026-07-22 草稿与实现门禁修订

- FACT 草稿的核心语义是目标模型粒度，不要求先选择具体物理表；目标表由后续实现产生，不能作为自己的上游来源。
- 进入实现前使用 inclusive OR：有效 `sourceRefs` 或锁定 revision 的有效 `dependsOn` 至少一种；两者同时存在时逐一校验。
- 目标数仓分层属于本 ModelSpec，上游来源分层属于输入，两者显式分开且不得自动互相推导。增量实现与真实联动验收由 F3-T06 跟踪。

### 2026-07-23 FACT 分层依赖收敛

F3-T07 在不回退本 Task/F3-T06 草稿语义的前提下进一步约束：

- FACT 目标层固定为 DWD，由类型自动确定；
- 直接 `sourceRefs` 允许 ODS_RAW/ODS_STANDARDIZED/STG，以及当前计划已确认的存量或外部管理 DWD 物理资产；
- `dependsOn` 只允许锁定 revision 的 FACT@DWD，禁止 DIMENSION 进入 dependsOn，也禁止反向依赖 DWS/ADS；DIMENSION 通过 `dimensionRefs` 引用；
- DRAFT 仍允许两类输入均为空，IMPLEMENTATION_READY 才要求至少一种有效；
- 旧 ODS/STG ModelSpec 不应成为新的 FACT 上游模型候选；其专属分类和迁为 SourceBinding/技术产物的流程仍待 F3-T07 实现。

类型/层级不匹配、上游层不允许和 revision 漂移必须返回稳定 blocker，不能在页面静默纠正已提交请求。
