# T06：拆分上游输入与目标模型并后移来源门禁

**优先级**：P0
**状态**：IN_PROGRESS
**依赖**：F2-T03、F3-T01、F3-T03、F3-T05、F6-T06

## 目标与用户结果

用户创建明细表时，先描述目标模型的名称、目标数仓分层和“一行代表什么”，可以在尚未确定上游输入时保存 FACT 草稿。进入 SQL/dbt 实现前，再从以下两类上游证据中至少选择一种：

1. 当前计划已确认且版本有效的物理来源 `sourceRefs`；
2. 锁定到明确 revision 的上游 ModelSpec `dependsOn`。

模型表单不再要求用户把“正在创建的目标表”当成自己的来源。目标物理表由后续 SQL/dbt 编译、构建和运行产生，不要求先通过 ETL/ELT 创建好后再登记模型。

## 问题来源

2026-07-22 人工测试发现，FACT 新建表单把“数据来源”设为草稿保存必填，并要求选择来源盘点中的具体表。该规则只适用于“从现有资产直接建模”的路径，却错误阻断了“先完成逻辑设计、后补输入映射”的路径，也容易让用户误以为必须先创建目标 DWD 表，再反向选择它作为来源。

根因是界面和契约混用了两种分层：

- **目标数仓分层**：当前 ModelSpec 未来产物所在层，例如 DWD；
- **上游来源分层**：已有物理来源或上游模型所在层，例如 ODS/DWD。

两者不能相互默认，也不能根据表名猜测。直接物理来源仍需先完成元数据同步并纳入当前计划；但这不是保存 FACT 草稿的前置条件，也不等于必须先完成 ETL/ELT。

## 分阶段契约

| 阶段 | FACT 必填 | 上游输入规则 | 失败策略 |
|---|---|---|---|
| `DRAFT_SAVE` | planId、domainId、名称、目标层、grain.statement/keys | `sourceRefs=[]` 且 `dependsOn=[]` 合法；若填写任一引用，仍立即校验计划归属、权限、版本和重复项 | 基础定义不完整或已填写引用无效时拒绝 |
| `IMPLEMENTATION_READY` | 草稿字段 + factShape + timeSemantics + 字段闭合 | 至少一个 CURRENT 物理来源，或至少一个锁定 revision 且当前可用的上游 ModelSpec | 两类均为空时返回 `MODEL_SPEC_FACT_INPUT_REQUIRED`；引用过期/未知时 fail closed |
| `RELEASE_READY` | 实现门禁 + 标准、质量、权限、当前 revision 产物 | 复用实现阶段的 inclusive OR；若两类同时提供，则两类引用都必须有效 | 不以另一类有效证据掩盖已填写的失效引用 |

`sourceRefs` 与 `dependsOn` 是 inclusive OR，不是互相豁免：至少一种可用；两种同时存在时都进入引用校验，`dependsOn` 继续进入依赖图/血缘关系，编译投影保持确定性的 direct-first 规则。

## 页面与字段语义

1. 将模型层级字段标为“目标数仓分层”，说明它描述本模型未来产物位置。
2. 将来源区标为“上游输入来源（不是本模型目标表）”，并展示两种选择：
   - “选择已确认物理来源”：读取当前 WarehousePlan 的 `CONFIRMED + CURRENT + AVAILABLE` 来源；
   - “选择上游模型”：保存 `{modelSpecId, revision}`，并参与循环依赖检查。
3. FACT 草稿没有上游输入时允许保存，并提示“进入实现前补齐物理来源或上游模型”。
4. 物理来源的“上游来源分层”仍由用户按规划语义确认；系统不根据目标层、表名或连接类型自动猜测。
5. 选择上游 ModelSpec 时，其名称和分层由锁定 revision 自动带入编译投影，不要求重复选择物理表。
6. 来源库存加载失败只阻止选择或校验物理来源；当草稿未选择 `sourceRefs` 时，不得因此阻止保存。

## WarehousePlan 导航边界

本 Task 不取消 WarehousePlan 的 onboarding 顺序：`ASSET_FIRST` 仍优先把工作台 `nextAction` 指向数据连接/来源盘点；`BUSINESS_FIRST` 只有在 `conceptualDesignAllowed=true` 时才可将空来源延后并先进入模型设计。该规则是工作台阶段排序和引导策略，不是 ModelSpec DRAFT 的保存校验；无论用户从哪个合法入口到达 FACT 表单，DRAFT API 都不得重新强制 `sourceRefs` 非空。

## 后端与编译边界

1. FACT 创建/更新契约移除 DRAFT 阶段的 `sourceRefs` 非空校验，保留 grain 最小语义。
2. stage gate 在 `IMPLEMENTATION_READY`/`RELEASE_READY` 执行 `sourceRefs OR dependsOn`，并对所有已提供引用逐一验证。
3. FACT 与 SUMMARY/APPLICATION 一样执行上游 ModelSpec 循环依赖检查。
4. 编译投影继续保持确定性：有直接 `sourceRefs` 时生成物理 source 投影；没有直接来源但存在 `dependsOn` 时按锁定的上游 ModelSpec 名称和层级生成模型引用。
5. 本 Task 不创建目标物理表、不触发 ELT/ETL、不猜测物理来源层级；这些动作分别属于实现、构建和运行阶段。

## F3-T07 后续边界（2026-07-23）

本 Task 解决“FACT 草稿是否必须有上游”和“目标表是否被误当来源”；F3-T07 接续解决“哪一种上游层允许进入哪一种目标模型”：

- FACT 目标层固定 DWD；
- 直接 sourceRefs 允许 ODS_RAW/ODS_STANDARDIZED/STG，以及当前计划已确认的存量或外部管理 DWD 物理资产；
- dependsOn 只允许锁定 revision 的 FACT@DWD；DIMENSION@DWD 通过 dimensionRefs 引用，不进入 FACT dependsOn；
- DWS/ADS 不得反向作为 DWD 上游；
- 模糊 ODS 来源必须先在来源盘点确认 RAW/STANDARDIZED；
- 历史 ODS/STG ModelSpec 的专属只读分类和候选排除是 F3-T07 后续实现项。

F3-T07 不得把本 Task 已完成的 source-free DRAFT 再收紧；类型/层级矩阵从 DRAFT 到 RELEASE 都校验引用合法性，但只有进入实现时才要求 FACT 至少具备一种有效输入。
