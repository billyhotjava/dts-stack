# T08：拆分业务维度与逻辑维度表并建立四层契约

**优先级**：P0
**状态**：IN_PROGRESS
**依赖**：F3-T01、F3-T02、F3-T07

## 目标

纠正“维度目录直接创建 DIMENSION ModelSpec”的对象混用，引入独立 `DimensionDefinition`，让业务维度、逻辑模型、数据实现和物理资产各有唯一所有者，并以稳定 ID/revision 关联。

## 权威设计

- [业务维度、逻辑模型、实现与物理资产四层最小闭环设计](../../assets/modeling-four-layer-minimal-loop-design.md)

## 范围

- 新增业务维度 canonical 契约、持久化、系统编码、权限和生命周期；
- DIMENSION ModelSpec 引用业务维度，不复制维度正文；
- 保留粒度、字段、业务键和 SCD 逻辑策略在 ModelSpec；
- 设计并实现旧 DIMENSION 记录的 expand/dry-run/backfill/compatibility；
- 旧深链和历史 revision 保持可读，禁止新的混合写入；
- T02 历史实现和证据保留，但目标契约由本 Task 替代。

## 不做

- 不删除旧 ModelSpec 或物理资产；
- 不新增第二套业务分类、标准或指标；
- 不在本 Task 实现数据物化和页面三阶段重构。

## 验证

- [ ] 无连接、无来源可以创建和确认业务维度；
- [ ] DIMENSION ModelSpec 必须引用可见且 CURRENT 的业务维度；
- [ ] 业务维度不保存来源、目标层、物化或 SQL/dbt 字段；
- [ ] 系统编码服务端生成、租户内唯一且不可手工伪造；
- [ ] 存量 DIMENSION dry-run 分类、幂等迁移、计数对账和回滚通过；
- [ ] 删除/退役业务维度不级联删除 ModelSpec、实现或物理资产；
- [ ] 旧 API/深链和历史 revision 保持可读。
