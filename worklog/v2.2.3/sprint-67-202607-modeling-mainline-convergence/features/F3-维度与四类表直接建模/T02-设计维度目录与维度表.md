# T02：设计维度目录与维度表

**优先级**：P0
**状态**：IN_PROGRESS
**依赖**：F3-T01

## 目标与用户结果

用户在“维度目录”登记分析角度，并直接形成 DIMENSION ModelSpec；不先登记业务对象，不要求业务活动。

## 范围与不做

- 范围：维度目录列表、创建/详情、键/属性/层级/SCD/复用范围和维度表生成。
- 不做：不复用 SemanticObjectsPage 的事实/事件/快照混合表单，不创建独立维度真值表与 ModelSpec 双写。

## 输入契约

| 字段 | 创建必填 | 实现前必填 | 规则 |
|---|---|---|---|
| planId/domainId | 是 | 是 | 有编辑权限 |
| name/code/definition | 是 | 是 | code 租户内稳定 |
| grain.statement | 是 | 是 | 表述“每行一个什么” |
| dimensionKey | 是 | 是 | 至少一个稳定键 |
| attributes/hierarchy | 否 | 按设计 | 层级不得成环 |
| scdPolicy | 否 | 是 | NONE/TYPE1/TYPE2 等支持值 |
| sourceRefs 或 generationPolicy | 否 | 二选一 | 概念阶段允许为空 |

## 输出产物

- `ModelSpec(modelType=DIMENSION)`；
- 维度字段/层级/SCD 策略；
- 可被 FACT/SUMMARY/APPLICATION 引用的 modelSpecId；
- 维度表实现候选。

## 详细设计

1. 新 `/modeling/dimensions` 查询 `modelType=DIMENSION` 的 ModelSpec。
2. 目录支持无 planId 浏览；新建时若无上下文，只弹一次计划和业务分类选择。
3. 从计划进入时锁定 planId，domainId 默认当前分类但允许在计划绑定范围内切换。
4. 概念维度保存为 DRAFT；生成维度表前补来源/生成策略、键、标准和历史策略。
5. 一致性维度通过复用同一 DIMENSION ModelSpec 表达，不另写总线矩阵；关系由模型引用派生。
6. 旧 ConformedDimensionCatalogCard 可抽取 UI，但数据源和保存接口必须替换，禁止继续以 sprint64 表为新真值。

## 影响范围

- 新 `DimensionCatalogPage`/路由和 focused components
- `ConformedDimensionCatalogCard.tsx`（可抽取，非直接复用数据契约）
- `SemanticObjectsPage.tsx` 兼容跳转
- ModelSpec API/validation
- menu seed、role defaults、route tests

## 异常、权限与恢复

- code 冲突、层级成环、key 重复返回字段级错误。
- 来源失效不删除维度；实现门禁变 UNKNOWN 并给修复入口。
- 无编辑权限保持可浏览，隐藏/禁用新建。

## 实施与测试设计

1. 先写 DIMENSION 必填矩阵、无 process、SCD 和层级环测试。
2. 建立路由、列表和创建表单；API 只写 ModelSpec。
3. 将旧 DIMENSION 对象映射到目录读模型。
4. 浏览器验证空态、无 plan、从计划返回和窄屏。
