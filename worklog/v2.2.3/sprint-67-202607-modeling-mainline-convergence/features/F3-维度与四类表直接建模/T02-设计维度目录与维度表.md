# T02：设计维度目录与维度表

**优先级**：P0
**状态**：DONE
**依赖**：F3-T01

## 目标与用户结果

用户在“维度目录”登记分析角度，并直接形成 DIMENSION ModelSpec；不先登记业务对象，不要求业务活动。

## 范围与不做

- 范围：维度目录列表、创建/详情、键/属性/层级/SCD/复用范围和维度表生成。
- 不做：不复用 SemanticObjectsPage 的事实/事件/快照混合表单，不创建独立维度真值表与 ModelSpec 双写。

## 输入契约

| 字段 | 创建必填 | 实现前必填 | 规则 |
|---|---|---|---|
| planId/domainId | 是 | 是 | 计划可编辑且分类已确认 |
| layer/implementationMode | 是 | 是 | 沿用 canonical ModelSpec 通用字段 |
| name/description | 新 UI 是 | 是 | `description` 是维度定义；客户所说的 definition 直接复用它，不新增同义字段；历史 v2 空值保持可读 |
| dimensionProfile.dimensionCode | 是 | 是 | 匹配 `^[A-Z][A-Z0-9_]{0,63}$`；租户内大小写不敏感唯一且创建后不可变 |
| grain.statement | 是 | 是 | 表述“每行一个什么” |
| grain.keys + KEY fields | grain.keys 至少一个 | 是 | 不新增 dimensionKey；实现前每个 key 必须唯一命中 `fields.role=KEY` |
| fields(role=ATTRIBUTE) | 否 | 按设计 | 不新增 attributes 第二真值 |
| dimensionProfile.hierarchies | 否 | 按设计 | 层级只引用已声明字段，层级内字段不重复且不得成环 |
| dimensionProfile.scdPolicy | 否 | 是 | `NONE/TYPE1/TYPE2`；属于 `IMPLEMENTATION_READY` 门禁 |
| dimensionProfile.reuseScope | 否，默认 PLAN | 是 | `PLAN/DOMAIN/TENANT`；不放大原有权限 |
| sourceRefs / generationStrategy | 否 | 至少一个 | 是 inclusive OR；概念阶段可同时为空，实现前允许两者同时存在 |

### Phase-B canonical 契约裁决（已实现）

`dimensionProfile` 是 DIMENSION ModelSpec 的类型专属片段，不是新的维度主表或第二事实源：

```json
{
  "dimensionProfile": {
    "dimensionCode": "DIM_STABLE_CODE",
    "hierarchies": [
      {
        "code": "hierarchy-code",
        "name": "层级名称",
        "levels": [
          { "fieldName": "level_code", "order": 1 }
        ]
      }
    ],
    "scdPolicy": {
      "type": "NONE|TYPE1|TYPE2",
      "effectiveFromField": "optional-field",
      "effectiveToField": "optional-field",
      "currentFlagField": "optional-field"
    },
    "reuseScope": "PLAN|DOMAIN|TENANT"
  }
}
```

- `TYPE2` 在进入实现前必须绑定生效起始、生效结束和当前标志字段；`NONE/TYPE1` 不接收这三个 TYPE2 专属引用。
- PlanningPolicy `historyPolicy` 只给创建表单提供默认建议；用户确认后 `scdPolicy` 随 ModelSpec revision 保存，计划策略变更不得静默改写已有模型。
- `sourceRefs` 是可追溯输入，`generationStrategy` 描述如何生成；两者同时存在时是组合语义，不存在优先级、覆盖或暗默舍弃。
- DRAFT 保存允许 `sourceRefs=[]` 且 `generationStrategy=null`；`IMPLEMENTATION_READY` 要求两者至少一个有效。
- Phase-B 不得原地收紧 `contractVersion=2`：历史空 description、重复 grain key 或 grain/KEY 未闭合必须继续可读、可重放；完成 snapshot、idempotency、checksum/ETag 兼容迁移后，才允许以新 contract version 或独立实现门禁强制。

### 四类“编码/键”语义

1. `dimensionCode`：维度目录中的稳定大写 ASCII 标识，匹配 `^[A-Z][A-Z0-9_]{0,63}$`，租户内大小写不敏感唯一且创建后不可变；用于定位 ModelSpec，不是数据行 JOIN 键。
2. 业务自然键：由 `grain.keys` 声明并引用 `fields.role=KEY` 字段，可以是组合键。
3. 代理键：是 SQL/dbt 实现产物中的物理键，不在概念维度中冒充业务自然键。
4. `standard_code`：是码表/标准模块持有的数据值归一码，模型通过 `standardBindings` 引用，不与 `dimensionCode` 合并。

## 输出产物

- `ModelSpec(modelType=DIMENSION)`；
- 维度字段/`dimensionProfile`/层级/SCD 策略；
- 可被 FACT/SUMMARY/APPLICATION 以 `modelSpecId + revision` 引用的维度 revision；
- 维度表实现候选。

## 详细设计

1. 新 `/modeling/dimensions` 查询 `modelType=DIMENSION` 的 ModelSpec。
2. 目录支持无 planId 浏览；新建时若无上下文，只弹一次计划和业务分类选择。
3. 从计划进入时锁定 planId，domainId 默认当前分类但允许在计划绑定范围内切换。
4. 概念维度保存为 DRAFT；`IMPLEMENTATION_READY` 再校验 KEY 字段闭合、SCD、层级和“来源/生成策略至少一个”，标准/质量/权限属于后续发布门禁。
5. 一致性维度通过复用同一 DIMENSION ModelSpec 表达，不另写总线矩阵；关系由 revision-pinned `dimensionRefs` 派生。同计划按可读 revision 复用，跨计划只允许引用已发布且当前用户有权访问的 revision；`reuseScope` 不放大权限。
6. 旧 ConformedDimensionCatalogCard 可抽取 UI，但数据源和保存接口必须替换，禁止继续以 sprint64 表为新真值。

## 异常、权限与恢复

- dimensionCode 冲突、层级成环、key 重复返回字段级错误。
- 来源失效不删除维度；实现门禁变 UNKNOWN 并给修复入口。
- 无编辑权限保持可浏览，隐藏/禁用新建。

## 实施与测试设计

1. 在增加 `dimensionProfile` 前先写 checksum/idempotency 兼容 RED：旧 v2 snapshot 可读、原 checksum/ETag 不漂移、同 key 重放返回原快照；不允许为了通过新契约而静默重算历史记录。
2. 写 DIMENSION 分阶段必填矩阵、无 process、dimensionCode、KEY 闭合、inclusive OR、SCD 和层级环测试。
3. 按 expand 方式同步 Java/TS/Schema/DB/snapshot codec；旧 snapshot 缺少 `dimensionProfile` 时只能投影为待完善，不伪造已完成门禁。
4. 建立列表、创建/详情表单和 blocker panel；API 只写 ModelSpec，不写 sprint64 维度真值。
5. 将旧 DIMENSION 对象映射到目录读模型，浏览器验证空态、无 plan、从计划返回和窄屏。

## 当前进展（2026-07-19，入口与维度草稿闭环）

- `/modeling/dimensions` 已直接读取 `modelType=DIMENSION` 的 canonical ModelSpec，与模型中心共用唯一数据源；登记维度不读取业务过程或业务对象 API。
- 规划详情“事实与维度”按“维度目录 → 模型中心”展示两个专业入口，并统一透传服务端计划 `planId`。
- portal menu 保留既有 role-bound key/titleKey，只把客户可见标题和 target 收敛为“维度目录”与“模型中心”；旧语义对象路由继续作为隐藏兼容入口，等待 F5 迁移。
- 新建 UI 以“维度名称 / 维度定义 / 每行代表什么 / 维度键”为主输入；概念维度允许暂不填写来源，保存后直接形成 DRAFT ModelSpec。
- 抽屉先校验当前可见字段，再读取包括折叠区默认值在内的完整表单状态；计划或业务分类加载期间禁止提交，分类加载失败会清空失效 domainId。
- 目录已区分真实空态、搜索无结果和加载失败；加载失败不显示伪空表，并提供局部重试。
- 详情只允许 DRAFT 编辑；PUBLISHED 和并发变为只读状态时保留输入并提供“加载最新状态”，返回目录使用服务端 ModelSpec 的 planId/domainId。
- 新 UI 要求维度定义，但没有破坏性收紧 contractVersion=2；历史空 description、重复 grain keys 与 grain/KEY 未闭合仍通过 Java/Schema/decoder 兼容回归。
- 前端契约、legacy production build 与真实 Chrome 95（桌面/390px）已通过，证据见 `it/evidence/frontend/dimension-draft-journey.txt`、`it/evidence/backend-contract/dimension-model-validation.txt` 和 `it/evidence/chrome95/README.md`。
- `dimensionProfile` 已进入 Java/TS/JSON Schema/快照/持久化唯一契约；`dimensionCode` 租户内大小写不敏感唯一、创建后不可变，历史 snapshot 缺字段时不伪造。
- 实现门禁已覆盖 grain/KEY 闭合、层级字段与环、SCD TYPE2 字段、reuseScope 以及 sourceRefs/generationStrategy inclusive OR；前端 blocker panel 只展示服务端判定。
- 真实联动验收通过登录、owner 权限、创建、CAS 更新、revision 快照和 r1→r2 门禁重算；测试夹具已按精确 UUID 清理。
