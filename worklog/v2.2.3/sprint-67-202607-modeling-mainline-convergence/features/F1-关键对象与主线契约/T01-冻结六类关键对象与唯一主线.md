# T01：冻结六类关键对象与唯一主线

**优先级**：P0
**状态**：DONE
**依赖**：无

## 目标与用户结果

让用户只需理解业务分类、分层、标准、维度、四类表和指标，并始终从建模工作台获得一个明确下一步。

## 范围与不做

- 范围：产品词表、页面主标题、菜单名称、表单标签、帮助文案、API 字段客户含义和主线顺序。
- 不做：本 Task 不实现页面、不修改数据库、不硬编码任何行业示例。

## 输入契约

| 输入 | 来源 | 采用规则 |
|---|---|---|
| Sprint-65 canonical 词表 | `assets/modeling-concept-canon.md` | 继承六类对象和退役词 |
| 当前模型类型 | `ModelingVNextContract.ModelType` | FACT/DIMENSION/SUMMARY/APPLICATION 对应四类表 |
| 当前计划主线 | WarehousePlan/StageProjection | 保留 planId 和九站证据，不新建状态源 |
| DataWorks 截图 | 用户提供 | 只提取对象模型，不复制品牌 UI 或电商示例 |

## 预期输出

- 一份机器可检查的客户词表；
- 业务分类 → 维度/四类表 → 标准/实现 → 指标的主线定义；
- 禁用词：业务对象、语义对象（仅迁移/兼容代码允许）；
- route/menu/page/API copy 的 source-contract 断言清单。

## 详细设计

1. UI 主称固定为“业务分类”；“数据域/主题域”仅在帮助文本说明同义，不创建新 ID。
2. 四类表客户名称固定为“明细表、维度表、汇总表、应用表”，内部枚举保持 FACT、DIMENSION、SUMMARY、APPLICATION。
3. “原始指标/二次指标”只在兼容数据中保留，UI 使用“原子指标/派生指标”。
4. 所有页面标题、菜单标题和空状态通过集中词表或 source-contract 测试守卫；迁移说明可出现退役词，但必须带“旧”或“兼容”语境。
5. StageProjection 仍是完成度唯一来源；词表不能携带完成状态。
