# T02：定义业务对象退役与信息归位

**优先级**：P0
**状态**：READY
**依赖**：F1-T01

## 目标与用户结果

删除业务对象作为独立登记步骤，同时保证其中有价值的维度键、粒度、来源、标准和模型关系不丢失。

## 范围与不做

- 范围：SemanticBusinessObject、Modeling BusinessObject、对象表映射及 objectId 消费者的处置规则。
- 不做：不把所有旧对象自动改成维度，不在本 Task 执行数据迁移。

## 输入契约

| 旧信息 | 识别信号 | 目标归属 |
|---|---|---|
| 稳定实体、主数据、参考枚举 | 当前 `objectKind=DIMENSION`，或 `ENTITY` 且有稳定键、无事实信号；MASTER/REFERENCE 仅作为旧元数据标签读取，不新增 ObjectKind 枚举 | DIMENSION ModelSpec |
| 事件、快照、事实锚 | FACT/EVENT/SNAPSHOT、粒度/时间字段 | FACT ModelSpec |
| 字段标准/码值 | standard binding/reference code | 标准模块引用 |
| 指标公式 | formula/metric binding | 指标模块 |
| 表/数据集/dbt 来源 | table mapping/source refs | ModelSpec.sourceRefs |
| 无法判定或混合职责 | 冲突信号 | 人工拆分清单 |

## 预期输出

- 字段级处置矩阵；
- 三轴迁移决策：识别类别 `DIMENSION_LIKE/FACT_LIKE/MIXED/ARCHIVE_CANDIDATE`、准备状态 `READY/NEEDS_CLASSIFICATION/NEEDS_TARGET/NEEDS_SPLIT/BLOCKED_BY_CONSUMERS`、可选处置动作 `AUTO_DIMENSION/AUTO_FACT_MERGE/MANUAL_SPLIT/ARCHIVE_ONLY`；
- legacyRef 和审计要求；
- 新写路径禁用 objectId 的验收规则。

## 详细设计

1. 业务对象不再有新的 CRUD、菜单或页面主动作。
2. DIMENSION 型旧对象转换为一个 ModelSpec，而不是先建内部对象再建维度表。
3. FACT 型旧对象只在能唯一对应模型时合并；不存在目标模型时创建 DRAFT FACT 候选，必须人工确认后才能实现。
4. 混合记录禁止系统自动猜测，避免把一个对象同时变成维度和事实真值。
5. 旧 ID 写入 `legacyRef`/迁移映射表，用于深链、运行、评审和产物追溯。
6. `objectId` 在新 DTO 中删除，在兼容 DTO 中只读且标记 deprecated；发布门禁不得再检查对象存在性。
7. 内部 `ModelEntity` 仅允许作为 ModelSpec 的可重建投影服务编译器/图查询；它没有用户 CRUD、菜单、独立生命周期或反向外键，删除投影后可从 ModelSpec 重建。
8. 准备状态不是处置动作：`NEEDS_CLASSIFICATION/NEEDS_TARGET/NEEDS_SPLIT/BLOCKED_BY_CONSUMERS` 不得产生可执行自动迁移；`ARCHIVE_ONLY` 只有消费者归零后才可执行。

## 异常、权限与回滚

- 冲突记录不得部分迁移；按租户和批次回滚。
- 无权访问目标 domain/model 的用户不能通过 legacyRef 得到更多信息。
- 回滚恢复旧只读读取，不恢复旧写入和双写。
