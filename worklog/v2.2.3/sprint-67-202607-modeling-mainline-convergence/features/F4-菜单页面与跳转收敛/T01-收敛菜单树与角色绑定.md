# T01：收敛菜单树与角色绑定

**优先级**：P0
**状态**：READY
**依赖**：F1、F3-T02、F3-T04

## 目标与用户结果

用户从菜单能够判断“先规划、再建模、后指标”，同时可直接进入专业目录浏览；菜单不再暴露业务对象和多套重复入口。

## 范围与不做

- 范围：portal menu seed、role defaults、现网菜单记录/可见性绑定、排序、标题和 target。
- 不做：不通过删除旧 menu ID 破坏客户角色绑定；不把阶段导航复制成菜单序号。

## 输入契约

目标菜单以 `assets/page-input-output-navigation-matrix.md` 第 3 节为准。保留现有数据建模父级和可复用菜单 ID；新增 target 必须先有真实路由和权限处理。

## 输出产物

- canonical 菜单树；
- old menu key → new title/target/status 映射；
- role visibility 迁移报告；
- source-contract 守卫。

## 详细设计

1. “主题域管理”对外改为“业务分类”，target 仍是 `/governance/subjects`。
2. `semantic-objects` 不再可见；若复用其 menu ID，必须改为维度目录且数据源已切到 DIMENSION ModelSpec，否则先标 deleted/redirect。
3. `semantic-models` 收敛为“模型中心” `/modeling/models`。
4. SQL 与 dbt 文件入口收敛为一个“高级建模（SQL/dbt）”，项目文件作为 Tab，不占一级菜单。
5. 指标只保留“指标工作台”；发布审核归模型中心/发布视图，不挂在指标下。
6. seed 更新必须使用迁移式 upsert，保留已有角色绑定；删除父子关系前先解析准确 ID。
7. 数据标准明确显示数据元、公共码表、命名词典三个现有入口；“度量单位”菜单记录可预置但保持不可见，只有 F6-T01 的 owner API、页面、权限和 Chrome 95 验收通过后才激活。

## 影响范围

- `source/dts-admin/.../portal-menu-seed.json`
- `source/dts-admin/.../role-menu-defaults.json`
- portal_menu/portal_menu_visibility seed/reconcile 服务
- `portalGoldenLineMenu.source-contract.test.ts`

## 异常、权限与回滚

- target 未注册时禁止切换默认菜单。
- 角色绑定差异不为零时停止删除并输出受影响角色。
- 回滚恢复旧 target/title，但不恢复业务对象写入口。

## 实施与测试设计

1. 导出现网 menu ID/父子/visibility 快照。
2. 先写 canonical 顺序、禁用词、唯一入口和 binding 保留测试。
3. 更新 seed/reconcile 并 dry-run 差异。
4. 在管理员、建模用户、只读用户三种角色下浏览验证。
