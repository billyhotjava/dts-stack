# T05：补齐建设规划台账与编辑归档

**优先级**：P0
**状态**：IN_PROGRESS
**依赖**：T01、T04、F4-T02、F4-T03、F4-T04

## 目标与用户结果

用户创建 WarehousePlan 后，可以在当前计划直接修改名称、目标、范围和责任信息，也可以在建设规划台账中搜索、查看、编辑和归档多个计划，不再依赖无法管理的下拉框。

## 问题来源

2026-07-21 人工测试发现：工作台只提供计划下拉、“新建规划”和“查看计划详情”；计划详情的计划头只读。canonical 后端已经提供 PATCH 与 archive，但前端 API、页面和菜单没有接入，因此当前主线不能恢复创建时的输入错误，也缺少跨计划生命周期管理。

## 范围与不做

### 范围

- 新增 canonical 建设规划台账 `/modeling/plans`；
- 工作台和计划详情增加可发现的“编辑规划”；
- 接通 WarehousePlan header PATCH 和 archive；
- 搜索、生命周期筛选、负责人筛选、查看、编辑、归档；
- 权限、生命周期、CAS 冲突、空态、失败态和 Chrome 95；
- 更新菜单、操作手册和 Sprint-67 最终验收状态。

### 不做

- 不复用或改写旧“项目空间管理”数据源；
- 不新增规划主表或第二套前端计划缓存；
- 不允许修改计划编码、开始方式、tenantId 或前端直接设置生命周期；
- 不提供永久删除、批量归档、复制计划、导入导出和归档恢复；
- 不复制规划基线或九站轨迹到台账。

## 详细设计

权威设计见 [建设规划台账与计划头编辑设计](../../assets/warehouse-plan-ledger-design.md)。实现必须满足：

1. 台账只消费 `/modeling/warehouse-plans`，不得调用旧 `/modeling/plans` 项目空间 API。
2. 工作台仍只呈现当前计划、九站证据和唯一下一步；“全部规划”是次级入口。
3. 台账默认隐藏 ARCHIVED，支持显式筛选；StageProjection 独立失败时保留计划行并显示证据未知。
4. 编辑抽屉由工作台和计划详情复用；成功后刷新 header，不改变当前 `planId`、Tab 或已加载证据。
5. 已发布/已归档计划不显示编辑动作；无权限用户只保留查看。
6. 更新必须携带 `If-Match: "plan-head:{version}"`；409 保留输入并提供重试/加载最新版两种选择。
7. 归档使用二次确认和同一 plan-head CAS；归档当前计划后返回台账，不自动替换为其他计划。
8. 页面最多一个主动作：“新建规划”；查看、编辑、归档均为行级或次级动作。
9. 列表、详情、projection 和 mutation 使用独立请求序列，迟到响应不得覆盖新选择或新版本。
10. 390px 下筛选与行操作可堆叠，页面不得产生 document/body 水平滚动。

## 权限、错误与恢复

- list/get 失败：已有数据保持，展示独立重试；初次失败显示错误态而不是空台账。
- PATCH 400：字段级提示并保留输入。
- PATCH/归档 403：切换为只读提示，不假装成功。
- PATCH/归档 404：提示计划已不可访问并返回台账。
- 409：显示服务端 currentVersion；编辑允许显式重试，归档必须重新确认。
- 归档成功：默认列表移除，已归档筛选可见；当前工作台 planId 清理后返回台账。
- 网络超时：保持表单和原 version，重试前先 GET 核对服务端状态。
