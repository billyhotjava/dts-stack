# T03：执行数据迁移与物理退出门槛

**优先级**：P0
**状态**：DONE
**依赖**：F5-T01、F5-T02、F3-T05

## 目标与用户结果

将可迁移业务对象和 semantic 模型安全归位，保证模型、JOIN、维度、指标、产物、运行和评审可追溯；满足证据后再删除旧结构。

## 范围与不做

- 范围：forward-only Liquibase、migration ledger、幂等 backfill、校验、冻结和 contract/drop。
- 不做：不修改已执行 changeset，不把 DROP 和不可验证 backfill 混成一个 changeset。

## 输入条件

- T01 dry-run 为 READY 且人工冲突已批准/隔离；
- T02 旧写冻结已启用；
- ModelSpec v2 和目标专业模块可写；
- 备份、租户批次和 rollback window 已确认。

## 输出产物

- `modeling_legacy_object_migration` 等迁移台账；
- 目标 ModelSpec/refs/revisions；
- 迁移前后 reconciliation；
- legacy read map；
- drop/no-drop 决策和回滚证据。

## 详细设计

1. EXPAND：添加 v2 nullable 字段、迁移台账、兼容索引；放宽 object_id 但暂不删除 FK/列。
2. MIGRATE：按租户批次幂等 upsert；旧 semantic DWS/ADS 映射 SUMMARY/APPLICATION，维度/指标变引用，artifact/run/review 关联目标模型。
3. JOIN 映射扩展 SourceRef，历史 revision 保留，新建 v2 revision，不原地改审计历史。
4. NEEDS_CLASSIFICATION 保持 LEGACY_READONLY，发布门禁为 DOMAIN_CLASSIFICATION_REQUIRED。
5. CONTRACT：前端/控制台/API/指标包零消费者、两版本零写、校验和通过、备份审批后，分 changeset 删除 FK/列/API/表。
6. semantic subject domain 最后删除；catalog domain 始终保留。

## 影响范围

- 新 Liquibase forward-only changelogs/master include
- modeling/semantic tables、model revisions、artifacts/runs/reviews
- migration service/resource/CLI 和 tests
- deployment runbook/rollback flags

## 异常、权限与回滚

- 单租户失败只回滚该批次；状态 FAILED，可从相同 batch ID 重跑。
- checksum 不一致立即停止 contract 阶段。
- 回滚读取兼容映射和旧快照，不删除已创建目标记录。

## 实施与测试设计

1. 空库升级、存量升级、重复升级、失败注入测试。
2. dry-run → migrate → dry-run 验证 pending 数归零/隔离。
3. 比较模型/映射/产物/运行/评审数量和 checksum。
4. 仅在退出条件满足的隔离库验证 drop；生产审批独立记录。
