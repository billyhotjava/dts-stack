Verified boundary
- DomainResolution describes only the catalog domain: AVAILABLE, MISSING, ARCHIVED, FORBIDDEN.
- BusinessActivityResolution independently describes only businessActivityRef with the same four states.
- Blank domainId emits only MODEL_DOMAIN_REQUIRED / domainId / ERROR.
- A nonblank domainId whose resolution is not AVAILABLE, including a null runtime value, emits
  MODEL_DOMAIN_UNAVAILABLE / domainId / ERROR.
- FACT accepts a blank businessActivityRef. A nonblank unavailable activity emits
  MODEL_BUSINESS_ACTIVITY_UNAVAILABLE / businessActivityRef / WARNING.
- DIMENSION, SUMMARY and APPLICATION reject a nonblank activity with
  MODEL_BUSINESS_ACTIVITY_NOT_ALLOWED / businessActivityRef / ERROR and do not add an activity availability warning.
- A domain ERROR and FACT activity WARNING can be returned together.
- Java and TypeScript expose the same five-input rule in this order:
  modelType, domainId, domainResolution, businessActivityRef, businessActivityResolution.
