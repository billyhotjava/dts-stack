# T04: 全阶段审计 event 接入 platform /internal/audit-events

**优先级**: P0
**状态**: READY
**依赖**: T01

## 目标

generate / validate / publish / rollback 四个高风险动作都向 platform 落审计事件，补齐 #3 的审计缺口（与 Sprint-36 机密级合规要求关联）。

## 技术设计

- `PlatformContractClient` 新增 `recordAuditEvent(AuditEventRequest)` → POST `/internal/audit-events`（契约已定义）。
- `MetricModelLifecycleService` 各阶段在状态落库后发审计：动作类型、modelId、actor、policySource/predicateHash、platform 引用、结果。
- 审计失败策略：发布类（publish/rollback）审计失败应阻断或显式告警（不静默吞），与 platform release gate 语义一致；查询类可降级记 warning。
- platform 端 `/internal/audit-events` 若未就绪，标注为联调依赖（F3-T03 收口），metrics 侧先实现调用与开关。

## 影响范围
- `PlatformContractClient`（新增审计调用）。
- `MetricModelLifecycleService`（各阶段埋点）。

## 验证
- [ ] 四个动作各产生一条审计调用（用 MockRestServiceServer 断言）。
- [ ] publish 审计失败时不静默成功。

## 完成标准
- [ ] 高风险动作审计链完整，可作为合规证据。
