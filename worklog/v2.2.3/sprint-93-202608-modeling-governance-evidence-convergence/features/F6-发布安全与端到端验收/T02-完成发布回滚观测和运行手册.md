# T02：完成发布、回滚、观测和运行手册

**优先级**：P0
**状态**：READY_FOR_REHEARSAL
**依赖**：F6/T01、发布窗口

## 目标

证明本 Sprint 可分阶段发布、可停止、可回滚、可告警，并把真实故障处理步骤固化为运行手册。

## 技术设计（Contract-first）

- **输入契约**：`assets/release-plan.md`、迁移 batchId、镜像 tag、feature flag、projection/outbox/quality/lineage 指标和日志字段。
- **输出契约**：更新后的 release plan/runbook；IT-12 `{releaseId,commit,image,migrationBatches,flags,startedAt,rolledBackAt,recoveredAt,actor,result}`。
- **发布顺序**：Expand migration → backend shadow writer/consumer → preview/backfill → frontend read switch → Chrome/API/DB 验收。
- **回滚顺序**：前端 → read switch → consumer → 本批 backfill；不回滚历史 candidate/run/observation。
- **观测**：覆盖率、pending age、sync failed、orphan ref、质量证据缺失、字段血缘缺口、统计差异。
- **错误路径**：回滚 drift 时 fail-closed 并转人工；告警无分类或日志缺 correlationId 视为 NO-GO。
- **复用点**：现有 health、audit、platform event、质量问题和 reconciliation API。

## UI 交互规格

无新运维页面要求；复用现有日志、质量问题和资产状态入口。若现有入口不足，先补深链/日志字段，不新增工作台。

## 影响范围

部署配置/feature flag（如实施需要）、审计字典、日志/指标、worklog 证据；变更前需单独影响分析和回滚审批。
