# T01：统一概览、目录、详情与模型工作台状态和深链

**优先级**：P1
**状态**：IMPLEMENTATION_COMPLETE / MODULE_VERIFIED / IT-09_PENDING
**依赖**：F1～F4、F0/T01 浏览器基线

## 目标

在不改变菜单结构的前提下，让用户从模型发布/物化一路进入资产治理详情，并在各页面得到相同状态解释。

## 技术设计（Contract-first）

- **输入契约**：assets-v2 list/overview/semantics、dataset governance-health、serving projection、quality evidence 和 lineage links。
- **输出契约**：兼容扩展 `AssetSummary {statusAxes,consumptionEligibility,eligibilityReasons,projectionUpdatedAt,modelRefs,servingSync}`；旧字段不删除。
- **查询策略**：后端按当前页 AssetKey 批量补齐语义，不允许浏览器逐行调用 semantics；一页额外查询 ≤2。
- **URL 状态**：目录继续消费 keyword/domain/type/layer/governance/page/size；新增 eligibility/servingStatus/qualityStatus 参数必须可复制、刷新、后退。
- **错误路径**：语义缺失显示“待登记/CONDITIONAL”；OM 失败显示技术同步异常；质量/血缘接口失败按区块降级，页面主体仍可用。
- **术语**：Catalog 页面统一“业务归属数据域”；只在建模应用层显示“应用主题域”。
- **复用点**：Sprint-88 组件、DataSearchPage Table、DatasetDetailSupportTabs、ModelingWorkbenchEditor、现有 routes/source-contract。

## UI 交互规格

```text
模型工作台
  [物化状态] [目录同步] [工程质量] [治理质量] [查看资产]
                                      │
                                      ▼
资产详情
  身份/五轴/消费资格 | 字段标准 | 模型与物化 | 血缘 | 质量问题 | 权限审计
```

操作走查：

1. 在模型列表打开已物化模型，查看同步和质量状态。
2. 点击“查看资产”，进入同 datasetId 的现有详情。
3. 从详情进入血缘、质量运行和技术元数据深链。
4. 回到目录，用消费资格/状态筛选并刷新，筛选保持。
5. 在 OM/质量/血缘分别失败时验证区块级错误态。
