# T01：接入生产资产观察并统一目录与统计事实

**优先级**：P0
**状态**：COMPLETE / IT-01-02-09_PASS
**依赖**：F0/T01 可并行，最终 IT 消费其样本

## 目标

首次物化或采集到稳定关系后，在同一事务/耐久事件链中写入唯一 AssetKey 的目录事实和语义投影，不依赖人工 POST observations。

## 技术设计（Contract-first）

- **输入契约**：模型侧 `{modelSpecId,modelRevision,implementationRevision,candidateId,candidateVersion,physicalAssetId,sourceId,schema,identifier,actualType,observedAt,evidenceChecksum}`；采集/dbt 侧消费 Sprint-89 的稳定 dataset/table locator 与 schema fingerprint。
- **转换契约**：构造既有 `ObservationCommand`；`assetType=DATASET`；relationType 仅 TABLE/VIEW/MATERIALIZED_VIEW；`evidenceChannel` 按 INGESTION_EVENT/DBT_SYNC/MATERIALIZATION_OBSERVATION；producer/evidence 均必填。
- **输出契约**：`ObservationResult(admitted,excluded,reasonCode,receipt)`；receipt 的 assetKey/resourceId/projectionVersion 可与 `catalog_dataset` 唯一对账。
- **数据流**：现有 publication/materialization/ingestion/dbt owner → 薄 adapter → `CatalogAssetRegistrationService.observe` → semantic store/stats；不把第二套状态写回 producer 表。
- **错误路径**：临时关系 excluded；缺 producer/evidence、未知层、身份冲突 rejected；观察失败不得把 publication/serving 标为成功；已登记相同证据幂等。
- **复用点**：账本 L01～L09、Sprint-89 来源契约、`CandidatePublicationRepository` 既有 dataset/field/lineage 登记。
- **实现守卫**：逐符号跑 GitNexus impact；若 `CandidatePublicationRepository` 为 HIGH/CRITICAL，先向用户报告并通过薄 adapter 减少改动面。

## UI 交互规格

无直接 UI 写操作。模型工作台物化完成后的“查看资产”只能在 receipt/servingRef 可解析时启用；失败显示结构化 reasonCode，不跳到空详情。

## 影响范围

`source/dts-platform` modeling/catalog adapter、`source/dts-ingestion` 观察 adapter（若 Sprint-89 已提供则仅接线）、对应单元/集成测试；不改菜单。
