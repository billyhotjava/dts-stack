# T01：建立三层生效视图与本地改写模型

**优先级**：P0  
**状态**：READY  
**依赖**：F1-T03

## 目标

把 DTS 基线、客户新增和客户对基线的改写分开持久化，并向消费者提供唯一生效视图。

## 技术设计

- Baseline 保存签名包正文及 revision。
- Customer Extension 保存客户独立记录。
- Local Override 只保存相对基线的字段差异和目标 revision。
- 查询服务投影 Effective View，并返回来源类型和差异摘要。
- 编辑基线记录时写 override，不直接篡改基线快照。

## 影响范围

- 术语、数据元、码表、单位持久化和查询
- 编辑 API/DTO
- 页面列表、详情和引用选择器

## 验证

- [ ] 三类记录分别创建、读取、编辑。
- [ ] 编辑基线只产生 override，原基线 checksum 不变。
- [ ] 模型/指标等下游读取生效值和稳定 owner ID。

## 完成标准

- [ ] 页面与 API 不再把“当前值”误认为“包原始值”。
- [ ] 移除本地改写可恢复到当前基线。
