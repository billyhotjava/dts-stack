# T03：建立记录级来源与基线版本模型

**优先级**：P0  
**状态**：READY  
**依赖**：T02

## 目标

让每条标准内容保存其包、版本、来源、基线 revision 和本地覆盖关系，为安全升级提供事实源。

## 技术设计

- 为术语、数据元、码表目录/码值和计量单位设计统一 provenance 关联或等价字段。
- 稳定记录键采用 `packageCode + entityType + originRecordKey`，不依赖数据库自增/UUID。
- `source_system` 保持业务来源含义，新增 `origin_source_ref/standard_no/edition`。
- 保存基线 checksum、revision、本地覆盖标志、弃用和替代关系。
- 提供 Liquibase 迁移、旧数据分类和幂等回填策略；旧客户记录默认为 CUSTOMER，不伪装为 DTS 基线。

## 影响范围

- dts-platform domain/repository/service/DTO
- Liquibase changelog
- 标准包 apply/rollback
- 术语、数据元、码表、计量单位查询

## 验证

- [ ] 旧数据迁移幂等，记录数和业务字段不变。
- [ ] 同一包记录升级保持稳定身份。
- [ ] 客户原有记录不会被错误标记为基线。

## 完成标准

- [ ] API 可返回记录来源、包版本、基线 revision 和覆盖状态。
- [ ] 后续三方 diff 不需要从审计日志反推旧基线。
