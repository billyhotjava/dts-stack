# T01: 治理中心首页重构

**状态**: DONE  
**优先级**: P0  
**涉及路由**: `/governance/subjects`, `/governance/standards/*`, `/governance/templates`, `/governance/rules`, `/governance/quality`, `/security/data-security`

## 目标

把治理中心从多个分散入口重构为“发布门禁中心”，让用户知道哪些数据可以发布、哪些被阻断、下一步如何修复。

## 按钮清单

| 按钮 | 类型 | 目标行为 |
|------|------|----------|
| 新建治理规则 | 主按钮 | 打开规则创建流程 |
| 运行质量检查 | 主按钮 | 对选中主题/资产运行质量检查 |
| 修复阻断项 | 主按钮 | 跳转阻断资产或待办 |
| 查看质量报告 | 次按钮 | 打开质量报告 |
| 配置分级分类 | 次按钮 | 跳转数据安全 |
| 停用规则 | 危险按钮 | 二次确认并展示影响资产 |

## 组件清单

- `GovernanceOverview`: 治理总览。
- `PublishGateSummary`: owner、分级、标准、质量、血缘、权限门禁状态。
- `GovernanceModuleCard`: 主题、标准、模板、规则、质量、分类。
- `QualityTrendChart`: 质量趋势。
- `BlockedAssetTable`: 被阻断资产清单。
- `RuleImpactDrawer`: 规则影响范围。

## 数据约束

- 阻断资产必须来自真实质量/治理结果。
- 发布门禁状态不能只前端推断；缺接口时标注后端依赖。

## 验收

- [x] 治理首页能解释当前发布门禁总体状态。
- [x] 质量失败能进入影响资产。
- [x] 停用规则前展示影响范围。
- [x] 治理入口文案面向客户，不暴露内部工程名。
