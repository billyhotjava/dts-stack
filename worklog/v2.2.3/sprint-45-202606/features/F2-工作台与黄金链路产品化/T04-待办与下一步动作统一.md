# T04: 待办与下一步动作统一

**状态**: DONE  
**优先级**: P0  
**涉及页面**: `/workbench/todo`, 工作台动作面板、治理/运维阻断项

## 目标

统一“阻断项、审批、异常、提醒”的动作模型，让工作台和待办中心展示同一类下一步动作。

## 按钮清单

| 按钮 | 类型 | 目标行为 |
|------|------|----------|
| 立即处理 | 主按钮 | 跳转目标对象 |
| 指派给我 | 次按钮 | 领取待办或标记负责人 |
| 创建待办 | 次按钮 | 从告警/质量失败创建待办 |
| 标记完成 | 次按钮 | 完成非系统阻断待办 |
| 忽略提醒 | 危险按钮 | 二次确认后忽略提醒 |

## 组件清单

- `ActionItem`: 标准动作对象。
- `ActionItemList`: 工作台/待办中心共用列表。
- `ActionReason`: 展示阻断原因。
- `AssigneePicker`: 指派责任人。
- `ActionAuditTimeline`: 动作处理记录。

## 数据约束

- 动作对象需要统一字段：`id`、`type`、`severity`、`title`、`reason`、`targetRoute`、`assignee`、`status`。
- 如果没有后端动作 API，先只读展示真实阻断项，不允许伪造完成状态。

## 验收

- [x] 工作台阻断项和待办中心展示一致。
- [x] “立即处理”能进入目标对象。
- [x] 无法处理的动作展示原因，不显示可点击假按钮。
- [x] 操作后审计或状态更新路径明确。
