# T02: 工作台待办入口修复

**状态**: DONE  
**优先级**: P0  
**涉及路由**: `/workbench/todo`

## 目标

让工作台菜单中的“待办事项”进入真实页面，承接治理阻断、发布门禁、权限审批、任务异常和客户验收待处理项。

## 按钮清单

| 按钮 | 类型 | 目标行为 |
|------|------|----------|
| 处理 | 主按钮 | 进入待办关联对象，例如资产、质量报告、审批单、任务实例 |
| 刷新 | 次按钮 | 重新拉取待办列表 |
| 返回工作台 | 次按钮 | 跳回 `/workbench/data-management` |
| 标记已读 | 次按钮 | 本地或接口更新待办阅读状态 |
| 跳过/忽略 | 危险/谨慎按钮 | 二次确认后忽略非阻断提醒 |

## 组件清单

- `WorkflowCenterPage`: 页面主体。
- `TodoList`: 按阻断、审批、异常、提醒分类。
- `TodoFilterTabs`: 全部、阻断项、审批、运维、治理。
- `TodoDetailDrawer`: 显示关联对象、原因、下一步。
- `EmptyState`: 无待办时展示“查看数据管理工作台”。
- `ErrorState`: 拉取失败时展示重试。

## 数据约束

- 优先接入现有待办/工作流接口；若接口未具备，页面必须展示真实空态和后端 blocker，不允许静态假待办。
- 待办项必须携带 `targetType`、`targetId`、`targetRoute` 或明确不可跳转原因。

## 验收

- [x] 菜单点击 `/workbench/todo` 不 404。
- [x] 无数据时展示空态和返回工作台按钮。
- [x] 有待办时“处理”能跳转到真实对象页面。
- [x] 接口失败时展示错误状态和重试按钮。
