# 低代码 ELT 与指标设计边界

## 一句话原则

低代码开发不是让业务用户手工创建数仓分层表，而是让用户用业务语言表达“我要什么指标和消费结果”，由平台把这个意图编译成 DWD 草案、DWS/ADS 候选、指标草案、发布审核和运行证据。

## 分层职责

| 层级 | 产品定位 | 低代码可做 | 需要专业处理 | 默认展示策略 |
|------|----------|------------|--------------|--------------|
| 数据源 | 连接外部系统或文件 | 发起接入需求、选择已授权数据源 | JDBC/API/文件配置、账号、网络、增量策略 | 展示“数据来源”和“接入状态” |
| ODS | 原始入湖层 | 查看是否已同步、提交同步需求 | 入湖任务配置、错误排查、Schema drift | 不作为低代码建模输入展示 |
| DWD | 明细事实和维度层 | 确认业务对象、字段含义、主键、时间字段、敏感字段 | 标准码、统一口径、跨表关联、发布 | 展示为“已治理明细模型”或“待确认明细草案” |
| DWS | 主题汇总层 | 选择指标、维度、粒度、周期 | 复杂 Join、性能优化、异常口径审核 | 作为低代码主要生成目标 |
| ADS | 消费应用层 | 选择报表、大屏、API、数据产品输出 | 权限、发布审核、服务 SLA | 作为报表数据集和服务输出目标 |

## 现有页面关系

| 工作环节 | 应复用或联动页面 | 说明 |
|----------|------------------|------|
| 新手总入口 | `/workbench?section=data-management&journey=first-report` | 保留首张报表旅程，作为低代码向导的全局入口之一 |
| 数据开发入口 | 新增或改造数据开发下低代码入口 | 作为 ELT 区域入口，不能只停留在工作台 |
| 数据源和接入 | `/foundation/data-sources`、入湖任务创建页 | 低代码页只发起或跳转，不复制连接器配置 |
| 数据资产确认 | `/catalog/assets`、`/catalog/datasets/:id` | 字段、负责人、密级、主题域、标准映射从资产事实读取 |
| 指标设计 | `/modeling/metric-workbench`、指标管理、模型管理 | 低代码向导必须能带上下文进入指标工作台 |
| DWS/ADS 模型 | 模型管理、发布审核 | DWS/ADS 由指标和消费目标驱动生成和审核 |
| 任务运行 | 任务运维中心、任务编排 | 运行实例、日志、重跑、补数统一进入运维视角 |

## 用户旅程

```text
选择业务目标
  -> 选择已有业务表或提交接入需求
  -> 确认业务对象和字段含义
  -> 定义指标、维度、粒度和筛选条件
  -> 生成 DWS/ADS 候选和报表数据集草案
  -> 通过治理/权限/质量审核
  -> 发布到报表、大屏、API 或数据产品
  -> 查看运行证据和问题处理入口
```

## 不能割裂的三条线

1. **ELT 线**: 数据源、入湖、DWD 草案、DWS/ADS 候选、任务运行必须在向导中可追踪。
2. **指标线**: 业务对象、指标、维度、粒度、口径、发布状态必须和指标工作台共享概念。
3. **治理线**: owner、密级、主题域、标准码、质量门禁和权限审核必须在发布前显式提示。

## 决策

- 低代码入口必须落在数据开发的信息架构里，但不要替代 SQL/脚本/dbt。
- 指标设计不是低代码向导的“下一站链接”，而是向导的核心步骤。
- DWD 由专业用户负责最终发布；低代码只生成草案、建议和待办。
- DWS/ADS 可以由低代码生成候选，但必须经过发布审核和质量门禁。
- 报表数据集、指标入口、API、数据产品消费必须从治理后的 DWS/ADS 开始。
