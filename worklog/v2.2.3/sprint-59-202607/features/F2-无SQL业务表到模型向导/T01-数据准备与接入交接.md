# T01: 数据准备与接入交接

**优先级**: P0
**状态**: DONE
**依赖**: F1-T03

## 目标

让低代码用户从“已有业务表”或“需要接入业务表”开始，并清楚知道自己能继续操作还是需要数据工程师处理。

## 技术设计

- 提供两个入口：
  - 选择已治理或已采集的数据表。
  - 发起新业务表接入需求并跳转到数据源/入湖任务页面。
- 对数据准备状态做归一化：
  - `ready`: 可继续确认业务对象。
  - `needs_ingestion`: 需要配置或运行接入任务。
  - `failed`: 接入失败，进入运行或错误详情。
  - `no_permission`: 无权限，进入授权申请。
- 页面不直接要求填写 JDBC、Reader、Writer、DAG。

## 影响范围

- 低代码向导页面
- 数据源入口
- 入湖任务创建或详情入口
- 资产列表或数据集详情入口

## 验证

- [x] 无数据源时显示接入需求入口。
- [x] 已有表时可进入字段确认。
- [x] 接入失败时可跳转到任务详情或运维入口。
- [x] 文案不把技术配置交给普通用户。

## 完成标准

- [x] 用户知道下一步是自助继续、申请权限还是交给工程师。
