# T03: DWD 草案边界与工程审核

**优先级**: P0
**状态**: DONE
**依赖**: T02

## 目标

把低代码流程中的 DWD 定位为“明细模型草案和审核事项”，避免让无 SQL 用户直接创建或发布基础层物理表。

## 技术设计

- 向导可生成 DWD 草案摘要：
  - 业务对象。
  - 字段映射建议。
  - 主键、时间字段、标准码、敏感字段。
  - 质量和治理缺口。
- 草案状态分为：
  - `draft_ready`: 可提交工程审核。
  - `missing_required_metadata`: 缺关键字段或治理信息。
  - `engineering_required`: 需要工程师处理跨表关联、复杂口径或性能问题。
- 低代码页面提供“提交工程审核”“进入高级 SQL 建模”“查看资产详情”动作。

## 影响范围

- 低代码向导页面
- SQL 建模入口
- 资产治理页面
- 发布审核入口

## 验证

- [x] 普通用户路径没有“直接发布 DWD”按钮。
- [x] DWD 草案能解释为什么需要工程审核。
- [x] 高级模式入口保留，但不是主按钮。

## 完成标准

- [x] DWD 边界清楚，低代码流程不会破坏基础层治理。
