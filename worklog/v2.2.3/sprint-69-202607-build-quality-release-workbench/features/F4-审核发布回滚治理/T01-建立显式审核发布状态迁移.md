# T01：建立显式审核发布状态迁移

**优先级**：P0
**状态**：READY
**依赖**：F2-T04、F3-T04

## 目标

拆开提交审核、批准/拒绝和发布命令，禁止 build 成功后由 SQL 页面连续自动完成审核与发布。

## 技术设计

- `QUALITY_PASSED → REVIEW_PENDING → APPROVED/REJECTED → PUBLISHING`。
- 每个命令复验 candidate ETag、版本锁、build 和 quality 新鲜度。
- REJECTED 必须有原因，修复后产生新 revision/run 并重新提交。
- 命令与事件一一对应，不允许客户端直接写状态。

## 影响范围

- `ModelLifecycleService.java`
- `ModelLifecyclePublicationService.java`
- `ModelLifecycleResource.java`
- lifecycle state/security tests

## 实施步骤

1. 先写自动连跳、旧证据提交和非法迁移失败测试。
2. 实现显式 commands、events 和允许动作投影。
3. 移除 SQL 页自动 approve/publish 依赖前先保持兼容告警。

## 完成标准

- [ ] build/quality 成功后页面只出现“提交审核”，不会自动批准或发布。
- [ ] 拒绝、修复、重提及并发提交具有完整审计。
- [ ] **UI 契约验收**：审核面板按 QUALITY_PASSED、REVIEW_PENDING、APPROVED 分步显示唯一主动作，任何状态都不得同时出现提交、批准和发布三个动作。
