# T01：拆分静态编译产物和外部构建证据

**优先级**：P0
**状态**：READY
**依赖**：F1-T04

## 目标

区分“生成过文件”和“真实构建成功”，让 SQL、schema、test、doc artifact 与外部 compile/build/test run 分别留证。

## 技术设计

- artifact 记录类型、路径、checksum、generatorVersion、model revision 和生成时间。
- build run 记录 adapter、command、selector、target、invocationId、起止时间、终态和日志引用。
- 禁止用 artifact SUCCESS 推导 build SUCCESS。
- 大日志和 manifest 通过受控对象引用保存，不写入生命周期事件正文。

## 影响范围

- `ModelLifecycleContract.java`
- `ModelLifecycleService.java`
- `CanonicalModelLifecycleCompilerAdapter.java`
- 对应 contract/adapter 测试

## 实施步骤

1. 先写 artifact 成功但 run 缺失时门禁失败的测试。
2. 拆分证据结构与保存端口，保留旧证据只读兼容。
3. 编写 lifecycle/compiler 测试源码并完成静态审查；运行验证留到 F6 单一整体测试窗口。

## 完成标准

- [ ] UI 和门禁均能独立展示/判断 artifact 与真实 run。
- [ ] 历史混合证据不会被误判为新契约下的构建成功。
- [ ] **UI 契约验收**：构建证据面板可将 artifact 与 dbt run 分栏展示，并覆盖“文件已生成但 run 缺失/运行中/失败”的非成功状态。
