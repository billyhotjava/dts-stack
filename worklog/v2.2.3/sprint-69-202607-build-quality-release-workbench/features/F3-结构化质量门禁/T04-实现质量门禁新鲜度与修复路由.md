# T04：实现质量门禁新鲜度与修复路由

**优先级**：P0
**状态**：READY
**依赖**：T03

## 目标

按严重度、阈值、新鲜度和版本一致性计算质量门禁，并为失败规则提供精确修复与重跑路径。

## 技术设计

- BLOCKER/ERROR 阻断；WARNING 按计划策略显示但不默认伪装通过。
- revision、checksum、rulePackVersion 或 snapshot 超期使旧结果失效。
- 阻塞原因包含 model、rule、expected/actual、sample summary 和 remediation route。
- 仅重跑受影响模型/规则，保留历史 run。

## 影响范围

- `ModelSpecStageGateService.java`
- quality gate service
- `WarehousePlanDownstreamEvidenceAdapter.java`
- quality gate/unit tests

## 实施步骤

1. 先写严重度、阈值、超期、漂移和部分重跑测试。
2. 实现确定性 gate evaluator 和修复路由。
3. 验证 StageProjection 只消费结构化聚合结论。

## 完成标准

- [ ] 门禁理由对业务用户可解释，对测试可确定复现。
- [ ] 修复或规则变更后必须产生新鲜运行才能继续审核。
- [ ] **UI 契约验收**：质量 Banner 展示过期/漂移原因、失败规则、expected/actual 和精确重跑动作；WARNING 与阻断失败必须视觉和文字可区分。
