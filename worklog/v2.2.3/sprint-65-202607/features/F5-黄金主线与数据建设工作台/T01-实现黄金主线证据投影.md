# T01：实现黄金主线证据投影

- **状态**：IN_PROGRESS
- **优先级**：P0
- **依赖**：F2-T03、F3-T04
- **影响模块**：dts-platform query/application、跨模块 client、缓存

## 目标

按 `planId` 聚合连接、来源、规划、标准、模型、构建、资产、指标、服务和运行的真实证据，计算当前阶段、阻塞和新鲜度。

## 实施内容

1. 为九个黄金主线阶段定义证据提供者、完成规则和失败规则。
2. 计算 `StageProjection`、`primaryBlocker`、`nextAction` 和 evidence freshness。
3. 跨模块读取使用超时、降级和 correlationId，不把异常当空数据。
4. 通过事件或短 TTL 失效刷新投影，关键发布门禁使用实时查询。
5. 保存必要的证据摘要与原始引用，不复制专业对象正文。
6. 定义九站 `StageCode` 到 `/workbench` 八阶段展示组的唯一映射 DTO；展示组只聚合状态、阻塞与动作，不产生第二套状态。

## 验收标准

- 相同后台事实产生确定的阶段状态；
- UNKNOWN/STALE 不会计算为 COMPLETE；
- 当前阻塞选择规则稳定且客户可理解；
- 下游模块故障不阻止查看其他阶段；
- 投影查询满足性能预算并有可观测指标。
- 九站投影到八阶段总览的映射确定、可测试，任一 UNKNOWN/STALE 不会在分组后变为完成。

## 验证证据

- 每阶段完成/阻塞参数化测试；
- 超时和降级集成测试；
- 缓存失效/实时门禁测试；
- 性能和调用链记录。
