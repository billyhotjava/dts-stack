# T03：建立受控退役与回滚机制

- **状态**：READY
- **优先级**：P0
- **依赖**：T01、T02
- **影响模块**：菜单、路由、前端状态、旧 API、旧表、审计

## 目标

为每个旧资产建立 INVENTORY -> COMPATIBLE -> FROZEN -> REMOVAL_CANDIDATE -> RETIRED 的生命周期，并支持可观测、可回滚的切换。

## 实施内容

1. 落实受控退役登记表的所有者、替代物、默认 Flag、回滚时限和退出条件。
2. 为旧路由/API/入口增加调用审计，不采集敏感参数。
3. 设计服务端和前端 Feature Flag，明确新老读取、写入和 redirect 行为。
4. 定义紧急回滚：恢复旧入口和读取，保留新聚合已写数据。
5. 增加移除审批门禁：两个版本周期零调用、迁移核对、权限回归和备份确认。

## 验收标准

- 没有“直接删除”状态转换；
- Flag 的默认值、作用域和回滚责任人明确；
- 新写入开启后旧写入口不可产生分叉；
- 回滚演练不会丢失 canonical 新数据；
- 每个退役候选有真实调用统计和验收证据。

## 验证证据

- Flag 矩阵；
- 调用审计样例；
- 回滚演练记录；
- 退役审批模板。
