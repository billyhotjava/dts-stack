# T01：统一概念与数据所有权

- **状态**：READY
- **优先级**：P0
- **依赖**：无
- **影响模块**：dts-platform、dts-platform-webapp、规划/标准/模型/资产/指标边界

## 目标

形成一份代码、API、数据库和 UI 共用的中性术语与所有权合同，消除“规划方法、模型设计、实现工具”混层。

## 实施内容

1. 建立术语表：WarehousePlan、PlanningBaseline、DomainBinding、ProcessBinding、SourceBinding、ModelSpec、ImplementationArtifact、StageEvidence。
2. 明确经典维度数仓为默认规划方法，关系模型为设计视图，dbt 为实现方式。
3. 为连接、标准、模型、dbt 产物、资产、指标和运行指定唯一写所有者。
4. 盘点核心枚举和前端文案，标记 `DBT_NATIVE` 等混层概念的兼容映射。
5. 增加架构约束测试或静态检查，阻止 PJM/行业专属词进入核心 DTO、表和流程枚举。

## 验收标准

- 所有新 Feature 引用同一术语，不自行定义同义对象；
- 所有权矩阵没有双写事实源；
- dbt 不出现在规划阶段枚举中；
- 行业示例只能位于 fixture/template/example；
- 评审记录明确旧术语的替代物与兼容期。

## 验证证据

- 术语/所有权评审记录；
- 枚举和文案扫描结果；
- 架构约束测试结果；
- GitNexus impact 记录。
