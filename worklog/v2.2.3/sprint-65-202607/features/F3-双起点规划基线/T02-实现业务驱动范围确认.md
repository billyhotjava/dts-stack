# T02：实现业务驱动范围确认

- **状态**：READY
- **优先级**：P0
- **依赖**：T01
- **影响模块**：规划基线 UI/API、主题域/过程引用、指标需求草案

## 目标

让业务驱动用户先确认目标、范围、责任人、主题域、业务过程、对象和指标需求，同时保持行业中立。

## 实施内容

1. 业务范围 Tab 编辑目标、范围、负责人和责任部门。
2. 从现有主题域/过程服务选择或创建候选绑定，不复制治理对象正文。
3. 过程可选事务、周期快照、累积快照形态，作为事实设计推荐输入。
4. 业务对象性质和指标需求使用候选状态，后续由模型/指标专业模块落地。
5. 提供逐项保存、版本冲突和未保存离开保护。

## 验收标准

- 不要求所有业务过程都是电商事务事件；
- 行业样例不改变字段、枚举或页面结构；
- 业务对象和指标需求不会提前生成物理表或正式指标；
- 未确认项不计入 baseline READY；
- 同一用户兼具治理和建模职责时无需切换控制台。

## 验证证据

- 事务/周期/累积快照通用夹具；
- 候选与确认 API 测试；
- 并发和离开保护 UI 测试；
- 无行业硬编码扫描。
