# T01: 存量 tags 文本迁移工具

**优先级**: P2
**状态**: READY
**依赖**: F2/T02

## 目标

把存量 `CatalogDataset.tags` 自由文本解析为结构化标签并建立打标关系，全程可预览、可回滚。

## 技术设计

### 迁移逻辑

新建 `service/catalog/CatalogTagMigrationService.java`：

1. 扫描全部 `CatalogDataset.tags` 非空记录
2. 按分隔符拆分（需先探查现网真实分隔符，可能是逗号/分号/空格混用，**不要假设**）
3. 逐个文本值匹配已有标签 `name`：
   - 精确命中 → 建立打标关系
   - 未命中 → 归入「待处理」清单，**不自动创建标签**（避免脏文本污染标签库）
4. 产出迁移报告：命中数 / 未命中清单 / 建立关系数

### dry-run 优先

必须先提供 `dryRun=true` 模式，只产报告不写库。运维确认报告后再执行实际迁移。
未命中的文本值由治理人员决定是新建标签还是丢弃，不由程序代劳。

### 回滚

迁移批次打标记（如迁移批次号写入 `catalog_asset_tag` 或独立记录表），
支持按批次撤销全部由该次迁移创建的打标关系。
**存量 `tags` 字段全程不被修改**，因此回滚不涉及数据恢复。

### 执行入口

提供受限的运维端点或管理命令，非普通用户可触发。迁移动作须审计。

## 影响范围

- 新增 `.../service/catalog/CatalogTagMigrationService.java`
- 新增迁移执行入口（运维端点或 CLI）
- **不修改** `CatalogDataset.tags` 字段与既有消费方
  （`CatalogMetadataService:191/238/253` 透传逻辑保持不变）

## 前置探查

实施第一步须先在现网库执行一次统计，确认：
- `tags` 非空记录数量级
- 实际使用的分隔符
- 去重后的不同文本值总数

探查结果写入 `assets/`，作为迁移策略的依据。不做探查直接写解析逻辑属于凭空假设。
