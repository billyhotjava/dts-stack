# T03: 预置常用标签库（标准内容库管道）

**优先级**: P1
**状态**: READY
**依赖**: T02

## 目标

交付协议要求的「预置常用标签」，走 Sprint-68 标准内容库管道实现可版本化、可安全升级，且不覆盖客户本地自定义标签。

## 技术设计

### 为什么不用硬编码 seed

若用 `DevDataSeeder` 式硬编码插入，升级时会与客户已改名/已停用的标签冲突，且无法追溯版本。
Sprint-68 已建立标准内容库的版本化安装管道（`worklog/v2.2.3/sprint-68-202607-standard-content-library/`），
标签预置包复用该管道，实施前需先读该 sprint 的包格式与安装契约。

### 预置内容（建议基线）

分类树按数据治理通用维度设计，具体条目在实施时与业务确认：

| 分类 | 示例标签 |
|------|----------|
| 业务域 | 财务、人力、采购、生产、销售 |
| 数据质量 | 高可信、待核验、存在缺失 |
| 更新频率 | 实时、日更、周更、月更 |
| 使用场景 | 报表分析、对外服务、内部管理 |
| 管理属性 | 核心资产、临时数据、待归档 |

**明确排除**：任何密级/涉密相关标签。密级由 `classification` 字段与 `SecurityLevelCatalog` 独立承载，
标签体系混入密级语义会污染合规判定面（见 Sprint README 设计决策表）。

### 升级安全性

- 预置标签 `builtin=true`，以 `code` 为幂等键
- 安装/升级时：`code` 已存在则跳过（不覆盖客户改动），不存在则插入
- 客户停用的预置标签，升级不得重新启用
- 安装结果产出报告：新增数 / 跳过数 / 冲突项

## 影响范围

- 新增预置标签包内容文件（格式遵循 Sprint-68 标准内容库约定）
- 新增 `.../service/catalog/CatalogTagSeedService.java` 或复用标准内容库既有安装器
- 依赖 T02 的 `CatalogTagService`
