# T02：冻结关键数据模型关系与端到端契约

**优先级**：P0

**状态**：DONE

**依赖**：F1/T01、[`assets/data-model-relationships.md`](../../assets/data-model-relationships.md)

## 目标

把架构字典、数仓计划、模型修订、发布候选、物化证据、资产、指标、质量和后续业务主数据连接为一条可追溯关系链，使后续实现不会只完成单页或单表而断开上下游。

## 输入/输出契约

- 输入：统一语言与 owner、现有 Liquibase 关系、ModelSpec/ReleaseCandidate/物化控制面、CatalogAssetKey、指标与质量绑定事实。
- 输出：关系基数矩阵；稳定引用/版本规则；状态传播规则；E2E-A～D；IT-03 验收矩阵；关系缺口与 ADR owner。评审输入见 [`assets/f1-t02-decision-pack.md`](../../assets/f1-t02-decision-pack.md) 与 [`assets/consolidated-approval-pack.md`](../../assets/consolidated-approval-pack.md)。
- 错误路径：目标关系与当前 schema 不一致却未登记迁移、同一状态被跨聚合复用、名称代替 ID、逻辑模型被当作物理表时，Task 保持 DRAFT。
- 非目标：不在本 Task 设计具体表结构，不创建通用 MDM，不授权修改运行数据。

- [x] ADR-86-13/14/15 的候选、反例、兼容影响和评审 owner 已登记
- [x] NFR-86-04～08/12 的容量、幂等、超时、审计、并发和事务问题已进入评审输入

## 评审重点

1. 业务分类→数据域→业务过程、业务分类→数据集市→主题域两条业务链是否在所有模型类型中一致。
2. 数仓计划是建设范围而非架构字典，ModelSpec 上下文必须包含于计划已确认基线。
3. ModelSpec head、不可变 Revision、ReleaseCandidate entry、物化 observation 和 CatalogAsset 身份不能跳级或混用状态。
4. 维度定义→维度表→事实表→汇总表→应用表形成有向无环依赖；批量与二次物化保留依赖闭包、attempt 和历史 observation。
   **（RF-86-10）批量候选的原子失败/显式排除策略在本 Task 冻结**，不下放 F4/F5：部分失败若允许继续，依赖闭包可能不完整，不变量 9 的 DAG 约束即无法保证。F4 只负责该策略的交互呈现与失败可见性。
5. 指标引用业务上下文和版本化来源，质量引用规则版本和物理资产。
6. 业务主数据与架构元数据、分析维度之间只有引用/投影关系，没有重叠 owner。
