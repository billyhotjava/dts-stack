# T01：冻结统一语言与权威归属

**优先级**：P0
**状态**：DRAFT
**依赖**：[`assets/domain-profile.md`](../../assets/domain-profile.md)

## 目标

产出一份经评审的统一语言与 owner 矩阵，使任何实施人员无需重新判断“域、分层、集市、主题域属于哪个模块”，也不会把架构字典误称为业务主数据。

## 输入/输出契约

- 输入：账本 L01～L04、现有规划关系、用户确认的平台全局范围。
- 输出：正式 ADR；owner/consumer 矩阵；术语迁移表；数据架构元数据与业务主数据边界。实体关系与端到端契约由 T02 承接。
- 错误路径：存在同一实体两个写 owner、同一术语两个实体或核心关系未决时，Task 保持 DRAFT。
- 复用点：`catalog_domain`、现有业务过程/分层/集市/主题域台账；禁止新建平行实体。

## 验证

- [ ] 每个实体恰好一个写 owner
- [ ] 每个消费模块只依赖稳定 ID/只读投影
- [ ] “业务主题域”等冲突术语有明确迁移映射
- [ ] “数据架构元数据/架构字典”与“业务主数据（MDM）”不再混称
- [ ] 权限、审计、平台全局作用域均有明确规则
- [ ] **（RF-86-09）** 每个写 owner 的**强制手段**已明确，不只停留在文档约定：现有粒度仅 read/write/export，无法按实体类型区分写权限，I07 运行时不可强制。ADR-86-17 须给出机制（服务层 port 收口 / 独立角色 / 审计后置检测），或显式接受约定级并记为具名风险

## Definition of Done

- [ ] ADR 经用户/架构评审确认（状态达到 `ACCEPTED`，词汇口径见 `decision-register.md` 状态词汇表）
- [ ] ADR-86-17 形成结论；ADR-86-08 不得在其之前冻结
- [ ] 未决项关闭或转为具名风险
- [ ] T02 可直接引用本 Task 产物冻结关系；F2～F4 不再重复定义 owner
