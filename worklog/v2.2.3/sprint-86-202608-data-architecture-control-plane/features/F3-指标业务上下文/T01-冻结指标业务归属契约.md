# T01：冻结指标业务归属契约

**优先级**：P1
**状态**：DONE
**依赖**：F1/T01、F1/T02

## 目标

形成可由指标创建、模板、版本、派生校验、发布和 dbt 生成共同消费的业务上下文契约。

## 输入/输出契约

- 输入：账本 L10/L13/L20、用户“category 应是业务分类”的确认、既有指标生命周期、F1/T02 关系/状态传播规则。
- 输出：字段/DTO 候选；ATOMIC/DERIVED/COMPOSITE 必填矩阵；继承与跨域校验；不可变来源模型/资产引用；旧字段迁移契约。完整候选见 [`assets/f2-f3-data-contract-pack.md`](../../assets/f2-f3-data-contract-pack.md)。
- 错误路径：分类与数据域父子不一致、业务过程不属于数据域、派生来源跨分类、旧文本无法回填时的阻断/待治理规则。
- 复用点：GovIndicatorDefinition、version/reference、IndicatorService 及现有发布控制面；不新建第二套指标表。

## Definition of Ready

- [x] F1 的业务分类/数据域/业务过程稳定身份和状态规则可供消费
- [x] `GovIndicatorDefinition` 当前字段和 HIGH 风险消费者清单已作为输入，不需要重复扫描
- [x] 单/多分类、三类指标必填/继承、跨分类与回填失败均有候选和反例
- [x] IT-04 已登记指标 canonical owner、数据架构 owner 和真实评审日期
- [x] 评审输出写回 ADR-86-06/07 与下一实施测试矩阵的位置已明确

## 风险

GitNexus 当前结果为 HIGH（18 个直接消费者）。任何实施必须先补兼容字段和 mapper/版本快照，再迁移 UI 与写入链，最后才允许收缩旧字段。
