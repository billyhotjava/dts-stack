# T01: 覆盖两种实现方式的统一物化发布链

**优先级**: P0
**状态**: BLOCKED
**依赖**: F2、F3、F4 完成

## 目标

用同一套 release candidate 契约分别验证 DESIGNER_GENERATED 和 DBT_MANAGED，实现方式只影响制品来源，不影响候选状态机与发布资产登记。

## 技术设计 (Contract-first)

- **输入契约**: F0 三个 E2E 模型；各自 current model/implementation revision/checksum；三个不同 actor 分别承担 maintainer/reviewer/operator duty。
- **输出契约**: 三个独立 candidate 均从 DRAFT 经既有动作到 PUBLISHED；entry 钉住正确 implementation id/mode/revision/checksum。
- **数据流**:
  - DESIGNER：保存可视化实现 → compiler 生成 artifacts → candidate → materialization → quality/review/publish；
  - DBT（原生）：draft commit SQL/SCHEMA → candidate → 同一 materialization/quality/review/publish；
  - **DBT（接管而来）：F2 接管 → compile → candidate → 同一链路**。这条是本 Sprint 新增风险的唯一出口，不可省略——它验证接管产出的 `{SQL,SCHEMA,CONFIG}` 制品确实能走完发布链。
- **错误路径**: ownership transition 后旧 candidate 必须 STALE 或被稳定冲突拒绝；发布失败使用 retry/rollback，不重写实现；候选不得引用旧 implementation checksum。

  > **已核实契约**：候选 scope 锁定 model revision/checksum/implementation mode；任一漂移在后续命令时转为 `STALE`，稳定码为 `MODEL_RELEASE_CANDIDATE_STALE`。本 Task 补 ownership transition 的定向回归，失败即阻断交付。
- **复用点**: `ModelReleaseCandidateResource/ApplicationService`、ModelPublishDialog、现有 materialization dispatch、asset registration。
- **禁止项**: 不增加 `if ownership then publishToX` 的第二状态机；分支只允许存在于 artifact preparation seam。

## 影响范围

- release/lifecycle focused integration tests
- ModelPublishDialog regression tests（若刷新语义需调整）
- `it/IT-06`、`it/IT-07` 真实证据

## 验证 (RED→GREEN)

- [ ] 三条路径（DESIGNER / DBT 原生 / DBT 接管而来）创建 candidate 的同一契约测试。
- [ ] **接管而来的模型能走完到 PUBLISHED**，且候选 entry 的 implementation checksum 指向接管产出的实现。
- [ ] candidate entry 的 model/implementation pins 与数据库 current revision 完全一致。
- [ ] ownership 转换后旧 candidate 转 STALE，返回 `MODEL_RELEASE_CANDIDATE_STALE`，不能继续发布。
- [ ] submittedBy/approvedBy/publishedBy 为三个不同 actor，且 duty 与动作匹配。
- [ ] 重复 publish idempotency key 不重复登记资产。
- [ ] 发布后的表示 projection 回传 publication evidence。

## Definition of Done

- [ ] IT-06、IT-07 均达到 PUBLISHED，而非只到 compile/materialized。
- [ ] 三条路径共用同一 candidate API、状态机和审计结构。
- [ ] 发布资产可从统一数据资产入口检索，且关联当前发布证据。
