# T03: 落地代码预览与显式接管交互

**优先级**: P0
**状态**: IN_PROGRESS（源码与聚焦自动化完成；真实浏览器 IT 待补）
**依赖**: F0/T01、F1/T02、F2/T01、F2/T02

## 目标

让用户在代码模式中先安全查看生成代码，再通过有明确后果说明的确认流程接管代码实现。

## 技术设计 (Contract-first)

- **输入契约**: DESIGNER_GENERATED model + exact lifecycle pins + `ModeAccess.action='PREVIEW'`；接管可用性单独来自 transition validate，不由 mode resolver 伪造 `CONVERT`。
- **输出契约**: 只读代码面板；接管确认对话框；成功后使用 `OwnershipTransitionView.model/implementation` 刷新工作台并创建 dbt draft。
- **数据流**: 进入 code view → fetch preview → 点击接管 → validate → 展示摘要 → confirm → commit transition → refresh representation/lifecycle → 打开可编辑草稿。
- **错误路径**: loading skeleton；preview/validate 422 显示 reasons；409/412 提示刷新；403 保留只读说明；取消确认零写入。
- **复用点**: F1 模式容器、现有 RequestState/Status/dialog、AdvancedDbtWorkspace draft create；不复制草稿编辑器。

## UI 交互规格

- 顶部状态：“当前由可视化配置维护 · 代码只读”。
- 文件列表按 `nodeKind` 分组：主模型 `<name>.sql` 与 `<name>.yml` 展开，`stg_<name>.sql` 标注“系统生成的中间节点”并默认折叠。
- 主按钮：“接管代码实现”；禁用时 title 显示真实原因。
- 确认框必须展示：源/目标维护方式、当前与目标 revision、预览 checksum 前 12 位、接管后可视化模式只读、发布入口不变，以及**「本版本不可转回可视化维护」**（依据 validate 的 `reversible:false` 渲染，不写死）。
- 成功 toast：“已接管代码实现，当前模型 rN / 实现 rM”；失败不切换模式。
- 只读账号进入代码模式：显示“需要维护权限才能查看实现代码”的空态，无接管按钮，不报错。
