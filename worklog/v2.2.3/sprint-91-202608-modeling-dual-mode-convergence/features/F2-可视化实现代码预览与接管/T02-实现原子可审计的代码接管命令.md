# T02: 实现原子且可审计的代码接管命令

**优先级**: P0
**状态**: IN_PROGRESS（源码与聚焦自动化完成；真实 PostgreSQL 事务/发布 IT 待补）
**依赖**: F0/T02（确证复核结论 A）、F2/T01

> **首版标 READY 已作废**，原设计「生成 SQL/SCHEMA 作为首个 dbt source bundle」会让接管后的模型无法编译。修订依据见复核结论 A 与账本 #16～#19。

## 目标

提供统一 ownership transition 的预检与提交 seam，使 `DESIGNER_GENERATED → DBT_MANAGED` 转换：①不出现 ModelSpec 已切换而 implementation 未切换的中间态；②转换后的模型**仍能通过既有 `compile()` 门禁**并继续走统一发布链。

## 首版设计为什么会失败

```
DESIGNER 编译产物  = {STG_SQL, SQL, SCHEMA, TEST}     ← ModelingDbtCompiler.java:105-113
                                                        CanonicalModelLifecycleCompilerAdapter.java:79-83
compile() 对 DBT_MANAGED 接受 = {SQL,SCHEMA} 或 {SQL,SCHEMA,CONFIG}  ← ModelLifecycleService.java:462-476
```

带上 `STG_SQL` → 抛 `MODEL_DBT_IMPORT_REQUIRED`；丢掉 stg → 主模型的 `{{ ref('stg_x') }}` 在 dbt 运行期解析失败。**接管后既不能编译也不能物化，F5/T01 的核心承诺直接落空。**

出路已经存在于既有代码里：draft commit 的制品映射（`DbtImplementationDraftService.java:819-852`）只为**被拥有节点**产 `SQL/SCHEMA/CONFIG`，其中 `CONFIG` 是 `.dts/dbt-project-bundle.json` 冻结的**整包清单**——stg 文件在包里完整保留，类型集合又恰好落在门禁的接受集合内。接管必须复用这条 seam，而不是自造 `seededArtifacts`。

## 技术设计 (Contract-first)

### 预检 `POST .../ownership-transitions/validate`

- **输入**: headers `If-Match`（model ETag）、`If-Match-Implementation`；body `{targetOwnership:'DBT_MANAGED'}`。
- **输出**:
  ```
  { allowed, reasons[], sourceOwnership:'DESIGNER_GENERATED', targetOwnership:'DBT_MANAGED',
    previewChecksum, baseModelRevision, baseImplementationRevision,
    previewFileCount:3, bundleFileCount:4, reversible:false }
  ```
- 只读，不写库。`reversible:false` 是**契约字段**，供 UI 渲染不可逆告知（ADR-91-09），不是注释。

### 提交 `POST .../ownership-transitions`

- **输入**: 同一组 ETag + 严格 JSON `{targetOwnership:'DBT_MANAGED', previewChecksum, idempotencyKey}`。
  **不接受 `projectKey` / `dbtUniqueId`**（ADR-91-08）——服务端一律用
  `ModelImplementationExecutionPlanner.systemManagedDbtProjectKey/UniqueId(model)`。
- **解码**: endpoint 使用局部 strict `ObjectReader`/decoder（`FAIL_ON_UNKNOWN_PROPERTIES`）；任何未知字段，包括 `projectKey`/`dbtUniqueId`，稳定返回 400。
- **输出**: `{transitionId, sourceOwnership, targetOwnership, model, implementation, artifactTypes:['SQL','SCHEMA','CONFIG'], previewFileCount:3, bundleFileCount:4}`。
- **事务内顺序**（顺序不可调换）:

  1. 重算预检摘要，比对 `previewChecksum`；
  2. 锁定 current model/implementation；
  3. `ModelingDbtCompiler` 生成 3 个预览文件；
  4. 复用/最小抽取 `DbtCanonicalProjectReconstructor` 的 project-file 规则，补确定性 `dbt_project.yml`，形成 4 文件 project；
  5. `AdvancedDbtDraftStaticValidator.validate` 后调用 `DbtProjectBundleManifest.freeze(...)`，并核对 project identity；
  6. 创建 DBT_MANAGED ModelSpec revision；
  7. 通过既有 lifecycle implementation 写入 owner 创建 `ACTIVE + DBT_MANAGED + GENERATED` implementation revision；`inputs_json` 恰一项 `generatorType=DBT`，config 的系统 `projectKey/dbtUniqueId` 与实现字段一致；
  8. **`ModelingDbtArtifactImportService.importArtifacts(...)` 落 `SQL/SCHEMA/CONFIG`**，只针对被拥有节点；
  9. command receipt + audit；
  10. 单事务提交。

  > 第 6/7 步必须早于任何草稿创建。后续建草稿时 `base != null`，`target()` 才能按 `dbtUniqueId` 选中被拥有节点；source bundle 恢复同时要求 4 文件中存在 `dbt_project.yml`。

- **错误路径**:
  - ETag / `previewChecksum` 过期 → 409/412，零写入；
  - 同 `idempotencyKey` 同 payload → 返回原 receipt；同 key 不同 payload → 409；
  - 编译门禁未满足 → 422，透传稳定 diagnostic code；
  - artifact / receipt / audit 任一写失败 → 整体回滚，ownership mismatch 保持 0。
- **复用点**: ModelSpec application service、ModelLifecycle repository/command receipt、F2/T01 compiler、`DbtProjectBundleManifest`、`ModelingDbtArtifactImportService`、现有 audit service。**禁止新增 artifact 类型，禁止放宽 `compile()` 门禁。**
- **安全**: `CATALOG_MAINTAINERS`；新增审计动作先登记到 dts-admin 审计资源字典。

## 影响范围

- modeling lifecycle/transition contract、resource、service
- 既有 model spec + implementation + artifact + command receipt repository
- dts-admin 审计资源字典 changelog（仅确有新 action 时）
- service/REST/transaction tests
- **不改** `ModelingDbtCompiler`、`CanonicalModelLifecycleCompilerAdapter`、`ModelLifecycleService.compile()`、`DbtImplementationDraftService`

## 验证 (RED→GREEN)

阻断项（前四条直接继承 F0/T02 探针 C）：

- [ ] 接管后落地的制品类型集合**等于** `{SQL,SCHEMA,CONFIG}`。
- [ ] 接管后立即调 `compile`，**不抛** `MODEL_DBT_IMPORT_REQUIRED`。
- [ ] `CONFIG` bundle 内可检出 `stg_*.sql`，内容与编译输出逐字节一致。
- [ ] `CONFIG` bundle 恰含 `dbt_project.yml` + 3 个生成文件，restore 后逐文件 checksum 一致。
- [ ] 接管前后 `dbtUniqueId` 与 `ExecutionPlan.selector` 逐字符不变。
- [ ] 请求体携带 `projectKey`/`dbtUniqueId` 时被拒（400），而非被静默采纳。
- [ ] implementation 为 `ACTIVE/DBT_MANAGED/GENERATED`，且单一 DBT generator config 与系统 identity 一致。
- [ ] 接管后创建首个草稿成功（`base != null` 路径），stg 出现在可编辑文件列表中且非被拥有节点。

其余：

- [ ] 服务测试注入每个写步骤失败，断言 model/implementation/artifact 均未部分提交。
- [ ] 重放同一 idempotency key 返回相同 transitionId/revision；冲突 payload 返回 409。
- [ ] 两客户端并发时一成功、一冲突，mismatch count=0。
- [ ] 审计 payload 完整且不含文件正文。

## Definition of Done

- [ ] transition seam 是唯一所有权转换 owner，不在前端串联两个写 API。
- [ ] 接管后的模型可编译、可物化、可进入发布候选（与 F5/T01 对接）。
- [ ] 八条阻断项全绿。
- [ ] 旧 model lifecycle/release tests 无回归；`convert-to-designer-generated` 未被触碰。
