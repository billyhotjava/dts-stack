# T02: 统一单表与批量物化交互

**优先级**: P0
**状态**: CODE_COMPLETE / E2E_PENDING
**依赖**: F8/T01

## 目标

让模型列表的单条「物化/再次物化」与多选「批量物化」打开同一计划对话框，先说明将构建、复用和阻断哪些模型，再由用户确认创建候选。

## UI/UX 契约

- 模型列表保留搜索、过滤、分页与复选框；不可物化的维度定义等对象不提供复选框。
- 行动作：未物化显示「物化」，已有历史显示「物化历史 / 再次物化」。
- 批量动作仅在至少选中一个可物化模型时启用；选择跨环境/目标不一致对象时在 preview 明确阻断。
- 对话框固定展示：
  - 目标环境与策略；
  - 用户选中的目标模型；
  - 按执行顺序的 BUILD/REUSE 列表；
  - blocker 及可返回修复的模型/字段/来源链接；
  - plan checksum 摘要和「创建候选」主动作。
- 默认策略 `WITH_MISSING_UPSTREAMS`；仅在全部上游可 REUSE 时允许 `CURRENT_ONLY`。

## 状态与错误

- 空、加载、成功、阻断、网络错误均保留用户选择；刷新计划不清空选中项。
- preview 成功但 create 因 stale checksum 失败时，显示「依赖已变化，重新预览」，禁止直接重试旧请求。
- 403 只移除写动作并保留只读物化状态/历史；后端仍 fail closed。
- 创建候选后跳转既有发布/物化工作区，不新增第二套进度页。

## Feature 关联

- 读取 F8/T01 response，不在前端计算依赖或 BUILD/REUSE。
- 候选创建仍走 F5/Sprint-76 既有 API；执行和历史由 F8/T03 收敛。
- Sprint-93 资产/血缘/质量入口从统一模型/候选身份跳转，不从本对话框建立平行链接。
