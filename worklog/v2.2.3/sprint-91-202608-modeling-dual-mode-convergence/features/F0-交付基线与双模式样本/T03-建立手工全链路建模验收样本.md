# T03: 建立手工全链路建模验收样本

**优先级**: P0
**状态**: DRAFT
**依赖**: F0/T01 的真实登录与运行实例；已有且含测试数据的 ODS source binding

## 目标

建立一条不依赖 ZIP 导入、可由用户在现有工作台逐表创建的隔离验收链，固定后续 F6～F8 与 F5 的共同输入，避免各 Feature 自建互不相认的测试数据。

规范链路为：

`已接入 ODS → DWD DIM + DWD FACT → DWS SUMMARY → ADS APPLICATION`

STG 只允许作为 dbt 编译产生的技术中间节点，不创建业务 ModelSpec，也不登记为独立业务资产。

## 技术设计 (Contract-first)

### 输入契约

- 使用现有数据集成已接入、字段已确认且至少有 1 行测试数据的 ODS 物理表；本 Task 不执行 ODS DDL、TRUNCATE 或装数。
- 使用前缀 `E2E_S91_CHAIN_*` 创建隔离对象，不修改 PJM 现有模型和已发布资产。
- 使用真实菜单与账号 `xiezm` 创建：
  - 1 个 `DIMENSION`，层级为 DWD；
  - 1 个 `FACT`，层级为 DWD，同时引用 ODS 基础来源和该维度固定修订；
  - 1 个 `SUMMARY`，层级为 DWS，依赖事实模型固定修订；
  - 1 个 `APPLICATION`，层级为 ADS，依赖汇总模型固定修订。

### 输出契约

在 `it/evidence/` 留存不含密码和 SQL 正文的样本清单：

```text
sourceBindingId / resolvedVersion / physicalTable
modelSpecId / objectType / layer / modelRevision / modelChecksum
implementationId / ownership / implementationRevision / implementationChecksum
sourceRefs / dependsOn / dimensionRefs
```

每个模型均须具备稳定业务字段、明确主键/粒度、非空中文定义；引用必须钉住 revision/checksum，不接受只记名称的松散关联。

### 失败与清理

- ODS 无数据、字段未确认、source binding 失效或模型引用形成环时，样本状态保持 BLOCKED，不以伪数据或跳过门禁继续。
- 草稿规划对象可按 `ADS → DWS → FACT → DIM` 顺序清理；已形成的候选、执行、发布、审计与治理证据不硬删除。
- 本 Task 不创建 ZIP、不调用数据库脚本替代 UI，也不把 STG 暴露成业务模型。

## Feature 关联

|---|---|---|
| F0/T01 登录、真实实例、ODS 数据可用性 | 唯一的 `E2E_S91_CHAIN_*` 模型与版本清单 | F6/T01 依赖快照；F6/T02/T03 UI/代码实现；F7 可视化生成；F8 物化计划；F5 发布与治理验收 |

## Definition of Ready

- [ ] `xiezm` 可登录真实模型工作台，部门受限账号可用于负向验收。
- [ ] 已选定 ODS source binding，并核验字段已确认、resolved version 固定、测试数据行数大于 0。
- [ ] E2E 前缀、证据目录和非破坏性清理边界已确认。

## 验证

- [ ] 从真实菜单逐个创建 4 个模型，未使用 ZIP、SQL 脚本或后门 API。
- [ ] FACT 同时表达 ODS 基础来源与 DIMENSION 引用；DWS/ADS 形成有向无环固定修订依赖。
- [ ] 每个 revision/checksum 可从 API 与数据库事实交叉核验。
- [ ] ODS 数据只读且行数未因建模样本创建发生变化。

## Definition of Done

- [ ] IT-10 样本清单完整，后续 Feature 全部引用同一批 ID 与 checksum。
- [ ] 不存在孤立模型、名称关联、重复 source ledger 或将 STG 当业务资产的记录。
- [ ] 样本清理边界和证据保留策略已记录。
