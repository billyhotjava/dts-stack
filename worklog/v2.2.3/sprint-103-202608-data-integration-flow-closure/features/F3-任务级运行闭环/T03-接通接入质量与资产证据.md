# T03：接通接入质量与资产证据

**优先级**：P0
**状态**：`IMPLEMENTED_AND_DEPLOYED`（真实双批资产质量切换待安全金丝雀）
**依赖**：F0/T02 的资产/质量契约；F3/T01 的 execution DTO；F3/T02 的运行状态机

## 目标

复用现有 post-ingestion quality workflow，把一次成功接入 execution 与唯一目标数据资产、正式质量 workflow/run 和消费资格贯通。用户能判断“数据是否接入成功、质量验证是否启动、当前证据是否通过、当前是否可信可用”，且四个事实不会相互覆盖。

## 现有 owner 与复用边界

- `IngestionExecution` 已保存 `qualityPolicyRef/qualityWorkflowId/qualityRunId/qualityWorkflowStatus`，继续作为接入与质量关联账本。
- `AirflowExecutionSyncService` 在接入成功后持久化触发意图，并在事务提交后调用 `PostIngestionQualityWorkflowService`；进程中断由调度恢复，不新增第二触发器。
- `PostIngestionQualityWorkflowAttemptStore` 继续拥有 `TRIGGERING/TRIGGERED/RETRY_WAIT/EXHAUSTED`、最多 3 次与退避策略。
- `QualityWorkflowOrchestrator` 拥有 workflow 生命周期，`QualityRunService` 只执行规则；规则继续按 `datasetId` 读取已发布、启用绑定。
- 目录继续使用 `CatalogAssetType.DATASET + CatalogAssetKey/CatalogDataset.id`；资产质量与消费资格继续由 catalog status/eligibility owner 投影。
- 本任务只补契约、关联、新鲜度与 UI/API 投影，不复制规则 JSON、不新建质量执行器、不新增 `TRUSTED/VERIFIED` 生命周期。

## 端到端数据流

1. ACTIVE revision/runtime snapshot 冻结 `destination.assetRef.datasetId`、`postIngestionQuality` 与 `qualityPolicyRef=dataset:<datasetId>`。
2. 新 execution 冻结相同字段；接入过程中只做连接、映射、schema/type、权限、密级和暂存校验。
3. execution 完整提交成功时，先把接入观察/血缘证据幂等写入设计期已确定的 canonical asset identity，再在同一业务完成路径持久化质量触发意图。
4. 事务提交后，以 `datasetId + ingestionExecutionId` 调用现有 trusted ingestion start；重复状态同步、回调或调度恢复返回同一 workflow。
5. 触发成功后回写 workflowId；正式 run 创建/完成后回写 runId 与质量状态。暂时失败进入 `RETRY_WAIT`，三次耗尽进入 `EXHAUSTED/TRIGGER_FAILED`。
6. 当前证据投影必须同时匹配目标 dataset 与当前 ingestion execution。新 execution 成功时，旧 run 即使 `PASSED` 也变为 `STALE`，不能支持当前可信展示。
7. 资产详情与 execution 详情读取同一 `QualityEvidenceRef`；只有 `evidenceState=CURRENT`、`qualityStatus=PASSED` 且 `consumptionEligibility=ELIGIBLE` 时派生“可信可用”。

## API/DTO 契约

execution 列表只返回质量摘要，详情与资产状态端点返回完整：

```text
QualityEvidenceRef {
  ingestionExecutionId: long
  qualityWorkflowId: uuid|null
  qualityRunId: uuid|null
  triggerStatus: NOT_CONFIGURED|TRIGGERING|TRIGGERED|RETRY_WAIT|EXHAUSTED
  evidenceState: MISSING|PENDING|CURRENT|STALE|TRIGGER_FAILED
  qualityStatus: UNKNOWN|RUNNING|PASSED|FAILED
  observedAt: instant|null
}

AssetTrustProjection {
  assetRef: DestinationAssetRef
  qualityEvidence: QualityEvidenceRef
  consumptionEligibility: ELIGIBLE|CONDITIONAL|BLOCKED
  trustedUsable: boolean
  reasonCodes: string[]
}
```

- `trustedUsable` 必须由服务端按既有 asset semantics 派生，前端不得自行把 `PASSED` 等同为可信。
- 旧 execution 没有绑定信息时返回 `MISSING/UNKNOWN` 和 legacy reason，不猜测关联 latest run。
- 深链使用业务身份 `taskId/executionId/datasetId/workflowId`，内部 dagRunId 只作有权限诊断字段。

## 状态与错误路径

| 场景 | ingestion 状态 | 质量证据 | 资产/消费表现 |
|---|---|---|---|
| 未开启接入后质量验证 | SUCCESS | `NOT_CONFIGURED/MISSING/UNKNOWN` | 资产存在，不显示可信 |
| 成功后待触发/运行 | SUCCESS | `TRIGGERING|TRIGGERED / PENDING / UNKNOWN|RUNNING` | 显示“待质量验证/验证中” |
| 临时触发失败 | SUCCESS | `RETRY_WAIT/PENDING/UNKNOWN` | 显示下次重试和 correlationId |
| 触发耗尽 | SUCCESS | `EXHAUSTED/TRIGGER_FAILED/UNKNOWN` | 禁止沿用旧可信，显示治理处置原因 |
| 正式质量失败 | SUCCESS | `TRIGGERED/CURRENT/FAILED` | 不可消费或有条件可消费，进入质量问题处置 |
| 正式质量通过 | SUCCESS | `TRIGGERED/CURRENT/PASSED` | 重新计算资格；仅 ELIGIBLE 显示可信可用 |
| 新批次刚成功 | SUCCESS | 旧证据 `STALE`，新证据 `PENDING` | 旧徽标立即失效 |

目标资产不一致返回 `QUALITY_ASSET_MISMATCH`；目标未解析返回 `TARGET_ASSET_UNRESOLVED`；无可执行规则在设计校验阶段返回 `QUALITY_BINDING_UNAVAILABLE`，运行期规则被撤回则由 workflow `BLOCKED`/reason code 表达。所有跨部门、跨密级访问服务端 fail closed。

## UI 交互规格

- 运行实例详情展示“接入执行”和“质量验证”两条时间线；质量卡显示触发状态、证据新鲜度、正式结果、验证时间和 correlationId。
- 目标资产卡提供同一 dataset 详情深链；质量卡提供 workflow/run 深链，均服从既有权限。
- 资产详情“质量与 SLA”及消费资格卡增加本次 execution、workflow/run 与证据是否当前，不新增笼统资产状态字段。
- 未启用、待验证、验证中、证据失效、触发异常、未通过、已通过分别使用明确业务中文；禁止裸“已验证”。
- Chrome 95 稳定标识：`integration-flow-target-asset`、`integration-flow-quality-evidence`、`integration-flow-asset-link`。

## 验证（RED→GREEN）

- [ ] 并发/重复 success 回调 20 次只产生一个 `datasetId + ingestionExecutionId` workflow；进程在提交后、外部调用前中断可由调度恢复。
- [ ] 未配置、无规则、跨资产、跨部门、跨密级、暂时触发失败、三次耗尽、workflow BLOCKED、PASSED、FAILED 全矩阵有契约/集成测试。
- [ ] 未认证服务、普通用户 token、伪造 machine actor/quality Header、替换 datasetId 均不能进入 trusted ingestion 路径；错误响应不泄露规则、凭据或内部 stack。
- [ ] 两个连续成功 execution：第二个提交后第一个 PASS 立即为 STALE；第二个未完成前绝不显示可信可用。
- [ ] 质量 FAILED/EXHAUSTED 不改写 ingestion SUCCESS，不删除/重建资产，不创建第二资产身份。
- [ ] execution、workflow、run、asset detail 双向深链一致，100 行列表无 asset/quality N+1。
- [ ] `CURRENT/PASSED` 但 eligibility 非 ELIGIBLE 时不显示可信；全部门禁满足时才显示。
- [ ] Chrome 95 完成“选择目标资产 → 开启接入后质量验证 → 运行 → 查看当前资产证据”的单一旅程，无阻断 console/network 错误。
