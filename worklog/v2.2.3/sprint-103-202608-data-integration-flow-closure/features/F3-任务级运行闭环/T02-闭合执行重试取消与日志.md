# T02：闭合执行、重试、取消与日志

**优先级**：P0
**状态**：`IMPLEMENTED_AND_DEPLOYED`
**依赖**：F3/T01 的 task execution 查询契约

## 目标

用户针对当前任务和固定版本安全发起运行、重试或取消，并能从平台账本查看最终状态、日志和关联关系。

## 技术设计（Contract-first）

- **立即运行**：复用 task execute，固定 ACTIVE revision 与 plan checksum；先创建 PREPARING 账本，再 after-commit 触发执行器。
- **质量边界**：立即运行只创建 ingestion execution；只有该 execution 完整提交成功后，F3/T03 才登记正式质量 workflow。FAILED/CANCELLED 不触发成功后质量验证。
- **重试**：只允许冻结的失败终态；复用/完善任务级 retry，生成新 execution 并保存 `sourceExecutionId`；移除无消费者 `retryRunId` conf。
- **重试证据**：新 execution 使用冻结的目标 asset/quality 配置，但拥有新的 `ingestionExecutionId` 和独立质量证据；不得复用原 execution 的 workflow/run 充当当前结果。
- **取消**：新增异步 cancel；合法状态转 CANCEL_REQUESTED，调用 Airflow/执行器后收敛 CANCELLED；超时由同步器补偿。
- **幂等**：三类写命令携带 idempotency key；24h 内相同 key 返回同一业务结果。
- **状态**：平台状态机是业务真源，`AirflowExecutionSyncService` 做映射；未知状态 fail safe 并告警。
- **日志**：按 taskId+executionId 分页，覆盖所有 ingestion 类型；删除 dagId/dbt 名称判断和硬编码 `dbt_run`。

## UI 交互规格

- 立即运行显示绑定版本摘要，双击不重复创建实例。
- 重试抽屉展示原实例、原 revision、失败原因与冻结输入摘要。
- 取消需二次确认；CANCEL_REQUESTED 显示“取消处理中”，超时给出关联 ID 与恢复说明。
- 日志视图显示时间、组件、级别、脱敏内容与 correlationId；终态停止高频轮询。

## 验证（RED→GREEN）

- [ ] 双击运行只创建一个 execution；revision/plan checksum 与 ACTIVE 设计一致。
- [ ] 重试使用原实例冻结输入，原/新实例双向可查，非法状态返回 409。
- [ ] PREPARING/RUNNING 可取消；重复取消幂等；外部超时最终收敛或明确 BLOCKED。
- [ ] SUCCESS/FAILED/CANCELLED 为终态，前端停止轮询。
- [ ] mysql/http/file 等接入任务均可查看日志，不依赖 dbt 名称。
- [ ] 运行、重试、取消的成功与失败均有严格审计和 correlationId。
- [ ] FAILED/CANCELLED 不登记 post-ingestion workflow；SUCCESS 重放通知不产生重复 workflow。
