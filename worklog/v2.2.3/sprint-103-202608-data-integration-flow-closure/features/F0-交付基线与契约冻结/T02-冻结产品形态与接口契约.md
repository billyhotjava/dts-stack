# T02：冻结产品形态与接口契约

**优先级**：P0
**状态**：`DONE`
**依赖**：F0/T01 的复杂度报告、金丝雀、角色和 Chrome 95 基线

## 目标

把“配置表单 → 自动拓扑 → 校验 → 准入 → 调度 → 运行 → 资产登记 → 接入后质量验证 → 当前证据投影”冻结成可测试契约，使 F1～F4 不在编码中重新讨论产品形态或数据 owner。

## 固定边界

- 任务配置与 revision 是唯一执行事实；拓扑是只读投影。
- 路由保持 `/explore/etl/orchestration`，客户可见名称改为“数据集成流程”，不新增菜单。
- `graphDsl` 仅兼容读取/导出，不参与校验、准入或执行。
- 目标端必须解析为 `CatalogAssetType.DATASET + CatalogAssetKey + CatalogDataset.id`；F0 冻结新目标资产在 design 保存、准入或 execution 前置阶段的唯一登记时点，不建立平行资产表。
- 兼容字段 `qualityPolicyRef` 的格式已确认是 `dataset:<uuid>`，且 UUID 必须等于目标 `datasetId`；UI 名称为“接入后质量验证”，不展示任意策略选择器。
- 接入过程校验不产生正式质量证据；正式 workflow 只在 execution 完整提交后触发。接入成功与质量结果分别记账。
- 不新增 `TRUSTED/VERIFIED` 生命周期；`可信可用`只由当前 execution 的 `CURRENT/PASSED` 证据与 `ELIGIBLE` 消费资格派生。
- 转换、多作业依赖、循环、事件、回滚不属于本 Sprint。

## 待冻结 DTO

```text
IngestionTaskDesign {
  taskId: long
  taskName: string
  revisionNumber: int|null
  revisionState: DRAFT|ACTIVE|SUPERSEDED
  source: { dataSourceId: long, connectorType: string, objectRef: string }
  destination: {
    dataSourceId: long, objectRef: string, writeMode: string,
    assetRef: {
      assetType: "DATASET", assetKey: string,
      datasetId: uuid, resolution: RESOLVED|UNRESOLVED
    }
  }
  mappings: [{ sourceField: string, targetField: string, expressionRef?: string }]
  schedule: { trigger: MANUAL|CRON, cronExpression?: string, timezone?: string }
  postIngestionQuality: {
    enabled: boolean,
    policyRef: string|null,
    timing: "POST_COMMIT",
    boundRuleCount: int
  }
  qualityPolicyRef?: string  // 兼容投影；enabled=true 时为 dataset:<datasetId>
  planChecksum: string
  validation: ValidationReport
  topology: TopologyProjection
}

TopologyProjection {
  taskId: long
  revisionNumber: int|null
  planChecksum: string
  projectionVersion: string
  nodes: [{ id: string, kind: SOURCE|LOAD|ASSET_OBSERVATION|POST_INGESTION_QUALITY|END, label: string, status: string }]
  edges: [{ id: string, source: string, target: string }]
}

QualityEvidenceRef {
  ingestionExecutionId: long
  qualityWorkflowId: uuid|null
  qualityRunId: uuid|null
  triggerStatus: NOT_CONFIGURED|TRIGGERING|TRIGGERED|RETRY_WAIT|EXHAUSTED
  evidenceState: MISSING|PENDING|CURRENT|STALE|TRIGGER_FAILED
  qualityStatus: UNKNOWN|RUNNING|PASSED|FAILED
  observedAt: instant|null
}
```

F0/T02 必须逐字段映射现有 connector/task DTO；不适用字段删除，不允许为了满足草案而新建平行配置。

### 实施冻结补充（2026-08-28）

- `planChecksum` 直接复用 revision 的 `effectiveConfigChecksum`，不新增重复列；保存、校验、准入与 execution 都使用该值。
- `source/destination/mappings/schedule` 逐字段映射既有 `IngestionTaskDTO` 的 `sourceDataSourceId/sourceType/sourceConfig/destinationType/destinationConfig/tableMapping/syncMode/syncSchedule/syncConfig`。
- 设计 API 只允许更新上述配置及 `name/description/qualityPolicyRef`，不接收 `status/airflowDagId/addaxJobPath/graphDsl/classificationSeal` 等控制字段。
- 目标资产只接受既有 `qualityPolicyRef=dataset:<uuid>` 作为稳定 dataset 引用；平台代理用 `CatalogDataset` 与 `CatalogAssetKey.dataset` 解析。未解析、重复或物理对象不匹配时 fail-closed，不自动注册/合并资产。
- 新目标表在接入成功后继续走既有 catalog observation/lineage owner；在获得稳定 datasetId 和正式规则前，页面只能关闭“接入后质量验证”。
- 质量证据以 `workflow.triggerRef=ingestion:<executionId>`、workflow datasetId 和 execution 冻结的 policyRef 三方一致为 CURRENT；仅 workflow 通过且既有消费资格为 ELIGIBLE 时派生“可信可用”。
- 调度启停与取消只解析任务自身 `airflowDagId/executionId`，浏览器不能提交任意 dagId。

## API 与错误路径

| API | 关键行为 |
|---|---|
| `GET /api/ingestion/tasks/{id}/design` | 权限过滤；返回指定任务 draft/active 设计与投影 |
| `PUT /api/ingestion/tasks/{id}/design` | `If-Match`；仅更新配置字段；409 冲突，不整对象覆盖 |
| `POST /api/ingestion/tasks/{id}/design/validate` | 连接、引用、mapping、Cron、目标资产解析、同资产质量绑定、权限、密级校验 |
| `GET /api/ingestion/tasks/{id}/topology` | 按 `view=DRAFT|ACTIVE` 生成只读投影 |
| 既有 `POST /tasks/{id}/admit` | 增加 expected plan checksum 条件，不新建发布 owner |
| task-scoped schedule/execution | 不接受客户端任意 dagId；所有命令幂等并审计 |
| execution detail / asset status projection | 返回独立的接入状态、trigger/evidence/quality 状态和 asset/workflow/run 深链 |

trusted post-ingestion 端点必须从服务端认证上下文识别 `dts-ingestion`，不能信任浏览器传入 actor/header；datasetId 只能来自冻结 execution。普通用户、未认证服务、跨资产替换与重放的响应码、审计和限流/幂等行为一并冻结。

错误码至少冻结：`TASK_DESIGN_INVALID`(422)、`TASK_DESIGN_CONFLICT`(409)、`TASK_REVISION_MISMATCH`(409)、`TASK_NOT_ADMITTED`(409)、`TASK_EXECUTION_NOT_CANCELLABLE`(409)、`TARGET_ASSET_UNRESOLVED`(422)、`QUALITY_ASSET_MISMATCH`(422)、`QUALITY_BINDING_UNAVAILABLE`(422)、权限 403、对象 404。触发重试/耗尽是 execution 详情状态，不伪装为设计 422。

## UI/UX 走查

1. 用户进入“数据集成流程”，选择金丝雀任务。
2. 左侧依次填写数据源、目标与映射、调度、接入后质量验证；目标资产未解析时第四步禁用。
3. 右侧拓扑随服务端校验结果刷新，但不能拖拽改变执行语义。
4. 保存草稿后显示 plan checksum/更新时间；另一会话冲突时保留本地输入并提示重新加载。
5. 校验通过后“提交发布”可用；发布状态和运行实例可从同一 taskId 深链查看。
6. execution 提交后，页面先显示“待质量验证”，随后分别展示触发状态、正式结果和当前证据；质量失败不把接入成功改为失败。
7. 从 execution 进入同一目标资产与 quality workflow/run；只有 `CURRENT/PASSED + ELIGIBLE` 时显示“可信可用”。
