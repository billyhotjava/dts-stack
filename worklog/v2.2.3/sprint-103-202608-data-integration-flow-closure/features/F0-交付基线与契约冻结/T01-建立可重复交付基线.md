# T01：建立可重复交付基线并验证流程复杂度

**优先级**：P0
**状态**：`DONE`（Chrome 95/三角色为环境说明，不伪装通过）
**依赖**：无
**变更性质**：只读核验 + 经批准的可回收测试夹具

## 目标

证明客户真正需要的是线性数据集成、ELT 还是多任务 DAG，并建立后续代码可在真实角色、数据和 Chrome 95 上验收的基线。

## 输入与输出契约

- 输入：当前 7 条 ACTIVE 接入任务、现有 execution/DAG、canonical 数据资产与质量规则绑定、客户提供或现场可见的真实流程样本。
- 输出：`assets/workflow-complexity-evidence.md`，每条流程记录 `workflowId/source/taskIds/stepCount/dependencyShape/changeFrequency/operator/recoveryMode/evidence`。
- 分类：`SINGLE_TASK_EL`、`VERSIONED_ELT`、`MULTI_JOB_DAG`、`DOMAIN_WORKFLOW`；不得把审批或质量处置误归为技术 DAG。

## 执行范围

1. 全量盘点 7 条活跃任务：源、目标、目标资产解析结果、映射、调度、`qualityPolicyRef`、运行结果以及是否依赖其他作业。
2. 收集客户侧真实流程；明确哪些需求不能由单任务配置表单表达。
3. 仅当至少 3 条真实流程同时存在多作业和分支/汇聚/条件依赖时，才记录“另立可编辑 DAG capability”的建议。
4. 建立只读、编辑、执行三档验收账号或隔离 `storageState`，验证登录过期与跨部门行为。
5. 选定一条可重复成功的 ACTIVE 接入任务作为金丝雀；其目标必须解析为 canonical dataset，并至少有一条已发布、启用的正式质量规则绑定；记录 connector、revision、datasetId、数据量、耗时与回收步骤。
6. 建立合法配置、服务端非法配置、双会话 plan checksum 冲突三类样本；不得包含真实凭据。
7. 对 81 条失败 execution 抽样归因；对 31 个未匹配 ingestion DAG 只读归类，禁止修改 Airflow。
8. 指定 Chrome 95 executable 或甲方验收机，固化最小前端、后端、契约、数据库与 E2E 命令。
9. 对金丝雀连续执行两批，采集 `taskId/revisionNumber/planChecksum/executionId/datasetId/qualityWorkflowId/qualityRunId`，验证第二批提交后第一批 `PASSED` 不再支持当前“可信可用”。

## 验证与完成标准

- [ ] 7 条活跃任务无遗漏；每条均能回答“表单是否足够、是否跨作业、失败如何恢复”。
- [ ] 客户流程证据具名，不以竞品截图或已有画布代码代替需求。
- [ ] DAG 门槛结果为 `PASS` 或 `NOT_JUSTIFIED`，结论及原始证据可复查。
- [ ] 三档角色矩阵覆盖设计、校验、发布、调度、运行、日志、重试和取消。
- [ ] 金丝雀任务至少连续成功 2 次，目标资产和已发布质量规则可定位，数据可验证、夹具可清理。
- [ ] 两批次均可回链 execution/workflow/run/asset；接入成功与质量结果分别留证。
- [ ] 当前质量证据有明确 `MISSING/PENDING/CURRENT/STALE/TRIGGER_FAILED` 预期，不以数据集任意 latest run 替代当前 execution。
- [ ] 三类配置样本均有 taskId、预期结果和回收步骤。
- [ ] 31 个 DAG 每项有分类，不执行自动删除、暂停或接管。
- [ ] Chrome 95 旅程可启动；只有现代浏览器时 Sprint 继续 BLOCKED。
- [ ] `it/baseline.md` 更新为当前命令与结果，敏感字段脱敏。

## 停止条件

任何夹具会影响客户数据、真实调度或共享任务时，停止写入并转为只读报告，等待明确批准。
