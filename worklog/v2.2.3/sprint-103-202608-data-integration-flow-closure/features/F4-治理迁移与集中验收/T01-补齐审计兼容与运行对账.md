# T01：补齐审计、兼容与运行对账

**优先级**：P0
**状态**：`IMPLEMENTED_AND_DEPLOYED`
**依赖**：F1～F3 的最终 schema、API 与状态契约

## 目标

在不破坏旧任务、旧 revision、历史 DSL 与质量历史的前提下交付 plan checksum、目标资产/质量证据关联与任务级运行能力，并让所有写动作、外部 run、质量触发和 DAG 差异可追踪。

## 技术设计（Contract-first）

- **schema**：expand/contract；新增 planChecksum/sourceExecutionId/idempotencyKey、destination asset ref 或 quality evidence freshness 所需字段先可空，兼容读后再回填。索引必须用真实查询与 EXPLAIN 证明。
- **旧 DSL**：`graphDsl=null`、JSON null、对象型 v1 均可读；对象型 v1 提供脱敏导出，不映射为 canonical design，不自动删除。
- **外部 run**：为 task/revision/dagRun 关联建立强唯一身份或等价约束；回调丢失由补偿扫描恢复。
- **质量关联**：沿用 execution 已有 workflow/run 字段与触发 attempt store；如需补充 datasetId/evidence state，采用 additive nullable 字段或可证明等价投影，不复制 quality run，不持久化“可信可用”总状态。
- **历史证据**：旧 execution 缺 ingestionExecutionId↔qualityRun 证明时保持 `MISSING/UNKNOWN`；只允许有确定关联的精确回填，禁止把数据集 latest PASSED 批量绑定到历史 execution。
- **审计**：扩展现有 action catalog/严格审计，不新建旁路表；保存、校验、准入、启停、运行、重试、取消均登记。
- **脱敏**：审计/change log 记录配置变更摘要和 plan checksum；移除/脱敏实体 `toString()` 中 graphDsl、脚本、依赖和凭据风险字段。
- **DAG 对账**：31 个未匹配 DAG 逐项标记 `KEEP / ADOPT_AFTER_PROOF / RETIRE_AFTER_APPROVAL`；默认 KEEP。

## 错误与回滚

- migration 可重跑；失败通过前向修复恢复，不回滚删除已写业务数据。
- 旧数据无法回填 checksum 时保持 null 并标记 legacy，不伪造摘要。
- 旧数据无法证明目标 dataset 或当前质量 run 时保持 unknown；回滚不得重新让 stale PASS 显示为当前可信。
- 接管/退役脚本只支持 dry-run、精确目标和审批清单；无批准不执行。

## 验证（RED→GREEN）

- [ ] 旧 null/JSON null/object DSL、旧 revision 和旧 API 兼容测试通过。
- [ ] 重复外部触发/回调不创建重复业务记录。
- [ ] 重复质量触发、回调与恢复扫描不创建第二 workflow/run 关联；`datasetId + ingestionExecutionId` 唯一性可证明。
- [ ] legacy/新 execution 的 `MISSING/PENDING/CURRENT/STALE/TRIGGER_FAILED` 投影及回填边界有迁移测试。
- [ ] 所有写动作成功与失败审计完整，action catalog 分类正确。
- [ ] 日志扫描无凭据、脚本正文或 DSL 全文。
- [ ] DAG 对账每项有来源、最后运行、状态、调用方证据和批准决定。
- [ ] migration、索引和恢复在测试库/副本演练。

## Definition of Done

- [ ] 架构：schema、唯一性、审计、脱敏、兼容测试绿。
- [ ] UI：历史 DSL 提示与导出不误导为可运行能力。
- [ ] 切片：金丝雀及至少一条 legacy 任务在迁移后可读可运行。
- [ ] 切片：legacy 任务不伪造可信；金丝雀两批次的当前证据切换不受 migration/rollback 影响。
