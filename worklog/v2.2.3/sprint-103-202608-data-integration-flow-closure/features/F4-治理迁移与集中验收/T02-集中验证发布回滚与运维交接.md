## 目标

## 验证顺序

1. 精确 diff、GitNexus impact/detect changes 与共享工作树复核。
2. design validation、topology projection、checksum、execution/quality evidence state machine 单元测试。
3. ingestion service、post-ingestion quality、asset projection、platform proxy、migration、权限和审计集成测试。
4. webapp source-contract、组件测试与生产/legacy browser 构建。
5. 使用资产/质量金丝雀执行 `it/README.md` 的单一端到端旅程，连续两批证明当前证据切换。
6. Chrome 95 重跑同一旅程，采集 console、network、截图。
7. 保留前端/后端当前回滚制品，按实际改动范围部署；核对 digest、健康、日志和内外网路由。
8. 演练制品、schema、DAG 和旧 ACTIVE revision 的回滚/前向修复。

## 运维交接

- runbook 覆盖：配置校验失败、目标资产未解析/不匹配、plan checksum 冲突、投影不一致、DAG 发布失败、运行未触发、质量触发重试/耗尽、证据过期、状态不同步、取消悬挂、日志缺失、幂等冲突、legacy DSL 和 DAG 漂移。
- 指标至少包含：校验失败率、目标资产解析失败率、投影耗时、发布失败率、运行排队、同步延迟、质量触发延迟/耗尽、当前证据投影延迟、取消收敛、日志缺失和对账差异数。
- 告警给出阈值、持续时间、owner、correlationId 查询方法和安全降级方式。
