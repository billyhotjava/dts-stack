# T02：生成拓扑投影与服务端校验

**优先级**：P0
**状态**：`IMPLEMENTED_AND_DEPLOYED`
**依赖**：F1/T01 的 design 与 plan checksum

## 目标

服务端从指定任务草稿/版本确定性生成只读拓扑，并在发布前校验配置、引用、治理和执行能力；前端只负责展示与定位错误。

## 技术设计（Contract-first）

- **输入**：`taskId`、`view=DRAFT|ACTIVE` 或 `revisionNumber`、`expectedPlanChecksum`。
- **投影**：从 source/destination.assetRef/mappings/schedule/postIngestionQuality 生成稳定 node/edge ID；拓扑为 `数据源 → 写入目标 → 更新资产证据 → 接入后质量验证? → 完成`，不读取 React Flow store 或 graphDsl。
- **输出**：`TopologyProjection(taskId, revisionNumber, planChecksum, projectionVersion, nodes, edges)`。
- **校验层次**：连接可达、源/目标对象存在、mapping 类型与必填、writeMode 能力、Cron/时区、目标资产可解析、质量引用同资产且有已发布启用规则、权限、分类密级、配置大小。
- **错误**：每项包含 `code, severity, fieldPath, step, message`；可选 `projectionNodeId` 只用于高亮，不成为业务身份。
- **确定性**：相同 canonical task design + projectionVersion 产生相同 nodes/edges/checksum；无坐标持久化。

## UI 交互规格

- 右侧拓扑只支持缩放、适配画布和点击节点定位表单步骤；禁止拖拽、连线和节点新增。
- 保存后刷新 DRAFT 投影；运行 Tab/历史版本可请求 ACTIVE/revision 投影。
- 校验错误同时显示页面摘要、步骤字段和拓扑节点高亮。
- 资产证据节点表达成功写入后对既有 canonical identity 的观察/血缘更新，不负责新建第二身份，也不宣称已经通过质量；质量节点标题固定为“接入后质量验证”。
- 无任务显示说明性空态；旧 graphDsl 可提供“导出历史草稿”入口，但不可加载为发布设计。

## 验证（RED→GREEN）

- [ ] 同 design 重复投影 100 次输出一致；字段顺序变化不影响 checksum。
- [ ] 连接失败、失效对象、mapping 错误、非法 Cron、目标资产未解析、跨资产质量引用、无有效规则、越权、密级不满足分别返回稳定 422/403。
- [ ] 前端无法通过构造 node/edge 请求改变任务配置。
- [ ] DRAFT 与 ACTIVE revision 投影可同时查看且身份不混淆。
- [ ] 大任务预算、外部连接超时和错误脱敏满足 NFR。
- [ ] Chrome 95 下拓扑缩放、适配、错误定位无阻断 console/network 错误。

## Definition of Done

- [ ] UI：只读状态不可误操作，四态和字段定位证据齐全。
- [ ] 切片：金丝雀任务的 design、projection、validation 使用同一 plan checksum。
- [ ] 切片：投影资产/质量节点与 design 的 destination.datasetId 一致，预检查结果不生成正式质量证据。
