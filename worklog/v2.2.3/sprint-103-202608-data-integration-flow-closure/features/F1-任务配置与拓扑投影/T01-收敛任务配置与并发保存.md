# T01：收敛任务配置与并发保存

**优先级**：P0
**状态**：`IMPLEMENTED_AND_DEPLOYED`
**依赖**：F0/T02 的 `IngestionTaskDesign` 与并发契约

## 目标

用户通过复用的类型化表单读取和保存一个明确 taskId 的配置草稿，保存失败或并发冲突时不覆盖任务其他字段、不串任务、不丢输入。

## 技术设计（Contract-first）

- **输入**：`taskId: long`、`If-Match: planChecksum`、F0 冻结的 source/destination.assetRef/mappings/schedule/postIngestionQuality；兼容字段 `qualityPolicyRef` 由服务端从目标 dataset 派生/校验。
- **输出**：`IngestionTaskDesign`，包含当前 revision state、目标资产解析结果、正式规则数量、新 `planChecksum`、更新时间与未执行校验状态。
- **数据流**：页面任务选择 → platform proxy 权限/审计 → ingestion design facade → 既有 `IngestionTaskService`/revision snapshot。
- **错误路径**：字段错误 422；旧 checksum 409；任务无权限 403；不存在 404；登录过期 401；网络失败不清除当前输入。
- **复用点**：账本 C02/C05/C08；复用已有数据源、目标、mapping、schedule DTO/组件，不复制 connector schema。
- **持久化**：保存草稿不激活 revision、不发布 DAG、不运行；禁止发送完整任务对象覆盖状态或治理字段。
- **资产身份**：复用 catalog dataset 与 `CatalogAssetKey`；目标对象不存在时按 F0 冻结的声明/登记流程获取稳定 datasetId，不在页面或 ingestion 建第二套资产记录。
- **质量配置**：`enabled=true` 时只允许 `policyRef=dataset:<destination.datasetId>`，`timing=POST_COMMIT` 为服务端常量；目标未解析或无正式规则时返回稳定错误。
- **本地恢复**：如保留断网草稿，必须按 user+taskId+basePlanChecksum 分区并带过期时间；服务端仍是真源。

## UI 交互规格

1. 未选任务：显示任务选择器与“新建接入任务”，不从全局 localStorage 恢复上一任务。
2. 选中任务：页头展示名称、状态、revision；四步表单加载相同 taskId；目标步骤展示资产名称/datasetId/解析来源。
3. 修改字段：标记“未保存”；切换任务/路由/刷新前提示。
4. 保存成功：展示新 checksum 和时间，清除脏标记并刷新右侧投影。
5. 409：保留用户输入，展示当前服务端版本并提供“重新加载/复制本次修改”，不自动覆盖。
6. “接入后质量验证”只显示开关和目标资产已有规则摘要；不能切换到另一数据集，未解析目标时禁用并说明原因。

## 验证（RED→GREEN）

- [ ] 契约测试先证明完整 DTO PUT 可以误覆盖，再证明 design PUT 只改允许字段。
- [ ] 两会话同 checksum：先保存成功，后保存 409；输入可恢复。
- [ ] task A → task B → task A、B 无草稿、403/404/401/网络错误不串状态。
- [ ] 目标资产不存在/越权/跨密级、无规则、构造跨 dataset policyRef 分别 fail closed。
- [ ] quality disabled/enabled 会改变 plan checksum；服务端常量 timing 不接受客户端篡改。
- [ ] UI 四态和脏数据保护组件测试。
