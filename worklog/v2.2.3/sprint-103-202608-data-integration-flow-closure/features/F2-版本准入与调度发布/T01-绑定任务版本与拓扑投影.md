# T01：绑定任务版本与拓扑投影

**优先级**：P0
**状态**：`IMPLEMENTED_AND_DEPLOYED`
**依赖**：F1/T02 的 canonical design、validation 与 topology projection

## 目标

把一份已校验任务配置固定到不可变 revision/runtime snapshot，并让 ACTIVE 拓扑和后续 execution 可证明来自该版本，而不是浏览器草稿。

## 技术设计（Contract-first）

- **canonical plan**：由现有 task source/destination.assetRef/mappings/schedule/postIngestionQuality/qualityPolicyRef 规范化；不包含 UI 坐标、折叠状态或 graphDsl。
- **身份**：`planChecksum = hash(canonicalPlan + planSchemaVersion)`；算法、字段顺序和空值规则版本化。
- **snapshot**：revision/runtime snapshot 保存或可确定性重建 canonical plan、schema version 与 checksum；凭据继续安全物化，不进入摘要输入明文。
- **projection**：ACTIVE topology 只从指定 revision plan 生成；最新 DRAFT 不影响历史版本或运行中实例。
- **execution**：新 execution 写入 taskId、revisionNumber、planChecksum，并冻结 destination dataset 与 post-quality 引用；旧数据可空兼容。
- **迁移**：采用 expand/contract；是否新增显式列由实际查询/索引证据决定，禁止为了图新建 workflow schema。

## 错误路径

- 校验完成后草稿变化：准入返回 `TASK_DESIGN_CONFLICT`/409。
- 引用对象或密级在准入前变化：重新校验并拒绝，不使用旧缓存。
- 目标资产已删除、不可见或 `qualityPolicyRef.datasetId != destination.datasetId`：拒绝准入，不生成 revision/DAG。
- checksum 算法版本未知：旧 revision 保持可读，禁止错误重算覆盖。
- snapshot 写入失败：事务回滚，不生成可激活 revision。

## 验证（RED→GREEN）

- [ ] 同 canonical plan 重复摘要 100 次一致；字段顺序、空值、时区和 mapping 顺序规则有黄金样本。
- [ ] DRAFT 修改不会改变 ACTIVE projection；历史 revision 投影稳定。
- [ ] source/destination.assetRef/mapping/schedule/post-quality 任一执行字段变化产生新 checksum；UI-only 字段不影响摘要。
- [ ] 旧 graphDsl/null/旧 revision 可读，不能改变 canonical plan 或发布结果。
- [ ] execution/revision/topology 三方 plan checksum 一致性有集成测试。
- [ ] design/revision/runtime snapshot/execution 的 datasetId 与 qualityPolicyRef 四方一致；客户端不能通过兼容字段覆盖服务端解析结果。
- [ ] 日志、审计和 toString 不输出凭据或完整敏感配置。

## Definition of Done

- [ ] 架构：checksum、snapshot、migration 和兼容测试通过。
- [ ] UI：DRAFT/ACTIVE/历史拓扑身份清晰，无“最新草稿即运行版本”误导。
- [ ] 切片：金丝雀 revision 与投影可用 SQL/API 交叉证明一致。
- [ ] 证据进入 `it/IT-02-projection.md` 与 `it/IT-03-release.md`。
