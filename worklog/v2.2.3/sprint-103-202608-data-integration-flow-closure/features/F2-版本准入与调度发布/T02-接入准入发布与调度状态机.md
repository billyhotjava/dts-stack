# T02：接入准入发布与调度状态机

**优先级**：P0
**状态**：`IMPLEMENTED_AND_DEPLOYED`
**依赖**：F2/T01 的 revision/plan checksum 契约

## 目标

复用现有 admission 和 DAG 原子发布链，把指定 plan checksum 安全激活，并提供只作用于当前任务 owned DAG 的幂等启用/暂停命令。

## 技术设计（Contract-first）

- 扩展既有 `/admit`，要求 `X-Expected-Plan-Checksum` 与当前 VALID design 一致；旧客户端兼容策略由 F0/T02 冻结。
- 复用 staged DAG、post-commit reconcile、atomic publish、revision activate；禁止建立第二套 publish service。
- 准入只验证并冻结“接入后质量验证”配置，不同步执行正式质量规则；正式触发属于每个 execution 数据提交后的 after-commit 动作。
- DAG metadata 至少携带 taskId、revisionNumber、planChecksum，便于对账；凭据仍由 runtime snapshot 安全物化。
- DAG/runtime snapshot 携带冻结的 destination datasetId 与 qualityPolicyRef；DAG 只回传 execution 结果，不成为质量 workflow owner。
- 暂存、发布、激活任一步失败时保持旧 ACTIVE revision/DAG 可运行，并产生可恢复补偿记录。
- `schedule/enable|pause` 从 task/revision 解析 owned DAG，不接受请求体 dagId；命令携带幂等键。
- 现有权限只有 `read/write/export`；发布/调度沿用服务端 write 门禁并在 UI/文档显式说明，不伪造细粒度权限。

## UI 交互规格

- “提交发布”前展示任务、版本、plan checksum 和变更摘要；checksum 变化则要求重新校验。
- 发布进度映射 PREPARING/STAGED/PUBLISHED/ACTIVE 或冻结后的等价状态。
- 启用/暂停按钮消费真实状态；处理中禁止重复提交，失败保留原状态并显示 correlationId。
- 任何情况下不允许用户输入或替换 dagId。

## 验证（RED→GREEN）

- [ ] 保存后再修改的旧 checksum 无法准入，不产生半激活版本。
- [ ] 故障注入覆盖 DAG 暂存、Airflow 发布、数据库激活和补偿重试。
- [ ] 启用/暂停重复提交只产生一个最终状态和一组关联审计。
- [ ] 跨任务 dagId 注入无输入面；无 task write 权限返回 403。
- [ ] 发布后 revision、ACTIVE projection、DAG metadata 和页面 checksum 一致。
- [ ] 准入期间没有创建 quality workflow/run；只有成功 execution 的 after-commit 路径可触发。
- [ ] 新版本发布失败时旧 ACTIVE revision 继续运行，回滚证据完整。

## Definition of Done

- [ ] 架构：admission、事务补偿、幂等和 owned-DAG 契约测试通过。
- [ ] UI：保存/校验/发布/启停的空、加载、错误、成功状态均有证据。
- [ ] 切片：金丝雀真实发布、暂停、启用一次，未影响其他 DAG。
- [ ] 证据进入 `it/IT-03-release.md`。
