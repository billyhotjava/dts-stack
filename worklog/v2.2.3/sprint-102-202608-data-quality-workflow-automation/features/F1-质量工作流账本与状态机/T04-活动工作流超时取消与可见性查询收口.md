# T04：活动工作流超时、取消与可见性查询收口

**优先级**：P1  
**状态**：DONE  
**依赖**：F1/T01～T03

## 目标

失联规则执行不能永久占用活动策略；授权用户可以取消等待，且部门用户的工作流列表先按资产权限过滤再应用数量上限。

## 技术设计（Contract-first）

- `POST /api/governance/quality/workflows/{id}/cancel`：仅 `QUEUED/RUNNING` 可取消，返回 `QualityWorkflowRunDto(status=CANCELLED)`。
- 默认超时：`dts.platform.governance.quality.workflow-timeout-seconds=1800`；超时转 `BLOCKED`，`errorCategory=WORKFLOW_TIMEOUT`。
- 取消只终止工作流等待并释放活动策略约束；已提交执行器的规则事实仍保留，不伪造为失败。
- 列表查询先限定可读 `datasetId` 与可选状态，再执行 `limit<=200`。
- 审计：`GOV_QUALITY_WORKFLOW_CANCEL`；超时复用 `GOV_QUALITY_WORKFLOW_FINALIZE`。

## 验证（RED→GREEN）

- [x] 超时活动工作流转 `BLOCKED` 并写终态审计。
- [x] 取消活动工作流成功，重复取消返回冲突。
- [x] 不可见数据资产不会挤占部门用户的列表上限。

- [x] 服务、资源与查询测试通过；审计字典登记完成。
- [x] F5/T04 提供取消、自动刷新和终态反馈。
