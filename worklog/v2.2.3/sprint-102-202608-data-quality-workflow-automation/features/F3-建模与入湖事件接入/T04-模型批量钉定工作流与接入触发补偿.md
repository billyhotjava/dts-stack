# T04：模型批量钉定工作流与接入触发补偿

**优先级**：P1  
**状态**：DONE  
**依赖**：F2/T04

## 目标

一次模型质量命令只产生一个聚合工作流；数据接入后的质量触发失败有持久状态和有限次自动补偿。

## 技术设计（Contract-first）

- 模型工作流 `contextJson` 保存全部 `{ruleId, ruleVersionId, bindingId}`；一个 candidate command 对应一个 workflow 和 N 个规则运行。
- 所有钉定绑定必须属于同一候选数据资产；跨资产证据返回稳定 blocker，不静默拆分。
- 模型进入 `QUALITY_RUNNING` 后若工作流未能启动，返回 `MODEL_SPEC_GOVERNANCE_QUALITY_START_FAILED`，保留显式重试入口。
- 接入成功事务先登记 `PENDING`，提交后转 `TRIGGERING` 并调用平台；成功为 `TRIGGERED`，失败为 `RETRY_WAIT`，第三次失败为 `EXHAUSTED`。
- `prepare/complete/fail` 各自使用 `REQUIRES_NEW` 和执行记录行锁；Airflow 在事务提交后触发，进程中断由 `PENDING/TRIGGERING/RETRY_WAIT` 调度补偿。
- 使用原 execution identity 作为稳定幂等身份，最多尝试 3 次；任何质量状态都不改写接入成功事实。

## 验证（RED→GREEN）

- [x] 两条钉定规则产生一个工作流和两条关联运行。
- [x] 自动启动失败对 UI 返回稳定错误，不只写日志。
- [x] 接入成功先持久化 `PENDING`；启动失败落 `RETRY_WAIT`，到期补偿后转 `TRIGGERED`，第三次失败转 `EXHAUSTED`，且不改变接入成功状态。
