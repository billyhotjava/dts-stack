# T01：实现默认业务分类与业务过程的端到端简化

**优先级**：P0

**状态**：IN_PROGRESS

**依赖**：F1/T01、F4/T01

## 实施目标

让单研究所用户在日常规划和建模中主要操作数据域：业务分类由规划策略提供默认值，业务过程仅在事实模型/原子指标无法唯一推导时要求人工选择，同时保留完整治理关系、兼容性、审计和引用保护。

## Contract-first

- **UI**：将现有“规划参数配置”占位页接入真实规划策略 API；默认隐藏业务分类；`AUTO_SELECT_SINGLE` 下仅在零过程/多过程时显示引导或选择器，`MANAGED` 下始终显示选择器。
- **API**：兼容扩展既有 `GET/PUT /api/modeling/warehouse-plans/{id}/baseline/policy`，新增 `businessCategoryMode`、`defaultBusinessCategoryId`、`businessProcessMode=AUTO_SELECT_SINGLE|MANAGED`；不新增平行设置接口。
- **Service**：扩展 `WarehousePlanContract` 和 `WarehousePlanApplicationService`；分类校验走现有架构字典 read port，默认过程写入只走 `BusinessProcessApplicationService`。
- **Data**：在 `modeling_warehouse_plan_policy` Expand 新列并提供旧行默认值；不得新建分类、过程或来源映射平行表。
- **Migration**：先 Expand、回填可唯一确定的默认分类和模式，再切换消费者；无法唯一回填的计划登记为 issue/阻断配置，不按名称猜测。
- **Compatibility**：旧请求缺少新字段时保持既有行为；旧响应字段不删除；默认分类变更不追溯改写历史对象。

## 业务规则与错误契约

| 规则 | 预期结果 |
|---|---|
| 默认分类不在当前计划、跨租户、非根或已停用 | 保存失败，返回可定位字段 `defaultBusinessCategoryId` 的业务错误 |
| `SINGLE_DEFAULT` 未配置且无法唯一推导分类 | 建模提交失败，提示先完成规划参数配置 |
| 切换默认分类 | 仅更新策略版本；历史数据域/模型保持原分类 ID |
| 创建数据域重试 | 分类绑定幂等；不创建或确认泛化业务过程 |
| FACT/ATOMIC 无有效过程 | 阻断并提示先定义有事件和粒度的业务过程 |
| FACT/ATOMIC 只有一个有效过程 | `AUTO_SELECT_SINGLE` 自动选择稳定 process ID；`MANAGED` 仍需人工确认 |
| FACT/ATOMIC 有多个有效过程 | 未选择时阻断，选择后校验同域且有效 |
| DIM/汇总/应用模型 | 不要求也不展示业务过程 |
| 删除被引用过程 | 拒绝物理删除，返回引用对象摘要；允许按规则停用 |

具体错误码在编码前由实施 session 沿用 `WAREHOUSE_PLAN_*`、ModelSpec 和 Indicator 既有命名约定一次性冻结，并写入 API 契约测试；不得把数据库外键异常直接暴露给页面。
