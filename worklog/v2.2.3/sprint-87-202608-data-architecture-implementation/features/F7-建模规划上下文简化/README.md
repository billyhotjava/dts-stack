# F7：建模规划上下文简化

**优先级**：P0

**状态**：IN_PROGRESS

**来源**：2026-08-10 产品评审结论

## 目标

以“数据域”为日常建模的主入口，在不删除治理语义和历史引用的前提下，默认隐藏业务分类，并在业务过程可唯一确定时自动选择，减少重复选择和上下文冲突。

交付后，单研究所场景默认只需维护数据域；业务分类初始为“研究所业务”，仅在“规划参数配置”中按需变更。业务过程继续作为事实模型和原子指标的治理依据：一个数据域只有一个已确认过程时由系统自动选择并隐藏，存在多个过程时要求用户明确选择，没有过程时引导先定义真实业务活动。

## 决策边界

1. **业务分类保留，不物理删除**：它仍是数据域的上级治理范围、权限/指标兼容上下文和历史稳定 ID。默认采用单分类模式，日常建模表单不再重复选择。
2. **数据域成为可见主对象**：建议按研究项目、产品技术、物料供应、质量、财务、组织人员、考勤工时等业务能力划分；不得按 ERP、PLM、QMS、财务、考勤系统机械地“一系统一域”。
3. **来源系统与数据域是多对多**：一个系统可服务多个域，一个域也可汇聚多个系统；复用既有 `SourceBusinessMapping`，不得另建映射台账。
4. **业务过程保留但简化选择**：事实模型和原子指标仍必须落到真实业务活动；维度、维度表、汇总及应用模型不展示业务过程选择。禁止把 `<domainCode>_default` 之类泛化占位直接确认为业务过程。
5. **不新增平行 owner**：规划参数扩展既有仓库规划策略，业务分类复用架构字典 owner，业务过程复用 `BusinessProcessApplicationService` 及现有台账。

## 目标交互

| 场景 | 用户看到的内容 | 系统行为 |
|---|---|---|
| 初始使用 | 数据域，不显示业务分类 | 使用默认分类“研究所业务”创建/归属数据域 |
| 规划参数配置 | 默认业务分类、业务分类模式、业务过程模式 | 通过既有规划策略 API 保存并进行版本并发控制 |
| 新建数据域 | 域编码、名称、说明等业务字段 | 自动绑定当前默认业务分类；不伪造已确认业务过程 |
| 维度/维度表/汇总/应用建模 | 不显示业务过程 | 从数据域或集市/主题上下文派生分类，不写冲突上下文 |
| 事实模型/原子指标 | 单一有效过程时不显示；多个过程时显示选择器 | 唯一时自动绑定；无法唯一确定时阻止提交并要求选择 |
| 接入 ERP/PLM/QMS/财务/考勤 | 来源系统和数据域映射 | 允许多对多，并可选绑定业务过程，不创建同名“系统数据域” |

## 规划参数契约

沿用：

- `GET /api/modeling/warehouse-plans/{id}/baseline/policy`
- `PUT /api/modeling/warehouse-plans/{id}/baseline/policy`
- `If-Match`/版本号及既有 `POLICY` edit unit

对 `PlanningPolicyCommand` / `PlanningPolicyView` 兼容新增以下字段，旧客户端不传时使用默认值：

| 字段 | 类型/枚举 | 默认值 | 语义 |
|---|---|---|---|
| `businessCategoryMode` | `SINGLE_DEFAULT` / `MULTI_SELECT` | `SINGLE_DEFAULT` | 单默认分类或显式多分类 |
| `defaultBusinessCategoryId` | UUID | 当前计划中唯一有效根分类 | 新对象自动归属的业务分类稳定 ID |
| `businessProcessMode` | `AUTO_SELECT_SINGLE` / `MANAGED` | `AUTO_SELECT_SINGLE` | 唯一过程自动选择或始终人工选择 |

约束：默认分类必须是同租户、当前计划范围内、有效且未停用的根分类。无法唯一推导默认分类时，策略保存或建模提交必须返回明确业务错误，不得按名称猜测。

## 变更语义

- 修改默认分类名称：保持同一 ID，只改变展示，无数据迁移。
- 切换默认分类：只影响之后新建的数据域/集市等对象，不追溯搬迁历史对象。
- 搬迁既有对象：必须走独立显式操作，先展示影响范围，再确认执行；记录操作者、前后分类 ID、原因和时间，并提供按批次回退证据。
- 新建数据域不会自动确认泛化过程；空域在创建 FACT/原子指标时提示先定义能表达事件和粒度的真实业务活动。
- `AUTO_SELECT_SINGLE` 下，一个域只有一个已确认有效过程时，事实模型/原子指标自动选择；存在多个有效过程时必须由用户明确选择。
- `MANAGED` 下，即使只有一个有效过程也显示选择器并要求人工确认。
- 删除过程：草稿且未引用可删除；已确认且未引用只能停用；被模型、指标或来源映射引用时禁止物理删除，只能停用。每个有效数据域至少保留一个有效过程，默认且被引用的过程不得删除。

## 项目域业务过程基线

业务过程按“独立业务事件 + 独立事实粒度”拆分，不按 ERP、PLM、QMS 等来源系统拆分。项目域可按实际数据逐步启用：

| 过程编码示例 | 过程名称 | 事实粒度示例 |
|---|---|---|
| `project_initiation` | 项目立项 | 一次项目立项/审批事件一行 |
| `project_plan_change` | 项目计划变更 | 一个计划版本或变更单一行 |
| `project_execution_snapshot` | 项目执行快照 | 一个项目或项目任务每天一行 |
| `project_milestone_acceptance` | 里程碑验收 | 一次里程碑验收事件一行 |
| `project_risk_handling` | 项目风险处置 | 一条风险或一次状态变化一行 |
| `project_closure` | 项目结项 | 一次项目结项事件一行 |

现有“项目健康监测”仅在其事实粒度确为项目每日快照时保留，并建议改名为“项目执行快照”；若混合立项、风险、里程碑等多种粒度，则必须拆分。财务成本和质量问题分别由财务域、质量域负责，项目应用层组合跨域结果。

## Feature DoD

- [ ] “规划参数配置”可读取/保存三个新增策略字段，旧请求与旧数据无损兼容，冲突更新返回既有版本错误。
- [ ] 默认分类只对新对象生效；历史对象搬迁不被策略保存暗中触发。
- [ ] 数据域创建可自动绑定默认分类，但不会自动确认泛化业务过程；空过程域具有明确引导。
- [ ] 事实模型和原子指标满足“唯一自动、多项必选”；其他模型类型不要求业务过程。
- [ ] 来源系统与数据域支持多对多，未出现“一系统一域”的新增约束或第二套映射表。
- [ ] 过程停用/删除具有引用保护、明确错误、权限负向测试和审计记录。
- [ ] 单元、API、迁移、前端 source-contract、Chrome 95 和真实菜单旅程分别留证；本 Feature 未完成前不得标记 Sprint 为 CODE_COMPLETE。

## 非目标

- 不删除业务分类、业务过程或旧 API/字段。
- 不引入新的规划空间台账；当前仍使用既有单空间/当前计划上下文。
- 不在本 Feature 中重划研究所全部数据域，只提供可演进的默认机制。
- 不以来源系统替代业务能力建模，也不自动搬迁历史对象。
- 不把“项目健康监测”等应用分析主题无条件当作单一业务过程；业务过程必须能说明事件与事实粒度。
