# Sprint-72: 数据密级全生命周期与不可降级传播闭环

**时间**: 2026-07
**状态**: IN_PROGRESS
**类型**: P0 Implementation Epic / Data Governance / Security / Full-stack / Cross-service
**目标**: 在数据首次落盘前封存来源密级，沿字段血缘、资产血缘和消费引用自动传播最高密级，保证全链路只能升密不能降密，并把创建、存储、使用、共享、归档、临时销毁和永久销毁纳入可审批、可监控、可审计的生命周期闭环。

## 背景

当前系统已经存在密级枚举、数据集密级、表级覆盖、字段敏感标签、API/数据产品/报表/大屏密级、查询权限校验和生命周期申请等能力，但没有统一的密级事实与传播契约：

- JDBC、ODS、Excel/CSV 等接入路径大量使用默认 `INTERNAL`，未在首次落盘前形成来源声明和封存证据。
- `CatalogColumnSchema` 只有 `sensitiveTags`，缺少字段级声明密级和有效密级。
- `CatalogDataset.classification`、`CatalogTableSchema.classification` 以及不同消费资产的 `classification` 都可被各自写入口直接覆盖。
- OpenLineage、dbt 和数据集/字段血缘已经存在，但没有在血缘写入或变更时统一执行最高密级传播。
- Sprint-24 的大屏密级由用户创建时手工选择，且目前仍允许填写原因后降密；这与“来源密级不可覆盖、有效密级只能升不能降”的新规则冲突。
- 大屏可以引用 card、metric、dataset、SQL、API 和 database 等多类数据源，但目前没有服务端统一计算“所有展示数据的最高密级”。
- 生命周期申请只覆盖归档、处置和延期；使用/共享审批在另一套服务中，创建/存储准入、临时销毁恢复、永久销毁证明和生命周期专项统计仍不完整。

本 Sprint 不把密级当作普通标签，也不继续扩张散落的可编辑字段，而是建立不可变密级事实、追加式变更事件和兼容投影。

## 已确认业务规则

1. 数据源字段声明的密级、Excel/CSV 文件声明的密级和字段声明的密级均属于来源事实，封存后不可覆盖。
2. 有效密级只能升高，不能降低；重新计算公式为：

   `effective = max(previousEffective, declared, detected, allUpstreamEffective)`

3. 文件级密级默认作用于文件内全部字段；字段可以升到更高密级，但不能低于文件密级。
4. 派生字段取所有输入字段最高密级；无法解析字段血缘时，保守继承所有上游资产最高密级。
5. 资产级有效密级取所有字段和所有上游资产的最高密级。
6. API、数据产品、报表、指标、Card 和大屏等消费资产继承其全部数据来源的最高密级，可额外设置更高的人工下限，但不能覆盖为更低值。
7. 大屏有效密级取全部页面、组件、下钻层级和运行时数据来源的最高密级；服务端是最终裁决方。
8. 上游升密后，下游资产自动升密，并立即影响查询、分享、公开链接、导出、缓存和访问授权。
9. 归档、临时销毁和永久销毁都保留密级事实、审批、血缘摘要和销毁证明；永久销毁只处理 DTS 管理的数据副本，不越权删除外部源系统原始数据。
10. 数据标签与密级继续严格分离；Sprint-71 的标签目录和资产打标不参与合规密级计算。

## 架构边界

- `dts-common` 只持有稳定的四级枚举、排序和 `max` 规则，不承载业务持久化或传播编排。
- `dts-platform` 是密级事实、字段/资产血缘传播、生命周期状态和跨资产查询的控制面真源。
- 现有各表的 `classification` 字段保留为兼容投影，逐步改为由事实服务写入；不得继续作为可任意修改的独立真源。
- `dts-ingestion` 负责携带接入密级契约和运行证据，首次落盘准入由平台控制面裁决。
- `dts-analytics` 负责解析大屏引用并提交可验证来源集合；最终有效密级由服务端根据平台密级事实计算。
- OpenMetadata 继续作为技术元数据引擎或缓存，不成为 DTS 密级与生命周期的业务真源。
- 永久销毁仅由显式存储适配器执行。外部 JDBC/MySQL/达梦源表只解除接入、删除 DTS 副本并留证，不从 DTS 反向 DROP 客户源表。

## 工作量结论

- 总工作量：约 **80～103 人日**，属于跨服务实施 Epic，不是普通两周小 Sprint。
- 单人串行：约 16～21 周。
- 推荐配置：2 名后端、1 名前端、1 名测试/运维按阶段投入，约 6～8 个自然周。

  - `CatalogDataset`：`CRITICAL`，86 个直接影响点。
  - `CatalogLifecycleRequestService`：`LOW`，适合作为生命周期编排扩展入口。
  - `ScreenResource`：图索引显示 `LOW`，但它的 JSON 数据源引用和跨服务同步需要单独契约测试，不能据此低估业务风险。

## 非目标

- 不新增第五种密级，不改变 `PUBLIC < INTERNAL < SECRET < CONFIDENTIAL` 四级语义。
- 不允许普通编辑、审批理由或管理员旁路直接降低有效密级。
- 不把脱敏等同于降密；脱敏数据仍保留原密级来源，若未来需要解密/降密，必须另立有法规依据的专项流程。
- 不由 DTS 删除外部业务系统的源表或源文件。
- 不在本 Sprint 顺带修复资产台账分页数量或业务数据标签 404；这些问题继续作为独立缺陷处理，避免污染本 Sprint 范围。

- [ ] 所有来源声明、识别结果、继承结果和人工升密均形成不可变证据与追加事件。
