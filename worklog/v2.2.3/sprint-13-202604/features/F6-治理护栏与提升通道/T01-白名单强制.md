# T01: 白名单强制 + 角色权限细化

**优先级**: P0
**状态**: READY
**依赖**: F2, F5

## 目标

把"只有 dbt 能定义原子指标 / 只有白名单路径能 join"的不变量在**多个入口**强制：
- 前端 UI 不暴露原子指标创建按钮
- 后端 REST 对涉及原子指标创建/修改的请求 403
- 画布受控 drop（已在 F5/T03 做，本 Task 加后端兜底）
- 角色区分三类用户的能力

## 技术设计

### 1. 角色定义对齐

沿用现有 Keycloak 角色（Sprint-11 后已统一到 OP_ADMIN 等）：

| Keycloak 角色 | BI 层权限 |
|---|---|
| `OP_ADMIN` | 全部（含审计旁路） |
| `BI_DATA_ENGINEER` | 看所有 + 改 dbt（git PR），不从 UI 改指标 |
| `BI_ANALYST` | 拖画布 / 建 Card / 建 VDS / 改派生指标 / 订阅 |
| `BI_CONSUMER` | 只读 Dashboard，不访问 Card Editor |
| 无以上 | 登录即 0 权限 |

若 Keycloak 里角色和 BI 预期不完全对齐：本 Task 在 `KeycloakRoleMapper` 里加一层映射 + `application.yml` 可配置。

### 2. 前端 RoleGuard

CardEditor 进入前检查：
```tsx
<RoleGuard require={["BI_ANALYST", "BI_DATA_ENGINEER", "OP_ADMIN"]}>
  <CardEditorLayout ... />
</RoleGuard>
```

`BI_CONSUMER` 直接跳 `/bi/explore`（只读）+ toast 提示。

菜单项按角色过滤：
- `/bi/card/new` 对 consumer 不显示
- `/bi/virtual-datasets/new` 同上

### 3. 后端 Endpoint Guard

所有修改类 endpoint 加 `@PreAuthorize`:

```java
@PostMapping("/api/semantic/virtual-datasets")
@PreAuthorize("hasAnyRole('BI_ANALYST', 'BI_DATA_ENGINEER', 'OP_ADMIN')")
public VirtualDatasetDTO create(...) { ... }

@PostMapping("/api/semantic/virtual-datasets/{id}/promote")
@PreAuthorize("hasAnyRole('BI_DATA_ENGINEER', 'OP_ADMIN')")   // 仅工程师可 promote
public PromoteResult promote(...) { ... }
```

`IndicatorDefinitionService` 里原子指标 update:

```java
public Indicator update(UpdateRequest req) {
    Indicator existing = repo.findById(req.id()).orElseThrow();
    if (existing.isSyncedFromDbt()) {
        throw new AccessDeniedException("原子指标通过 dbt 管理，请提交 PR");
    }
    // ...
}
```

### 4. 后端 Join 白名单兜底

F3/T02 `MultiModelCompiler` 已经校验，但为**深度防御**再加：

- `SemanticQueryResource.query()` 入口先过 `JoinWhitelistValidator`
- Validator 查 `JoinGraphRegistry.directEdge(from, to).isPresent()`
- 不通过直接 422 + 错误码 `JOIN_NOT_WHITELISTED`

Validator 单独存在是为了：日志 / 审计打点位置统一，而不是和编译逻辑耦合。

### 5. 审计日志

本 Sprint 涉及的所有敏感动作入审计表：

| 动作 | 审计 key |

走现有 `AuditLogService`。

### 6. 失败提示本地化

前端收到 403/422 统一走一个 `useBiErrorHandler` hook，按错误码出中英文 toast：

```
JOIN_NOT_WHITELISTED  → "无法 join：两表之间未声明 join 关系。请联系工程师在 dbt 中声明。"
SECURITY_LEVEL_EXCEEDED → "数据密级超出你的访问上限。"
ATOMIC_METRIC_READ_ONLY → "原子指标在 dbt 中管理，请通过工程师提交 PR。"
```

### 7. 兼容老路径的过渡

`IndicatorsPage.tsx` 的老 Modal 代码保留但不暴露按钮。Sprint-14 再清理。

本 Sprint 任何新代码路径都不允许从 UI 创建原子指标；老已存在的 UI 指标（Sprint-5 `DbtIndicatorGenerator` 生成过）保留读不改。
