# T03: 模型画布（ReactFlow）+ 受控 join 连线

**优先级**: P0
**状态**: READY
**依赖**: T01, F3/T01

## 目标

实现 CardEditor / VirtualDataset Editor 中间栏的**模型画布**。用户拖 model 到画布上，系统自动展示可连接的 join target（亮色 outline），用户点击即创建 join。**所有 join 路径限定在 JoinGraphRegistry 白名单内**，用户无法拖出任意 join。

## 技术选型

**ReactFlow `^10.x`**（MIT 许可）— **锁 v10，不升 v11**。理由：
- 社区成熟（ETL / workflow 场景广泛应用）
- 自带 pan/zoom/minimap/控制栏
- 节点和边完全 customizable
- 性能好（内部 virtualization）
- 体积 ~50KB gzipped

### ⚠️ Chrome 95 兼容锁定（客户环境硬约束）

客户浏览器 Chrome 95 不支持 `@container queries`（Chrome 105+ 才支持）。ReactFlow **v11** 内部使用了 container queries 做节点尺寸响应，会在 Chrome 95 出现节点错位或不渲染。

**约束**：
- `package.json` 固定 `"reactflow": "^10.4.0"`（或当时 v10 最新）
- 升级到 v11 必须同时做 Chrome 95 实机验证（见 `it/README.md` 第九节 TC-CR-03）
- 合并 PR 前跑 `grep -rn '@container\|:has(' node_modules/reactflow/` 必须无命中

**候选 antv/x6**：中文社区活跃但 API 庞大，学习曲线高，抛弃。
**候选自研 SVG**：工作量大，wheel 不重造。

## 技术设计

### 1. 画布状态

```ts
type CanvasState = {
  nodes: CanvasNode[];
  edges: CanvasEdge[];
  selectedNodeId?: string;
  selectedEdgeId?: string;
};

type CanvasNode = {
  id: string;                    // 同 model name
  type: "model";
  position: {x: number; y: number};
  data: {
    modelId: string;
    label: string;
    subjectArea: string;
    securityLevel: SecurityLevel;
    isBase: boolean;             // base model 有特殊标识
    fanoutBadge: boolean;
  };
};

type CanvasEdge = {
  id: string;
  source: string;                // from model
  target: string;                // to model
  data: {
    joinType: "many_to_one" | "one_to_many" | ...;
    fanoutWarning: boolean;
    approvalRequired: boolean;
    onClauseRendered: string;    // 展示用
  };
  style: {...};                  // 1:N 用红虚线，M:1 用灰实线
};
```

### 2. 画布交互

**添加 model**：
- 从左栏树把 model 拖到画布
- 自动分配位置（初始 base model 居中，后续右侧展开）
- 若画布已有 base，新加的 model 必须与现有某节点有 join 关系（否则拒绝 drop + toast）

**添加 join**：
- 方式 A：用户把 model B 拖到 model A 附近，系统自动检测"A 能否 join 到 B"，可则自动连线
- 方式 B：点击 A 节点，系统亮出所有可 join 的目标虚影，用户点击即连
- **绝不允许**用户手动在两个任意节点间画线。没有声明的 join 不存在"尝试"的可能。

**删除**：
- 删 edge：移除 join
- 删 node：如果是 base，整个画布重置；如果是 join 进来的，一并删除涉及该节点的 edge 和相关 measure/dimension/filter

### 3. 白名单强制

```ts
function canDrop(sourceModel: string, targetModel: string, graph: JoinGraph): boolean {
  return graph.directEdge(sourceModel, targetModel) !== null;
}

function onDrop(payload) {
  if (!canDrop(...)) {
    toast.warning("无法 join：两表之间未声明 join 关系。请联系工程师在 dbt 中声明。");
    return;
  }
  // ...
}
```

**不可 join 的节点**在拖拽 hover 时给红色边框 + 禁止 cursor。

### 4. fanout 警告 UI

1:N join 的 edge 用**红色虚线**，edge 上标一个 ⚠ 图标。Click 弹窗：

```
⚠ 此 Join 会产生 1:N 扇出
系统将自动采用对称聚合（Symmetric Aggregate）改写 SQL，
以保证你的 metric 不被重复放大。

SQL 会比预期更复杂，可在"SQL 预览"查看。

[我知道了] [改用其他 Join]
```

### 5. approval_required 交互

若 edge 的 `approval_required = true` 且当前用户无对应权限：
- edge 显示为灰色虚线 + 🔒 图标
- 不可 drop
- Tooltip："该 Join 需要审批，点击申请"
- 点击跳转到审批流（复用现有 `GovIndicatorReview` 或同类）

### 6. 画布 → 请求

画布状态 → F1/T04 的 VirtualDataset 片段（`base` + `joins`）+ F1/T02 的 QueryRequest（当只在 CardEditor 中使用时）。

```ts
function canvasToQuery(state: CanvasState): Pick<QueryRequest, "base" | "joins"> {
  const baseNode = state.nodes.find(n => n.data.isBase);
  const joins = state.edges.map(e => ({
    to: e.target,
    via: e.data.onClauseRendered
  }));
  return { base: baseNode.id, joins };
}
```

### 7. 画布持久化

- CardEditor 模式：画布状态塞到 Card.query 里（配合 T05）
- VirtualDataset 模式：画布状态 = VDS definition.base + joins + canvas_layout.nodes

### 8. 视觉

- ReactFlow 自带 light/dark，接入现有主题 token
- node 卡片参考 antd `Card size="small"`，顶部色条按 subject_area 着色
- 密级徽章用 `Tag` 组件，颜色映射：PUBLIC=绿 / INTERNAL=蓝 / SENSITIVE=橙 / CONFIDENTIAL=红
- 可折叠：节点收起只显示 label + 密级

### 9. 可访问性

- 键盘 Tab 可切节点
- Enter 进入节点详情面板
- Delete 删除选中节点 / edge
- Esc 取消选择

### 10. 性能

- 节点数上限 10（UI 强制，超过警告用户"请拆成多个画布"）
- ReactFlow 自带虚拟化不必担心 DOM 节点数
