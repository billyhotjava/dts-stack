# T06: 存量数据迁移接口

**优先级**: P0
**状态**: READY
**依赖**: T02, T05

## 目标

提供两个超管专用迁移接口，将存量大屏数据迁移到 `analytics_screen_access` 表。所有操作幂等，可重复执行。

## 技术设计

### 接口一：迁移创建者 OWNER 记录

```
POST /api/screens/admin/backfill-owner-grants
```

遍历所有非归档大屏，根据 `analytics_screen.creator_id` 插入 OWNER 记录：

```java
for (AnalyticsScreen screen : screenRepository.findAllByArchivedFalseOrderByIdDesc()) {
    Long creatorId = screen.getCreatorId();
    if (creatorId == null) { skipped++; continue; }
    // granteeId = analytics user.id 数字字符串，无需 platform_username
    screenOwnershipService.createGrant(
        screen.getId(), "USER",
        String.valueOf(creatorId),
        "OWNER", null);  // granted_by = null（系统迁移）
    processed++;
}
```

响应：`{ "processed": 42, "skipped": 0, "total": 42 }`

### 接口二：从平台 grant 迁移授权记录（可选，历史存量）

```
POST /api/screens/admin/migrate-platform-grants
```

如果平台 grant 表中有历史大屏授权数据，此接口将其拉取并写入本地表。

流程：
1. 遍历所有大屏，调用 `GET {platform}/api/asset-grants?assetType=SCREEN&assetId={id}`
2. 对每条 grant，将 `granteeType`/`granteeId`/`permission` 翻译后写入本地表
3. `permission` 映射：`READ → VIEWER`，`EDIT → OWNER`（历史 EDIT 权限视为编辑者）
4. `granteeId` 对 USER 类型需翻译：平台存的是 Keycloak username → 查 `analytics_user.platform_username` 反查 `user.id`

此接口依赖平台可访问性，失败时只记录日志不回滚（部分迁移安全）。

**注意**：两个接口均需 `MetabaseAuth.requireSuperuser` 鉴权。
