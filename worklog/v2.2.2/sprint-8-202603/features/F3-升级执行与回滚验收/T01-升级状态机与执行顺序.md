# T01: 升级状态机与执行顺序

**优先级**: P0
**状态**: DONE
**依赖**: 无

## 目标
定义平滑升级的执行顺序，避免“先覆盖、后校验”。

## 技术设计
- 状态机建议固定为：
  - `PRECHECK`
  - `MODE_DETECT`
  - `PACKAGE_VERIFY`
  - `DB_COMPAT_CHECK`
  - `BACKUP`
  - `IMAGE_LOAD`
  - `MERGE_CONFIG`
  - `START_CONTAINERS`
  - `POSTCHECK`
  - `SUCCESS`
- 执行顺序必须是“先校验、后覆盖”：
  1. 人工停止运行中容器
  2. 读取旧目录 `.env`，识别 `LEGACY_STACK` 和 `DEPLOY_MODE`
  3. 选择 compose 主文件：
     - legacy：`docker-compose.legacy.yml`
     - normal：`docker-compose.yml` / `docker-compose-app.yml`
  4. 校验升级包 `images/`、`extra/manifest`、`checksums`
  5. 校验 PostgreSQL 数据目录兼容性
  6. 备份 `.env`、compose、`config/`、`services/dts-pg/data`
  7. `docker load` 导入新镜像
  8. 按旧值优先规则合并 `.env`、compose、`config/`
  9. 用识别到的 compose 主文件启动容器
  10. 做 postcheck，并写入 `logs/upgrade-*.summary.md`
- 阻断条件：
  - 容器未停干净
  - 离线包校验失败
  - PostgreSQL major 不兼容
  - 数据冷备失败
- summary 中必须记录：
  - 识别到的运行模式
  - 本次使用的 compose 主文件
  - PostgreSQL 版本兼容结论
  - 备份路径
  - 回滚清单路径

## 影响范围
- `bin/dts-upgrade`
- runbook
