# T02: 回滚清单与数据库恢复策略

**优先级**: P0
**状态**: DONE
**依赖**: T01

## 目标
明确升级失败时，配置回滚和数据库回滚分别如何处理。

## 技术设计
- `rollback-manifest.json` 至少覆盖两类资产：
  - 配置类：`.env`、compose、`config/`
  - 状态类：`services/dts-pg/data` 冷备目录
- 配置回滚规则：
  - 以升级前备份清单逐文件恢复
  - 对合并过程中产生的冲突备份目录一并记录
- 数据库回滚规则：
  - 仅支持停机后的整目录恢复
  - 不支持在线回滚
  - 不支持对 `services/dts-pg/data` 做局部文件拼接恢复
- 回滚触发条件：
  - 配置合并失败
  - 镜像导入失败
  - PostgreSQL postcheck 失败
  - 主容器启动后关键健康检查失败
- runbook 里必须明确：
  - 何时只回滚配置
  - 何时必须连同数据库目录一起回滚
  - 回滚后如何重新启动 legacy / normal 对应的 compose 主文件

## 影响范围
- 备份目录
- rollback manifest
- runbook
- `logs/upgrade-*.summary.md`

## 验证
- [ ] 失败场景有明确回滚动作
- [ ] 数据库回滚是整目录恢复而不是模糊描述
- [ ] legacy/normal 回滚后的启动方式有区分

## 完成标准
- [ ] 回滚路径不再停留在口头约定
- [ ] 配置回滚与数据库回滚的边界清楚可执行
