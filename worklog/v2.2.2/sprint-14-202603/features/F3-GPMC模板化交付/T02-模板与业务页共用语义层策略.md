# T02: 模板与业务页共用语义层策略

**优先级**: P0
**状态**: DONE
**依赖**: T01

## 目标
定义模板层和业务页共用语义层的策略，避免页面与模板分叉。

## 总体策略
- 模板优先，业务页复用模板语义。
- 不允许形成“两套页面指标口径 + 两套模板绑定”的双轨。
- 后端先输出页面级 view model，再由模板通过 `responsePath` 消费。

## 统一语义层分层

### L1: 源表语义层
- 9 张逻辑源表
- 5 个主题域
- 主键与次级键规则

### L2: 领域口径层
- 指标口径矩阵
- 统一枚举字典
- 时间窗口语义

### L3: 页面级 view model 层
- `StrategicOverviewVm`
- `ExecutionBoardVm`
- `QualityBoardVm`
- `TechStateBoardVm`
- `CostBoardVm`
- `RiskBoardVm`
- 各类 drill vm

### L4: 模板绑定层
- `ScreenTemplate` 布局
- 组件配置
- `responsePath`
- `jump-url`

## 页面与模板必须共用的内容

| 共享项 | 说明 |
|--------|------|
| 指标命名 | 同一 KPI 的 `id/label/unit` 必须统一 |
| 变量键 | `dateFrom/dateTo/deptId/projectNo/riskLevel` 必须统一 |
| API 路径 | 页面和模板必须消费同一组 GPMC API |
| responsePath | 模板中组件的 `responsePath` 来自页面级 view model 字段路径 |
| 下钻动作 | 模板与业务页跳同一套路由，不允许一边跳看板一边跳弹窗 |
| 字段翻译与枚举 | 风险等级、闭环状态、签署状态等统一由口径层解释 |

## 推荐落地方式

### 1. 业务页只负责三件事
- 路由承载
- 全局筛选同步
- drill 页面编排

### 2. 模板只负责三件事
- 布局
- 组件组合
- 组件与语义层字段绑定

### 3. 后端只负责语义层
- 不直接为模板写专用接口
- 不直接暴露原始表结构给模板

## 文件组织建议
- 页面语义模型：
  - `src/pages/gpmc/view-models/`
- 模板定义：
  - `src/pages/screens/gpmcTemplates/`
- 模板注册入口：
  - `screenTemplates.ts`

## 禁止事项
- 禁止在 `gpmc` 页面里直接写一套 mock-only 字段映射，而模板里再写一套真实字段映射。
- 禁止模板直接拼 SQL 或直接绑定 9 张原始表。
- 禁止页面层和模板层各自维护不同的筛选变量名。
