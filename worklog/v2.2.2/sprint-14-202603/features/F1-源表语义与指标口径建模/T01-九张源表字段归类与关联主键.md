# T01: 九张源表字段归类与关联主键

**优先级**: P0
**状态**: DONE
**依赖**: 无

## 目标
明确 9 张业务源表在执行、质量、技术状态、风险、成本五个主题域中的归属与关联主键。

## 输入依据
- 用户确认的 9 张逻辑源表：
  - 项目信息表
  - 进度跟进措施表
  - 质量信息汇总表
  - 质量跟进措施表
  - 技术状态信息汇总表
  - 技术状态跟进措施表
  - 风险信息汇总表
  - 风险跟进措施表
  - 成本核算基本表
- 字段与字典参考：
  - `worklog/v2.2.2/req/s10/project1.xlsx`
  - `worklog/v2.2.2/req/s10/project2.xlsx`
  - `worklog/v2.2.2/req/s10/project3.xlsx`
  - `worklog/v2.2.2/req/s10/project_ref.xlsx`

|---------|--------|------|--------------|------------|------------|------|

## 统一关联规则

### 1. 全局主键
- 统一以 `项目编号` 作为跨主题域主键。
- 所有战略层、管控层、执行层页面都必须接受 `projectNo` 作为最小下钻参数。

### 2. 主题域二级键
- 项目执行域：
  - `分系统/分任务`
  - `节点任务及目标`
  - `节点计划时间`
- 质量域：
  - `问题编号` 优先；若缺失则用 `项目编号 + 问题名称/问题描述 + 质量问题发生时间`
- 技术状态域：
  - `技术状态名称/代号 + 更改事项`
- 风险域：
  - `风险名称 + 风险提出时间`
- 成本域：
  - `统计周期`

### 3. 时间键
- 执行域主时间键：`节点计划时间`、`实际完成时间`
- 质量域主时间键：`质量问题发生时间`、`最后更新时间`
- 技术域主时间键：`最后更新时间`
- 风险域主时间键：`风险提出时间`、`最后更新时间`
- 成本域主时间键：`统计周期`

### 4. 跟进措施表的关联原则
- 措施表永远不单独成为大屏或看板的主对象。
- 措施表以对应汇总事实表作为父对象：
  - 质量问题 -> 质量跟进措施
  - 技术状态 -> 技术状态跟进措施
  - 风险 -> 风险跟进措施
  - 进度节点 -> 进度跟进措施
- 下钻页需要同时展示“对象基本信息 + 措施列表 + 最新状态”。

## 对后续实现的约束
- 前端页面和模板层都不能直接消费 9 张原始表。
- 后端必须先按 5 个主题域构建语义层，再输出战略层、管控层、执行层 view model。
- 如果现场源表缺少显式业务 ID，后端需要先统一生成稳定业务键，再供前端下钻使用。
