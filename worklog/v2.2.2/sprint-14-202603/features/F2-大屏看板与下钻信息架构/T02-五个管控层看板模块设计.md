# T02: 五个管控层看板模块设计

**优先级**: P0
**状态**: DONE
**依赖**: T01

## 目标
固定五个管控层看板的模块结构与各自下钻对象。

## 通用看板骨架
- 顶部：全局筛选 + 面包屑返回
- 第一行：4~6 个 KPI 卡
- 第二行：2~3 个核心分析图
- 第三行：榜单 / 分布 / 摘要
- 底部：明细表与下钻入口

通用约束：
- 看板负责“问题定位”，不做执行层全部细节承载。
- 每个看板必须能跳只读执行层页面。
- 看板中不单独保留“资源负载与协同”页面；资源负载信息只作为执行层明细内容。

## 五个看板的正式信息架构

### 1. 项目执行监控
定位：
- 找出延期、阻塞、责任归属问题

模块：
- KPI：
  - 项目本周期节点总数
  - 节点未完成总数
  - 节点按时完成数
  - 节点超期完成数
  - 里程碑达成率
- 图表：
  - 甘特图概览
  - 里程碑完成趋势
  - 阶段分布
- 榜单：
  - 延期 TOP10 项目
  - 责任科室/责任人负载排名
- 表格：
  - 项目执行清单
  - 阻塞链摘要清单
- 下钻：
  - 项目执行详情页
  - 节点任务详情页

### 2. 质量信息与跟进措施
定位：
- 找出质量问题来源、规模、闭环进展和措施覆盖情况

模块：
- KPI：
  - 新增质量问题数
  - 现存质量问题数
  - 闭环率
  - 未提交归零计划数
  - 跟进措施覆盖率
- 图表：
  - 问题分类分布
  - 项目/科室质量问题分布
- 榜单：
  - 质量问题项目排名
  - 科室质量问题排名
- 表格：
  - 质量问题清单
  - 措施摘要清单
- 下钻：
  - 项目质量详情页
  - 单个质量问题详情页

### 3. 技术状态与跟进
定位：
- 找出技术状态变更是否失控、签署与归零是否滞后

模块：
- KPI：
  - 技术状态变更数
  - 未闭环数
  - 文件签署完成率
  - 跟进措施覆盖率
- 图表：
  - 更改类别分布
  - 文件签署状态分布
  - 项目技术状态分布
- 榜单：
  - 技术状态项目排名
- 表格：
  - 技术状态清单
  - 技术措施摘要清单
- 下钻：
  - 项目技术状态详情页
  - 单项技术状态详情页

### 4. 成本与预算控制
定位：
- 找出预算执行偏差最大的项目、部门和时间段

模块：
- KPI：
  - 年度预算总额
  - 实际执行额
  - 预算执行率
  - 偏差额
  - 偏差率
- 图表：
  - 预算 vs 实际趋势
  - 部门预算执行
  - 偏差结构分布
- 榜单：
  - 项目成本偏差 TOPN
  - 部门偏差排名
- 表格：
  - 项目成本清单
  - 周期成本明细
- 下钻：
  - 项目成本详情页
  - 部门 / 周期成本详情页

### 5. 风险与预警中心
定位：
- 找出风险等级、聚集区域、闭环情况和措施落地情况

模块：
- KPI：
  - 风险总数
  - 高风险数
  - 中风险数
  - 闭环率
  - 跟进措施覆盖率
- 图表：
  - 风险矩阵
  - 风险等级分布
  - 风险分类分布
- 榜单：
  - 风险项目排名
  - 科室风险排名
- 表格：
  - 风险清单
  - 风险措施摘要清单
- 下钻：
  - 项目风险详情页
  - 单个风险详情页

## 页面边界与拆分规则
- “质量信息与跟进措施”与“技术状态与跟进”必须拆成两套独立看板，不再共页。
- “资源负载与协同”从独立看板移除，仅保留为执行层详情页中的分析模块。
- 看板只呈现摘要措施，不承载执行层完整时间线。
- 任何看板都不能直接编辑或回写。
