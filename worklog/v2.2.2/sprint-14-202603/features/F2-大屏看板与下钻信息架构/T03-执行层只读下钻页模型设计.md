# T03: 执行层只读下钻页模型设计

**优先级**: P0
**状态**: DONE
**依赖**: T02

## 目标
定义执行层只读下钻页的通用承载结构。

## 页面定位
- 受众：项目经理、项目主管、部门负责人
- 关键词：执行控制
- 目标：在只读前提下看清楚“为什么出问题、卡在哪、措施是什么、谁负责”

## 路由策略
- 执行层下钻页必须是独立页面，不是弹窗/抽屉。
- 推荐统一路由前缀：
  - `/gpmc/drill/execution/project/:projectNo`
  - `/gpmc/drill/execution/node/:projectNo/:nodeKey`
  - `/gpmc/drill/quality/issue/:projectNo/:issueKey`
  - `/gpmc/drill/tech-state/item/:projectNo/:techKey`
  - `/gpmc/drill/cost/project/:projectNo`
  - `/gpmc/drill/risk/item/:projectNo/:riskKey`

## 通用页面骨架

### A. 顶部操作区
- 返回上级看板
- 面包屑
- 当前筛选条件回显
- 打印 / 导出入口（只读导出）

### B. 对象概要区
- 项目编号 / 项目名称
- 所属事业部 / 责任科室
- 责任人 / 项目主管
- 当前状态 / 风险等级 / 闭环状态
- 最近更新时间

### C. 执行分析区
- 关键指标卡
- 时间线 / 甘特图 / 状态流程
- 阻塞摘要 / 偏差摘要 / 风险摘要

### D. 明细区
- 主明细表
- 跟进措施表
- 交付物 / 闭环物列表

### E. 只读说明
- 页面全部只读
- 不承载编辑表单
- 不承载在线回写

## 五类下钻页的专属内容

### 1. 项目执行详情页
- 项目概要
- 关键里程碑清单
- 任务甘特图
- 阻塞链路
- 责任人负载
- 进度跟进措施

### 2. 质量问题详情页
- 问题概要
- 发生时间线
- 原因分类与责任信息
- 跟进措施表
- 闭环交付物

### 3. 技术状态详情页
- 状态对象概要
- 更改历史
- 文件签署状态
- 跟进措施表
- 归零交付物

### 4. 成本详情页
- 项目成本概要
- 周期趋势
- 预算 / 实际对比表
- 偏差分析

### 5. 风险详情页
- 风险概要
- 风险时间线
- 风险等级变化
- 跟进措施表
- 闭环交付物

## 资源负载的安置方式
- 不再作为单独看板存在。
- 仅在“项目执行详情页”中作为分析模块展示：
  - 责任人负载
  - 责任科室负载
  - 协同部门参与度

## 对后续前后端实现的约束
- 后端 drill API 必须直接返回页面级只读模型，不把原始表直接透给前端。
- 前端执行层页面与 `screens` 模板中的 `jump-url` 必须共享同一套路由参数规则。
- 执行层下钻页允许继续筛选，但筛选只能收窄视图，不能改变业务口径。
