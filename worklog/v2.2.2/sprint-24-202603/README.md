# Sprint-24: 逻辑建模主工作流补完

**时间**: 2026-03
**状态**: IN_PROGRESS
**目标**: 完整补齐逻辑建模的主工作流，收口模型唯一性、文件浏览器、导入治理、归档删除、模板生成以及编译测试上线链路

## 背景

当前逻辑建模虽然已经具备基础 CRUD、批量删除和文件浏览器雏形，但主工作流仍不完整：

- 同一项目空间下模型名没有真正做到严格唯一
- 列表接口通过静默去重隐藏冲突模型，页面状态与数据库状态不一致
- 左侧文件浏览器、治理弹窗、未归档列表三处选择语义仍然不够统一
- 导入、批量导入、模型治理、批量归档、删除模型等高频路径缺少统一的完成标准
- `从 ODS 一键生成` 不是稳定可交付的能力，需要替换成新的 `从 ODS 生成模板`
- 编译、测试、上线和人工验收没有在同一条工作流里收口
