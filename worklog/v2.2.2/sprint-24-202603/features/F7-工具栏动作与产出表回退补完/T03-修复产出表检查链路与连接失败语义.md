# T03: 修复产出表检查链路与连接失败语义

**优先级**: P0
**状态**: DONE
**依赖**: T01

## 目标

修复 `清空产出表`、`重建产出表` 在执行前检查产出 relation 时的目标数仓连接失败问题，并把错误语义收口成平台侧可诊断信息。

## 技术设计

- 复核 `DbtOutputRelationService.analyze()` 与 `DbtTargetConnectionFactory`
- 为目标数仓连接失败建立稳定错误分类
- 收口前端 modal 的错误展示，不再只出现底层 JDBC 原文
- 保持 `truncate` 的目标库检查，并把 `rebuild` 改为基于模型元数据直接进入 `dbt --full-refresh`

## 影响范围

- `source/dts-platform/src/main/java/com/yuzhi/dts/platform/service/etl/DbtOutputRelationService.java`
- `source/dts-platform/src/main/java/com/yuzhi/dts/platform/service/etl/DbtTargetConnectionFactory.java`
- `source/dts-platform/src/main/java/com/yuzhi/dts/platform/web/rest/EtlResource.java`
- `source/dts-platform-webapp/src/pages/modeling/components/OutputRelationModal.tsx`
- `source/dts-platform-webapp/src/pages/modeling/SqlModelingPage.tsx`

## 验证

- [x] 目标数仓连接失败时返回稳定且可解释错误
- [x] `重建产出表` 不再依赖平台直连目标库预检
- [x] 连接成功时 `清空产出表` 行为不回退

## 完成标准

- [x] 现场不再只看到 `The connection attempt failed.`
