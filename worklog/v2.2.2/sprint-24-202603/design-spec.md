# 逻辑建模主工作流补完 — 设计规格

## 1. 目标

补齐逻辑建模的主工作流，使模型创建、导入、治理、归档、删除、模板生成以及编译上线链路具备统一语义和可验收标准。

## 2. 设计结论

### 2.1 模型唯一性

- 同一项目空间下模型名严格唯一
- 后端不再依赖 `list()` 阶段静默去重掩盖冲突
- 唯一性规则统一覆盖：
  - 新建
  - 更新改名
  - 导入
  - 批量导入
  - 从 ODS 生成模板

### 2.2 文件浏览器与批量选择

- 左树、治理弹窗、未归档列表共用一套批量选择模型
- 语义定义为 `tree / governance / list` 三个 source bucket 的并集
- 不再通过打开某个入口就无条件清空所有选择
- 左侧文件浏览器需具备明确节点类型和受控展开状态

### 2.3 生命周期操作

- 删除模型、批量删除、模型治理、批量归档共用一致的反馈模式
- 成功、失败、跳过必须可追踪
- 当前编辑模型删除后的回收行为要稳定

### 2.4 导入链路

- 单模型导入与批量导入必须遵守唯一性规则
- companion 文件写入不能污染未成功导入的模型工作区
- 批量导入需有可解释的明细结果

### 2.5 从 ODS 生成模板

- 旧的“从 ODS 一键生成”整体下线
- 新入口改为“从 ODS 生成模板”
- 输出内容定位为：
  - 模型模板骨架
  - 标准命名草稿
  - 字段注释草稿
  - 基础 SQL 模板
- 不再对外宣称“直接生成最终模型”

### 2.6 验证与上线

- 本轮改动必须和 `dts-platform` / `dts-platform-webapp` 的编译、测试、上线步骤一起收口
- sprint 中需保留自动化验证和人工验收清单
