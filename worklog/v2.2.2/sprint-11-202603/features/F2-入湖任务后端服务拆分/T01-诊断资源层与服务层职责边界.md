# T01: 诊断资源层与服务层职责边界

**优先级**: P0
**状态**: DONE
**依赖**: 无

## 目标
识别入湖后端哪些职责最适合优先拆分，避免直接大范围重构。

## 技术设计

扫描结果表明：

- [IngestionTaskResource.java](/opt/prod/s10/s10-stack/source/dts-ingestion/src/main/java/com/yuzhi/dts/ingestion/web/rest/IngestionTaskResource.java) 同时承载 CRUD、执行、重试、日志、模板、能力、状态查询等大量 endpoint
- [IngestionTaskService.java](/opt/prod/s10/s10-stack/source/dts-ingestion/src/main/java/com/yuzhi/dts/ingestion/service/IngestionTaskService.java) 混合了 CRUD、执行编排、Airflow 触发、日志查询和观测逻辑
- [AddaxJobService.java](/opt/prod/s10/s10-stack/source/dts-ingestion/src/main/java/com/yuzhi/dts/ingestion/service/etl/AddaxJobService.java) 体量过大，不适合作为下一刀的首选切口

因此第一批后端优化建议优先从“查询/视图”和“执行编排”分离开始。
