# T03: 五个主题域视图模型定义

**优先级**: P0
**状态**: DONE
**依赖**: T01,T02

## 目标
定义后续后端 API 和前端页面都可直接消费的主题域视图模型。

## 设计原则
- 页面层、模板层、后端 API 共享同一套语义模型。
- 每个 view model 只暴露页面真正需要的汇总、图表、榜单、明细和下钻动作。
- 前端不直接消费 9 张原始源表。
- 执行层下钻页全部只读，不包含编辑和回写动作。

## 页面级 view model 定义

### 1. StrategicOverviewVm
服务对象：
- 战略层大屏
- 战略层模板 `gpmc-strategic-overview`

结构：
- `filters: GlobalFiltersVm`
- `headlineMetrics: MetricCardVm[]`
- `completionTrend: ChartVm`
- `riskHeatmap: ChartVm`
- `deptRanking: LeaderboardVm`
- `exceptionSnapshots: { delayedProjects, highRiskProjects, qualityAlerts, techAlerts, costAlerts }`
- `drillActions: DrillActionVm[]`

说明：
- 只放全局态势，不直接挂措施明细。
- 点击任何异常摘要，必须能进入对应管控层看板。

### 2. ExecutionBoardVm
服务对象：
- 项目执行监控看板
- 执行看板模板 `gpmc-execution-board`

结构：
- `filters: GlobalFiltersVm`
- `summaryMetrics: MetricCardVm[]`
- `ganttOverview: ChartVm`
- `milestoneCompletion: ChartVm`
- `delayTopProjects: LeaderboardVm`
- `ownerLoadRanking: LeaderboardVm`
- `blockChainSummary: DetailTableVm`
- `projectExecutionTable: DetailTableVm`
- `drillActions: DrillActionVm[]`

说明：
- 该模型是执行层 drill 的父模型。
- 看板只定位问题，不承载完整任务明细。

### 3. QualityBoardVm
服务对象：
- 质量信息与跟进措施看板
- 质量看板模板 `gpmc-quality-board`

结构：
- `filters: GlobalFiltersVm`
- `summaryMetrics: MetricCardVm[]`
- `issueCategoryDistribution: ChartVm`
- `deptIssueRanking: LeaderboardVm`
- `projectIssueRanking: LeaderboardVm`
- `issueTable: DetailTableVm`
- `measureCoverageSummary: ChartVm`
- `measureTablePreview: DetailTableVm`
- `drillActions: DrillActionVm[]`

说明：
- 质量问题和质量措施必须同时呈现，但措施只展示摘要和预览。

### 4. TechStateBoardVm
服务对象：
- 技术状态与跟进看板
- 技术状态看板模板 `gpmc-tech-state-board`

结构：
- `filters: GlobalFiltersVm`
- `summaryMetrics: MetricCardVm[]`
- `changeCategoryDistribution: ChartVm`
- `signatureStatusDistribution: ChartVm`
- `projectTechRanking: LeaderboardVm`
- `techStateTable: DetailTableVm`
- `measureTablePreview: DetailTableVm`
- `drillActions: DrillActionVm[]`

说明：
- 从质量看板中彻底拆出技术状态，不再共用页面模型。

### 5. CostBoardVm
服务对象：
- 成本与预算控制看板
- 成本看板模板 `gpmc-cost-board`

结构：
- `filters: GlobalFiltersVm`
- `summaryMetrics: MetricCardVm[]`
- `budgetVsActualTrend: ChartVm`
- `deptBudgetExecution: ChartVm`
- `projectCostDeviationRanking: LeaderboardVm`
- `costTable: DetailTableVm`
- `drillActions: DrillActionVm[]`

说明：
- 第一版重点是预算、执行、偏差，不做复杂财务凭证明细。

### 6. RiskBoardVm
服务对象：
- 风险与预警中心看板
- 风险看板模板 `gpmc-risk-board`

结构：
- `filters: GlobalFiltersVm`
- `summaryMetrics: MetricCardVm[]`
- `riskMatrix: ChartVm`
- `riskLevelDistribution: ChartVm`
- `projectRiskRanking: LeaderboardVm`
- `riskTable: DetailTableVm`
- `measureTablePreview: DetailTableVm`
- `drillActions: DrillActionVm[]`

说明：
- 风险矩阵是本页核心组件，必须支持按项目、事业部、风险等级过滤。

## 路由与模板层约束
- `gpmc` 路由页面消费页面级 view model。
- `screens` 模板消费同一语义层，但以 `ScreenTemplate` 的组件配置方式承载。
- 下钻动作统一输出为显式页面路由，不使用弹窗或抽屉承载执行层内容。

## 对后端 API 的拆分要求
- 后端按页面模型出接口，而不是按源表出接口。
- 最少需要产出：
  - `overview`
  - `execution-board`
  - `quality-board`
  - `tech-state-board`
  - `cost-board`
  - `risk-board`
  - `execution-drill`
  - `quality-drill`
  - `tech-state-drill`
  - `cost-drill`
  - `risk-drill`
