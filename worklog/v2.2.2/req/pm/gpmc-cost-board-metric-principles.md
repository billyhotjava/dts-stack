# GPMC 成本与预算控制大屏指标口径说明

## 1. 适用范围

本文针对当前 `GPMC 成本与预算控制` 模板页整理指标计算原理，主要对应：

- `source/dts-analytics-webapp/modern/src/pages/screens/gpmcTemplates.ts`
- 模板：`gpmc-cost-board`

说明：

- 当前这张大屏仍是演示模板，数据是写在模板里的静态值，不是后端实时计算结果。
- 页面顶部筛选项当前只定义了变量，不会驱动本模板中的 KPI、图表、表格重新计算。
- 因此本文分为两层：
  - 当前代码中的真实取值方式
  - 后续如果接真实数据，建议采用的正式业务口径

## 2. 当前代码中的真实来源

### 2.1 顶部 KPI

当前顶部 7 个 KPI 直接写在模板里：

| 指标 | 当前模板值 | 当前代码取值方式 | 当前是否可由下方明细反推 |
| --- | --- | --- | --- |
| 年度预算总额 | `36.8 亿` | 固定写死 | 可以，与下方部门预算汇总一致 |
| 累计执行额 | `26.1 亿` | 固定写死 | 不可以，和下方部门实际汇总不一致 |
| 预算执行率 | `70.9%` | 固定写死 | 可以，等于 `26.1 / 36.8` |
| 预算偏差 | `0.72 亿` | 固定写死 | 不可以，不能由当前图表/表格直接反推 |
| 预算效率 | `0.93` | 固定写死 | 不可以，当前代码里没有推导公式 |
| 燃尽率 | `71%` | 固定写死 | 基本可以，约等于 `26.1 / 36.8` 四舍五入 |
| 偏差项目数 | `8` | 固定写死 | 不可以，和当前预警榜 4 条不一致 |

### 2.2 月度支出与偏差趋势

当前模板中的 3 组序列为：

- 计划支出：`[2.8, 3.1, 3.5, 3.2, 3.6, 3.8]`
- 实际支出：`[2.6, 3.3, 3.8, 3.0, 3.4, 3.7]`
- 预算偏差：`[-0.2, 0.2, 0.3, -0.2, -0.2, -0.1]`

这里的 `预算偏差` 是按月直接用：

`预算偏差 = 实际支出 - 计划支出`

逐月核对如下：

| 月份 | 计划 | 实际 | 实际 - 计划 | 图中偏差 |
| --- | --- | --- | --- | --- |
| 1月 | 2.8 | 2.6 | -0.2 | -0.2 |
| 2月 | 3.1 | 3.3 | +0.2 | +0.2 |
| 3月 | 3.5 | 3.8 | +0.3 | +0.3 |
| 4月 | 3.2 | 3.0 | -0.2 | -0.2 |
| 5月 | 3.6 | 3.4 | -0.2 | -0.2 |
| 6月 | 3.8 | 3.7 | -0.1 | -0.1 |

结论：这张趋势图内部是自洽的。

### 2.4 成本偏差预警榜

当前预警榜是静态表格，不做计算。表中偏差值直接写死：

`执行状态` 与 `预警` 也是直接配置的文本标签，不是实时推导。

### 2.5 项目预算执行明细

当前底部明细表里，`执行率` 与 `偏差` 是能由行数据反推的：

- `执行率 = 实际 / 预算 × 100%`
- `偏差 = 实际 - 预算`

逐行核对：

| 项目/科室 | 预算 | 实际 | 执行率 | 偏差 |
| --- | --- | --- | --- | --- |
| 工程建设中心 | 9.5 | 8.6 | `8.6 / 9.5 = 90.5%` | `8.6 - 9.5 = -0.9` |
| 数字化事业部 | 6.0 | 5.2 | `86.7%` | `-0.8` |
| 研发中心 | 8.2 | 6.8 | `82.9%` | `-1.4` |
| 生产制造中心 | 10.0 | 10.4 | `104.0%` | `+0.4` |
| 采购中心 | 3.1 | 2.8 | `90.3%` | `-0.3` |

结论：底部明细表与右侧部门预算执行图是同一批部门数据，二者是自洽的。

## 3. 当前模板内部的一致性结论

### 3.1 已经闭环或基本闭环的部分

- `年度预算总额 = 9.5 + 6.0 + 8.2 + 10.0 + 3.1 = 36.8`
- `预算执行率 = 26.1 / 36.8 = 70.9%`
- `燃尽率 = 71%`，与上式取整后接近
- `月度偏差 = 实际支出 - 计划支出`
- `底部明细的执行率、偏差` 均可按公式复算

### 3.2 当前未闭环的部分

以下指标目前是演示值，不应被当成已经和图表/明细完全一致的正式口径：

- `累计执行额 26.1 亿`
- `预算偏差 0.72 亿`
- `预算效率 0.93`
- `偏差项目数 8`

原因：

- 当前右侧部门实际汇总为 `8.6 + 5.2 + 6.8 + 10.4 + 2.8 = 33.8 亿`，与 `26.1 亿` 不一致
- 当前月度计划/实际累计分别约为 `20.0 / 19.8 亿`，也与 `26.1 亿` 不一致
- 当前预警榜只展示 `4` 个项目，不足以支撑 `偏差项目数 8`
- `预算效率 0.93` 在当前代码中没有任何显式推导逻辑

## 4. 建议的正式业务口径

如果后续把这张模板接入真实接口或查询，建议按下面的正式口径收敛：

| 指标 | 建议正式口径 |
| --- | --- |
| 年度预算总额 | 当前筛选范围内全部项目/责任科室的年度预算总和 |
| 累计执行额 | 当前统计周期截止日的累计实际支出总额 |
| 预算执行率 | `累计执行额 / 年度预算总额 × 100%` |
| 预算偏差 | 建议明确为二选一：`累计实际 - 累计计划` 或 `累计实际 - 对应预算`，不能混用 |
| 预算效率 | 建议定义为 `产出完成率 / 预算执行率`，或改名为更明确的“预算产出比” |
| 燃尽率 | 如果保留该名，建议定义为 `累计执行额 / 年度预算总额 × 100%` |
| 偏差项目数 | 偏差绝对值超过阈值的项目数量，例如 `abs(偏差) > 0.1 亿` 的项目数 |

## 5. 建议的后续处理

1. 先确定 `预算偏差` 的正式定义，是“对预算偏差”还是“对计划偏差”。
2. 明确 `预算效率 0.93` 的业务定义；如果当前没有统一定义，建议先不要作为正式 KPI 对外。
3. 若接真实数据，应让顶部 KPI、月度趋势、部门执行、偏差榜、明细表全部来自同一套查询结果，避免再出现模板内部不闭环。
4. 当前顶部筛选项如果要生效，需要把 `deptId/projectNo/dateFrom/dateTo/riskLevel` 透传到统一数据源，而不是只保留展示控件。
