# ELT 人工异常路径验收手册

## 目标

为接入中心和开发中心补一份可重复执行的人工异常路径验收手册，避免只验证 happy path。

## 覆盖范围

### 接入中心

- 任务异步执行提交后，DAG 未注册
- 任务执行中，状态同步延迟或日志暂不可见
- 任务执行失败，但页面仅显示 submitted / 运行中

### 开发中心

- `dbt compile / test / build` 触发前，Airflow DAG 查询失败
- 质量门禁 / 发布门禁阻断或告警
- `dbt build` 已触发，但运行记录和执行日志未及时回显

## 验收步骤

### 1. 接入中心：执行任务后查看进度与日志

入口：
- `数据开发中心 -> 数据接入中心 -> 入湖任务中心`

步骤：
1. 打开任务列表，确认任务清单可见。
2. 选择一条活跃任务，点击“执行”。
3. 确认执行进度弹窗出现，并能在 30 秒内看到状态变化。
4. 进入任务详情，点击“最新日志”。
5. 确认日志抽屉能显示最近一次执行日志。

期望：
- 若执行成功，进度弹窗显示“执行成功”。
- 若执行失败，进度弹窗显示“执行失败”，并展示错误原因。
- 若日志尚未同步，页面应明确提示“日志加载中”或“暂无日志”，不能静默空白。

### 2. 开发中心：编译 / 测试 / 上线

入口：
- `数据开发中心 -> 逻辑建模`

步骤：
1. 进入“逻辑建模工作区”，确认活动模型已选中。
2. 点击“编译”，确认“操作记录 -> 编译”出现最新结果。
3. 点击“测试”，确认“操作记录 -> 测试”出现最新结果。
4. 点击“上线”，提交 `dbt build`。
5. 在“操作记录 -> 运行记录”确认最新 DAG 运行记录出现。
6. 如有需要，切换到“执行日志”查看 Airflow 日志。

期望：
- `compile/test/build` 三个动作的结果语义清晰区分。
- 阻断时显示门禁原因；告警时允许用户显式确认继续。
- DAG 查询失败时，错误文案应体现 Airflow 查询失败，而不是统一显示“DAG 未就绪/未注册”。

## 重点异常场景

### A. DAG 未注册

操作：
- 在新建任务或新建建模 DAG 后立即触发执行。

期望：
- 页面提示 DAG 正在注册，可稍后重试。
- 不得把 401/403/500 混淆成 DAG 未注册。

### B. Airflow API 401 / 403 / 500

操作：
- 模拟 Airflow API 鉴权失败或内部错误。

期望：
- 接口和页面提示应明确是 Airflow 查询/触发失败。
- 不应继续等待 30 秒后才返回“DAG 未注册”。

### C. 状态同步延迟

操作：
- 模拟任务已提交，但状态同步接口短时间内返回空或旧状态。

期望：
- 页面维持“状态同步中，稍后自动重试”之类的中间态。
- 不应直接误报成功或失败。

### D. 门禁阻断 / 告警

操作：
- 让质量门禁或发布门禁分别返回 blocker / warning。

期望：
- blocker 必须阻断；
- warning 必须要求用户确认后才能继续；
- 最近一次命令不是 `compile/test/build` 时，应根据最近历史证据判断，而不是简单一刀切阻断。
