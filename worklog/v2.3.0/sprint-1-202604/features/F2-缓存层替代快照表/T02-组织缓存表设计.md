# T02: kc_org_cache 表设计与实现

**优先级**: P1
**状态**: READY
**依赖**: F1

## 目标
设计并实现组织缓存表，替代 OrganizationNode 的查询功能（写入已在 F2/T02 改为直写 Keycloak）。

## 技术设计

### 表结构

```sql
CREATE TABLE kc_org_cache (
    keycloak_group_id VARCHAR(64) PRIMARY KEY,
    name              VARCHAR(256) NOT NULL,
    dept_code         VARCHAR(128),
    org_code          VARCHAR(128),
    parent_group_id   VARCHAR(64),
    data_level        VARCHAR(64) NOT NULL DEFAULT 'DATA_PUBLIC',
    contact           VARCHAR(256),
    short_name        VARCHAR(256),
    sort_order        VARCHAR(64),
    status            VARCHAR(32) DEFAULT 'ACTIVE',
    is_root           BOOLEAN NOT NULL DEFAULT false,
    cached_at         TIMESTAMP NOT NULL DEFAULT now(),
    expires_at        TIMESTAMP NOT NULL,

    CONSTRAINT uk_kc_org_cache_dept_code UNIQUE (dept_code)
);
CREATE INDEX idx_kc_org_cache_parent ON kc_org_cache (parent_group_id);
CREATE INDEX idx_kc_org_cache_expires ON kc_org_cache (expires_at);
```

### 缓存刷新策略

组织树变动频率低，采用**全量刷新**而非按需刷新：
- 应用启动时全量拉取 Keycloak groups → 写入 kc_org_cache
- 组织同步操作后触发全量刷新
- 定时刷新（如每小时一次）作为兜底

```java
@Service

    public List<OrgTreeNode> getOrgTree() {
        // 查缓存 → 过期则刷新 → Keycloak 不可用则用过期缓存
    }
    public void refreshAll() {
        // 拉取 Keycloak groups 全量 → upsert kc_org_cache
    }
}
```
