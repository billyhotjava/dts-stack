# T03: PlatformDirectoryResource 改用缓存层

**优先级**: P1
**状态**: READY
**依赖**: T01, T02

## 目标
PlatformDirectoryResource 的用户/组织查询改为走缓存层，不再直接查 Keycloak Admin API 或 AdminKeycloakUser 表。

## 技术设计

### 用户查询重构

`PlatformDirectoryResource.listUsers()` 改为:
```
1. KcUserCacheService.search(keyword) 
   → 缓存命中 → 返回
   → 缓存未命中/过期 → Keycloak Admin API → 写缓存 → 返回
   → Keycloak 不可用 → 返回过期缓存
2. 不再有 fallbackFromSnapshots() / fallbackFromStore() 逻辑
```

### 组织查询重构

`DirectoryResource.fetchOrgTree()` (dts-platform 侧) 改为:
- admin 侧: `KcOrgCacheService.getOrgTree()` → 返回缓存的树
- platform 侧: 无需改动，API 签名不变

### 删除的降级逻辑

| 当前降级 | 替代 |
|---------|------|
| `fallbackFromSnapshots()` — 查 AdminKeycloakUser | 缓存宽限期 |
| `fallbackFromStore()` — 查 InMemoryStore | 删除 |
| `AdminDirectoryGateway.toSummary(KeycloakUser)` — legacy fallback | 缓存层统一处理 |

## 影响范围

| 文件 | 改动 |
|------|------|
| `dts-admin/.../PlatformDirectoryResource.java` | searchUsers 改用缓存 |
| `dts-admin/.../AdminUserService.java` | resolveDisplayNames 改用缓存 |
| `dts-platform/.../AdminDirectoryGateway.java` | 删除 legacy fallback |

## 验证
- [ ] /api/platform/directory/users 返回结果与改动前一致
- [ ] /api/platform/directory/roles 不受影响
- [ ] Keycloak 正常时查询响应时间 < 500ms
- [ ] Keycloak 挂掉后查询仍返回缓存数据

## 完成标准
- [ ] 所有用户查询通过缓存层
- [ ] 所有组织查询通过缓存层
- [ ] fallbackFromSnapshots / fallbackFromStore 删除
