# F1: 审批引擎 MVP (dts-approval)

**优先级**: P0
**状态**: READY
**依赖**: Sprint-1（IAM 重构）完成

## 目标

抽取一个**业务无关**的审批引擎服务 `dts-approval`，承担后续所有业务系统（MDM / 填报 / 资产访问 / 未来 PLM/ERP）的审批需求。admin 的三员账号审批**不迁入**，保持在 admin 原地。

## 设计红线（brainstorm 已对齐）

- **引擎不理解业务**：业务系统提交 `payload + schema_key`，引擎只管流程（谁审、几级、是否通过），业务落库由业务系统在收到"通过"事件后自做
- **组织树不复制**：审批要"找部门领导"时，调 admin 或直查 Keycloak groups（Sprint-1 之后 Keycloak 是真源）
- **MVP 范围要狠砍**：单级审批 / 串行多级 / 驳回 / 站内通知为 day-1；**不做**并行会签、委托、超时自动通过、动态分支
- **可抽取边界**：独立后端服务、独立数据库 schema（`apr_*` 表）、独立前端路由 `/approval/*`、事件经消息总线发布
