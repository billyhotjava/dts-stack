# 下一阶段 Feature 依赖图

## 推荐实施顺序

```text
F6 旅程上下文组件化
  -> F7 阶段状态与缺口计算
  -> F2 数据集成到数仓规划
  -> F3 标准落标到建模与指标
  -> F4 数据开发到发布门禁与运行证据
  -> F5 数据服务消费闭环
  -> F8 客户验收包与证据聚合
```

F9 可登录浏览器验收与回归基线需要尽早并行启动，因为它解除当前 Playwright 只能停在登录页的验证阻断。

## 依赖原则

- 先做共享上下文组件，再铺页面，否则每个页面都会重复解析 query。
- 先做阶段状态模型，再做缺口和下一步，否则工作台会继续停留在静态说明。
- 标准落标、建模、指标、服务都必须能读同一条 journey context。
- 验收包不等所有后端 API 完备，先聚合已有页面证据；缺口必须可见。
- Browser smoke 必须区分登录/DNS/API/布局问题，不把环境阻断写成 UI 通过。
