# DTS v2.2.0 完整开发计划（Platform + Analytics）

## 1. 文档索引
- 总清单：`worklog/v2.2.0/platform-elt-task-list.md`
- P0：`worklog/v2.2.0/platform-elt-p0-issues.md`
- P1：`worklog/v2.2.0/platform-elt-p1-issues.md`
- P2：`worklog/v2.2.0/platform-elt-p2-issues.md`
- P3：`worklog/v2.2.0/platform-elt-p3-issues.md`

## 2. 阶段目标
- P0：可用性兜底（流程可跑、结果可查、日志可读、模型可生）。
- P1：稳定性与性能（观测增强、错误归因、用户查询性能）。
- P2：产品化闭环（查询沉淀数据集、看板链接治理、项目包导入）。
- P3：架构演进（连接器抽象、Airbyte 迁移、实时化预留）。

## 3. 里程碑与周期（建议）
- Sprint-1（1周）：P0 完成并上线验证。
- Sprint-2（1~2周）：P1 完成并进行压测回归。
- Sprint-3（2周）：P2 主链路完成（查询->数据集->看板）。
- Sprint-4（并行预研）：P3 PoC（连接器抽象+实时试点）。

## 4. 依赖关系
- P1 依赖 P0：日志映射、执行链路稳定。
- P2 依赖 P0/P1：数据源与权限模型稳定，审计能力可复用。
- P3 依赖 P1/P2：先稳态，再演进。

## 5. 风险与缓解
- 风险：`legacy/normal/dev` 行为不一致。
  - 缓解：每个 Sprint 强制双模式回归。
- 风险：`x86/鲲鹏麒麟` 运行差异。
  - 缓解：每阶段至少一次 ARM 环境验证。
- 风险：Addax 与 Airbyte 语义不一致。
  - 缓解：先产出语义差异矩阵再迁移。

## 6. 发布准入门槛
- 门槛1：核心流程一次走通（创建任务->执行->日志->模型生成）。
- 门槛2：无 P0 阻断级缺陷。
- 门槛3：关键接口与页面回归通过。
- 门槛4：`legacy/normal/dev` 与 `x86/ARM` 基础用例通过。

## 7. 实施建议
- 先按 P0 issue 清单并行拆组（后端/前端/测试）。
- P1 起引入每周稳定性报告（失败率、MTTR、P95 时延）。
- P2/P3 保留架构评审节点，避免功能先行导致返工。
