# DTS v2.2.0 Platform + Analytics 任务清单（ELT/可视化）

## 1. 背景与目标
- 当前状态：已打通 ODS 入湖主流程（Excel/源库），全量与增量能力进入稳定化阶段。
- 核心目标：
  - `Platform` 负责数据与流程编排（API、任务、审计、上线）。
  - `Analytics` 负责可视化消费（查询结果沉淀为数据源、看板链接化发布）。
  - 全链路可观测：任务状态、进度、日志、审计、回放。

## 2. 与商业软件差距（聚焦 ELT）
- 编排与可靠性：缺少“任务创建后立即可触发”的强一致保障（现有短暂 DAG 不可见窗口）。
- 资产化能力：查询结果沉淀与复用链路不完整（数据集 -> 指标 -> 看板）。
- 运维体验：失败诊断、重试策略、补数向导、告警分级仍偏工程化。
- 多环境一致性：`Legacy/普通模式`、`x86/ARM(鲲鹏)+麒麟` 仍有行为差异。

## 3. 菜单映射与优先级

### P0（必须先完成，保证可用性）

#### 3.1 数据采集（Platform）
- [ ] 统一全量语义：全量=先 `DROP TABLE IF EXISTS` 再建表导入（Excel/源库一致）。
- [ ] 修复“创建任务后立即执行 DAG 404”窗口：
  - DAG 写入后主动轮询 Airflow 识别完成，再触发执行。
  - 超时给出明确错误码与建议动作（非模糊失败）。
- [ ] 修复 Addax 表名前缀丢失与 schema 误拼接（`db.schema.table`）。
- [ ] 修复文件导入 `import_time` 语法与时区问题（统一 `Asia/Shanghai`）。
- [ ] 修复执行成功但日志页 404（TaskInstance 对齐 runId/taskId 映射）。
- [ ] 任务页面异步化：启动后立即返回，前端用进度条+轮询/推送展示状态，不阻塞界面。

#### 3.2 元数据采集（Platform）
- [ ] 默认数据湖采集范围修正：仅展示目标连接采集结果，不混入其他连接表。
- [ ] 采集结果强刷新：删除源表后，前端 ODS 下拉必须反映最新状态。
- [ ] 采集日志可见性：采集动作必须有可追踪输出（开始/结束/发现数/失败项）。

#### 3.3 逻辑建模（Platform）
- [ ] “从 ODS 一键生成 DWD/DWS/ADS”根因修复：`source_data_source_id` 不能为空。
- [ ] 来源数据源显示名称，不显示 ID 或 ID 截断别名。
- [ ] ODS 下拉统一格式：`schema.table`，且切换来源数据源后列表实时刷新。
- [ ] 移除 ZIP 导入后的主流程文案与交互闭环（简要说明 Tab 已并入，继续完善提示）。

### P1（稳定性与性能）

#### 3.4 执行与审计（Platform）
- [ ] 增量审计看板：按执行批次展示 `before/after/advanced`，支持筛选与导出。
- [ ] 日志聚合：任务级、节点级、SQL 级日志统一索引，支持关键字检索。
- [ ] 重试策略：失败任务支持“从失败节点继续/整批重跑”。
- [ ] 异常归因标准化：连接失败/权限失败/DDL 失败/脏数据失败分层提示。

#### 3.5 Admin 用户与权限
- [ ] 800+ 用户查询慢问题优化：
  - API 分页与索引核查。
  - 前端输入防抖、最小查询长度、服务端排序白名单。
- [ ] 校验默认角色授权矩阵（普通员工仅工作台+可视化）。
- [ ] 报表密级可见性校验：登录者仅可见不高于自身密级的报表。

### P2（产品化增强）

#### 3.6 Analytics（可视化）
- [x] 查询结果保存为“可复用数据集”（等价 Metabase Question）。
- [x] 数据集作为看板数据源，支持版本与刷新策略。
- [x] 看板中心链接治理：
  - 平台统一管理链接、密级、有效期、访问审计。
  - 非 Analytics 用户只通过链接消费。

#### 3.7 数据建模协同
- [ ] 支持“一个项目一个包”的导入规范（幂等、校验、审计）并给冲突预警。
- [ ] 与外部 LLM 产出兼容：通过命令行/包导入不与在线生成冲突。

### P3（架构演进）

#### 3.8 Airbyte/K8s 迁移准备
- [x] 对齐 Addax 与 Airbyte 的全量/增量语义差异矩阵。
- [x] 抽象连接器能力层（全量、增量、CDC、回填）。
- [x] 为实时化预留：Kafka/消息总线接入点与延迟指标体系。
- [x] 完成 QueryDataset/BI Link 项目上下文隔离（`X-Active-Dept`）。
- [x] 完成跨模块血缘影响视图（方向/深度/项目过滤 + 资产类型）。
- [x] 补齐 P3 回归验收清单与执行步骤。

## 4. 交付里程碑（建议）
- M1（1周）：完成 P0，保证“建任务-立刻可跑-可观测-可回溯”。
- M2（2周）：完成 P1，提升稳定性与运维效率。
- M3（2~3周）：推进 P2，形成可复用数据集与看板资产化闭环。
- M4（并行预研）：推进 P3，为 K8s/Airbyte 与实时化做技术准备。

## 5. 验收标准（最小可用）
- [ ] 新建任务后 10 秒内可触发执行，不出现 DAG 404。
- [ ] 全量导入严格执行“删表重建”，Excel 与源库行为一致。
- [ ] 执行历史日志可 100% 打开，不出现 TaskInstance not found 误判。
- [ ] 逻辑建模 ODS 下拉与来源数据源实时一致，无历史脏缓存。
- [ ] `Legacy/普通` 与 `x86/ARM(鲲鹏)+麒麟` 回归用例全部通过。

## 6. 环境与兼容性基线
- 运行模式：`legacy` / `normal` / `dev`。
- 硬件与系统：`x86_64`、`aarch64(鲲鹏)` + `KylinOS`。
- 基础组件：Docker Compose（当前）+ K8s/Airbyte（后续）。
