# UI-001

## Module

`source/dts-platform-webapp`

## Affected Page

`development / modeling / ETL` main pages, especially:

- `SqlModelingPage`
- `TransformCreatePage`
- `QueryWorkbenchPage`

## Current Behavior

The production build passes, but route-level chunking is weak:

- dynamic import and static import overlap warnings remain
- customer-critical development pages produce large bundles
- first-screen loading risk is higher on onsite environments with weaker hardware or older browsers

## Expected Behavior

Development-center pages should have cleaner route chunk boundaries and better first-load behavior without changing the `2.2.1` information architecture.

## Candidate Fix Area

- `source/dts-platform-webapp/src/routes/sections/dashboard/utils.tsx`
- `source/dts-platform-webapp/src/routes/sections/dashboard/index.tsx`
- `source/dts-platform-webapp/src/pages/modeling/`
- `source/dts-platform-webapp/src/pages/explore/etl/`

## Verification Method

- `pnpm -C source/dts-platform-webapp build`
- inspect whether chunk warnings are reduced
- manual walkthrough of development-center entry and target pages

## Root Cause (First Slice)

`source/dts-platform-webapp/src/routes/sections/dashboard/index.tsx` statically imported `@/pages/workbench`, while the dynamic resolver also lazy-loaded the same page path. Vite therefore kept warning that `workbench` could not be split into a separate chunk.

## Fix (First Slice)

- changed `workbench` route elements in `source/dts-platform-webapp/src/routes/sections/dashboard/index.tsx`
- replaced static import with `lazy + Suspense`
- aligned the route definition with the existing lazy-loading pattern already used by static dashboard routes

## Verification Result

- Regression script:
  - `worklog/v2.2.1/customer-hardening/scripts/check-platform-workbench-route-splitting.sh`
  - `worklog/v2.2.1/customer-hardening/scripts/check-platform-system-route-splitting.sh`
- Result:
  - build passes
  - `workbench` static/dynamic overlap warning is gone
  - `sys/login` overlap warning is gone
  - `sys/error` overlap warnings are gone

## Follow-Up Boundary

The remaining large JS chunks are now a separate optimization topic. They should not be mixed with this completed route-splitting cleanup item.
