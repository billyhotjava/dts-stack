# BUG-001

## Module

`source/dts-platform`

## Symptom

`mvn -f source/dts-platform/pom.xml -DskipTests compile` succeeds, but Maven enforcer reports dependency convergence violations during baseline verification.

## Reproduction

1. Run `mvn -f source/dts-platform/pom.xml -DskipTests compile`
2. Observe dependency convergence warnings from `enforcer`
3. Confirm the conflicts reference:
   - `commons-io`
   - `commons-compress`
   - `nimbus-jose-jwt`

## Expected Behavior

The baseline compile should complete without dependency convergence violations so future bug-fix work is not built on a noisy or unstable dependency graph.

## Candidate Fix Area

- `source/dts-platform/pom.xml`
- transitive dependency management for:
  - `easyexcel`
  - `liquibase-core`
  - `kerb-client`
  - `spring-boot-starter-oauth2-client`

## Verification Command

`mvn -f source/dts-platform/pom.xml -DskipTests compile`

## Root Cause

`source/dts-platform/pom.xml` did not pin versions for the conflicting transitive dependencies, so Maven resolved mixed versions from:

- `easyexcel` / `poi`
- `liquibase-core`
- `kerby`
- `spring-security oauth2`

This produced dependency convergence warnings during every baseline compile.

## Fix

Added explicit version alignment in `source/dts-platform/pom.xml` `dependencyManagement` for:

- `commons-io = 2.16.1`
- `commons-compress = 1.26.2`
- `nimbus-jose-jwt = 9.37.3`

## Verification Result

- Regression script:
  - `worklog/v2.2.1/customer-hardening/scripts/check-platform-dependency-convergence.sh`
- Result:
  - `DependencyConvergence passed`
  - compile remains `BUILD SUCCESS`
