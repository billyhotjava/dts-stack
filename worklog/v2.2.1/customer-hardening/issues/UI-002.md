# UI-002

## Module

`source/dts-platform-webapp`

## Affected Page

`source/dts-platform-webapp/src/pages/explore/etl/TransformDetailPage.tsx`

## Current Behavior

The ETL task detail page always rendered a `"实时状态（预留）"` card, even for batch-oriented tasks such as `full_refresh` and `incremental`.

For the `2.2.1` customer line, this created avoidable noise:

- it exposed a reserved realtime panel on pages where the customer only uses batch flows
- it suggested an active CDC capability even when the current task was not a realtime task
- it pushed the actually useful task details further down the page

## Expected Behavior

Only `cdc` tasks should display the realtime-status card. Batch tasks should keep the detail page focused on execution info and incremental checkpoints.

## Candidate Fix Area

- `source/dts-platform-webapp/src/pages/explore/etl/TransformDetailPage.tsx`

## Verification Method

- `pnpm -C source/dts-platform-webapp build`
- confirm the page still compiles after gating realtime fetch/render logic by `syncMode`

## Root Cause

`TransformDetailPage.tsx` loaded and rendered realtime-status UI solely based on task existence. It did not use `task.syncMode` to determine whether the current task could legitimately surface realtime monitoring information.

## Fix

- stop loading realtime status when `task.syncMode !== "cdc"`
- clear stale realtime data for non-`cdc` tasks
- render the realtime-status card only when the current task is `cdc`

## Verification Result

- `pnpm -C source/dts-platform-webapp build`
  - `✓ built in 22.53s`

Result: the customer branch now hides the reserved realtime panel for batch tasks while keeping the existing `cdc`-ready UI path intact.
