# Sprint-10：dbt 工作区自举与产出表管理修复

## 目标

在 `v2.2.1` 版本线上把逻辑建模里的 dbt 工作区从“目录可写”提升为“最小可运行项目”，并同时修复两类核心问题：

1. **批量导入模型失败** — 空工作区下也能自动初始化骨架、预检 ZIP、稳定落盘
2. **清空/重建产出表失败** — 不再走通用 rollback 链路，改成 dbt 原生产出 relation 管理

## 范围

### 后端
- `source/dts-platform` — dbt 配置/工作区初始化、批量导入、模型产出表维护、Airflow 触发

### 前端
- `source/dts-platform-webapp/src/pages/modeling/` — 逻辑建模页、批量导入反馈、产出表维护交互

### 工作区
- `services/dts-dbt/` — 最小 dbt 项目骨架、models/sources/target/logs 目录

## 本 Sprint 不做

- 不引入完整的 dbt package/template marketplace
- 不做 dbt Git 初始化与远端仓库托管
- 不实现产出表下游依赖的完整血缘阻断，只提供提示与影响摘要
- 不改造客户环境的数仓物理 schema 规划
- 不重做逻辑建模整体信息架构

## 集成测试

`it/` 目录存放验证说明，覆盖：
- 空目录 `services/dts-dbt` 首次进入逻辑建模自动生成最小 dbt 工作区
- 单模型导入与 ZIP 批量导入在空工作区可成功落盘
- 批量导入缺文件/非法 layer/materialized 时能返回明确失败
- 清空产出表对 table 生效、对 view 给出明确拒绝
- 重建产出表执行 `drop relation + dbt build`
- 逻辑建模页不再调用 `/api/rollback/*` 管理 dbt 产出表
