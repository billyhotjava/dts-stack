# Sprint-13 设计：科研项目管理指挥大屏模板

日期：2026-03-16  
Sprint：`worklog/v2.2.1/sprint-13`

## 1. 背景

当前 `dts-analytics-webapp` 已有项目看板页 `/project-cockpit`，但页面形态仍然是“专题分析页”：

- 有页面头部和筛选区
- 通过 Tabs 切换不同主题
- 更接近日常经营分析，而不是会议室常驻大屏

客户明确偏向传统项目管理大屏，希望：

- 新建一套专用大屏
- 不动现有项目看板页面
- 适配 `1920x1080` 和 `2560x1440`
- `16:9` 横屏必须铺满，不能留边

同时，`worklog/v2.2.1/req/pm/project3.xlsx` 已经给出了本轮项目管理指标需求，适合作为大屏口径基线。

## 2. 设计目标

本次大屏设计目标是：

1. 在大屏工厂中新增一套内置模板，而不是继续扩展 `/project-cockpit`
2. 用 `3` 屏轮播承载领导总览、执行推进、风险变更三类信息
3. 风格回归科研院所常见的“指挥中心式”传统大屏，而不是 BI 分析页卡片风格
4. `project3.xlsx` 的业务口径由后端聚合接口负责表达，模板只负责展示
5. 公共运行态支持 `1080p` 和 `2K 16:9` 全屏铺满，不出现黑边或外层留白

## 3. 非目标

本 sprint 不做以下事项：

- 不替换现有 `/project-cockpit` 页面
- 不把现有普通页面直接强行改成大屏样式
- 不先做可视化设计器里的“完全可编辑行业包”
- 不为第一版引入新的重型自定义图表内核，优先复用现有 Screen Factory + ECharts/DataV 组件

## 4. 指标需求归并

`project3.xlsx` 的 `35` 条指标需求可以归并为四组语义：

### 4.1 项目总体完成态势

- 项目总数
- 完成项目数
- 按时完成项目数
- 超期完成项目数
- 异常待完成且已申请变更项目数
- 超期未完成且未变更项目数
- 超期未完成且已变更项目数
- 异常变更占比
- 超期项目占比

这组指标决定大屏的第一屏主 KPI 和总览趋势。

### 4.2 截止当前未完成节点风险

- 未完成高风险节点数
- 未完成中风险节点数
- 未完成里程碑节点数
- 未完成重大节点数
- 未完成重要节点数

这组指标决定风险热区、预警清单和项目健康度排行。

### 4.3 本周期节点执行与里程碑推进

- 本周期里程碑按时完成数
- 本周期里程碑超期完成数
- 本周期里程碑正常待完成数
- 本周期里程碑完成率
- 本周期高风险节点数
- 本周期中风险节点数
- 本周期里程碑节点数
- 本周期重大节点数
- 本周期重要节点数

这组指标决定第二屏的执行推进和里程碑主视图。

### 4.4 风险、延期与变更治理

- 超期未完成与是否变更的拆分
- 超期完成与是否变更的拆分
- 异常待完成且已变更项目
- 重点超期项目和异常项目清单

这组指标决定第三屏的风险与变更治理视图。

## 5. 为什么采用三屏轮播

不采用单屏，原因是单屏无法在不牺牲可读性的前提下同时容纳：

- 领导关心的总体态势
- 执行层关心的里程碑和节点清单
- 风险治理关心的归因、变更和异常项目

不采用超过三屏，原因是：

- 会议室常驻轮播过长会降低信息命中率
- 客户当前更看重稳定展示，不是交互式浏览

因此选择 `3` 屏是最平衡的方案：

1. 第一屏：总体态势
2. 第二屏：执行与里程碑
3. 第三屏：风险与变更

默认轮播建议为 `12-15` 秒一屏，循环播放；预览态可切换页面，公共运行态默认无显式操作控件。

## 6. 模板定义

建议新增模板：

- 模板名：`科研项目管理指挥大屏`
- 模板 ID：`project-management-command-center`
- 分类：`project-management`
- 形态：内置模板 + 多页轮播

它与现有 `project-management-cockpit` 的边界是：

- 旧模板：偏“项目管理驾驶舱”，更像单页 demo 化模板
- 新模板：偏“会议室指挥大屏”，强调三页结构、轮播、传统视觉语言和项目管理指标密度

## 7. 公共壳层设计

三屏共享同一套公共壳层：

- 左上：标题、副标题
- 中上：当前批次时间、数据更新时间、覆盖范围
- 右上：项目群 / 重大项目 / 日期区间 / 风险等级
- 顶部次级信息条：当前筛选摘要、轮播页签、告警数量

公共变量沿用项目看板现有过滤语义：

- `programId`
- `majorProjectId`
- `dateFrom`
- `dateTo`
- `deptId`
- `riskLevel`

第一版不引入与现有看板冲突的新业务筛选维度。

## 8. 三屏信息架构

### 8.1 第一屏：总体态势

目标问题：当前项目群整体是好转还是恶化，哪里最需要领导注意。

建议布局：

- 顶部 `8` 个核心 KPI
- 左中：项目总体趋势
- 右中：项目群/重大项目健康分布
- 左下：重点项目健康排行
- 右下：异常项目与预警清单

建议重点指标：

- 项目总数
- 完成项目数
- 按时完成率
- 超期项目数
- 异常变更项目数
- 未完成高风险节点数
- 未完成里程碑节点数
- 当前预警项目数

### 8.2 第二屏：执行与里程碑

目标问题：本周期执行卡在哪，里程碑推进是否失速。

建议布局：

- 顶部：本周期里程碑 KPI 条
- 中部左侧：里程碑推进趋势/柱图
- 中部右侧：项目执行主表或甘特视图
- 底部左侧：本周期节点分类统计
- 底部右侧：即将到期 / 已超期节点清单

建议重点指标：

- 本周期里程碑按时完成数
- 本周期里程碑超期完成数
- 本周期里程碑正常待完成数
- 本周期里程碑完成率
- 本周期高风险节点数
- 本周期中风险节点数
- 本周期重大节点数
- 本周期重要节点数

### 8.3 第三屏：风险与变更

目标问题：延期和异常主要来自哪里，变更是否真正发挥治理作用。

建议布局：

- 顶部：风险与变更 KPI
- 左中：风险等级结构 / 未完成节点风险分布
- 右中：延期原因矩阵 / 变更前后对比
- 左下：超期项目重点清单
- 右下：风险治理建议与异常治理摘要

建议重点指标：

- 超期未完成未变更项目数
- 超期未完成已变更项目数
- 超期完成未变更项目数
- 异常待完成已变更项目数
- 异常变更占比
- 超期项目占比

## 9. 视觉方向

本次视觉方向明确选择传统大屏风格，不沿用现有普通业务页视觉：

- 主色调：深蓝、钢青、冷灰
- 强调色：青色用于正常态，橙色用于预警，红色用于高风险
- 模块边界：发光描边、金属质感分区、顶部横向指挥条
- 字体与文案：偏正式、偏设备面板感，不做“互联网 BI 卡片化”

整体气质应接近：

- 科研院所项目指挥中心
- 型号/课题管理调度大屏
- 常驻会议室大屏

而不是：

- 电商运营屏
- 智慧城市宣传屏
- 浅色经营分析驾驶舱

## 10. 技术落点

### 10.1 模板运行形态

前端基于现有 Screen Factory 落地：

- `pages`
- `carouselConfig`
- `globalVariables`
- 现有图表和表格组件

模板不走普通 React 页面壳，而是作为内置模板进入大屏模板库。

### 10.2 数据供给策略

后端继续复用 `ProjectCockpitService` 所掌握的数据上下文，但新增专门的大屏聚合接口：

- `/api/project-cockpit/screen/header`
- `/api/project-cockpit/screen/overview`
- `/api/project-cockpit/screen/execution`
- `/api/project-cockpit/screen/risk`

原因是：

- `project3.xlsx` 里的统计口径需要在后端统一固化
- 模板层不应该自己拼装“超期未完成已变更”这类业务语义
- 后续如果客户确认某个口径要调整，只需改聚合接口，不必改大屏布局

### 10.3 Screen Runtime 的一个现实约束

当前 Screen Runtime 对 `api` 数据源的支持只够发静态 URL/Body，请求体不会自动带上大屏运行时的全局变量。  
如果直接用现状做模板，模板里的筛选变量无法真实驱动接口查询。

因此第一版实现里需要补一层运行时能力：

- 支持 `apiConfig.params` 使用全局变量占位
- 支持 `apiConfig.body` 使用全局变量占位
- 或者在 `POST` 请求中自动附带 `queryContext.globalVariables`

这一步不是锦上添花，而是新模板能否真正可用的前置条件。

## 11. 全屏自适应方案

本次大屏的基准画布仍然是：

- `1920 x 1080`

但运行态必须满足 `2560 x 1440` 同样铺满，因此需要调整当前 Runtime 的缩放策略。

当前 `ScreenPreviewPage` 和 `PublicScreenPage` 的自动缩放逻辑只允许缩小，不允许放大，并且会预留外层安全边距；这会导致：

- `2K 16:9` 上内容不铺满
- 相同宽高比下仍可能出现外边距

目标行为应为：

- `1920x1080` 下比例为 `1`
- `2560x1440` 下比例为 `1.333...`
- 对于公共运行态，大屏画布直接贴满屏幕
- 对于预览态，编辑工具栏与画布区域分离，进入全屏预览时同样不留边

## 12. 验收标准

满足以下条件即可认为设计闭环：

1. 模板库中能看到新的 `科研项目管理指挥大屏`
2. 从模板创建后得到 `3` 屏轮播结构
3. 三屏内容分别对应“总体态势 / 执行与里程碑 / 风险与变更”
4. `project3.xlsx` 的核心指标在接口口径中可追溯
5. 不影响现有 `/project-cockpit`
6. 公共运行态在 `1920x1080` 和 `2560x1440` 下都无边铺满

## 13. 工作量判断

按当前架构，实施工作量仍维持此前评估：

- 设计与指标映射：`2-3` 人天
- 后端聚合接口：`4-6` 人天
- 模板与三屏编排：`5-7` 人天
- 全屏适配与运行时补强：`1-2` 人天
- 联调与 UAT：`2-3` 人天

总量约为：`14-21` 人天。
