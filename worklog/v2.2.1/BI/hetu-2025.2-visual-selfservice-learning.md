## 1. 重点可学习方向（聚焦你关心的两块）

### 1.1 可视化交互：从“图表动作”升级到“分析动作”
- 学习点 A：交互动作不只筛选/跳转，还要支持“解释”“诊断”“建议下一步”。
- 学习点 B：全局筛选器 + 跨组件联动要有“影响范围可视化”，避免黑盒联动。
- 学习点 C：图表上直接做分析（hover/click 后出现“同比、环比、异常原因、下钻路径”）。
- 学习点 D：从设计器到运行时保持一致（所见即所得 + 可追溯）。

### 1.2 自助分析：从“问数”升级到“可闭环”
- 学习点 E：自然语言到 SQL 只是起点，必须补齐“口径解释 + 血缘 + 权限 + 审计”。
- 学习点 F：要让业务用户看到“我为什么得到这个结论”（可解释查询计划）。
- 学习点 G：支持“问题 -> 结果 -> 报告”一键沉淀，变成可复用资产。
- 学习点 H：语义层优先，降低业务侧对底层表结构/SQL 的依赖。

## 2. 与 DTS BI 现状对照（基于 `worklog/v2.2.1/BI/tasks`）

### 2.1 已经在路上的能力（继续做深）
- `P1-02-global-filter-interaction-engine.md`
  - 已覆盖全局筛选器与联动引擎，是承接“分析动作化”的基础。
- `P1-01-datasource-unification-sql-mode.md`
  - 已覆盖 SQL/语义双模式，是承接“自助分析闭环”的底座。
- `P2-01-ai-screen-copilot.md`
  - 已覆盖 NL2SQL/NL2Viz 方向，是“问答即洞察”的入口能力。
- `P0-04-release-acl-audit-sharing.md`
  - 已覆盖 ACL/审计/分享，满足企业级治理要求。

### 2.2 主要差距（需要新增或前移）
- 差距 1：交互后“解释层”不足
  - 现状：联动已做，但“为什么变了、建议看什么”不够显式。
- 差距 2：自助分析会话化不足
  - 现状：有查询与图表，但“问题-探索-结论-报告”链路还不完整。
- 差距 3：指标口径可视化不足
  - 现状：语义能力在增强，但口径解释与血缘展示还不够前台化。
- 差距 4：报告自动化不足
  - 现状：有导出能力（P2-02），但模板化自动报告与分发编排能力偏弱。

## 3. 建议新增任务（对现有任务体系的增量，不推翻原计划）

### P1 新增（建议并行）
- `P1-06 分析解释层（Explainability Layer）`
  - 内容：查询解释卡、指标口径卡、筛选影响范围、异常诊断摘要。
  - 验收：任意图表可在 1 次点击内看到“口径+过滤+来源+建议下钻”。

- `P1-07 自助分析会话（Explore Session）`
  - 内容：问题历史、分析步骤树、结论标注、会话保存与复盘。
  - 验收：业务用户可保存会话并二次编辑，复盘路径完整。

### P2 增强（与 AI 任务联动）
- `P2-04 智能报告工厂（Report Factory）`
  - 内容：从会话自动生成报告模板（摘要、图表、结论、风险点）、定时分发。
  - 验收：支持按部门/角色分发，支持审计留痕。

- `P2-05 指标语义透视台（Metric Lens）`
  - 内容：指标定义、版本、血缘、口径冲突检测、权限范围一体展示。
  - 验收：用户可直接看到“本图使用了哪些指标口径与版本”。

## 4. 推荐实施顺序（8~10 周）
- 第 1 阶段（2~3 周）：先落 `P1-06`（解释层），最快提升“可理解性”。
- 第 2 阶段（2~3 周）：再落 `P1-07`（会话化），形成“自助分析可闭环”。
- 第 3 阶段（3~4 周）：推进 `P2-04` 与 `P2-05`，形成差异化对外能力。

## 5. 结论
- Hetu 方向最值得学的不是“多几个图表”，而是把 BI 变成“可解释、可复用、可闭环”的分析系统。
- DTS 当前基础（统一内核、联动引擎、AI Copilot、ACL 审计）已经具备，下一步核心是把“解释层 + 会话层 + 报告层”补齐。
