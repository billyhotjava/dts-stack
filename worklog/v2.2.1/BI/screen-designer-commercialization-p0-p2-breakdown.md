# 大屏设计器商用化任务分解（P0/P1/P2）

> 基于 DTS 当前实现与 DataEase/FineBI/DataV 等商用能力对比形成。
>
> 文档日期：2026-02-13
> 目标：将「可用设计器」升级为「可规模交付的商用产品能力」。

---

## 0. 分解原则
- 任务按 `P0 -> P1 -> P2` 推进，前一阶段未达验收门槛，不进入下一阶段。
- 每个任务均包含：后端、前端、测试、运维/发布四类子任务。
- 验收以“可演示 + 可审计 + 可回滚”为标准，不以“代码完成”替代。

---

## 1. P0（必须，商用准入）

### V221-SD-P0-001 发布体系（草稿/发布/回滚）
- 目标：解决当前“保存即覆盖、不可回滚”的生产风险。
- 子任务：
  - BE-1：新增 `analytics_screen_version`（版本号、状态、配置快照、发布人、发布时间）。
  - BE-2：`/api/screens` 增加草稿保存、发布、版本列表、回滚 API。
  - FE-1：设计器 Header 增加“发布/回滚/版本历史”入口。
  - FE-2：预览默认加载“已发布版本”，编辑默认加载“草稿”。
  - QA-1：覆盖并发发布、回滚后预览一致性、历史版本只读。
- 交付物：
  - 版本表 DDL + 迁移脚本
  - 发布/回滚 API 文档
  - 前端发布流程与版本侧栏
- 验收标准：
  - 连续发布 10 次后可任意回滚到历史版本。
  - 公开链接始终指向“最新发布版”，不会读到草稿。

### V221-SD-P0-002 权限体系（查看/编辑/发布分权）
- 目标：将“能登录即可操作”升级为可审计的最小权限模型。
- 子任务：
  - BE-1：补 `analytics_screen_acl`（subject_type、subject_id、perm）。
  - BE-2：Screen API 增加 ACL 校验（read/edit/publish/manage）。
  - FE-1：列表与编辑页按权限控制按钮显隐（发布、删除、分享、编辑）。
  - FE-2：新增“成员授权”弹窗（用户/角色维度授权）。
  - QA-1：越权回归（无编辑权限不可写、无发布权限不可发版）。
- 交付物：
  - ACL 数据模型与权限矩阵
  - 权限拦截器与错误码规范
- 验收标准：
  - 角色矩阵回归 100% 通过。
  - 任意越权操作均返回一致错误码且有审计记录。

### V221-SD-P0-003 分享安全（过期/密码/IP 白名单）
- 目标：让公开链接满足客户内控要求。
- 子任务：
  - BE-1：扩展 `analytics_public_link`（expire_at、password_hash、ip_allowlist、disabled）。
  - BE-2：PublicResource 增加访问前校验链（时效、密码、来源 IP）。
  - FE-1：分享弹窗增加安全策略配置项。
  - FE-2：公开页增加密码输入与错误提示。
  - QA-1：过期、口令错误、IP 不匹配、禁用链接回归。
- 交付物：
  - 安全分享配置 UI
  - 公开访问校验与审计日志
- 验收标准：
  - 4 类拒绝场景均可稳定复现并有日志。
  - 分享策略改动 30 秒内生效。

### V221-SD-P0-004 操作审计（谁改了什么）
- 目标：满足甲方审计追踪要求。
- 子任务：
  - BE-1：新增 `analytics_screen_audit_log`（actor、action、before/after 摘要、request_id）。
  - BE-2：覆盖 create/update/publish/rollback/share/delete。
  - FE-1：列表页增加“操作记录”抽屉，支持按时间/用户筛选。
  - QA-1：核对审计记录与真实操作一致性。
- 交付物：
  - 审计表与写入链路
  - 审计查询 API + 前端查询页
- 验收标准：
  - 关键动作日志覆盖率 100%。
  - 审计记录可按大屏 ID 全链路追溯。

### V221-SD-P0-005 稳定性与可观测（500/502 可定位）
- 目标：把“现场排障靠猜”变成“可定位、可恢复”。
- 子任务：
  - BE-1：统一异常码（数据源不可达、SQL 执行失败、权限失败、版本冲突）。
  - BE-2：为 Screen/Card 查询链路补 metrics（成功率、P95、错误分布）。
  - FE-1：预览页统一错误层（可重试、错误码、requestId 展示）。
  - OPS-1：补健康检查与依赖探测（DB、外部数据源、缓存）。
  - QA-1：故障注入回归（DB 断开、数据源超时、接口 5xx）。
- 交付物：
  - 错误码手册
  - 监控看板（成功率/P95/错误码 TopN）
- 验收标准：
  - 线上 500/502 问题可在 15 分钟内定位根因范围。

### V221-SD-P0-006 浏览器兼容基线（含旧版 Chrome）
- 目标：避免“新浏览器正常、客户旧环境不可用”。
- 子任务：
  - FE-1：建立兼容基线（Chrome 95/109/最新版、Edge LTS）。
  - FE-2：主题变量/颜色降级兜底，补关键 CSS fallback。
  - QA-1：录制核心路径脚本（编辑、预览、分享）并做兼容回归。
- 交付物：
  - 兼容性测试报告
  - 关键样式降级修复清单
- 验收标准：
  - 基线浏览器全部通过核心用例。

## 2. P1（增强，形成“成熟产品感”）

### V221-SD-P1-001 语义层接入（指标口径统一）
- 目标：大屏不再直接耦合裸 SQL，统一到语义指标层。
- 子任务：
  - BE-1：屏幕组件数据源支持绑定“指标实体/数据集版本”。
  - BE-2：查询链路记录“指标 ID + 版本 + 执行 SQL”用于追溯。
  - FE-1：数据源面板新增“指标选择器/版本选择器”。
  - QA-1：口径变更后历史版本展示一致性。
- 交付物：
  - 指标绑定协议
  - 追溯字段与查询 API
- 验收标准：
  - 同一指标在多屏口径一致，变更可追溯。

### V221-SD-P1-002 全局变量与跨组件联动
- 目标：支持筛选联动、钻取联动、页面级参数。
- 子任务：
  - FE-1：新增全局变量管理（日期、组织、关键词、枚举）。
  - FE-2：组件支持 `{{global.xxx}}` 参数绑定与事件触发。
  - BE-1：查询 API 增加安全参数透传与白名单校验。
  - QA-1：联动链路回归（1->N 组件联动、循环依赖检测）。
- 交付物：
  - 全局变量配置面板
  - 联动规则执行引擎（前端）
- 验收标准：
  - 10+ 组件联动场景响应可控，无死循环。

### V221-SD-P1-003 资产中心（模板/组件/主题）
- 目标：形成“可复用资产”而非一次性页面。
- 子任务：
  - BE-1：模板资产表（分类、标签、封面、版本、权限）。
  - FE-1：模板市场页（搜索、筛选、预览、收藏、克隆）。
  - FE-2：主题包导入导出（含品牌色、字体、背景、组件默认样式）。
  - QA-1：模板克隆后配置隔离、升级兼容。
- 交付物：
  - 模板市场
  - 主题包机制
- 验收标准：
  - 新项目可在 30 分钟内通过模板落地一套可用大屏。

### V221-SD-P1-004 数据源能力补齐（API/DB/Card 一致化）
- 目标：修复“类型定义有 api/database，UI 仅支持 card/static”的断层。
- 子任务：
  - FE-1：PropertyPanel 开放 `api/database` 配置入口。
  - BE-1：统一数据源执行协议（超时、重试、错误码、脱敏）。
  - BE-2：数据库连接探活与权限校验。
  - QA-1：三类数据源一致性回归。
- 交付物：
  - 数据源统一配置面板
  - 数据源执行协议文档
- 验收标准：
  - 三类数据源在预览与发布环境行为一致。

### V221-SD-P1-005 性能优化（缓存与预计算）
- 目标：大屏加载稳定在可演示、可交付范围。
- 子任务：
  - BE-1：查询结果缓存（按数据源+参数+版本 key）。
  - BE-2：预热任务（发布后自动预热关键组件）。
  - FE-1：分批渲染与骨架屏，降低首屏白屏时间。
  - QA-1：压测与性能基线（组件数 50/100）。
- 交付物：
  - 缓存策略与预热任务
  - 性能压测报告
- 验收标准：
  - 常规大屏首屏 < 3s，缓存命中后刷新 < 1s（目标值）。

## 3. P2（差异化，形成壁垒）

### V221-SD-P2-001 AI 生成大屏（NL2SQL -> NL2Viz）
- 目标：把你现有 NL2SQL 能力延展到“自动生成可编辑大屏”。
- 子任务：
  - AI-1：提示词协议（业务目标、口径、时间范围、主题风格）。
  - BE-1：生成结果标准化为 screen schema（组件+布局+数据绑定）。
  - FE-1：提供“AI 生成草稿”入口与差异确认。
  - QA-1：评估指标（正确率、可编辑率、用户二次修改成本）。
- 交付物：
  - AI 大屏生成 API
  - 生成质量评估报告
- 验收标准：
  - 典型场景一次生成可用率达到设定阈值（建议 >= 70%）。

### V221-SD-P2-002 插件化架构（组件 SDK / 数据源 SDK）
- 目标：让行业功能可外包开发、可按客户扩展。
- 子任务：
  - BE-1：插件清单、签名校验、启停与版本管理。
  - FE-1：组件 SDK（属性面板 schema + renderer contract）。
  - FE-2：数据源 SDK（连接参数 schema + 查询适配 contract）。
  - OPS-1：插件隔离策略（资源限流、异常熔断）。
- 交付物：
  - SDK 文档与示例插件
  - 插件管理台
- 验收标准：
  - 第三方可在不改主仓核心代码情况下接入新组件/新数据源。

### V221-SD-P2-003 行业包与交付包（硬件一体化预置）
- 目标：面向“软硬一体交付”，沉淀可复制行业包。
- 子任务：
  - BE-1：行业包打包格式（模板、数据连接、权限策略、设备参数）。
  - FE-1：一键安装行业包向导。
  - OPS-1：离线部署包（含依赖镜像、初始化脚本、健康检查脚本）。
  - QA-1：离线机房升级/回滚演练。
- 交付物：
  - 行业包规范
  - 离线交付工具链
- 验收标准：
  - 新现场可在限定时间内完成“安装-初始化-上线”。

### V221-SD-P2-004 企业级合规增强（xpack 方向）
- 目标：支持更高等级客户的审计与安全要求。
- 子任务：
  - BE-1：细粒度脱敏（列级/规则级）。
  - BE-2：审计报表导出（审计追踪、访问热度、越权尝试）。
  - FE-1：合规配置中心（可视化策略管理）。
  - QA-1：合规场景回归与渗透测试。
- 交付物：
  - 合规能力开关与策略中心
  - 合规审计报表
- 验收标准：
  - 通过目标客户内审条目。

## 4. 里程碑与排期建议
- M1（4~6 周）：完成 P0 全项，形成“可商用试点”版本。
- M2（6~10 周）：完成 P1，形成“可复制交付”版本。
- M3（8~12 周）：完成 P2 核心项，形成“差异化销售”版本。

## 5. 风险与依赖
- 依赖平台统一权限中心与组织架构数据准确性。
- 依赖数据源网络连通与现场防火墙策略（尤其跨网段）。
- 依赖统一日志与监控基础设施；否则 P0-005 很难闭环。
- AI 能力效果受行业语料质量影响，需要最小可用语料集。

## 6. 建议执行顺序（落地）
1. 先做 `P0-001/002/003`（发布、权限、分享），构建商用最小闭环。
2. 再做 `P0-004/005/006`（审计、稳定、兼容），压住现场风险。
3. 进入 P1 时优先 `P1-004`（数据源补齐）与 `P1-002`（联动），直接提升可见价值。
4. P2 先上 `P2-001`（AI 生成草稿），最快形成市场差异化演示。
