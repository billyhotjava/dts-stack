# 财务大屏模板族插件化重构设计

## 背景

`dts-analytics-webapp/modern` 当前已经内置了四套财务大屏模板：

- `fin-auxiliary-balance`
- `fin-own-fund`
- `fin-personal-balance`
- `fin-project-fund`

它们都写在 `src/pages/screens/screenTemplates.ts` 中，但当前实现只是基于现有基础组件的低保真拼装版，和需求侧提供的四个财务原型存在明显偏差：

- 视觉风格被统一改成深色 `glacier`，没有保留财务原型的白底蓝条驾驶舱语言
- 原型中的筛选条、说明区、排行区、合计区、状态块等区块被简化或删除
- 原型里的瀑布图、矩形树图、双仪表盘、复合说明块没有被完整映射
- 当前模板虽然能被设计器读取，但编辑体验停留在“普通通用组件拼装”，不能表达财务模板族的统一设计语言

本次目标不是把 `worklog/v2.2.2/req/fin/dashboard-*.jsx` 直接搬进运行时，而是在现有大屏引擎中补一层“财务组件族”，用插件化和组合组件的方式重写这四套模板。

## 目标

在不破坏现有大屏设计器和运行时协议的前提下，完成以下目标：

- 为财务大屏建立统一的组件化设计语言
- 将四套财务模板升级为“财务模板族”
- 尽量对齐四个 JSX 原型的信息结构和主要视觉方向
- 保留设计器中的二次拖拽、编辑、保存和再次打开能力

## 非目标

本次不做以下内容：

- 不新增独立于大屏系统之外的四个专用页面
- 不引入运行时 CDN 加载 ECharts 的方式
- 不重写大屏整体协议、设计器布局模型或存储格式
- 不自动迁移已基于旧模板创建的历史实例

## 当前约束

当前系统具备以下能力，可直接复用：

- `ScreenComponent` / `ScreenConfig` / `specV2` 作为设计器协议
- `RendererPlugin` 机制作为自定义渲染扩展点
- 组件库、设计器、模板选择器、预览页、公屏运行页已经接通
- 现有图表 renderer 已支持 `bar-chart`、`pie-chart`、`gauge-chart`、`treemap-chart`、`waterfall-chart`

因此最合理的做法不是做“整屏黑盒”，而是在现有协议内增加一组财务专用组件。

## 方案对比

### 方案 A：整屏单插件

每套财务屏做成一个整页插件组件。

优点：

- 原型还原速度最快
- 组件内部布局自由度最高

缺点：

- 设计器里只能拖一个整块
- 内部元素不可拆、不可独立挪动
- 不满足“继续支持在设计器里可编辑、可二次拖拽配置”

结论：不采用。

### 方案 B：继续增强 `screenTemplates.ts`

只在模板层继续堆通用组件。

优点：

- 改动面最小
- 不需要新增插件组件

缺点：

- 无法承载财务模板族的统一风格
- 说明区、排行区、状态块、财务表格壳等只能继续零散写死
- 后续四套模板维护成本高，复用弱

结论：不采用。

### 方案 C：财务组件族插件 + 财务模板族

新增一组 `finance-*` renderer plugin，并用它们重写四套财务模板。

优点：

- 满足“可编辑、可拖拽、可二次配置”
- 能较完整映射财务原型的信息结构和视觉方向
- 四套模板共享同一层财务设计语言，后续维护成本最低

缺点：

- 工程量高于单纯改模板
- 需要补插件注册、组件库、属性面板、模板重写和测试

结论：采用此方案。

## 总体架构

本次重构分三层：

### 1. 基础引擎层

保持现有能力不变：

- `specV2.ts`
- `ScreenDesignerPage.tsx`
- `ComponentRenderer.tsx`
- `PluginRenderBoundary.tsx`
- `builtinPluginAdapters.tsx`

即：不改变设计器协议、不改变页面存储模型、不改变运行时入口。

### 2. 财务组件层

新增财务专用 renderer plugin，形成一套可复用组件族。

首批组件建议包括：

- `finance-shell`
- `finance-header-bar`
- `finance-filter-strip`
- `finance-kpi-card`
- `finance-ranking-list`
- `finance-summary-table`
- `finance-note-panel`
- `finance-status-grid`

这些组件统一承担：

- 白底财务驾驶舱视觉
- 蓝色标题栏
- 浅色筛选区
- 财务 KPI 卡片
- 排行、说明、状态卡、合计表等结构化区块

### 3. 财务模板层

四套财务模板重写为“财务组件 + 现有图表组件”的组合：

- 辅助余额表_项目维度
- 辅助余额表_个人维度
- 自有资金表
- 项目经费表

模板只负责默认布局、默认文案、默认静态数据和默认组件组合，不再承担视觉壳层逻辑。

## 组件设计

### finance-shell

职责：

- 提供白底页面基底
- 统一内容区最大宽度、外边距、底部状态条
- 承载底部轻说明或系统状态

设计要求：

- 设计器中仍表现为普通组件，可移动、可缩放
- 支持配置主背景色、内边距、底部文案

### finance-header-bar

职责：

- 提供蓝色顶部栏
- 显示 logo 区、主标题、副标题、日期时间

设计要求：

- 标题、副标题、logo 文案可配置
- 时间格式可配置
- 不把时间显示逻辑散落到模板文本组件里

### finance-filter-strip

职责：

- 统一财务筛选区表现
- 支持标签、下拉、关键词输入、清空操作、统计提示

设计要求：

- 插件内支持渲染多个筛选项描述
- 与全局变量绑定兼容
- 保留“清空筛选”语义

### finance-kpi-card

职责：

- 统一 KPI 卡表现
- 支持主值、单位、副说明、语义颜色

设计要求：

- 与当前 `number-card` 区分，保留财务卡片风格
- 暴露 title/value/unit/sub/color 等基础属性

### finance-ranking-list

职责：

- 用于合同 TOP、借款 TOP 等场景
- 支持序号、主标签、副标签、金额高亮

### finance-summary-table

职责：

- 用于财务明细表
- 支持表头、斑马纹、金额列对齐、固定头、合计行

说明：

- 不追求这次支持全部复杂多级表头
- 先覆盖四套财务模板目前所需的单表头 + 合计行 + 金额高亮
- 若后续自有资金表需要完整双层表头，再扩第二阶段

### finance-note-panel

职责：

- 用于指标口径、说明文字、业务规则解释

### finance-status-grid

职责：

- 用于项目经费页“正常 / 超支 / 偏快 / 偏慢”状态块

## 图表策略

图表层尽量复用已有 renderer，不重复造轮子。

直接复用：

- `bar-chart`
- `pie-chart`
- `gauge-chart`
- `treemap-chart`
- `waterfall-chart`

需要新增的是“财务默认配置”和模板编排，而不是新的图表引擎。

如个别现有 renderer 无法满足原型要求，只允许做最小增强：

- 样式默认值增强
- label / legend / title 排版增强
- 色板和 tooltip 预设增强

不允许为了财务模板单独再写第二套 chart renderer。

## 设计器编辑能力要求

这是本次设计的硬约束。

必须保证：

- 每个财务区块是独立 `ScreenComponent`
- 可以单独拖拽、缩放、删除、复制
- 可以在属性面板中编辑文案和关键配置
- 模板创建出的页面再次打开时仍是普通设计器页面

明确不允许：

- 把整屏做成一个不可拆解的大组件
- 让模板只能在运行态看、设计器里无法编辑
- 引入只能预览、不能保存回配置的运行时状态

## 属性面板策略

财务组件的属性面板只暴露高价值配置，不做过度可配：

- 标题 / 副标题
- 主题色 / 标题色 / 强调色
- KPI 值 / 单位 / 副说明
- 排行列表项
- 表格列 / 数据 / 合计文案
- 说明块文案
- 统计数字与状态块数值

不做：

- 任意 CSS 文本编辑
- 任意嵌套布局 DSL
- 在首期暴露过多细节属性，导致组件难用

## 迁移策略

本次仅重写模板定义，不自动迁移已创建实例。

策略如下：

- 保留四个现有模板 ID
- 用新模板内容替换旧模板内容
- 新创建的大屏实例使用新模板
- 已经创建出来的旧实例保持原状，用户如需升级可手工基于新模板重建

这样可以避免：

- 历史大屏被静默改样式
- 存量实例在没有迁移脚本的情况下发生布局破坏

## 测试策略

### 单元测试

- 财务插件 property schema 正确
- 关键渲染分支正确
- 默认配置生成稳定

### 模板测试

- 四套模板都能从 `getTemplateById` 取到
- 关键财务组件存在
- 组件数量和主要类型符合预期

### 设计器契约测试

- 基于模板创建后的 screen config 能通过 `specV2` 规范化
- 设计器可以加载、编辑、再次保存

### 页面回归

- 模板在预览页正常渲染
- 大屏管理中新建模板正常
- 模板不会破坏现有非财务模板

## 风险

### 风险 1：插件组件太黑盒

如果组件内部封装过重，会削弱设计器编辑能力。

控制措施：

- 严格按“区块组件”而不是“整屏组件”设计

### 风险 2：模板和插件职责混乱

如果视觉壳、文案、布局、数据都堆进插件，会让模板失去价值。

控制措施：

- 插件负责区块样式和区块行为
- 模板负责页面编排和默认内容

### 风险 3：图表差异过大导致范围失控

控制措施：

- 首期只做最小图表增强
- 图表 renderer 复用优先，禁止再造第二套图表系统

## 成功标准

- 四套财务模板视觉方向与 `worklog/v2.2.2/req/fin/dashboard-*.jsx` 明显对齐
- 四套模板使用统一的财务组件族，而不是继续散落在模板里手工拼装
- 模板在设计器中仍可编辑、可拖拽、可保存、可再次打开
- 不影响现有大屏系统的非财务模板
