# DTS_GPMC 项目运营管理指挥中心 — 设计方案

## 1. 产品定位

面向科研院所/集团企业的**项目群运营管理指挥中心**，覆盖进度、质量、技术状态、成本、风险、资源六大域，支持战略层（领导）、管控层（PMO）、执行层（项目经理）三层视角，适配 PC/投影/大屏三种终端。

### 与现有系统的关系
- **大屏编辑器**：保留做模板设计工具，GPMC 可读取其模板配置
- **项目看板**：保留做深度分析入口，GPMC 的 drill 操作跳转到看板
- **GPMC**：新模块，独立路由 `/analytics/gpmc`，响应式布局，不依赖 1920×1080 画布

## 3. 六块大屏定义

### 3.1 综合态势总览 (Overview)

| 层级 | 内容 |
|------|------|
| **战略层** | 项目总数/在建/延期/高风险 KPI、年度预算vs执行、完成率趋势(环比/同比)、风险热力分布、事业部排名 |
| **管控层** | 项目健康矩阵表（编号/名称/责任人/计划vs实际/执行率/状态/风险等级）、部门成本核算 |
| **执行层** | 预警摘要（关键里程碑逾期/需求变更频繁/资源缺口） |

数据来源：进度管理表 + 全域汇总

### 3.2 项目执行监控 (Execution)

| 层级 | 内容 |
|------|------|
| **战略层** | 整体完成率/里程碑达成率/关键路径偏差 |
| **管控层** | 延期 TOP10 项目、科室负载分布、阶段分布饼图 |
| **执行层** | 甘特图(必须)、里程碑清单、任务阻塞链路 |

数据来源：进度管理表

### 3.3 质量与技术状态 (Quality)

| 层级 | 内容 |
|------|------|
| **战略层** | 质量问题总量/归零率/技术状态变更数 |
| **管控层** | 质量问题分类分布(设计/工艺/管理/元器件/...)、归零进度 |
| **执行层** | 未归零问题清单、技术状态变更签署进度 |

数据来源：质量问题记录表 + 技术状态信息汇总表

### 3.4 成本与预算控制 (Cost)

| 层级 | 内容 |
|------|------|
| **战略层** | 年度预算总额/执行额/预算执行率/预算偏差 |
| **管控层** | 部门成本核算（实际vs预算进度条）、累计超支/预算效率/燃尽率 |
| **执行层** | 月度支出趋势、成本异常预警 |

数据来源：**模拟数据**（后续对接财务系统）

### 3.5 风险与预警中心 (Risk)

| 层级 | 内容 |
|------|------|
| **战略层** | 风险总数/高风险占比/风险趋势 |
| **管控层** | 风险矩阵(概率×影响)、风险分类分布、变更频率 |
| **执行层** | 风险跟进清单、闭环状态、跟进措施 |

数据来源：风险信息汇总表 + 风险跟进表

### 3.6 资源负载与协同 (Resource)

| 层级 | 内容 |
|------|------|
| **战略层** | 总人力投入/资源利用率/协同效率 |
| **管控层** | 科室负载热力图、跨部门协同矩阵 |
| **执行层** | 责任人任务分布、工时统计 |

数据来源：进度管理表(责任人/科室) + **模拟数据**

## 4. 三层架构交互模式

```
┌─────────────────────────────────────┐
│  战略层 (默认视图)                    │
│  一屏看全局 — "是否健康？是否失控？"   │
│                                     │
│  KPI 卡片 → 点击下钻到管控层          │
│  图表 → 点击下钻到管控层              │
└──────────────┬──────────────────────┘
               │ drill-down
               ▼
┌─────────────────────────────────────┐
│  管控层                              │
│  看问题在哪 — "哪里出问题？谁在拖？"   │
│                                     │
│  表格行 → 点击下钻到执行层            │
│  面包屑 → 回到战略层                  │
└──────────────┬──────────────────────┘
               │ drill-down
               ▼
┌─────────────────────────────────────┐
│  执行层                              │
│  能落地 — "怎么解决？"               │
│                                     │
│  甘特图/清单/责任人详情               │
│  面包屑 → 回到管控层或战略层          │
│  "跳转看板" → 打开项目看板深度分析     │
└─────────────────────────────────────┘
```

## 6. 响应式适配

| 终端 | 分辨率 | 适配策略 |
|------|--------|---------|
| PC | 1366-1920 | CSS Grid 12列，面板自适应 |
| 投影 | 1920×1080 | 全屏模式，字号放大，隐藏侧边栏 |
| 大屏 | 3840×2160+ | 同投影模式，`transform: scale` 缩放 |

## 7. 技术约束

- Chrome 95+ 兼容（客户离线环境）
- 无 CDN 依赖，所有资源本地化
- ARM/Kunpeng + KylinOS 适配
- ECharts 本地 bundle（已有）
- 后端：Spring Boot 3.4.5 + Java 21 + PostgreSQL 17.6

## 8. 分期交付计划

### Phase 1: 基础框架 + 综合态势 + 项目执行（4 周）
- GPMC 模块骨架（路由/布局/主题/导航）
- 综合态势总览（战略层+管控层）
- 项目执行监控（三层完整）
- Light/Dark 主题切换
- PC + 投影适配

### Phase 2: 风险 + 质量（3 周）
- 风险与预警中心（三层完整）
- 质量与技术状态（三层完整）
- 三层 drill-down 交互完善
- 与项目看板联动

### Phase 3: 成本 + 资源 + 故事线（3 周）
- 成本与预算控制（模拟数据）
- 资源负载与协同（模拟数据）

- 大屏适配

### Phase 4: 打磨 + 对接（2 周）
- 成本/资源真实数据对接
- 性能优化
- 现场部署验证
