# 项目运营管理大屏五屏重平衡设计

## 背景

当前 `项目运营管理大屏` 已从 3 屏扩到 5 屏，但结构已经失衡：

- 原第 4 屏 `指标全览` 只展示系统原始值，和第 5 屏 `指标对账` 职责重叠。
- 第 5 屏已经覆盖全量 34 项 `系统值 / Excel 值 / 差值 / 状态`，能够承担客户核对 Excel 的职责。
- 与 `项目看板` 相比，大屏仍缺 `项目树 / 重点项目穿透` 这一类传统指挥屏最有价值的内容。
- 客户明确不需要再保留 `口径支撑` 风格页面，因为 `指标对账` 已承担核对职责。

## 目标

将当前大屏重平衡为 5 屏：

1. 总体态势
2. 执行与里程碑
3. 风险归因
4. 项目树与重点项目
5. 指标对账

## 非目标

- 本轮不再恢复 `指标全览` 独立屏。
- 本轮不引入 `口径支撑` 独立屏。
- 本轮不把项目看板 React 组件直接嵌入 Screen Runtime。

## 设计原则

- 保留传统大屏的“扫一眼”节奏，不把管理页 1:1 搬进大屏。
- 对账能力集中在第 5 屏，不再分散到单独“系统值全览”屏。
- 第 4 屏使用大屏原生组件表达 `项目树摘要 + 重点项目详情`，不引入新的运行时渲染内核。
- 预览态、发布态、public 分享态必须走同一套 API/runtime 链路。

## 最终五屏信息结构

### 第 1 屏：总体态势

- 保留现有 KPI、排名、告警主体结构
- 增强 `项目趋势`
- 补 `完成率环形图`
- 补 `健康度雷达图`
- 保留 `总览摘要 / 重点预警`

### 第 2 屏：执行与里程碑

- 保留并增强 `甘特图`
- 补 `里程碑完成率环形`
- 补 `执行摘要 KPI`
- 保留 `到期 / 超期列表`

### 第 3 屏：风险归因

- 保留风险等级分布、延期原因结构、延期趋势
- 补 `延期原因矩阵/热力表达`
- 补 `治理摘要`

### 第 4 屏：项目树与重点项目

- 左上：树摘要 KPI
- 左下：重点项目列表
- 右上：子项目/节点明细
- 右下：关键节点链/重点盯防节点

这一屏不追求把项目看板树控件原样搬进来，而是把 `major-project-tree` 的数据重组为传统指挥屏更适合的表格与摘要。

### 第 5 屏：指标对账

- 保留当前 `指标对账`
- 展示全量 34 项
- 保留重复校验项
- 继续承担客户 Excel 对账职责

## 数据策略

### 第 1/2/3 屏

继续优先复用已有：

- `/analytics/api/project-cockpit/screen/overview`
- `/analytics/api/project-cockpit/screen/execution`
- `/analytics/api/project-cockpit/screen/risk`

必要时只在已有返回结构中补字段，不新增无边界专题接口。

### 第 4 屏

新增轻量 `screen/tree` 聚合，目标不是复制项目看板接口，而是提供大屏更直接可绑的数据结构：

- `summary`
- `focusProjects`
- `subprojectRows`
- `focusNodes`

底层仍复用现有 `majorProjectTree()` 的过滤和树构建逻辑。

### 第 5 屏

继续复用现有 `metrics-compare`。

## Public / Runtime 约束

第 4 屏如果新增 `screen/tree`，必须同步补：

- `ProjectCockpitResource` 受保护端点
- `PublicResource` 公共代理端点
- `apiDataSourceRuntime` 的 public URL 改写

避免出现“编辑/预览可以，发布态 401”的回归。

## 实施顺序

1. 删除原第 4 屏 `指标全览`
2. 新增第 4 屏 `项目树与重点项目`
3. 保持第 5 屏 `指标对账`
4. 增强第 1/2/3 屏缺失组件
5. 最后收口大屏→看板联动与轮播控制

## 验收标准

- 大屏最终为 5 屏，但不再包含 `指标全览`
- 第 4 屏能稳定展示 `项目树/重点项目` 相关数据
- 第 5 屏继续展示全量 34 项对账指标
- 第 1/2/3 屏补齐 sprint-9 中已列的核心缺项
- 预览态、发布态、public 分享态都可正常访问新增第 4 屏数据
