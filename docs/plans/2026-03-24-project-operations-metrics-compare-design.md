# 项目运营管理大屏指标对账屏设计

## 背景

当前“项目运营管理大屏”已经包含一屏 `指标全览`，用于展示系统侧计算出的 34 个项目管理指标。但客户现场仍然以 Excel 为主要核验载体，更关注“系统值是否与 Excel 计算值一致”，而不是只看系统值本身。

现场数据链路是：

1. 客户通过数据入湖任务上传 Excel。
2. Excel 中的公式列在导入预处理阶段先被求值。
3. 文件经 Addax 入湖后生成 ODS 明细表。
4. dbt 与项目看板逻辑继续基于这些明细构建数仓与专题结果。

因此，大屏需要新增一屏“指标对账”，用于展示“系统值 vs Excel 值”的差异，而不是继续用卡片堆叠的方式展示原始指标。

## 目标

- 保留现有第 4 屏 `指标全览`，继续展示系统原始指标。
- 新增第 5 屏 `指标对账`。
- 后端新增 `metrics-compare` 聚合接口，统一返回：
  - 系统值
  - Excel 值
  - 差值
  - 偏差率
  - 是否一致
- 先覆盖一批核心指标，保证演示稳定，再扩展到剩余指标。

## 非目标

- 第一版不做“全部 34 项均为强校验”的承诺。
- 第一版不做可配置容差治理界面。
- 第一版不改成 card/sql 驱动。

## 数据策略

### 系统值

系统值直接复用现有 `screenMetricsOverview()` 产出的指标口径。

### Excel 值

Excel 值不直接来自页面上传文件，也不直接来自现有 `biz_dwd_project_node_enriched` 再重复计算，而是由后端新增一套“Excel 口径聚合器”从 ODS 明细字段对应的业务语义进行统计。

这套 Excel 聚合器的第一版聚焦于以下特征：

- 基于原始状态字段、风险等级、节点类型、计划/实际日期等明细列聚合。
- 与现有系统指标口径在同一筛选条件下对齐。
- 百分比类指标按约定容差判断是否一致。

## 第一版指标范围

先覆盖一批核心指标：

- 项目本周期节点总数
- 正常待完成
- 已到时间节点总数
- 未完成总数
- 按时完成数
- 超期完成数
- 完成总数
- 节点完成百分比
- 按时完成百分比
- 超期完成百分比
- 不正常待变更
- 超期未完未变更
- 异常率
- 超期率
- 高风险未完成
- 里程碑完成率

原因：

- 客户最容易拿 Excel 直接核验。
- 能覆盖四个指标维度。
- 口径相对稳定，适合作为演示版。

其余指标先返回为“待补充/未对账”，避免在演示版里制造伪精确。

## 接口设计

新增：

- `GET /analytics/api/project-cockpit/screen/metrics-compare`

返回结构：

- `summary`
  - `metricTotal`
  - `matchedCount`
  - `mismatchCount`
  - `maxDiffMetric`
  - `maxDiffValue`
- `groups`
  - `dimension`
  - `items[]`
    - `metricKey`
    - `label`
    - `unit`
    - `systemValue`
    - `excelValue`
    - `diffValue`
    - `diffRate`
    - `matched`
    - `status`
    - `remark`
- `mismatchTop`
  - 按绝对差值倒序的异常指标列表

## 大屏布局

新增第 5 屏 `指标对账`：

- 顶部摘要区：4 个 number card
  - 指标总数
  - 一致数
  - 差异数
  - 最大偏差指标
- 中部左侧：4 个分组表格
  - 每个维度一张表
  - 列：指标、系统值、Excel 值、差值、偏差率、状态
- 中部右侧：异常指标榜
  - 只展示 `matched=false`
- 底部：筛选范围与对账说明

## Public / Preview 兼容

该新接口不仅要支持编辑与预览，还要支持 public 发布态，因此需要同步接入：

- `PublicResource` 的公开代理接口
- `apiDataSourceRuntime` 的 public URL 改写逻辑

## 风险

- 当前工作区存在未提交改动，实施时不得覆盖已有修改。
- `pm_ods_sources.yml` 在工作区仍可见，说明项目管理 source 统一治理仍未彻底收口；本次不扩大处理范围。
- 若 ODS 明细字段与 Excel 实际公式口径不完全一致，第一版需要通过 `remark/status` 标注“待人工确认”。
