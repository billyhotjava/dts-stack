# Excel ODS 字段粘贴映射设计

## 背景

当前 Excel 入湖流程已经支持两种列名处理方式：

- 用户逐列编辑字段名
- 用户通过“批量输入列名”按顺序回填列名
- 用户选择已有 ODS 表后，按 ODS 字段顺序自动覆盖 Excel 列名

但客户的真实现场流程是：大量离线 Excel 文件先做 ODS 设计，再做数仓三层设计，很多时候物理 ODS 表尚未先创建。因此“必须先选一个已有 ODS 表”不满足现场流程。

## 目标

在不改后端协议的前提下，为 Excel 入湖创建页新增“粘贴 ODS 字段列表自动映射 Excel 列”的能力。

## 方案选择

选择方案 1：

- 在文件入湖步骤中新增“粘贴 ODS 字段列表”入口
- 支持字段名列表输入，不处理类型和中文名
- 将粘贴字段按顺序覆盖当前 Excel 列名
- 复用已有 ODS 匹配语义展示：
  - 已匹配字段
  - Excel 多余字段
  - ODS 未匹配字段

不采用更重的“字段名+类型+中文名”或“DDL 导入”方案，以控制第一版复杂度。

## 交互设计

在 [FileBasicStep.tsx](/opt/prod/s10/s10-stack/source/dts-platform-webapp/src/pages/explore/etl/steps/FileBasicStep.tsx) 现有 ODS 匹配区域新增一个按钮：

- `粘贴 ODS 字段`

点击后弹出输入框，允许粘贴：

- 英文逗号分隔
- 中文逗号分隔
- 换行分隔
- Tab 分隔

确认后：

1. 解析出字段数组
2. 按顺序覆盖 `fileUploadResult.columns[i].name`
3. 前 N 列标记 `_odsMatched`
4. 剩余 Excel 列标记 `_odsExtra`
5. 剩余 ODS 字段显示为未匹配字段

## 数据与状态设计

第一版只做前端状态扩展：

- 文件列数据仍以 `fileUploadResult.columns` 为准
- 不引入新的后端 DTO
- 新增一个 helper，专门处理：
  - 粘贴文本解析
  - 字段顺序映射
  - 未匹配字段输出

页面提交时仍沿用现有 `_fileColumns` 提交逻辑，因此不需要改后端接口。

## 错误处理

- 粘贴内容解析后为空：提示“未识别到有效字段”
- 解析成功但字段数与 Excel 列数不一致：允许继续，按现有 ODS 匹配语义展示差异
- 不做字段合法性强校验，仍允许用户后续手工修正列名

## 验证

- helper 测试：
  - 支持 `,` / `，` / 换行 / Tab
  - 顺序映射正确
  - 多余 Excel 列与未匹配 ODS 字段计算正确
- 页面回归：
  - 粘贴后列名被覆盖
  - 标记和提示正确
  - 原有“选择 ODS 表自动匹配”能力不回归
