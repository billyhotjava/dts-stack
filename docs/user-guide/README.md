# DTS 用户操作手册

**适用版本**：v2.2.3<br>
**文档状态**：第 1 轮真实截图已纳入，持续迭代<br>
**最近核对**：2026-07-27

这套手册面向第一次接触 DTS 的业务人员、数据管理员和建模人员。手册不按菜单逐页介绍功能，而是围绕一个可验收任务展开：

> 建立一个数据建设计划，跟随“当前阶段”和“下一步”完成九阶段建设，并让系统形成可核验的完成证据。

## 从这里开始

1. 先阅读[第一次完成数据建设任务](getting-started.md)。
2. 操作过程中只跟随“数据建设工作台”显示的**当前阶段、首要阻塞和蓝色主按钮**。
3. 需要了解某一阶段的目标、入口和完成条件时，查阅[九阶段任务指南](stage-guide.md)。
4. 遇到“证据未知”“证据已过期”或按钮不可用时，不要自行把阶段当成完成，按手册的异常处理方式记录并反馈。

## 建设轨迹不是普通进度条

“建设轨迹”由后台 `StageProjection` 根据真实产物计算，页面本身是只读视图。打开页面、切换 Tab 或看到成功提示，都不等于阶段完成。

| 页面状态 | 含义 | 用户应该怎么做 |
|---|---|---|
| 已完成 | 已存在当前有效的完成证据 | 不需要重复操作，继续主按钮指向的阶段 |
| 有阻塞 | 已找到明确缺口 | 点击当前阶段的蓝色主按钮，补齐缺口 |
| 进行中 | 已产生部分证据，但还不完整 | 继续当前任务，直到重新计算为已完成 |
| 未开始 | 尚未产生该阶段产物，或当前开始方式允许稍后处理 | 先处理工作台给出的当前阶段 |
| 证据已过期 | 产物曾经有效，但引用版本或运行结果已经变化 | 重新核验、重新绑定或重新运行 |
| 证据未知 | 系统暂时无法读取当前证据 | 先刷新或重试；持续未知时记录计划、阶段和时间并联系管理员 |

只有“状态为已完成”且证据仍为当前版本时，才算真正完成。

## 九个编号不代表必须从左到右点击

九个编号表达完整产品生命周期，不是固定的页面点击顺序。

- **从业务目标开始**：适合尚未整理数据源、没有 SQL 经验的用户。系统会优先引导确认业务分类和数仓规划，再进入模型设计。
- **从现有数据开始**：适合已经知道数据库表、文件或 dbt 产物的用户。系统会先要求验证数据连接和来源盘点。
- 数据标准需要绑定到真实模型字段，因此可能先完成“05 事实与维度设计”，再回到“04 数据标准”。这是正常顺序。

无论选择哪种开始方式，都以工作台上的“当前阶段”和唯一主按钮为准，不要同时在多个模块里试错。

## 权限说明

创建建设计划需要“规划维护”权限。后续阶段还可能需要数据源、治理、建模、发布、指标或运维权限。

如果页面可以查看但没有“新建”“保存”“发布”等按钮，或者按钮显示只读/禁用，请先确认账号权限和计划生命周期。不要通过修改 URL 绕过权限。

## 版本边界

本手册以 v2.2.3 当前主线页面和九阶段证据模型为准。产品仍在迭代，页面文字或布局可能变化；如果主按钮、完成条件或路由发生变化，应先更新手册，再补拍对应截图。
