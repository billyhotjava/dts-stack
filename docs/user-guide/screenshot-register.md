# 操作手册截图登记与迭代清单

**用途**：供产品、测试和文档维护人员补拍操作截图。最终用户无需按本文件操作。

**基线**：DTS v2.2.3，Chrome 95 桌面基线 1366×768；关键旅程补 390×844 窄屏图。

## 截图准入规则

一张截图进入用户手册前必须同时满足：

1. 来自当前可部署构建和真实页面，不用静态 mock 替代成功结果；
2. 能说明一个明确动作或判断，不用整页大图堆数量；
3. 记录路由、版本/commit、账号角色、测试数据、拍摄时间和预期状态；
4. 隐去口令、Token、连接串、真实人员信息和不应公开的业务数据；
5. 截图中的计划、模型、指标和资产名称在同一条示例旅程中保持一致；
6. 关键按钮、输入值、成功结果或错误提示必须清晰可见；
7. 页面改版、按钮改名、完成条件变化时，对应截图立即标记为待重拍。

截图不应把分析结论写进产品页面。需要强调位置时，在文档正文中用编号说明，或另存带标注副本。

## 首版示例数据

建议所有主线截图统一使用一套可重建样例：

| 对象 | 建议值 |
|---|---|
| 建设计划 | 经营分析主题数仓 |
| 建设目标 | 统一查看各区域月度收入、成本和毛利 |
| 业务分类 | 经营分析 |
| 来源 | `sales_order`、`customer`、`region` |
| 维度模型 | 客户维度、区域维度 |
| 事实模型 | 订单收入明细 |
| 汇总模型 | 区域月度经营汇总 |
| 指标 | 营业收入、毛利额、毛利率 |

样例数据必须可重复初始化。不能依赖某个开发者浏览器里的 sessionStorage 或一次性数据库记录。

## 推荐迭代顺序

### 第 1 轮：让新人能开始

完成 UG-01～UG-05、UG-10～UG-13、UG-20～UG-22。目标是让新用户能创建计划并完成前三个阶段。

### 第 2 轮：形成模型和标准

完成 UG-30～UG-42。目标是让没有 SQL 经验的用户也能完成逻辑模型和字段标准绑定。

### 第 3 轮：证明交付闭环

在真实发布候选和权威模块证据链闭合后，完成 UG-50～UG-82。没有真实“已完成”证据前，不拍“成功完成”图。

### 第 4 轮：补异常与窄屏

完成 UG-06、UG-33、UG-54、UG-90～UG-93，并补充关键页面的 390×844 截图。
