# Concept Dimension and Dimension Table Separation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make “创建维度” create only a `DimensionDefinition` with a server-generated system code, while “创建维度表” remains the full `ModelSpec(DIMENSION)` editor.

**Architecture:** Keep one workbench shell but introduce a discriminated draft union so concept dimensions and logical models cannot share validation or persistence accidentally. The editor branches on `createKind`, the service exposes separate save functions, and the page handles each response without manufacturing a parallel catalog or lifecycle.

**Tech Stack:** React 18, TypeScript 5.6, Vitest/jsdom, Vite, existing `dimensionDefinitionApi` and `modelSpecApi`, Playwright, Chrome 95 production target.

## Global Constraints

- Work only in the existing data-modeling workbench, its focused tests, the Sprint-84 smoke, and this plan.
- Preserve unrelated dirty-worktree files and stage exact paths only.
- `createKind === "dimension"` owns `DimensionDefinition`; `createKind === "dimension-table"` owns `ModelSpec(DIMENSION)`.
- System code is generated by the server. The browser must never send `systemCode`.
- Creating a concept dimension shows only 数仓分层、业务分类、数据域、系统编码、中文名称、描述 and 保存.
- Creating a concept dimension does not render field management or `ModelSpec` lifecycle actions.
- Creating a dimension table still requires a CURRENT dimension reference, physical table data, fields, and a business key.
- Do not add backend fields, migrations, menus, routes, registries, or demo defaults.
- Chrome 95 is the browser floor.
- Run GitNexus impact before editing existing symbols and detect changes before committing.
- Follow strict RED → GREEN TDD; run the one focused browser E2E only after coding and unit/source-contract tests finish.

- [ ] **Step 3: Implement the discriminated drafts and independent save function**

Use these public shapes:

```ts
export type ConceptDimensionDraft = {
  createKind: "dimension";
  base: null;
  definitionBase: DimensionDefinitionView | null;
  domainId: string;
  name: string;
  description: string;
  reuseScope: DimensionDefinitionReuseScope;
};

export type ModelSpecDraft = {
  createKind: Exclude<ModelCreateKind, "dimension">;
  base: ModelSpecView | null;
  planId: string;
  domainId: string;
  name: string;
  description: string;
  physicalName: string;
  materialization: string;
  grainStatement: string;
  fields: ModelSpecField[];
  partitionFields: string;
  loadStrategy: ModelSpecLoadStrategy;
  scdType: ModelSpecScdType;
  reuseScope: DimensionDefinitionReuseScope;
  dimensionDefinitionId: string;
  standardBindings: ModelSpecStandardBinding[];
};

export type ModelDraft = ConceptDimensionDraft | ModelSpecDraft;
```

`emptyModelDraft("dimension", context)` returns the concept shape. `saveDimensionDefinitionDraft` validates only domain, Chinese name, and owner identity, calls `createDimensionDefinition`, and rejects attempts to resave `definitionBase` through this creation-only path. `saveModelDraft` and `buildUpdate` accept only `ModelSpecDraft`.
