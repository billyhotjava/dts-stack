# 离线文件目标表结构复用与字段编辑设计

日期：2026-08-04

## 1. 目标与边界

在现有“新建/编辑离线文件接入计划”的第二步“资源定义”内扩展字段编辑能力，不新增菜单、路由或页面。

用户上传并解析 CSV/XLSX 后可以：

1. 直接编辑目标字段名、字段类型和字段描述；
2. 从当前目标数据源搜索已有表，复用其字段结构作为模板；
3. 选择使用模板创建新表，或全量重建原表并沿用原表全名。

数据库接入、API 接入、文件密级声明、加密上传和密级封存链路不在本次改造范围内。

## 2. 产品交互

### 2.1 页面位置

只改造现有 `FileAccessStep` 的 `resource` 阶段：

- 目标数据源提前显示在资源定义阶段，默认使用平台默认数据湖；
- 文件任务在第三步只展示目标数据源摘要，不再重复编辑；
- 上传步骤和三步向导整体结构保持不变。

### 2.2 字段定义方式

字段定义支持两种方式：

- **手工定义**：默认使用文件解析字段，用户可编辑目标字段名、类型和描述；
- **引用已有表结构**：选择目标数据源后，通过关键字检索表，再读取选中表的字段结构。

表搜索框支持输入：

- 表名片段；
- 字段名片段。

搜索结果展示完整限定名 `schema.table`；命中字段时同时展示命中的字段名。搜索只读取 JDBC 元数据，不扫描表数据。前端 300ms 防抖、至少输入 2 个字符、最多返回 20 张表。

### 2.3 自动映射

选择结构模板后：

1. 先按源字段名与目标字段名精确匹配；
2. 再按忽略大小写、空格和下划线后的规范名匹配；
3. 未匹配字段保留待处理状态；
4. 用户可以显式执行“按顺序填充未匹配字段”，系统不得默认静默按位置覆盖。

字段编辑表格固定展示：源文件字段、目标字段名、目标类型、字段描述、匹配状态。目标字段名必须非空、合法且在当前文件内唯一。

### 2.4 落地方式

#### 新建目标表（默认）

- 已有表只作为结构模板；
- 用户必须输入新的目标表名；
- 字段名、类型和描述仍可继续编辑；
- 保存前检查新表名在目标数据源中不存在，避免误覆盖。

#### 全量重建原表

- 必须先选中已有表；
- 目标名锁定为选中表的完整限定名；
- 字段允许按当前文件重新定义，因此新结构可以与原结构不同；
- 用户必须勾选“确认删除并重建原表”；
- 执行时由服务端生成 `DROP TABLE` 和 `CREATE TABLE`，不接受用户提供的 DDL；
- 只允许 `DROP TABLE`，禁止 `CASCADE`。存在视图、外键等依赖时执行失败并保留依赖对象；
- 审计元数据必须包含任务、目标数据源、完整表名、操作者和 `destructive=true`。

该模式是明确的破坏性全量覆盖。DROP 后若后续文件写入失败，原数据不会自动恢复；页面必须在用户确认前展示这一后果。

## 3. 技术设计

### 3.1 复用的控制面

- 继续使用平台托管目标数据源和现有数据源权限校验；
- 复用 SQL 元数据服务，不新增第二套表扫描服务；
- 扩展现有表清单接口的可选搜索参数，使其支持按表名或字段名搜索；
- 扩展现有列元数据结果，返回顺序、可空、默认值、自增和描述，用于字段模板和提示；
- 元数据读取继续通过公共审计接口记录，不暴露 JDBC URL、用户名或密码。

### 3.2 前端状态与持久化

`AccessPlanFormValues` 增加文件落地状态：

- 字段定义方式；
- 结构模板的目标数据源、Schema 和表名；
- 落地方式 `create_new` / `recreate_existing`；
- 破坏性操作确认状态。

文件列按原始位置保存：

- 原始文件表头保留在 `label`/源字段属性；
- `name` 表示实际目标字段名；
- `type` 表示实际目标字段类型；
- `description` 表示目标字段描述；
- `_odsMatched` 标识模板映射结果，仅作界面恢复和证据展示。

任务源配置保存 `_fileLanding` 摘要，以便重新编辑时恢复模板来源和落地方式。该字段属于 DTS 文件元数据，生成 Addax Reader 参数前必须剥离。

### 3.3 执行语义

- `create_new` 沿用当前文件建表流程，但目标表已存在时拒绝执行；
- `recreate_existing` 仅允许文件来源任务，在服务端校验目标表与准入快照一致后生成无 `CASCADE` 的 DROP/CREATE；
- Addax Writer 的字段顺序严格使用文件列顺序，目标列名使用映射后的 `name`；
- PostgreSQL 新建表根据非空描述生成安全转义的列注释；
- 任何前端传入的 `preSql`/`postSql` 都不能获得 DROP 权限，破坏性 DDL 只能来自受控落地模式。

## 4. 错误处理

- 元数据搜索失败时保留手工定义入口，不清空用户已有编辑；
- 切换模板前如已有手工编辑，要求用户确认；
- 切换目标数据源后立即失效旧模板和搜索结果；
- 重新上传文件时按原始表头恢复仍然有效的映射，其余字段回到待处理；
- 重复目标字段、非法字段名、空映射和未确认的重建操作阻止进入下一步；
- DROP 因依赖失败时返回可识别错误，不使用 CASCADE 重试。

## 5. 安全与审计

- 文件明文处理、密级封存和字段密级规则保持现状；
- 表和列搜索只返回结构元数据，不返回样例数据；
- 目标数据源访问继续执行租户/部门读取权限；
- 破坏性重建复用公共审计通道，在现有任务执行审计中增加落地模式和目标表证据；
- 日志和响应不得包含目标数据源凭据。

## 6. 测试与验收

采用测试优先实现，最终至少覆盖：

1. 表名关键字和字段关键字都能返回完整 `schema.table`；
2. 搜索不读取业务数据，限制返回数量；
3. 可靠名称匹配、显式顺序匹配、重复字段和未匹配状态；
4. 手工编辑字段名、类型和描述后能保存并恢复；
5. 新建表模式拒绝已存在目标表；
6. 重建模式要求显式确认，生成 DROP 不包含 CASCADE；
7. 有依赖时重建失败且不会级联删除；
8. 文件密级封存和字段密级不因结构模板切换而丢失；
9. 原有数据库/API 接入向导回归不受影响；
10. 对应页面 source-contract、前端单测、后端聚焦测试和构建通过后，再进行一次文件接入浏览器验收。

## 7. 非目标

- 不提供任意 SQL 或自定义 DDL 编辑器；
- 不建立独立字段映射中心；
- 不扫描目标表业务数据；
- 不支持 DROP CASCADE；
- 不改变数据库/API 接入的字段发现和运行后质量检查策略。

## 8. 上传数据预览补充设计

在现有 `FileAccessStep` 的资源定义阶段、字段映射区下方展示上传接口已经返回的 `preview` 样本，不新增页面、路由或后台接口。

- 默认展示前 10 行；用户可以在 1～20 之间选择显示行数；
- 选择只影响浏览器内 `preview.slice(0, limit)` 的展示，不写入接入计划，也不改变实际导入行数；
- 表头使用当前编辑后的目标字段名称，单元格仍按上传文件原始列位置对应；
- 预览样本不足时只展示实际行数；无样本时显示明确空状态；
- 当前上传链路继续只申请 20 行样本，避免为界面展示扩大明文样本暴露范围或增加文件解析耗时；
- 表格须支持横向滚动，兼容 Chrome 95 和多列离线文件。
