# 维度建模页面原型对齐设计

## 1. 背景与目标

当前维度建模工作区已经接入真实的 `ModelSpec`、`DimensionDefinition` 和模型生命周期能力，但主编辑区仍展示上一版表单信息，与 `worklog/prototype/dm/dataworks-kimball/prototype-model-editor.png` 的页面结构不一致。前一版实现还把“创建维度”和“创建维度表”都按 `ModelSpec(DIMENSION)` 处理，导致概念维度错误进入维度表表单和保存链路。

本次改造以该原型为视觉和交互目标，收敛维度建模主页面的信息结构，同时继续使用现有权威接口和保存契约。页面不得写死原型示例值，也不得为了视觉对齐新增一套平行模型台账或发布控制面。

成功标准：

- 主编辑区字段、工具栏、字段表和信息层级与目标原型一致。
- 创建维度只编辑并保存 `DimensionDefinition`，不出现维度表字段、实现设置或模型生命周期操作。
- 创建维度表只编辑并保存引用既有现行维度的 `ModelSpec(DIMENSION)`。
- 新建概念维度能够独立保存并显示服务端系统编码；已有模型能够正常加载和保存，新建维度表能够完成必填校验与保存。
- 无权威来源的信息显示真实的未配置、禁用或只读状态，不使用演示数据。
- 页面加载、无权限、空目录、筛选无结果和保存失败均有明确状态。
- 聚焦测试、前端构建、Chrome 95 回归检查和页面截图比对通过。

## 2. 范围

### 2.1 本次包含

- 维度建模工作区的模型目录、顶部工具栏、基本信息区和字段管理区。
- 概念维度与逻辑维度表两套明确分离的草稿、表单、校验和保存结果。
- 原型字段到现有 `ModelSpec`、`DimensionDefinition`、用户身份和目录数据的映射。
- 保存前校验、未保存修改保护、只读模型和权限禁用状态。
- 对超长页面组件做服务于本次改造的最小拆分。
- 对应源码契约测试、组件测试和页面样式。

### 2.2 本次不包含

- 新增菜单、路由或建模入口。
- 新增后端字段、数据库迁移或新的模型台账。
- 扩展业务分类、命名规则、存储策略或负责人管理接口。
- 改造数仓规划、数据标准、数据指标、通用工具和关系图页面。
- 修改发布、dbt、质量门禁和物理预览的后端流程。
- 把维度表专属字段套用到明细表、汇总表或应用表；这些类型只复用本次统一的工具栏和字段表交互。
- 未经授权的生产写入或把构建结果标记为真实用户验收完成。

## 3. 方案选择

采用“对象边界纠偏 + 原型对齐 + 现有契约保真”方案：`createKind === "dimension"` 是 `DimensionDefinition`，`createKind === "dimension-table"` 才是 `ModelSpec(DIMENSION)`。页面不得再通过共同的 `modelType === "DIMENSION"` 判断二者表单或保存路径。能从现有权威数据取得的字段直接映射；没有权威字段的内容只读展示来源或未配置状态。

DataWorks 参考页中的“英文缩写”不直接落入 DTS。DTS 的稳定系统编码由服务端首次保存时生成，创建请求不得提交或伪造编码；创建页显示只读“系统编码”，新建时显示“保存后生成”，保存成功后显示服务端返回值。

不采用纯视觉换皮，因为它会让标签语义与实际保存字段不一致；不采用前后端全量扩展，因为这会把页面改造扩大为跨服务契约和迁移项目。

## 4. 页面结构

### 4.1 模型目录

保留贴源层、公共层、应用层标签，维度建模默认定位公共层。目录继续按数据域分组，并使用真实 `ModelSpec` 列表。

目录必须区分以下状态：

- 正在读取模型目录。
- 当前身份无访问权限。
- 当前分层和数据域下暂无模型。
- 搜索条件无匹配结果。
- 接口请求失败，可重试。

选择模型时更新 URL 中的 `modelSpecId`。若当前草稿已修改，切换模型、刷新页面或关闭编辑入口前必须先确认是否放弃修改。

### 4.2 编辑页签与工具栏

编辑页签显示当前对象中文名称；新建时按入口显示“创建维度”或“创建维度表”。

创建维度的顶部工具栏只有“保存”。它不显示提交、刷新、关联关系、发布、日志、质量规则、模型开发或导出，因为这些操作属于逻辑模型及其交付生命周期。

创建维度表及其他逻辑模型的工具栏顺序与原型一致：

1. 保存
2. 提交
3. 刷新
4. 关联关系
5. 发布
6. 日志
7. 质量规则
8. 模型开发
9. 导出

已有真实能力继续映射到现有对话框和接口。尚无真实能力的操作保持禁用，并通过 `title` 说明缺少的契约或前置条件，不创建假成功提示。概念维度不得把 `ModelSpec` 对话框误当成自己的版本或发布能力。

右侧版本管理和发布记录只为已保存的逻辑模型保留并继续读取 `ModelSpec` 生命周期事实。创建概念维度时隐藏这两个入口，避免把 `ModelSpec` 的版本与发布能力错误套到 `DimensionDefinition`。

### 4.3 创建维度基本信息

创建维度使用独立的概念维度表单，不复用维度表表单：

| 页面字段 | 来源与行为 |
|---|---|
| 数仓分层 | 固定显示“公共层 / 维度层”；只读 |
| 业务分类 | 显示所选数据域的权威上级分类；没有关系时显示“未配置”，只读 |
| 数据域 | `DimensionDefinition.domainId`；必选 |
| 系统编码 | 新建时显示“保存后生成”；保存后显示服务端 `systemCode`；始终只读 |
| 中文名称 | `DimensionDefinition.name`；必填 |
| 描述 | `DimensionDefinition.definition`；可编辑，空值保存时回退为中文名称 |

保存调用现有 `createDimensionDefinition`，请求只包含 `domainId/name/definition/ownerId/reuseScope/scopeType/attributes/hierarchies/idempotencyKey`。本页不提交 `systemCode`、物理表名、字段类型、模型粒度、SCD、存储策略或任何 `ModelSpec` 字段。

保存成功后保留当前概念维度表单，显示服务端返回的系统编码、状态和 revision，并清除脏状态。本次只覆盖新建与保存；维度定义的目录浏览、确认 CURRENT、编辑、退役不冒充 `ModelSpec` 能力，后续应使用 `DimensionDefinition` 专属版本流程补齐。

### 4.4 创建维度表基本信息

创建维度表采用原型的左右双列表单布局：

| 页面字段 | 来源与行为 |
|---|---|
| 数仓分层 | 根据 `ModelSpec.layer` 显示为“公共层 / 维度层”；只读 |
| 业务分类 | 显示所选数据域的权威上级分类；没有关系时显示“未配置”，只读 |
| 数据域 | `ModelDraft.domainId`；新建时可选，已有模型保持不可变约束 |
| 存储策略 | 由当前 `materialization` 映射为业务可读名称 |
| 维度 | `dimensionDefinitionId`；必须引用 CURRENT 维度定义 |
| 表名规则 | 使用现有物理表名校验结果显示“DIM 表命名规范”或具体错误；只读 |
| 表名 | `physicalName`；可编辑并即时校验 |
| 表中文名 | `name`；必填 |
| 生命周期 | 使用已有保留周期；没有权威值时显示“未配置” |
| 负责人 | 显示所选 `DimensionDefinition.ownerId`；只读 |
| 描述 | `description`；可编辑 |

原型中的示例值如“财务管理”“默认存储策略”“长期”和具体用户名不得作为页面默认数据。明细表、汇总表和应用表继续使用各自适用的模型字段，共享组件必须按 `createKind` 明确分支。

## 5. 字段管理

字段管理只属于维度表和其他逻辑模型；创建维度不得渲染字段管理。维度表默认字段表收敛为原型列：

1. 序号
2. 字段名称
3. 类型
4. 字段显示名
5. 主键
6. 非空
7. 维度属性编码
8. 操作

映射规则：

- “主键”勾选后将字段 `role` 设为 `KEY`；取消后设为 `ATTRIBUTE`。
- “非空”与 `nullable` 反向映射。
- 维度属性编码继续使用 `dimensionAttributeCode`。
- 字段标准等扩展属性进入“字段显示设置”，不在默认表格中占列。
- 密级不与业务标签或字段标准混合。本次没有字段密级权威契约，因此不在默认表格中伪造安全等级。

字段区保留并完善以下操作：

- 快捷模式：默认表格编辑。
- 代码模式：进入现有模型开发/dbt 能力；没有可写模型时禁用。
- 从表或视图导入：只有真实导入契约可用时启用。
- 字段关联：读取真实依赖或关联信息。
- 移除空白行：只删除字段名和显示名均为空的草稿行。
- 插入指定行数：校验为正整数并设置合理上限。
- 字段显示设置：控制扩展列或查看字段标准信息。

字段表在窄屏下允许横向滚动，操作列保持可见；所有图标按钮具备文本提示和可访问名称。

## 6. 组件边界

当前 `ModelingWorkbenchPage.tsx` 已超过 800 行。本次改造不继续扩大该文件，按职责拆分为：

- `ModelingWorkbenchPage.tsx`：请求编排、路由参数、选择模型、保存和对话框状态。
- `ModelingWorkbenchEditor.tsx`：按明确的 `createKind` 分发概念维度、维度表和兼容模型表单，并控制各自工具栏。
- `ConceptDimensionForm`：只承载 `DimensionDefinition` 基本信息和只读系统编码，不接收模型字段属性。
- `ModelFieldEditorTable.tsx`：字段增删、主键/非空映射、扩展列和表格交互。
- `modelWorkbenchPresentation.ts`：分层、存储策略、生命周期和负责人等纯展示映射。

服务层 `modelWorkbenchService.ts` 继续负责契约转换、确定性默认值、保存命令和保存前校验。它必须提供互斥的 `saveDimensionDefinitionDraft` 与 `saveModelDraft` 路径；不得再由共同的 `modelType` 把概念维度送入组合创建接口。不得在展示组件中拼装 API 请求或复制保存逻辑。

## 7. 数据流与状态

1. 页面加载 `ModelWorkbenchContext`，取得数据域、逻辑模型和字段标准。
2. “创建维度”生成 `ConceptDimensionDraft`；“创建维度表”等入口生成 `ModelDraft`，两者使用可判别联合类型。
3. 维度表草稿根据数据域加载 CURRENT `DimensionDefinition` 候选；概念维度不加载维度表候选。
4. 展示层按 `createKind` 映射原型字段和工具栏，禁止用共同 `modelType` 分支。
5. 用户修改草稿后设置脏状态；切换、刷新或离开前触发确认。
6. 概念维度保存调用 `createDimensionDefinition`；维度表保存继续调用现有 `createDimensionModel` 的 EXISTING 绑定路径；其他模型继续调用 `saveModelDraft`。
7. 保存成功后按返回对象类型重建对应草稿。概念维度显示 `systemCode/status/revision`，逻辑模型更新 `modelSpecId` 并刷新模型目录。

请求使用现有请求纪元或取消机制防止旧响应覆盖新选择。失败时保留当前草稿，不把空响应误判为保存成功。

## 8. 校验与错误处理

创建维度保存前只校验：

- 数据域和中文名称必填。
- 当前身份存在可用的人员 ID。
- 系统编码字段不可编辑，也不得进入创建请求。

创建维度表保存前至少校验：

- 数据域、CURRENT 维度引用、表名和表中文名必填。
- 物理表名满足现有标识符规则。
- 至少存在一个完整字段。
- 至少一个业务主键字段。
- 字段名称和类型完整，字段名称不重复。
- 维度属性编码在非空时满足编码规则。
- 当前身份具备维护权限且模型不是历史只读模型。

错误优先显示在对应字段附近，并保留顶部错误摘要便于快速定位。权限错误不提供无效重试；网络或服务错误允许重试。保存按钮在请求期间禁用，避免重复提交。

## 10. 发布与回退

本次复用现有 `DimensionDefinition` 和 `ModelSpec` API，不含数据迁移和后端契约变化。发布仅需重建 `dts-platform-webapp`。回退可通过恢复本次前端文件并重新构建镜像完成；现有模型和维度定义数据不需要回滚。

工作区当前存在其他未提交的建模改动。实现和提交时只暂存本次明确拥有的文件，不覆盖、不回退、不捎带已有改动。
