# 维度建模页面原型对齐设计

## 1. 背景与目标

当前维度建模工作区已经接入真实的 `ModelSpec`、`DimensionDefinition` 和模型生命周期能力，但主编辑区仍展示上一版表单信息，与 `worklog/prototype/dm/dataworks-kimball/prototype-model-editor.png` 的页面结构不一致。

本次改造以该原型为视觉和交互目标，收敛维度建模主页面的信息结构，同时继续使用现有权威接口和保存契约。页面不得写死原型示例值，也不得为了视觉对齐新增一套平行模型台账或发布控制面。

成功标准：

- 主编辑区字段、工具栏、字段表和信息层级与目标原型一致。
- 编辑维度或维度表时，旧版主表单字段不再出现在基本信息区。
- 已有模型能够正常加载和保存，新建维度表能够完成必填校验与保存。
- 无权威来源的信息显示真实的未配置、禁用或只读状态，不使用演示数据。
- 页面加载、无权限、空目录、筛选无结果和保存失败均有明确状态。
- 聚焦测试、前端构建、Chrome 95 回归检查和页面截图比对通过。

## 2. 范围

### 2.1 本次包含

- 维度建模工作区的模型目录、顶部工具栏、基本信息区和字段管理区。
- 维度和维度表草稿的原型化基本信息表单。
- 原型字段到现有 `ModelSpec`、`DimensionDefinition`、用户身份和目录数据的映射。
- 保存前校验、未保存修改保护、只读模型和权限禁用状态。
- 对超长页面组件做服务于本次改造的最小拆分。
- 对应源码契约测试、组件测试和页面样式。

### 2.2 本次不包含

- 新增菜单、路由或建模入口。
- 新增后端字段、数据库迁移或新的模型台账。
- 扩展业务分类、命名规则、存储策略或负责人管理接口。
- 改造数仓规划、数据标准、数据指标、通用工具和关系图页面。
- 修改发布、dbt、质量门禁和物理预览的后端流程。
- 把维度表专属字段套用到明细表、汇总表或应用表；这些类型只复用本次统一的工具栏和字段表交互。
- 未经授权的生产写入或把构建结果标记为真实用户验收完成。

## 3. 方案选择

采用“原型对齐 + 现有契约保真”方案：页面结构按原型重排，能从现有权威数据取得的字段直接映射；没有模型级权威字段的内容只读展示来源或未配置状态。保存所需但不再放在基本信息区的实现属性由现有模型值、维度定义和确定性默认值维护。

不采用纯视觉换皮，因为它会让标签语义与实际保存字段不一致；不采用前后端全量扩展，因为这会把页面改造扩大为跨服务契约和迁移项目。

## 4. 页面结构

### 4.1 模型目录

保留贴源层、公共层、应用层标签，维度建模默认定位公共层。目录继续按数据域分组，并使用真实 `ModelSpec` 列表。

目录必须区分以下状态：

- 正在读取模型目录。
- 当前身份无访问权限。
- 当前分层和数据域下暂无模型。
- 搜索条件无匹配结果。
- 接口请求失败，可重试。

选择模型时更新 URL 中的 `modelSpecId`。若当前草稿已修改，切换模型、刷新页面或关闭编辑入口前必须先确认是否放弃修改。

### 4.2 编辑页签与工具栏

编辑页签显示当前模型中文名称；新建时显示“创建维度表”。工具栏顺序与原型一致：

1. 保存
2. 提交
3. 刷新
4. 关联关系
5. 发布
6. 日志
7. 质量规则
8. 模型开发
9. 导出

已有真实能力继续映射到现有对话框和接口。尚无真实能力的操作保持禁用，并通过 `title` 说明缺少的契约或前置条件，不创建假成功提示。

右侧保留版本管理和发布记录入口，它们继续读取模型生命周期事实。

### 4.3 基本信息

编辑维度或维度表草稿时，基本信息采用原型的左右双列表单布局，字段映射如下：

| 原型字段 | 来源与行为 |
|---|---|
| 数仓分层 | 根据模型类型与 `layer` 显示为“公共层 / 维度层”；只读 |
| 业务分类 | 优先显示所选数据域的权威上级分类；当前接口没有该关系时显示“未配置”，只读 |
| 数据域 | `ModelDraft.domainId`；新建时可选，已有模型保持现有不可变约束 |
| 存储策略 | 由当前 `materialization` 映射为业务可读名称；允许选择已有受支持值 |
| 维度 | `dimensionDefinitionId`；创建维度表时必选 |
| 表名规则 | 使用现有物理表名校验结果显示“DIM 表命名规范”或具体错误；只读 |
| 表名 | `physicalName`；可编辑并即时校验 |
| 表中文名 | `name`；必填 |
| 生命周期 | 使用已有保留周期或模型状态生成只读展示；没有权威值时显示“未配置” |
| 负责人 | 优先显示所选 `DimensionDefinition.ownerId`；新建维度时显示当前身份；只读 |
| 描述 | `description`；可编辑 |

原型中的示例值如“财务管理”“默认存储策略”“长期”和具体用户名不得作为页面默认数据。

以下上一版字段不再出现在基本信息区：模型类型、目标分层、业务定义、模型粒度、物化方式、加载策略、分区字段、SCD 策略、复用范围。

明细表、汇总表和应用表继续使用各自适用的模型字段，本次不把“维度”和维度负责人等字段套用到这些模型。共享组件必须按 `createKind` 明确分支，避免视觉调整改变非维度模型的保存语义。

处理规则：

- `模型类型` 和 `目标分层` 由当前创建类型确定。
- `业务定义` 统一收敛为“描述”。
- `模型粒度` 对已有模型保留原值；新建模型根据所选维度和业务主键生成“一个{维度名称}一行”，保存前仍执行完整校验。
- `物化方式` 以“存储策略”的业务语言呈现，不丢失实际值。
- `加载策略`、`分区字段`、`SCD 策略`、`复用范围` 对已有模型保持原值；新建维度表使用当前维度模型默认值。本次不在基本信息区提供编辑入口。

## 5. 字段管理

默认字段表收敛为原型列：

1. 序号
2. 字段名称
3. 类型
4. 字段显示名
5. 主键
6. 非空
7. 维度属性编码
8. 操作

映射规则：

- “主键”勾选后将字段 `role` 设为 `KEY`；取消后设为 `ATTRIBUTE`。
- “非空”与 `nullable` 反向映射。
- 维度属性编码继续使用 `dimensionAttributeCode`。
- 字段标准等扩展属性进入“字段显示设置”，不在默认表格中占列。
- 密级不与业务标签或字段标准混合。本次没有字段密级权威契约，因此不在默认表格中伪造安全等级。

字段区保留并完善以下操作：

- 快捷模式：默认表格编辑。
- 代码模式：进入现有模型开发/dbt 能力；没有可写模型时禁用。
- 从表或视图导入：只有真实导入契约可用时启用。
- 字段关联：读取真实依赖或关联信息。
- 移除空白行：只删除字段名和显示名均为空的草稿行。
- 插入指定行数：校验为正整数并设置合理上限。
- 字段显示设置：控制扩展列或查看字段标准信息。

字段表在窄屏下允许横向滚动，操作列保持可见；所有图标按钮具备文本提示和可访问名称。

## 6. 组件边界

当前 `ModelingWorkbenchPage.tsx` 已超过 800 行。本次改造不继续扩大该文件，按职责拆分为：

- `ModelingWorkbenchPage.tsx`：请求编排、路由参数、选择模型、保存和对话框状态。
- `ModelingWorkbenchEditor.tsx`：页签、工具栏、基本信息和未保存状态展示。
- `ModelFieldEditorTable.tsx`：字段增删、主键/非空映射、扩展列和表格交互。
- `modelWorkbenchPresentation.ts`：分层、存储策略、生命周期和负责人等纯展示映射。

服务层 `modelWorkbenchService.ts` 继续负责契约转换、确定性默认值、保存命令和保存前校验。不得在展示组件中拼装新的 API 请求或复制保存逻辑。

## 7. 数据流与状态

1. 页面加载 `ModelWorkbenchContext`，取得数据域、模型和字段标准。
2. 根据 URL 或目录选择模型，转换为 `ModelDraft`。
3. 维度表草稿根据数据域加载当前有效的 `DimensionDefinition`。
4. 展示映射层把契约字段转换为原型所需的业务文案。
5. 用户修改草稿后设置脏状态；切换、刷新或离开前触发确认。
6. 保存时补齐确定性派生值，执行字段级校验，再交由现有 `saveModelDraft` 写入。
7. 保存成功后用服务端响应重建草稿、清除脏状态并刷新目录。

请求使用现有请求纪元或取消机制防止旧响应覆盖新选择。失败时保留当前草稿，不把空响应误判为保存成功。

## 8. 校验与错误处理

保存前至少校验：

- 数据域、维度、表名和表中文名必填。
- 物理表名满足现有标识符规则。
- 至少存在一个完整字段。
- 至少一个业务主键字段。
- 字段名称和类型完整，字段名称不重复。
- 维度属性编码在非空时满足编码规则。
- 当前身份具备维护权限且模型不是历史只读模型。

错误优先显示在对应字段附近，并保留顶部错误摘要便于快速定位。权限错误不提供无效重试；网络或服务错误允许重试。保存按钮在请求期间禁用，避免重复提交。
