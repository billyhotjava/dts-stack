# 平台工作台（我的概览）· 领导视角重构设计

## 概述

把 `dts-platform-webapp` 的工作台首页（`src/pages/workbench/index.tsx`）从现在偏"数据治理 / 资产沉淀"的通用视角，重构为**领导视角的概览页**：只保留**报表**和**数据资产**两块内容，按登录人角色自适应默认范围。

## 问题

现状（`workbench/index.tsx`）与领导关心的事几乎不重合：

- KPI 卡片是"我创建的资产 / 今日新增资产 / 待办事项 / 质量检查"——对领导无感。
- 主视区是"资产增长趋势"折线图——领导并不关心资产数条走势。
- 有"待办"块但不区分"我审批的 / 我申请的"——当前审批流程未定，混在一起反而误导。
- 有"我的收藏"块，但菜单早已移除；代码还在，属于孤岛。
- 没有**业务域**和**部门**两个筛选维度，领导无法按口径切片。

同时，相关后端基础设施已经具备：`CatalogDomain` 主题域、`bizDomain` 表级字段、`reportsService.getPublishedReports({ deptCode, … })`、角色常量 `ROLE_INST_LEADER` 等。所以这次重构是**拉齐产品形态**，不是重建能力。

## 目标 / 非目标

### 目标

1. 登录工作台后，领导一屏能看清**所内/本部门当前报表与资产的态势**。
2. 业务域与部门两个维度可切换，切换时整屏联动刷新。
3. 按角色区分默认范围：普通员工、部门领导、所领导三层。
4. 砍掉冗余、失联和未对齐功能（收藏 / 审批 / 我的申请 / 质量 KPI 等）。

### 非目标

- **不重新定义审批工作流**。当前审批能力未定（中层既可审批又可申请），本次不做任何审批块。
- **不新建业务域字典**。沿用"数据治理中心 - 主题域管理"的 `CatalogDomain`，且为**软依赖**——API 失败或返回空时，业务域筛选器优雅降级，不阻塞整页。
- **不改造报表中心 / 资产目录子页面**。工作台只聚合"TOP N"形态，"查看全部"链接跳到既有子页。
- **不做二次搜索引擎**。工作台上不提供全文搜索框；关键字搜索在子页承载。

## 目标用户 / 角色模型

| 角色 | 识别依据 | 默认范围 | 部门过滤 | 业务域过滤 |
|---|---|---|---|---|
| 普通员工 | 非领导角色 | 本人订阅 / 常用 | 锁定本部门 | 可切换 |
| 部门领导 | 部门领导 / 副所领导 / 财务主管 等 | 本部门 | 锁定本部门 | 可切换 |
| 所级领导 | `ROLE_INST_LEADER` / `INST_LEADER` | 全所 | 可切具体部门 / 全所 | 可切换 |

**角色识别**：读 `userStore` 里的 roleCodes。识别优先级从高到低：`所领导 > 部门领导 > 员工`。降级：若无法识别角色，按"员工"处理（最小权限）。

**范围持久化**：所领导切到具体部门后**不持久化**；下次进入仍默认"全所"。避免领导上次切到某部门后忘记切回，误判全所态势。

## 整体布局

单页 Dashboard（纵向滚动）。自上而下：

1. **顶部过滤条**（sticky）：部门 / 业务域 / 时间 三个下拉。部门在最前，业务域次之（用户熟组织不熟业务域）。
2. **KPI 行**：员工 3 个、部门领导 3 个、所领导 4 个。
3. **业务域矩阵（仅所领导）**：色块按业务域汇总当前时间段的访问热度，点击切到该域。
4. **主内容两栏**：左 2 / 右 1。左侧报表块，右侧资产块。
5. **数据大屏快捷条**（保留）：当用户至少有一个已发布大屏可见时，显示在 KPI 行上方的一条 horizontal strip（最多 6 个 chip，超出 `更多 →`）；无可见大屏时整条隐藏。大屏与报表语义不同，保留快捷入口符合既有使用习惯。

```
┌──────────────────────────────────────────────────┐
│ 工作台 · 2026-04 · 所领导              ⟳ 刷新      │
├──────────────────────────────────────────────────┤
│ [部门: 全所 ▾] [业务域: 全部 ▾] [时间: 本月 ▾]     │
├──────────────────────────────────────────────────┤
│ 🖥 [大屏 A] [大屏 B] [大屏 C]            更多 →   │  有大屏时才出现
├──────────────────────────────────────────────────┤
│ [报表 248] [访问 14.3k] [资产 1284] [S1 资产 84]  │
├──────────────────────────────────────────────────┤
│ 业务域矩阵: 项目 财务 科研 生产 质量 其他           │  仅所领导
├────────────────────────────┬─────────────────────┤
│ 📊 TOP 报表                │ 📦 核心资产 · 按密级 │
│ (按访问量降序, 5-10 条)     │ (按密级降序, 5-10)   │
│ 行: 名称 / 访问 / 业务域 tag│ 行: 名称 / S1-S4 tag │
└────────────────────────────┴─────────────────────┘
```

## 筛选器

### 部门过滤（首选）

| 角色 | 初始值 | 可选项 | 可切换 |
|---|---|---|---|
| 员工 | 本部门 | — | 否 |
| 部门领导 | 本部门 | — | 否 |
| 所领导 | `ALL`（全所） | `ALL` + 部门树 | 是 |

部门树数据来自 `deptService` 现有接口。所领导场景下下拉支持层级展开。

### 业务域过滤（次选 · 软依赖）

- 数据源：`GET /catalog/domains`（`CatalogDomain` 树）。
- 值：`ALL`（默认） + 域 `code` 列表。
- **降级策略**：
  - API 失败 → 筛选器隐藏（而非显示"加载失败"），整页仍可按部门+时间工作。
  - API 返回空 → 筛选器隐藏。
  - 失败不提示红色 toast，只记录埋点。
- 色块矩阵（仅所领导）：每个域显示一个色块，数字是该域当前过滤条件下的报表访问总量；点击 = 设当前 `bizDomain = code` 并刷新整页。
- 矩阵最多展示前 6 个域（按访问量降序），剩余聚合为"其他"。

### 时间过滤

- 预设：本月（默认）/ 本季度 / 本年。
- 无自定义日期。
- 时间语义：KPI 里和访问/新增相关的数字、TOP 报表排序、业务域矩阵数字都跟随时间切换。"资产总数 / 核心资产"这类静态口径不受时间影响。
- 文案约定：避免写死"本月"，统一写"本期"（或直接用当前选中值如"本月 / 本季 / 本年"动态替换）。

## 三角色 KPI / 主内容

### 普通员工

**KPI（3 项）**

| 名称 | 口径 | 数据源 |
|---|---|---|
| 我常用的报表 | 当前用户近 30 天访问过的报表个数（第一期用"访问"代替"订阅"） | `reports/visit` 聚合 |
| 本期访问 | 当前用户在选定时间段内的报表访问次数 | `reports/visit` 聚合 |
| 我常用的资产 | 当前用户近 30 天访问过的资产个数 | catalog 访问日志 |

**报表块：我常用的报表**
- 排序：最近访问时间降序。
- 每行：报表名 / 最近访问相对时间 / 业务域 tag。
- 空态文案："还没有访问过任何报表，去 [报表中心] 看看"。

**资产块：我常用的资产**
- 排序：个人访问量降序。
- 每行：资产名 / 访问次数。

### 部门领导

**KPI（3 项）**

| 名称 | 口径 |
|---|---|
| 本部门报表 | 本部门已发布报表总数（副标题显示"本期新发布 N"，N 受时间过滤影响） |
| 本期访问 | 本部门报表在选定时间段内的总访问量（带上期环比） |
| 部门核心资产 | 本部门归属资产中密级为 S1 + S2 的总数（静态口径） |

**报表块：本部门 TOP 报表**
- 排序：访问量降序，取前 10。
- `reportsService.getPublishedReports({ deptCode, bizDomain? })`。

**资产块：本部门资产 · 按密级**
- 排序：密级降序（S1 > S2 > S3 > S4），同级按更新时间。
- 取前 10。

### 所级领导

**KPI（4 项）**

| 名称 | 口径 |
|---|---|
| 所内报表 | 全所已发布报表总数（副标题显示"本期新发布 N"） |
| 本期访问 | 全所报表访问量（带上期环比） |
| 数据资产 | 全所资产总数（副标题显示"本期新增 N"） |
| 核心资产（S1） | 全所 S1 资产数（带占比，静态口径） |

**业务域矩阵**
- 所领导专属。色块布局 1 行 6 列。
- 每格显示：域名称 / 当前时间段访问总量。
- 颜色按访问量深浅渐变（同色系）。
- 点击 = 设业务域为该域。

**报表块：全所 TOP 报表**
- 逻辑同部门领导，但 `deptCode = undefined`（全所）。

**资产块：核心资产 · 按密级**
- 逻辑同部门领导，但全所范围。

## 数据接口（前后端对齐）

| 能力 | 现有 | 需要新增 |
|---|---|---|
| 领导视角聚合 KPI | — | `GET /workbench/leader-overview?scope=MINE\|DEPT\|ALL&deptCode=&bizDomain=&timeRange=` → 聚合返回 KPI、TOP 报表、TOP 资产、业务域矩阵 |
| 主题域（业务域）列表 | `GET /catalog/domains` | 无 |
| 部门树 | `deptService` 既有接口 | 无 |
| 已发布报表 | `reportsService.getPublishedReports({ keyword, deptCode, type, queryDatasetId })` | 增加 `bizDomain` 过滤参数 |
| 报表访问统计 | `reports/visit` 写入 | 新增按期聚合查询（内嵌在 leader-overview 里） |
| 资产列表（按密级） | catalog 既有接口 | 确认支持 `orderBy=classification` 和 `deptCode` 过滤 |

**"订阅"概念**：系统当前无显式订阅关系，本设计第一期**统一用"近 30 天访问过"代替**（已反映在员工 KPI 和报表块口径里）。未来若落地订阅，再平替到同一 KPI。

### 软依赖失败路径

- `GET /catalog/domains` 失败 → 业务域下拉 + 业务域矩阵同时隐藏；整页仍以"部门 × 时间"工作。
- `deptService` 失败（所领导场景）→ 部门下拉退化为只有"全所"+"本部门"两项；不阻塞页面。
- `GET /workbench/leader-overview` 失败 → 展示空态骨架 + 刷新按钮；不做自动重试轮询。

## 空态 / 错误态 / 加载态

| 状态 | 策略 |
|---|---|
| 首次加载 | 骨架屏（KPI 4 个灰块 + 两个列表骨架）。 |
| 业务域 API 失败 | 业务域筛选器 + 色块矩阵静默隐藏。 |
| 部门 API 失败（所领导） | 下拉退化为"全所 / 本部门"。 |

| 员工无访问历史 | "还没有访问过任何报表，去 [报表中心] 看看"。 |

## 审计 / 埋点

复用现有 `auditService`：

- 筛选器切换：`WORKBENCH_FILTER_CHANGE`，payload `{ dim, value, role }`。
- 业务域色块点击：`WORKBENCH_DOMAIN_DRILL`，payload `{ domain, role }`。
- TOP 报表点击：沿用 `reports/visit`。
- 页面进入：`WORKBENCH_OVERVIEW_VIEW`，payload `{ role, deptCode }`。

## 权限

- 页面进入不需要额外权限（工作台为登录后默认页）。
- 后端聚合端点按角色校验 `scope` 参数：
  - 非所领导 传 `scope=ALL` 时强制降级为 `scope=DEPT` + 自身 `deptCode`。
  - 非领导 传 `scope=DEPT` 时强制降级为 `scope=MINE`。
- 业务域 / 部门下拉只返回当前用户可见范围。

## 测试要点

- 三角色分别登录：筛选器锁定、KPI 口径、报表/资产范围是否正确。

- 业务域 API 失败：业务域筛选器与色块消失，部门 + 时间仍可工作。
- 部门 API 失败（所领导）：退化为"全所 / 本部门"。
- 聚合接口失败：骨架 → 错误态 → 重试。
- 收藏删除后，老的 `/workbench/favorites` 路径应返回 404，前端不再引用。
- E2E（Playwright）覆盖：所领导整路流（切域 / 切部门 / 打开 TOP 报表）。
