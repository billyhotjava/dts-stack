## 1. 能力声明

治理维护人员可以在当前主题域内手工登记一致性维度，或显式安装一个行业模板。手工登记的数据立即成为该业务域的有效事实；模板安装的数据先进入待确认区，只有经过逐项或批量确认后，才能进入总线矩阵、维度推荐和后续建模。

这个闭环保证行业模板只是辅助输入，不会因为安装、模型同名或页面初始化而自动成为客户的业务事实。

## 3. 方案选择

### 采用：现有主题域页内的工作台式闭环

- 在业务过程区旁增加“一致性维度”工作区。
- 在页面工作区提供“选择行业模板”次要动作，使用抽屉预览和安装。
- 在业务过程、维度列表内直接显示待确认状态，并提供单项和批量确认。
- 总线矩阵仍留在当前页面，只展示已确认过程和已确认维度。

### 不采用：独立模板中心

独立页面会增加菜单和上下文切换，用户安装模板后仍需返回主题域完成确认，不利于形成短闭环。

### 不采用：首次使用向导

向导适合首次教学，但不适合日常维护。本阶段先让熟手可以在一个页面直接工作，首次引导以后通过可折叠说明补充。

## 4. 状态与不变量

### 4.1 来源与确认状态

继续使用第一阶段已经落库的字段：

- `sourceType=MANUAL`：手工创建，`confirmed=true`。
- `sourceType=TEMPLATE`：模板安装，初始 `confirmed=false`。
- `sourceId/sourceVersion`：记录模板及版本。

不新增新的状态枚举。用户“不采用候选”的动作就是删除尚未确认的候选，避免引入无消费方的 `REJECTED` 状态。

### 4.2 状态转换

```text
手工创建 -> 已确认 -> 可进入矩阵/推荐

显式安装模板 -> 待确认候选 -> 单项或批量确认 -> 可进入矩阵/推荐
                         \-> 删除候选 -> 不再出现
```

### 4.3 强制不变量

- 空白主题域仍然返回空业务过程和空一致性维度。
- 模板安装不等于业务确认。
- 未确认的业务过程或维度不能新增总线矩阵关系。
- 总线矩阵和建模推荐只消费 `confirmed=true` 的对象。
- 手工对象不能被模板重复安装覆盖。
- 已被总线矩阵引用的维度不能直接删除；后端返回冲突，UI 给出解除引用提示。
- 既有数据库记录沿用迁移默认值 `confirmed=true`，不改变历史客户行为。

## 5. 后端接口

### 5.1 手工一致性维度

```http
POST /api/governance/sprint64/domains/{domainId}/conformed-dimensions
Content-Type: application/json

{
  "dimensionId": "organization",
  "name": "组织机构",
  "sourceModel": "dim_organization"
}
```

返回 `ConformedDimensionDto`，来源固定为 `MANUAL`，确认状态固定为 `true`。

```http
DELETE /api/governance/sprint64/domains/{domainId}/conformed-dimensions/{dimensionId}
```

- 无矩阵引用时返回成功。
- 存在矩阵引用时返回 HTTP 409，不自动删除引用关系。

### 5.2 单项与批量确认

前端的单项确认也调用同一个批量接口，减少重复契约：

```http
POST /api/governance/sprint64/domains/{domainId}/modeling-candidates/confirm
Content-Type: application/json

{
  "processIds": ["issue-closure"],
  "dimensionIds": ["organization", "completion-status"]
}
```

返回：

```json
{
  "confirmedProcesses": 1,
  "confirmedDimensions": 2
}
```

规则：

- 请求内所有 ID 必须属于当前业务域，否则整个请求失败，不做部分更新。
- 已确认对象重复提交是幂等操作，计数不增加。
- 允许一次只提交过程或只提交维度。

### 5.3 既有查询契约

前端类型补齐以下字段，不再丢弃后端来源信息：

```ts
type ModelingFactProvenance = {
  sourceType: "MANUAL" | "TEMPLATE" | "IMPORTED" | "SCANNED" | string;
  sourceId?: string;
  sourceVersion?: string;
  confirmed: boolean;
};
```

`Sprint64BusinessProcess` 和 `Sprint64ConformedDimension` 均继承该字段集合。

### 5.4 总线矩阵门禁

`saveBusMatrix` 在写入前同时校验：

- 业务过程存在且 `confirmed=true`。
- 一致性维度存在且 `confirmed=true`。

失败时返回明确业务错误，不写入矩阵。

### 5.5 权限与审计

- 新增、删除、确认、安装继续使用 `GOVERNANCE_MAINTAINERS` 或 `CATALOG_MAINTAINERS`。
- 查询保持当前读取权限。
- 新增审计动作：`SPRINT64_DIMENSION_CREATE`、`SPRINT64_DIMENSION_DELETE`、`SPRINT64_MODELING_CANDIDATES_CONFIRM`。
- 模板安装继续使用 `MODELING_TEMPLATE_INSTALL`，审计结果包含新增过程数和维度数。

## 6. 页面设计

### 6.1 页面结构

不增加页面顶部说明卡。选中主题域后的核心工作区保持三块：

1. 业务过程
2. 一致性维度
3. 总线矩阵

“选择行业模板”放在业务过程和一致性维度工作区的次要动作区，打开右侧抽屉，不形成第四块常驻说明卡。

### 6.2 业务过程与维度列表

每条记录显示：

- 名称与编码
- 来源标签：手工创建，或模板名称与版本
- 状态标签：待确认、已确认
- 可用动作：确认、删除、发起规划或引用

待确认记录集中显示在列表前部。存在候选时显示一个紧凑批量操作条：`待确认 N 项 | 全部确认`，不新增大面积引导卡。

### 6.3 一致性维度空状态

空状态提供两个动作：

- 主动作：“新增一致性维度”
- 次动作：“选择行业模板”

新增表单字段只包括名称、编码和可选来源模型。行业、对象性质、SCD 类型不在本阶段引入。

### 6.4 模板抽屉

模板抽屉展示：

- 模板名称、行业、版本和描述
- 将新增的业务过程数和一致性维度数
- 明确提示“安装后仍需确认，未确认内容不会进入建模”
- 安装结果：新增数量或“已经安装”

安装成功后刷新当前业务域数据并定位到待确认区，不自动确认、不自动修改矩阵。

### 6.5 总线矩阵

- 行只展示已确认业务过程。
- 列只展示已确认一致性维度。
- 存在候选时在矩阵标题旁显示轻量提示“另有 N 项待确认”。
- 没有已确认数据时，空状态引导回列表确认，不展示不可操作的空表格。

## 7. 失败与恢复

- 表单提交失败时保持抽屉或弹窗打开并保留输入。
- 模板列表失败时抽屉展示可重试错误，不影响手工登记。
- 模板安装失败时不刷新为成功状态。
- 确认操作失败时保留选中项，用户可重试。
- 后端是来源真值；session storage 只可保留未提交表单草稿，不能伪装为已保存对象。
- 409 删除冲突显示“该维度已被总线矩阵引用，请先取消对应勾选”。

## 8. 测试与验证

### 后端

- 手工维度创建为 `MANUAL + confirmed=true`。
- 重复维度 ID 被拒绝。
- 模板安装后对象保持 `confirmed=false`。
- 批量确认是业务域隔离、原子且幂等的。
- 未确认过程或维度不能写入矩阵。
- 被矩阵引用的维度删除返回冲突。
- 使用真实 PostgreSQL 验证时间类型、约束与事务行为。

### 前端

- 源码契约证明不新增页面或菜单。
- 空状态同时提供手工登记和模板选择。
- 未确认对象不进入矩阵。
- 单项与批量确认调用同一 API。
- 安装成功刷新数据但不自动确认。
- API 失败保持表单内容和明确错误状态。

### Chrome 95

- 不使用 `:has()`、容器查询、新视口单位、`toSorted()` 等不兼容能力。
- 在 1366×768 检查抽屉、列表操作和矩阵横向滚动。
- 在窄视口检查按钮不会叠成不可操作状态。
- 运行 Node 定向测试、Maven 定向测试、`pnpm build` 和浏览器 smoke。

## 9. 非目标

- 不新增行业模板管理后台或模板编辑能力。
- 不实现过程形态、事实表类型、时间语义和 SCD 配置。
- 不实现存量表或 dbt manifest 逆向登记。
- 不在本阶段整体重构主题域页面布局。
- 不清理既有客户数据库中的历史示例记录。

## 10. 验收标准

- 空白主题域可以完全通过手工操作建立业务过程、一致性维度和总线矩阵。
- 安装 PJM 或未来任意行业模板后，所有新增对象默认待确认。
- 未确认对象在矩阵和建模推荐中不可用。
- 客户确认后对象立即进入同一业务域的矩阵和推荐链路。
- 页面没有新增菜单、第四顶说明卡或自动填充行业内容。
- 后端、前端、真实 PostgreSQL 和 Chrome 95 验证全部通过。
